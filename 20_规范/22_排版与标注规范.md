## 一、总则

**禁止使用任何 emoji 或装饰性图形字符；只使用 Markdown 原生语法排版。**

- 禁止：表情符号、图标符号，以及星形、三角形、圆形、菱形、方形、勾选框等一切装饰性几何字符。
- 禁止：把上述字符用作列表符号、强调标记或状态标记。
- 允许：`#` 标题、`**加粗**`、`*斜体*`、`>` 引用块、`-` 无序列表、`1.` 有序列表、
  表格、代码块、`---` 分隔线、行内代码、`- [ ]` 任务列表（仅用于自测清单）、
  顺序箭头（用于表达学习先后顺序）。

> **【易错】** 现有素材笔记（`资料\02_数据结构\`、`资料\03_算法集训\`）中 emoji 密集
> （地图、图钉、火苗、警告、星星等）。整合旧内容时**极易带入**。
> 交付前必须逐文件检索，这是最常违反的一条规范。

> **【规律】** 判定标准是「这个字符在黑白打印稿上是否仍能表达含义」。
> 能表达则它承载了信息，应改为文字标签；不能表达则它是纯装饰，应删除。

## 二、标准标注体系

所有强调一律使用**加粗**加**中文方括号标签**，置于引用块行首或正文行内。

| 标签 | 用途 | 使用位置 | 适用分类 |
|------|------|---------|---------|
| `**【重点】**` | 关键结论、必背公式、核心判断 | 要点清单、知识点开头 | 全部 |
| `**【难点】**` | 理解困难、易绕晕的机制 | 要点清单 | 全部 |
| `**【易错】**` | 常见错误与后果（TLE / RE / WA） | 正文提示 | 全部 |
| `**【规律】**` | 可推广的判断规则、口诀 | 正文提示 | 全部 |
| `**【注意】**` | 容易忽略的前提、边界 | 正文提示 | 全部 |
| `**【记忆】**` | 一句话记忆点 | 知识点末尾 | 全部 |
| `**【类比】**` | 生活化类比，帮助建立直觉 | 知识点内 | 全部 |
| `**【模板】**` | 可直接套用的代码骨架 | 竞赛侧 | 全部 |
| `**【补充】**` | 原资料没有、由本次作业新增的内容 | 正文提示 | 全部 |
| `**【延伸】**` | 超出当前范围、供深入的方向 | 章末 | 全部 |
| `**【修正】**` | 原资料有误，附「原文 / 问题 / 正确」三段 | 正文提示 | 全部 |
| `**【真源】**` | 声明某信息以别处为唯一出处 | 章首、节首 | 全部 |
| `**【硬规则】**` | 不可违反、违反即返工的约束 | 约束段落 | 全部 |
| `**【要点】**` | 手册类文档的关键提醒 | 手册条目 | `70_速查手册` |
| `**【入门】/【进阶】**` | 题目难度 | 题干之前 | 题集 |

示例（正确写法）：

```markdown
> **【重点】** 顺序表的随机访问是 O(1)，插入删除是 O(n)，差异源于存储的物理连续性。

> **【易错】** 顺序表插入时必须**倒着**移动元素。正着移动会用前一个元素覆盖后一个，整段数据被污染。

> **【规律】** 稳定的排序只有四种：**直接插入、冒泡、归并、计数**（口诀：插冒归计）。
```

> **【注意】** 标签必须紧贴引用块行首，中间不留空格。
> 这一形式是可被样式表自动识别的关键——见第五节。

## 三、优先级标注体系

每个知识点必须标注优先级，使用 `P0` / `P1` / `P2` 三级。

| 优先级 | 含义 | 考研侧判定依据 | 竞赛侧判定依据 |
|--------|------|--------------|--------------|
| **P0** | 必掌握 | 408 大纲明确要求且历年高频必考；不会则直接失分 | 高频模板，几乎每场必用 |
| **P1** | 需熟练 | 大纲要求但频率中等；或作为 P0 的前置 | 中频，特定题型必用 |
| **P2** | 了解即可 | 大纲边缘、低频，或仅作背景知识 | 低频、高难或兴趣向 |

**标注位置**：知识点标题行末尾，以及章首的「知识点优先级与学习顺序」表中。

```markdown
### 1-3 顺序表的插入与删除　【P0】
```

> **【规律】** 优先级的**实际**等级要叠加「被依赖次数」。
> 一个被三个 P0 知识点依赖的 P1，其在学习路径上的实际优先级高于标称等级。
> 排学习顺序时必须体现这一点，不得只看标称等级。

### 3.1 每章开头的「知识点优先级与学习顺序」表

```markdown
## 知识点优先级与学习顺序

| 序 | 知识点 | 优先级 | 前置依赖 | 预估投入 |
|----|--------|--------|---------|---------|
| 1 | 抽象数据类型与线性结构 | P1 | 无 | 0.5 小时 |
| 2 | 顺序表的定义与随机访问 | P0 | 知识点 1 | 1 小时 |
| 3 | 顺序表的插入与删除 | P0 | 知识点 2 | 1 小时 |
| 4 | 单链表的建立与查找 | P0 | 知识点 2 | 1.5 小时 |
```

> **【硬规则】** 「序」列即**学习先后顺序**。排在后面的知识点只允许依赖排在它前面
> （或表中已标注为外部前置）的知识点。违反此约束的排列即视为错误。

## 四、难度标注（题集特有）

题集与题库中，每道题必须标注难度，位置在题干之前。

| 标签 | 考研侧判定 | 竞赛侧判定 |
|------|-----------|-----------|
| `【入门】` | 直接套用定义或单一公式；单一知识点 | 模板题，套模板即可通过 |
| `【进阶】` | 需要多步推导或跨知识点组合；或为算法设计题 | 变式题或综合题，需识别转化 |

**配比要求**：每章至少 1 道进阶题；全库入门与进阶比例控制在 **6:4 至 7:3**。

## 五、颜色区分规范（三通道）

颜色用于**加速定位**，不用于承载信息。全工程采用**三通道**配色，
每个通道承担一类信息，互不干扰。

| 通道 | 承载的信息 | 表达方式 | 平台降级后的表现 |
|------|-----------|---------|----------------|
| **内容类型** | 这段是什么性质的内容 | 块级：左侧色条 + 浅底色 | 引用块标签（如 `**【易错】**`） |
| **重要程度** | 这一点有多重要 | 行内：文字色 + 字重 | 加粗 / 下划线 / 常规 |
| **掌握状态** | 我学到什么程度了 | 纯文字标签，**不着色** | 不变（本就是文字） |

### 5.1 通道一　内容类型（块级）

| 内容类型 | 语义标签 | 通道一的降级载体 |
|---------|---------|----------------|
| 定义概念 | `**【重点】**` | 引用块 |
| 模板公式 | `**【模板】**` | 引用块 |
| 例题自测 | `**【入门】/【进阶】**` | 题干前缀 |
| 易错陷阱 | `**【易错】**` | 引用块 |
| 通俗类比 | `**【类比】**` | 引用块 |
| 补充延伸 | `**【补充】/【延伸】**` | 引用块 |

### 5.2 通道二　重要程度（行内）

| 等级 | 表达方式 | 黑白打印降级 |
|------|---------|------------|
| P0 | **加粗** + 主色 | 保留加粗 |
| P1 | 常规字重 + 次色 | 转为下划线 |
| P2 | 常规字重 + 弱化色 | 转为常规（无色无饰） |

### 5.3 通道三　掌握状态（纯文字，刻意不着色）

`[未学]` `[学过]` `[会做]` `[易错]` `[掌握]` —— 五种状态**一律不上色**。

> **【规律】** 掌握状态是变化最频繁的信息。若给它上色，全篇配色会随复习进度频繁变动，
> 破坏「颜色 = 稳定语义」这一认知基础。因此它必须保持为纯文字。

### 5.4 无障碍硬规则

> **【硬规则】** **颜色永不单独承载信息。**
> 每一处颜色都必须同时配有**字重**或**文字标签**，二者必居其一。
>
> 理由有三：黑白打印会丢失全部颜色；色觉障碍读者无法区分色相；
> 导出 PDF 与粘贴到纯文本环境同样会丢失颜色。
> 只要信息由文字与字重承载，这三种场景下信息都**零丢失**。

### 5.5 颜色的实现方式（关键）

**不得在 Markdown 源码中写任何 HTML 着色标签。**

颜色通过 **Obsidian CSS 片段**按语义标签自动着色实现：

| 项 | 说明 |
|----|------|
| 样式表文件 | `50_工具与模板\53_笔记配色样式.css` |
| 着色原理 | CSS 选择器匹配引用块行首的 `**【标签】**` 文本，自动加色条与底色 |
| 安装位置 | Obsidian 仓库 `.obsidian\snippets\` 目录，在设置中启用 |
| 源码形态 | 与无颜色版本**完全相同**，不含任何私有语法 |

> **【重点】** 这一设计使颜色成为**纯展示层**：
> 同一份 Markdown 源码，在 Obsidian 中带色，在 Notion、GitHub、通用编辑器、
> 纯文本与黑白打印中自动降级为标签与字重，**信息量与结构完全一致**。

### 5.6 打印降级

样式表必须单独编写 `@media print` 规则：

- 去掉全部底色与色条（黑白打印下底色会变成灰块，反而降低可读性）。
- **P0 保留加粗**；**P1 转为下划线**；**P2 转为常规**。
- 折叠内容全部展开，避免打印稿出现空白区。

> **【易错】** 不写 `@media print` 会导致黑白打印稿丢失**全部**重要程度信息
> ——颜色没了，且若字重未区分，P0 与 P2 在纸面上完全无法分辨。

### 5.7 图例（每篇笔记章首固定放置）

每篇笔记在标题之后、正文之前，**必须**插入下列图例块。
它是颜色的**使用说明书**：读者第一眼就知道本笔记用颜色与粗细表达什么。

```markdown
> **图例**
> **重要程度**：`P0` 必掌握（加粗 + 主色）｜`P1` 需熟练（次色）｜`P2` 了解即可（弱化色）
> **内容类型**：定义概念｜模板公式｜例题自测｜易错陷阱｜通俗类比｜补充延伸
> **掌握状态**：`[未学]` `[学过]` `[会做]` `[易错]` `[掌握]`（纯文字，不着色）
> 说明：颜色仅用于加速定位，**信息一律由文字标签与字重承载**，黑白打印不丢信息。
```

> **【硬规则】** 图例是**格式的一部分**，不是可选项。
> 没有图例的笔记视为未按规范排版——读者无法自行推断配色的含义。

> **【规律】** 图例本身也必须遵守「颜色不单独承载信息」：
> 它在括号里写明了每种等级对应的字重，即使在无色环境下读者也能理解对应关系。

## 六、代码规范

- 代码块**必须标注语言**：`cpp`、`c`、`text`、`bash`、`python`、`markdown`。
- **必须逐行或逐逻辑块注释**，注释同时说明「这一行在做什么」与「为什么这么做」。
- 模板代码给出**可直接提交的完整版本**（含 `#include` 与 `main`）。
- 每段代码后标注**时间复杂度与空间复杂度**。
- 涉及边界条件的行，显式标注 `// 边界：...`。
- 单块代码不超过 **60 行**，超出则拆分或只保留关键片段。
- 语言标准：竞赛侧 **C++17**；考研侧 **C**（遵循 408 以 C 描述算法的惯例）。
- 树状图、目录树、流程示意一律标注 `text`。

## 七、跨平台兼容规范

产出内容需可在 **Obsidian、Notion、GitHub、通用 Markdown 编辑器**之间无损迁移。

### 7.1 三层语法策略

| 层级 | 内容 | 降级后果 |
|------|------|---------|
| **第一层　通用核心** | 标题、加粗、斜体、列表、表格、代码块、引用块、公式、任务列表 | 无（全平台支持） |
| **第二层　语义增强** | `> **【重点】**` 形式的标签、`路径/文件.md#标题` 文本链接 | 降级为普通引用块，**信息不丢** |
| **第三层　平台专属** | Obsidian 双链与 Callout、HTML 标签、等号包裹的高亮、百分号包裹的注释 | 失效，**必须可剥离** |

> **【硬规则】** **信息只能由第一层承载。**
> 第二层只允许重复表达第一层已有的信息；第三层只允许作视觉增强。
> 任何「只有第三层才能读到的信息」即为设计错误。

### 7.2 硬性限制

| 限制项 | 上限 | 原因 |
|--------|------|------|
| 标题层级 | **不超过四级** | Notion 导入会压平五级及更深，层级信息丢失 |
| 表格列数 | **不超过六列** | 移动端需横向滚动，超过六列可读性急剧下降 |
| 代码块语言 | 标准语言名，C++ 写 `cpp` | Notion 与 GitHub 均识别 |
| HTML 标签 | **一律禁用** | Notion 不渲染，会把标签原样显示为文本 |
| 文件名 | 禁用 `/ \ : * ? " < > \|` 与英文逗号 | 跨平台文件系统兼容；含顿号或逗号者改用下划线 |

### 7.3 迁移前检查

```bash
python 50_工具与模板/52_检查_跨平台兼容.py .
```

检查项覆盖表情与装饰字符、HTML 标签、高亮语法、专属注释、双链、嵌入、
标题深度、表格列数、代码块语言、Dataview 块。**必须零问题方可交付。**

> **【补充】** 若某文档本身就是在讲解这些不兼容语法（如本文件），
> 在文件内任一处写 `<!-- compat-ignore-file -->` 即可整体跳过检查。
> 单行例外用 `<!-- compat-ignore -->`。
