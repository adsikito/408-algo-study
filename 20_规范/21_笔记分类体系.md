# 笔记分类体系与命名规范

> **作用**：本文件是全套笔记的**分类地基**。任何新建笔记、任何提示词、任何目录调整，均以本文件的划分为准。
> **定版时间**：2026-09-12
> **配套提示词**：`12_笔记生成提示词.md`、`13_练习题集生成提示词.md`

---

## 一、三类划分

全部笔记**只分三类**，不设第四类。

| 分类 | 收录范围 | 本轮状态 | 笔记规模预估 |
|------|---------|---------|------------|
| **01 考研** | 408 数据结构大纲要求的全部内容 | 生成 | 12 篇 |
| **02 竞赛** | 直接服务赛事（CCF 系列、蓝桥杯、百度之星、ACM）的算法与 C++ 内容 | 生成 | 42 篇 |
| **03 常规课程** | 工程向、教学向的 C++ 及其他课程内容 | **本轮不处理** | 0 篇 |

> **【要点】** 划分类别的目的是**互斥**。任何一个知识点只能属于一类，不允许两边都写正文。

## 二、判定准则：单一问题法

判定一个知识点归入哪一类，**按顺序**问三个问题，命中即停：

```text
问题 1　它是 408 大纲要求的内容吗？
         是 → 归「01 考研」，结束
         否 → 继续问题 2

问题 2　它在算法竞赛的赛场上能直接用上吗？
         是 → 归「02 竞赛」，结束
         否 → 继续问题 3

问题 3　以上都不是
         → 归「03 常规课程」，本轮不处理
```

> **【注意】** 三个问题必须**按顺序问，不能并列判断**。
> 并列判断会导致同一知识点（例如「二分查找」）在考研与竞赛两边各写一遍，这是本方案要杜绝的头号问题。

### 判定示例

| 知识点 | 问题 1 | 问题 2 | 结论 |
|--------|-------|-------|------|
| 顺序表的插入与删除 | 是 | — | 考研 |
| 折半查找判定树与 ASL 计算 | 是 | — | 考研 |
| 外部排序（败者树、置换-选择） | 是 | — | 考研 |
| `ios::sync_with_stdio(false)` | 否 | 是 | 竞赛 |
| `lower_bound` 与 `unique` 去重 | 否 | 是 | 竞赛 |
| 单调队列（滑动窗口最值） | 否 | 是 | 竞赛 |
| 智能指针与移动语义 | 否 | 否 | 常规课程（不处理） |
| 协程与 Modules | 否 | 否 | 常规课程（不处理） |
| 多线程与网络编程 | 否 | 否 | 常规课程（不处理） |

### 为何竞赛 C++ 独立成子分类

**问题**：竞赛 C++ 与常规 C++ 存在同名知识点（`vector`、`string`、`sort`），若合在一处，会出现同一知识点两种写法混排，读者无法判断该学哪一种。

**做法**：竞赛 C++ 独立为 `02_竞赛\02_竞赛C++\`，与常规 C++ **物理隔离**。同时在文档层面用「四、边界清单」明确哪些知识点归哪边。

## 四、竞赛 C++ 与常规 C++ 的边界清单

**这是本分类体系最核心的一张表。** 表中每一条都必须无歧义地归入某一侧。

### 4.1 仅归竞赛 C++ 的内容

| 知识点 | 归此侧的理由 |
|--------|------------|
| `ios::sync_with_stdio(false)` 与 `cin.tie(nullptr)` | 纯竞赛性能优化手段 |
| `"\n"` 与 `endl` 的性能差异 | 只在竞赛数据量下才重要 |
| 手写快读快写 | 竞赛专用 |
| 编译期调试宏（本地开 freopen，提交自动关闭） | 应对 OJ 提交流程的专用技巧 |
| STL 容器的**卡常写法**与内存预分配 | 竞赛性能优化 |
| `sort` 自定义比较器与 lambda 就地写法 | 赛场所需的写法习惯 |
| `lower_bound` / `upper_bound` / `unique` + `erase` | 赛场高频工具 |
| `__builtin_` 系列内建函数 | 竞赛专用 |
| 结构化绑定在**图论建图与遍历**中的用法 | 赛场代码简洁性 |
| 对拍（暴力加生成器加比对脚本） | 赛场自查手段 |
| 常见 RE / TLE / MLE 排查顺序 | 赛场排错 |
| 比赛代码模板 | 赛场效率 |

### 4.2 仅归常规课程的内容（本轮不处理）

| 知识点 | 归此侧的理由 |
|--------|------------|
| 类、继承、多态、虚函数 | 工程向，竞赛不用 |
| 模板元编程、可变参数模板 | 工程向 |
| 异常处理（try / catch / throw） | 工程向，竞赛中反而是负担 |
| 智能指针（unique_ptr / shared_ptr） | 工程向，竞赛不用 |
| 移动语义与右值引用的**完整语义** | 工程向；竞赛只需知道「避免拷贝」 |
| 协程、Modules（C++20） | 多数 OJ 编译器不支持 |
| `std::filesystem` | 工程向 |
| `optional` / `variant` / `any` | 工程向，且能被更简写法替代 |
| 多线程、网络编程、HTTP 服务器 | 求职向 |
| 构建系统（CMake、Makefile） | 工程向 |
| 设计模式 | 工程向 |

### 4.3 两边都需要、但**写法与深度不同**的内容

这类内容是混淆的高发区，处理规则必须严格执行：

| 知识点 | 竞赛 C++ 侧只写 | 常规课程侧写 | 处理规则 |
|--------|---------------|------------|---------|
| `vector` | 内存预分配、`reserve`、下标与迭代器失效、卡常用法 | 完整语义、构造与析构、异常安全、与算法的配合 | **两侧各写各的**，用交叉引用指向对方，**不复制正文** |
| `string` | `cin` 读串、`getline`、`stringstream` 分割、与 `char[]` 的转换 | 完整类语义、SSO、编码处理 | 同上 |
| `sort` | 自定义比较器、lambda、稳定性要求、复杂度 | 完整算法实现与迭代器要求 | 同上 |
| 指针 | 数组传参、函数传参避免拷贝 | 完整内存模型、RAII | 同上 |
| 位运算 | lowbit、状压、集合运算 | 完整位运算语义与未定义行为 | 同上 |
| 递归 | 递归深度与爆栈规避 | 调用栈机制与尾递归优化 | 同上 |

> **【硬规则一】** 每个知识点必须**明确归入某一侧作为主写方**。本表 4.3 的六个知识点，**主写方为「常规课程」**（因其语义完整性要求更高），竞赛侧只写赛场特定用法。
> **【硬规则二】** 跨侧引用必须使用相对路径文本链接，例如：`../03_常规课程/...`。**不得复制对方正文。**
> **【硬规则三】** 竞赛侧笔记中，若某知识点在常规课程侧已有完整讲解，竞赛侧用一行链接代替正文，例如：
> `vector 的完整语义见常规课程笔记；本节只讲赛场用法。`

## 六、命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 顶层分类 | 两位数字前缀加下划线加名称 | `01_考研`、`02_竞赛`、`03_常规课程` |
| 子分类 | 两位数字前缀加下划线加名称 | `01_算法专题`、`02_竞赛C++` |
| 章节笔记 | 两位数字前缀加下划线加名称加 `.md` | `04_树与二叉树.md` |
| 模块笔记 | 单个大写字母加下划线加名称加 `.md` | `B_输入输出与性能.md` |
| 阶段目录 | `阶段N_名称` | `阶段5_图论` |
| 全局文件 | 下划线开头 | `_竞赛总索引.md` |
| 附录文件 | `附录` 加字母或名称 | `附录A_C语言前置基础速查.md` |

**禁止字符**：`/` `\` `:` `*` `?` `"` `<` `>` `|` 以及英文逗号。
含顿号、中文逗号的名称改用下划线，例如「栈、队列和数组」写作 `02_栈_队列和数组`。

加号 `+` 可用于文件名（如 `竞赛C++`），但**不得用于目录树之外的路径拼接**。

## 七、跨分类引用规则

1. **只引用，不复制。** 跨分类的知识点引用一律用文本链接，正文留在原分类。
2. 链接写法（Obsidian 内可用双链，导出稿用文本链接）：

```text
考研侧引用竞赛侧：   ../02_竞赛/02_竞赛C++/C_STL容器.md#C-3 set 与 multiset
竞赛侧引用考研侧：   ../01_考研/04_树与二叉树.md#4-2 二叉树的五条性质
常规课程引用（仅声明）： 见 03_常规课程，本轮未生成
```

3. 各分类的 `README` 必须维护一张**跨分类引用表**：

| 本分类的笔记 | 引用的外部分类 | 引用位置 | 说明 |
|------------|--------------|---------|------|
| `C_STL容器.md` | 03_常规课程 | C-1 vector | 完整语义见常规课程，本节只讲赛场用法 |

4. **禁止反向污染**：常规课程笔记不得引用竞赛侧内容。竞赛是特化，常规是全集。

## 九、本体系的调整方式

若需新增分类或调整边界：

1. **先改本文件**，再改提示词，最后改笔记。
2. 本文件是**单一真源**。提示词中的分类规则一律引用本文件，不重复定义。
3. 调整边界时，必须同步检查 4.3 表中受影响的知识点，确认主写方未改变。
