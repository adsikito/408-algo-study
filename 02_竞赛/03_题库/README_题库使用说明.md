> **题库位置**：`02_竞赛\03_题库\`
> **当前规模**：5 道题（种子），1 道已有代码
> **设计文档**：`33_笔记题库知识点组织方案.md`
> **定版时间**：2026-09-12

---

## 一、题库里有什么

| 文件 | 作用 | 是否手工编辑 |
|------|------|------------|
| `_题库总表.md` | **题目的元数据单一真源**：题号、链接、涉及知识点、状态、代码文件名 | **是**，加题改状态都在此 |
| `_知识点索引.md` | **知识点的元数据单一真源**：编号、名称、优先级、掌握状态、所属笔记 | **是**，掌握状态在此更新 |
| `代码\` | 题解代码，一题一文件，命名 `<题号>.cpp` | **是**，做题时新建 |
| `题解\` | 思路拆解，**可选**，只对值得写思路的题建立 | 按需 |
| `check_bank.py` | 三方一致性校验脚本 | 否 |

> **【要点】** 这里只有**两个**手工维护的真源文件。
> 代码放代码目录，题面在链接里，思路按需写——**同一信息不会出现两次**。

## 二、三者是什么关系

```text
知识点（枢纽）──── 1:N ──── 笔记（怎么讲）
      │
      └──── N:M ──── 题目（怎么练）
```

- **知识点 → 笔记**：一个笔记讲多个知识点；一个知识点只属于一个笔记
- **知识点 ↔ 题目**：一题考多个知识点；一个知识点被多题考（需区分**主 / 副**知识点）
- **笔记 → 题目**：笔记的「典型例题」节引用题号，**不复制链接与题面**

**为什么知识点是枢纽**：学习顺序沿「知识点 → 笔记」走，练习顺序沿「知识点 → 题目」走。两条线共用知识点做锚点，顺序才不会错位。

完整说明见 `33_笔记题库知识点组织方案.md` 第二节。

## 三、四步工作流

### 第 1 步　学

在 `01_算法专题\` 或 `02_竞赛C++\` 的对应笔记里读知识点。
读完把 `_知识点索引.md` 中该知识点的状态改为 `[学过]`。

### 第 2 步　登记（关键动作）

在 `_题库总表.md` **对应阶段**的表格下加一行：

```markdown
| luogu-P1115 | 最大子段和【入门】 | https://www.luogu.com.cn/problem/P1115 | 1-2 前缀和 · — | 未做 | — |
```

**填表要点**：

| 列 | 怎么填 |
|----|-------|
| 题号 | `<平台>-<原题号>`，平台小写（`luogu` / `leetcode` / `cf`） |
| 题名 | 题目名，末尾加 `【入门】` 或 `【进阶】` |
| 链接 | **联网核实后**再填，不得凭记忆 |
| 知识点 | `主 · 副`，主知识点决定这题归到哪个阶段 |
| 状态 | 新登记一律写 `未做` |
| 代码 | 先写 `—`，建文件后改成文件名 |

> **【重点】** **先登记，后做题。**
> 登记时就要确定「这题考哪个知识点」，这一步会暴露「该不该现在做」的问题——
> 如果发现主知识点属于自己还没学的阶段，说明这题超纲，先别做。
> 做完再补登记，往往是白做了一道超纲题。

### 第 3 步　做

在 `代码\` 下建 `<题号>.cpp`，例如 `代码\luogu-P1115.cpp`。

文件头建议保留元数据注释，便于脱离题库也能看懂：

```cpp
// ============================================================================
// luogu-P1115　最大子段和
// 链接：https://www.luogu.com.cn/problem/P1115
// 主知识点：1-2 一维前缀和与二维前缀和
// 状态：已通过
// 复杂度：时间 O(n)　空间 O(n)
// 易错点：答案不能取 dp[n]，要在全表取 max
// ============================================================================
```

做完把总表状态改为 `已做`。

### 第 4 步　复盘

| 结果 | 动作 |
|------|------|
| 通过 | 总表状态改 `已通过`；`代码` 列填文件名 |
| 未通过 | 总表状态改 `待复习`；在题解文件里记下错误原因 |
| 同知识点全部通过 | 把 `_知识点索引.md` 中该知识点状态提升为 `[掌握]` |

> **【易错】** **题目「已通过」不等于知识点「掌握」。**
> 换一道同知识点的题可能又错。所以知识点状态要**该知识点下全部题目通过**才提升。

## 四、状态字段（两个，含义不同）

| 字段 | 在哪 | 取值 |
|------|------|------|
| **题目状态** | `_题库总表.md` | `未做` / `已做` / `已通过` / `待复习` |
| **知识点状态** | `_知识点索引.md` | `[未学]` / `[学过]` / `[会做]` / `[易错]` / `[掌握]` |

**联动规则**：

```text
题目全部通过 + 隔 7 天复测通过  →  知识点 [掌握]
任一题做错                      →  知识点退回 [易错]
```

## 五、命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 题号 | `<平台小写>-<原题号>` | `luogu-P5788`、`leetcode-42`、`cf-1927A` |
| 代码文件 | `<题号>.cpp` | `luogu-P5788.cpp` |
| 题解文件 | `<题号>.md` | `luogu-P4779.md` |
| 平台前缀 | `luogu` / `leetcode` / `cf` / `lanqiao` / `baidu` / `ccf` | — |
| 408 真题 | `408-<年份>-<题号>` | `408-2023-41`，链接列写「真题无公开网址」 |

> **【注意】** 题号保留原平台的大小写形式：洛谷用大写 `P`，Codeforces 用 `1927A`。

## 六、为什么按阶段排而不按平台排

题库总表**按「阶段 → 知识点」分组**，不按洛谷 / 力扣 / CF 分组。

理由很直接：**平台的划分对学习没有任何指导意义**。学到阶段 3 时，不会因为题目在洛谷还是力扣而改变该不该做它。而按阶段分组后，**学到哪就做到哪**，每个阶段的表格可以直接当待办清单用。

平台信息保留在题号前缀里（`luogu-` / `leetcode-` / `cf-`），需要时一眼可见，不需要单开一列。

## 七、校验脚本

```bash
cd 02_竞赛/03_题库
python check_bank.py .              # 全量校验
python check_bank.py . --report     # 附加统计与未覆盖知识点清单
```

### 检查项

| 编号 | 检查内容 | 严重度 |
|------|---------|-------|
| E101 | 链接格式是否符合平台规范 | 高 |
| E102 | 题目引用的知识点编号是否在索引中存在 | 高 |
| E103 | 状态为「已通过」但缺代码文件 | 高 |
| E104 | P0 知识点无任何题目覆盖 | 中 |
| E105 | 表格列数或状态取值非法 | 中 |
| E106 | 代码文件名与题号不一致，或存在无主代码文件 | 中 |

### 当前校验结果（2026-09-12）

```text
题目总数：5        已通过：1        代码文件数：1
知识点总数：43     其中 P0：25      已被题目覆盖：9
```

- **E101 / E102 / E103 / E105 / E106 全部为 0**，三方一致。
- **E104 剩 3 处**（阶段 0 的 0-1 / 0-2 / 0-3 免做项，理由已登记总表）。题库现为 **189 道**
  （竞赛 124 + 408 真题 65），生产侧登记收官；变式层按方法论待学习反馈后补。

> **【补充】** 竞赛 C++ 模块的 P0 知识点**不参与 E104 判定**，
> 已在脚本中以 `EXEMPT_PREFIX` 豁免。原因：依附类知识点不单独配题；三批 24 道已覆盖该模块 26 个知识点。

## 八、常见问题

| 问题 | 处理 |
|------|------|
| 一道题同时属于两个阶段 | 写**主知识点**决定归属，副知识点写另一个。不要在两处重复登记 |
| 题目链接失效了 | 只改 `_题库总表.md` 一处即可。笔记里只有题号，不受影响 |
| 想给某道题写详细思路 | 在 `题解\` 下建 `<题号>.md`，总表不动 |
| 代码想按知识点归档 | 不推荐。代码按题号命名，用总表的「知识点」列做反向检索即可 |
| 做到一半发现超纲 | 状态改 `待复习`，在题解里注明「依赖 X 阶段，暂缓」。不要删行，保留记录 |
