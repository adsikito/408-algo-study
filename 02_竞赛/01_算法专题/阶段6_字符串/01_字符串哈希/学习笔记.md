## 🗺️ 本章地图

> **本章解决一个问题：怎么把字符串变成整数，让"比较字符串"变成"比较整数"？**
> 路线是"原理 → 公式 → 防撞 → 真题"：先理解哈希的动机与"碰撞"概念（知识点 1）；再学多项式哈希（b 进制 + 质数 M 取模），用 "abc" 手推前缀哈希（知识点 2）；然后推导滚动哈希公式——O(1) 取任意子串哈希（知识点 3）；最后学两种降碰撞手段（自然取余法、双哈希）并拿下 P3370 字符串判重（知识点 4）。
> 学完自测：能否手算 "abc" 的前缀哈希？能否写出 O(1) 子串哈希公式？

## 📌 本章重点（3-5个）

⭐ **字符串哈希的定义与性质**：Hash 值不同 → 两串一定不同；Hash 值相同 → 不一定相同（碰撞）
⭐ **多项式哈希**：把串看成 b 进制数再对质数 M 取模，hash[i] = hash[i-1]·base + s[i]
⭐ **滚动哈希**：O(n) 预处理前缀哈希和 base 的幂，h(l..r) = hash[r] − hash[l−1]·base^(r−l+1)，O(1) 查子串
⭐ **自然取余法**：unsigned long long 溢出时自动对 2^64 取模，不手写取模语句
⭐ **双哈希**：两组 (base, MOD) 各算一次，配成二元组比较，极难被构造数据卡掉

## 🔥 本章难点（2-3个）

🔥 **滚动哈希公式的推导**：为什么减去 hash[l−1]·base^(r−l+1) 恰好"抹掉"前 l−1 位（进位制的错位对齐）
🔥 **自然取余法的原理**：无符号溢出即模 2^64，等价于选 M = 2^64，好处是不用取模运算、值域极大
🔥 **哈希碰撞的对抗思维**：碰撞不可根除只能降概率——值域取大（M 尽量大）、双哈希（模数互相独立）

## ⚠️ 本章易错点（3-5个）

⚠️ **字符映射到 0**：若把 a 映成 0，则 "ab" 与 "b" 哈希相同（前导零被抹掉）；字符应从 1 开始（a→1…z→26）或用 ASCII 值
⚠️ **类型用错**：自然取余法必须 `typedef unsigned long long ull`，用 long long 溢出是未定义行为；运算顺序要保证中间量也是 ull
⚠️ **base 与 M 选得不好**：base 必须大于最大字符值且不含模数的质因子；M 要是质数且 M > b；常用 b=131/27，M=19260817、19660813
⚠️ **忘了预处理 base 的幂**：每次查询现算 base^(r−l+1) 会退化成 O(n)，必须先打 pow 数组
⚠️ **单哈希拍板"相等"**：单模哈希可被专门数据卡掉，判重关键场合用双哈希或哈希相同后再比对原串

## 📖 知识点讲解

### 1. 字符串哈希：把字符串映成整数

**是什么**：**哈希**就是把一个数据经哈希函数映射到值域较小、方便比较的范围；**字符串哈希**专门把字符串转成一个整数来存。两条铁律：①Hash 值不一样 ⇒ 两串一定不一样；②Hash 值一样 ⇒ 不一定一样（大概率相同），这种"值相同串不同"叫**哈希碰撞**。

**为什么**：比较两个长 n 的字符串要 O(n)，比较两个整数只要 O(1)；超长字符串转成整数存还能省空间。判重、匹配子串、判回文等高频操作都从"字符级"降到"整数级"。

**怎么用**：凡是"只比较、不修改"的字符串场景都可以哈希：字符串判重（P3370）、模式串匹配、判两个子串是否相等、二分+哈希求最长公共子串等。

> ⚠️ 注意事项：哈希是"以概率换时间"——理论上有误判风险，工程上靠降碰撞把概率压到可忽略。

> 🎯 规律：哈希值不同必不同，相同才需要担心。
> 💡 一句话总结：字符串变整数，比较从 O(n) 到 O(1)。

### 2. 多项式哈希（b 进制 + 质数 M 取模）

**是什么**：把长度为 l 的字符串看成 **b 进制数**：f(s) = s[0]·b^(l−1) + s[1]·b^(l−2) + … + s[l−1]，再对**质数 M** 取模。这和"n 进制 234 = 2·n² + 3·n + 4"是同一件事。要求：M 选质数（至少比最大字符大），b 也比最大字符大。

**为什么**：多项式函数满足"前缀可递推、子串可拼减"（下两点的根基）；对质数 M 取模让结果均匀散布在小值域；b > 字符值保证不同串（无前导零歧义时）对应不同的 b 进制数。

**怎么用**：
```cpp
typedef unsigned long long ull;
ull Has(char s[]) {              // 自然取余版：不手动取模
    ull sum = (ull)s[0];
    for (int i = 1; i < strlen(s); i++)
        sum = sum * b + (ull)s[i];   // b=131
    return sum;
}
```
**跟着算**：s = "abc"，取 base=27、a=1, b=2, c=3（先不取模）：
- hash[0] = a = **1**
- hash[1] = hash[0]×27 + b = 1×27 + 2 = **29**（即 "ab" = 1·27+2）
- hash[2] = hash[1]×27 + c = 29×27 + 3 = **786**（即 1·27² + 2·27 + 3）

递推通式：hash[0]=s[0]；i>0 时 **hash[i] = hash[i−1]·base + s[i]**——"老数整体升一位，新字符接在个位"。

> ⚠️ 注意事项：不要把任意字符映成 0（前导零问题）；base 常用 131（通用）或 27（仅 a-z）。

> 🎯 规律：字符串就是 b 进制数，哈希就是它模 M 的余数。
> 💡 一句话总结：逐位左移进一位，乘 base 加新字符。

### 3. 滚动哈希：O(1) 求任意子串的哈希

**是什么**：先 O(n) 预处理**前缀哈希** hash[i]（s[0..i] 的哈希值）和 **base 的幂** pw[i]=base^i；之后任意子串 s[l..r] 的哈希：
**h(l..r) = hash[r] − hash[l−1]·base^(r−l+1)**，单次查询 O(1)。这套"前缀相减取中段"就叫滚动哈希。

**为什么**：hash[r] 是整个前缀的 b 进制值，其中 s[l..r] 这一段比 hash[l−1] 这一段**恰好高 r−l+1 位**；把 hash[l−1] 左移（乘 base^(r−l+1)）对齐后相减，前段完全抵消，剩下的就是子串的值——和前缀和求区间和"sum[r]−sum[l−1]"同构，只是这里要带权对齐。

**怎么用**：
```cpp
pw[0] = 1;
for (int i = 1; i <= n; i++) {
    pw[i]  = pw[i-1] * base;             // 预处理 base 的幂
    hash[i] = hash[i-1] * base + s[i];   // 预处理前缀哈希
}
ull get(int l, int r) {                   // 子串 s[l..r]，下标从1开始
    return hash[r] - hash[l-1] * pw[r - l + 1];
}
```
**跟着算**：接上例 "abc"（hash = [1, 29, 786]，pw = [1, 27, 729]），求子串 "bc"（l=1, r=2）：
- h(1..2) = hash[2] − hash[0]×base^(2−1+1) = 786 − 1×27² = 786 − 729 = **57**
- 验算：直接算 "bc" = 2×27 + 3 = **57** ✓ 对上了

对比子串只需两次 get() 比较：判断文本串每个长度为 m 的窗口是否等于模式串，总复杂度 O(n+m)——这就是**哈希匹配**。

> ⚠️ 注意事项：下标建议从 1 开始，让 hash[l−1] 在 l=1 时自然等于 0；自然取余版中减法可能出现"负数回绕"，由于是无符号数、比较双方口径一致，不影响正确性比较（若用有符号取模版需再 +M 防负）。

> 🎯 规律：前缀哈希 + 幂数组 = 任意子串 O(1) 取，减法要对齐位数。
> 💡 一句话总结：左移对齐再相减，中段哈希手到擒来。

### 4. 降低碰撞：自然取余法、双哈希 与 P3370

**是什么**：**降碰撞两板斧**：①**把 b 和 M 尽量取大**——值域越大碰撞越小；M 最大就是 2^64：用 unsigned long long 存、不手写取模，溢出时硬件自动对 2^64 取余，即**自然取余法**。②**双哈希**——选两组不同的 (base, MOD)（如 131/19260817 与 101/19660813）各哈希一次，结果构成二元组，**两个都相同才判相等**。

**为什么**：单哈希的碰撞概率约 n/M；M=2^64 已很大但仍可能被专门构造的数据卡掉（出题人知道你的 base 和 M 就能造碰撞）；双哈希要同时撞两组独立参数，构造难度指数级上升，目前除了卡时间无法卡掉。

**怎么用**（P3370【模板】字符串哈希：给 n 个字符串求不同串个数）：
```cpp
// 双哈希版：读入后
h[i].x = Has(s, b1, m1);   // (131, 19260817)
h[i].y = Has(s, b2, m2);   // (101, 19660813)
sort(h + 1, h + n + 1, cmp);       // 二元组排序
for (i = 2; i <= n; i++)
    if (h[i].x != h[i-1].x || h[i].y != h[i-1].y) ans++;  // 相邻不同则计数
```
跟着算：三个串哈希成 (101, 101, 205) → 排序后相邻比较得 3−1=2 个不同值 → 不同串 2 个。

> ⚠️ 注意事项：自然取余法"可能产生冲突被卡掉"，竞赛高风险场合优先双哈希；P3370 还可用 sort+string 直接比较水过，但本章练的是哈希思想。

> 🎯 规律：M 尽量大是底线，双哈希是保险。
> 💡 一句话总结：模大碰撞小，双哈希双保险。

## 🔍 相似概念辨析

### 自然取余法 vs 双哈希

| 维度 | 自然取余法 | 双哈希 |
|------|-----------|--------|
| 模数 | 隐式 M = 2^64（硬件自动） | 两个显式质数（如 19260817） |
| 代码量 | 最短：不写取模语句 | 两套函数/两个结果 |
| 存储开销 | 1 个 ull | 1 个二元组（2 个数） |
| 抗卡能力 | 可被针对性构造数据卡掉 | 目前无法被卡（除卡时间） |
| 速度 | 最快（无 % 运算） | 约慢一倍（算两次） |
| 使用场景 | 随机数据、练手 | 对抗性比赛、判重关键题 |
| 代表代码 | P3370--自然取余.cpp | P3370--双哈希.cpp |

### 哈希匹配 vs KMP（下一章预告）

| 维度 | 哈希匹配 | KMP |
|------|---------|-----|
| 思想 | 把子串变整数直接比 | 利用已匹配前缀的自身信息 |
| 判等方式 | 比较哈希值（概率性） | 逐字符保证（确定性） |
| 预处理 | 前缀哈希 + 幂数组 | next 失配数组 |
| 单次匹配复杂度 | O(n+m)，最坏可被卡 | O(n+m) 严格保证 |
| 优势 | 好写、可推广到二维/多模式 | 无碰撞风险、稳定 |
| 短板 | 理论上会碰撞 | 思维难度更高、扩展性弱 |

## 🧩 本章归纳：一条主线串全章

> 本章主线一句话：**"字符串难比较" → 多项式哈希把它看成 b 进制数模 M → 前缀递推 hash[i]=hash[i−1]·base+s[i] → 错位相减 O(1) 取子串 → 值域拉大 + 双哈希压碰撞**。定义上记住"不同必不同、相同不一定"；公式上滚动哈希是全章核心，它把"匹配/判等/判重"全部变成整数比较；P3370 两种写法（自然取余、双哈希）就是这道主线的两个落地版本。哈希与下一章 KMP 解决同一个问题（子串匹配），KMP 用确定性换掉了哈希的"概率性"——两章对照着学效果最佳。
