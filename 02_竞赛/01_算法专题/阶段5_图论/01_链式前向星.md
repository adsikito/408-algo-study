## 本章地图

本章解决一个问题：**「一张图（点 + 边），用什么结构存又快又稳？」**

```text
图存储的三代方案：
   ├─ 邻接矩阵：O(n²) 空间，查边 O(1) —— n ≤ 3000 且稠密时才用
   ├─ vector 邻接表：每点一个 vector —— 好写，指针跳转多
   └─ 链式前向星：边数组 + head 链表 ★ 竞赛标准
         ├─ 存储三要素：to（去哪）、w（权）、nxt（同起点的下一条边）
         ├─ head[u] = u 的第一条边编号（−1 表无边）
         └─ 遍历：沿 nxt 链走到 −1
   ↓
本篇产出「建图三行代码」→ 后续六篇 + 考研第 5 章全部复用
```

**为什么这条路径是这样**：图算法的难点在算法本身，
**存储结构不该成为第二道难题**——前向星用「数组模拟链表」把建图
压到三行代码、零动态内存，这就是它成为标准的原因。

| 题目特征 | 应想到的算法 | 优先级 |

> **【规律】** **选型看稠密与规模**：稠密小图用矩阵（查边 O(1)），
> 稀疏大图用前向星 / vector（空间 O(n + m)）。
> **「n² 空间爆炸」是矩阵方案的唯一死因。**

## 核心概念与模板

**是什么**：链式前向星 = 数组版邻接表：`head[u]` 存 u 的第一条边的**编号**，
`nxt[e]` 存同起点的下一条边编号，`to[e]` / `w[e]` 存终点与权。

**为什么**：三数组搞定，比指针邻接表快且省；**一条边存一个编号**
（无向图存 2e 条：e 与 e^1 互为反向边），是阶段 5 全部图算法的标准建图方式。

> **【规律】** **建图三行代码**（本篇的全部产出）：
> `to[tot] = v; w[tot] = c; nxt[tot] = head[u]; head[u] = tot++;`——
> **头插法**：新边永远挂在链头，遍历顺序与输入顺序相反（多数算法不关心顺序）。

**怎么用**：

```cpp
// g++ -std=c++17 -O2
#include <cstdio>
#include <cstring>
const int N = 100005, M = 200005;        /* 无向图 M 开 2 倍 */

int head[N], nxt[M], to[M], w[M], tot = 0;

void init() {
    memset(head, -1, sizeof(head));      /* -1 表示无边 */
    tot = 0;
}

void addEdge(int u, int v, int c) {      /* 加有向边 u -> v，权 c */
    to[tot] = v;
    w[tot] = c;
    nxt[tot] = head[u];
    head[u] = tot++;
}

void addU(int u, int v, int c) {         /* 无向边：正反两条 */
    addEdge(u, v, c);
    addEdge(v, u, c);
}

/* 遍历 u 的所有出边 */
void traverse(int u) {
    for (int e = head[u]; e != -1; e = nxt[e]) {
        int v = to[e], c = w[e];
        /* 使用 v、c */
    }
}
```

> **【类比】** 前向星像**火车编组**：每节车厢（边）记着「我拉到哪站（to）、
> 载重多少（w）、我的下一节车厢是谁（nxt）」；
> 每个车站（点）只记「我这里编组的第一节车厢是哪节（head）」。
> **新到的车厢永远挂在最前面（头插），查这站的编组就顺着 nxt 走到 −1 为止。**

## 本章难点

> **【难点】** **−1 表无边与「0 号边可用」的约定**。
> 本模板边编号从 0 起，head 初始化 −1——**0 号边是真实边**，
> 所以「无边」必须用 −1 而不是 0。两套口径（−1 / 0 表无边）都有人用，
> **赛场锁定一套写到底**：本套教材统一 −1 口径。

> **【难点】** **无向图的对称边与反向边定位。**
> `addU` 产生第 tot 与 tot+1 两条互为反向的边——
> **反向边的编号 = `e ^ 1`**（异或 1：奇偶互换；前提：从 0 起编号）。
> 这个性质在网络流（进阶）里是命根子，
> 本篇先建立习惯：**成对加边、从 0 起编号、与 e^1 配套**。

---

## 本章易错点

> **【头号易错】** **无向图 M 忘开 2 倍**（正反两条边）——RE 首因；
> head 忘初始化 −1（0 号边被当成「无边」）。

> **【易错】** **`addU` 只调了一次**（漏反向边）——症状是遍历时少一半边，
> 极难从答案察觉。

> **【易错】** **tot 复用前未清零**（多组数据）；遍历写成 `e++`（应 `e = nxt[e]`）。

> **【易错】** **重边 / 自环**：模板天然支持重边（多条边都在链上）；
> 自环是否合法按题意——最短路自环无效、DFS 自环算环。

> **【易错】** **混合题（既正推又反推）**：开两套 head 数组（或加一维），
> 不要共用一条链。

## 典型例题

### 例 1　建图 + 出边遍历（模板）　难度：模板题

**题干摘要**：n 点 m 条有向带权边，依次输出每个点的出边表。
**题源**：同类真源见配套练习 T1（P4779）、T2（P3371）——两者都以此模板为底座
**涉及知识点**：知识点 1、2、3

**解题思路**：

1. **信号**：「n, m 达 10⁵ / 5×10⁵」→ 前向星（矩阵必炸）。
2. **方法**：核心模板 + 读入 + 遍历输出。

**复杂度**：建图 O(m)，全图遍历 O(n + m)，空间 O(n + m)。

> **【易错】** 输出顺序与输入相反（头插）——题目要求原序时先按下标存再反转，
> 或逆序读入。

---

### 例 2　有向图存反向图（反建技巧）　难度：变式题

**题干摘要**：求每个点能到达多少点 / 汇点到各点距离——建反向图跑一遍即可。
**题源**：同类真源见配套练习 T3（P3916 图的遍历，vector 版在库，两种建图对照）
**涉及知识点**：知识点 2、5

**解题思路**：

1. **信号**：「u 可达 v」的反向查询 → `addEdge(v, u, c)` 建反图。
2. **方法**：反向 BFS / DFS / Dijkstra 全部适用；边数不变。

**复杂度**：O(n + m)。

> **【易错】** 反图的边数不变；混合题（既有正推又有反推）开两套 head 数组。
> 「建图方向 = 信息流向」要按算法需要定，不是按题面。

## 本章总结

### 核心内容（一页纸）

1. **图存储三代**：矩阵（稠密小图）→ vector（好写）→ 前向星（竞赛标准）。
2. **三要素**：to（去哪）、w（权）、nxt（同起点的下一条边）。
3. **建图三行**：`to/w/nxt` 赋值 + `head[u] = tot++` 头插法。
4. **head 初始化 −1 表无边**，0 号边是真实边——两套口径锁定一套。
5. **遍历语法**：`for (e = head[u]; e != -1; e = nxt[e])`——全阶段共享。
6. **无向图开 2m、addU 成对加**；反向边 = `e ^ 1`（网络流命根）。
7. **重边天然支持**；自环按题意；反建 = 调换 addEdge 参数。
8. **多组数据重置 head 与 tot**。
9. **建图层 bug 伪装成算法 bug**——先验证建图再写算法。
10. **本篇产出被后续六篇全部复用**——地基专题，写熟一次终身受益。
