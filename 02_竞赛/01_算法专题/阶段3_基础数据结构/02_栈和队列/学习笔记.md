## 🗺️ 本章地图

本章学两个最基础的"受限"线性结构：栈（先进后出）与队列（先进先出）。课件定调：队列多用于辅助（如图的 BFS），很少单独出题；**重点是栈的应用**——先进后出天然适配括号匹配、碰撞抵消这类"最近匹配"问题。实现上两条路：数组直接模拟或 STL stack/queue。路线：结构特性与两种实现（知识点 1）→ P4387 用栈判定合法出栈序列（2）→ LC735 用栈模拟行星碰撞的分类讨论（3）→ 队列家族速览：优先队列、单调栈/单调队列（4，单调栈下一章详讲）。

## 📌 本章重点

⭐ **栈=先进后出，只在栈顶操作**：匹配、抵消、回退类问题的标准容器；做题可数组模拟（vector 的 push_back/back/pop_back）或 STL stack
⭐ **出栈序列判定模板**（P4387）：按入栈序列逐个压栈，每压一个就 **while** 栈顶==出栈序列当前元素就弹出；最后栈空 → 合法
⭐ **碰撞判定的分类讨论**（LC735）：3 种不撞（栈空/同号/相背）直接压栈；1 种相撞（相向）分 3 种结局，用 while 处理连环撞
⭐ **优先队列**：元素带优先级、最高优先级先出，基于堆实现；`priority_queue<int>` 大顶堆、加 `greater<int>` 小顶堆（第八章合并果子已用）

## 🔥 本章难点

🔥 **LC735 连环碰撞**：一个向左的行星可能连撞毁多个向右的行星，while 弹栈后的三种结局（被毁/同归/存活入栈）都要接对，且"当前为正直接压栈、不与栈顶比较"的分支不能丢
🔥 **P4387 多组数据的状态清理**：每组数据前必须清空栈（和数组），上一组的残留栈顶会让下一组全部判错——例题代码专门用红色感叹号注释了这一行

## ⚠️ 本章易错点

⚠️ **弹栈判断用 if 不用 while**：栈顶弹出后新栈顶可能还能匹配，必须 while 连续弹（P4387、LC735 同理）
⚠️ **栈空还访问 top()/back()**：判断栈顶前先判 `!s.empty()`，条件顺序不能反（短路求值要靠左边的判空兜底）
⚠️ **P4387 漏清空容器**：多组数据间 `while(!s.empty())s.pop();` 忘写，上一组残留直接污染下一组答案
⚠️ **LC735 分支写错**：当前行星 >0 必须直接压栈（与栈顶"相背而行"不撞）；两行星相等时是同归于尽——pop 栈顶且**当前不入栈**，只写一半就错
⚠️ **绝对值比较绕晕**：LC735 判"栈顶比当前小"用 `s.back() < -asteroids[i]`（利用负号取绝对值），漏掉负号方向全反

## 📖 知识点讲解

### 1. 栈与队列：特性与两种实现

**是什么**：白话——栈是只有一口子的桶，后放的先出来（先进后出 LIFO）；队列是水管，尾巴进、头出（先进先出 FIFO）。课件强调做题姿势：**多数使用数组直接模拟栈（队列），或直接用 C++ STL 的 stack（queue）**；队列多用于辅助（图的 BFS 要队列帮忙），很少单独出题，栈的应用及题目才是重点（先进后出 → 括号匹配类）。

**为什么**：栈的"只在栈顶进出"恰好对应"最近的未匹配元素"——括号匹配、行星碰撞、撤销操作都是"和最近的一个比一下"；队列的先进先出恰好对应"按到达顺序处理"——BFS 逐层扩展靠它。

**怎么用**——两种实现对照（默写级）：
```cpp
// STL 版
stack<int> s;
s.push(x);            // 入栈
s.top();              // 看（不删）
s.pop();              // 删（无返回值！取值要先用 top）
s.empty();            // 判空

// 数组模拟版（vector，LC735 用法）
vector<int> s;
s.push_back(x);       // 入栈（压到尾部）
s.back();             // 看栈顶
s.pop_back();         // 弹栈顶
s.size(); s.empty();  // 大小/判空
```
跟算：依次 push 1、2、3——栈：3(顶) 2 1，top()=3；队列：1(头) 2 3(尾)，出队得 1。同一串输入，栈出来是 3、2、1，队列出来是 1、2、3。

> ⚠️ 注意事项：STL 的 pop()/front()/top() 都不返回元素，"取+删"要分两步；数组模拟栈空时 back()/pop_back() 未定义行为。

> 🎯 规律：见"最近匹配/抵消/回退"选栈，见"按顺序处理/逐层扩散"选队列；动手前先在纸上画出桶/管子里的变化。

> 💡 一句话总结：栈顶进出叫栈，队尾进队头出。

### 2. 验证栈序列（P4387）：边压边弹判合法性

**是什么**：白话——给一个入栈顺序和一个出栈顺序，问"是否存在一种操作序列"（随时可压可弹）能走出给出的出栈顺序。课件思路：**按入栈顺序入栈；每压入一个，就反复检查栈顶是否等于出栈序列的当前元素，相等就弹出**；i、j 分别是入栈/出栈序列的下标。

**为什么**：出栈序列合法 ⇔ 贪心地"能弹就弹"走完全程后栈恰好为空。压入 a[i] 后若栈顶==b[j]，这一步弹出是被迫的（不出栈就无法让 b[j] 在正确时机出栈）；while 判断是因为弹出后新栈顶可能仍等于下一个出栈元素——可能**连续弹出**。

**怎么用**——模板（`P4387.cpp`）：
```cpp
cin >> q;                                  // q 组数据
for (int k = 1; k <= q; k++)
{
    while (!s.empty()) s.pop();            // 清空上组数据！！
    cin >> n;
    for (i=1..n) cin >> a[i];              // 入栈序列
    for (i=1..n) cin >> b[i];              // 出栈序列
    int i, j = 1;
    for (i = 1; i <= n; i++)
    {
        s.push(a[i]);                      // 第 i 个数入栈
        while (!s.empty() && s.top() == b[j])
        {                                  // 栈非空 且 栈顶是预期出栈元素
            s.pop();
            j++;
        }
    }
    if (s.empty()) cout << "Yes" << endl;  // 全部按序弹出=合法
    else cout << "No" << endl;
}
```
跟算：入 1 2 3 4 5 / 出 4 5 3 2 1：
```
push1(顶1≠4) push2(≠4) push3(≠4) push4(=4→弹,j=5)
顶3≠5 → push5(=5→弹,j=3) 顶3=3→弹(j=4) 顶2=2→弹(j=5) 顶1=1→弹(j=6)
栈空 → Yes ✓
```
反例：出 4 3 1 2 5：push1..4 → 4 出、3 出（栈内剩 1,2）；顶2≠1，push5 后顶5≠1；i 走完栈非空 → No ✓（1 压在 2 下面，不可能先于 2 出栈）。

> ⚠️ 注意事项：每组数据必须清空栈（课件代码的感叹号注释）；while 里判空写在 `s.top()==b[j]` 前面，靠 && 短路保护。

> 🎯 规律：判定"某顺序/某过程是否可行"→ 让程序按规则**贪心模拟一遍**，能无冲突走完即合法；这套"边压边弹"骨架可迁移到表达式求值、括号匹配。

> 💡 一句话总结：边压边弹，弹完看空。

### 3. 行星碰撞（LC735）：分类讨论 + 连环弹栈

**是什么**：白话——一排行星，正数向右、负数向左，大小=绝对值；相向而行的会相撞，大的活小的亡、相等同归于尽，问最终剩哪些。课件思路（数组模拟栈）：**3 种情况不会碰撞，可把当前行星压栈**——①栈空（不管正负）；②当前行星与栈顶同号（同向移动）；③当前行星向右（正）且栈顶向左（负）——相背而行。**只有 1 种情况会碰撞需要出栈**：当前行星向左（负）、栈顶向右（正），再做判断——①栈顶 > |当前|：当前被撞毁；②栈顶 == |当前|：栈顶弹出、两者抵消；③栈顶 < |当前|：栈顶弹出，**与新栈顶继续上述判断**。

**为什么**：向左的行星只可能撞上它左边的向右行星——恰好就是栈顶；栈里保存的正是"还没撞完的幸存者序列"，所以碰撞模拟天然长在栈上。

**怎么用**——模板（`LC 735.cpp`）：
```cpp
vector<int> s;                          // 数组模拟栈
for (int i = 0; i < n; i++)
{
    if (s.empty() || asteroids[i] > 0)  // 栈空 或 当前向右：直接压
        s.push_back(asteroids[i]);
    else                                // 当前向左，可能与向右的栈顶相撞
    {
        while (s.size() && s.back() > 0 && s.back() < -asteroids[i])
            s.pop_back();               // 栈顶小：连环撞毁
        if (s.empty() || s.back() < 0)  // 撞光/顶上同向：当前存活入栈
            s.push_back(asteroids[i]);
        else if (s.back() == -asteroids[i])
            s.pop_back();               // 等大：同归于尽（当前不入栈）
        // 否则：栈顶更大，当前被毁，什么都不做
    }
}
return s;                               // 栈里就是幸存者序列
```
跟算：asteroids=[10, 2, -5]：
```
10：栈空 → 压 [10]
2：当前>0 → 压 [10,2]
-5：向左；顶2<5 → 弹 [10]；顶10>5 → 当前被毁
结果 [10] ✓（原题示例）
```
再跟算 [8, -8]：8 压栈；-8 向左，顶 8==|-8| → pop 同归 → 空栈 []。

> ⚠️ 注意事项：`asteroids[i]>0 直接压栈`这个分支独立存在（哪怕栈顶是正数也不比较）；相等分支 pop 完当前不入栈；"当前为负、栈顶也为负"走 `s.back()<0` 分支照样入栈——同向不撞。

> 🎯 规律：碰撞/抵消/消除类 → 栈顶就是"最近的对手"；套路=不撞则压、相撞 while 弹、弹完三分（亡/平/活）。括号匹配、字符串消除同款。

> 💡 一句话总结：相向才撞，连环弹栈。

### 4. 队列家族速览：优先队列与单调结构

**是什么**：课件定义——**优先队列**：普通队列先进先出、队尾进队头删；优先队列中元素被赋予优先级，访问时具有**最高优先级的元素最先删除**（最高级先出），基于堆（大顶堆/小顶堆）实现。**单调栈**：栈中元素严格单调递增或递减（从栈底到栈顶逐渐增大/减小）——下一章详细讲解。**单调队列**：概念与单调栈类似，应用很少，多用于对一些算法的优化（如动态规划）。

**为什么**：很多场景要"反复取当前最值"（第八章合并果子）或"反复取当前最优候选"（第十二章上一题的下一个更大元素），普通栈/队列只能 O(n) 扫，堆/单调结构把它压到 O(logn)/O(1)。

**怎么用**——优先队列速记（#include <queue>）：
```cpp
priority_queue<int> pq;                              // 大顶堆：堆顶最大
priority_queue<int, vector<int>, greater<int>> p;    // 小顶堆：堆顶最小
pq.push(x); pq.top(); pq.pop();                      // 入队/看堆顶/删堆顶
```
跟算：依次 push 3,1,2——大顶堆 top() 恒为当前最大（先 3，弹后 2）；小顶堆 top() 恒为当前最小（先 1，弹后 2）。第八章 P1090 合并果子用小顶堆每次取两最小，就是优先队列的实战。

> ⚠️ 注意事项：优先队列底层是堆不是排序数组，top() 是 O(1)、push/pop 是 O(logn)；单调栈的"单调"指值，不是下标——细节下一章展开。

> 🎯 规律：反复取最值 → 优先队列（堆）；反复取"下一个更大/更小" → 单调栈；滑动窗口最值 → 单调队列。三种受限容器都是"维护局部有序性"的工具。

> 💡 一句话总结：队列辅助BFS，优先队列按级出。

## 🔍 相似概念辨析

**组1：栈 vs 队列**

| 对比维度 | 栈 | 队列 |
|---|---|---|
| 各自定义 | 只在栈顶进出的先进后出（LIFO）结构 | 队尾进、队头出的先进先出（FIFO）结构 |
| 核心区别 | 后来的先走（电梯） | 先来的先走（排队） |
| 各自特点 | 操作集中一端，匹配"最近元素" | 操作分两端，保持"到达顺序" |
| 使用场景 | 括号匹配/碰撞抵消/撤销（LC735） | 按序处理、图的 BFS 辅助（课件） |
| 典型示例 | P4387 判出栈序列 | BFS 逐层扩展结点 |
| 记忆口诀 | 栈像桶后出先，队像管先出先 |

**组2：普通队列 vs 优先队列**

| 对比维度 | 普通队列 | 优先队列 |
|---|---|---|
| 各自定义 | 元素队尾追加、队头删除 | 元素带优先级，最高优先级最先删除（课件） |
| 核心区别 | 出队顺序=入队顺序 | 出队顺序=优先级顺序，与入队顺序无关 |
| 各自特点 | FIFO 严格公平 | 基于堆实现，取最值 O(1)、插入删除 O(logn) |
| 使用场景 | BFS、缓冲区等按序处理 | 反复取最值：合并果子（第八章）、Dijkstra 优化 |
| 典型示例 | queue<int> q | priority_queue<int,vector<int>,greater<int>> |
| 记忆口诀 | 队列看先来，优先看最大 |

## 🧩 本章归纳：一条主线串全章

主线因果链：**很多过程只需要"看最近的一个"（匹配/碰撞/撤销）→ 无需全序列，只要保存"还没处理完的幸存者"→ 栈顶恰是最近的幸存者（栈的本质价值）→ 用"不撞则压、相撞则弹、弹完分类"统一模拟（P4387 边压边弹、LC735 连环弹栈）→ 需要的若是"最值/最优候选"而非"最近"，把栈换成堆（优先队列）或维护有序性（单调栈，下一章）**。受限容器三兄弟（栈/堆/单调栈）都是"只维护必要信息"的省力哲学。

跨知识点共性：
1. **与第八章贪心同款套路**：P4387"能弹就弹"和 LC735"撞完再看下一个"都是贪心式模拟——局部立即决策、绝不回头，栈只是承载决策的容器。
2. **与第十章链表互通**：栈/队列既可用数组模拟也可用链表实现（课件 STL 背后即是链/数组结构）；上一章的结点+指针在这里换个身份登场。
3. **向后铺垫**：单调栈是第十二章全章主角（LC42 接雨水、P5788）；队列是第十六章 BFS 的发动机（课件原话"图的 BFS 需要队列辅助"）；优先队列还要在堆优化 Dijkstra（第 20 章）再挑大梁。

## 📋 速查表

| 模板 | 复杂度 | 适用条件 |
|---|---|---|
| 边压边弹判出栈序列 | O(n) | P4387；while 弹、栈空判合法 |
| 数组模拟栈（vector） | 单步 O(1) | push_back/back/pop_back，省 STL |
| 碰撞三分模拟 | O(n) 均摊 | LC735；不撞压、撞则弹、三分结局 |
| 优先队列（堆） | push/pop O(logn) | 反复取最值；大顶默认，小顶加 greater |
| STL stack/queue | 单步 O(1) | top/front/pop 均无返回值，取删分两步 |

```cpp
// 出栈序列判定骨架（默写级）
int j = 1;
for (int i = 1; i <= n; i++) {
    s.push(a[i]);
    while (!s.empty() && s.top() == b[j]) {  // 判空在前！
        s.pop(); j++;                        // while 不是 if
    }
}
puts(s.empty() ? "Yes" : "No");              // 多组数据先清空栈！
```
