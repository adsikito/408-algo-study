## 第十七章：并查集

> 课件来源：`并查集.pdf`、`并查集代码\并查集代码.c`
>
> 并查集是"精巧而实用"的树形数据结构：**用一棵树表示一个集合、用数组存父指针**，专门处理不相交集合的合并与查询，代码短、思想妙、考试与上机高频。

## 🗺️ 本章地图

- **本章解决什么问题**：元素不断"抱团"，还要随时问"这两个是不是一伙的"——并查集用近似常数的代价完成合并与查询。
- **学习顺序**：先建立"树根 = 代表"的表示法（节1~2）→ 初始化（节3）→ 查找 Find（节4）→ 合并 Union（节5）→ 朴素合并会长链，用路径压缩拍扁（节6）。
- **为什么是这个顺序**：Find 是一切操作的地基，Union 只是"两次 Find + 根接根"；而链式退化正是节6 压缩存在的理由——先看见病，才理解药。
- **各节关系一句话**：节1~3 搭舞台，节4~5 是两大主角，节6 是给主角上的保险。

## 📌 本章重点（3-5个）

⭐ **并查集的定位**：处理**不相交集合**（交集为空）的合并与查询问题的树形数据结构，元素用整数表示，S={S1,S2,…,Sk}
⭐ **三大基本操作**：建立（s 个单元素集合）、合并（把 x、y 所在集合合并，相交就不合并）、查找（找到 x 所在集合的代表）
⭐ **树的表示与存储**：结点=元素、根=集合代表，每个结点存**指向父节点的指针**，根结点指针指向自己；沿父指针上溯到根即找到代表
⭐ **路径压缩**：每次查找时，令查找路径上的每个节点都直接指向根节点
⭐ **判断同集合**：两元素各自的代表（根）相同 → 属于同一集合

## 🔥 本章难点（2-3个）

🔥 **合并顺序导致退化成链**：依次合并 (4,3)、(3,2)、(2,1) 会得到 4→3→2→1 的单链；若合并一万个结点，查找次数就非常非常多——这是路径压缩要解决的核心问题
🔥 **递归 Find 中的路径压缩**：`f=Find(fa[x]); fa[x]=f; return f;` 压缩发生在**递归回溯**的路上——先拿到根，回溯时顺带把沿途结点全部改挂到根；一行版 `return fa[x]=Find(fa[x])`
🔥 **合并的是"根"不是元素本身**：必须先 Find 出两个根 fx、fy 再 `fa[fy]=fx`，直接写 `fa[y]=x` 会把结构接错甚至破坏集合

## ⚠️ 本章易错点（3-5个）

⚠️ **根的判断条件写错**：课件正文画的是"根指针指向自己"，代码约定是 **fa[x]==-1 表示 x 是根**（-1 表示不存在）；判断条件按所用约定来，两种写法不能混（fa[x]==x 版本必须配 fa[x]=x 的初始化）
⚠️ **忘记初始化 fa 数组**：每次使用前必须把 fa 全部初始化为 -1，漏了初始化则 Find 行为不可预期
⚠️ **合并时挂错对象**：`fa[fy]=fx`（把 y 的根挂到 x 的根下）才是集合合并；写成 `fa[y]=x` 只改了一个普通结点的父指针，集合并没有合并
⚠️ **压缩没写对位置**：写成 `return Find(fa[x])` 只返回了根、**丢掉了赋值**，路径没有被压缩；必须 `fa[x]=Find(fa[x])` 或先接住 f 再赋值
⚠️ **迭代版没有压缩**：迭代 Find1 只是一路 `p=fa[p]` 上溯，**不修改任何 fa 值**——能找到根但不会让树变矮（代码注释"引以为戒"）

## 📖 知识点讲解

### 1. 并查集与不相交集合

**是什么**：一群人不断拉帮结派，随时要问"他俩一伙吗"——并查集就是专管"分堆"的极速后台：合并、查询都快到常数级。严格地说，并查集是一种非常精巧而实用的**树形数据结构**，主要处理**不相交集合的合并和查询**问题。不相交集合就是**交集为空**的一些集合：如 {1,3,5} 和 {2,4,6} 交集为空，是不相交集合；{2,3,5} 和 {1,3,5} 有公共元素 3、5，就不是。使用时先存在一组**不相交的动态集合** S={S1,S2,…,Sk}，一般用**一个整数表示集合中的一个元素**。

**为什么**：每个集合会选出**某个元素作为代表**（集合的"发言人"，集合的身份全靠它辨认）。集合里具体包含哪些元素不关心、具体选哪个元素做代表也不关心；关心的是：对给定元素，能**很快找到它所在集合的代表**，以及**合并两个元素所在的集合**——而且这些操作的时间复杂度都是**常数级**的。

**怎么用**——两个典型问题：
```
① 查询：元素 x 和 y 是否属于同一个集合？（比较各自的代表）
② 合并：把 x 所在集合与 y 所在集合并成一组（朋友圈、连通块）
```
跟着算（6 个元素、5 条关系）：
```text
第1步 初始 6 人各自成派：{1} {2} {3} {4} {5} {6}
第2步 读到关系 (1,3)、(3,5)：合并得 {1,3,5}；读到 (2,4)、(4,6)：合并得 {2,4,6}
第3步 查询 3 和 5：两派的代表相同 → YES；查询 3 和 2：代表不同 → NO
```

> ⚠️ 注意事项："动态"意味着集合的成员会随合并操作不断变化，但任何时刻各集合互不相交这一性质不变。

> 🎯 规律：集合的身份 = 它的代表；一切"分堆问题"最终都化归为"找到代表、比较代表"。

> 💡 一句话总结：不相交集合管合并查询，代表说了算。

### 2. 树的表现形式与 fa 数组存储

**是什么**：每个元素只记一件事——"我爹是谁"；族谱一路翻到底，那位没有爹的就是代表。并查集用**树来表示一个集合**：树的每个结点是集合的一个元素，**树根对应的结点就是该集合的代表**。例如两棵树分别对应集合 {a,b,c,d}（代表 a）和 {e,f,g}（代表 e）。树的结点表示元素，**指针表示指向父节点的指针，根结点的指针指向自己**（表示它没有父节点）；沿着每个结点的父节点不断向上查找，最终就能找到树根，即该集合的代表元素。

**为什么**：只需"父指针"这一个信息就能完成全部操作——向上能找根（查询），把一根接到另一根下（合并）。实现时用一个**足够长的数组**存树结点：`fa[i]` 存 i 的父节点下标，这就是树的**双亲表示法**（只记每个结点的父亲、不记孩子的存树法）。

**怎么用**（树与 fa 两视角对照）：
```text
树视角：    a ←代表     e ←代表
           / \         / \
          b   c       f   g
          |
          d
fa 视角（存父下标，-1 表示没有父结点）：
fa[a]=-1  fa[b]=a  fa[c]=a  fa[d]=b      ← 整棵树只知道"爹"，不知道"儿子"
fa[e]=-1  fa[f]=e  fa[g]=e
```
```c
int fa[105];          // fa[i]: i 的父结点下标
// 两种等价约定（保持一套即可）：
// 课件图示：根的指针指向自己  fa[x]==x  → x 是根
// 课程代码：用 -1 表示不存在  fa[x]==-1 → x 是根
```

> ⚠️ 注意事项：整片森林共用一个 fa 数组；fa 里存的是**下标**，不是值。

> 🎯 规律：只存"父指针"就够用——每个结点向上的路唯一，找代表永不迷路；孩子信息可以完全不知道。

> 💡 一句话总结：一棵树一个集合，树根就是代表。

### 3. 初始化 makeSet

**是什么**：开局人人自立为王——每个元素自己一棵树、自己当根。建立一个新并查集，其中包含 **s 个单元素集合**——每个元素自成一棵树，即父节点是其自身（课件图：1~6 每个结点自环）。代码实现中就是构造出这样一片"森林"，课程代码用 fa 全部置 -1 来表达"每个结点都是根"。

**为什么**：初始时每个元素各自独立成集合，之后每读入一条关系才逐步合并——这是"动态集合"的起点。

**怎么用**（跟着算：n=5 初始化后的模样）：
```text
fa[1..5] = -1  -1  -1  -1  -1
对应森林：①  ②  ③  ④  ⑤     ← 5 棵单结点树 = 5 个集合，人人都是根
```
```c
for(int i=0;i<=n;i++) fa[i]=-1;   // -1：不存在父结点，即自己是根
```

> ⚠️ 注意事项：**每次运行都要重新初始化**，多组数据时尤其容易漏；初始化范围要覆盖所有用到的下标。

> 🎯 规律："是根"必须有机器能判断的标记（-1 或自身）；初始化就是在统一发放这个标记，漏发全盘皆乱。

> 💡 一句话总结：全员自立为王，fa 全部置 -1。

### 4. 查找 Find（迭代版与递归版）

**是什么**：Find 就是顺着父指针一路向上"认爸爸"，认到没有爸爸的那位，就是集合的代表。查找操作就是**找到 i 的祖先（树根）直接返回**。两种写法：迭代版一路沿父指针上溯；递归版在回溯时顺带做路径压缩（见知识点 6）。

**为什么**：代表元素是集合的"身份证"——要判断两元素是否同一集合，只需比较它们各自的代表是否相同；合并也必须先找到两根。所以 Find 是并查集一切操作的基础。

**怎么用**——课程代码两个版本：
```c
int Find(int x){                      // 递归版（带路径压缩）
    if(fa[x]==-1) return x;           // 根：直接返回
    int f=Find(fa[x]);                // 父亲的根就是 x 的根
    fa[x]=f;                          // 路径压缩：结点直接连到根上
    return f;
    // 一行版：return fa[x]=Find(fa[x]);
}
int Find1(int x){                     // 迭代版（无压缩）
    int p=x;
    while(fa[p]!=-1) p=fa[p];         // 沿父指针上溯到根
    return p;
}
```
跟着算（链 4→3→2→1，fa[4]=3、fa[3]=2、fa[2]=1、fa[1]=-1，用迭代版 Find1(4)）：
```text
第1步 p=4，fa[4]=3≠-1 → p=3
第2步 p=3，fa[3]=2≠-1 → p=2
第3步 p=2，fa[2]=1≠-1 → p=1
第4步 p=1，fa[1]=-1 → 循环停，返回 1
全程只读不改：fa 数组原封不动，链还是链——这正是节6 要治的病。
```

> ⚠️ 注意事项：递归深度等于树高，极端退化成链时递归也很深；迭代版循环条件是 `fa[p]!=-1`，停在根上返回 p。

> 🎯 规律：查找的终点是 fa==-1；递归写法在回溯路上留下"顺手做事"的机会——路径压缩就藏在回溯的那一瞬间。

> 💡 一句话总结：顺着爹找祖先，找到根才返回。

### 5. 合并 Union

**是什么**：合并两个圈子不必惊动每个成员：让一帮之主给另一帮之主当小弟即可——根一换，全组成员的代表自动换人。Union 把元素 x 和元素 y 所在的集合合并成一个，要求 x 和 y 所在的集合**不相交**（如果相交就不合并）。实现：先 `fx=Find(x)`、`fy=Find(y)` 分别找到两根，再 `fa[fy]=fx`（把 y 的根挂到 x 的根下，反过来 `fa[fx]=fy` 也对）。

**为什么**：合并集合 = 合并两棵树，只需把**一棵树的根**接到**另一棵树的根**下面，根变了整棵树的代表就统一变了；动任何非根结点都做不到"整体合并"。

**怎么用**——判断 + 合并的固定套路：
```c
fx=Find(x); fy=Find(y);
if(op==1) fa[fy]=fx;                  // 合并：根接根
else printf(fx==fy?"YES":"NO");       // 查询：同根即同集合
```
跟着算（5 个元素，fa 初始全 -1，约定 fa[fy]=fx）：
```text
第1步 Union(1,2)：fx=Find(1)=1、fy=Find(2)=2 → fa[2]=1
第2步 Union(3,4)：fx=3、fy=4 → fa[4]=3
第3步 Union(2,4)：fx=Find(2)=1、fy=Find(4)=3 → fa[3]=1
      ⚠ 挂的是两个"根"1 和 3；若误写 fa[4]=2，只是 4 一个结点搬家，
        3 还留在原地，集合 {3,4} 根本没被并进来。
第4步 查询 2、4 是否同集合：Find(2)=1、Find(4)=1，同根 → YES
第3步后的森林（4→3→1 已悄悄连成链，为节6 埋下伏笔）：
        1        5
       / \
      2   3
          |
          4
```

> ⚠️ 注意事项：合并前**必须先 Find 两个根**；按课件，两集合相交就不合并（同根时无需任何操作）；朴素合并不管树高，顺序不当就会长链（见知识点 6 的引子）。

> 🎯 规律：改根才叫合并（fa[fy]=fx）——根是全集合唯一的"户口"，根动全组跟着搬；动普通结点只是搬家，不是合并。

> 💡 一句话总结：根接根才叫合并，同根即同集合。

### 6. 路径压缩

**是什么**：既然链是病，就在每次查找时顺路把病人治了：查谁，谁和沿途结点统统直接挂到根下——一次治本，回回省力。路径压缩就是**每次查找时，令查找路径上的每个节点都直接指向根节点**。效果：链 4→3→2→1（根为 1）执行一次带压缩的 Find(4) 后，变成 2、3、4 全部直接挂在 1 下面，树高从 3 变成 1。

**为什么**：朴素地依次合并 (4,3)、(3,2)、(2,1) 会得到一条链；如果此时合并了一万个结点，从链尾查找要从一万一步步上溯，查找次数非常非常多。压缩把树"拍扁"，一次支付的代价换来后续查找近乎一步到位。

**怎么用**——压缩就藏在递归回溯里：
```c
int f=Find(fa[x]);   // ① 先递归到根，拿到根 f
fa[x]=f;             // ② 回溯途中：沿途结点全部改挂到根
return f;
// 执行一次 Find(4) 前：fa[4]=3, fa[3]=2, fa[2]=1, fa[1]=-1
// 执行后：            fa[4]=1, fa[3]=1, fa[2]=1, fa[1]=-1
```
跟着算（同一条件用文字走一遍递归的"去"与"回"）：
```text
第1步 一路递归下去：Find(4)→Find(3)→Find(2)→Find(1)，fa[1]=-1 命中根，返回 1
第2步 回溯到 x=2：f=1，fa[2]=1（2 直挂根）
第3步 回溯到 x=3：f=1，fa[3]=1
第4步 回溯到 x=4：f=1，fa[4]=1，返回 1 —— 去时只查，回时改挂
压缩前：1            压缩后：   1
        ↑                     / | \
        2                    2  3  4
        ↑
        3
        ↑
        4
```

> ⚠️ 注意事项：压缩**只改 fa，不改集合成员**；单次压缩本身要花一次完整查找的代价，收益在后续——配课件说法，优化后查找与合并的时间复杂度都是常数级。

> 🎯 规律：递归"去时只查、回时改挂"——回溯阶段每个结点都已知道根，顺手赋值零额外成本；迭代版想压缩就得拿到根后再走一遍。

> 💡 一句话总结：查谁谁挂根，一次拍扁全链。

### 🧩 本章归纳：一条主线串全章

**一条主线**：动态分堆要快（节1 需求）→ 树表示集合、根当代表（节2）→ 初始化人人自为根（节3）→ Find 找根是一切操作的地基（节4）→ Union 只是"两次 Find + 根接根"（节5）→ 朴素合并会长链、查找越来越慢 → 路径压缩借递归回溯顺手拍扁（节6），代价拉回常数级。

**回头看才看得见的共性**：
1. **信息越少，维护越便宜**：并查集不存孩子、不管树内形状，只保"向上唯一"一条性质，换来十几行代码的近常数操作——与堆放弃兄弟有序是同一个道理。
2. **代表思想**：给每个集合选一个"发言人"（根），集合运算全部化归为代表运算；堆的堆顶、哈夫曼树的根权值，都是"把全局信息集中到一个结点上"的用法。
3. **退化与修复成对出现**：不加约束的操作会让结构退化（并查集长链、二叉搜索树变链、AVL 失衡），对应的修复手段（路径压缩、旋转）都只在"事发的那条路径"上局部动刀。

## 🔍 相似概念辨析

### 组1：查找 Find vs 合并 Union

| 对比维度 | 查找 Find | 合并 Union |
|----------|-----------|-----------|
| 各自定义 | 找到元素 x 所在集合的代表（树根） | 把 x、y 所在集合合并成一个（不相交才并） |
| 核心区别 | 只读上溯（递归版顺带压缩） | 两次 Find + 一次根接根赋值 |
| 各自特点 | 朴素最坏要走完树高 | `fa[fy]=fx` 根变了全集合代表跟着变 |
| 使用场景 | 查询两元素是否同集合 | 朋友圈/连通块的关系合入 |
| 典型示例 | `while(fa[p]!=-1)p=fa[p]; return p;` | `fx=Find(x);fy=Find(y);fa[fy]=fx;` |
| 记忆口诀 | 查找找根，合并接根 | |

### 组2：路径压缩版 Find vs 迭代版 Find1

| 对比维度 | 递归 Find（带压缩） | 迭代 Find1（无压缩） |
|----------|--------------------|---------------------|
| 各自定义 | 找根，并把路径上结点全部直挂根 | 找根，一路只读不改 |
| 核心区别 | `fa[x]=f` 发生在回溯路上 | 循环内只 `p=fa[p]`，不动 fa |
| 各自特点 | 树越用越扁，后续查找近乎常数 | 树形不变，链还是链 |
| 使用场景 | 默认首选（课程主实现） | 理解原理/忌递归爆栈时 |
| 典型示例 | Find(4) 后 fa 变为全挂根 1 | Find1(4) 后 fa 仍是 4→3→2→1 |
| 记忆口诀 | 递归顺手拍扁，迭代只看不改 | |

### 组3：并查集的树 vs 普通二叉树

| 对比维度 | 并查集的树 | 普通二叉树 |
|----------|-----------|-----------|
| 各自定义 | 表示集合的"父指针森林"，根=代表 | 每个结点最多两孩子的层次结构 |
| 核心区别 | 只存"父指针"，孩子信息完全不知道 | 存孩子指针，从根往下遍历 |
| 各自特点 | 形状随意、可为链；查找自底向上 | 形态受约束（如搜索树有序）；遍历自顶向下 |
| 使用场景 | 不相交集合的合并与查询 | 查找、排序、层次关系 |
| 典型示例 | `fa[i]` 数组即可表达整片森林 | 链式结点 `lchild/rchild` |
| 记忆口诀 | 并查集只认爹，二叉树才认儿 | |

### 组4：并查集判连通 vs 图 DFS/BFS 判连通

| 对比维度 | 并查集 | 图 DFS/BFS |
|----------|--------|-----------|
| 各自定义 | 用代表是否相同判断两元素是否同集合 | 从起点遍历图，标记可达点 |
| 核心区别 | 只动态合并、不需建完整图结构 | 需要邻接表/矩阵并整体遍历 |
| 各自特点 | 合并、查询近似常数级，代码十几行 | 每次遍历 O(n+e)，适合一次性问题 |
| 使用场景 | 关系流式到来、多次合并+多次查询 | 已有静态图、问一次可达性 |
| 典型示例 | op==1 合并 / op==2 查 YES/NO | visited[] 标记连通分量 |
| 记忆口诀 | 关系边来边并查，静态图上跑遍历 | |

## 📋 速查表

### 操作与复杂度
```
操作          做法                                复杂度
初始化        fa[i]=-1（共 n 个单元素集合）         O(n)
查找 Find     沿 fa 上溯到根（fa[x]==-1 即根）      朴素最坏 O(n)；路径压缩后常数级
合并 Union    fx=Find(x); fy=Find(y); fa[fy]=fx    常数级（两次 Find + 一次赋值）
判断同集合    Find(x)==Find(y) ？                  同上
课件口径      优化后查找、合并的时间复杂度都是常数级
```

### 完整代码模板（课程代码骨架）
```c
#include<stdio.h>
int fa[105], n, m, op, x, y;

int Find(int x){                 // 查找 + 路径压缩
    if(fa[x]==-1) return x;      // 根
    return fa[x]=Find(fa[x]);    // 先递归到根，回溯时直挂根
}
// 迭代版（无压缩，理解用）：
// int Find1(int x){int p=x;while(fa[p]!=-1)p=fa[p];return p;}

int main(){
    scanf("%d %d",&n,&m);
    for(int i=0;i<=n;i++) fa[i]=-1;      // 初始化：全员为根
    for(int i=1;i<=m;i++){
        scanf("%d %d %d",&op,&x,&y);
        int fx=Find(x), fy=Find(y);      // 先找两根
        if(op==1) fa[fy]=fx;             // 合并：y 的根挂到 x 的根
        else printf(fx==fy?"YES\n":"NO\n");  // 查询：同根 YES
    }
    return 0;
}
```

### 常见变形（考试扩展）
```
统计集合个数：数一遍 fa[i]==-1 的下标个数（根的个数=集合个数）
维护集合大小：size[i] 初值 1，合并时 size[fx]+=size[fy]（只更新新根）
带权并查集：额外维护到根的权值（关系量），Find 回溯时同步更新
```

### 易混点一分钟对照
```
fa[x]==-1 是根（本课代码约定）≠ 课件图示 fa[x]==x，一套代码只许一种
合并 = 根接根 fa[fy]=fx    ≠ fa[y]=x（错！）
压缩 = fa[x]=Find(fa[x])   ≠ Find(fa[x])（丢了赋值=没压缩）
```
