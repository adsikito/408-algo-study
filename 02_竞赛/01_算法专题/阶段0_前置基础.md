## 本章地图

在正式学任何算法之前，竞赛选手需要先回答三个问题：

1. **这个做法会不会超时？**——这是 0-1 复杂度估算。没有它，你写出的暴力程序会在评测机白跑两秒然后 WA（TLE），而你不知道该优化哪一层。
2. **同样的算法，为什么别人过了我 TLE？**——这是 0-2 卡常意识。同一复杂度的两种写法，常数差 2 至 5 倍是常态；输入输出、容器选型、循环顺序都藏常数。
3. **这个问题该拿哪个现成工具打？**——这是 0-3 的 STL 选型。STL 是 CCF / 蓝桥杯 / 洛谷普及场的「标准兵器库」，选对容器一行顶三十行。

路径安排：先建立复杂度的「量感」（0-1），再看常数花在哪里（0-2），最后把工具箱清点一遍（0-3、0-4）。
**量感 → 常数 → 工具**，之后阶段 1 至 8 的每个算法都默认你已经具备这三件事。

## 核心概念与模板

### 0-1　复杂度估算：算得出才敢写　【P0】【补充】

**是什么**：把「算法的基本操作次数」估成一个关于输入规模 n 的函数，再乘以「评测机每秒约 10^8 至 10^9 次简单操作」的经验常数，判断是否落在时限（通常 1 至 2 秒）内。

**为什么**：竞赛的 90% 的 TLE 不是「不会写优化」，而是**写之前没算过账**。估算能力决定了你拿到题的第一分钟该走暴力还是直接上正解。

**怎么用**：

**第一步：记住经验基准表**（按评测机 1 秒约 10^8 次操作、时限 1 秒计）：

| 复杂度 | n 的安全上限（1 秒） | 典型算法 |
|--------|---------------------|---------|
| O(n!) | 10 至 11 | 全排列暴力 |
| O(2^n) | 20 至 24（乘 n 约 20） | 子集枚举、状压 DP |
| O(n³) | 300 至 500 | Floyd、区间 DP 朴素实现 |
| O(n²) | 5000 至 1 万 | 朴素 DP、双重循环模拟 |
| O(n log n) | 约 10^6 | 排序、线段树、Dijkstra+堆 |
| O(n) | 约 10^7 至 10^8 | 双指针、桶计数、线性 DP |
| O(√n) | 约 10^12 | 试除判素、莫队分块 |
| O(log n) | 几乎不限 | 快速幂、二分 |

**第二步：复杂度相乘与相加**。嵌套循环相乘、并列段落取最大；
多组数据（T 组 × 每组 n）总复杂度是 O(T × n)，**T 很大时单组 n 的上限要除回去**。

**第三步：对数基不敏感**。log 的底数只差常数因子，估算时统一当 2 处理即可；
`10^6` 规模下 `log n ≈ 20`。

**第四步：留安全余量**。估算值贴着 10^8 时，若常数偏大（STL、递归、取模多），按可能 TLE 处理，先想优化再动手。

> **【规律】** 「数据范围反推算法」是竞赛第一直觉：
> 出题人给 n ≤ 10^5，就是在暗示 O(n log n) 以内；给 n ≤ 20，就是在暗示搜索或状压。
> **范围即提示**。

> **【记忆】** 10^8 是秒级门槛；n 每涨 10 倍，能用的复杂度就掉一个 log 档。

**前置与延伸**：
- 前置：无
- 延伸：均摊复杂度（`vector` 扩容、并查集路径压缩）、常数级的具体来源见 0-2

### 0-2　评测环境与卡常意识　【P0】【补充】

**是什么**：卡常 = 在**复杂度不变**的前提下压低常数因子。竞赛里的常数大头集中在三处：输入输出、容器选型、循环与访存方式。

**为什么**：同一题、同一算法，`cin` 不关同步比 `scanf` 慢 3 至 8 倍；
`endl` 比换行符慢一个数量级（本项目 `02_竞赛\02_竞赛C++\B_输入输出与性能.md` 实测约 32 倍，本地 MinGW g++ 8.1.0，相对关系稳定）。
时限 1 秒的题，常数差 3 倍就是过与不过的差别。

**怎么用**：

**输入输出三板斧**（按速度从慢到快）：

```cpp
?
?ios::sync_with_stdio(false);   /* 解除 C 与 C++ 流同步 */
cin.tie(nullptr);              /* 解绑 cin 与 cout 的强制刷新 */
/* 或直接用 scanf / printf；大数据量用 fread 快读（见 D 模块） */
```

- **禁止用 `endl`**（每处都强制刷新缓冲区），统一 `'\n'`。
- 输出量大时最后统一 flush，或用 `printf` / 快写。

**容器选型的常数差异**：

| 需求 | 首选 | 避开 | 原因 |
|------|------|------|------|
| 动态数组 | `vector`（**预分配** `reserve`） | 反复 `push_back` 不预留 | 扩容搬运浪费 |
| 键值映射（键少且范围小） | **数组打表** | `map` | `map` 每次访问 O(log n) 且常数大 |
| 去重存在性判断 | `sort` + `unique` / 布尔数组 | `set` | 同上 |
| 优先队列 | `priority_queue` | 手写堆（除非需删任意元素） | 标准库足够快 |
| 字符串大量拼接 | `string` + `reserve`，或字符数组 | 循环 `s = s + c` | 反复整串拷贝 |

**循环与访存**：

- 内层循环访问**连续内存**（行优先遍历二维数组），别跨行跳。
- 取模是除法，**比加减乘慢一个量级**：循环内的 `% MOD` 能省则省（先加后统一取模）。
- 递归层数深时考虑改迭代或加大栈空间；`unsigned long long` 与 `long long` 混用易触发隐式转换。
- 编译期常量用 `const` / `constexpr`，方便编译器内联。

**对拍意识**：写完先造小数据暴力对拍（暴力 + 随机数据），确认正确性再交；
卡常调整前后用**同一份大数据**计时比较，不凭感觉。

> **【注意】** 各 OJ 的 g++ 版本与是否默认 `-O2` 存在差异，绝对运行时间不可跨平台比较；
> 本工程所有性能结论只保证**相对关系**。上考场前查一次目标赛事的评测环境。

> **【规律】** 卡常优先级：**先换算法 / 复杂度，再换容器，最后才抠语句**。
> 复杂度差一档，语句级优化全白搭。

**前置与延伸**：
- 前置：知识点 0-1
- 延伸：完整实测数据与逐条写法对照见 `02_竞赛\02_竞赛C++\B_输入输出与性能.md` 与 `F_竞赛工程化与技巧.md`

## 本章难点

> **【难点】** **复杂度估算不是背表，而是「乘法分配」**：T 组数据 × 每组 n、外层枚举 × 内层二分（O(n log n)）、枚举子集 × 转移（O(2^n × n)）——考试 TLE 的多半是忘了乘另一维。

> **【难点】** **常数来源不可见但可测**：同样是 O(n log n)，`map` 版与「排序 + 双指针」版能差 5 倍。建立「先估复杂度、再选常数小的实现」的两步决策，而不是写完 TLE 才回头改。

## 本章易错点

> **【易错】** **头号易错：用 `endl` 输出换行**。每次输出都强制刷新缓冲区，输出量大的题直接 TLE。全工程统一 `'\n'`。

> **【易错】** **忘记多组数据总复杂度按乘积算**。T = 1000、单组 n = 10^5 的 O(n log n) 做法是 10^8 × log 量级，必炸；单组复杂度结论不能直接搬。

> **【易错】** **局部数组开太大爆栈**。`int a[10000000]` 写在函数内是 40 MB 栈分配，直接 RE。大数组一律开全局。

> **【易错】** **`int` 乘法中间溢出**。`int` 即使最终结果赋给 `long long`，**乘法本身已按 int 溢出**；正确写法是先把操作数转成 `long long` 再乘：`(long long)a * b`。

> **【易错】** **拿 `map` 当数组用**。值域不大时用 `map` 计数是常见坏习惯，常数是数组的几十倍；先看值域能不能开数组。

## 典型例题

### 例题 0-1　估算题　难度：模板题
**题干摘要**：n = 200000，时限 1 秒。下列做法哪些可能通过：(a) O(n²) 双重循环；(b) O(n log n) 排序 + 二分；(c) O(2^n) 子集枚举？

**题源**：通用判断题（非特定 OJ 题目，属估算基本功训练）。

**解题思路**：直接套 0-1 的基准表，n = 2 × 10^5。
**解答过程**：(a) 4 × 10^10 次操作，超出 10^8 四个数量级，**必 TLE**；
(b) 2 × 10^5 × 18 ≈ 3.6 × 10^6，**轻松通过**；
(c) 2^(2×10^5)，天文数字，**完全不可行**。答案：只有 (b)。

**复杂度**：估算本身 O(1)。
**易错提示**：不要因为「排序很常用」就觉得 O(n log n) 慢——它在 10^6 规模都是首选复杂度。

### 例题 0-2　卡常改造题　难度：变式题
**题干摘要**：读入 n = 10^6 个整数并输出它们的和。用 `cin` + `endl` 的写法超时，请改造。

**题源**：输入输出基本功训练；实测数据依据见 `02_竞赛\02_竞赛C++\B_输入输出与性能.md`。

**解题思路**：TLE 来源两处：流同步未关（读入慢）与 `endl` 强制刷新（输出慢）。
**解答过程**：
```cpp
?
?#include <cstdio>
int main() {
    int n;
    scanf("%d", &n);
    long long sum = 0, x;
    for (int i = 0; i < n; i++) {
        scanf("%lld", &x);
        sum += x;                    /* 累加和用 long long 防溢出 */
    }
    printf("%lld\n", sum);           /* '\n'，不用 endl */
    return 0;
}
```
若仍嫌慢（极端数据量），换 `fread` 快读（见 `D_STL算法.md` / `B` 模块的快读模板）。
**复杂度**：O(n)。
**易错提示**：求和变量必须是 `long long`：10^6 个 10^9 量级的数相加达 10^15，`int` 必溢出。

### 例题 0-3　数据范围反推算法　难度：综合题
**题干摘要**：给定 n ≤ 3000 的序列，求所有区间的最大值之和。直接枚举区间是 O(n³)（区间 O(n²) 个、每段求最大值 O(n)）。请在时限内解出。

**题源**：通用训练题（类似洛谷「区间贡献」类专题；具体题号待联网核实后补登记至题库）。

**解题思路**：n = 3000 时 O(n³) 是 2.7 × 10^10，必炸；O(n²) 是 9 × 10^6，可行。
目标：把「每段求最大值」从 O(n) 降到 O(1)。
**解答过程**：固定左端点 i，右端点 j 从 i 向右扫，**边扫边维护当前最大值**，内层变为 O(1)，总复杂度 O(n²)：
```cpp
?
?#include <cstdio>
#include <algorithm>
using namespace std;

int a[3005];
int main() {
    int n;
    scanf("%d", &n);
    for (int i = 0; i < n; i++) scanf("%d", &a[i]);
    long long ans = 0;                       /* n^2 个区间，和可能很大 */
    for (int i = 0; i < n; i++) {
        int mx = a[i];
        for (int j = i; j < n; j++) {
            mx = max(mx, a[j]);              /* 扫描中增量维护，避免重求 */
            ans += mx;                       /* 区间 [i, j] 的贡献 */
        }
    }
    printf("%lld\n", ans);
    return 0;
}
```
**复杂度**：时间 O(n²)，空间 O(n)。
**易错提示**：答案用 `long long`——3000² / 2 ≈ 4.5 × 10^6 个区间、每个最大值可达 10^9，总和远超 `int`。

## 本章总结

### 核心内容（一页纸）

- **10^8 是 1 秒的经验门槛**：O(n²) 撑 1 万、O(n log n) 撑 10^6、O(√n) 撑 10^12——先查表再动手。
- **数据范围即算法提示**：n ≤ 20 想指数暴力，n ≤ 5000 想平方，n ≤ 10^5 想 n log n。
- **多组数据的总复杂度 = T × 单组复杂度**，忘乘是 TLE 第一大原因。
- **输入输出三板斧**：关同步、解绑 `cin.tie`、**用 `'\n'` 永不用 `endl`**。
- **值域小用数组打表，别碰 `map`**；`vector` 记得 `reserve`；堆直接用 `priority_queue`。
- **大数组开全局**（防爆栈）；**两数相乘先转 `long long`**（防中间溢出）。
- **先换算法，再换容器，最后抠语句**——卡常的优先级顺序。
- 所有性能结论只保证**相对关系**，绝对时间依赖评测环境（g++ 版本、是否 `-O2`）。
