## 🗺️ 本章地图

> **本章解决一个问题：单点修改和区间查询都要 O(n) 的暴力太慢，怎么用一棵"分治出来的二叉树"把两者都压到 O(log n)？**
> 路线是"动机 → 结构 → 基本操作 → 进阶"：先明白暴力为什么 TLE（知识点 1）；再认识线段树——分治与二叉树的结合体，数组存树（2）；然后用 n=8 完整走一遍建树、单点修改、区间查询（3）；最后攻坚区间修改的懒标记——"先欠着账，查到再还"（4）。
> 学完请自测三件事：能不能默写 `tree[4n]` 的建树模板？说清完全覆盖/部分覆盖两种情况各怎么处理？解释懒标记为什么"欠账"还能保证复杂度？

## 📌 本章重点（3-5个）

⭐ **线段树的结构**：分治建树，每个节点存一段区间，叶子存单元素，`mid=(l+r)/2` 平分给左右儿子
⭐ **数组存树**：近似完全二叉树，节点 o 的左儿子 `2o`、右儿子 `2o+1`，数组开 4n 防越界
⭐ **单点修改与区间查询**：递归定位 + 回溯时 `sum = 左儿子 + 右儿子`，单次 O(log n)
⭐ **懒标记 lazy-tag**：区间修改只改覆盖节点并记账，下传（down）时才真正改儿子
⭐ **完全覆盖 vs 部分覆盖**：`tree[i].l>=le && tree[i].r<=ri` 直接返回/整段改，否则下传后分两侧递归

## 🔥 本章难点（2-3个）

🔥 **懒标记的正确性与时机**：为什么"只改覆盖节点的 sum，儿子先不改"是对的；为什么**查询和修改碰到部分覆盖时都必须先 down**，漏写 down 直接答案错
🔥 **递归边界的判断**：`if(le<=mid)` / `if(ri>=mid+1)` 决定往哪边递归，判断写错会越界访问不存在的节点或漏算区间
🔥 **复杂度的直观理解**：建树 O(n)、单点/区间操作 O(log n)，为什么树高 log n 就保证了这些界

## ⚠️ 本章易错点（3-5个）

⚠️ **tree 数组开成 n**：线段树不是满二叉树，最后一层可能多出一截，必须开 **4n**（课件原话：可能存在空间浪费），开小了直接 RE
⚠️ **下传后忘记清空 tag**：`down(i)` 把 tag 传给儿子后必须 `tree[i].tag=0`，否则同一笔账被算多次（例题代码注释"注意"处）
⚠️ **修改连续多次时 tag 要累加**：写 `tree[i].tag=k` 覆盖旧账就错了，必须 `tree[i].tag+=k`——"有可能连续多次修改"
⚠️ **down 里儿子 sum 的更新量算错**：区间加 k 时儿子 sum 应加 `(儿子区间长度)*k`，即 `r-l+1` 乘 k，不是只加 k
⚠️ **节点编号从 0 开始**：若根为 0，则左儿子 2*0=0 自我循环；必须从 **1** 号节点开始建树（例题 `Build(1,1,n)`）

## 📖 知识点讲解

### 1. 为什么需要线段树：从暴力到 log

**是什么**：线段树是一棵**二叉搜索树**，每个节点存储一个区间（线段）的信息（区间和、最值等），"搜索"就是在这些线段上定位到你想要的区间。它能在 **O(log n)** 内完成单点修改、区间修改、区间查询（求和/最大值/最小值）。

**为什么**：以 P3372 为例——n 个数、m 次操作，暴力"改一个点 O(1) 但查区间和 O(n)"或"维护前缀和 O(1) 查但改一点要 O(n) 重算"，总复杂度 O(nm)=O(n²)，必然 TLE。矛盾在于"改得快"和"查得快"不可兼得——直到我们把区间组织成树：**大区间的解可以由小区间的解合并而来**，每个节点的值代表整棵子树区间的答案，查询子树时直接读根，不必遍历到底。

**怎么用**：判断一道题能不能上线段树，只看一句话——**要维护的信息满足"区间可合并"**（和能相加、max/min 能取大取小）。不满足可合并的信息（如中位数）线段树无能为力。

> ⚠️ 注意事项：线段树是"维护区间信息的数据结构"，不是只会求和——sum、max、min、计数都能当节点值。

> 🎯 规律：改得快与查得快的矛盾，用"分治树"一举两得。
> 💡 一句话总结：区间可合并，才配上线段树。

### 2. 建树：分治与二叉树的结合体

**是什么**：对区间 [l,r]：若 l==r 就是叶子，存单元素；否则取 `mid=(l+r)/2`，左儿子管 [l,mid]、右儿子管 [mid+1,r]（类似归并排序的"分"），回溯时 `tree[i].sum = tree[2i].sum + tree[2i+1].sum`。因为除最后一层外每层都满（近似完全二叉树），可以直接用数组存：节点 o 的左儿子 `2o`、右儿子 `2o+1`。建树复杂度 **O(n)**。

**为什么**：树高为 ⌈log₂n⌉，从根到任何叶子只走 log n 步——这是后面修改/查询都是 O(log n) 的根本原因；用数组而非指针存树，省去动态分配，且父子关系一个乘法就能算出来。

**怎么用**——跟着算（n=8，a = 1 3 5 7 9 11 13 15），建出来的树（括号内是数组下标）：

```
                 1:[1,8]Σ64
              /              \
      2:[1,4]Σ16             3:[5,8]Σ48
      /       \              /        \
 4:[1,2]Σ4   5:[3,4]Σ12  6:[5,6]Σ20   7:[7,8]Σ28
  /    \       /    \      /    \       /     \
8:[1]  9:[2] 10:[3] 11:[4] 12:[5] 13:[6] 14:[7] 15:[8]
 Σ1    Σ3    Σ5     Σ7     Σ9     Σ11    Σ13    Σ15
```

数组形态：`tree[] = {64, 16, 48, 4, 12, 20, 28, 1, 3, 5, 7, 9, 11, 13, 15}`（下标 1~15）。建树时先分到底（递归左右儿子），再回溯把两个儿子的 sum 加起来填父节点——n=8 恰好是满二叉树共 2n-1=15 个节点。

```cpp
void Build(int i, int le, int ri) {
    tree[i].l = le; tree[i].r = ri;
    if (le == ri) { tree[i].sum = a[le]; return; }   // 叶子
    int mid = (le + ri) / 2;
    Build(2*i, le, mid);  Build(2*i+1, mid+1, ri);
    tree[i].sum = tree[2*i].sum + tree[2*i+1].sum;   // 回溯合并
}
```

> ⚠️ 注意事项：数组要开 `4n`；n 不是 2 的幂时最后一层会"断开"，靠 4n 兜底。

> 🎯 规律：mid 平分天下，父亲等于儿子之和。
> 💡 一句话总结：自顶向下分，自底向上合。

### 3. 单点修改与区间查询

**是什么**：**单点修改**：递归找到目标叶子（靠 `x<=mid` 走左、否则走右），改掉叶子值，回溯路上把所有祖先的 sum 重算——一个点变，它的全部父节点都得变。**区间查询**[le,ri]：当前节点区间被查询区间**完全覆盖**（`l>=le && r<=ri`）→ 直接返回它的 sum；否则**部分覆盖** → 分别看左右两侧有无交集，有则递归。

**为什么**：修改只影响根到叶子这一条链（log n 个节点）；查询时"完全覆盖就整块拿走"保证了任何区间只需拆成 O(log n) 个整块，不必摸到每个叶子——这就是 O(log n) 的来源。

**怎么用**——跟着算（用上面 n=8 的树）：

单点修改：a[5] 加 9（9→18）。从根出发：5>mid=4 走右儿子 3；3 的 mid=6，5<=6 走左儿子 6；6 的 mid=5，5<=5 走左儿子 12（叶子 [5,5]）。改完后回溯更新一条链：
```
node12: 9→18 → node6: 20→29 → node3: 48→57 → node1: 64→73
```

区间查询：query(2, 6)，从根递归：
```
node1 [1,8]：不完全覆盖(1<2)，mid=4 → 两边都递归
├─ node2 [1,4]：不完全覆盖(1<2)，mid=2 → 只递归有交集的一侧
│   ├─ node4 [1,2]：不完全覆盖(1<2)，mid=1 → 左[1,1]无交集跳过，右递归
│   │   └─ node9 [2,2]：完全覆盖 → 返回 3
│   └─ node5 [3,4]：完全覆盖 → 返回 12
└─ node3 [5,8]：不完全覆盖(8>6)，mid=6 → 左递归，右(ri=6≥7?否)跳过
    └─ node6 [5,6]：完全覆盖 → 返回 20
答案 = 3 + 12 + 20 = 35   （验算：3+5+7+9+11 = 35 ✓）
```

> ⚠️ 注意事项：判断"往哪边递归"用 `if(le<=mid)` 和 `if(ri>=mid+1)`，两行缺一不可——查询区间完全落在另一侧时不能白进空子树。

> 🎯 规律：完全覆盖整块拿，部分覆盖往下钻。
> 💡 一句话总结：改一条链，查 log n 块。

### 4. 区间修改与懒标记 lazy-tag

**是什么**：区间修改如果"对区间内每个点都跑一遍单点修改"，最坏退化成 O(n)。懒标记的做法：`tag[i]` 记录"节点 i 的整段区间欠下的修改"。修改时若节点区间被**完全覆盖**，只把它的 `sum += 区间长度*k`、`tag += k` 就返回——**内部元素先不改**（"一会再修改"）；等到后续操作必须进入它的儿子时（部分覆盖），才执行 `down(i)` 把账下传：儿子的 sum、tag 各自更新，然后 `tree[i].tag=0` 清账。

**为什么**：一笔"+k"对整段的效果是确定的（sum 加上 长度×k），不需要立刻通知每个元素；只有当要访问儿子时这笔账才必须先还，否则儿子的 sum 和真实值对不上。这样每次修改/查询仍只碰 O(log n) 个节点，区间修改也保持 O(log n)。

**怎么用**——跟着算（n=8 的树，操作：区间 [1,4] 每个数 +2，随后查询 [3,4]）：

```
修改 [1,4] +2：
node1 [1,8] 不完全覆盖 → down(1)(无账) → mid=4 → 只进左
node2 [1,4] 被 [1,4] 完全覆盖 → tag=2, sum=16+4*2=24，直接返回
（此刻 node4、node5 的 sum 还是旧值——账欠着）

查询 [3,4]：
node1 不完全覆盖 → down(1)：tag=0 无事
node2 [1,4] 不被 [3,4] 完全覆盖(1<3) → 先 down(2)：
    node4.sum += 2*2 = 8,  node4.tag += 2
    node5.sum += 2*2 = 16, node5.tag += 2
    node2.tag = 0（清账！）
    mid=2：左(le=3>2 跳过)，右递归
node5 [3,4] 完全覆盖 → 返回 16   （验算：7+9=16 ✓）
```

```cpp
void down(int i) {                        // 下传懒标记
    if (tree[i].tag != 0) {
        tree[2*i].tag   += tree[i].tag;
        tree[2*i].sum   += (tree[2*i].r - tree[2*i].l + 1) * tree[i].tag;
        tree[2*i+1].tag += tree[i].tag;
        tree[2*i+1].sum += (tree[2*i+1].r - tree[2*i+1].l + 1) * tree[i].tag;
        tree[i].tag = 0;                  // 清账
    }
}
void Update(int i, int le, int ri, ll k) {
    if (tree[i].l >= le && tree[i].r <= ri) {   // 完全覆盖
        tree[i].tag += k;  tree[i].sum += (tree[i].r - tree[i].l + 1) * k;
        return;
    }
    down(i);                              // 部分覆盖：先把欠的账还了
    int mid = (tree[i].l + tree[i].r) / 2;
    if (le <= mid)  Update(2*i, le, ri, k);
    if (ri >= mid+1) Update(2*i+1, le, ri, k);
    tree[i].sum = tree[2*i].sum + tree[2*i+1].sum;
}
ll query(int i, int le, int ri) {
    if (tree[i].l >= le && tree[i].r <= ri) return tree[i].sum;
    down(i);                              // 查询也要下传！
    int mid = (tree[i].l + tree[i].r) / 2;  ll ans = 0;
    if (le <= mid)  ans += query(2*i, le, ri);
    if (ri >= mid+1) ans += query(2*i+1, le, ri);
    return ans;
}
```

> ⚠️ 注意事项：Lazy 的精髓——"平时先把事情放着，等检查到哪部分才临时做哪部分"（课件原话）；**修改和查询里都要 down**，只在一处写是常见事故。

> 🎯 规律：整段打标记，进入才下传，传完必清零。
> 💡 一句话总结：欠账不赖账，查前先还清。

## 🔍 相似概念辨析

**组1：线段树 vs 树状数组（下一章主角）**

| 维度 | 线段树 | 树状数组 |
|------|--------|----------|
| 代码量 | 建树+down+Update+query，几十行 | 一个 lowbit 套路，十来行 |
| 区间修改 | 天然支持（懒标记） | 需配合差分才能做 |
| 可维护信息 | 任意可合并信息（和/max/min/计数） | 本质只有前缀和类（和、靠差分扩展） |
| 单点修改+前缀查询 | 支持，但杀鸡用牛刀 | 最擅长，更快更短 |
| 思想 | 分治二叉树 | 二进制低位分解（lowbit） |
| 空间 | 4n | n |
| 适用场景 | 区间改+区间查、max/min、扫描线 | 单点改+前缀查、求逆序对 |

**组2：单点修改 vs 区间修改（懒标记）**

| 维度 | 单点修改 | 区间修改（带懒标记） |
|------|----------|---------------------|
| 影响范围 | 根到叶子一条链 | 一批被完全覆盖的子树根 |
| 是否需要 tag | 不需要 | 必须要 |
| 复杂度 | O(log n) | O(log n)（无 tag 会退化到 O(n)） |
| down 的必要性 | 无 | 修改/查询碰到部分覆盖都必须先 down |
| 实现难度 | 低 | 高（down、清账、累加三处易错） |
| 典型题目 | P1531、LC 307 | P3372、P1471 |
| 共同点 | 都要回溯重算 sum；都靠"完全覆盖提前返回"剪枝 | 同左 |

## 🧩 本章归纳

一条主线：**"区间可分治 → 树形组织 → 懒惰 owe 账"**。暴力在"改得快"与"查得快"之间二选一，线段树用分治把区间建成一棵近似完全二叉树：建树自顶向下分、自底向上合（O(n)）；单点修改沿一条链改（O(log n)）；区间查询把查询区间拆成 O(log n) 个完全覆盖的整块；区间修改靠懒标记只改覆盖根、把细活推迟到必须进入时才做（down 下传+清零）。P3372 的四件套 `Build / down / Update / query` 就是全部骨架——换个维护的信息（max、min、平方和），变的只是"合并"那一行。

## 📋 速查表

| 项目 | 内容 |
|------|------|
| 数组大小 | `tree[4*n]`（防止最后一层越界） |
| 节点编号 | 根为 1，左儿子 `2i`，右儿子 `2i+1` |
| 叶子判定 | `l == r` → `sum = a[l]` |
| 分治中点 | `mid = (l + r) / 2`，左 [l,mid]，右 [mid+1,r] |
| 完全覆盖 | `tree[i].l>=le && tree[i].r<=ri` → 直接返回/整段打 tag |
| 递归条件 | `if(le<=mid)` 进左；`if(ri>=mid+1)` 进右 |
| 懒标记下传 | 儿子 `sum += 儿子区间长 * tag`、`tag += tag`，然后 `tag=0` |
| 复杂度 | 建树 O(n)；单点改/区间改/区间查 均 O(log n) |
| 纪律 | 部分覆盖前必 down；tag 累加不清零覆盖；long long 保平安 |
