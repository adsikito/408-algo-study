## 本章地图

本章解决一个问题：**「修改与查询交织，怎么都保持对数级？」**

```text
前缀和：建 O(n)、查 O(1)、改 O(n)   ← 静态场景无敌
差分：  改 O(1)、单点查 O(1)、区间查 O(n)
   ↓
两者的短板：动态 + 区间查不可兼得
   ↓
线段树：[1, n] 递归二分，每结点存聚合值
   ├─ 修改：从根到叶的一条链 → O(log n)
   ├─ 查询：区间分解成 O(log n) 个结点 → O(log n)
   └─ 懒标记：区间整体操作「打标停」，用不到不下传
   ↓
改写：聚合换成 max → 区间最值版（知识点 3）
```

**为什么这条路径是这样**：线段树的复杂度来自**「区间分解」**——
任何区间被拆成 O(log n) 个整结点，修改 / 查询都只在分解结点处停。
**「全含打标停」是同一思想的修改侧表达：整段一起记，不递归到底。**

## 核心概念与模板

**是什么**：线段树把 [1, n] 递归二分：每结点管一个区间、存聚合值（和 / 最值）。

**为什么**：**单点 / 区间修改 O(log n)、区间查询 O(log n)**——
前缀和只能静态查，线段树把「改」也纳入 log 代价。
识别信号：修改与查询交织、区间最值 / 覆盖、动态开点。
前置依赖（真源 README）：阶段 1 前缀和差分是其静态对照。

> **【规律】** **懒标记三原则**：①全含才打标（部分交必须先 pushdown）；
> ②下传后父标记清零；③**update 与 query 都要 pushdown**——
> 漏一处答案错且难查。

**怎么用**：

```cpp
// g++ -std=c++17 -O2
#include <cstdio>
#include <cstring>
typedef long long ll;
const int N = 100005;
int n;
ll a[N], sum[4 * N], lz[4 * N];          /* 4n 空间；lz：加法懒标记 */

void build(int p, int l, int r) {
    if (l == r) { sum[p] = a[l]; return; }
    int mid = (l + r) / 2;
    build(2 * p, l, mid);
    build(2 * p + 1, mid + 1, r);
    sum[p] = sum[2 * p] + sum[2 * p + 1]; /* 回溯聚合 */
}

void apply(int p, int l, int r, ll v) {   /* 打标记：本区间整体 +v */
    sum[p] += v * (r - l + 1);
    lz[p] += v;
}

void pushdown(int p, int l, int r) {      /* 标记下传 */
    if (lz[p]) {
        int mid = (l + r) / 2;
        apply(2 * p, l, mid, lz[p]);
        apply(2 * p + 1, mid + 1, r, lz[p]);
        lz[p] = 0;
    }
}

void update(int p, int l, int r, int ql, int qr, ll v) {
    if (qr < l || r < ql) return;         /* 不相交 */
    if (ql <= l && r <= qr) { apply(p, l, r, v); return; }  /* 全含：打标停 */
    pushdown(p, l, r);                    /* 部分交：下传再递归 */
    int mid = (l + r) / 2;
    update(2 * p, l, mid, ql, qr, v);
    update(2 * p + 1, mid + 1, r, ql, qr, v);
    sum[p] = sum[2 * p] + sum[2 * p + 1];
}

ll query(int p, int l, int r, int ql, int qr) {
    if (qr < l || r < ql) return 0;
    if (ql <= l && r <= qr) return sum[p];
    pushdown(p, l, r);
    int mid = (l + r) / 2;
    return query(2 * p, l, mid, ql, qr) + query(2 * p + 1, mid + 1, r, ql, qr);
}
```

> **【类比】** 懒标记像**部门经理的授权**：总部（根）下发一个「整层涨薪」的文件
> （懒标记），**经理先挂在墙上不执行**（sum 已更新），等有人真来查基层细节时
> 才转发给下属（pushdown）——
> **「没人查就不下发」是效率来源，「下发后销毁原件」是正确性保障。**

## 本章难点

> **【难点】** **懒标记三原则的「各自反例」。**
> ①部分交就打标 → 未覆盖的格被错加；②下传不清零 → 重复下发；
> ③query 不 pushdown → 查询读到过期值。**三原则各配一个反例来记**，
> 赛场自查按三条顺序过一遍。

> **【难点】** **「何时需要懒标」的设计判断。**
> 区间**整体**操作（加 / 乘 / 覆盖）→ 可懒；**结构性操作**（区间排序、
> 非规律修改）→ 不可懒，需别的设计。
> 判断标准：**一个标记能否 O(1) 表达「对整个区间的聚合影响」**。

---

## 本章易错点

> **【头号易错】** **懒标记三原则破一条**：①全含才打标（部分交必须先 pushdown）；
> ②下传后父标记清零；③update 与 query 都要 pushdown——漏一处答案错且难查。

> **【易错】** **数组只开 n**（要 **4n**）；离散化后动态开点的计数忘。

> **【易错】** **乘法标记（乘加混合标记）时下传顺序（先乘后加）错**。

> **【易错】** **查询返回值的单位元**：max 版返回 −INF 而不是 0（求和版才返回 0）。

> **【易错】** **build 后忘了同步 a 数组与 sum**（单点改时 a 与树都改）。

## 典型例题

### 例 1　区间加 + 区间求和（模板）　难度：模板题

**题干摘要**：n ≤ 10⁵、m ≤ 10⁵，操作为区间加或区间求和。
**题源**：同类真源见配套 T1（P3372 线段树 1）
**涉及知识点**：知识点 1、2

**解题思路**：

1. **信号**：「改后立刻查区间和」→ 懒标记线段树。
2. **方法**：核心模板全量。

**复杂度**：build O(n)，每操作 O(log n)。

> **【易错】** 差分（阶段 1）做不了「改后立刻查区间和」——
> 这正是线段树的登场条件，答案里可先给差分对照说明。

---

### 例 2　区间最值 + 单点修改（最值版）　难度：变式题

**题干摘要**：维护区间 max，支持单点改与区间查 max。
**题源**：线段树最值版（对照练习见配套 T2 的跨篇引用——P1531 单点改区间查 max）
**涉及知识点**：知识点 3、4

**解题思路**：

1. **信号**：「区间最值 + 单点改」→ max 版线段树。
2. **方法**：把聚合换成 max：apply 退化为单点赋值（可去懒标）；merge = max(a, b)。

**复杂度**：每操作 O(log n)。

> **【易错】** max 版无需懒标记（单点赋值）——
> 「何时需要懒标」的判断（区间整体操作才需要）是本题考点。

## 本章总结

### 核心内容（一页纸）

1. **三段分工**：静态 → 前缀和；动态 + 区间查 → 线段树；轻量动态 → 树状数组。
2. **三参递归（p, l, r）+ 三分支**：不交返回 / 全含打标停 / 部分交下传递归。
3. **懒标记三原则**：全含才打标、下传清零、update 与 query 都 pushdown。
4. **4n 空间**；动态开点处理大值域。
5. **聚合可替换**：sum → max（max 版返回 −INF，单点改免懒标）。
6. **「何时需要懒标」**：标记能 O(1) 表达对整段聚合的影响。
7. **乘加混合下传顺序**：先乘后加。
8. **build / update / query 的回溯聚合**都不能漏。
9. **与差分的对照**：差分管「改后单点查」，线段树管「改后区间查」。
10. **分治思想的动态化**——阶段 2 的最终归宿。
