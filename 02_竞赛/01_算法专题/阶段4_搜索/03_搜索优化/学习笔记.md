## 🗺️ 本章地图

> **本章解决一个问题：DFS 本质是暴力枚举，复杂度爆炸，怎么让它"少干蠢事"？**
> 路线是"一个认识 → 两把剪刀"：先明确搜索的优化统称剪枝，本质是减少对不合法及重复答案的枚举，并立起通用深搜模板（知识点 1）；最优性/可行性剪枝用 P1025 数的划分示范"提前判断必败就整枝砍掉"（知识点 2）；记忆化搜索用 P1464 Function 示范"相同传入值的答案存进数组，第二次直接抄"（知识点 3）。这也是通往动态规划的第一座桥。
> 学完请自测三件事：可行性剪枝与最优性剪枝分别判什么？记忆化成立的条件是什么？P1464 为什么负数特判必须写在访问数组之前？

## 📌 本章重点（3-5个）

⭐ **剪枝的本质**：搜索复杂度特别高（本质仍是暴力），减小状态空间、更改搜索顺序、剪枝、记忆化等优化统称剪枝——本质都是减少对不合法及重复答案的枚举
⭐ **最优性/可行性剪枝**：当前解已比已有解更差，或可明确判断当前解不合法时，立即停止搜索
⭐ **P1025 数的划分**：升序记录划分去重（last 保证当前 ≥ 上次）+ 剪枝"sum+i*(k-stp+1)>n 就 break"
⭐ **记忆化搜索**：相同传入值带来相同解 → 用数组记忆已遍历状态的信息，避免重复遍历；每个状态只访问一次；也是常见的动态规划实现方式
⭐ **P1464 Function**：三维数组 f[a][b][c] 记录 w(a,b,c)（范围 0~20），负数与超界先特判

## 🔥 本章难点（2-3个）

🔥 **剪枝条件的推导**：P1025 为什么是 `sum+i*(k-stp+1)>n` 就 break？——升序下剩余 k-stp+1 份每份至少为 i，最小总和已超 n，后面的 i 只会更大，整段枚举全部作废；这步"给未来定下界"的推理是剪枝的灵魂
🔥 **记忆化的状态设计**：能记忆化的前提是"参数相同 ⇒ 答案相同"且状态能用数组下标表示——P1464 要先看出 a>20 时函数值都等于 w(20,20,20)，才能把无限参数域压进 21³ 的数组

## ⚠️ 本章易错点（3-5个）

⚠️ **该 break 写成 continue**：P1025 中 sum+i*(k-stp+1)>n 时，i 再大只会更超，必须 break 砍掉整段；写 continue 只跳过当前值，剪枝效果全无
⚠️ **记忆数组忘了初始化 / 语义混掉**：`memset(f,-1,sizeof f)` 用 -1 表示"没算过"；若拿 0 当"没算过"，遇到答案恰为 0 的状态会重复死算
⚠️ **负数下标不特判**：课件原话强调——输入可能有负数，只写 `if(dp[x][y][z])` 会因**数组没有负数下标**直接炸掉；`a<=0||b<=0||c<=0` 的判断必须放在最前面
⚠️ **去重想靠 vis**：数的划分"不重复"靠**升序记录**（last），不是 used 数组；套用排列题的 vis 反而把 1+1+5 这类含相同数的合法解剪没了
⚠️ **递归出口判一半**：P1025 的出口是 stp>k 后再判 sum==n；若中途见 sum==n 就 return，会漏掉后面还能填数（或提前断送）的分支

## 📖 知识点讲解

### 1. 为什么要剪枝：搜索的代价与通用模板

**是什么**：白话——DFS 是"把所有可能都走一遍"的老实人，走之前先问一句"这条路还有戏吗"能省下整片森林。课件定义：搜索是对状态空间进行枚举、穷尽所有可能来找到最优解或统计合法解个数，但**其时间复杂度特别高，因为 DFS 本质上还是暴力枚举答案**；搜索有很多优化方式（减小状态空间、更改搜索顺序、剪枝等），**统称为剪枝**——无论何种方式，**本质都是想办法减少对不合法及重复的答案的枚举**。常用的剪枝：最优性/可行性剪枝、记忆化搜索。

**为什么**：不优化的 DFS 状态数是指数/阶乘级（如 n=7,k=3 尚可，n=100 就完蛋）；剪掉一个分支 = 少算一整棵子树，早剪比晚剪划算，能在"进入递归前"判死就别"递归完再回头"。

**怎么用**——通用深搜模板（课件："先来一段深搜模板，之后的模板将在此基础上进行修改"）：
```cpp
void dfs(状态参数)
{
    if(到达终点/边界){ 记录或输出答案; return; }   // 出口
    if(剪枝条件) return;                          // ← 优化都加在这一带
    for(枚举每一个可行选择)
    {
        做选择(标记/累加);
        dfs(下一层状态);
        撤销选择(回溯);
    }
}
```
两种剪枝的判断口诀（课件）：**最优性剪枝**——当前解已经比已有解更差，不用再走；**可行性剪枝**——可明确判断当前解不合法（或必然非法），不用再走。

> ⚠️ 注意事项：剪枝条件必须"宁枉勿纵"地正确——错杀合法分支会丢答案；剪枝写在 for 之前还是循环体内，取决于它判的是"整个分支"还是"某个具体选择"。

> 🎯 规律：写完暴力先跑小数据确认正确，再问"哪一步明知没戏还在走？"——答案就是你的剪枝条件。

> 💡 一句话总结：提前认输，整枝砍掉。

### 2. 可行性剪枝实战：数的划分（P1025）

**是什么**：白话——把整数 n 分成 k 份（每份正整数，顺序不计：1,1,5 与 5,1,1 算一种），求方案数。课件思路：**DFS+可行性剪枝**。因为要不重复，所以**按升序记录每一次划分**：记录上一次划分所用的数 last，保证当前划分所用数不小于上次；当划分次数等于 k 时，比较该次划分总分是否等于 n 并计数。剪枝：枚举当前划分所用分数 i 时，从 last 枚举到 `sum+i*(k-cur)<=n` 为止就停——因为之后划分的分数一定大于或等于当前分数，再大必然超。

**为什么**：两层优化各管一件事——**升序**消灭"同一组数的不同排列"这类重复答案（5+1+1、1+5+1 全被压成 1,1,5 只数一次）；**剪枝**消灭"明知会超和还继续枚举"的不合法分支。代码里循环上界还收紧到 `i<=n-k+1`：升序下最大的一份 ≤ n-k+1（其余 k-1 份每个至少 1）。

**怎么用**——模板（`P1025.cpp`）：
```cpp
void dfs(int last,int stp,int sum)   // 上次选的数 / 当前第几份 / 已选总和
{
    if(stp>k){ if(sum==n)ans++; return; }        // 填满 k 份再验收
    for(int i=last;i<=n-k+1;i++)                 // 升序：i≥last
    {
        if(sum+i*(k-stp+1)>n) break;             // 可行性剪枝！！
        dfs(i,stp+1,sum+i);                      // 记录 i，继续下一份
    }
}
// 调用：dfs(1,1,0);
```
跟算：n=7, k=3：
```
升序枚举出的全部解：1+1+5、1+2+4、1+3+3、2+2+3 → ans=4
去重演示：5+1+1、1+5+1 都被"升序"压成 1,1,5，只数一次 ✓
剪枝演示：路径 1,5 之后（sum=6, stp=3）枚举 i=5：
    6 + 5×1 = 11 > 7 → break，i≥5 全不用看
    （手工验证剪得对：第三份须 ≥5，6+5 已超，更不可能）
若无这行 break：i 要从 5 空转到 n-k+1 才罢休，分支越深浪费越多
```

> ⚠️ 注意事项：出口是 `stp>k` 而不是 `sum==n`；去重靠 last 的升序约束而非标记数组；剪枝用 break（整段舍弃）不是 continue。

> 🎯 规律："和固定/上限固定"的构造类搜索，用"剩余份数 × 当前最小值"算出理论下界，超了就整段砍。

> 💡 一句话总结：升序去重，超和即断。

### 3. 记忆化搜索：Function（P1464）

**是什么**：白话——递归函数第一次算出答案时抄在小本本上，第二次再被问到直接念答案。课件定义：在搜索中，**相同的传入值往往会带来相同的解**，那就可以用数组来记忆已经遍历过的状态的信息，从而**避免对同一状态重复遍历**；这种实现方式**确保了每个状态只访问一次**，它也是一种常见的动态规划实现方式。P1464 的递归函数 w(a,b,c) 分段：a<0||b<0||c<0 时返回 1；a>20||b>20||c>20 时返回 w(20,20,20)；a<b<c 走一条递归式，否则走另一条。用**三维数组 dp[a][b][c] 记录 w(a,b,c) 的值**（0~20 以内的答案存下来），下次递归时有记录就直接返回。

**为什么**：直接 DFS 模拟，w(20,20,20) 会把同一子问题（如 w(15,15,15)）成千上万次重复展开，指数爆炸；而答案只依赖 0~20 范围内的参数，状态总数 ≤ 21³=9261——记忆化把"算过的只算一次"，复杂度从指数掉到状态数级别。

**怎么用**——关键代码（`P1464.cpp`）：
```cpp
int f[25][25][25];
ll w(ll a,ll b,ll c)
{
    if(a<=0||b<=0||c<=0) return 1;        // 特判放最前：负数不能当数组下标！
    else if(a>20||b>20||c>20)             // 超界统一映射到 (20,20,20)
    {
        if(f[20][20][20]!=-1)return f[20][20][20];
        return f[20][20][20]=w(20,20,20);
    }
    // …以下每个分支：先查 f，没算过才算并存档（如）：
    else
    {
        if(f[a-1][b][c]==-1)f[a-1][b][c]=w(a-1,b,c);
        ……
        return f[a-1][b][c]+f[a-1][b-1][c]+f[a-1][b][c-1]-f[a-1][b-1][c-1];
    }
}
// 主程序：memset(f,-1,sizeof f);  多组输入读到 -1 -1 -1 为止
```
跟算：
```
w(1,1,1)：不超界、非 a<b<c → else 分支
        = w(0,1,1)+w(0,0,1)+w(0,1,0)−w(0,0,0)
        = 1 + 1 + 1 − 1 = 2，f[1][1][1]=2 存档 → 再问秒回
w(30,30,30)：触发 a>20 → 映射到 w(20,20,20)=1048576（也存档）
对比：不加记忆化，w(20,20,20) 的递归调用树指数膨胀跑不完；
     加了记忆化，最多 21³=9261 个状态、每个只真正计算一次。
```

> ⚠️ 注意事项：`a<=0||b<=0||c<=0` 的特判必须写在访问数组**之前**（课件强调只写 if(dp[x][y][z]) 会炸）；f 初始化为 -1 区分"没算过"；多组询问共用同一张记忆表（这正是记忆化的红利）；输出格式照题目 `w(a, b, c) = ans` 抄。

> 🎯 规律：递归函数"参数相同 ⇒ 返回值相同"且参数可映射到有限数组下标 → 就能记忆化；先缩小参数域（如 >20 全映射到 20）再开数组。

> 💡 一句话总结：算过的存起来，第二次直接抄。

## 🔍 相似概念辨析

**组1：爆搜 vs 记忆化搜索**

| 对比维度 | 爆搜（朴素 DFS） | 记忆化搜索 |
|---|---|---|
| 各自定义 | 对状态空间全部枚举，重复状态重复算 | 相同传入值的答案存数组，算过直接返回 |
| 核心区别 | 同一状态可能被访问指数次 | 每个状态只访问一次（课件原话） |
| 各自特点 | 代码最短，n 一大必 TLE | 多一个 memo 数组与"查-存"两步 |
| 使用场景 | 数据范围极小、状态互不相同 | 状态可作数组下标且参数域有限（P1464 的 0~20³） |
| 典型示例 | 裸算 w(20,20,20) 跑不完 | 记忆化后 9261 个状态封顶 |
| 记忆口诀 | 爆搜会重算，记忆化只算一遍 |

**组2：可行性剪枝 vs 最优性剪枝**

| 对比维度 | 可行性剪枝 | 最优性剪枝 |
|---|---|---|
| 各自定义 | 可明确判断当前解不合法时停止 | 当前解已比已有解更差时停止 |
| 核心区别 | 判"还行不行" | 判"还值不值" |
| 各自特点 | 常用下界/剩余量推算（P1025 的 break） | 常配全局最优解变量边搜边比 |
| 使用场景 | 构造满足约束的方案（数的划分、八皇后） | 搜索求最值（最短路、最大得分） |
| 典型示例 | sum+i*(k-stp+1)>n → break | 求最短时步数已超过当前最优 → return |
| 记忆口诀 | 可行性剪不合法，最优性剪不更优 |

**组3：记忆化搜索 vs 递推 DP**

| 对比维度 | 记忆化搜索 | 递推 DP |
|---|---|---|
| 各自定义 | 自顶向下：递归+查表，要哪个算哪个 | 自底向上：循环按序填表 |
| 核心区别 | 状态稀疏也能只算被需要的 | 从边界出发把全部状态算完 |
| 各自特点 | 不用想转移顺序，递归式即代码（课件：记忆化是 DP 的常见实现方式） | 无递归开销，常可滚动数组优化 |
| 使用场景 | 转移顺序难定、状态不对称（P1464） | 转移规整成循环（背包、线性 DP） |
| 典型示例 | w(a,b,c) 递归 + f 数组 | 三重 for 递推 f[a][b][c] |
| 记忆口诀 | 记忆化是懒人版的 DP |

## 🧩 本章归纳：一条主线串全章

主线因果链：**DFS=暴力枚举状态空间（第十五章的遗产）→ 复杂度爆炸 → 一切优化统称剪枝，本质是减少对不合法及重复答案的枚举 → 对"必败的路"剪：可行性/最优性剪枝（P1025：升序去重 + 超和即断）→ 对"重复的状态"剪：记忆化搜索（P1464：查表-计算-存档）→ 记忆化就是自顶向下的动态规划 → 第二十七章线性 DP 正式接班**。两把剪刀各剪一种浪费：一个砍"注定失败"，一个省"重复劳动"。

跨知识点共性：
1. **承接第九、十五章**：本章所有代码都是第十五章 DFS 模板的"原地升级"——模板骨架不变，只在出口与循环处插入判断。
2. **与第二章前缀和同理**：记忆化"以空间换时间"，前缀和、打表同属一族——预处理/存档一次，查询 O(1)。
3. **向后铺垫**：P1464 的 f[a][b][c] 抄下来就是 DP 的状态定义，递归式就是转移方程——下一阶段动态规划的所有概念已在本章现形；搜索顺序优化（更改搜索顺序）还会在贪心与构造类专题中反复出现。

## 📋 速查表

| 优化 | 判断内容 | 写法位置 | 例 |
|---|---|---|---|
| 可行性剪枝 | 当前路必然不合法 | 循环内 break / 递归前 return | P1025：`sum+i*(k-stp+1)>n → break` |
| 最优性剪枝 | 当前路不可能更优 | 递归入口 return | 搜最值时当前劣于已有答案 |
| 记忆化搜索 | 参数相同答案相同 | 函数入口查表、返回前存档 | P1464：`f[a][b][c]` |

```cpp
// 剪枝+记忆化速记
ll dfs(参数)
{
    if(特判非法输入) return 边界值;          // 必须在访问数组前！
    if(f[参数]!=-1) return f[参数];          // 查表
    计算 ans = 各子递归组合;                  // 每个状态只算一次
    return f[参数]=ans;                      // 存档
}
```
