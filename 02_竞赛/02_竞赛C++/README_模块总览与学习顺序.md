## 三、学习顺序：五阶段

```text
阶段 1　语言基础子集与输入输出
        ├─ 模块 A　语言基础子集
        └─ 模块 B　输入输出与性能
        目标：能写出正确、读入不超时的代码
        验收：独立完成 5 道纯模拟题，全部通过且无 IO 超时
              ↓
阶段 2　STL 容器
        └─ 模块 C
        目标：知道每种容器在什么场景用，能默写常用操作
        验收：见到题目能立刻说出该用哪个容器及理由
              ↓
阶段 3　STL 算法
        └─ 模块 D
        目标：能用现成算法替代手写循环
        验收：能不用手写循环完成排序、查找、去重、统计
              ↓
阶段 4　现代语法糖
        └─ 模块 E
        目标：编码速度提升，代码长度下降
        验收：同一道题的代码长度与出错率明显下降
              ↓
阶段 5　竞赛工程化
        └─ 模块 F
        目标：具备自查与排查能力
        验收：能对一个错误程序完成对拍并定位错误
```

> **【要点】** 阶段 1 的模块 B **必须先于一切**。
> 理由见 `B_输入输出与性能.md` 的「零、为什么这个模块排在最前」一节。

## 四、模块间依赖关系

| 模块 | 前置 | 被谁依赖 |
|------|------|---------|
| A 语言基础子集 | 无 | 全部模块 |
| B 输入输出与性能 | A（部分） | 全部模块 |
| C STL 容器 | A | D、E、F |
| D STL 算法 | C | E、F |
| E 现代语法糖 | A、C | F |
| F 竞赛工程化 | A 至 E | — |

**关键依赖说明**：

1. **D 依赖 C**。`lower_bound`、`unique` 都要作用于容器，不熟悉容器无法用好算法。
2. **E 依赖 C**。结构化绑定最典型的用法是遍历 `vector<pair>` 与 `vector<tuple>`；运算符重载是 `set` / `map` 的前提。
3. **F 依赖 A 至 E**。对拍需要能写出正确的暴力程序，卡常需要知道哪些写法慢。

## 五、当前薄弱点（实测统计）

对竞赛代码（`资料\03_算法集训\` 下 **75 个 `.cpp`**）逐项统计的结果：

| 特性 | 出现次数 | 判定 |
|------|---------|------|
| `long long` | 27 | 使用一般 |
| `vector<` | 61 | 使用充分 |
| `memset(` | 18 | 使用一般 |
| `struct` | 26 | 使用一般 |
| `queue<` | 10 | 使用一般 |
| `priority_queue` | 4 | 使用不足 |
| `greater<` | 4 | 使用不足 |
| `stack<` | 8 | 使用一般 |
| `pair<` | 4 | 使用不足 |
| `bool cmp` 手写比较器 | 5 | 使用一般 |
| `vector<vector` | 7 | 使用一般 |
| `__builtin_` 系列 | **0** | **完全未使用** |
| `cin>>` / `cout<<` | 112 / 66 | — |
| `scanf(` / `printf(` | 56 / 43 | 与 `cin` 混用 |
| `endl` / `"\n"` | 38 / 35 | 混用，无规范 |
| `lower_bound` | **0** | **完全未使用** |
| `map<` / `unordered_map` | **1 / 1** | **严重不足** |
| `ios::sync_with_stdio` | **0** | **完全未使用** |
| `set<` / `auto` / lambda / `operator<` | **0 / 0 / 0 / 0** | **完全未使用** |
| `erase(` / `unique(` / `reverse(` / `fill(` | **0** | **完全未使用** |

### 由统计得出的三条结论

1. **关联容器与查找算法几乎空白**。`set` 零使用，`map` 与 `lower_bound` 各仅 1 次。
2. **现代语法糖完全空白**。`auto`、lambda、运算符重载均为零，说明代码冗长、写得慢、易出错。
3. **输入输出性能意识薄弱**。`ios::sync_with_stdio` 仅 1 次，而 `cin` 用了 114 次。

### 一个已经存在的具体隐患

`资料\03_算法集训\12_单调栈\例题代码\P5788.cpp` 的题面约束为 **n ≤ 3×10⁶**，
代码使用 `cin>>` 循环读入且**未关闭同步**。这在多数 OJ 上会超时或接近时限。
完整分析与修正见 `B_输入输出与性能.md`。
