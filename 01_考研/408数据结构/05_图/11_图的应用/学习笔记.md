## 第十一章：图的应用

> 课件来源：`拓扑排序.pdf`、`最小生成树.pdf`、`最短路径.pdf`、`关键路径.pdf`、`关键路径---课堂笔记.pdf`
>
> 本章是图论的"落地章"：**拓扑排序、最小生成树、最短路径、关键路径** 四大算法全是考试与面试高频，且环环相扣——拓扑排序是关键路径的基础，贪心思想贯穿 Prim/Kruskal/Dijkstra。

## 🗺️ 本章地图

本章解决的问题是：**把图变成"决策工具"**——谁先做（拓扑）→ 怎么连通最省钱（最小生成树）→ 怎么走最近（最短路径）→ 整个工程最少多久完工（关键路径）。
- 先学**拓扑排序**：它判定"无环"并给出处理顺序，是关键路径的发动机，所以排第一；
- 再学**最小生成树**：Prim/Kruskal 两种贪心，一个从"点"扩张、一个从"边"挑选；
- 然后**最短路径**：Dijkstra 是贪心"逐点定案"，Floyd 是动态规划"逐个开放中转"；
- 最后**关键路径**：把拓扑排序和"最长路"合体，正推 ETV、倒推 LTV 算出工期。
- 顺序的逻辑：拓扑给"无环 + 先后顺序"，关键路径直接复用；贪心思想从最小生成树一路贯穿到 Dijkstra——学后面的每一步都在用前面。

## 📌 本章重点（3-5个）

⭐ **拓扑排序**：AOV 网 + "选无前驱顶点输出、删它及以它为尾的弧"两步走，入度数组 + 栈实现，**有环判断**（序列没输出全部顶点 = 有环）
⭐ **最小生成树两种算法**：Prim 从**顶点**角度扩张（O(n²)），Kruskal 从**边**角度贪心选边（排序 + 并查集判环），手算选边/终点数组过程
⭐ **Dijkstra 单源最短路径**：D / P / Final 三个辅助数组的**逐轮表格变化**必须会手算
⭐ **Floyd 多源最短路径**：中转点递推式 `D(k)[i][j] = Min{ D(k-1)[i][j], D(k-1)[i][k] + D(k-1)[k][j] }`，k 必须放最外层
⭐ **关键路径**：AOE 网四组时间 **ETV / LTV / ETE / LTE**，关键活动判定 `ETE == LTE`，工期 = 关键路径长度

## 🔥 本章难点（2-3个）

🔥 **Dijkstra 的贪心本质**：当前 dist 最小且未确定的顶点，其最短路径"不可能再变小"——为什么成立、以及它**不能处理负权边**的原因
🔥 **Floyd 的递推思想**：允许中转顶点序号 ≤k 时的最短路径，由 ≤k-1 的结果递推而来；三维 `dp[k][i][j]` 滚动压缩成二维后 **k 的循环必须在最外层**
🔥 **关键路径四组时间的互推关系**：ETV 按拓扑序**正推取 max**，LTV 按逆拓扑序**倒推取 min**，ETE/LTE 由事件时间**推算活动时间**，三步不能混

## ⚠️ 本章易错点（3-5个）

⚠️ **拓扑序列不唯一**：每一步可能有多个入度为 0（无前驱）的顶点，选谁都是合法答案；考试写出一个即可，但漏写"有环时未输出全部顶点"就是错
⚠️ **Dijkstra 遇负权必错**：它假设"已确定点不可再优化"，负权边会推翻这一假设；同时 Final 数组忘记置 1、或拿已确定的点继续当中转更新，都是常见手算失误
⚠️ **Prim 的 dist 与 Dijkstra 的 dist 含义不同**：Prim 的 dist[i] = Vi **到生成树（集合）** 的最小边权；Dijkstra 的 dist[i] = 源点**到 Vi 的路径**长度。公式差一个"路径累加"，混用必错
⚠️ **Kruskal 忘判环**：选边前必须判断两端点是否已连通（终点相同 / 并查集同根），相同则该边再小也要**舍弃**
⚠️ **事件（顶点）与活动（边）的时间张冠李戴**：ETV/LTV 是**事件**（顶点）的时间，ETE/LTE 是**活动**（弧）的时间；`ETE = 弧起点ETV`，`LTE = 弧终点LTV − w`，别用反

## 📖 知识点讲解

### 1. 拓扑排序与 AOV 网

**是什么**：拓扑排序解决的是"一堆互相牵制的事情，按什么顺序做才不冲突"——每一轮挑一个"没有任何事卡它"的先办。严格说：**有向无环图 DAG**（Directed Acycline Graph，课件拼写）是无环的有向图；对比：有向树 ⊂ DAG ⊂ 一般有向图（一般有向图可含环，如 B、E、D 三顶点构成有向环）。工程分成的小阶段叫**活动**；用顶点表示活动、弧表示活动间**优先关系（制约关系）**的有向图叫 **AOV 网**（Activity On Vertex Network，例：先学 C 语言才能学数据结构）。若 Vi 到 Vj 有路径则序列中 Vi 排在 Vj 前，这样的顶点序列叫**拓扑序列**；构造拓扑序列的过程叫**拓扑排序**——官方定义：**由偏序得到全序的操作过程**（偏序＝只规定部分先后，全序＝排成一条完整的先后链）。

**为什么**：工程/课程/代码依赖都有"先后制约"，拓扑排序把偏序关系排成一条可执行的线性顺序；更重要的是——**它能判断有向图是否有环**（面试问"如何判断有向图有环"，第一反应就是拓扑排序），而 DAG 是关键路径、DP 等一切的前提。

**怎么用**——算法思想（两步反复）：
```
(1) 在有向图中选一个没有前驱的顶点且输出之
(2) 从图中删除该顶点和所有以它为尾的弧
重复上述两步，直至：
  ① 全部顶点均已输出 → 得到拓扑序列
  ② 当前图不存在无前驱顶点 → 剩余顶点构成环，图有环
```
**跟着算**——先拿 5 顶点小网手算一遍入度变化（弧：V1→V3、V2→V3、V3→V4、V3→V5）：
```
V1 ──→ V3 ──→ V4
       ▲  └──→ V5
V2 ────┘
```
初始入度（每列数"指向我的箭头数"）：V1=0, V2=0, V3=2, V4=1, V5=1。

| 步骤 | 本步入度为 0 的顶点 | 输出 | 入度变化（删弧=入度减 1） |
|------|--------------------|------|---------------------------|
| 1 | V1、V2 | V1 | V3: 2→1 |
| 2 | V2 | V2 | V3: 1→0 |
| 3 | V3 | V3 | V4: 1→0；V5: 1→0 |
| 4 | V4 | V4 | — |
| 5 | V5 | V5 | 输出 5 = n → **无环** ✓ |

第 1 步若先选 V2，则得 V2 V1 V3 V4 V5……每步有多个候选 → **拓扑序列可以有多个**，输出够 n 个就是合法答案。

手算示例（V1→V2, V1→V3, V1→V4, V3→V2, V3→V5, V4→V5, V6→V4, V6→V5）：

| 步骤 | 无前驱顶点 | 选择 | 操作 |
|------|-----------|------|------|
| 1 | V1、V6 | 选 V1 | 删 V1 及其出边 |
| 2 | V6、V3 | 选 V6 | 删 V6 及其出边 |
| 3 | V4、V3 | 选 V4 | 删 V4 及其出边 |
| 4 | V3 | 选 V3 | 删 V3 及其出边 |
| 5 | V2、V5 | 选 V2，再 V5 | 全部输出 |

得拓扑序列（本例选择下）**V1 V6 V4 V3 V2 V5**；每次都有多个候选 → **拓扑序列可以有多个**。
有环图判断示例（A→B, A→C, B→D, D→E, E→B, C→E）：删 A、删 C 后，B/D/E 互相制约（B→D→E→B），**不存在无前驱顶点但序列未含全部顶点** → 剩余顶点构成环 → 有环。
计算机实现（思想的实现）：
```c
// 邻接表 + 头结点增加入度数组 indegree；另设一个栈暂存入度为0的顶点
for (每个顶点) if (indegree[i]==0) Push(i);   // 入度0 = 没有前驱
while (栈不空) {
    j = Pop();  topo[++k] = j;               // 输出栈顶
    for (j 的每个出边邻接点 z) {              // "删弧" = 弧头顶点入度减1
        if (--indegree[z] == 0) Push(z);
    }
}
if (k != n)  "有环";                          // 输出顶点数 < n → 有环
```
栈模拟全过程（indegree 初始：V1=0, V2=2, V3=1, V4=2, V5=3, V6=0）：

| 步骤 | 操作 | 入度变化 / 入栈 | 拓扑序列 |
|------|------|----------------|----------|
| 1 | V1、V6 入栈 | — | — |
| 2 | 弹 V6 输出 | V4: 2→1，V5: 3→2（不入栈） | V6 |
| 3 | 弹 V1 输出 | V2: 2→1；V3: 1→0 入栈；V4: 2→0 入栈 | V6, V1 |
| 4 | 弹 V4 输出 | V5: 2→1（不入栈） | V6, V1, V4 |
| 5 | 弹 V3 输出 | V2: 1→0 入栈；V5: 1→0 入栈 | V6, V1, V4, V3 |
| 6 | 弹 V5 输出（无后继） | — | + V5 |
| 7 | 弹 V2 输出（无后继），栈空结束 | — | **V6 V1 V4 V3 V5 V2** |

对照上面小例子回看这张表：每行干的事完全一样——**弹一个入度 0 的点输出，把它所有出边终点的入度减 1，减到 0 就入栈**。

> ⚠️ 注意事项：入度为 0 的顶点 = 没有前驱的顶点；"删除顶点及以它为尾的弧"用"弧头顶点入度减 1"实现。邻接表实现复杂度 O(n+m)，邻接矩阵 O(n²)。拓扑排序最经典应用是课程表编排、代码依赖处理，且它是关键路径的基础。

> 🎯 规律：入度就是"还卡着几件前驱事"——减到 0 才能输出；输出个数 < n 必有环。

> 💡 一句话总结：入度零者先输出，删弧减一，输出不全必有环。

| 对比 | AOV 网 | DAG |
|------|--------|-----|
| 定位 | 顶点=活动、弧=优先关系的有向图 | 无环的有向图 |
| 用途 | 描述活动制约关系，做拓扑排序 | 拓扑排序的适用前提 |
| 有环时 | 无法完成全部排序（工程不可行） | 定义上不允许 |

### 2. 最小生成树：Prim 与 Kruskal

**是什么**：最小生成树回答的是"把 n 个点连成一体最少花多少钱"——边只能留 n−1 条（多一条就成环），还要总花钱最少。严格说：**生成树** = 连通图的一个**极小连通子图**，含图中全部 n 个顶点、但只有构成树的 n-1 条边。**最小生成树（MST）** = 带权连通图（连通网）中，边权值之和小于等于其他一切生成树的生成树。两大经典算法：**克鲁斯卡尔（Kruskal）** 与 **普里姆（Prim）**——考试面试常遇。

**为什么**：生成树属性决定了 MST 的可行性：①连通图可有多个生成树；②所有生成树顶点数、边数相同（n 个顶点 n-1 条边）；③生成树中不存在环；④移除任一条边图就不连通（边最少）；⑤添加任一条边就成环；⑥n 个顶点的无向完全图最多有 **n^(n-2)** 颗生成树——不能枚举，必须贪心（贪心＝每步都选当前看起来最优的选项、绝不回头）。应用：n 个城市架通信网线（顶点=城市，边=线路，权=造价），求总造价最低的方案；还有最少电线装电路、道路铺设、聚类算法、以太网桥防环等。

**怎么用**——Kruskal（从**边**的角度，贪心选边）：
初始把图视为森林，每个顶点自成一棵树；每次选**权值最小且不构成环**的边连树。
**跟着算**——4 顶点小图，边：A-B=1、B-D=2、A-D=3、C-D=4、A-C=5：
```
        1
    A ───── B
    │ ╲     │
  5 │  ╲3   │ 2
    │   ╲   │
    C ───── D
        4
```
第 1 步排序：A-B(1) < B-D(2) < A-D(3) < C-D(4) < A-C(5)；第 2 步逐条判定：

| 步 | 候选边(权) | 判断 | 操作 |
|----|-----------|------|------|
| 1 | A-B (1) | 无环 | 添加 |
| 2 | B-D (2) | 无环 | 添加 |
| 3 | A-D (3) | A、D 已连通（A─B─D）→ 成环 | **舍弃** |
| 4 | C-D (4) | 无环 | 添加；已够 n−1=3 条 → 停 |

MST 边集 {A-B, B-D, C-D}，总权 = 1+2+4 = **7**。看第 3 步：贪心不是"见小边就要"——**会造成环的小边必须扔**。
（判环用并查集最顺手：并查集就是用数组 f[] 记"每个点的老大是谁"，两端点同根 = 已连通 = 会成环。）

手算九步（9 顶点 V0~V8，15 条边）：

| 步骤 | 候选边(权) | 判断 | 操作 |
|------|-----------|------|------|
| 0 | 全部边按权非降序排列 | 4-7(1), 2-8(2), 0-1(3), 0-5(4), 1-8(5), 3-7(6), 1-6(6), 5-6(7), 1-2(8), 6-7(9), 3-4(10), 3-8(11), 2-3(12), 3-6(14), 4-5(18) | — |
| 1 | V4-V7 (1) | 无环 | 添加 |
| 2 | V2-V8 (2) | 无环 | 添加 |
| 3 | V0-V1 (3) | 无环 | 添加 |
| 4 | V0-V5 (4) | 无环 | 添加 |
| 5 | V1-V8 (5) | 无环 | 添加 |
| 6 | V3-V7 (6) | 无环 | 添加 |
| 7 | V1-V6 (6) | 无环 | 添加 |
| 8 | V5-V6 (7) | **成环，舍弃** | 跳过 |
| 9 | V1-V2 (8) | **成环，舍弃** | 跳过 |
| 10 | V6-V7 (9) | 无环 | 添加；已够 9-1=8 条边，停止 |

MST 边集 {4-7, 2-8, 0-1, 0-5, 1-8, 3-7, 1-6, 6-7}，总权 = 36。（过程与小例完全同构：排序 → 逐条判环 → 够 n−1 条停。）
**判环——终点法（并查集思想）**：顶点从小到大排序后，某顶点的"终点" = 与它**连通的最大顶点**；初始各自成树，终点记 0。边 X-Y 的 X 终点 == Y 终点 → 会成环，舍弃；否则添加，并更新终点。终点数组变化：

| 选边后 | 终点数组 (V0~V8) |
|--------|----------------|
| 初始 | 0 0 0 0 0 0 0 0 0 |
| 加4-7 | 0 0 0 0 7 0 0 0 0 |
| 加2-8 | 0 0 8 0 7 0 0 0 0 |
| 加0-1 | 1 0 8 0 7 0 0 0 0 |
| 加0-5 | 1 5 8 0 7 0 0 0 0 |
| 加1-8 | 1 5 8 0 7 8 0 0 0 |
| 加3-7 | 1 5 8 7 7 8 0 0 0 |
| 加1-6 | 1 5 8 7 7 8 0 0 6 |
| 加6-7 | 1 5 8 7 7 8 7 0 6（共8条边，停止） |

**怎么用**——Prim（从**顶点**的角度，逐步扩张）：
顶点分两类：A 类 = 已并入生成树，B 类 = 其余；初始全在 B 类。任选起点移入 A 类，之后每轮把"B 类中到 A 类**权值最小**的顶点"移入 A 类，直到 B 类为空；所走顶点和边即 MST。
**跟着算**——还是上面那张 4 顶点小图，从 A 出发（注意这里的 dist 是"点到树"的最近边权，不是"到 A 的路径长"）：

| 轮 | 动作 | dist 更新（到树的最小边权） |
|----|------|----------------------------|
| 初始 | A 入树 | B=1(A-B)，C=5(A-C)，D=3(A-D) |
| 1 | 并入最小的 B（边 A-B=1） | D: min(3, B-D=2)=2；C: 5 不变 |
| 2 | 并入 D（边 B-D=2） | C: min(5, D-C=4)=4 |
| 3 | 并入 C（边 D-C=4） | 全部入树，停 |

总权 = 1+2+4 = **7**，边集与 Kruskal 相同。
手算（同一图从 V0 出发）：V0 的邻接点 V1(3)、V5(4) → 选 V1；与 {V0,V1} 相邻的顶点中 V5(4) 最小 → 加 V5；再比较得 V8(V1-V8=5) → 加 V8；然后 V2(V2-V8=2)、V6(V1-V6=6)、V7(V6-V7=9)、V4(V4-V7=1)、V3(V3-V7=6)。与 Kruskal 结果相同，总权 36。

```c
// Prim 核心（邻接矩阵，O(n^2)）：dist[i] = i 到生成树的最小边权
for (i = 0; i < n; i++) {              // 循环n次，每次并入一个点
    // 1.找 flag==0 且 dist 最小的点 minn
    // 2.把 minn 并入生成树，sum += dist[minn]
    // 3.用 minn 松弛（试一试借道新点能不能更近）：
    //   dist[j] = min(dist[j], g[minn][j])  (j未入树)
}

// Kruskal 核心：边按权排序 + 并查集
Sortt(1, m);                            // 排序（复杂度取决于排序算法）
fu = Find(e[i].u);  fv = Find(e[i].v);  // 并查集找根
if (fu != fv) { 选边; sum += w; cnt++; f[fv] = fu; }  // 不同集合才选
if (cnt == n-1) break;                  // 选够 n-1 条边提前结束
```

> ⚠️ 注意事项：课件贪心算法两要素——①**贪心选择性质**：整体最优解可由一系列局部最优选择达到（贪心与动态规划的主要区别：贪心自顶向下迭代，动态规划自底向上）；②**最优子结构性质**：最优解包含子问题的最优解。贪心不能保证所有问题整体最优，但对单源最短路径、最小生成树等问题可产生整体最优解。

> 🎯 规律：Prim 问"哪个点离树最近"，Kruskal 问"哪条边全局最便宜"——两把筛子都靠"不成环"把关。

> 💡 一句话总结：Prim 拉点，Kruskal 排边。

| 对比 | 生成树 | 最小生成树 |
|------|--------|-----------|
| 图型 | 任何连通图 | 带权连通图（连通网） |
| 目标 | n 个顶点 n-1 条边的极小连通子图 | 权值之和最小的生成树 |
| 唯一性 | 可有多个 | 也可有多个，但总权值唯一最小 |
| 无权图 | 只存在生成树，无"最小" | 不适用 |

### 3. 最短路径：Dijkstra（单源）

**是什么**：Dijkstra 像"报价逐轮刷新"：每轮把离源点最近的一个点**定案**（它的最短距离不可能再被别人改小），再让它去压低邻居的报价。术语先理清：路径的起点叫**源点（Source）**，最后一个顶点叫**终点（Destination）**，源点与终点相对一条路径而言。无权图中"最短路径" = 边数最少的路径，从源点做 **BFS**（广度优先搜索）遇到终点即得。带权图用**迪杰斯特拉（Dijkstra）算法**：**单源点**最短路径算法，求从一个顶点到其余所有顶点的最短路径（导航规划、换乘路线的底层算法）。

**为什么**：贪心策略成立的关键——辅助向量 D[i] 中当前最小的 `Min{ D[i] | vi∈V }`，就是源点到该顶点的最终最短路径长度（再绕别的点只会更长）；把已确定顶点当中转继续松弛其余顶点，一步步扩大"已确定"集合。课件补充：可用小顶堆优化，但 Dijkstra **无法处理负权边**。

**怎么用**——三个辅助数组 + 两步循环：
| 数组 | 含义 | 初始化 |
|------|------|--------|
| D[i] | 当前求得的源点 V0 到 Vi 的最短路径长度 | 有弧=权值，无弧=∞ |
| P[i] | 路径向量，记 Vi 的前驱顶点下标 | 全 0 |
| Final[i] | 1 = V0 到 Vi 的最短路径已求得 | Final[V0]=1，其余 0 |

```
循环 n 次：
① 遍历找 dist 最小且 final==0 的顶点 wk，Final[wk] = 1
② 遍历 wk 的邻接点 vi：若 D[wk] + w(wk,vi) < D[vi]，
   则更新 D[vi] = D[wk]+w(wk,vi)，P[vi] = wk
```
**跟着算**——5 顶点小图逐轮填表（弧：V0→V1=2, V0→V2=5, V1→V2=1, V1→V3=4, V2→V3=2, V3→V4=3）：
```
V0 ──2──> V1 ──4──> V3 ──3──> V4
│         │        ▲
5         1        2
▼         ▼        │
└────────> V2 ─────┘
```
| 轮次(确定点) | D0 | D1 | D2 | D3 | D4 |
|-------------|----|----|----|----|----|
| 初始 | 0 | **2** | 5 | ∞ | ∞ |
| V1 (2) | 0 | 2 | 3¹ | 6¹ | ∞ |
| V2 (3) | 0 | 2 | 3 | 5² | ∞ |
| V3 (5) | 0 | 2 | 3 | 5 | 8³ |
| V4 (8) | 0 | 2 | 3 | 5 | 8 |

（上标 = P 数组记录的前驱。）第 1 轮选最小的 V1(2) 定案：V2 = 2+1 = 3 < 5 → **直达价 5 被中转价 3 推翻**，D[2]=3、P[2]=1；V3 = 2+4 = 6。第 2 轮选 V2(3)：V3 = 3+2 = 5 < 6 → 又被刷新一次，D[3]=5、P[3]=2。第 3 轮选 V3(5)：V4 = 5+3 = 8。最终 D=[0,2,3,5,8]，P=[0,0,1,2,3]，路径倒追：V4←3←2←1←0，即 V0→V1→V2→V3→V4，长 8。小例演完再看九顶点大表，每轮就干这两件事：**选最小定案、拿它刷新邻居**。
手算全过程表（图：V0V1=1, V0V2=5, V1V2=3, V1V3=7, V1V4=5, V2V4=1, V2V5=7, V3V4=2, V3V6=3, V4V5=3, V4V6=6, V4V7=9, V5V7=5, V6V7=2, V6V8=7, V7V8=4）：

| 轮次(确定点) | D0 | D1 | D2 | D3 | D4 | D5 | D6 | D7 | D8 |
|-------------|----|----|----|----|----|----|----|----|----|
| 初始 | 0 | **1** | 5 | ∞ | ∞ | ∞ | ∞ | ∞ | ∞ |
| V1 (1) | 0 | 1 | 4¹ | 8¹ | 6¹ | ∞ | ∞ | ∞ | ∞ |
| V2 (4) | 0 | 1 | 4 | 8 | 5² | 11² | ∞ | ∞ | ∞ |
| V4 (5) | 0 | 1 | 4 | 7⁴ | 5 | 8⁴ | 11⁴ | 14⁴ | ∞ |
| V3 (7) | 0 | 1 | 4 | 7 | 5 | 8 | 10³ | 14 | ∞ |
| V5 (8) | 0 | 1 | 4 | 7 | 5 | 8 | 10 | 13⁵ | ∞ |
| V6 (10) | 0 | 1 | 4 | 7 | 5 | 8 | 10 | 12⁶ | 17⁶ |
| V7 (12) | 0 | 1 | 4 | 7 | 5 | 8 | 10 | 12 | 16⁷ |
| V8 (16) | 0 | 1 | 4 | 7 | 5 | 8 | 10 | 12 | 16 |

（上标 = P 数组中记录的前驱下标；如第五步遍历 V2：V4 = 4+1 = 5 < 6 → D[4]=5, P[4]=2；第七步遍历 V4：D[3]=5+2=7、D[5]=5+3=8、D[6]=5+6=11、D[7]=5+9=14）
最终 **D = [0,1,4,7,5,8,10,12,16]**，**P = [0,0,1,4,2,4,3,6,7]**，Final 全 1。
路径回溯（P 数组从终点倒着追）：V8←7←6←3←4←2←1←0，即 **V0→V1→V2→V4→V3→V6→V7→V8**，长度 16。

> ⚠️ 注意事项：P 数组不是"边"而是"前驱下标"，回溯路径时从终点一路追到源点再倒序输出；已 Final=1 的顶点不再参与第①步选择，但会被用作中转做第②步松弛。

> 🎯 规律：每轮只"定案"一个 dist 最小者，再拿它刷新邻居——直达价随时可能被中转价推翻。

> 💡 一句话总结：贪心定一点，松弛它邻居，P 链回溯路径。

### 4. 最短路径：Floyd（多源）

**是什么**：Floyd 的哲学是"逐个开放中转站"：从"只许直达"出发，每放开一个中转点，就问所有点对一句"借它中转会不会更近？"。严格说：**弗洛伊德（Floyd）算法**求图中**每一对顶点之间**（多源点）的最短路径。也可以对每个顶点做一次 Dijkstra（n 次），时间复杂度同为 **O(n³)**，但 Floyd 实现更简洁优雅、思想巧妙。维护 **n×n 辅助矩阵 D** 与 **n×n 路径矩阵 P**。

**为什么**：定义 n 阶方阵序列 `D⁽⁻¹⁾, D⁽⁰⁾, D⁽¹⁾, …, D⁽ᵏ⁾, …, D⁽ⁿ⁻¹⁾`：

```
D⁽⁻¹⁾[i][j] = G.arcs[i][j]                      （图的邻接矩阵）
D⁽ᵏ⁾[i][j] = Min{ D⁽ᵏ⁻¹⁾[i][j], D⁽ᵏ⁻¹⁾[i][k] + D⁽ᵏ⁻¹⁾[k][j] }， 0 ≤ k ≤ n-1
```
- `D⁽ᵏ⁾[i][j]`：从 Vi 到 Vj 的**中间顶点序号不大于 k** 的最短路径长度
- `D⁽ⁿ⁻¹⁾[i][j]`：Vi 到 Vj 的最短路径长度（最终答案）
- 注意 `D⁽⁰⁾[i][j] = Min{ D⁽⁻¹⁾[i][j], D⁽⁻¹⁾[i][0]+D⁽⁻¹⁾[0][j] } = D⁽⁻¹⁾[i][j]`，所以 D⁽⁻¹⁾ 与 D⁽⁰⁾ 是同一个矩阵

精妙所在：求 Vi、Vj 最短路径时**不断尝试所有中转结点 k**，比较"直达"与"经 k 中转"，取小者。如三顶点例（V0V1=1, V0V2=5, V1V2=3）：`D⁽¹⁾[0][2] = Min{ D⁽⁰⁾[0][2]=5, D⁽⁰⁾[0][1]+D⁽⁰⁾[1][2]=1+3=4 } = 4`，V0 到 V2 经 V1 中转更近。

**怎么用**——代码与手算：
```c
// Floyd：时间 O(n^3)，空间 O(n^2)
// dp[i][j]：允许用前 k 个点做中转点时，(i,j) 间最短距离
for (i=1..n) for (j=1..n) dp[i][j] = a[i][j];   // 初始：直连边（对角0，不通inf）
for (k = 1; k <= n; k++)            // 中转点必须最外层！
    for (i = 1; i <= n; i++)
        for (j = 1; j <= n; j++)
            dp[i][j] = min(dp[i][j], dp[i][k] + dp[k][j]);
```
**跟着算**——把上面 3 顶点小图完整过一遍中转递推（无向，边 V0V1=1、V0V2=5、V1V2=3）：
```
第1步 初始 D⁽⁻¹⁾（直连边）：
        V0   V1   V2
V0  [    0    1    5  ]
V1  [    1    0    3  ]
V2  [    5    3    0  ]

第2步 放开 k=0（允许经 V0 中转）：只看点对 (1,2)：
      D[1][2] = Min{ 3, D[1][0]+D[0][2]=1+5=6 } = 3，不变
      → D⁽⁰⁾ = D⁽⁻¹⁾（这就是"D⁽⁻¹⁾ 与 D⁽⁰⁾ 相同"的由来）

第3步 放开 k=1（允许再经 V1 中转）：看点对 (0,2)：
      D[0][2] = Min{ 5, D[0][1]+D[1][2]=1+3=4 } = 4 → 更新！（对称地 D[2][0]=4）
        V0   V1   V2
V0  [    0    1    4  ]   ← 5 被改成 4
V1  [    1    0    3  ]
V2  [    4    3    0  ]

第4步 放开 k=2（允许再经 V2 中转）：看点对 (0,1)：
      D[0][1] = Min{ 1, D[0][2]+D[2][1]=4+3=7 } = 1，不变 → 结束
```
结论：V0 到 V2 最短距离 = 4，路线 V0→V1→V2——"直达 5，不如借 V1 中转"。
用"绿行绿列法"复述第 3 步：k=1 时绿行是 V1 行 [1,0,3]、绿列是 V1 列 [1,0,3]；绿列元素与绿行元素两两配对相加，只有 (0,2) 格 1+3=4 比原值 5 小，更新它。
手算口诀（课件"绿行绿列法"）：固定中转点 k 后，第 k **行**是绿色行、第 k **列**是绿色列；绿列元素与绿行元素两两相加，与原 `D[i][j]` 比较、更小则更新（同时 `P[i][j]` 更新为 `P[i][k]`，即记下中转）。对 9 顶点例依次令 k=1..8 扫描全部 D 矩阵；到 k=8 时左上角区域都不需再更新，D⁷ 与 D⁸ 相同，算法结束。最终 V0 行 = [0,1,4,7,5,8,10,12,16]，与 Dijkstra 单源结果一致。

> ⚠️ 注意事项：k 的循环必须在最外层——逐个"放开"中转点，内层 i、j 是对所有点对的全表扫描；Floyd 同样**不能处理负权**。课件建议：自己照图手工模拟一遍 D/P 矩阵才能真正体会算法精妙。

> 🎯 规律：k 是"阶段"不是普通循环变量——第 k 轮答案全靠第 k−1 轮，所以 k 必须放最外层。

> 💡 一句话总结：逐个中转放开，三重循环取小，见好就更新。

| 对比 | Dijkstra | Floyd |
|------|----------|-------|
| 求解范围 | 单源点 → 其余各点 | 任意两点（多源） |
| 数据结构 | 一维 D/P/Final | 二维矩阵 D 和 P |
| 时间复杂度 | O(n²)（可小顶堆优化） | O(n³) |
| 负权边 | 不能处理 | 不能处理 |
| 获得多源 | 执行 n 次 | 一次搞定 |

### 5. 关键路径与 AOE 网

**是什么**：AOE 网问的是"整条工程里，哪一条活动链最费时"——最费时的那条链就是工期，链上的活动一天都拖不得。严格说：**AOE 网**（Activity On Edge）= **边表示活动**的带权有向无环图：**顶点表示事件（Event）**、**弧表示活动**、**权表示活动持续的时间**。与 AOV 网（顶点表示活动）相对应——拓扑排序在 AOV 网上进行，关键路径在 AOE 网上定义，这就是两者的直观联系。事件的发生标志着它之前的活动已完成、之后的活动可以开始；源点 = 入度为 0（工程唯一开始点），汇点 = 出度为 0（唯一完成点）。**关键路径（Critical Path）** = 从源点到汇点**路径长度最长**的路径（活动中有些可并行，最长的决定工期）；关键路径上的活动叫**关键活动**。

**为什么**：完成工程的最短时间 = 源点到汇点**最长**路径长度（短路径上的活动并行等待完最长那条）。关键路径回答两个问题：①完成整个工程至少需要多少时间；②哪些活动是影响工程的关键。1956 年美国杜邦公司提出关键路径法，1957 年用于 1000 万美元化工厂建设，工期缩短 4 个月，一年节省 100 万美元——考 PMP 必学：**向关键路径要时间，向非关键路径要资源**；关键路径是动态的，非关键路径可能变成关键路径。

**怎么用**——四个核心概念（先分清"事件=顶点"与"活动=边"）：

| 概念 | 全称 | 含义 | 计算公式 |
|------|------|------|----------|
| ETV | Earliest Time Of Vertex | 事件（顶点）最早发生时间 | 从源点到该顶点最长路径的权值和；`ETV[源]=0`，按**拓扑序正推** `ETV[i]=max(ETV[j]+w)` |
| LTV | Latest Time Of Vertex | 事件（顶点）最晚发生时间 | 超出就延误工期；`LTV[汇]=ETV[汇]`，按**逆拓扑序倒推** `LTV[i]=min(LTV[j]-w)` |
| ETE | Earliest Time Of Edge | 活动（弧）最早开工时间 | = **弧起点**事件的 ETV |
| LTE | Latest Time Of Edge | 活动（弧）最晚开工时间 | = **弧终点**事件的 LTV − 该活动耗时 w |

关键活动判定：**ETE == LTE**（一点不能耽误）；ETE ≠ LTE 为非关键活动（有富余时间）。顶点在关键路径上 ⇔ `etv == ltv`。关键路径是**活动的集合**而非事件的集合，所以求出 ETV/LTV 后还要算 ETE/LTE。
**跟着算**——先用 4 事件小 AOE 网把"三步走"完整跑一遍（a1=3(V1→V2)、a2=2(V1→V3)、a3=4(V2→V4)、a4=1(V3→V4)）：
```
        a1=3
   V1 ──────→ V2
    │           ╲
a2=2            a3=4
    │           ╲
    ▼            ▼
   V3 ──a4=1──→ V4
```
第 1 步，拓扑序正推 ETV（取 max = 等最慢的前驱完工）：ETV[V1]=0 → V2=0+3=3、V3=0+2=2 → V4=max(3+4, 2+1)=**7**。工期 = ETV[汇] = 7。
第 2 步，逆拓扑序倒推 LTV（取 min = 赶最紧迫的后继 Deadline）：LTV[V4]=7 → V2=7−4=3、V3=7−1=6 → V1=min(3−3, 6−2)=0。
第 3 步，算 ETE/LTE、判关键：

| 活动 | 弧 | w | ETE=起点ETV | LTE=终点LTV−w | 关键？ |
|------|-----|---|-------------|---------------|--------|
| a1 | V1→V2 | 3 | 0 | 3−3=0 | ✓ |
| a2 | V1→V3 | 2 | 0 | 6−2=4 | ✗（富余 4 天） |
| a3 | V2→V4 | 4 | 3 | 7−4=3 | ✓ |
| a4 | V3→V4 | 1 | 2 | 7−1=6 | ✗（富余 4 天） |

关键活动 a1、a3 → 关键路径 V1→V2→V4，工期 7。V3 那条"短支线"整体有 4 天富余——晚开工也不影响完工，这就是"向非关键路径要资源"的账。
小例跑熟了，再看课件 9 事件大例，只是顶点更多、公式不变。
手算 Step By Step（AOE 网：a1=6(V1V2), a2=4(V1V3), a3=5(V1V4), a4=1(V2V5), a5=1(V3V5), a6=2(V4V6), a7=9(V5V7), a8=7(V5V8), a9=4(V6V8), a10=2(V7V9), a11=4(V8V9)）：

第一步，**拓扑排序求 ETV**（初始全 0，出栈时用 `etv[v]=max(etv[v], etv[u]+w)` 松弛后继）：

| 出栈顶点 | 入栈顶点 | ETV 更新 |
|----------|----------|----------|
| V1 | V2、V3、V4 | ETV=6, 4, 5 |
| V4 | V6 | ETV[V6]=5+2=7 |
| V6 | （V8 入度2→1） | ETV[V8]=7+4=11 |
| V3 | （V5 入度2→1） | ETV[V5]=4+1=5 |
| V2 | V5（入度0入栈） | ETV[V5]=max(5, 6+1)=**7** |
| V5 | V7、V8 | ETV[V7]=7+9=16；ETV[V8]=max(11,7+7)=**14** |
| V8 | （V9 入度2→1） | ETV[V9]=14+4=18 |
| V7 | V9（入度0入栈） | 16+2=18 相等不更新 |
| V9 | — | 结束 |

技巧：把拓扑排序的**出栈序列依次入另一个栈**，即得逆拓扑序（V1 V4 V6 V3 V2 V5 V8 V7 V9），供倒推 LTV 用。
第二步，**逆拓扑序倒推 LTV**（初始全部 = 汇点 ETV = 18；V9 出栈啥也不做）：
V7: 18−2=16 → V8: 18−4=14 → V5: min(16−9, 14−7)=**7** → V2: 7−1=6 → V3: 7−1=6 → V6: 14−4=10 → V4: 10−2=8 → V1: 6−6=0。源点 ETV=LTV=0 毋庸置疑。

第三步，**求 ETE/LTE、判关键活动**：

| 活动 | 弧 | w | ETE=起点ETV | LTE=终点LTV−w | 关键? |
|------|-----|---|----|----|------|
| a1 | ⟨V1,V2⟩ | 6 | 0 | 6−6=0 | ✓ |
| a2 | ⟨V1,V3⟩ | 4 | 0 | 6−4=2 | ✗ |
| a3 | ⟨V1,V4⟩ | 5 | 0 | 8−5=3 | ✗ |
| a4 | ⟨V2,V5⟩ | 1 | 6 | 7−1=6 | ✓ |
| a5 | ⟨V3,V5⟩ | 1 | 4 | 7−1=6 | ✗ |
| a6 | ⟨V4,V6⟩ | 2 | 5 | 10−2=8 | ✗ |
| a7 | ⟨V5,V7⟩ | 9 | 7 | 16−9=7 | ✓ |
| a8 | ⟨V5,V8⟩ | 7 | 7 | 14−7=7 | ✓ |
| a9 | ⟨V6,V8⟩ | 4 | 7 | 14−4=10 | ✗ |
| a10 | ⟨V7,V9⟩ | 2 | 16 | 18−2=16 | ✓ |
| a11 | ⟨V8,V9⟩ | 4 | 14 | 18−4=14 | ✓ |

两张汇总表：

| 事件 | V1 | V2 | V3 | V4 | V5 | V6 | V7 | V8 | V9 |
|------|----|----|----|----|----|----|----|----|----|
| ETV | 0 | 6 | 4 | 5 | 7 | 7 | 16 | 14 | 18 |
| LTV | 0 | 6 | 6 | 8 | 7 | 10 | 16 | 14 | 18 |

关键活动 a1, a4, a7, a8, a10, a11 → **两条关键路径**：V1→V2→V5→V7→V9 与 V1→V2→V5→V8→V9，**工期 = 18**。

```c
// 关键路径核心（邻接表+栈）
// 拓扑排序同时求 etv：etv[v] = max(etv[v], etv[u] + w);
end = topo[k];                       // 拓扑序列最后一个 = 汇点
for (i=1..n) ltv[i] = etv[end];      // LTV 初始化为汇点ETV
for (i = k-1; i >= 1; i--)           // 按逆拓扑序倒推
    ltv[u] = min(ltv[u], ltv[v] - w);        // v是u的出边邻接点
// 枚举所有弧：ete = etv[i];  lte = ltv[j] - w;
if (ete == lte) 输出关键活动(i→j);
```

> ⚠️ 注意事项：ETV 用 max（要等最慢的前驱活动全部完成）、LTV 用 min（取最紧迫的后继要求）；工程工期 = 汇点的 ETV = 关键路径长度；非关键活动（如 a6）可富余几天而不影响工期，可抽调资源支援关键活动。

> 🎯 规律：正推取 max 是"等最慢的前驱"，倒推取 min 是"赶最紧的后继"；ETE==LTE 即一天拖不得。

> 💡 一句话总结：正推最早倒推最晚，相等即关键。

### 🧩 本章归纳：一条主线串全章

把全章串成一条因果链：

```
有环吗？按什么顺序做？→ 拓扑排序（AOV 网：入度归零才输出，输出不全=有环）
   ↓ 无环才有"拓扑序"，有拓扑序才能"正推/倒推"
工程多久完工？→ 关键路径（AOE 网：拓扑正推 ETV，逆拓扑倒推 LTV，ETE==LTE 判关键）
连起来最少花多少钱？→ 最小生成树（Prim 拉点 / Kruskal 排边，贪心 + 判环）
从这里到那里最近怎么走？→ Dijkstra（贪心逐点定案）/ Floyd（DP 逐个放开中转）
```

回头看才看得见的三条共性规律：
1. **贪心 = 局部最优 + 一句"为什么安全"**：Kruskal 敢选最小边是因为判过环，Dijkstra 敢定案最小 dist 是因为"不可能再变小"——负权边击穿的正是这句保证，所以两者都怕负权。
2. **辅助数组是算法的手和眼**：indegree[] 支撑拓扑，dist+flag 支撑 Prim，D/P/Final 支撑 Dijkstra，etv/ltv 支撑关键路径——背算法不如背"每个数组每轮怎么变"。
3. **"环"是全章的头号敌人，dist 一词两义**：拓扑靠"输出不全"识破环，Kruskal 靠并查集躲开环，关键路径直接定义在无环上；而 Prim 的 dist 是"到树"的边权、Dijkstra 的 dist 是"到源点"的路径长——同名不同义，混用必错（拓扑排序正是关键路径的第一步，四道大题常拼成一张卷）。

## 🔍 相似概念辨析

### 组1：Prim vs Kruskal

| 对比维度 | Prim | Kruskal |
|----------|------|---------|
| 各自定义 | 从顶点角度：每次把"到生成树权值最小的 B 类顶点"并入生成树 | 从边角度：初始每顶点自成树，按权递增选不成环的边连树 |
| 核心区别 | 维护"点到**树集合**"的最小边权 dist | 维护"边的有序列表 + 连通性判断" |
| 各自特点 | 逐点扩张，n−1 轮，每轮选点再松弛邻接点 | 先排序全部边，逐边判定选/舍 |
| 使用场景 | 稠密图（边多），邻接矩阵实现 O(n²) | 稀疏图（边少），排序 O(mlogm) + 并查集 |
| 典型示例 | 从 V0 出发依次并入 V1(3), V5(4), V8(5)... | 依次选 4-7(1), 2-8(2), 0-1(3)... |
| 记忆口诀 | Prim 拉点，Kruskal 拉线 | |

### 组2：Dijkstra vs Floyd

| 对比维度 | Dijkstra | Floyd |
|----------|----------|-------|
| 各自定义 | 单源点最短路径：一个源点到其余各点 | 多源点最短路径：每一对顶点之间 |
| 核心区别 | 贪心：逐个"确定"dist 最小的点 | 动态规划：逐个"放开"中转点 k |
| 各自特点 | 一维 D/P/Final，O(n²)，可用小顶堆优化 | 二维 D/P 矩阵，O(n³)，k 必须最外层 |
| 使用场景 | 只要一个起点到各处的距离/路径 | 要任意两点间的距离/路径 |
| 典型示例 | V0 到 V8 = 16，路径 V0→V1→V2→V4→V3→V6→V7→V8 | D⁽ᵏ⁾矩阵迭代，V0 行与 Dijkstra 结果一致 |
| 记忆口诀 | 单源 Dijkstra 贪心，全源 Floyd 递推 | |

### 组3：AOV 网 vs AOE 网

| 对比维度 | AOV 网 | AOE 网 |
|----------|--------|--------|
| 各自定义 | 顶点表示**活动**、弧表示活动间优先关系的有向图 | 边（弧）表示**活动**、顶点表示**事件**的带权有向无环图 |
| 核心区别 | 弧只表先后制约，**无权值** | 弧带权值 = 活动持续时间 |
| 各自特点 | 顶点即可并行活动，排序输出顶点序列 | 事件=瞬时状态，活动=有耗时的过程 |
| 使用场景 | 工程流程管理、课程先修安排、依赖判断 | 计算工期、找关键路径和关键活动 |
| 典型示例 | 先学 C 语言 → 才能学数据结构 | a1=6 表示活动 a1 需 6 天，工期 18 |
| 记忆口诀 | AOV 点是活动，AOE 边是活动 | |

### 组4：拓扑排序 vs 关键路径

| 对比维度 | 拓扑排序 | 关键路径 |
|----------|----------|----------|
| 各自定义 | 由 AOV 网的偏序得到全序的操作过程 | AOE 网中源点到汇点路径长度最长的路径 |
| 核心区别 | 只排"先后顺序"，不关心时间长短 | 找"最耗时"的路径，决定工程工期 |
| 各自特点 | 删顶点/入度减一，栈实现，可判环 | 拓扑正推 ETV、逆拓扑倒推 LTV、再算 ETE/LTE |
| 使用场景 | 课程表编排、代码依赖处理、判 DAG | 项目工期管理、资源调配（PMP） |
| 典型示例 | 序列 V1 V6 V4 V3 V2 V5 | 关键活动 ETE==LTE，工期=18 |
| 记忆口诀 | 拓扑排顺序，关键路径定工期（拓扑是关键路径的基础） | |

### 组5：关键活动 vs 非关键活动

| 对比维度 | 关键活动 | 非关键活动 |
|----------|----------|-----------|
| 各自定义 | 关键路径上的活动 | 不在关键路径上的活动 |
| 核心区别 | ETE == LTE（无富余时间） | ETE ≠ LTE（有富余时间） |
| 各自特点 | 拖延则整个工期延误，需优先保资源 | 可抽人力物力财力支援关键活动 |
| 使用场景 | 压缩它的耗时可缩短工期 | 晚开工（如 a9 最晚=10，最早=7）不影响完工 |
| 典型示例 | a1(0=0)、a4(6=6)、a7(7=7) | a6(ETE=5, LTE=8，富余3天) |
| 记忆口诀 | 关键零富余，非关键可偷懒 | |

## 📋 速查表

### 四大算法适用条件与复杂度

| 算法 | 解决问题 | 图型要求 | 存储结构 | 时间复杂度 | 核心数据 |
|------|----------|----------|----------|-----------|----------|
| 拓扑排序 | 活动顺序 / 判环 | AOV 网（有向无环） | 邻接表 | O(n+m)（矩阵 O(n²)） | indegree[] + 栈 |
| Prim | 最小生成树 | 无向连通带权 | 邻接矩阵 | O(n²) | dist[](到树)、flag[] |
| Kruskal | 最小生成树 | 无向连通带权 | 边集数组+并查集 | 排序 O(mlogm)+O(n+m) | f[](并查集)，选 n−1 条 |
| Dijkstra | 单源最短路径 | 带权，**无负权** | 邻接矩阵 | O(n²)（可小顶堆优化） | D/P/Final |
| Floyd | 多源最短路径 | 带权，**无负权** | 邻接矩阵 | O(n³)，空间 O(n²) | D/P 二维矩阵 |
| 关键路径 | 工期与关键活动 | AOE 网（有向无环带权） | 邻接表 | 拓扑+逆拓扑 O(n+m) | etv/ltv/ete/lte |

### 步骤模板

```
拓扑排序：  入度0全部入栈 → 出栈顶输出 → 邻接点入度-1，减到0入栈
            → 栈空时输出个数 < n ⇒ 有环
Kruskal：   边按权排序 → 依次取最小边 → 两端点不同集合(并查集)则选
            → 成环(同集合)舍弃 → 选满 n-1 条边停止
Prim：      任选起点入树 → 每轮选"树外点到树的最小边权"的点入树
            → 用新点松弛 dist[j]=min(dist[j], g[j][新点])
Dijkstra：  循环n次：①选 dist最小且 final==0 的点，final=1
            ②用该点松弛：dist[k]+g[k][i] < dist[i] 则更新 dist 和 pre
Floyd：     k 最外层 → i → j：
            dp[i][j] = min(dp[i][j], dp[i][k] + dp[k][j])
关键路径：  拓扑排序正推 ETV (max) → 逆拓扑倒推 LTV (min)
            → ETE=起点ETV，LTE=终点LTV−w → ETE==LTE 即关键活动
```

### 关键公式

```
ETV[源]=0            ETV[i] = max( ETV[j] + w<j,i> )     拓扑序正推
LTV[汇]=ETV[汇]      LTV[i] = min( LTV[j] − w<i,j> )     逆拓扑序倒推
ETE(k) = ETV(弧起点)            LTE(k) = LTV(弧终点) − w(k)
关键活动: ETE==LTE     关键路径上顶点: etv==ltv     工期 = 汇点ETV
```

### 结果速记（课件例）

```
最小生成树(9点15边)：边集{4-7,2-8,0-1,0-5,1-8,3-7,1-6,6-7}，总权 36（Prim/Kruskal 结果一致）
Dijkstra(源V0)：D=[0,1,4,7,5,8,10,12,16]  P=[0,0,1,4,2,4,3,6,7]
               V0→V8 最短路径：V0→V1→V2→V4→V3→V6→V7→V8，长 16
关键路径(AOE 9事件11活动)：ETV=[0,6,4,5,7,7,16,14,18] LTV=[0,6,6,8,7,10,16,14,18]
               关键活动 a1,a4,a7,a8,a10,a11；关键路径 V1→V2→V5→V7→V9 / V1→V2→V5→V8→V9，工期 18
```

### 常见陷阱对照

```
输出不全 < n     → 有向图有环（拓扑排序判环）
选边两端同集合   → 成环，Kruskal 必须舍弃
负权边          → Dijkstra / Floyd 都失效（现实少见但要记得）
Dijkstra 的 dist → 到源点的路径长；Prim 的 dist → 到树集合的边权
关键路径是活动的集合，不是事件的集合
关键路径是动态的：非关键路径可能变成关键路径
```
