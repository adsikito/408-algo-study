## 🗺️ 本章地图

本章解决的问题是：**"多对多"的关系怎么装进线性的内存、又怎么一个不漏地访问？**
- 先学**定义与术语**（知识点 1~6）：点、边、度、路径、连通——这是读懂后面一切内容的"词汇表"；
- 再学**存储结构**（知识点 7~10）：同样一张图，稠密用矩阵、稀疏用邻接表，还要出入度用十字链表、要操作边用多重邻接表/边集数组；
- 最后学**遍历**（知识点 11~12）：DFS 归结于栈（递归），BFS 归结于队列。
- 顺序不能颠倒：不懂"度"就看不懂存储结构为什么那样设计；没把图存进内存，遍历无从谈起。一句话——**术语是词汇，存储是纸，遍历是笔。**

## 📌 本章重点（3-5个）

⭐ **图的定义 G=(V, E)**：线性表一对一 → 树一对多 → 图多对多；任意两顶点都可能联系，无法用内存物理位置（线性）表达平面关系
⭐ **基本术语的计算**：完全无向图 n(n-1)/2 条边、完全有向图 n(n-1) 条弧；所有顶点度之和 = 2e；有向图度 = 入度 + 出度
⭐ **五种存储结构的选择**：邻接矩阵（稠密）、邻接表（稀疏）、十字链表（有向图求出入度）、邻接多重表（无向图边操作）、边集数组
⭐ **DFS 与 BFS 的本质**：DFS 归结于**栈**（递归），BFS 归结于**队列**；非连通图要在外层对每个顶点再启动一次遍历
⭐ **遍历复杂度**：邻接矩阵存图 O(n²)，邻接表存图 O(n+m)

## 🔥 本章难点（2-3个）

🔥 **"极大"与"极小"**：连通分量是**极大**连通子图（再加点就不连通）；生成树是**极小**连通子图（n 个结点只留 n-1 条边，再去边就不连通）
🔥 **十字链表与邻接多重表的结点设计**：一条边（弧）只有**一个结点**，却同时挂在**两条链**上（十字链表 tnext/hnext，多重邻接表 xnext/ynext）
🔥 **DFS 的手动模拟与回溯**：某顶点的邻接点均已被访问时，依次**退回到最近被访问的顶点**继续试探——这正是递归的归位过程

## ⚠️ 本章易错点（3-5个）

⚠️ **有向图邻接矩阵行列记反**：第 i **行**元素之和 = 出度，第 i **列**元素之和 = 入度（"行出列入"）
⚠️ **BFS 的标记时机**：vis 数组标记"是否**入队过**"，必须**入队时打标记**；若出队才打标记，同一顶点会重复入队
⚠️ **无向图一条边存两份**：邻接表中 e 条边有 2e 个边表结点（建边要头插两次）；邻接矩阵则是对称矩阵 a[i][j]=a[j][i]
⚠️ **连通 vs 强连通**：连通是**无向图**概念；强连通是**有向图**概念（i 到 j、j 到 i 都存在路径）
⚠️ **遍历序列不唯一**：访问次序取决于存储结构中邻接点的排列（矩阵按下标序、邻接表按链表序），同一图可有多个合法序列

## 📖 知识点讲解

### 1. 图的定义：G = (V, E)

**是什么**：把一群对象画成点、把它们之间的联系画成线，再把"点的全体"和"线的全体"各记成一个集合——这就是图的全部本质。落到定义：图 G 由两个集合组成，记为 G=(V, E)：V 是顶点的**有限非空**集合（顶点集，元素称顶点/点，用 |V| 表示顶点数）；E 是 V 中顶点偶对的有限集（边集，元素称边/弧，用 |E| 表示边数）。点代表事物或对象，边代表点之间的联系或相互作用——图是描述事物之间联系状态的概念。

**为什么**：线性表中元素只有一个直接前驱和一个直接后继（一对一）；树中元素是层次关系、只能和上一层中一个元素相关（一对多）；要描述**多对多**的复杂关系，就需要图。

**怎么用**：图形表示法——顶点用平面上的一个黑点表示，边用连接相应点对的任意形状的线表示。图上任一顶点都可被看作第一个顶点，任一顶点的邻接点之间也不存在次序关系。

**跟着算**：三人朋友圈，A、B、C 两两都是朋友：
```
V = {A, B, C}        E = {(A,B), (B,C), (A,C)}

   A
   │ ╲
   │  ╲
   B───C
```
|V| = 3，|E| = 3；A 的邻接点是 B 和 C。第 1 步先列顶点集 V，第 2 步再列边集 E——任何图都这样"两步装进数学"。

> ⚠️ 注意事项：V 必须非空；图的元素关系是"平面"的，而内存物理位置是线性的，所以**无法用物理位置表达元素关系**。

> 🎯 规律：遇到关系问题，第一步永远是定"谁是点、谁是边"——点边选对，问题就解了一半。

> 💡 一句话总结：图=顶点集+边集，多对多。

### 2. 图的分类：简单图、无向/有向、DAG、完全图

**是什么**：给图分类，其实只回答两个问题：边有没有方向？边够不够多？具体类别：
- **简单图**：不存在顶点到其自身的边，且同一条边不重复出现
- **无向图**：边的顶点偶对是**无序**的，用 (Vi, Vj) 表示，称为一条边（edge）
- **有向图**：边的顶点偶对是**有序**的，用 <Vi, Vj> 表示；Vi 为**弧尾**（箭头射出的那端，即起点），Vj 为**弧头**（箭头指向的那端，即终点）；一个图要么无向、要么有向，不存在部分有向部分无向（混合图 Mixed Graph 的边可有向可无向）
- **有向无环图（DAG）**：从任一顶点出发无法经过若干条边回到该顶点的有向图
- **完全图**：图中每两个顶点之间都存在一条边——完全无向图有 **n(n-1)/2** 条边，完全有向图有 **n(n-1)** 条边

**为什么**：有没有方向决定了边集的写法、度的含义、存储结构的选择，是一切后续内容的分水岭。

**怎么用**：n=4 时：完全无向图 4×3/2=6 条边；完全有向图 4×3=12 条弧。
```
K4（完全无向图，6 条边）          DAG（有向无环图）
A ─── B
│ ╲ ╱ │                          A ──→ B
│  ╳  │                          │     │
│ ╱ ╲ │                          ▼     ▼
C ─── D                          C ──→ D
边：A-B、A-C、A-D、                弧：A→B、A→C、B→D、C→D
    B-C、B-D、C-D                 沿任何箭头走都有去无回 → 无环
```

| 对比 | 无向图 | 有向图 |
|------|--------|--------|
| 边的表示 | (Vi, Vj)，无序 | <Vi, Vj>，有序 |
| 名称 | 边（edge） | 弧（弧尾→弧头） |
| 完全图边数 | n(n-1)/2 | n(n-1) |
| 度 | 边数 | 入度 + 出度 |

> ⚠️ 注意事项：无向图里 (i, j) 与 (j, i) 是**同一条边**；有向图里 <i, j> 与 <j, i> 是**两条不同的弧**。

> 🎯 规律：先问"边有没有方向"，再问"边全不全"——分类一定，公式、度、存储跟着全定。

> 💡 一句话总结：无向除以二，有向直接乘。

### 3. 邻接点、度、入度和出度

**是什么**：度就是数一个顶点身上"挂了几条线"；有向图再把线分成"甩出去的"（出度）和"落进来的"（入度）。严格说：
- **端点/邻接点**：无向图中存在边 (i, j)，则 i、j 互为邻接点；有向图中存在弧 <i, j>，则 i（起点）与 j（终点）互为邻接点
- **度**：无向图中顶点所具有的边的数目
- **出度（Out-degree）**：有 x 条边以该顶点为**起点**；**入度（In-degree）**：有 x 条边以该顶点为**终点**；一个顶点的入度和出度之和称为该顶点的度
- 在具有 e 条边的图中：**度之和为 2e**

**为什么**：每条边（弧）恰有两个端点、贡献两个"度"，所以全体顶点度之和必是边数的 2 倍——这是快速验算的利器。

**怎么用**：有向图求度不用逐个数：邻接矩阵中第 i 行之和 = 出度、第 i 列之和 = 入度（见知识点 7）；十字链表中沿 firstout/tnext 数出度、沿 firstin/hnext 数入度（见知识点 9）。

**跟着算**：无向图 4 个顶点，边 A-B、A-C、B-C、C-D：
```
A ─── B        度：A = 2（挂 B、C）
 ╲   ╱             B = 2（挂 A、C）
  ╲ ╱              C = 3（挂 A、B、D）
   C ─── D         D = 1（挂 C）
```
第 1 步逐点数"挂线"：2+2+3+1 = 8；第 2 步验算：e = 4，2e = 8 ✓。有向图同样成立：3 条弧 <A,B>、<B,C>、<C,A>，出度和 = 3、入度和 = 3，度之和 = 6 = 2e ✓。

> ⚠️ 注意事项：度之和 = 2e 对有向图同样成立（每条弧贡献 1 个出度 + 1 个入度）。

> 🎯 规律：数度就是数"挂线"：一条边给两端各记 1 度——验算永远回到 2e。

> 💡 一句话总结：每边两个头，度和必 2e。

### 4. 路径、回路与两类环路

**是什么**：路径就是一张"途经点行程单"——从哪出发、依次经过哪些点、走到哪。严格定义：
- **路径**：从顶点 i 到顶点 j 的一个顶点序列 (i, i1, i2, ..., im, j)；无向图要求边 (i,i1)、(i1,i2)...(im,j) 都属于 E(G)，有向图要求 <i,i1>、<i1,i2>...<im,j> 都属于 E(G)
- **路径长度**：一条路径上经过的**边的数目**
- **简单路径**：除开始点和结束点可以相同外，其余顶点均不相同的路径
- **回路/环**：开始点与结束点为同一个顶点的路径；开始点和结束点相同的简单路径称**简单回路/简单环**
- **欧拉环路**：经过图中各**边**一次且恰好一次的环路，长度恰等于图中边的总数，如 {C, A, B, A, D, C, D, B, C}
- **哈密尔顿环路**：经过图中各**顶点**一次且恰好一次的环路，如 {C, A, D, B, C}

**为什么**：欧拉看"边不重复"、哈密尔顿看"点不重复"，两者经常被放混，必须分清。

**怎么用**：在下面的图上练一遍"读路径"：
```
A ─── B        边：A-B、A-C、B-C、C-D
 ╲   ╱
  ╲ ╱
   C ─── D
```
第 1 步，验证路径 (A, B, C, D)：边 A-B、B-C、C-D 都存在 ✓，长度 = **3**（数边不数点：4 个顶点只算 3 条边）；中间没有重复顶点 → 是**简单路径**。
第 2 步，找回路：A→B→C→A 用到边 A-B、B-C、C-A，起点 = 终点 = A，其余顶点互不相同 → 是**简单回路**。
第 3 步，反例：(A, B, A, C) 中顶点 A 出现在中间 → 不是简单路径。

| 对比 | 欧拉环路 | 哈密尔顿环路 |
|------|----------|--------------|
| 不重复的对象 | 边 | 顶点 |
| 长度 | = 边的总数 | = 构成环路的边数 |
| 顶点可否重复 | 可以 | 不可以 |

> ⚠️ 注意事项：路径长度数的是**边数**，不是顶点个数。

> 🎯 规律：路径长度数边不数点；判断"简单"只看中间点是否重复。

> 💡 一句话总结：欧拉数边，哈密尔顿数点。

### 5. 连通、连通分量与生成树

**是什么**：连通问的是"任意两地能不能互相走到"；连通分量是把不连通的图切成的"几座孤岛"；生成树是把一座岛上的边删到"刚好够连通"。严格定义：
- **连通**：顶点 x 和 y 之间存在可相互抵达的路径（直接或间接）
- **连通图**（无向）：任意两个顶点都连通；否则为非连通图
- **连通分量**：无向图 G 中的**极大**连通子图；连通图只有一个分量（就是它本身，唯一），非连通图有多个；"极大"指再加入一个不在图点集中的点就会导致不连通
- **极小连通子图**：只有连通图才有这个概念——在能连通的前提下去掉多余的边（如四边形 4 个结点 4 条边，其实 3 条边就能连通）
- **强连通图**（有向）：任意两个顶点 i、j 之间，i 到 j 和 j 到 i 都存在路径；**强连通分量**：有向图的极大强连通子图，强连通图只有自身一个分量，非强连通图有多个
- **生成树**：连通图的生成树是一个**极小**连通子图，含图中全部 n 个结点，但只有构成树的 **n-1 条边**

**为什么**：极大 = 不能再加，极小 = 不能再减；前者针对"分量"，后者针对"生成树"。

**怎么用**——一张图看清"极大 → 极小 → 分量"：
```
原图（连通，5 条边）             生成树（保留 3 条边，如 A-B、A-D、D-C）
A ─── B                         A ─── B
│ ╲   │                         │
│  ╲  │                         D ─── C
│   ╲ │
D ─── C                         n=4，边恰为 n-1=3；再去任何一条边就断
边：A-B、B-C、C-D、D-A、A-C
```
第 1 步：原图连通，所以它的极大连通子图就是它自己（连通分量唯一）。
第 2 步：删边到恰好 n-1=3 条仍连通（如左下图），得到一棵生成树——生成树不唯一（保留 A-C、D-A、C-D 也行）。
第 3 步：若图里只剩 A-B 和 C-D 两条边：
```
A ─── B        C ─── D      →  两个连通分量 {A,B} 与 {C,D}
```
非连通图没有贯穿全图的生成树。

| 对比 | 极大连通子图（连通分量） | 极小连通子图（生成树） |
|------|--------------------------|------------------------|
| 前提 | 连通/非连通图都有 | 只有连通图才有 |
| 边数 | 尽可能多（保连通） | 恰好 n-1 条（保连通） |
| 加减一条边 | 加点会破坏 | 减边就不连通 |
| 唯一性 | 连通图时唯一 | 不一定唯一 |

> ⚠️ 注意事项：生成树 = 全部 n 个结点 + 恰好 n-1 条边；非连通图没有贯穿全图的生成树。

> 🎯 规律："极大/极小"都相对"保连通"：分量不能再加点，生成树不能再减边。

> 💡 一句话总结：极大是分量，极小是生成树。

### 6. 稠密图、稀疏图与权、网

**是什么**：稠密/稀疏是在问：这张图里"实线"多，还是"没连上的空位"多？严格说：
- 当一个图接近完全图时（边很多），称之为**稠密图**；边数较少的图称**稀疏图**。通常认为边数小于 **n·log n**（n 是顶点个数）的图为稀疏图，反之为稠密图
- **权**：与边相关的数，可以表示从一个顶点到另一个顶点的距离或花费的代价；边上带权的图称**带权图**，也叫**网**（有权图 Weighted Graph）。权值可以是整数、小数、负数，甚至自定义对象

**为什么**：稠密/稀疏直接决定存储方案——稠密图适合邻接矩阵（二维数组不亏），稀疏图适合邻接表（避免大量无效 0/∞ 占空间）。

**怎么用**：带权图的邻接矩阵中，值 = 权值（如两地间道路长 1200 公里，对应格子里就填 1200）；两个顶点之间没有弧时用 **∞** 表示。
**跟着算**：n = 8 的图，完全图应有 C(8,2) = 28 条边；判稀疏阈值 n·log n = 8×3 = 24（log 以 2 为底）。第 1 步数边：实际 10 条；第 2 步比较：10 < 24 → 稀疏图 → 选邻接表存，矩阵的 64 个格子里大半都是 ∞，白占空间。

> ⚠️ 注意事项：∞ 不是数学无穷大，而是"一个计算机允许的、大于所有边上权值的值"。

> 🎯 规律：先算 e < n·log n 定疏密，疏密直接替你选好存储结构。

> 💡 一句话总结：边多用矩阵，边少用邻接表。

### 7. 存储一：邻接矩阵

**是什么**：邻接矩阵就是给"所有可能的关系"排一张座位表：行是起点、列是终点，格子里填 1/0（或权值），查任何一条边只需报出行列号。落到结构上，用**两个数组**表示图：一个一维数组存顶点信息（vertex[]），一个二维数组存边信息（arc[][]，即邻接矩阵）。无向图的边数组是**对称矩阵**（沿主对角线对折两边能重合）：a[i][j] = a[j][i]；有向图则不一定对称；带权图矩阵中存权值、无弧处存 ∞。

**为什么**：有了这个二维数组，三件事变得非常容易：① 判定任意两顶点**是否有边**；② 求某个顶点的**度**——第 i 行（或第 i 列）元素之和；③ 求顶点 Vi 的**所有邻接点**——扫描第 i 行，arc[i][j] 为 1（或 <∞）即是。

**怎么用**（配套 `邻接矩阵.c`，带权无向图）：
```c
#define inf 10001                 /* "无穷大"：大于所有权值的值 */
char v[105]; int g[105][105];
/* 建边：一条无向边 = 两条方向相反、权值相同的有向边 */
g[xi][yi] = g[yi][xi] = w;
/* 求顶点 xi 的度：扫一行 */
int d = 0;
for (int j = 1; j <= n; j++)
    if (g[xi][j] < inf) d++;
```
**跟着算**（行出列入）：有向图 3 个顶点，弧 <V0,V1>、<V1,V2>、<V2,V0>、<V2,V1>：
```
V0 ──→ V1
 ▲    ↙ │
 │   ╱  │        （V1→V2 竖直向下；V2→V0、V2→V1 从 V2 发出）
 └──── V2
```
填表——第 1 步逐条弧"行填 1"：<V0,V1> → arc[0][1]=1；<V1,V2> → arc[1][2]=1；<V2,V0>、<V2,V1> → arc[2][0]=arc[2][1]=1。第 2 步按"行出列入"求和：
```
        V0   V1   V2     行和 = 出度      列和 = 入度
V0  [    0    1    0 ]       1               1（来自V2）
V1  [    0    0    1 ]       1               2（来自V0、V2）
V2  [    1    1    0 ]       2               1（来自V1）
```
第 3 步验算：度之和 = (1+1+2)+(1+2+1) = 8 = 2e（e=4 条弧）✓。
有向图示例：V0 到 V3 有弧 → arc[0][3]=1，V3 到 V0 无弧 → arc[3][0]=0；顶点 V1 的**入度 = 第 V1 列各数之和**，**出度 = 第 V1 行各数之和**。

| 对比 | 无向图邻接矩阵 | 有向图邻接矩阵 |
|------|---------------|---------------|
| 矩阵性质 | 对称 a[i][j]=a[j][i] | 不对称 |
| 求度 | 第 i 行（或列）之和 | 行和=出度，列和=入度 |
| 空间利用 | 对角线两侧重复，浪费一半 | 恰好用满 |

> ⚠️ 注意事项：面对**稀疏图**，邻接矩阵存在极大的空间浪费——这正是引出邻接表的动机。

> 🎯 规律：矩阵第 i 行管"出"、第 i 列管"入"——行出列入，一查就得。

> 💡 一句话总结：两个数组，行列定出入度。

### 8. 存储二：邻接表（含逆邻接表）

**是什么**：邻接表的思路是"每个顶点记一本自己的好友名单"：名单长短不一，所以用链表串，来一个邻接点就挂一个结点。严格说：① 图中顶点用一个一维数组存储（也可用单链表，但数组更易读取顶点信息）；② 每个顶点 Vi 的**所有邻接点**构成一个线性表——由于邻接点个数不确定，选用**单链表**存储。有向图若以顶点为**弧尾**建表，易求**出度**；若需便于确定顶点的入度或以顶点为弧头的弧，可建立**逆邻接表**（以弧头建表，易求入度）。

**为什么**：邻接矩阵对稀疏图浪费严重；邻接表只存实际存在的边，空间与"顶点数+边数"成正比。

**怎么用**（配套 `邻接表.c`，带权无向图，头插法建边——头插法即新结点总是插到链表最前面）：
```c
typedef struct ENode {
    int adj;               /* 邻接点的下标 */
    int w;                 /* 边权 */
    struct ENode *next;
} ENode;
struct Graph { char data; ENode *first; } g[105];  /* first 指向边链表 */

/* 无向边 x-y 存两份：y 头插进 x 的链表，x 头插进 y 的链表 */
e->adj = yi; e->w = w; e->next = g[xi].first; g[xi].first = e;
e->adj = xi; e->w = w; e->next = g[yi].first; g[yi].first = e;

/* 求顶点 xi 的度：数它的边链表长度 */
ENode *p = g[xi].first;
while (p != NULL) { d++; p = p->next; }
```
**跟着算**：3 个顶点 A、B、C，边 A-B(3)、A-C(5)，按此顺序头插建边：
```
第1步 建边 A-B：A 链表 [B]→∧；B 链表 [A]→∧（一条边挂两个结点）
第2步 建边 A-C：C 头插进 A 链表 → A 链表 [C]→[B]→∧；A 头插进 C 链表 → [A]→∧

data       边链表（后建的边排在链头）
A    →    [C|5] → [B|3] → ∧
B    →    [A|3] → ∧
C    →    [A|5] → ∧
```
验算：e = 2 → 边结点应共 2e = 4 个：A 链 2 个 + B 链 1 个 + C 链 1 个 = 4 ✓。注意 A 的链表序是 C 在前、B 在后——**头插法把建边顺序反了过来**，这正是"遍历序列不唯一"的根源之一。

> ⚠️ 注意事项：无向图一条边要建**两个**边结点；有向图（以弧尾建表）只建**一个**；两种表对同一边集的链表内容不同。

> 🎯 规律：链表里邻接点的次序由建边顺序决定（头插则相反）——这正是遍历序列不唯一的根源。

> 💡 一句话总结：顶点数组挂边链。

### 9. 存储三：十字链表

**是什么**：十字链表把"出边名单"和"入边名单"合订成一本：每条弧只印一张工牌（一个结点），却同时出现在两张名单上。它就是**邻接表和逆邻接表整合在一起**的有向图存储结构。边结点同时含弧尾、弧头信息；顶点结点设两个指针：firstout（出边链表）、firstin（入边链表）。

**为什么**：十字链表既容易找到以 Vi 为**尾**的弧，也容易找到以 Vi 为**头**的弧，因而容易求得顶点的**出度和入度**；除结构复杂一点外，创建图算法的时间复杂度与邻接表相同，因此在有向图应用中是非常好的数据结构模型。

**怎么用**（配套 `十字链表.c`，带权有向图）：
```c
typedef struct ENode {
    int w;
    int taili;  struct ENode *tnext;  /* 弧尾下标 + 弧尾的下一条出边（出边链表） */
    int headi;  struct ENode *hnext;  /* 弧头下标 + 弧头的下一条入边（入边链表） */
} ENode;
struct Graph { char data; ENode *firstout; ENode *firstin; } g[105];

/* 一条弧 x->y 只建一个结点，同时挂上两条链： */
e->taili = xi;  e->headi = yi;  e->w = w;
e->tnext = g[xi].firstout; g[xi].firstout = e;  /* 挂进 x 的出边链 */
e->hnext = g[yi].firstin;  g[yi].firstin  = e;  /* 挂进 y 的入边链 */

/* 出度走 tnext，入度走 hnext */
for (p = g[xi].firstout; p; p = p->tnext) outd++;
for (p = g[xi].firstin;  p; p = p->hnext) ind++;
```
**跟着算**：弧 V0→V1、V0→V2、V1→V2 按顺序插入，看每条弧怎么"一结点挂两链"：
```
第1步 插入 V0→V1：结点挂进 V0 出边链头 + V1 入边链头
第2步 插入 V0→V2：结点挂进 V0 出边链头（排到 V0→V1 前面）+ V2 入边链头
第3步 插入 V1→V2：结点挂进 V1 出边链头 + V2 入边链头

V0.firstout → [V0→V2] ═tnext═> [V0→V1] ═tnext═> ∧     出度(V0) = 2
V1.firstout → [V1→V2] ═tnext═> ∧                       出度(V1) = 1
V1.firstin   → [V0→V1] ═hnext═> ∧                      入度(V1) = 1
V2.firstin   → [V1→V2] ═hnext═> [V0→V2] ═hnext═> ∧     入度(V2) = 2
```
验算：出度之和 2+1+0 = 3 = 弧数 ✓（V2 的 firstin 沿 hnext 数出 2 个结点）。同一批结点，沿 tnext 数出度、沿 hnext 数入度，互不干扰。

> ⚠️ 注意事项：一条弧**只有一个结点**，但同时属于**两条**链表——出边链靠 tnext 串、入边链靠 hnext 串。

> 🎯 规律：找"谁出的"沿 tnext，找"谁入的"沿 hnext；一条弧永远只占一个结点。

> 💡 一句话总结：一弧两链，出入度全有。

### 10. 存储四：邻接多重表 与 边集数组

**是什么**：邻接多重表治的是邻接表"一条边存两份"的病：让一条无向边也只建一个结点，照样挂在两端的名单上；边集数组则干脆只留一张"边清单"。具体说：
- **邻接多重表**：无向图应用中若更关注**边的操作**（对已访问的边做标记、删除某一条边等），仿照十字链表对边表结构改装：iVex 和 jVex 是该边依附的两个顶点在顶点表中的**下标**；iLink 指向依附顶点 iVex 的**下一条边**，jLink 指向依附顶点 jVex 的下一条边
- **边集数组**：由两个一维数组构成——一个存顶点信息，一个存边信息；边数组的每个元素由一条边的**起点下标 begin、终点下标 end、权 weight** 组成

**为什么**：邻接表中一条无向边存两个结点，删除/标记一条边要改两处、找另一处也麻烦；多重邻接表**一条边只建一个结点**，边操作天然方便。边集数组则适合以"边"为核心的处理（如后续求最小生成树的 Kruskal 思路）。

**怎么用**（配套 `多重邻接表.c`，带权无向图）：
```c
typedef struct ENode {
    int w;
    int x;  struct ENode *xnext;  /* 端点 x 下标 + x 端的下一条边 */
    int y;  struct ENode *ynext;  /* 端点 y 下标 + y 端的下一条边 */
} ENode;
struct Graph { char data; ENode *first; } g[105];

/* 一条无向边一个结点，同时插入 a、b 两端的链表 */
e->x = ai; e->y = bi; e->w = w;
e->xnext = g[ai].first; g[ai].first = e;
e->ynext = g[bi].first; g[bi].first = e;

/* 遍历 ai 的边链表：走"依附 ai"的那条 next 指针 */
p = g[ai].first;
while (p != NULL) {
    d++;
    if (p->x == ai) p = p->xnext;
    else            p = p->ynext;
}
```
**跟着算**：3 个顶点 A、B、C，边 A-B(3)、A-C(5)，按此顺序头插，同十字链表一样"一结点挂两链"：
```
第1步 建边 A-B：结点[A-B|3] 从 A 端挂进 A 链、从 B 端挂进 B 链
第2步 建边 A-C：结点[A-C|5] 从 A 端挂进 A 链头、从 C 端挂进 C 链

A.first → [A-C|5] ═xnext═> [A-B|3] ═xnext═> ∧    （两个结点都从 x 端挂上）
B.first → [A-B|3] ═ynext═> ∧                     （从 y 端挂上）
C.first → [A-C|5] ═ynext═> ∧
```
遍历 A 的邻接点：[A-C|5] 的 x==A → 走 xnext；[A-B|3] 的 x==A → 再走 xnext；到 ∧ 停，度 = 2 ✓。对应的边集数组则只有两行：`(begin=0, end=1, weight=3)`、`(begin=0, end=2, weight=5)`。

> ⚠️ 注意事项：遍历多重邻接表时必须判断当前边结点是从 x 端挂上还是 y 端挂上，选对 next 指针，否则会走进死胡同。

> 🎯 规律：按问题的核心对象选结构——围着"边"转用边集数组/多重表，围着"点"转用邻接表/矩阵。

> 💡 一句话总结：一边一结点，删边标记快。

### 11. 深度优先搜索 DFS

**是什么**：DFS 就是走迷宫的笨办法：沿一条路一直走，撞墙（邻接点全被访问过）就退回上一个岔路口换条路——这正是"栈"的工作方式。深度优先遍历（Depth First Search），也有称为深度优化搜索，简称 **DFS**。树的**先序、中序、后序遍历**都属于深度优先遍历——这些方式本质上都归结于**栈**。两个直观原则：**右手原则**——没有碰到重复顶点时，分叉路口始终向右手边走，每路过一个顶点做记号（左手原则对称）；课件全篇以右手原则讲解。

**为什么**：图与树不同——从任一顶点出发可能沿环走回原点，所以必须给顶点打**已访问标记**；"一条路走到黑、走不通再退回"正是**递归/栈**的工作方式。

**怎么用**——DFS 三步骤（课件总结）：
1. 选定一个未被访问过的顶点 V 作为起始顶点（或访问指定的起始顶点 V），标记为已访问
2. 搜索与 V 邻接的所有顶点：若有未被访问过的顶点 W，再选取与 W 邻接的未被访问的一个顶点并访问，依次重复；当某顶点的所有邻接点均被访问时，**依次回退到最近被访问的顶点**，若该顶点还有未访问的邻接点，取一个重复上述过程，直到与起始顶点邻接的所有顶点被访问为止
3. 若此时图中依然有顶点未被访问，再选取一个顶点作为起始顶点进行遍历（转步骤 2）；反之，遍历结束

**跟着算**——先拿一张 6 顶点小图走完整流程（每个顶点的邻接点按字母序取）：
```
A ─── B ─── D
│           │
C ─── E ─── F      边：A-B、A-C、B-D、D-F、C-E、E-F
```
| 步 | 动作 | 递归栈（底→顶） |
|----|------|----------------|
| 1 | 访问 A，其未访问邻接点有 B、C，先走 B | A |
| 2 | 访问 B，A 已访问，走 D | A B |
| 3 | 访问 D，走 F | A B D |
| 4 | 访问 F，走 E | A B D F |
| 5 | 访问 E，走 C | A B D F E |
| 6 | 访问 C：邻接点 A、E 均已访问 → **开始回退** | A B D F E |
| 7 | 依次弹栈 E→F→D→B→A，途中均无未访问邻接点，结束 | …→ A |

序列 **A B D F E C**。看第 6、7 步："某顶点的邻接点均已被访问时退回"就是递归函数逐层 return——**回退 = 弹栈**，这正是"DFS 归结于栈"的含义。

课件 14 步示例（A 出发，右手原则）：A→B→C→D→E→F→G→H 后，H 的邻接点均已被访问，**退回** G→F→E→D，D 的邻接点 I 尚未访问则访问 I，最后一路退回起始顶点 A 结束——序列 **A B C D E F G H I**。把过程画成树形恰好就是二叉树的**前序遍历**过程。

配套 `DFS.c`（邻接矩阵存图，递归实现）：
```c
int flag[105];                        /* 标记某点是否访问过 */
void DFS(int i) {                     /* 对 i 点深度优先访问 */
    printf("%c ", v[i]);              /* 访问 */
    flag[i] = 1;                      /* 打标记：已访问 */
    for (int j = 1; j <= n; j++)      /* 找 i 的未被访问的邻接点 */
        if (g[i][j] == 1 && flag[j] == 0)
            DFS(j);
}
/* 非连通图兜底：每个顶点都可能成为新起点 */
for (int i = 1; i <= n; i++)
    if (flag[i] == 0) DFS(i);
```
复杂度（代码注释）：**邻接矩阵存图 O(n²)，邻接表存图 O(n+m)**。

**DFS 的优缺点与适用**（课件）：
- 优点：**空间优势**——DFS 不需要保存搜索过程中的状态（栈思想：搜索完一个点即弹出）
- 缺点：常用递归实现，若不给递归限制深度，往往超过时间与空间复杂度（递归深度 N 小于 20 的题目适用 DFS；N≥200 基本不可用）
- 适用：**搜索全部的解**；求解目标必须走到**最深**（如树走到叶子结点）才能得到解的情形

> ⚠️ 注意事项：外层 `for` 循环处理**非连通图**不能省，否则只会遍历到起点所在的连通分量。

> 🎯 规律：DFS 序就是递归"进入"各点的顺序（即先序）；"回退"就是函数逐层 return。

> 💡 一句话总结：一条道走到黑，撞墙回头。

### 12. 广度优先搜索 BFS

**是什么**：BFS 像往水里扔石头：波纹一圈圈向外扩，同一圈先被碰到的先处理——先进先出，天然是队列。广度优先遍历（Breadth First Search），又称广度优先搜索，简称 **BFS**。树的**层序遍历**就是一种广度优先搜索方式。BFS 一般步骤：① 将初始结点（一个或多个）加入队列；② 从队列头取出点，判断其周边结点，将符合条件的点加入队列尾部；③ 重复步骤 2 直至队列为空（一般每个点只加入队列一次）。

**为什么**：BFS 一层一层向外扩展，先被访问的顶点其邻接点也先被处理——先进先出，天然用**队列**实现。

**怎么用**——课件示例（A 出发，按层）：
```
第一层：A                       （第一步：访问顶点A）
第二层：B、F                    （第二步：A 的所有未被访问的邻接顶点）
第三层：C、I、G、E               （第三步：B、F 的所有未被访问的邻接顶点）
第四层：D、H                    （第四步：C、I、G、E 的邻接点中未被访问的顶点）
```
可见广度优先遍历是一层一层进行的，每层具体如何被访问就要靠队列实现。

**跟着算**——用与 DFS 相同的 6 顶点小图对比着走（邻接点按字母序）：
```
A ─── B ─── D
│           │
C ─── E ─── F      边：A-B、A-C、B-D、D-F、C-E、E-F
```
| 步骤 | 出队（访问） | 入队（入队即打标记） | 队列（队头→队尾） |
|------|-------------|---------------------|------------------|
| 1 | — | A | [A] |
| 2 | A | B、C | [B, C] |
| 3 | B | D | [C, D] |
| 4 | C | E | [D, E] |
| 5 | D | F | [E, F] |
| 6 | E | —（F 已标记） | [F] |
| 7 | F | — | [ ] 队空结束 |

序列 **A B C D E F**。同一张图：DFS 钻深（A B D F E C）、BFS 扩圈（A B C D E F）——第几层出队，就是离起点的最少边数，这正是 BFS 能顺带求最短步数的原因。

配套 `BFS.c`（邻接表存图 + 循环队列，入队时打标记）：
```c
int vis[105];                        /* 标记有没有入队过 */
void BFS(int p) {
    Queue q; InitQueue(&q);
    EnQueue(&q, p);  vis[p] = 1;     /* 起点入队，入队时打标记 */
    while (isEmpty(&q) == 0) {
        int x = DeQueue(&q);         /* 出队 */
        printf("%c ", g[x].data);    /* 访问 */
        ENode *t = g[x].first;
        while (t != NULL) {          /* 找 x 未入队过的邻接点 */
            if (vis[t->adj] == 0) {
                EnQueue(&q, t->adj);
                vis[t->adj] = 1;     /* 入队之后立刻打标记 */
            }
            t = t->next;
        }
    }
}
/* 非连通图兜底：for(i=1..n) if(vis[i]==0) BFS(i); */
```
复杂度：**邻接表存图 O(n+m)，邻接矩阵存图 O(n²)**。（代码中还留有 `dis[]` 数组：初始化为无穷大存距离——BFS 可顺带求起点到各点的最短步数。）

**BFS 的优缺点与适用**（课件）：
- 缺点：搜索过程中**必须保存搜索状态**用于判重（需要队列记录）
- 适用：一般树或图中用 BFS 的可能性较大；**搜索最短路径的解**比较合适（求最少步数、最少交换次数的解）——BFS 搜索过程中遇到的解一定是离根最近的，遇到解即可停止；此时不适宜 DFS（DFS 搜索到的解不一定是离根最近的，需全局搜索完毕）

**课件总结**（务必记住的两条链）：
```
DFS → 前中后序遍历 → 栈     → 线性表
BFS → 层序遍历     → 队列   → 链表
```
树的先序/中序/后序也可用栈实现，层序用队列实现——知识融会贯通。

> ⚠️ 注意事项：BFS 的 vis 标记含义是"**入队过**"，在**入队时**打；若在出队时才打标记，同一顶点会被多个邻接点重复塞进队列。

> 🎯 规律：队列里排的是"待处理的下一圈"；入队即打标记，一个点一生只入队一次。

> 💡 一句话总结：一层一层扫，队列保平安。

### 🧩 本章归纳：一条主线串全章

把全章串成一条因果链：

```
关系"多对多"（定义 G=(V,E)）
   → 术语给关系"量化"（度数边数、路径回路、连通与生成树）
   → 关系的疏密决定"存法"（稠密→矩阵，稀疏→邻接表，边操作→多重表）
   → 存储里邻接点的排列决定"遍历序列"（矩阵按下标序，链表按建边序）
   → 遍历的工具回归老朋友（DFS=栈/递归，BFS=队列）
```

回头看才看得见的三条共性规律：
1. **存储结构决定允许的操作与代价**：要 O(1) 判边选矩阵，要省空间选邻接表，要边操作选多重表，要同时求出入度选十字链表——没有最好的结构，只有匹配问题的结构。
2. **"一份信息挂两条链"是高级存储的共同设计**：十字链表的一条弧、多重邻接表的一条边都只有一个结点，却用两根 next 指针同时服务两端——用指针换掉重复存储。
3. **图把前几章全部收编**：一对一退化为线性表，无环一对多退化为树，DFS/BFS 直接把栈和队列当引擎——新章节其实是旧数据结构的组合应用，而"打访问标记"是图区别于树的根本原因（有环，不标记就转圈）。

## 🔍 相似概念辨析

### 组1：无向图 vs 有向图

| 对比维度 | 无向图 | 有向图 |
|----------|--------|--------|
| 各自定义 | 边的顶点偶对无序的图 | 边的顶点偶对有序的图 |
| 核心区别 | (i, j) 与 (j, i) 是同一条边 | <i, j> 与 <j, i> 是两条弧 |
| 各自特点 | 边称 edge，无弧尾弧头之分 | Vi 为弧尾（起点）、Vj 为弧头（终点） |
| 使用场景 | 双向关系（道路、朋友） | 单向关系（任务依赖、网页链接） |
| 典型示例 | 完全无向图 n(n-1)/2 条边 | 完全有向图 n(n-1) 条弧；DAG |
| 记忆口诀 | 无向一条边，有向分头尾 | |

### 组2：邻接矩阵 vs 邻接表

| 对比维度 | 邻接矩阵 | 邻接表 |
|----------|----------|--------|
| 各自定义 | 一维顶点数组 + 二维边数组 arc[][] | 顶点数组 + 每个顶点的邻接点单链表 |
| 核心区别 | 存"所有可能的关系"（含不存在的边） | 只存"实际存在的边" |
| 各自特点 | O(1) 判边；第 i 行(列)和=度(入/出度) | 省空间；数链表长度=度；找边需遍历链 |
| 使用场景 | 稠密图、频繁判边 | 稀疏图、频繁找邻接点 |
| 典型示例 | 无向图矩阵对称，浪费一半空间 | e 条边只建 e（有向）或 2e（无向）个边结点 |
| 记忆口诀 | 矩阵全铺开，链表按需挂 | |

### 组3：十字链表 vs 邻接多重表

| 对比维度 | 十字链表 | 邻接多重表 |
|----------|----------|-----------|
| 各自定义 | 邻接表+逆邻接表整合的有向图存储 | 边表改装后、一条边一个结点的无向图存储 |
| 核心区别 | 服务**有向图**（出入度） | 服务**无向图**（边操作） |
| 各自特点 | 边结点含 taili/tnext、headi/hnext，挂两条链 | 边结点含 iVex/jVex、iLink/jLink，挂两条链 |
| 使用场景 | 需同时求出度和入度 | 对已访问边做标记、删除边等频繁边操作 |
| 典型示例 | firstout 数出度、firstin 数入度 | 遍历时按 p->x==ai 选 xnext 或 ynext |
| 记忆口诀 | 十字管有向，多重管无向 | |

### 组4：连通分量 vs 生成树

| 对比维度 | 连通分量 | 生成树 |
|----------|----------|--------|
| 各自定义 | 无向图的**极大**连通子图 | 连通图的**极小**连通子图（含全部 n 个结点） |
| 核心区别 | 边尽量多、不能再加 | 边恰好 n-1、不能再减 |
| 各自特点 | 连通图只有一个（自身）；非连通图有多个 | 去掉任一条边就不连通 |
| 使用场景 | 分析非连通图由几块组成 | 最小生成树等算法的基础形态 |
| 典型示例 | 强连通分量是其有向图版本 | n 个结点 n-1 条边 |
| 记忆口诀 | 极大是分量，极小是生成树 | |

### 组5：DFS vs BFS

| 对比维度 | DFS（深度优先） | BFS（广度优先） |
|----------|----------------|----------------|
| 各自定义 | 沿一条路径走到最深处再回退的遍历 | 从起点一层一层向外扩展的遍历 |
| 核心区别 | 归结于**栈**（递归） | 归结于**队列** |
| 各自特点 | 不需保存搜索过程中的状态（空间优） | 必须保存搜索状态用于判重 |
| 使用场景 | 搜索全部的解、必须走到最深的解 | 最短路径类解（最少步数/交换），遇解即停 |
| 典型示例 | 树的前中后序遍历；课件序列 A B C D E F G H I | 树的层序遍历；课件按层 A｜B F｜C I G E｜D H |
| 记忆口诀 | 深搜一根筋，广搜荡涟漪 | |

### 组6：欧拉环路 vs 哈密尔顿环路

| 对比维度 | 欧拉环路 | 哈密尔顿环路 |
|----------|----------|--------------|
| 各自定义 | 经过图中各**边**一次且恰好一次的环路 | 经过图中各**顶点**一次且恰好一次的环路 |
| 核心区别 | 边不重复（点可重复） | 点不重复 |
| 各自特点 | 长度恰等于图中边的总数 | 长度等于构成环路的边数 |
| 使用场景 | 一笔画类问题 | 途经所有点的巡游类问题 |
| 典型示例 | {C, A, B, A, D, C, D, B, C} | {C, A, D, B, C} |
| 记忆口诀 | 欧拉数边，哈密尔顿数点 | |

## 📋 速查表

### 数字速记
```
完全无向图边数 n(n-1)/2      完全有向图弧数 n(n-1)
所有顶点度之和 = 2e          有向图：度 = 入度 + 出度
生成树：n 个结点、n-1 条边    稀疏图：e < n·log n（n 为顶点数）
稠密图：接近完全图            网 = 带权图（权可为负、可为小数）
```

### 有向图邻接矩阵求度
```
出度 = 第 i 行元素之和        入度 = 第 i 列元素之和（行出列入）
```

### 五种存储结构对比
| 存储结构 | 适用图 | 核心结构 | 一句话优势 |
|----------|--------|----------|-----------|
| 邻接矩阵 | 稠密图 | 顶点数组+边二维数组 | O(1) 判边，行列求度 |
| 邻接表 | 稀疏图 | 顶点数组+邻接点单链表 | 省空间，遍历 O(n+m) |
| 逆邻接表 | 有向图 | 以弧头建边链表 | 便于求入度 |
| 十字链表 | 有向图 | 出边链+入边链 | 出度入度都好求 |
| 邻接多重表 | 无向图 | 一边一结点双链 | 标记/删边方便 |
| 边集数组 | 边为核心 | (begin, end, weight) 数组 | 简单直观 |

### 复杂度速记
```
DFS / BFS：邻接矩阵存图 O(n^2)；邻接表存图 O(n+m)
十字链表建图时间复杂度与邻接表相同
```

### 遍历代码模板
```c
/* DFS：递归即隐式用栈，访问时打标记 */
void DFS(int i) {
    printf("%c ", v[i]);  flag[i] = 1;
    for (int j = 1; j <= n; j++)
        if (g[i][j] == 1 && flag[j] == 0) DFS(j);
}
/* BFS：循环队列，入队时打标记 */
void BFS(int p) {
    EnQueue(&q, p);  vis[p] = 1;
    while (!isEmpty(&q)) {
        int x = DeQueue(&q);  printf("%c ", g[x].data);
        for (t = g[x].first; t; t = t->next)
            if (vis[t->adj] == 0) { EnQueue(&q, t->adj); vis[t->adj] = 1; }
    }
}
/* 非连通图兜底（DFS/BFS 通用） */
for (int i = 1; i <= n; i++)
    if (未访问) 从 i 开始遍历;
```

### 两条融会贯通链
```
DFS → 前中后序遍历 → 栈     → 线性表
BFS → 层序遍历     → 队列   → 链表
```
