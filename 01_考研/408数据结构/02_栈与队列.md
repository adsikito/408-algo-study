## 本章地图

上一章的线性表允许「随便插、随便删」，但大量真实场景只在一端或两端操作：函数调用只压栈弹栈、打印机任务只排队。本章就是给线性表**加限制**——只许一端进出是**栈**（后进先出，LIFO），一端进一端出是**队列**（先进先出，FIFO）。限制变少反而让结构变得更快（全部 O(1)）也更专用。

学习路径与素材原章一致，按「先受限、再回绕、后放开、上工程」展开：先用顺序与链式两种存储把栈落地；队列走同一条路——顺序队列暴露出**假溢出**缺陷，于是催生**循环队列**（全章枢纽：取模三大公式）；再把限制放松到两端得到**双端队列**；最后归纳栈与队列在括号匹配、表达式求值、递归、缓冲区等场景的应用。本章末尾【补充】408 大纲明确要求但原资料缺失的**数组存储与特殊矩阵压缩存储**——它形式上独立，考法上是纯下标计算题。

## 本章重点

> **【重点】** **栈的定义**：只允许在**栈顶**一端进行插入（入栈 / push）和删除（出栈 / pop）的线性表，后进先出 LIFO。栈底固定，栈顶浮动。

> **【重点】** **循环队列三大公式**（牺牲一个存储单元的约定下）：
> 判空 `rear == front`；判满 `(rear + 1) % maxSize == front`；
> 元素个数 `(rear - front + maxSize) % maxSize`。

> **【重点】** **队列的定义**：只允许在**队尾**插入（入队）、**队头**删除（出队）的线性表，先进先出 FIFO。

> **【重点】** **特殊矩阵压缩存储的下标映射**【补充】：对称矩阵、三角矩阵、三对角矩阵按「行优先 + 等差数列求和」把二维下标映射到一维数组；核心是**数出该元素前面存了多少个元素**。

> **【重点】** **栈与队列的应用对应**：函数调用与递归 → 栈；操作系统作业调度、缓冲区（如键盘缓冲） → 队列；表达式求值 → 操作数栈 + 运算符栈。

---

## 本章难点

> **【难点】** **循环队列为什么牺牲一个存储单元**：若不牺牲，队空与队满都是 `rear == front`，无法区分。牺牲一格后，队满变成「尾的下一格撞上头」，即 `(rear + 1) % maxSize == front`。替代方案（增设 `size` 变量或 `tag` 标志）也必须掌握，408 两种考法都出现过。

> **【难点】** **取模实现「循环」**：指针前进用 `(x + 1) % maxSize`；**后退必须先加再模** `(x - 1 + maxSize) % maxSize`，否则下标变负数越界。

> **【难点】** **链式队列出队时的队尾指针维护**：删除最后一个结点后必须 `rear = front`（退回头结点），否则 `rear` 悬空成野指针，之后再入队会写崩内存。

---

## 本章易错点

> **【易错】** **数据结构中的栈 ≠ 内存中的栈区**：前者是抽象数据类型（一组受限操作），后者是内存中真实的一块区域；两者的「堆」与「栈」概念也不可混为一谈。

> **【易错】** **出栈 ≠ 数据被删除**：出栈只是栈顶指针下移，数据仍在原存储单元，只是被当作垃圾；下次入栈会覆盖它。

> **【易错】** **队头队尾方向记反**：入队是**队尾指针 +1**（`rear = (rear + 1) % maxSize`），出队是**队头指针 +1**（`front = (front + 1) % maxSize`）。

> **【易错】** **`top` 的语义混用**：`top` 是**下标**不是真指针。顺序栈 `top` 初始化为 0 时（指向下一个可放位置），`top - 1` 才是栈顶元素，`top == 0` 空、`top == maxSize` 满；若初始化为 -1（指向栈顶），则 `top == -1` 空、`top == maxSize - 1` 满。**两种约定都要会，读题先看约定**。

> **【易错】** **压缩存储公式里的「下标从 0 还是从 1 开始」**：教材与真题两种口径都出过，做题时先确认数组下标起点，再套公式；两口径的差是一个常数项。

## 知识点讲解

### 2-1　栈的定义与基本操作　【P0】

**是什么**：白话说，栈就是**只有一个口的容器**——进和出都走同一个口（栈顶）。严格定义：栈（Stack）是限定仅在**表尾**（栈顶 top）进行插入和删除操作的线性表；允许操作的一端叫栈顶，固定的一端叫栈底（bottom）。不含元素的栈叫空栈。

**为什么**：很多过程天然「后进先出」——函数调用里最后被调用的函数最先返回；编辑器的撤销（Undo）撤销的总是最近一次操作；走迷宫时退回的总是最近走过的岔路口。用普通线性表实现这些逻辑要在中间找位置，用栈则所有操作都发生在固定端，**天然 O(1)**。

**怎么用**：基本运算只有五个（408 简答题常要求写出定义）：

| 操作 | 含义 |
|------|------|
| `InitStack(&S)` | 初始化空栈 |
| `StackEmpty(S)` | 判空 |
| `Push(&S, x)` | 入栈：若未满，x 成为新栈顶 |
| `Pop(&S, &x)` | 出栈：若未空，取出栈顶并删除 |
| `GetTop(S, &x)` | 读栈顶：不删除 |

> **【类比】** 弹夹装子弹：最先压入的子弹最后打出；或者食堂摞盘子：取的总是最上面的，洗好的盘子也放在最上面。

> **【规律】** n 个**不同**元素依次入栈，出栈序列的种数 = 卡特兰数 C(2n, n) / (n + 1)。3 个元素为 5 种，4 个为 14 种。选择题常问「某序列是否可能」，用**模拟法**逐个判断（见知识点 2-7）。

**前置与延伸**：
- 前置：线性表的定义与两种存储结构（第 1 章 1-1、1-2）
- 延伸：递归的机器级实现（函数调用栈）、表达式求值（知识点 2-8）、深度优先搜索（第 5 章）

### 2-2　顺序栈与共享栈　【P0】

**是什么**：顺序栈 = 用**数组**存栈，`top` 记录栈顶位置。共享栈 = 两个栈共用一个数组，一个栈的栈底在数组头、另一个在数组尾，**两栈顶相向而行**。

**为什么**：顺序栈实现最简单、无指针开销；共享栈把「一个数组只装一个栈」的浪费补回来——两个栈的空间需求**互补**（一个涨另一个缩）时，共享栈比两个独立数组更省内存，且只有两栈顶相遇才溢出。

**怎么用**（采用 `top` 指向栈顶元素的约定，即初始 -1）：

```c
#include <stdio.h>
#include <stdlib.h>

#define MAXSIZE 100              /* 栈的最大容量 */
typedef int ElemType;

typedef struct {
    ElemType data[MAXSIZE];
    int top;                     /* 栈顶下标：-1 表示空栈 */
} SqStack;

void InitStack(SqStack *S) { S->top = -1; }

int StackEmpty(SqStack S) { return S->top == -1; }

int Push(SqStack *S, ElemType x) {
    if (S->top == MAXSIZE - 1)   /* 栈满，上溢 */
        return 0;
    S->data[++S->top] = x;       /* 指针先加 1，再存元素 */
    return 1;
}

int Pop(SqStack *S, ElemType *x) {
    if (S->top == -1)            /* 栈空，下溢 */
        return 0;
    *x = S->data[S->top--];      /* 先取元素，指针再减 1 */
    return 1;
}

int GetTop(SqStack S, ElemType *x) {
    if (S->top == -1) return 0;
    *x = S->data[S->top];
    return 1;
}
```

共享栈的判满：`top0 + 1 == top1`（0 号栈从低往高长，1 号栈从高往低长）。

> **【注意】** 若约定 `top` 指向**下一个可插入位置**（初始 0），则入栈是 `data[top++] = x`，出栈是 `x = data[--top]`，判满是 `top == MAXSIZE`。**两种约定都合法，读代码先看初始化**；408 选择题专门考两种约定的转换。

> **【规律】** 顺序栈的「上溢」是**异常**（容量不够），「下溢」是**正常**（可能是程序结束的条件）。填空题爱考这个措辞。

**前置与延伸**：
- 前置：知识点 2-1；顺序表（第 1 章 1-2、1-3）
- 延伸：多栈共享与动态扩容（非考纲，工程中用链式栈或动态数组替代）

### 2-3　链栈　【P1】

**是什么**：用**单链表**实现的栈，约定**头指针即栈顶**——入栈出栈都只在表头做，把「栈顶操作」转化为 O(1) 的「头插头删」。

**为什么**：链栈无容量上限、无假满，适合栈深难估计的场景；代价是每结点多一个指针域、`malloc` 有开销。408 对链栈的考查远少于顺序栈，重点是「为什么栈顶设在表头」。

**怎么用**：

```c
#include <stdio.h>
#include <stdlib.h>

typedef int ElemType;

typedef struct StackNode {
    ElemType data;
    struct StackNode *next;
} StackNode, *LinkStack;

/* 入栈：头插法，新结点成为栈顶 */
int Push(LinkStack *top, ElemType x) {
    StackNode *p = (StackNode *)malloc(sizeof(StackNode));
    if (!p) return 0;
    p->data = x;
    p->next = *top;              /* 新结点接在原栈顶之前 */
    *top = p;
    return 1;
}

/* 出栈：删除头结点 */
int Pop(LinkStack *top, ElemType *x) {
    if (*top == NULL) return 0;  /* 栈空 */
    StackNode *p = *top;
    *x = p->data;
    *top = p->next;
    free(p);
    return 1;
}
```

> **【规律】** 链栈一般**不设头结点**（头结点只会让栈顶多绕一跳）；判空就是 `top == NULL`。若题目给了带头结点的链栈，栈顶元素是 `top->next->data`。

**前置与延伸**：
- 前置：知识点 2-1；单链表头插法（第 1 章 1-4、1-5）
- 延伸：链式双端队列、多栈链式共享

### 2-4　队列的定义与顺序队列的假溢出　【P0】

**是什么**：队列（Queue）是只允许在**一端插入（队尾 rear）、另一端删除（队头 front）**的线性表，先进先出 FIFO。

**为什么**：凡是「先来先服务」的场景都用它——主机与打印机速度不匹配时用打印队列缓冲、多用户竞争 CPU 时用就绪队列排队、键盘缓冲区也是队列。**顺序队列**用数组加 front、rear 两个下标实现，但「出队后数组前部空出来却不能用」的**假溢出**问题决定了必须演进到循环队列。

**怎么用**：假溢出的推演（容量 5）：入队 a b c d e（rear=5，满）→ 出队 a b c（front=2）→ 再想入队 f，`rear == maxSize` 判满——**但前两个单元明明是空的**。这就是假溢出：rear 撞到数组边界，而非真正没有空间。

> **【注意】** 队列的基本操作与栈对应：`InitQueue` / `QueueEmpty` / `EnQueue`（入队）/ `DeQueue`（出队）/ `GetHead`（读队头）。简答题写定义时，方向别写反：**队尾入、队头出**。

**前置与延伸**：
- 前置：知识点 2-1（与栈对比着记）
- 延伸：循环队列（下一知识点，必考）、消息队列（工程概念，非考纲）

### 2-5　循环队列（三大公式）　【P0】

**是什么**：把顺序队列的数组**首尾逻辑相接**（下标对容量取模）构成环形结构，指针走到末尾就绕回头部，从而消除假溢出。

**为什么**：假溢出的根源是「数组是直线的、逻辑上是环形的」这一错位。取模运算 `(x + 1) % maxSize` 让下标在 `maxSize - 1` 之后回到 0，物理上仍是普通数组，逻辑上变成环。

**怎么用**：核心约定——**牺牲一个存储单元**来区分队空与队满：

| 项目 | 公式 | 记忆 |
|------|------|------|
| 判空 | `front == rear` | 两指针相遇且只差一圈以内 |
| 判满 | `(rear + 1) % maxSize == front` | rear 的下一格撞上 front |
| 元素个数 | `(rear - front + maxSize) % maxSize` | 先减防负，再模回绕 |

```c
#include <stdio.h>

#define MAXSIZE 100              /* 实际最多存 MAXSIZE-1 个元素 */
typedef int ElemType;

typedef struct {
    ElemType data[MAXSIZE];
    int front, rear;             /* front 队头，rear 队尾的下一位置 */
} CircularQueue;

void InitQueue(CircularQueue *Q) { Q->front = Q->rear = 0; }

int QueueEmpty(CircularQueue Q) { return Q.front == Q.rear; }

int EnQueue(CircularQueue *Q, ElemType x) {
    if ((Q->rear + 1) % MAXSIZE == Q->front)   /* 队满 */
        return 0;
    Q->data[Q->rear] = x;
    Q->rear = (Q->rear + 1) % MAXSIZE;         /* 取模回绕 */
    return 1;
}

int DeQueue(CircularQueue *Q, ElemType *x) {
    if (Q->front == Q->rear)                   /* 队空 */
        return 0;
    *x = Q->data[Q->front];
    Q->front = (Q->front + 1) % MAXSIZE;
    return 1;
}
```

> **【注意】** 另外两种「不牺牲单元」的方案也要会（选择题考过辨析）：
> ① 增设 `size` 变量记录元素个数，`size == 0` 空、`size == maxSize` 满，front 与 rear 独立增减；
> ② 增设 `tag` 标志：只有**入队后**才可能满（入队置 1），只有**出队后**才可能空（出队置 0），于是 `rear == front && tag == 1` 为满、`== 0` 为空。
> 三种方案的元素个数计算方式各不相同，按题目给的约定作答。

> **【规律】** 元素个数公式里的 `+ maxSize` 是防负数：rear 小于 front（已回绕）时 `rear - front` 为负，先加一圈再取模。同理**后退必须 `(x - 1 + maxSize) % maxSize`**。真题直接考「rear=2, front=98, maxSize=100，队列里几个元素」→ `(2 - 98 + 100) % 100 = 4`。

> **【记忆】** 「空等满差一」：判空是相等，判满差一个单元。

**前置与延伸**：
- 前置：知识点 2-4；取模运算（附录 A）
- 延伸：第 4 章二叉树的层序遍历用的就是循环队列；操作系统的循环缓冲区同理

### 2-6　链式队列　【P0】

**是什么**：用**带头结点的单链表**实现的队列，`front` 指头结点（出队在其后删），`rear` 指队尾结点（入队在其后插）。

**为什么**：链式队列无容量限制、无假溢出；出入队都在端点，天然 O(1)。408 综合题爱考它，因为「删除最后一个结点后 rear 怎么办」是真实的指针陷阱。

**怎么用**：

```c
#include <stdio.h>
#include <stdlib.h>

typedef int ElemType;

typedef struct QueueNode {
    ElemType data;
    struct QueueNode *next;
} QueueNode;

typedef struct {
    QueueNode *front, *rear;     /* front 指头结点，rear 指队尾结点 */
} LinkQueue;

void InitQueue(LinkQueue *Q) {
    QueueNode *head = (QueueNode *)malloc(sizeof(QueueNode));
    head->next = NULL;
    Q->front = Q->rear = head;   /* 空队：两指针都指头结点 */
}

int QueueEmpty(LinkQueue Q) { return Q.front == Q.rear; }

int EnQueue(LinkQueue *Q, ElemType x) {
    QueueNode *p = (QueueNode *)malloc(sizeof(QueueNode));
    if (!p) return 0;
    p->data = x;
    p->next = NULL;
    Q->rear->next = p;           /* 接在队尾之后 */
    Q->rear = p;
    return 1;
}

int DeQueue(LinkQueue *Q, ElemType *x) {
    if (Q->front == Q->rear) return 0;         /* 队空 */
    QueueNode *p = Q->front->next;             /* 第一个数据结点 */
    *x = p->data;
    Q->front->next = p->next;
    if (Q->rear == p)            /* 删的是最后一个结点：rear 退回头结点 */
        Q->rear = Q->front;      /* 否则 rear 悬空成野指针 */
    free(p);
    return 1;
}
```

> **【难点】** 上面标出的 `if (Q->rear == p)` 一行是本章链式部分**最重要的两行代码**：删到最后一个结点时不把 rear 拉回头结点，rear 就指向已 free 的内存，之后再入队等于写野指针。综合题答案里漏掉这两行通常扣一半分。

**前置与延伸**：
- 前置：知识点 2-4；单链表插入删除（第 1 章 1-5）
- 延伸：双端队列的链式实现、第 5 章图的 BFS 队列

### 2-7　双端队列与输出序列判定　【P0】

**是什么**：双端队列（Deque）= 两端都可插入与删除的队列。继续加限制得两个退化形态：**输入受限的双端队列**（只有一端能插）、**输出受限的双端队列**（只有一端能删）；只许一端进出即栈、一端进另一端出即普通队列。

**为什么**：它是 408 选择题的固定考点，考两件事：一是给出一个输出序列，判断它**能否**由某类队列得到；二是借它考「栈的合法输出序列」的模拟判定法。

**怎么用（栈的输出序列模拟判定法）**：判断序列 B 是否可能是入栈序列 A 的输出序列——按 A 的顺序依次入栈，**每入一个就尽量出栈**（只要栈顶等于 B 中下一个需要的元素就连续出栈）；扫完后栈空则可能，否则不可能。
例：入栈序 1 2 3 4，问 3 1 4 2 是否可能？入 1 入 2 入 3 → 出 3 → 栈顶是 2，而下一个要 1，1 被压在 2 下面**取不到** → 不可能。口诀：**下一个要出的元素必须正好在栈顶，否则该序列非法**。

> **【规律】** 经典结论：入栈序 1 2 … n 时，**任何含「…… 大元素、小 a、中 b ……」且 a、b 都在栈内被隔开的模式要警惕**；快速排除法——输出序列中若存在 `i < j < k` 位置上出现 `k 先出、随后小的大数` 排列错乱（如 3 1 2 型），必非法。3 1 2 不可能，3 2 1 可能（全入完再依次弹）。

> **【类比】** 双端队列 = 两头都能开关的安检通道；输入受限 = 只有前门能进但两头能出；输出受限 = 两头能进只有后门能出。画一个横条、两端标进/出箭头，把序列套进去模拟即可。

**前置与延伸**：
- 前置：知识点 2-1、2-4
- 延伸：滑动窗口最大值（单调双端队列，算法设计题热门，超出 408 必须范围）

### 2-8　栈与队列的典型应用　【P0】

**是什么**：把前七个知识点放到真实问题里：括号匹配、表达式求值、递归与函数调用、队列做缓冲与调度。

**为什么**：408 综合应用题（尤其算法设计题）常以这些应用为背景出题，要求「思路 + C 代码 + 复杂度」三段式作答。

**怎么用**：

**应用一：括号匹配（栈）**
扫描字符串，遇左括号入栈；遇右括号则检查栈顶是否为对应左括号：是则弹栈，否则失配。扫完后栈非空也失配。

```c
int isMatch(char *s) {
    char stack[1000];
    int top = -1;
    for (; *s; s++) {
        if (*s == '(' || *s == '[' || *s == '{')
            stack[++top] = *s;
        else if (*s == ')' || *s == ']' || *s == '}') {
            if (top == -1) return 0;         /* 右括号多 */
            char c = stack[top--];
            if ((*s == ')' && c != '(') ||
                (*s == ']' && c != '[') ||
                (*s == '}' && c != '{'))
                return 0;                     /* 类型不配 */
        }
    }
    return top == -1;                         /* 栈非空说明左括号多 */
}
```
时间 O(n)，空间 O(n)。

**应用二：表达式求值（两个栈）**
中缀转后缀（逆波兰式）或直接双栈求值：操作数栈 + 运算符栈。运算符入栈前与栈顶**比优先级**：栈顶优先级不低于当前运算符就先弹出计算。要点：
- 后缀表达式**不依赖优先级与括号**，机器求值只需一个栈：遇操作数入栈，遇运算符弹两个数算完再压回；
- 中缀转后缀是选择题高频：括号优先、`* /` 高于 `+ -`、从左到右同级先算先出。
- 例：`A+B*(C-D)-E/F` 的后缀式为 `ABCD-*+EF/-`。

**应用三：递归与函数调用栈**
递归调用的本质是系统栈：每层调用把返回地址、参数、局部变量压栈，返回时弹栈。**所有递归都可改用显式栈迭代**（综合题考过「用栈消去递归」）。要点：递归深度过大会栈溢出；尾递归可优化为循环。

**应用四：队列做缓冲与调度**
键盘缓冲、打印任务池、就绪队列（操作系统）。特点是「生产者与消费者速度不匹配」时削峰，必须 FIFO 才公平。

> **【注意】** 算法设计题答题模板（详见附录 B）：题干 → 用一句话点明选用的结构及原因（「利用栈的 LIFO 特性…」）→ C 代码（可编译、逐行注释）→ 时间与空间复杂度。

**前置与延伸**：
- 前置：知识点 2-2、2-5、2-6
- 延伸：第 4 章层序遍历（队列）、第 5 章 DFS（栈）、第 6 章表达式树

### 2-9　特殊矩阵的压缩存储【补充】　【P0】

> 本节为 408 大纲明确要求、原资料完全缺失的内容，全部为【补充】。题型固定：给矩阵规模与下标 (i, j)，求一维数组下标 k。**全部解法 = 数出 (i, j) 之前存了多少个元素**。

**是什么**：特殊矩阵指元素分布有规律、不必全存的高阶方阵：对称矩阵、三角矩阵、三对角矩阵；以及无规律但零元素极多的**稀疏矩阵**（存三元组表或十字链表）。

**为什么**：n 阶矩阵全存要 n² 个单元，压缩后对称矩阵只需 n(n+1)/2 个——省近一半；三对角只需 3n - 2。压缩的代价是必须**会算**：给出逻辑下标 (i, j) 能算出物理下标 k，反之亦然。

**怎么用**（以下均按**行优先、下标从 1 开始、一维数组也从 1 开始**的口径；换口径时整体平移常数）：

**① 对称矩阵（存下三角 + 主对角线，共 n(n+1)/2 个）**：
- i ≥ j（下三角）：第 1 至 i-1 行共存 `1+2+…+(i-1) = i(i-1)/2` 个，a[i][j] 是第 i 行第 j 个，故
  **k = i(i-1)/2 + j**；
- i < j（上三角）：由对称性 a[i][j] = a[j][i]，代入上式得 **k = j(j-1)/2 + i**。

**② 上三角矩阵（存上三角 + 常数 c 在最后）**：i ≤ j 时，第 1 至 i-1 行各存 n, n-1, …, n-i+2 个，共 `(i-1)(2n-i+2)/2` 个，a[i][j] 前同行还有 j - i 个，故
**k = (i-1)(2n-i+2)/2 + (j-i) + 1**；i > j 时存到末尾常数区：**k = n(n+1)/2 + 1**。

**③ 下三角矩阵**：与对称矩阵的下三角公式相同（k = i(i-1)/2 + j），i < j 时存末尾常数。

**④ 三对角矩阵（|i - j| ≤ 1，共 3n - 2 个）**：前 i-1 行共存 `3(i-1) - 1` 个（首行只有 2 个），a[i][j] 在第 i 行的位置：j = i-1 时第 1 个、j = i 时第 2 个、j = i+1 时第 3 个，故
**k = 2i + j - 2**（i > 1；i = 1 时 k = j）。反向：由 k 反解 i 的近似式 i = ⌊(k + 2) / 3⌋ 后微调。

**⑤ 稀疏矩阵**：只存非零元。**三元组表**（行、列、值）按行优先排列，失去了随机访问能力；**十字链表**给每个非零元挂两个指针（同行下一个、同列下一个），适合矩阵运算中非零元个数会变的场合（如加法、乘法）。

> **【规律】** 所有公式共享一个模板：**k = 前面整行存的总数 + 本行 j 之前存的数量 + 口径修正**。推导一遍胜过背五个公式；考场上现场数行即可。

> **【记忆】** 三对角「3n 减 2」；对称「二分之 n(n+1)」；三角矩阵多出一个「存常数的格子」。

**前置与延伸**：
- 前置：一维数组与行优先地址计算：**k 位元素的地址 = 基址 + k × 元素长度**；二维数组 a[m][n] 中 a[i][j]（下标从 0）行优先地址 = 基址 + (i × n + j) × L，列优先 = 基址 + (j × m + i) × L
- 延伸：稀疏矩阵转置的快速算法（按列计数，非考纲要求掌握推导，考过思想辨析）

## 典型例题

### 例题 2-1　（概念辨析题 · 选择题风格）
**题干**：设栈 S 和队列 Q 的初始状态均为空。元素 a, b, c, d, e, f 依次进入栈 S，且每个元素一入栈立即判断是否出栈入队：若栈顶元素与队列 Q 的队头之后应连续取出的次序匹配规则为「出栈即入队」，全部结束后依次出队。已知出队序列为 b, d, c, f, e, a，问栈 S 的容量至少是多少？

**解题思路**：
1. 这类题**不用套公式，直接模拟**。出队序列即出栈序列（中间队列只做转发），问题等价于：入栈序 a b c d e f、出栈序 b d c f e a，求栈内最多同时压过几个元素。
2. 模拟规则：按序入栈，一旦栈顶等于出栈序的下一个元素就连续弹出。
3. 常见错误是凭感觉估容量——必须逐步画栈。

**解答过程**：
| 步骤 | 动作 | 栈内（右为栈顶） | 已出 |
|------|------|-----------------|------|
| 1 | 入 a | a | — |
| 2 | 入 b | a b | — |
| 3 | 出 b（目标 b） | a | b |
| 4 | 入 c、入 d | a c d | — |
| 5 | 出 d（目标 d） | a c | b d |
| 6 | 出 c（目标 c） | a | b d c |
| 7 | 入 e、入 f | a e f | — |
| 8 | 出 f（目标 f） | a e | b d c f |
| 9 | 出 e（目标 e） | a | b d c f e |
| 10 | 出 a | 空 | 全部 |

栈内最多同时 3 个元素（第 4 步与第 7 步），故**最小容量为 3**。

**复杂度分析**：模拟一遍 O(n)，栈空间即答案上界 O(n)。

### 例题 2-2　（计算与推导题 · 选择题风格）
**题干**：循环队列用数组 `Q[0..m-1]` 存储，`front` 指向队头元素，`rear` 指向队尾元素的**下一个位置**，牺牲一个单元区分空满。（1）写出判空、判满、元素个数的表达式；（2）若 m = 100，front = 98，rear = 2，队列中有多少个元素？（3）若改用 `size` 计数的方案，判空判满怎么写？

**解题思路**：
1. （1）是模板题，直接默写三大公式，注意判满是「rear 的下一格撞 front」。
2. （2）代入个数公式，注意 `rear - front` 为负，**先加 m 再取模**。
3. （3）size 方案下空满两态由 size 独立判定，指针比较不再承担判满职责。

**解答过程**：
1. 判空 `front == rear`；判满 `(rear + 1) % m == front`；个数 `(rear - front + m) % m`。
2. `(2 - 98 + 100) % 100 = 4`，队列中有 **4 个元素**（98、99、0、1 四个单元）。
3. size 方案：`size == 0` 为空，`size == m` 为满；入队成功 `size++` 且 `rear = (rear + 1) % m`，出队成功 `size--` 且 `front = (front + 1) % m`。此方案 m 个单元全可用，不牺牲空间。

**复杂度分析**：所有判定与指针移动均为 O(1)。

### 例题 2-3　（算法设计题 · 综合应用题风格）
**题干**：设计一个算法，借助栈判断给定的字符序列是否为回文（正读反读相同，如 "abccba"、"abcba"）。序列存于数组 `s`，长度 n。要求给出思路、C 代码与复杂度。

**解题思路**：
1. 回文的性质：前半段与后半段的**倒序**相同。「倒序」立刻联想到栈的 LIFO——把前半段压栈，再逐个与后半段比较：弹出顺序恰好是前半段的倒序。
2. 长度为奇数时中间那个字符不参与比较，需跳过。
3. 也可以用双端队列两端同时取（留作练习），栈解法代码最短。

**解答过程**：
1. 把 s[0..n/2-1] 依次入栈；
2. 从 i = (n 为偶数 ? n/2 : n/2 + 1) 开始扫描后半段，每步弹出栈顶与 s[i] 比较，不等则返回 0；
3. 扫描结束即回文。

**代码实现**：
```c
#include <stdio.h>
#define MAXN 1000

int isPalindrome(char s[], int n) {
    char stack[MAXN / 2];            /* 只需存前半段 */
    int top = -1, i;
    for (i = 0; i < n / 2; i++)      /* 前半段入栈 */
        stack[++top] = s[i];
    if (n % 2 == 1) i++;             /* 奇数长度跳过中间字符 */
    for (; i < n; i++) {             /* 后半段与出栈序比较 */
        if (stack[top--] != s[i])
            return 0;                /* 对不上：不是回文 */
    }
    return 1;
}
```

**复杂度分析**：时间 O(n)，空间 O(n/2) = O(n)。

### 例题 2-4　（计算与推导题 · 压缩存储【补充】）
**题干**：将 10 阶对称矩阵 A（下标 1 至 10）的**下三角部分（含主对角线）**按行优先压缩存入一维数组 B（下标从 1 开始）。求：(1) B 的元素总个数；(2) A[8][5] 存放在 B 的哪个位置；(3) A[3][7] 存放在 B 的哪个位置。

**解题思路**：
1. 对称矩阵只存下三角含对角线，套「等差数列求和」；
2. i ≥ j 直接用公式 k = i(i-1)/2 + j；
3. i < j 用对称性转到 a[j][i] 再套公式。

**解答过程**：
1. 共 `10 × 11 / 2 = 55` 个元素。
2. A[8][5]：i = 8 ≥ j = 5，k = 8×7/2 + 5 = 28 + 5 = **33**。
3. A[3][7]：i = 3 < j = 7，转为 A[7][3]，k = 7×6/2 + 3 = 21 + 3 = **24**。

**复杂度分析**：O(1) 公式计算；存储量从 100 降至 55。

## 本章总结

### 核心内容（一页纸）

- **栈**：一端（栈顶）进出，LIFO；**队列**：队尾进、队头出，FIFO。两者都是操作受限的线性表，核心操作全部 O(1)。
- **顺序栈**两种 top 约定（指栈顶元素初始 -1 / 指下一空位初始 0）的入出栈、判空判满写法不同，**读题先看约定**。
- **共享栈**：两栈相向生长，判满 `top0 + 1 == top1`，空间互补时最省。
- **循环队列**（牺牲一格）：判空 `front == rear`，判满 `(rear + 1) % maxSize == front`，个数 `(rear - front + maxSize) % maxSize`；**后退下标必须先加 maxSize 再取模**。
- 判空判满的另两种方案：**size 计数**（不牺牲空间）、**tag 标志**（入队置 1 出队置 0）。
- **链式队列**删到最后一个结点必须 `rear = front`，**防野指针**——链式部分最重要的两行代码。
- **双端队列**两端进出；受限形态：输入受限 / 输出受限；输出序列判定用**模拟法**（要出的元素必须恰在可取位置）。
- **表达式求值**：后缀式只需一个操作数栈；中缀转后缀按「括号、优先级、从左到右」进出运算符栈。
- **特殊矩阵压缩**【补充】：对称（下三角）k = i(i-1)/2 + j；三对角 3n-2 个、k = 2i + j - 2；稀疏矩阵用三元组表 / 十字链表。**模板 = 前面整行总数 + 本行之前数量 + 修正**。
- n 个元素入栈的出栈序列种数 = **卡特兰数** C(2n,n)/(n+1)。
