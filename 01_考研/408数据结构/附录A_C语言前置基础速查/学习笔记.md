## 📌 本章重点（3-5个）

⭐ **指针的本质**：指针是"保存地址的变量"，指针类型决定 +1 的步长，这是链表/树的根基
⭐ **内存分段模型**：.text / .rodata / .data / .bss / 堆 / 栈 的分布与读写权限
⭐ **堆内存管理**：malloc 与 free 必须成对出现，防内存泄漏、防 double free
⭐ **结构体与字节对齐**：sizeof(struct) 的计算规则，成员顺序影响大小
⭐ **函数声明与定义、多文件编译链接流程**：.c → .o → 链接，符号在链接期定地址

## 🔥 本章难点（2-3个）

🔥 **复杂声明的解读**：`int *a[10]`（指针数组）、`int (*a)[10]`（数组指针）、`int (*a)(int)`（函数指针）、`void (*signal(int, void(*)(int)))(int)` 的拆解
🔥 **二级指针修改一级指针**：为什么 `GetMemory(char *p)` 无效而 `GetMemory(char **p)` 有效（值传递的拷贝本质）
🔥 **数组名的本质**：数组名是"常量标签"不是变量，`p+1` 到底跳几个字节取决于指针指向的类型

## ⚠️ 本章易错点（3-5个）

⚠️ **strlen 与 sizeof 混淆**：`char str[] = "hello"`，sizeof=6（含 '\0'），strlen=5（不含）；sizeof 是编译期测容器，strlen 是运行期数字符
⚠️ **修改字符串字面量**：`char *str = "2021"; str[3]='2';` 段错误！字面量在 .rodata 只读段；应写 `char str[] = "2021"`
⚠️ **类型转换方向记反**：大容量→小容量是**截断**（丢高位）；小容量→大容量是**补位**（有符号补符号位，无符号补 0）
⚠️ **以为传指针就能修改实参**：`GetMemory(char *p)` 里 malloc 的地址只拷贝给了形参 p，函数返回后 str 仍是 NULL，接着 strcpy 直接崩溃
⚠️ **返回局部变量的地址**：栈空间函数结束即回收，返回 `char p[]="hello world"` 的 p 是野指针；要么返回堆地址，要么返回 static/静态区地址

## 📖 知识点讲解

### 1. 数据类型与 sizeof

**是什么**：数据类型就是"数据保存的容器"，核心问题是这个容器有多大。C 语言数据类型分两类：基本数据类型（char/short/int/long/long long/float/double，大小为 1B/2B/4B/8B 量级）和自定义数据类型（struct/union/enum）。`sizeof` 是**关键字**（不是函数），在编译期求出容器占用的字节数。

**为什么**：ISO C90 标准只约束了相对大小 `char < short <= int <= long <= long long`，并规定 char 恒为 1B、long 不小于 4B、long long 恒为 8B，具体数值随平台变化。所以**跨平台代码要用 sizeof 而不要写死字节数**，用 `typedef` 给类型起别名（如 int32_t）来解决移植问题。

**怎么用**：
```c
printf("%zu\n", sizeof(int));      // 通常 4
printf("%zu\n", sizeof(long long)); // 恒为 8
typedef unsigned int u32;          // 类型别名，提升可移植性
```
整型常量有多种写法：进制表示（0x 前缀十六进制、0 前缀八进制）和字符表示（'A'）。ASCII 码中可打印字符（如 '0' 是 48）与不可打印控制字符（如 '\n'、'\0'）要分清。整型变量 = 给内存空间起一个方便访问的名字；浮点数默认 8B（double），且**有精度误差，不能直接用 == 比较**。

> ⚠️ 注意事项：`sizeof` 在编译期完成，不会真正"执行"；对数组名求 sizeof 得到整个数组大小，对指针求 sizeof 只得到指针本身大小（8B，64位系统）。

> 🎯 规律：跨平台别写死字节数，用 sizeof 和 typedef 换可移植性。
> 💡 一句话总结：类型即容器，sizeof 可测。

| 对比 | 基本数据类型 | 自定义数据类型 |
|------|------------|--------------|
| 来源 | 语言自带 | 程序员组合设计 |
| 大小 | 标准规定相对关系 | 由成员与对齐规则决定 |
| 设计方式 | 直接使用 | struct 累加组合 / union 共享组合 |

### 2. 赋值的本质与类型转换（截断与补位）

**是什么**：C 语言中 `=` 的语义是——**把等号右边的内存空间，逐字节拷贝到等号左边的内存空间**。当两边容器大小不一致时就会发生转换：大容量赋给小容量 → **截断**（直接丢高位字节）；小容量赋给大容量 → **补位**（有符号数补符号位，无符号数补 0）。

**为什么**：内存拷贝是按字节进行的，容器小装不下就只剩低字节（截断）；容器大则需要说明高字节填什么，有符号数用符号位填充才能保持数值含义（算术意义），无符号数没有符号位就补 0。

**怎么用**：
```c
char c = -1;        // 0xFF
int i = c;          // 补位：有符号补符号位 -> 0xFFFFFFFF，i = -1
unsigned char uc = 200;
int j = uc;         // 补位：无符号补0 -> j = 200
int big = 0x12345678;
short s = big;      // 截断 -> s = 0x5678
```
右移运算同理：**有符号数右移补符号位（算术右移），无符号数右移补 0（逻辑右移）**，这就是"除以 2"在不同符号类型下的行为差异。逻辑运算中若有符号与无符号混合运算，有符号会先被转为无符号再算，容易踩坑。

> ⚠️ 注意事项：`=` 是逐字节拷贝而不是"数学赋值"；混合运算时注意隐式转换方向。

> 🎯 规律：一切赋值都是逐字节拷贝——转换规则只是回答拷不完/装不满怎么办。
> 💡 一句话总结：大转小截断，小转大补位，右移看符号。

### 3. 自定义数据类型：struct / union / enum

**是什么**：自定义类型 = 告知编译器"我的新模型在内存中如何规划"，原则是**先声明再使用**。
- **struct（结构体）**：把多个成员**累加组合**。注意 struct 不是数据类型本身，而是"自定义成员组合行为的说明符"。成员按字节对齐规则排布，**成员顺序不同，总大小可能不同**；还可以用位域（`int a:3;`）按位分配。
- **union（共用体）**：所有成员**共享同一段内存**，大小 = 最大成员，同一时刻只能有效保存一个成员，专为"从底层连续区域的不同视角访问"而设计。
- **enum（枚举）**：课件直言它是"一个失败的类型"——实际就是一个整型，**并没有类型限定的约束**（C 的枚举变量可以赋任意整数值），只提供可读性。

**为什么**：struct 解决"把相关数据打包"（如链表节点）；union 解决"同一块内存多种解释"（如判断大小端）；enum 想解决"一组相关常量"但约束力不足。

**怎么用**：
```c
struct Node {          // 先声明
    int data;
    struct Node *next;
};
struct Node a;         // 再定义变量
typedef struct Node NodeT;  // 用 typedef 简化写法
```
字节对齐规则（32/64 位通用口诀）：①每个成员的偏移量必须是自身大小的整数倍；②结构体总大小必须是最大成员大小的整数倍。

> ⚠️ 注意事项：课件经典例题 `struct data { char c1; int si; char c2; }` 的 sizeof = **12** 而不是 6：c1 占 1B 后补 3B 对齐 si（4B），c2 占 1B 后再补 3B 使总长为 4 的倍数。若调整为 `int si; char c1; char c2;` 则只需 8B——**成员从小到大排列可省内存**。

> 🎯 规律：struct 管怎么拼、对齐规则管怎么放——成员按大小升序排最省内存。
> 💡 一句话总结：struct 累加，union 共享。

### 4. 变量名的本质与指针的本质

**是什么**：
- **变量名**：对一段内存空间的"名称映射"，方便程序员描述、让编译器翻译成正确的 CPU 指令。要求：合法标识符、不重复（一个变量名代表一段专属空间）、必须有类型（空间才有约束）、有作用域（对应申请和释放时机）。
- **指针**：**保存地址的容器（变量）**。C 语言地址与计算机底层地址在"定义时"发生了抽象改变——C 语言只定义地址的形态，怎么用全交给程序员：**不管越界访问、不管权限访问**（课件的"任性"）。指针支持 `*`（解引用）和 `[]`（下标）两种访问方式。

**为什么**：数据结构中节点之间的连接（链表的 next、树的左右孩子、图的边）全靠指针把"下一段内存的首地址"存起来，理解指针 = 理解一切动态结构。

**怎么用**：指针运算的步长由**指针指向的类型**决定。课件核心实验（起点都是 0x100）：
```c
int  *p1 = (int *)0x100;      p1 + 1 -> 0x104  (int 4B)
char *p2 = (char *)0x100;     p2 + 1 -> 0x101  (char 1B)
char  p3[5];                  p3 + 1 -> 0x101  (元素char)
char *p4[5];                  p4 + 1 -> 0x108  (元素是指针, 8B)
char (*p5)[5] = ...;          p5 + 1 -> 0x105  (指向含5个char的数组)
char  p6[6][5];               p6 + 1 -> 0x105  (一行5个char)
```

> ⚠️ 注意事项：指针变量本身有自己的地址（&p），存的值才是目标地址；野指针（未初始化/悬空）比空指针更危险。

> 🎯 规律：指针的步长写在它的类型里——加减之前先问指向什么。
> 💡 一句话总结：指针存地址，加减看类型，解引用看权限。

### 5. 数组、字符串与二维数组

**是什么**：数组是同类型元素的连续空间。两个颠覆认知的要点：① **C 语言只管分配、不管越界**——在 C 看来内存就是连续的，访问权限交给程序员而不是编译器；② **数组名不是变量名**，只是为标识这块空间引入的**常量标签**，C 语言压根没有"数组变量"的概念。字符串 = 字符数组 + '\0' 结尾约定。

**为什么**：理解"数组名是常量标签"才能解释：为什么数组名不能 `++`、为什么传参后数组退化为指针、为什么 sizeof 对形参数组失效。

**怎么用**——常用字符串/内存函数（注意单位差异）：
```c
strlen(s)            // 运行期数字符个数，不含'\0'
sizeof(s)            // 编译期容器大小，含'\0'
strcpy/strncpy(dst,src,n)  // 拷贝字符串，strncpy 更安全
memcpy/memset(p, v, n)     // 按字节(B)操作内存，不认'\0'
sprintf/snprintf           // 格式化写入，snprintf 可限长
printf("%s", s)            // %s = 从该地址开始打印直到'\0'
```
二维数组：内存是**线性编址**的，二维只是逻辑描述，按行优先存放。`char **args` 与 `char buf[4][5]` 完全不同：前者是"指针的指针"（二级指针，指向若干 char*），后者是一整块 4×5 连续空间（数组名 +1 跳一行 5B），**不能互相直接赋值**。

**跟着算**——两行代码，两种命运（画出来一目了然）：

```text
char *str = "2021";               char str[] = "2021";
  栈区:  str                            栈区: str[0..4]
           \                                '2','0','2','1','\0'
            \──> .rodata "2021"          （字面量被【拷贝】进栈数组）
                 （只读！）
  str[3]='2' → 段错误 ✗            str[3]='2' → 正常 ✓
```
同一个字面量，指针版只是"记了个地址"，数组版是"抄了一份到家"——改别人的只读资料当然崩，改自己抄的当然行。

> ⚠️ 注意事项：`char *str = "2021"` 中 str 指向只读段，不能改内容；`char str[] = "2021"` 是把字面量拷贝到栈数组，可以改。这是课件 4.1 的"经典错误"。

> 🎯 规律：数组名是常量标签、传参即退化为指针——边界安全 C 全交给程序员。
> 💡 一句话总结：数组名是常量标签，只管分配不管越界。

### 6. 内存分段模型与权限（重中之重）

**是什么**：进程虚拟内存从低到高的典型布局（Linux 32位示例）：

```
高地址 0xC0000000+  内核虚拟存储器   ← 用户代码不可见、不可访问
        ┌──────────────────────┐
        │ 用户栈（运行时创建）  │ ↓ 向低生长，esp 指示栈顶
        │        ↓↑            │
        │ 共享库存储器映射区    │ （0x40000000 附近）
        │        ↑             │
        │ 运行时堆(malloc创建) │ ↑ 向高生长，brk 指示堆顶
        ├──────────────────────┤
        │ 读/写段 .data / .bss │ ← 从可执行文件加载
        │ 只读段 .init/.text/.rodata │
        └──────────────────────┘
低地址 0x08048000-  未用（受保护）
```

**为什么**：分段是为了**权限隔离**——低地址段和 3G 以上的段被操作系统保护（不可读不可写），所以改字符串字面量、访问空指针都会段错误；栈空间由编译器在编译时安排好申请与释放；**堆空间必须由程序员自己维护，是内存泄漏的重灾区**。

**怎么用**——把变量归段：
| 变量/数据 | 所在段 | 谁负责回收 |
|-----------|--------|-----------|
| 函数的机器码 | .text（只读） | 程序结束 |
| 字符串字面量 "2021" | .rodata（只读） | 程序结束 |
| 已初始化全局变量、static 变量 | .data | 程序结束 |
| 未初始化全局变量、static 变量 | .bss | 程序结束 |
| malloc 的空间 | 堆 | **必须 free** |
| 局部变量、形参 | 栈 | 出作用域自动回收 |

> ⚠️ 注意事项：段错误（Segmentation Fault）的本质 = 访问了无权限的段；堆向高地址生长、栈向低地址生长。

> 🎯 规律：先问数据在哪个段，再问能不能写——段错误全是越权访问。
> 💡 一句话总结：栈编译器管，堆程序员管，只读段别碰。

### 7. 堆内存管理：malloc / free

**是什么**：`malloc(n)` 在堆上申请 n 字节**无名的连续空间**，返回首地址，通常用局部指针变量"临时接管"这个无名空间；`free(p)` 归还空间。配套：`calloc`（清零）、`realloc`（扩容）。

**为什么**：栈空间大小固定、生命周期绑定函数；数据结构的节点个数运行时才知道（如链表插入节点），必须用堆。但堆没有 GC，**程序员忘记 free 就是内存泄漏，free 两次就是 double free，free 后继续用就是悬空指针**——三大堆区事故。

**怎么用**：
```c
Node *p = (Node *)malloc(sizeof(Node));  // 申请并检查
if (p == NULL) return -1;                // malloc 可能失败
p->data = 10;  p->next = NULL;
...
free(p);       // 用完释放
p = NULL;      // 防悬空指针（防 double free 误用）
```
与 Java 对比（课件重点）：Java 的 `new Node()` 同样在堆上创建无名空间、把首地址交给引用变量，但**由 GC 自动回收，不需要 free**；C 的 `free` 换来的极致控制力，代价就是内存管理的责任全在程序员。C 指针是变量可以 `++` 遍历，Java 引用是受管指针，不支持地址运算。

**跟着算**——一次 malloc/free 的完整生命周期（每个时刻谁是责任人）：
第1步 `malloc(100)`：堆上划出 100 字节**无名**空间，首地址交给栈上的指针 p——p 从此刻起是唯一责任人；
第2步 使用中：把 p 拷贝给别人要谨慎——两个人都以为对方会 free，结果就是谁都没 free（泄漏）或都 free（double free）；
第3步 `free(p)`：空间归还系统，**但 p 的值没变**（还指着那块地址）→ 立刻 `p=NULL`，防止再碰；
第4步 若第 3 步忘做且 p 是局部变量：函数返回 p 消失，堆空间成了没人认领的"孤儿"——这就是内存泄漏。

> ⚠️ 注意事项：malloc 与 free 必须成对、谁申请谁释放；free 只释放空间不改指针值，所以释放后要置 NULL。

> 🎯 规律：堆的每一字节都有主人——谁申请谁释放，free 后立刻置 NULL。
> 💡 一句话总结：申请释放成对，防漏防重。

| 对比 | C：malloc/free | Java：new/GC |
|------|---------------|--------------|
| 申请 | malloc(sizeof(Node)) | new Node() |
| 空间位置 | 堆，无名连续空间 | 堆 |
| 释放 | 程序员手动 free | GC 自动回收 |
| 事故 | 泄漏、double free、悬空指针 | 无手动管理，但有 GC 停顿 |
| 地址运算 | 支持 p++ 遍历 | 引用不支持地址运算 |

### 8. 函数与多文件编程（编译链接）

**是什么**：函数是"标识一段代码空间的字符串（函数名）"，特性是**有输入、有返回值**。**声明**告诉编译器这段代码空间长什么样（调用时需要什么操作）；**定义**是在最后组合模块时把具体实现明确的过程——先声明再使用。多文件编程：每个 .c **独立编译**成 .o（目标文件），再由链接器把多个 .o 按布局规则融合成可执行文件，此时才确定每个符号的运行时地址。

**为什么**：函数调用时**实参逐字节拷贝给形参**（值传递），所以：想"读取"上层空间 → 传值或传地址都行；想"修改"上层空间 → 必须传地址；想返回大片空间 → 只能返回指针（静态空间或堆空间），**绝不能返回栈上局部变量的地址**（函数返回后栈帧回收，成野指针）。

**怎么用**：
```c
// 编译流程
gcc -c a.c        # 生成 a.o（缺运行时地址）
gcc a.o b.o -o app # 链接：确定所有符号的运行时地址
nm a.o            # 查看符号表：
#  U -> 未定义符号(等链接)  T -> 代码段符号
#  D/d -> data段全局/局部  B/b -> bss段全局/局部
```
链接报错对照：`undefined reference to 'abc'` = 只有声明没有实现（缺 .o）；`multiple definition of 'abc'` = 重复定义（用 static 限定为局部符号）。全局变量和函数名都是符号、链接期定地址、运行期地址不变；局部变量**不占符号**、运行时在栈上、地址可能变化。中文乱码：Windows 下 gcc 加编译选项 `-fexec-charset=GBK`。

> ⚠️ 注意事项：头文件放声明、.c 放定义；全局变量只能在**一个** .c 中定义，其他文件用 extern 声明。

> 🎯 规律：声明放 .h、定义放 .c，符号到链接期才领到运行时地址。
> 💡 一句话总结：各.c独立编译，链接期定符号地址。

### 🧩 本章归纳：一条主线串全章

> **主线：C 语言的一切都落在"内存"两个字上——类型定容器、名字是映射、指针存地址、分段定权限。**
> 数据类型回答"这段内存多大"（sizeof 可测）→ 自定义类型回答"怎么拼出想要的容器"（struct 累加对齐 / union 共享）→ 变量名与指针是访问内存的两把钥匙（名字交给编译器映射，地址交给程序员自己做主）→ 内存分段画出"哪里能碰"的地图（栈编译器管、堆程序员管、.rodata 别碰）→ 堆的自由由 malloc/free 的责任来换 → 多文件编译链接回答"名字如何变成运行时地址"（.c → .o → 链接定符号）。

回头看才看得见的三条规律：
1. **"赋值 = 逐字节拷贝"是全章第一原理**：struct 赋值、实参传形参、大小容量转换，全是同一条规则的不同表现——想通它，截断/补位、值传递的坑、GetMemory 问题一次全通。
2. **数据结构课的两大伏笔在本章埋下**：struct + 指针 = 链表/树/图的节点；malloc/free = 一切动态结构的生命周期——后面每一章都在用这两件武器。
3. **报错类型暴露问题层次**：写 .rodata/空指针 → 当场段错误；悬空指针/泄漏 → 埋雷后爆发——分清"当场崩"与"延迟爆"是 C 调试的基本功。

## 🔍 相似概念辨析

### 组1：数组 vs 指针

| 对比维度 | 数组 | 指针 |
|----------|------|------|
| 各自定义 | 同类型元素的连续内存块，数组名是**常量标签** | 保存地址的**变量** |
| 核心区别 | 数组名不可修改（不能++），空间在定义时确定 | 指针可指向任意同类型地址，可 ++ 遍历 |
| 各自特点 | sizeof 得到整个数组大小；传参时退化为指针 | sizeof 只得指针自身大小（64位为8B）；+1 步长看指向类型 |
| 使用场景 | 长度固定的顺序存储（顺序表、栈、循环队列） | 长度动态的链式结构（链表、树、图） |
| 典型示例 | `char p3[5]; p3+1 → 0x101` | `char *p4[5]` 是另一个东西（见组2） |
| 记忆口诀 | 数组名是标签，只读不挪窝 | 指针是变量，存址任我行 |

### 组2：指针数组 vs 数组指针

| 对比维度 | 指针数组 `char *p4[5]` | 数组指针 `char (*p5)[5]` |
|----------|------------------------|--------------------------|
| 各自定义 | 装了 5 个 char* 指针的数组 | 指向"含5个char的数组"的指针 |
| 核心区别 | 本质是**数组**，元素是指针 | 本质是**指针**，指向整个一维数组 |
| 各自特点 | p4+1 跳 8B（一个指针大小） | p5+1 跳 5B（一整个数组的大小） |
| 使用场景 | 字符串列表：`main` 的 `char **args` 本质类似 | 操作二维数组行：`char buf[4][5]` 传参用 `char (*)[5]` |
| 典型示例 | `p4[i]` 是第 i 个 char* | `(*p5)[i]` 是数组第 i 个元素 |
| 记忆口诀 | [] 优先级高先结合=指针数组；括号强夺 \* = 数组指针 |

### 组3：struct vs union

| 对比维度 | struct | union |
|----------|--------|-------|
| 各自定义 | 成员**累加组合**的复合类型 | 成员**共享同一块内存**的复合类型 |
| 核心区别 | 空间 = 各成员对齐后之和 | 空间 = 最大成员大小 |
| 各自特点 | 所有成员同时有效 | 同一时刻只有一个成员有效 |
| 使用场景 | 打包不同属性（学生：姓名+成绩） | 多视角解释同一数据（判大小端、寄存器拆分） |
| 典型示例 | `sizeof(struct data)=12`（对齐） | `union {int i; char c;} u; u.i=1; u.c==1 则小端` |
| 记忆口诀 | struct 加法，union 换壳 | |

### 组4：栈（stack） vs 堆（heap）

| 对比维度 | 栈区 | 堆区 |
|----------|------|------|
| 各自定义 | 函数运行用的临时内存区（局部变量、形参） | malloc 申请的无名连续空间 |
| 核心区别 | 编译器自动管理申请释放 | 程序员手动 malloc/free 管理 |
| 各自特点 | 向低地址生长，速度快，容量有限 | 向高地址生长（brk），容量大，速度较慢 |
| 使用场景 | 局部变量、函数调用 | 节点个数运行时才知的动态结构 |
| 典型示例 | `char p[]="hello"` 的 p 数组 | `malloc(sizeof(Node))` |
| 记忆口诀 | 栈自动省心，堆自由但要还（free） | |

### 组5：strlen vs sizeof

| 对比维度 | strlen | sizeof |
|----------|--------|--------|
| 各自定义 | 求字符串**字符个数**的库函数 | 求**容器大小**的关键字 |
| 核心区别 | 运行期执行，不含 '\0' | 编译期确定，含 '\0' |
| 各自特点 | 参数必须是以 '\0' 结尾的有效地址 | 任何类型/变量都可以测 |
| 使用场景 | 求串长 | 求内存占用、跨平台写法 |
| 典型示例 | `strlen("hello")==5` | `sizeof("hello")==6` |
| 记忆口诀 | strlen 数字，sizeof 量缸 | |

### 组6：函数声明 vs 函数定义

| 对比维度 | 声明 | 定义 |
|----------|------|------|
| 各自定义 | 告诉编译器"这段代码空间长什么样" | 给出具体实现，确定符号地址 |
| 核心区别 | 不产生代码空间，可多次 | 产生实体，只能一次 |
| 各自特点 | 通常放头文件 .h | 通常放源文件 .c |
| 使用场景 | 跨文件调用前先 include 声明 | 实现功能逻辑 |
| 典型示例 | `int add(int, int);` | `int add(int a,int b){return a+b;}` |
| 记忆口诀 | 声明是名片，定义是本人 | |

### 组7：C 指针 vs Java 引用

| 对比维度 | C 指针 | Java 引用 |
|----------|--------|-----------|
| 各自定义 | 保存地址的变量 | 指向堆对象的受管句柄（隐藏的指针） |
| 核心区别 | 地址可直接运算（p++、强转） | 禁止地址运算 |
| 各自特点 | `Node *p; p->data` | `Node p; p.data`（声明即引用，不需 \*） |
| 使用场景 | 链表遍历 `p=p->next` | 对象字段 `Node next` 相当于 `struct Node *const next` |
| 典型示例 | `malloc`+`free` 手动管理 | `new` + GC 自动管理 |
| 记忆口诀 | 指针裸奔自由险，引用托管安全贵 | |

## 📋 速查表

### 基本类型大小（ISO C90 约束）
```
char(1B) < short(2B) <= int(4B) <= long(≥4B) <= long long(8B)
float(4B)  double(8B)   指针统一 8B(64位平台)
```

### 类型转换规则
```
大 → 小：截断（保留低字节）
小 → 大：有符号补符号位；无符号补 0
右移：  有符号算术右移（补符号位）；无符号逻辑右移（补0）
```

### 位操作模板
```c
a |=  (0x1 << 3);      // 置位 bit3
a &= ~(0x1 << 3);      // 清零 bit3
int *p = (int *)0x67a7; p[0] = 0xaabb;   // 绝对地址写值
```

### 复杂声明速解（右左法则：先看右再看左）
```c
int a;            一个整型数
int *a;           指向整型的指针
int **a;          指向整型指针的指针
int a[10];        10个整型的数组
int *a[10];       10个整型指针的数组
int (*a)[10];     指向10个整型数组的指针
int (*a)(int);    指向函数(整型参数,整型返回)的指针
int (*a[10])(int);10个函数指针的数组
void (*signal(int, void(*)(int)))(int);
// signal 是函数：参数(int, 函数指针)，返回函数指针
// typedef 简化：typedef void (*handler_t)(int);
//               handler_t signal(int, handler_t);
```

### 字符串/内存函数
| 函数 | 单位 | 是否遇 '\0' 停 | 备注 |
|------|------|---------------|------|
| strlen | 字符串长度 | 统计到 '\0' 止（不含） | 运行期 |
| strcpy/strncpy | 字符串 | 连 '\0' 一起拷 | strncpy 可限长更安全 |
| memcpy/memset | 字节 B | 不停 | 内存操作不认字符串 |
| sprintf/snprintf | 格式化 | — | snprintf 防溢出 |

### 内存分段与存放内容
```
.text 代码段     函数机器码（只读）
.rodata          字符串字面量（只读，改它=段错误）
.data            已初始化全局/static 变量
.bss             未初始化全局/static 变量（0填充）
堆 ←brk          malloc/free，向高生长，泄漏重灾区
栈 ←esp          局部变量/形参，向低生长，自动回收
内核区(3G以上)   用户不可访问
```

### 编译链接命令
```
gcc -c a.c                只编译生成 a.o
gcc a.o b.o -o app        链接生成可执行文件
nm a.o                    查看符号表 U/T/D/d/B/b
gcc -fexec-charset=GBK    Windows 控制台中文乱码修正
```
符号表字母：`U`未定义 `T`代码段 `D`数据段全局 `d`数据段局部 `B`bss全局 `b`bss局部

### 编译链接报错对照
```
undefined reference to 'abc'   → 缺实现（缺 .o/函数体）
multiple definition of 'abc'   → 重复定义（加 static 或拆分）
```
