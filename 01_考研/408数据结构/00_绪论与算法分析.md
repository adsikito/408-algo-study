## 本章地图

本章解决一个问题：**怎样用统一的尺度衡量「一段代码要跑多久、要占多少内存」。**

学习的路径是这样排的：

```text
先分清「数据之间是什么关系」（逻辑结构）
   ↓
再分清「这些关系怎么存进内存」（存储结构）
   ↓
然后知道「操作这些数据的算法要满足什么条件」（ADT 与算法特性）
   ↓
最后学两把尺子：时间复杂度和空间复杂度
   ↓
并建立起「看到数据规模就能推定可用复杂度」的直觉
```

**为什么把复杂度放在最后而不是最前**：复杂度是**描述算法的语言**，
不先知道「算法是什么」，复杂度就无从谈起。但从应试看，
**复杂度是本章唯一的高频考点**——概念题只占 1 至 2 分，复杂度题每年必出。

## 本章重点

> **【重点】** 时间复杂度的**逐层分析**：先看循环次数与规模的关系，再忽略常数与低阶项。
> 这是本章唯一需要「算」的能力。
>
> **【重点】** **顺序存储与链式存储的三组对比**：随机访问 vs 顺序访问、
> 存储密度 vs 指针开销、插入删除 O(n) vs O(1)（已知前驱时）。这是全书的对比主线。
>
> **【重点】** **「O(1) 不代表只执行一次」**。它表示执行次数与 n **无关**，
> 哪怕固定执行 1000 次也是 O(1)。

## 本章难点

> **【难点】** **循环变量的边界与步长不规则时**如何算次数。例如
> `for (i = 1; i * i <= n; i++)` 的循环次数是 O(√n)，不是 O(n)。
>
> **【难点】** **嵌套循环中内层依赖外层**的情况。例如冒泡排序的内层是 O(n-i)，
> 总和需要求和而不是简单相乘。

## 本章易错点

> **【易错】** 把 `O(n)` 与「循环一次」画等号。**复杂度看的是 n 的量级关系，不是循环层数。**
> 一层循环也可能是 `O(√n)` 或 `O(log n)`。
>
> **【易错】** 忘记**忽略系数**。`3n² + 2n + 1` 记作 `O(n²)`，不写 `O(3n²)`。
>
> **【易错】** 空间复杂度的两个口径混淆：**「算法自身占用的辅助空间」**（标准口径）
> 与「输入数据占用的空间」（不计入）。递归的**栈深度也要计入**辅助空间。
>
> **【易错】** 认为「存储密度高」一定更好。链式存储的存储密度低于顺序存储，
> 但它换来了插入删除的 O(1)。

## 知识点讲解

### 0-1　数据结构的基本概念与三要素　【P1】

**是什么**：

| 术语 | 含义 | 举例 |
|------|------|------|
| 数据 | 信息的载体，能被计算机识别与处理 | 一个班的学生信息 |
| 数据元素 | 数据的基本单位，整体处理的对象 | 一名学生的全部信息 |
| 数据项 | 构成数据元素的不可分割的最小单位 | 学生的学号、姓名、年龄 |
| 数据结构 | 相互之间存在一种或多种特定关系的数据元素的集合 | 按学号有序组织的学生表 |

**数据结构的三要素**：

```text
逻辑结构    —— 数据元素之间的抽象关系（与存储无关）
存储结构    —— 逻辑结构在计算机中的表示（又称物理结构）
数据的运算  —— 定义在逻辑结构上（做什么），实现在存储结构上（怎么做）
```

> **【重点】** 三要素中**逻辑结构与存储结构是最常考的一对**。
> 判断题常这样设陷阱：「逻辑结构与存储结构一一对应」——
> **错**。同一逻辑结构可以对应多种存储结构（如线性表既可顺序存储也可链式存储）。

**为什么**：这三要素是把「数据结构」这门课拆开的刀 ——
后面每一章都在做三件事：分析逻辑结构（线性表？树？图？）、
选定存储结构（顺序？链式？）、实现运算（插入？删除？查找？）。

**怎么用**：遇到任何一章，先问三个问题：

1. 这一章的逻辑结构是什么？（线性 / 树形 / 图形 / 集合）
2. 它用了几种存储结构？（这一章的**两种实现**往往就是两种存储）
3. 它的核心运算是什么？复杂度如何？

> **【类比】** 逻辑结构像「家谱上谁是谁的长辈」——是**关系**；
> 存储结构像「家谱抄在纸上还是存进电脑」——是**载体**。
> 关系不变，载体可以换。

> **【记忆】** **逻辑管关系，存储管实现，运算管操作。**

**前置与延伸**：
- 前置：无
- 延伸：集合、线性、树形、图形四种逻辑结构分别对应第 1 章、第 4 章、第 5 章

### 0-2　逻辑结构与存储结构　【P1】

**是什么**：

**四种逻辑结构**：

| 逻辑结构 | 元素间关系 | 对应章节 |
|---------|-----------|---------|
| 线性结构 | 一对一（除首尾外，每个元素有唯一前驱与后继） | 第 1、2、3 章 |
| 树形结构 | 一对多（一个结点可有多个后继） | 第 4 章 |
| 图形结构 | 多对多（任意两个元素都可能有关系） | 第 5 章 |
| 集合 | 只有「同属一个集合」的关系 | 未单独成章 |

**四种存储结构**：

| 存储结构 | 做法 | 核心特征 |
|---------|------|---------|
| 顺序存储 | 用**连续的**存储单元，逻辑相邻则物理相邻 | **可随机访问**；插入删除需移动元素 |
| 链式存储 | 用**任意的**存储单元，靠指针表示逻辑关系 | **不可随机访问**；插入删除不移动元素 |
| 索引存储 | 存储元素 + 建立附加的**索引表** | 检索快；索引表占额外空间 |
| 散列存储 | 由关键字**直接计算**出存储地址 | 理想情况 O(1)；有冲突问题 |

**为什么**：**顺序与链式是全书最重要的对比**。它决定了：

| 对比维度 | 顺序存储 | 链式存储 |
|---------|---------|---------|
| 访问方式 | 随机访问（下标直接算地址） | 顺序访问（必须从头走） |
| 单次访问 | O(1) | O(n) |
| 插入删除 | O(n)（平均移动一半元素） | O(1)（已知位置时） |
| 存储密度 | 1（无额外开销） | < 1（要存指针） |
| 容量 | 需预先分配，可能溢出 | 动态申请，不会溢出（内存够的话） |

**怎么用**：选存储结构时按三个问题决策：

1. **要频繁按下标访问吗？** 要 → 顺序存储。
2. **要频繁在中间插入删除吗？** 要 → 链式存储。
3. **数据规模能预估吗？** 能且不大变 → 顺序；不能 → 链式。

> **【易错】** 三处：
> 1. **认为「链式存储一定比顺序存储好」** —— 错。链式丢失了随机访问能力，
>    且每个结点多一个指针的存储开销。**要看运算的特点。**
> 2. **把「存储结构」与「数据类型」混为一谈** —— 前者是组织方式，后者是取值范围与操作。
> 3. **忽略索引存储与散列存储** —— 大纲要求知道四种，考试会出「下列不属于…」类的选择题。

> **【类比】** 顺序存储像**电影院的连号座位**：知道第几排第几号，直接走过去（随机访问）；
> 但要插一个人进来，后面所有人都得往后挪。
> 链式存储像**击鼓传花的队伍**：只能从头问到尾（顺序访问）；
> 但要让某人插队，只要改两个人手里的小纸条。

> **【记忆】** **顺序快在「找」，链式快在「插」。**

**前置与延伸**：
- 前置：知识点 1
- 延伸：第 1 章会用这两种结构实现同一张线性表，对比最典型

### 0-3　抽象数据类型与算法定义　【P1】

**是什么**：

**抽象数据类型（ADT）**：一个数学模型以及定义在该模型上的一组操作。
它只关心「做什么」，不关心「怎么做」。

```text
ADT 线性表
数据对象：D = { a1, a2, ..., an }
数据关系：除 a1 与 an 外，每个元素有唯一前驱与后继
基本操作：
    InitList(&L)        初始化
    ListInsert(&L,i,e)   在第 i 个位置插入 e
    ListDelete(&L,i,&e)  删除第 i 个元素并用 e 返回
```

**算法**：对特定问题求解步骤的一种描述，是指令的**有限序列**。

**算法的五个特性**：

| 特性 | 含义 | 反例 |
|------|------|------|
| 有穷性 | 执行有限步后终止 | 死循环 |
| 确定性 | 每条指令含义唯一，无二义 | 「取一个较大的数」 |
| 可行性 | 每步都能通过基本运算实现 | 「判断任意程序是否停机」 |
| 输入 | 有零个或多个输入 | — |
| 输出 | 有**一个或多个**输出 | 只打印不返回结果 |

> **【重点】** **「有穷性」与「程序」的区别**是高频考点：
> 程序可以**不满足有穷性**（如操作系统常驻进程一直在跑），但算法必须满足。
> 所以「算法一定是程序，程序不一定是算法」—— **前半句也不严谨**：
> 算法是用自然语言或伪代码描述的，程序是算法的具体实现。

**怎么用**：ADT 的写法在 408 算法设计题中会用到 ——
**答题时先写 ADT 或数据结构定义，再写算法**。这是标准答题模板的第一步。

> **【易错】** **输出的数量**：算法必须有输出，且**至少一个**，可以是零个输入。
> 考试常把「零个或多个输入、一个或多个输出」拆开来设选项。

> **【类比】** ADT 像**遥控器的按键说明**：写着「按音量键调音量」，
> 但不说里面是电阻分压还是数字编码。**使用者只需要知道按键做什么。**

> **【记忆】** **输入可零，输出必有不小于一；有穷性是算法区别于程序的标志。**

### 0-4　时间复杂度分析　【P0】

**是什么**：算法执行时间随问题规模 n 增长的数量级关系，记作 `T(n) = O(f(n))`。

**严格定义**：若存在正常数 c 和 n₀，使得当 n ≥ n₀ 时恒有 `T(n) ≤ c·f(n)`，
则记 `T(n) = O(f(n))`。

**通俗理解**：`O(f(n))` 表示「当 n 很大时，执行时间的增长**不超过** f(n) 的某个常数倍」。

**为什么**：

1. 它**屏蔽了机器与实现差异** —— 同一算法在不同机器上的绝对时间不同，但量级相同。
2. 它**能预测能否通过** —— 408 单题限制约 1 秒，能执行约 10⁷ 至 10⁸ 次基本运算。
   据此可反推允许的复杂度（见知识点 6）。

**怎么用**：四步法。

**第 1 步：找基本语句。** 基本语句是**执行次数与 n 同阶**的那条语句，
通常在**最内层循环**里。

**第 2 步：算它的执行次数。** 三种典型形态：

| 循环形态 | 执行次数 | 复杂度 |
|---------|---------|--------|
| `for (i = 0; i < n; i++)` | n | O(n) |
| `for (i = 1; i < n; i *= 2)` | log₂n | O(log n) |
| `for (i = 1; i * i <= n; i++)` | √n | O(√n) |

**第 3 步：嵌套循环求和（不是相乘）。** 当内层界限依赖外层时，必须求和。

**第 4 步：只留最高阶项，去掉系数。**

```c
// 编译：gcc -std=c11 -O2
#include <stdio.h>

/* 例 1：单层循环，O(n) */
int sum1(int n) {
    int s = 0;
    for (int i = 1; i <= n; i++) {   /* 执行 n 次 */
        s += i;                      /* 基本语句 */
    }
    return s;
}

/* 例 2：步长倍增，O(log n) */
int countBits(int n) {
    int c = 0;
    while (n > 0) {
        n >>= 1;                     /* 每轮减半，共 log2(n) 轮 */
        c++;
    }
    return c;
}

/* 例 3：上界为平方，O(sqrt(n)) */
int sqrtCount(int n) {
    int c = 0;
    for (int i = 1; i * i <= n; i++) {   /* i 最大到 sqrt(n) */
        c++;
    }
    return c;
}

/* 例 4：双层嵌套且内层依赖外层 —— 必须求和，不能相乘 */
int nested(int n) {
    int c = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= i; j++) {   /* 内层执行 i 次，随外层变化 */
            c++;
        }
    }
    return c;
    /* 总次数 = 1+2+...+n = n(n+1)/2 = O(n^2) */
}

/* 例 5：内外层都用倍增，O(n log n) */
int nLogn(int n) {
    int c = 0;
    for (int i = 1; i <= n; i++) {       /* 外层 n 次 */
        int t = i;
        while (t > 0) { c++; t >>= 1; }  /* 内层 log(i) 次，与 i 同阶 */
    }
    return c;
}

/* 例 6：三个连续循环 —— 相加而非相乘，取最大者 */
int sequential(int n) {
    int c = 0;
    for (int i = 0; i < n; i++) c++;          /* O(n)   */
    for (int i = 0; i < n * n; i++) c++;      /* O(n^2) */
    for (int i = 0; i < 1000; i++) c++;       /* O(1)   */
    return c;   /* 总复杂度 O(n^2) —— 取最高阶 */
}

int main(void) {
    printf("sum1(10)=%d\n", sum1(10));
    printf("countBits(1024)=%d\n", countBits(1024));
    printf("sqrtCount(100)=%d\n", sqrtCount(100));
    printf("nested(10)=%d（应为 55）\n", nested(10));
    printf("nLogn(16)=%d\n", nLogn(16));
    printf("sequential(10)=%d\n", sequential(10));
    return 0;
}
```

> **【规律】** **常见复杂度的增长速度排序**（从慢到快）：
>
> ```text
> O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
> ```
>
> 记忆方法：**常数 → 对数 → 根号 → 线性 → 线性对数 → 平方 → 立方 → 指数 → 阶乘**。
> **分界线在 O(n log n)**：`O(n log n)` 及以下通常可用，`O(n²)` 只适合 n ≤ 5000，
> 指数级只适合 n ≤ 20。

> **【易错】** 四处：
> 1. **嵌套循环一律相乘** —— 只有**内层界限不依赖外层**时才能相乘。
>    例 4 的 `j <= i` 依赖外层，必须求和。
> 2. **把 `O(1)` 理解为「执行一次」** —— `for (i = 0; i < 1000; i++)` 是 O(1)，
>    因为 1000 与 n 无关。
> 3. **保留低阶项** —— `2n² + 3n + 1` 写 `O(n²)`，不写 `O(n² + n)`。
> 4. **误判 `i *= 2` 类循环** —— 次数是 log₂n 而非 n。

> **【类比】** 复杂度像**快递的计费方式**：不关心送一件收几毛（常数），
> 只关心「件数翻倍时费用涨几倍」。线性是翻倍，平方是翻四倍，对数几乎不涨。

> **【记忆】** **先找基本语句，再数次数；嵌套看内层是否依赖外层；最后只留最高阶。**

### 0-5　空间复杂度分析　【P0】

**是什么**：算法运行所需的**辅助空间**随问题规模 n 增长的数量级，记作 `S(n) = O(g(n))`。

**关键区分**：

| 口径 | 是否计入空间复杂度 | 说明 |
|------|------------------|------|
| **算法自身的指令、常数、变量** | 计入 | 固定部分，记 O(1) |
| **辅助数组 / 临时结构** | 计入 | 这是主要考察对象 |
| **输入数据的存储空间** | **不计入** | 输入由问题给定，不是算法的开销 |
| **递归调用的栈帧** | **计入** | 每层递归都要保存局部变量与返回地址 |

**为什么**：408 会考「原地算法」（in-place）的概念 ——
**辅助空间为 O(1)** 的算法称为原地算法。排序章节中要反复区分。

**怎么用**：

1. 数算法里**新申请**的数组大小与循环变量个数。
2. 递归算法：**栈深度 × 每层的固定开销**。
3. 输入数组本身不计入。

```c
// 编译：gcc -std=c11 -O2
#include <stdio.h>

#define MAXN 1005

/* 例 1：只用了常数个变量，S(n) = O(1) —— 原地算法 */
void reverseInPlace(int a[], int n) {
    for (int i = 0, j = n - 1; i < j; i++, j--) {
        int t = a[i];      /* t 是常数级辅助变量 */
        a[i] = a[j];
        a[j] = t;
    }
}

/* 例 2：借助一个长度 n 的辅助数组，S(n) = O(n) */
void reverseWithExtra(int a[], int n) {
    int tmp[MAXN];                    /* 辅助空间 n 个 int → O(n) */
    for (int i = 0; i < n; i++) tmp[i] = a[n - 1 - i];
    for (int i = 0; i < n; i++) a[i] = tmp[i];
}

/* 例 3：递归 —— 栈深度 n，S(n) = O(n) */
long long fact(int n) {
    if (n <= 1) return 1;             /* 每层递归占一个栈帧 */
    return n * fact(n - 1);
}

/* 例 4：递归但深度为 log n，S(n) = O(log n) */
long long fastPow(long long b, int e) {
    if (e == 0) return 1;
    long long h = fastPow(b, e / 2);  /* 每次减半 → 深度 log e */
    return (e & 1) ? h * h * b : h * h;
}

int main(void) {
    int a[5] = {1, 2, 3, 4, 5};
    reverseInPlace(a, 5);
    printf("原地反转后首元素=%d（S(n)=O(1)）\n", a[0]);

    printf("fact(20)=%lld（S(n)=O(n)，栈深度 n）\n", fact(20));
    printf("fastPow(2,20)=%lld（S(n)=O(log n)）\n", fastPow(2, 20));
    return 0;
}
```

> **【重点】** **递归的空间复杂度 = 递归深度**（每层栈帧的常数倍）。
> 这是最容易漏算的一处 —— 许多算法时间上是 O(log n)，但空间是 O(n)（如普通快速排序）。

> **【易错】** 四处：
> 1. **把输入数组算进辅助空间** —— 错，输入不计入。
> 2. **漏算递归栈深度** —— 见上。
> 3. **认为「时间换空间」总是划算** —— 两者要一起权衡。LRU 缓存就是空间换时间的典型。
> 4. **混淆「存储结构占用的空间」与「算法的辅助空间」** —— 前者是数据结构本身的
>    存储开销，后者是算法额外申请的。408 问的通常是后者。

> **【类比】** 空间复杂度像**做菜时占用的台面**：食材（输入）是别人送来的，
> 不算你的台面占用；你能算的是「自己摆了几个碗、请了几个帮手」。
> 递归的栈帧就是**每层帮手**——调用越深，帮手越多。

> **【记忆】** **输入不计入；递归深度就是空间；辅助空间 O(1) 叫原地算法。**

**前置与延伸**：
- 前置：知识点 4
- 延伸：第 7 章会反复区分「原地排序」与「非原地排序」

### 0-6　复杂度量级排序与规模推定　【P0】

**是什么**：给定数据规模 n 与时限，反推允许的时间复杂度。这是**做题时的第一判断**。

**为什么**：408 与 OJ 一样有时限。**先看 n 的范围，再决定用什么算法**，
而不是想到什么写什么。这一步能避免大量「算法正确但超时」的失败。

**怎么用**：

**规模推定表**（按 1 秒约 10⁷ 至 10⁸ 次基本运算估算）：

| n 的范围 | 允许的复杂度 | 常见算法 |
|---------|-------------|---------|
| n ≤ 20 | O(2ⁿ)、O(n!) | 暴力枚举子集、全排列 |
| n ≤ 100 | O(n³) | Floyd、三重循环 DP |
| n ≤ 5×10³ | O(n²) | 冒泡 / 插入 / 选择排序、普通 DP |
| n ≤ 10⁵ | O(n log n) | 快速 / 归并 / 堆排序、二分 |
| n ≤ 10⁶ | O(n) | 计数排序、线性扫描、KMP |
| n ≤ 10⁸ | O(log n)、O(1) | 二分查找、公式计算 |
| n 极大（如 10¹⁸） | O(log n) | 快速幂、矩阵快速幂 |

```text
决策流程（三步）：
  第 1 步　读题面上的 n 上限
  第 2 步　查上表，确定可用复杂度
  第 3 步　在该复杂度内选算法；若想不出，说明需要换思路而不是优化常数
```

**408 中的实际含义**：

| 场景 | 时限内的可接受算法 |
|------|------------------|
| 算法设计题（数据结构占第 41、42 题） | 通常要求**优于朴素解法**，如 O(n log n) 或 O(n) |
| 选择题中的复杂度比较 | 直接按量级排序比较 |
| 综合应用题的填空 | 常直接考某算法的复杂度 |

> **【规律】** **先从规模反推复杂度，再选算法。**
> 这条习惯能避免「写出正确但超时的代码」——而超时在 408 算法设计题中**不给分**。

> **【易错】** 三处：
> 1. **忽略「基本运算」的常数差异** —— 一次乘法比一次比较贵；
>    同是 O(n log n)，快排的实际常数小于归并（但归并稳定）。
> 2. **把 10⁷ 当成绝对上限** —— 简单运算可达 10⁸，复杂运算（如浮点开方）可能只有 10⁶。
> 3. **忽视空间限制** —— 时间够但内存超限同样失败。见知识点 5。

> **【类比】** 规模推定像**按发票金额选支付方式**：小额用零钱（暴力），
> 大额必须走转账（优化算法）。你**不会先选支付方式再问金额**。

> **【记忆】** **n 到 20 打表，到 100 三方，到 5000 平方，到 10⁵ 带 log，到 10⁶ 线性，更大只能对数。**

**前置与延伸**：
- 前置：知识点 4、5
- 延伸：附录 B 的高频考点索引会按此表给每类题标注可用复杂度

## 典型例题

> **【重点】** 例题 0-1　复杂度计算（计算与推导题）

**题干**：分析下列程序段的时间复杂度。

```c
int i = 1;
while (i <= n) {
    i = i * 3;
}
```

**解题思路**：

1. 从题面信号切入：循环变量是**乘性增长**（`i = i * 3`），不是加性。
2. 排除错误路径：不能因为「只有一层循环」就判 O(n)。
3. 最终方法：**列出执行次数与 n 的关系式**再求。

**解答过程**：

设循环执行 k 次。每轮 i 乘以 3，因此第 k 次循环前 `i = 3^(k-1)`。

循环结束条件是 `i > n`，即

```text
3^(k-1) > n
k - 1 > log₃ n
k > log₃ n + 1
```

所以 `k = ⌈log₃ n⌉ + 1`，执行次数与 log n 同阶。

**因此时间复杂度为 O(log n)。**

补充说明：底数 3 与底数 2 的差别只是一个常数因子
（`log₃ n = log₂ n / log₂ 3`），而在大 O 记号中**常数因子被忽略**，
所以无论乘 2 还是乘 3，都是 O(log n)。

**代码实现**：见知识点 4 的例 2（`countBits`，结构相同）。

**复杂度分析**：时间 O(log n)，空间 O(1)。

> **【易错】** 本题最常见的错误答案是 O(n)。原因是**只看循环层数不看增长方式**。
> 判断口诀：**循环变量是「加」还是「乘」——乘则带 log。**

---

> **【重点】** 例题 0-2　嵌套循环求和（计算与推导题）

**题干**：分析下列程序段的时间复杂度。

```c
int count = 0;
for (int i = 1; i <= n; i++) {
    for (int j = i; j <= n; j++) {
        count++;
    }
}
```

**解题思路**：

1. 题面信号：内层循环的**下界依赖外层变量 i**。
2. 排除错误路径：不能简单相乘为 n × n。
3. 最终方法：**对内层次数求和**。

**解答过程**：

外层第 i 轮时，内层执行次数为 `n - i + 1`。

总次数：

```text
Σ(i=1 到 n) (n - i + 1)
= n + (n-1) + (n-2) + ... + 1
= n(n+1)/2
= n²/2 + n/2
```

去掉系数与低阶项，得 **O(n²)**。

> **【注意】** 本题结果与「双重循环各 n 次」**同为 O(n²)**，
> 但**系数不同**（约 1/2）。这说明 **O 记号只保证量级，不保证实际速度** ——
> 两个都是 O(n²) 的程序，实际运行时间可能差一倍。

**代码实现**：见知识点 4 的例 4（`nested`）。

**复杂度分析**：时间 O(n²)，空间 O(1)。

> **【易错】** 本题的陷阱不在结果，而在**过程**：
> 许多同学直接写「两层循环，所以 O(n²)」——答案蒙对了，但方法错了。
> 换成例题 0-1 那种一层循环就答错。**必须养成「数次数」的习惯。**

## 本章总结

### 核心内容（一页纸）

1. **数据结构三要素**：逻辑结构（关系）、存储结构（实现）、数据运算（操作）。
   三者中**逻辑结构与存储结构不是一一对应**的。
2. **四种逻辑结构**：集合、线性、树形、图形。分别对应第 1、4、5 章。
3. **四种存储结构**：顺序、链式、索引、散列。
4. **顺序 vs 链式的核心对比**：顺序**随机访问 O(1)**、插入删除 O(n)、存储密度 1；
   链式**顺序访问 O(n)**、插入删除 O(1)（已知位置）、存储密度 < 1。
   口诀：**顺序快在「找」，链式快在「插」。**
5. **算法五特性**：有穷性、确定性、可行性、输入（可零）、输出（**必有不小于一**）。
   有穷性是算法区别于程序的标志。
6. **复杂度分析四步**：找基本语句 → 数次数 → 嵌套求和 → 只留最高阶。
7. **循环次数三种形态**：`i++` 是 n；`i *= 2` 是 **log n**；`i * i <= n` 是 **√n**。
   **判断口诀：看变量是「加」还是「乘」，乘则带 log。**
8. **嵌套循环**：内层界限**依赖**外层时必须**求和**（如 `j <= i` → n(n+1)/2 = O(n²)）；
   不依赖时可相乘。
9. **复杂度排序**：`O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)`。
   分界线在 **O(n log n)**。
10. **空间复杂度三要点**：**输入不计入**；**递归深度就是空间**；辅助空间 O(1) 称**原地算法**。
11. **规模推定表**：n ≤ 20 打表；n ≤ 100 三方；n ≤ 5000 平方；
    n ≤ 10⁵ 带 log；n ≤ 10⁶ 线性；更大只能对数。
12. **做题第一判断**：先看 n 的范围，再选算法。**不要先想算法再看规模。**

## 自测答案

**自测题 0-1 答案**：

外层循环 `i = 1, 2, 4, 8, ...` 是**乘性增长**，执行次数为 **log₂n**。
内层循环 `j = 1 到 n` 执行 **n** 次，且**内层界限不依赖外层变量 i**
（下界恒为 1，上界恒为 n），因此**可以相乘**。

```text
总次数 = log₂n × n
```

**时间复杂度为 O(n log n)。**

> **【易错】** 本题与例题 0-2 的区别在于**内层界限是否依赖外层**。
> 例题 0-2 的 `j = i` 依赖 i，必须求和；本题的 `j = 1` 不依赖，可以直接相乘。
> **判断这一点的能力就是本章的核心技能。**

**自测题 0-2 答案**：

**应选第一个算法（O(n log n) 时间、O(n) 空间）。**

**理由**：

1. **时间维度**：n = 10⁶，时限 1 秒。
   - O(n log n) ≈ 10⁶ × 20 = **2×10⁷** 次基本运算 —— 在 10⁷ 至 10⁸ 的预算内，**可通过**。
   - O(n²) = (10⁶)² = **10¹²** 次 —— 超出预算**五个数量级**，**必然超时**。
   
   **时间上第一个算法胜出，且是量级级别的胜出。**

2. **空间维度**：辅助空间 O(n) = 10⁶ 个元素。
   - 若每个元素 4 字节，共约 **4 MB**，远低于 256 MB 的限制，**不构成瓶颈**。

3. **结论**：**时间瓶颈是「量级问题」，空间瓶颈是「常数问题」**。
   当两者冲突时，**优先解决量级问题** —— 时间超标无法通过优化常数挽救，
   而空间超标往往能通过改用更紧凑的数据类型缓解。

> **【规律】** 一般决策顺序：**先保时间达标（量级），再在时间达标的前提下压空间。**
> 只有当空间**必然超限**（如 O(n²) 的辅助数组在 n = 10⁵ 时需要 4×10¹⁰ 字节）时，
> 才反过来牺牲时间去换空间。
