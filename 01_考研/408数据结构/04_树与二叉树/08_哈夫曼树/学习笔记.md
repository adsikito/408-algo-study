## 第八章：哈夫曼树

> 课件来源：`哈夫曼编码树.pdf`、`哈夫曼编码的代码\HuffmanTree.c`
>
> 本章主线：四个前导概念（路径长度 → WPL）→ 哈夫曼树 = WPL 最小的二叉树 → 哈夫曼编码 = 用哈夫曼树构造的前缀码 → 数据压缩的第一实用方案。

## 🗺️ 本章地图

- **本章解决什么问题**：给字符编"最省位数的二进制码"，还要保证解码不打架——这是数据压缩的第一课。
- **学习顺序**：先立标尺 WPL（节1）→ 学会造 WPL 最小的树（节2）→ 从定长/变长对比引出"短码"动机（节3）→ 变长带来的歧义由前缀码解决（节4）→ 树 + 前缀码合体成哈夫曼编码（节5）→ 落地成数组代码（节6）。
- **为什么是这个顺序**：没有 WPL 就无法定义"最优"；没有前缀属性变长码就不能用；节2 造的树正是节5 编码的载体——环环相扣，跳不得。
- **各节关系一句话**：节1 给目标函数，节2 给最优解法，节3~4 给应用动机，节5 把两者拼起来，节6 写成代码。

## 📌 本章重点（3-5个）

⭐ **WPL（树的带权路径长度）**：所有**叶子结点**的带权路径长度之和；WPL 越小，二叉树性能越优
⭐ **哈夫曼树的构造**：初始森林 n 棵单结点树 → 每次选**根权值最小的两棵**合并（新根权值 = 左右孩子权值之和）→ 合并 n−1 次，共 **2n−1 个结点**
⭐ **前缀属性/前缀码**：任一字符编码都不是其他字符编码的前缀，保证解码唯一不歧义
⭐ **哈夫曼编码的三大特征**：编码树是二叉树、叶子含字符、**左 0 右 1**，根到叶路径即编码
⭐ **变长编码思想**：出现频率越高，编码长度越短——短编码赋予高频字符

## 🔥 本章难点（2-3个）

🔥 **手工构造哈夫曼树并求 WPL**：每一步都要在"当前森林"里重新找两个最小，新根还要参与后续竞争，过程容易乱序
🔥 **编码与解码的双向推导**：从根到叶写编码；解码从根出发按 0/1 走到叶子即为一个字符，再回到根继续
🔥 **代码实现**：静态数组（w、fa、l、r 四域）存 2n−1 个结点；Find 两轮扫描选最小两根；CreatCode 从叶子沿 fa **回溯到根、从尾部倒着写**编码

## ⚠️ 本章易错点（3-5个）

⚠️ **WPL 算错范围**：只统计**叶子**的带权路径长度，内部结点不算；带权路径长度 = 路径长度 × 权值，别忘乘
⚠️ **结点数记错**：n 个叶子的哈夫曼树共有 **2n−1** 个结点（没有度为 1 的结点），代码数组开 2n 是留出余量
⚠️ **前缀属性理解反**：是"任何码字都不是其他码字的**前缀**"；例如 a=0,b=10,c=110,d=11 时 110 既可解成 c 又可解成 da，就是缺少前缀属性
⚠️ **合并时忘记更新候选集**：被合并的两棵树退出森林（fa 不再是 −1），新合并的树加入下一轮"找最小"
⚠️ **编码方向与约定混乱**：从根到叶读出的是正序编码；代码从叶子回溯生成是逆序（start 从 n−1 往前写）；"左 0 右 1"只是约定，课件代码里恰好相反（左记 '1'），关键是全局一致

## 📖 知识点讲解

### 1. 四个前导概念与 WPL

**是什么**：要比较不同的二叉树谁"更划算"，得先有一把统一的尺子：把每个叶子离根的距离（边数）乘上它的重要程度，再加起来——这把尺子的读数就是 WPL，读数越小的树越优。先记四个由浅入深的概念：
- **结点的路径长度**：从根结点到该结点的路径上的**连接数**（课件示例树中根 A 到结点 K 经过 3 条红边，K 的路径长度 = 3）
- **树的路径长度**：树的每个**叶子结点**的路径长度之和（示例树中 F、G、H、I、J 各为 2，K 为 3，总和 = 13）
- **结点的带权路径长度**：结点的**路径长度与结点权值的乘积**（权值——人为给叶子标的"重要程度"数值，编码场景下可理解为字符出现次数；结点 K 权值 4、路径长度 3，带权路径长度 = 3×4 = 12）
- **树的带权路径长度 WPL**：树的所有**叶子结点**的带权路径长度之和

**为什么**：WPL 是衡量二叉树"性能"的标尺——**WPL 的值越小，二叉树的性能越优**。把权值大的叶子放得离根越近、权值小的放远，WPL 就小；WPL 最小的二叉树正是哈夫曼树。

**怎么用**（课件示例树 A(B(E(K),F), C(G,H), D(I,J))，设叶权 F=G=H=I=J=2、K=4），跟着算一遍：
```text
第1步 找叶子、数边：K 在第 3 层，路径长度 3；F/G/H/I/J 在第 2 层，路径长度各 2
第2步 只数边不乘权：树的路径长度 = 2×5 + 3 = 13
第3步 乘上权值：K 的带权路径长度 = 3 × 4 = 12
第4步 只把叶子加总：WPL = (2+2+2+2+2)×2 + 3×4 = 20 + 12 = 32
```
再用权值 {1,2,3} 的两棵小树感受一下"摆法不同、WPL 不同"：
```text
     甲：三叶都在第 2 层           乙：权值 3 放到第 1 层
          o                            o
         / \                          / \
        1   o                        3   o
           / \                          / \
          2   3                        1   2
WPL甲 = (1+2+3)×2 = 12          WPL乙 = 3×1 + (1+2)×2 = 9
```
乙的 WPL 更小、更优——"大权靠根近"就是全部秘诀，哈夫曼树（下节）就是把这种摆法做到极致。

> ⚠️ 注意事项：WPL 只累加叶子；"权值"是人为设定的数值（可理解为字符出现次数），路径长度与权值是两个独立量，相乘才是带权路径长度。

> 🎯 规律：算 WPL 只需三问——是不是叶子？离根几条边？权值几？边数 × 权值逐叶求和；同权值下"大权靠根"者胜。

> 💡 一句话总结：叶子路径乘权值，求和即 WPL。

### 2. 哈夫曼树的定义与构造过程

**是什么**：让权值小的叶子站得远、权值大的站得近，总代价（WPL）就最小——哈夫曼树就是把这件事做到极致的"冠军树"。严格地说，哈夫曼树（Huffman 树）是 **WPL 最小的二叉树**（最优二叉树）。构造过程（课件三步）：
1. 给出初始森林：n 棵只有根结点的二叉树（示例：A=7、B=5、C=2、D=4）
2. **第一步**：森林中选出两棵结点权值最小的二叉树（C=2、D=4）
3. **第二步**：合并两棵二叉树，增加一个新结点作为新二叉树的根，**权值为左右孩子的权值之和**（新根 = 6）
4. **第三步**：不断将新的结点跟权值最小的结点相结合，直到森林只剩一棵树

**为什么**：每次都让最小的两个权值先"沉底"（离根最远），让大权值留在浅层，最终总 WPL 最小——这是贪心策略（每一步只选当前最好的选择、绝不回头反悔）在树上的应用。哈夫曼编码可以有效地压缩数据（压缩率依赖于数据的特性，在 20%～90% 不等）。

**怎么用**（课件示例 {A:7, B:5, C:2, D:4}），从头合并一遍：
```text
第1步 森林 {A7, B5, C2, D4} 中最小两棵是 C(2)、D(4) → 合并出新根 N1(6)
      森林变为：A7  B5  N1(6)        （新根要参加下一轮竞争！）
第2步 最小两棵是 B(5)、N1(6) → 合并出新根 N2(11)
      森林变为：A7  N2(11)
第3步 最小两棵是 A(7)、N2(11) → 合并得根 N3(18)，森林只剩一棵，构造完成
最终树（画出来核对一遍）：
              N3(18)
             /      \
           A(7)    N2(11)
                  /      \
                B(5)    N1(6)
                       /    \
                     C(2)   D(4)
```
核对：共 4 个叶子，合并 4−1 = 3 次，结点数 = 2×4−1 = 7，与图一致。

> ⚠️ 注意事项：n 个叶子合并 n−1 次，最终 **2n−1** 个结点，且哈夫曼树中没有度为 1 的结点；两棵最小树谁左谁右不影响 WPL，但编码会不同。

> 🎯 规律：构造口诀只有一句——每轮都合并"当前森林里最小的两棵"；小权值被合并得越早就沉得越深，大权值自然留在浅层。

> 💡 一句话总结：每次找两小合并，n 减一次成树。

### 3. 定长编码与变长编码

**是什么**：定长编码像统一规格的身份证——好管理但费位；变长编码按"出镜率"发长短不同的胸牌：越常出现给得越短，总位数立刻省下来。严格定义：
- **定长编码**：每个字符用固定位数。ASCII 每个字符 8 bit，能编码 256 个字符；Unicode 每个字符 16 bit，能编码 65536 个字符（包含所有 ASCII 字符）。用定长编码给 A、B、C、D、E 五个符号编码，**至少需要 3 位**（2 bit 只能表示 4 个字符）；对消息 DEAACAAAAABA（12 个字符）编码，每个 3 bit，共 **36 位**
- **变长编码**：单个编码长度不一样，按出现频率调节——**频率越高，编码越短**；同一消息的编码总长度小于定长编码

**为什么**：定长编码的缺陷是**浪费空间**——仅含 ASCII 字符的纯文本用 Unicode 存储要占两倍空间；字符 "a" 和 "e" 的出现频率比 "q" 和 "z" 高，却占用相同位数。要让短编码留给高频字符，就有了变长编码。

**怎么用**（跟着算：消息 DEAACAAAAABA，12 个字符）：
```text
第1步 统计频率：A 出现 8 次，B、C、D、E 各 1 次
第2步 定长方案：5 种符号至少 3 位 → 12 × 3 = 36 位
第3步 变长方案：频率最高的 A 给最短码 0（1 位），其余依次加长：
      B=10、C=110、D=1110、E=11110
第4步 变长总位数 = 8×1 + (2+3+4+5)×1 = 8 + 14 = 22 位，比定长的 36 位省 14 位
```

> ⚠️ 注意事项：变长编码立刻引出新问题——字符有长有短，**怎么知道一个字符从哪里开始、又从哪里结束**？这就要求编码具备前缀属性（见下节）。

> 🎯 规律：定长码的位数由"符号种数"决定（⌈log₂种数⌉），变长码的位数由"频率分布"决定——频率越偏斜，变长越划算。

> 💡 一句话总结：高频短码，定长费位。

### 4. 前缀属性与前缀码

**是什么**：变长码最怕读者迷路——不知道一个字符在哪里结束。前缀属性就是给路名牌立的规矩：**任何一个码字都不许是别的码字的开头**，于是一段 0/1 串只有一种切法。严格地说：字符集当中，一个字符编码**不是其他字符编码的前缀**，则该编码具有**前缀属性**。若违反（存在前缀关系），一个编码串可以被解码为多个字符序列，表示不唯一。**前缀码**：没有任何码字是其他码字的前缀的编码。

**为什么**：变长编码没有固定边界，解码唯一性全靠前缀属性保证；一旦某码字是另一码字的前缀，同一段 0/1 串就有多种切分方式，通信就出歧义。

**怎么用**（课件两个例子对比）：
```text
✅ 具有前缀属性：P=000, Q=11, R=01, S=001, T=10
   000 不是 11/01/001/10 的前缀；11 也不是它们的前缀
   编码 01001101100010 → 唯一译码为 RSTQPT

❌ 缺少前缀属性：P=0, Q=1, R=01, S=10, T=11
   编码 1110 可解码为 QQQP、QQS、QTP、TQP 和 TS 共 5 种——结果不唯一！
```
跟着算一遍"唯一译码"是怎么发生的（用 ✅ 那组码，从左往右贪心读）：
```text
第1步 读 "01" → R，剩 001101100010
第2步 读 "001" → S，剩 101100010
第3步 读 "10"  → T，剩 1100010
第4步 读 "11"  → Q，剩 00010
第5步 读 "000" → P，剩 10
第6步 读 "10"  → T，读完 → RSTQPT，每一步都只有一个码字能匹配
```
反例同理：设 a=0, b=10, c=110, d=11，编码 110 可以表示 c，也可以表示 da。

> ⚠️ 注意事项：**哈夫曼编码就是一种前缀码**——构造它用的正是一棵哈夫曼树；判断前缀属性只需两两检查"是否互不为前缀"。

> 🎯 规律：验前缀码就做两两检查"谁都不是谁的开头"；一旦违反，同一段串必有多种切分——解码唯一性 = 前缀属性。

> 💡 一句话总结：码字互不为前缀，解码唯一。

### 5. 哈夫曼编码的构造与特征

**是什么**：把字符挂上哈夫曼树的叶子，从根出发给左边路口立"0"牌、右边路口立"1"牌——走到某片叶子沿途读到的一串路牌，就是这个字符的编码。三大特征：
1. 哈夫曼编码树是一棵**二叉树**：每片叶子结点都包含一个字符；从结点到其**左孩子的路径标记 0**；到其**右孩子的路径标记 1**
2. 从根结点到包含字符的叶子结点的**路径上获得的标记序列**就是该叶结点的编码
3. 编码均具有**前缀属性**：每一个叶结点不能出现在到另一个叶结点的路径上（注：定长编码可以由完整的哈夫曼树表示，并且显然具有前缀属性）

**为什么**：字符只在叶子上，从根到叶子的路径互不重叠——一条路径不可能是另一条的"开头"，前缀属性天然成立；权值（频率）大的字符在合并中总是晚加入 → 离根近 → 编码短。

**怎么用**（课件完整示例：消息 "this is his message"）：
```text
统计字符次数：a1  g1  m1  t1  e2  h2  空格3  i3  s5   （共9种，19字符）
构造哈夫曼树（左0右1约定）：
              19
            /    \
           8      11
          / \    /  \
         4   4  6    s5
        /|  /| / \
       2 2 e2 h2 空格3 i3
      /| /|
     a1 g1 m1 t1
可得：s=111, 空格=10?, i=110, e/h=01x, a/g/m/t=000x（按左右约定而定）
```
权值大（s=5、空格=3、i=3）的字符编码短，权值小（各 1 次）的字符编码最长。

跟着算（用节2 造好的 {A:7, B:5, C:2, D:4} 的小树，约定左 0 右 1）：
```text
              N3(18)
             /      \
           A(7)    N2(11)
                  /      \
                B(5)    N1(6)
                       /    \
                     C(2)   D(4)
第1步 四个字符都只在叶子上：A、B、C、D（内部结点 N1/N2/N3 不放字符）
第2步 从根到每片叶子走一遍，沿途记 0/1：
      A = 0（1 位）、B = 10（2 位）、C = 110（3 位）、D = 111（3 位）
第3步 验证前缀属性：0、10、110、111 两两互不为前缀 ✓
第4步 双向演练：编码 CAD → "110 0 111"；解码从根走：110→C、0→A、111→D，唯一还原
第5步 验 WPL：7×1 + 5×2 + (2+4)×3 = 35，恰等于三个内部结点权值之和 18+11+6 = 35
```

> ⚠️ 注意事项：0/1 分配左右是约定（课件文字说左 0 右 1，配套代码里相反），只要整棵树一致即可；同一组权值的哈夫曼树形态可能不唯一，但 WPL 相同。

> 🎯 规律：码长 = 叶子深度 = 该字符"被合并的先后"——越早被合并沉得越深码越长；验算可用 WPL = 所有非叶子结点权值之和。

> 💡 一句话总结：叶子放字符，左右路标 0/1。

### 6. 哈夫曼树与编码的代码实现

**是什么**：不开链表、不搭指针树，直接开一个大数组当"花名册"：每个结点登记四项——权值、父亲、左孩子、右孩子，剩下的活全靠下标算。配套代码用**静态数组**（提前开好固定大小、运行时不再申请的数组）存储哈夫曼树，每个结点四个域：`w`（权值）、`fa`（父亲下标）、`l/r`（左右孩子下标）。流程：
1. **建树**：n 个叶子先各自成树（fa=-1）放入数组；循环 i 从 n 到 2n−2，Find 在 tree[0..i−1] 中找 **fa==-1（仍是根）且权值最小**的两个下标 s1、s2，新结点 `tree[i].l=s1, tree[i].r=s2, tree[i].w=两者之和`，并令两孩子的 fa 指向 i
2. **编码**：对每个叶子，从该叶子沿 fa **回溯到根**：当前结点是父亲的左孩子记 '1'（本代码约定）、否则记 '0'；用 start 从数组末尾 n−1 往前写，天然完成逆序
3. **输出**：n 个编码存入二级指针模拟的二维字符数组

**为什么**：顺序存储 + fa 指针让"找两棵最小树"退化为线性扫描（fa==-1 才是候选根）；从叶子回溯是"知道儿子找爸爸"最短路径，比从根下行判方向更省事。

**怎么用**（HuffmanTree.c 核心摘录）：
```c
typedef struct Node {
    int w;  int fa;  int l, r;   // 权值/父亲/左右孩子的下标
} HuffmanNode;

int m = 2 * n;                    // 结点总数 2n-1，数组开 2n
for (i = n; i <= 2*n-2; i++) {    // 合并 n-1 次
    Find(tree, i-1, &s1, &s2);    // 找 fa==-1 中权值最小的两个根
    tree[i].fa = -1;  tree[i].l = s1;  tree[i].r = s2;
    tree[i].w = tree[s1].w + tree[s2].w;   // 新根权值 = 之和
    tree[s1].fa = tree[s2].fa = i;         // 老根退出候选
}
// 编码：从叶子回溯，start 从 n-1 往前写（逆序生成即正序编码）
start = n-1;  t[start] = '\0';  p = i;  pre = tree[p].fa;
while (pre != -1) {
    start--;
    if (p == tree[pre].l) t[start] = '1';   // 本代码约定左 '1'
    else                  t[start] = '0';
    p = pre;  pre = tree[p].fa;
}
```
跟着算（n=4：A7 B5 C2 D4，数组下标从 0 起，把建树循环走一遍）：
```text
第0步 初始化：tree[0..3] = A7、B5、C2、D4，fa 全 -1（都还是根）
第1步 i=4：Find 扫描得最小两根 s1=2(C2)、s2=3(D4)
      tree[4] = {w=6, l=2, r=3}，fa[2]=fa[3]=4 → C、D 退出候选
第2步 i=5：候选根剩 A7、B5、N1(6)，选 s1=1(B5)、s2=4(6)
      tree[5] = {w=11, l=1, r=4}，fa[1]=fa[4]=5
第3步 i=6：候选根剩 A7、N2(11)，选 s1=0(A7)、s2=5(11)
      tree[6] = {w=18, l=0, r=5}，fa[0]=fa[5]=6 → 建树完成
最终数组（共 2n−1 = 7 个结点，正好用满）：
      下标  0   1   2   3   4   5   6
      w     7   5   2   4   6  11  18
      fa    6   5   4   4   5   6  -1
```

> ⚠️ 注意事项：Find 的候选条件是 `fa == -1`（还是根），被合并过的结点自动出局；数组开 2n 而非 2n−1，多留 1 格防越界；样例输入 `9 / agmteh is / 1 1 1 1 2 2 3 3 5` 与课件 "this is his message" 的频率一一对应。

> 🎯 规律：`fa == -1` 是"仍是根"的通行证——选两小靠它筛候选，回溯编码靠它上行；结点一旦有了父亲就终身出局。

> 💡 一句话总结：数组存树，回溯倒写编码。

### 🧩 本章归纳：一条主线串全章

**一条主线**：要压缩 → 用变长编码省位（节3）→ 变长有歧义 → 前缀属性保证唯一解码（节4）→ 字符挂叶子、路径当编码，前缀属性天然成立（节5）→ 那什么树编码总长最短？WPL 最小的树（节1）→ 贪心"每轮合并最小两棵"造出它，这就是哈夫曼树（节2）→ 数组四域 + 沿 fa 回溯倒写，落成代码（节6）。

**回头看才看得见的共性**：
1. **一条位置约束消灭一类错误**："字符只放叶子上"让解码歧义根本无从发生——好的结构设计用约束代替检查（对比：循环队列用取模运算消灭边界特判）。
2. **贪心 = 局部最优堆出全局最优**：每轮只做"合并当前最小两棵"这一件局部正确的事，n−1 轮后全局 WPL 必最小；这套思路后面还会在 Dijkstra、Prim 里反复出现。
3. **数组 + 下标可以顶替指针**：w/fa/l/r 四域数组撑起一整棵树——与堆的 2i+1 公式、并查集的 fa 数组是同一招：存储结构决定允许的操作。

## 🔍 相似概念辨析

### 组1：路径长度 vs 带权路径长度

| 对比维度 | 路径长度 | 带权路径长度 |
|----------|---------|-------------|
| 各自定义 | 根到该结点路径上的连接数 | 路径长度与结点权值的乘积 |
| 核心区别 | 只数边，与权值无关 | 边数 × 权值 |
| 各自特点 | 树的路径长度 = 各叶子路径长度之和 | 树的 WPL = 各叶子带权路径长度之和 |
| 使用场景 | 描述树的形状深浅 | 衡量二叉树性能优劣 |
| 典型示例 | 课件中 K 的路径长度为 3 | K 权值 4 → 3×4 = 12 |
| 记忆口诀 | 数边是长度，乘权才带权 |

### 组2：定长编码 vs 变长编码

| 对比维度 | 定长编码 | 变长编码 |
|----------|---------|---------|
| 各自定义 | 每个字符固定位数（ASCII 8bit、Unicode 16bit） | 每个字符位数不同，按频率调节 |
| 核心区别 | 码长与出现频率无关 | 频率越高码长越短 |
| 各自特点 | 无边界歧义但浪费空间 | 总长更短，但需前缀属性保证可解码 |
| 使用场景 | 通用字符集、硬件层 | 数据压缩、通信编码 |
| 典型示例 | DEAACAAAAABA 定长 3bit 共 36 位 | A=0,B=10,C=110… 共 22 位 |
| 记忆口诀 | 定长省心费位，变长省钱要前缀 |

### 组3：前缀码 vs 非前缀码

| 对比维度 | 前缀码 | 非前缀码 |
|----------|--------|---------|
| 各自定义 | 没有任何码字是其他码字的前缀 | 存在某码字是另一码字的前缀 |
| 核心区别 | 解码结果唯一 | 解码产生歧义 |
| 各自特点 | 可连续解码：到叶子即取字符再回根 | 需要分隔符或定长才可解码 |
| 使用场景 | 哈夫曼编码、通信压缩 | 不能用于实际编码 |
| 典型示例 | P=000,Q=11,R=01,S=001,T=10 → RSTQPT | P=0,Q=1,R=01,S=10,T=11：1110 有 5 种译法（QQQP/QQS/QTP/TQP/TS） |
| 记忆口诀 | 互不为前缀，连码不打架 |

### 组4：树的路径长度 vs 树的 WPL

| 对比维度 | 树的路径长度 | 树的带权路径长度（WPL） |
|----------|-------------|------------------------|
| 各自定义 | 所有叶子路径长度之和 | 所有叶子带权路径长度之和 |
| 核心区别 | 不乘权值 | 每项乘叶子的权值 |
| 各自特点 | 只反映结构 | 反映结构与权值分布的匹配度 |
| 使用场景 | 理论描述 | 判断二叉树性能、构造哈夫曼树的目标函数 |
| 典型示例 | 课件示例树 = 13 | 示例树（叶权2,2,2,2,2,4）= 32 |
| 记忆口诀 | WPL 越小树越优 |

### 组5：哈夫曼树 vs 普通二叉树

| 对比维度 | 哈夫曼树 | 普通二叉树 |
|----------|---------|-----------|
| 各自定义 | 同一组叶子权值下 WPL 最小的二叉树 | 任意的二叉树形 |
| 核心区别 | 大权叶子离根近、小权叶子离根远 | 无此保证 |
| 各自特点 | 无度为 1 的结点，共 2n−1 个结点 | 形态任意，可有度 1 结点 |
| 使用场景 | 压缩编码、最优判定树 | 一般数据组织 |
| 典型示例 | "this is his message" 编码树（根 19） | 同样权值随手搭的树 WPL 更大 |
| 记忆口诀 | 哈夫曼 = WPL 冠军树 |

## 📋 速查表

### 概念公式速查
```
结点路径长度   = 根到该结点的边数
结点带权路径长度 = 路径长度 × 权值
树的路径长度   = Σ(叶子路径长度)
WPL          = Σ(叶子路径长度 × 叶子权值)   ← 只算叶子！
哈夫曼树      = WPL 最小的二叉树（最优二叉树）
结点数        = n 叶子 → 2n − 1（无度1结点），合并 n−1 次
```

### 哈夫曼树构造三步
```
① 初始森林：n 棵单结点树
② 每轮：选根权值最小的两棵 → 合并（新根权值 = 两孩子之和）→ 放回森林
③ 重复 n−1 轮，森林剩一棵即哈夫曼树
示例 {7,5,2,4}：2+4→6；5+6→11；7+11→18
```

### 哈夫曼编码要点
```
特征：二叉树；叶子含字符；左0右1（约定）；根到叶路径 = 编码
性质：前缀码 —— 任一码字不是其他码字的前缀 → 解码唯一
解码：从根出发按 0/1 走，到叶子取字符，回根继续
示例：this is his message
  频率：a1 g1 m1 t1 e2 h2 空格3 i3 s5 → 根 19
```

### 代码模板（HuffmanTree.c）
```c
/* 结点：静态数组四域 */
typedef struct Node { int w, fa, l, r; } HuffmanNode;

/* 建树：n个叶子 → 合并n-1次 → 2n-1结点 */
for (i = n; i <= 2*n-2; i++) {
    Find(tree, i-1, &s1, &s2);          // 选 fa==-1 的最小两根
    tree[i].l = s1;  tree[i].r = s2;
    tree[i].w = tree[s1].w + tree[s2].w;
    tree[s1].fa = tree[s2].fa = i;      // 老根退赛
}
/* Find：两轮扫描，先找最小 s1，再在剩余根中找次小 s2 */
/* 编码：叶子沿 fa 回溯，start 从 n-1 倒着写 */
while (pre != -1) {
    t[--start] = (p == tree[pre].l) ? '1' : '0';
    p = pre;  pre = tree[p].fa;
}
```

### 易混数字对照
```
n 种字符编码 → 至少需 ⌈log2 n⌉ 位定长（5种 → 3位）
定长总位数 = 字符总数 × 每字符位数（12×3=36）
变长前缀编码示例：A出现8次 → A=0；B=10, C=110, D=1110, E=11110 → 22位
哈夫曼压缩率：依赖数据特性，20%～90% 不等
```
