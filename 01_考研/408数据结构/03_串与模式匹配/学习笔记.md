## 第五章：串与KMP

> 课件来源：`串及KMP匹配算法.pdf`、`KMP算法代码\KMP.c`
>
> 本章主线：从暴力匹配"主串指针 i 回溯"的痛点出发，引出 KMP"i 不回溯、j 看 next"——**next 数组是全章的核心资产**。

## 🗺️ 本章地图

本章解决一个问题：**在长主串里找短模式串，怎么才能不浪费已经比过的成果？** 先认识串及其存储（第 1 节），再看暴力匹配 BF 吃亏在哪一步——主串指针 i 回溯（第 2 节）；KMP 的解法是 i 永不回溯、失配时 j 按 next 表回退（第 3 节）。于是核心资产 next 数组登场：先学手工逐位计算（第 4 节），再学代码里怎么递推出来（第 5 节）。顺序即因果：**BF 的痛点 → next 的思想 → next 的手算 → next 的代码**。

## 📌 本章重点（3-5个）

⭐ **串的定义与串长管理**：'\0' 作结束标志求长要扫描 O(n)，额外存 length 变量才能常量时间求串长
⭐ **暴力匹配（BF）的缺点**：部分匹配后一旦失配，主串扫描指针 i 经常回溯，最坏时间复杂度 O(n×m)
⭐ **KMP 核心思想**：失配字符之前一定与模式串一致，利用该已知信息让 i 不回溯、只把 j 回退到 next[j]
⭐ **next 数组的手工计算**：前 j-1 个字符组成的串 S 的"最长相等前后缀长度 + 1"
⭐ **next 数组的递推实现**：`j==0 || 相等` 则 `next[i]=j` 双移，否则 `j=next[j]`

## 🔥 本章难点（2-3个）

🔥 **next 数组手工计算**：逐位找"最长相等前后缀"再 +1，位数容易数错，且要牢记"每次最多增加 1"
🔥 **getNext 递推逻辑**：为什么不等时令 `j=next[j]` 就能继续比较——本质是用已求出的 next 做"模式串对模式串"的自我匹配回退
🔥 **两版下标体系的差异**：课件版串从下标 1 存储（next[1]=0），KMP.c 从下标 0 存储（next[0]=-1, next[1]=0），思想一致但细节错位

## ⚠️ 本章易错点（3-5个）

⚠️ **串赋值直接用 =**：与普通变量赋值不同，串的赋值不能用 = 实现，必须写 strAssign 初始化函数做空间拷贝
⚠️ **前缀后缀搞反**：前缀含第一个字符不含最后一个；后缀含最后一个字符不含第一个
⚠️ **next[j] 忘了 +1**：next[j] = S 最长相等前后缀的**长度 + 1**，不是长度本身
⚠️ **忽略"模式串最后一位不影响 next"**：求 next 数组只用到前 m-1 个字符，最后一位只参与匹配
⚠️ **两版 next 混用**：`next[1]=0`（1 起始）与 `next[0]=-1`（0 起始）体系不同，混着背整体错一位

## 📖 知识点讲解

### 1. 串的定义与两种存储结构

**是什么**：先说白话——串就是"一串字符"的数据结构化说法：字符排成一队，和线性表同宗，只是元素限定为字符，因此求长度、赋值这些操作也有了串特有的讲究。严格定义：串是由零个或多个字符组成的有限序列，字符个数称为串的长度，含零个元素的串叫空串。C 语言中 `char str[] = "abcdef";` 即定义了一个串。课件给出两种存储表示：①定长顺序存储——事先开好一块固定大小的数组，`char str[maxSize+1]` + `int length`；②变长分配存储——运行时按需 malloc 空间，`char *str`（动态分配空间）+ `int length`。

**为什么**：C 语言用 '\0' 作字符串结束标志，但靠扫描整个串求长度是 O(n)；额外定义一个变量专门存储串长后，求串长只需常量时间。不同语言是否用 '\0' 作结束标志没有定论，用 length 约束长度的写法更通用。

**怎么用**（跟着算一遍两种求串长的差别，以 "abc" 为例）：
```
靠 '\0' 扫描（隐式约定，结尾藏一个哨兵字符）：
存储：[a][b][c][\0]
第1步 读 a，计数 1 → 第2步 读 b，计数 2 → 第3步 读 c，计数 3
第4步 读到 '\0' 才停 → 共访问 4 次，O(n)
靠 length 变量（显式存储）：str->length 直接返回 3，一步到位，O(1)
```
```c
typedef struct {
    char str[maxSize + 1]; // 从0号索引存储数据，+1是为了存储\0（可选）
    int length;
} StrType;                 // 定长顺序存储

typedef struct {
    char *str;             // 动态分配空间
    int length;
} StrType2;                // 变长分配存储（堆分配）
```

> ⚠️ 注意事项：与普通变量赋值不同，串的赋值操作不能直接用 = 实现，要通过初始化函数实现空间拷贝：`int strAssign(StrType *str, const char *ch);`

> 🎯 规律：隐式约定靠现场扫描，显式存储靠直接读取——能预先存下来的信息，别让算法再算一遍。

> 💡 一句话总结：串是字符有限序列，length 存长更通用。

### 2. 模式匹配与暴力匹配（Brute-Force）

**是什么**：先说白话——模式匹配就是"拿着短串当模板，在长串上一个位置一个位置平移比对"，笨办法但直观：失配就把模板往右挪一格、从头再比。严格定义：字符串模式匹配 = 在主串中找到与模式串相同的子串，并返回其所在位置。暴力匹配又称朴素模式匹配，思想：以字符为单位从左到右移动模式串；首字符匹配成功则继续往后比，失配则模式串从主串的下一个字符重新对齐匹配（对齐起点 = 模式串第 1 个字符对准主串的第几个字符），直到匹配成功或扫完整个文本串。

**为什么**：朴素匹配的缺点——当某些子串与模式串部分匹配后一旦失配，主串的扫描指针 i 经常回溯（回到本次起点 +1 重新出发），前面的比较成果全部作废，时间开销增大，最坏时间复杂度 **O(n×m)**。

**怎么用**（先跟着算一遍，再看代码）：

跟着算：主串 p = "aababc"，模式串 s = "abc"（0 下标）：
第1步 对齐起点 k=0：p[0]='a' 对上 s[0]='a'；p[1]='a' 对不上 s[1]='b' → 失配，i 退回 k+1=1
第2步 对齐起点 k=1：'a''b' 连对两个；p[3]='a' 对不上 s[2]='c' → 失配，i 退回 2
第3步 对齐起点 k=2：首位 p[2]='b' 就对不上 'a' → 失配，i 退回 3
第4步 对齐起点 k=3：'a''b''c' 全部对上 → 成功，返回起始下标 3
主串指针 i 的轨迹 0→1→2→3：每一步失配都"连本带利"从头再来——这就是 BF 的浪费。
```
第1步 对齐 k=0：
   p:  a a b a b c
   s:  a b c
         ↑ p[1]='a' ≠ s[1]='b' 失配 → i 退回 k+1=1（前面成果作废）
```

KMP.c 注释里的 0 下标 BF 版本：
```c
// 暴力匹配：O(n*m)，主串p、模式串s，0下标存储
for (int k = 0; k <= pl - sl; k++) {  // k为模式串在主串中的对齐起点
    i = k;  j = 0;                    // p[k]和s[0]对齐
    while (j < sl) {
        if (p[i] == s[j]) { i++; j++; }
        else break;                   // 失配：i退回，换下一个k
    }
    if (j == sl) { /* 成功：位置k */ }
}
```

> ⚠️ 注意事项：失配后 i 必须回到 k+1（主串指针回溯），这正是 KMP 要消除的开销来源。

> 🎯 规律：BF 的浪费模式是"部分匹配越长，失配时作废越多"——模式串自重复度越高，它越慢。

> 💡 一句话总结：朴素匹配简单可靠，失配 i 回溯太慢。

### 3. KMP 算法思想：跳过不可能成功的比较

**是什么**：先说白话——KMP 的算盘是：失配位置之前的字符刚刚全都比过、内容一清二楚，凭什么让主串回头重比？不用——模式串按"剧本"（next 表）退一位接着比就行。严格定义：KMP 由 D.E.Knuth、J.H.Morris、V.R.Pratt 三人提出。核心思想：**不匹配的字符之前，一定是和模式串一致的**——利用这个已知信息，确定模式失配时下次从模式串的第几个位置开始匹配。实现上引入 **next 数组**，专门存放"失配时模式串要回退到的位置"。

**为什么**：设模式串 "abcabd"、主串 "abcabxxxx"，从 s[1] 开始匹配在 p[6] 处失配。既然 p[6] 失配，说明 s[1:5] 一定是 p[1:5]；按朴素算法从 s[2]、s[3] 出发可以明确肯定不会成功（p[1]='a' 对不上），而**从 s[4] 开始才有可能成功**——所以 i 不动，直接把 j 调小即可。next 数组里的值只跟模式串有关：模式串前面已成功匹配的字符，就代表子串中已包含这些字符。

**怎么用**（跟着把上面的例子走成图）：

```
失配瞬间（i 停在主串第 6 位 'x'，j 停在模式串第 6 位 'd'）：
s:  a b c a b x x x x
p:  a b c a b d
              ↑ 此处失配

BF 的做法：起点挪到 s[2]、s[3]……逐个重比（明知 p[1]='a' 对不上 s[2]='b'）
KMP 的做法：p[1..5]="abcab" 的头部 "ab" 与尾部 "ab" 相等，
已匹配段的尾部可以直接充当模式串的头部 → i 不动，j 退到 next[6]=3：

s:  a b c a b x x x x
p:        a b c a b d
              ↑ p[3] 与主串第 6 位接着比
```
模式串"滑"到哪个新位置，完全由它自己的最长相等前后缀决定——这就是 next 表的全部内容。

（KMP.c，0 下标版本，总时间复杂度 O(n+m)）：
```c
// KMP匹配：O(n+m)，i是主串指针，j是模式串指针
int i = 0, j = 0;
while (i < pl && j < sl) {
    if (j == -1 || p[i] == s[j]) {   // j==-1：模式串首字符就失配
        i++;  j++;                   // 匹配上：双指针后移
    } else {
        j = next[j];                 // 失配：j回退，i保持不动
    }
}
if (j == sl) printf("%d\n", i - j);  // 返回匹配起始下标
else printf("-1\n");
```

| 算法 | 主串指针 i | 最坏时间复杂度 |
|------|-----------|---------------|
| 暴力匹配 BF | 失配后回溯到起点+1 | O(n×m) |
| KMP | **永不回溯** | O(n+m) |

> ⚠️ 注意事项：`j == -1` 的含义是模式串第一个字符就失配，此时 i++、j 归 0，从主串下一个字符重新开始。

> 🎯 规律：失配前的每一次比较都不会白费——模式串最了解自己，next 就是它提前写好的"自我介绍"。

> 💡 一句话总结：主串 i 不回溯，失配 j 看 next。

### 4. next 数组的手工计算

**是什么**：先说白话——next[j] 回答的问题是："若第 j 位失配，模式串往后退到第几位接着比？"答案藏在模式串自己身上：它头部与尾部有没有长得一样的段。严格定义：
- 串的**前缀**：包含第一个字符、且不包含最后一个字符的子串
- 串的**后缀**：包含最后一个字符、且不包含第一个字符的子串
- 当第 j 个字符匹配失败时，把前 [1, j-1] 个字符组成的串记为 S，**next[j] = S 最长相等前后缀的长度 + 1**

三条规律：① next[j] 的值每次最多增加 1；② 模式串的最后一位字符不影响 next 数组的结果；③ next 数组的定义 = 当主串与模式串某一位字符不匹配时，模式串要回退到的位置。

**为什么**：S 的最长相等前后缀意味着失配处之前，模式串头部与尾部已有一段"自我重合"的信息；回退到"前缀长度 + 1"的位置接着比，既不会漏掉解，也不会做多余的比较。

**怎么用**（以模式串 "abcabd" 为例，下标从 1 开始）：

| j | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| p[j] | a | b | c | a | b | d |
| next[j] | 0 | 1 | 1 | 1 | 2 | 3 |

跟着算（逐步验证三个关键位）：
第1步 j=1：规定 next[1]=0（退无可退的信号）
第2步 j=2：S="a"，长度 1 的串没有非空真前后缀 → 相等长度 0 → next[2]=0+1=1
第3步 j=4：S="bca"，前缀 {b, bc}，后缀 {a, ca}，无相等 → next[4]=0+1=1
第4步 j=5：S="abca"，最长相等前后缀 "a" 长度 1 → next[5]=1+1=2
第5步 j=6：S="abcab"，最长相等前后缀 "ab" 长度 2 → next[6]=2+1=3

j=6 时 S="abcab" 的前后缀对照（前缀带头不带尾，后缀带尾不带头）：
```
前缀： a    ab    abc    abca
后缀： b    ab    cab    bcab
最长相等前后缀 = "ab"，长 2 → next[6] = 2 + 1 = 3

     [a b] c [a b]
      └── 相等 ──┘
```

再拿 "abab" 完整独立算一遍（检验你是否真会了）：
第1步 j=1：next[1]=0
第2步 j=2：S="a"，无非空真前后缀 → next[2]=1
第3步 j=3：S="ab"，前缀 {a}、后缀 {b}，无相等 → next[3]=1
第4步 j=4：S="aba"，前缀 {a, ab}、后缀 {a, ba}，最长相等 "a" 长 1 → next[4]=2
（各位可自验：从 next[4]=2 起，每次至多 +1，符合规律①）

> ⚠️ 注意事项：求 next[j] 只看前 j-1 个字符；算出的是"长度"还要 +1 才是 next 值；next[1] 恒为 0（1 起始体系）。

> 🎯 规律：next 的本质是"模式串自己匹配自己"——在自己身上找"头部能接上尾部"的那段重合，找到了就填"长度 + 1"。

> 💡 一句话总结：找最长相等前后缀，长度加一。

### 5. next 数组的代码实现（递推法）

**是什么**：先说白话——手算每一位都要重新找最长相等前后缀，太慢；代码的聪明之处是递推（用已经算好的前几位结果推出下一位）：算到第 i 位时，next[i] 的答案几乎全在 next[i-1] 里，像多米诺一张推一张。严格说：课件版（串从下标 1 存储）：`i=1, j=0`，`next[1]=0`；循环中若 `j==0 || str[i]==str[j]` 则 `++i; ++j; next[i]=j;`，否则 `j=next[j]`。KMP.c 版（0 下标）：`next[0]=-1, next[1]=0`，用 x 记录 next[j-1]，若 `x==-1 || s[x]==s[j-1]` 则 `next[j]=x+1` 并双移，否则 `x=next[x]`。

**为什么**（递推逻辑，课件以 next[17] 为例）：算 next[17] 时 next[16] 已知，设 next[16]=8（即有 7 对相等前后缀）——若 `p[8]==p[16]`，相等前后缀延长一对，next[17]=8+1；若不等，设 p[8]=4，由已知相等关系可推出 p[5:7]==p[13:15]，于是转为考察 p[4]——若 `p[16]==p[4]` 则 next[17]=3+1；若还不等（设 p[4]=2），考察 p[2]——若 `p[16]==p[2]` 则 next[17]=2+1；否则退到 next[2]=1→next[1]=0，遇到 0 递推结束，next[17]=1。**`j=next[j]` 就是用已求好的 next 做"模式串对模式串"的快速回退**，避免从头重比。

**怎么用**（跟着把递推在 "abcabd" 上跑一遍，正好和第 4 节的手算表对答案）：

模式串 "abcabd"（下标 1 起始），初始 next[1]=0、i=1、j=0：
第1步 j==0（退无可退）→ i=2, j=1，next[2]=1
第2步 str[2]='b' ≠ str[1]='a' → j=next[1]=0
第3步 j==0 → i=3, j=1，next[3]=1
第4步 str[3]='c' ≠ str[1]='a' → j=next[1]=0
第5步 j==0 → i=4, j=1，next[4]=1
第6步 str[4]='a' == str[1]='a'（相等双移）→ i=5, j=2，next[5]=2
第7步 str[5]='b' == str[2]='b' → i=6, j=3，next[6]=3
循环结束（i=6 不再小于 6）→ next = 0 1 1 1 2 3，与手算完全一致。
注意第 2、4 步：不等时 j 跳回 next[1]=0，等于"模式串对模式串"匹配失败后回退。

```c
// 课件版：串从数组下标1位置开始存储
void getNext(StrType *subStr, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;
    while (i < subStr->length) {
        if (j == 0 || subStr->str[i] == subStr->str[j]) {
            ++i;
            ++j;
            next[i] = j;
        } else {
            j = next[j];
        }
    }
}
```

> ⚠️ 注意事项：课件版的 `j==0` 与 KMP.c 版的 `x==-1` 都是"退无可退、从头再比"的信号；求 next 的 while 条件是 `i < subStr->length`，最后一位字符不参与求 next。

> 🎯 规律：递推 = 用已知推未知——next[i] 只需 next[i-1] 加一次字符比较，不等就顺着 next 链往回跳，直到相等或退无可退。

> 💡 一句话总结：相等双移续前缘，不等 j 跳 next。

### 🧩 本章归纳：一条主线串全章

全章主线是一条因果链：**BF 的浪费（i 回溯）→ 发现"失配前主串与模式串完全一致"这条已知信息 → 把模式串的"自我重合"预计算成 next 表 → 匹配时 i 只前进、j 按表回退 → O(n+m)**。

| 关键概念 | 在主线中的角色 |
|----------|----------------|
| 前缀 / 后缀 | 定义"自我重合"的语言 |
| next[j] | 第 j 位失配时 j 的"安全落点" |
| 递推 getNext | 用旧 next 算新 next，免去每次从头找前后缀 |

回头看才看得见的三条联系：
1. **next 就是"模式串自己匹配自己"**：手算时找最长相等前后缀、递推时 `j=next[j]`，是同一件事的两种写法——让模式串的头部接在自己尾部的重合段上。
2. **"空间换时间"思想的第一次亮相**：花 O(m) 预处理 next 表，换来匹配阶段 O(n+m)；和顺序表"下标直取"同源——预先把答案存起来，用到时直接取。
3. **下标体系只是外壳**：1 起始（next[1]=0）与 0 起始（next[0]=-1）数值错一位，但"退无可退的信号 + 相等双移 + 不等跳 next"的三段式逻辑完全一致——背逻辑，别背数值。

## 🔍 相似概念辨析

### 组1：主串 vs 模式串

| 对比维度 | 主串（文本串） | 模式串 |
|----------|---------------|--------|
| 各自定义 | 被查找的原始串 | 要在主串中寻找的子串模板 |
| 核心区别 | 长度 n，是搜索范围 | 长度 m，是搜索目标（m ≤ n） |
| 各自特点 | 只有 i 一个扫描指针，KMP 中不回溯 | j 指针失配时按 next[j] 回退 |
| 使用场景 | 全文检索中的正文 | 关键字查找、病毒特征码匹配 |
| 典型示例 | "abcabxxxx" | "abcabd" |
| 记忆口诀 | 主串是被搜的，模式串是模板 |

### 组2：暴力匹配 BF vs KMP

| 对比维度 | 暴力匹配（Brute-Force） | KMP |
|----------|------------------------|-----|
| 各自定义 | 从左到右逐起点对齐的朴素模式匹配 | 利用 next 数组跳过无效比较的匹配算法 |
| 核心区别 | 失配后主串指针 i 回溯 | **i 永不回溯**，只回退 j |
| 各自特点 | 思想直观、代码简单 | 需预处理 next，匹配 O(n+m) |
| 使用场景 | 短串、一次性匹配 | 长文本、模式串有重复前后缀时收益大 |
| 典型示例 | 最坏 O(n×m)（如 "aaaaab" 找 "aaab"） | O(n+m)，next 只与模式串有关 |
| 记忆口诀 | BF 蛮力i回头，KMP 用表i不愁 |

### 组3：前缀 vs 后缀

| 对比维度 | 前缀 | 后缀 |
|----------|------|------|
| 各自定义 | 包含第一个字符、不含最后一个字符的子串 | 包含最后一个字符、不含第一个字符的子串 |
| 核心区别 | 锚定串头 | 锚定串尾 |
| 各自特点 | 从左往右取 | 从右往左取 |
| 使用场景 | 求 next 时与"尾部对齐"比较 | 求 next 时与"头部对齐"比较 |
| 典型示例 | "abcab" 的前缀：a, ab, abc, abca | "abcab" 的后缀：b, ab, cab, bcab |
| 记忆口诀 | 前缀带头不带尾，后缀带尾不带头 |

### 组4：定长顺序存储 vs 变长分配存储

| 对比维度 | 定长顺序存储 | 变长分配存储 |
|----------|-------------|-------------|
| 各自定义 | 预分配定长数组的串存储 | char* 指针动态分配空间的串存储 |
| 核心区别 | 空间编译期定死 maxSize+1 | 空间运行时按需 malloc |
| 各自特点 | `char str[maxSize+1]; int length;` | `char *str; int length;` |
| 使用场景 | 长度可预估、 maxlen 已知 | 长度未知或需动态增长 |
| 典型示例 | `char str[256]; str[255]` 有上限 | `strAssign` 内部按 ch 长度分配 |
| 记忆口诀 | 定长死板够用，变长灵活要释放 |

### 组5：'\0' 结束标志 vs length 变量

| 对比维度 | '\0' 结束标志 | length 变量 |
|----------|--------------|-------------|
| 各自定义 | C 语言约定的串结尾哨兵字符 | 结构体中显式记录串长的整型成员 |
| 核心区别 | 隐式约定，靠扫描感知结尾 | 显式存储，直接读取 |
| 各自特点 | 求串长需遍历 O(n) | 求串长常量时间 |
| 使用场景 | C 标准字符串函数体系 | 数据结构课件推荐的通用做法 |
| 典型示例 | `strlen(str)` 扫描到 '\0' | `str->length` 直接得长度 |
| 记忆口诀 | \0 靠扫描，length 一步到 |

## 📋 速查表

### 复杂度速查
```
求串长（有length）：O(1)      求串长（扫'\0'）：O(n)
BF 暴力匹配：      O(n×m)    最坏：模式串前缀高度自重复
求 next 数组：     O(m)
KMP 匹配：         O(n+m)
```

### next 数组手算四步（1起始体系）
```
① next[1] = 0
② 对每个 j≥2：取前 j-1 个字符 S
③ 求 S 的最长相等前后缀长度 k
④ next[j] = k + 1
规律：next 逐位最多+1；模式串最后一位不参与求 next
```

### next 计算模板（课件版，1起始）
```c
void getNext(StrType *subStr, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;
    while (i < subStr->length) {
        if (j == 0 || subStr->str[i] == subStr->str[j]) {
            ++i; ++j; next[i] = j;
        } else j = next[j];
    }
}
```

### next 计算模板（KMP.c，0起始）
```c
next[0] = -1; next[1] = 0;
int x = 0, j = 2;          // x 即 next[j-1]
while (j < sl) {
    if (x == -1 || s[x] == s[j-1]) { next[j] = x + 1; x++; j++; }
    else x = next[x];
}
```

### KMP 匹配模板（0起始）
```c
int i = 0, j = 0;
while (i < pl && j < sl) {
    if (j == -1 || p[i] == s[j]) { i++; j++; }
    else j = next[j];
}
// j==sl：匹配成功，起始下标 i-j；否则 -1
```

### 串的结构与初始化
```c
typedef struct { char str[maxSize+1]; int length; } StrType;
int strAssign(StrType *str, const char *ch);  // 串赋值不能用=，用函数拷贝
```

### 两版 next 对照
| | 课件版（1起始） | KMP.c 版（0起始） |
|---|---|---|
| 串存储起点 | 下标 1 | 下标 0 |
| 初始值 | next[1]=0 | next[0]=-1, next[1]=0 |
| 退无可退 | j==0 | x==-1（匹配时 j==-1） |
| 回退语句 | j=next[j] | j=next[j] / x=next[x] |
