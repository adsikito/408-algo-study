## 第四章：栈与队列

> 课件来源：`栈、队列.pdf`；配套代码：`顺序栈代码.c`、`链栈代码.c`、`循环队列代码.c`、`链式队列代码.c`、`顺序双端队列代码.c`、`链式双端队列代码.c`
>
> 栈与队列都是**操作受限的线性表**：栈**后进先出（LIFO）**、队列**先进先出（FIFO）**，它们是函数调用、任务调度、缓存淘汰等系统机制的底层模型。

## 🗺️ 本章地图

本章给线性表"加限制"：只许在一端进出就是栈，一端进一端出就是队列。先从 CPU 里的物理堆栈认识"后进先出"的原型（第 1~2 节），再用顺序、链式两种存储把栈落地（第 3 节）；队列走同一条路——定义（第 4 节）暴露出顺序队列的"假溢出"缺陷，于是催生循环队列与链式队列（第 5~6 节），最后把限制放松到两端得到双端队列（第 7 节），并看它的三个工程变种（第 8 节）。顺序即"先受限、再回绕、后放开、上工程"：**循环队列的取模三大公式是全章枢纽**。

## 📌 本章重点（3-5个）

⭐ **物理中堆栈的本质**：栈的本质是内存中的一个区域，特殊之处在于 CPU 存取数据的方式——**先入后出、后入先出**（像弹夹装子弹）；函数调用的地址取用就用到了堆栈
⭐ **栈顶/栈底与压栈弹栈**：栈顶（可以变化）、栈底（固定不动）；栈顶栈底重合即空栈；入栈 top 上挪、出栈 top 下挪——**出栈后数据还在，只是被当成垃圾**
⭐ **队列的定义与应用**：前端删除、后端插入，队尾入队、队头出队，先进先出线性表；应用：解决主机与外部设备速度不匹配、多用户资源竞争
⭐ **循环队列三大公式**：判空 `rear==front`、判满 `(rear+1)%maxSize==front`（牺牲一个空间）、元素个数 `(rear-front+maxSize)%maxSize`；假溢出问题
⭐ **双端队列及其退化**：两端都可进出；限一端进出→栈，一端只进另一端只出→普通队列；LRU/LFU、延迟队列、阻塞队列三大应用

## 🔥 本章难点（2-3个）

🔥 **循环队列为什么牺牲一个空间**：不牺牲时队空、队满都是 `rear==front` 无法区分；牺牲一格后判满变成 `(rear+1)%maxSize==front`
🔥 **取模运算实现"循环"**：前进用 `(x+1)%maxx`，后退必须 `(x-1+maxx)%maxx`（先加 maxx 再取模），否则下标变负
🔥 **链队列出队的队尾指针维护**：删到最后一个结点时必须 `r=f`（尾指针退回头结点），否则 r 悬空成野指针，再入队就写崩

## ⚠️ 本章易错点（3-5个）

⚠️ **数据结构中的栈 ≠ 内存中的栈区**：前者是模仿堆栈特点的**抽象数据类型**（一系列动作），后者是内存里一块真实区域；堆和栈的特性也很不一样
⚠️ **以为出栈=数据被删掉**：出栈只是栈顶下移，数据还在堆栈中，只是这个数据被当成了垃圾
⚠️ **队头队尾方向记反**：入队是**队尾指示器 +1**（`rear=(rear+1)%maxSize`），出队是**队头指示器 +1**（`front=(front+1)%maxSize`）
⚠️ **top 的含义混用**：top 本质是**下标**不是真指针；顺序栈代码 top 初始化为 0 时，**top-1 才是真正的栈顶数据**，`top==0` 空、`top==maxx` 满
⚠️ **假溢出当真满**：rear 指向 size-1 时看似已满，但出队腾出的前部空间还空着——普通顺序队列误报"队满"，必须用循环队列（取模回绕）解决

## 📖 知识点讲解

### 1. 物理中的堆栈：从 CPU 说起

**是什么**：先说白话——想想弹夹：后压进去的子弹压住先前的，打出去的永远是最上面那颗；CPU 在内存里划出的"堆栈"就是这样一块只从顶端存取的工作台。故事从头讲：CPU 中有一个核心模块 **ALU（算术逻辑单元）**，执行各种计算和逻辑运算，是 CPU 的执行单元。多个运算参与时（如 111+222+333，先算 111+222），临时结果需要地方存——**寄存器**（AX、BX、CX、DX 等，CPU 内部速度最快但数量极少的临时存储格子）。但寄存器不能做特别多（会增加 CPU 设计上的成本和复杂性），于是需要从外面找帮手，计算机设计者把目光放在了内存条上：**在内存中划出一块专门的区域临时存储数据，这块区域叫堆栈（"栈"只是乳名）**。注意内存里还有一个区域叫**堆**，和栈的特性很不一样。

**为什么**：栈的本质就是内存中的一个区域，它的特殊之处在于 **CPU 从中存取数据的方式——先入后出、后入先出，就像弹夹装子弹**。CPU 中很多对数据的操作都遵循这个规律；**函数调用的地址取用就用到了堆栈**（程序以机器码形式躺在内存中，CPU 逐句取址执行）。

**怎么用**：
```
栈顶（可以变化） ↘
                   ▓ ▓ ▓   ← 堆栈区域
栈底（固定不动） ↗
```
- 栈顶和栈底**重合** → 栈里没有数据（空栈）
- 存数据：栈顶指针往上挪，数据存放在栈顶位置 → **压栈/入栈**
- 取数据：先将数据保存到寄存器，然后栈顶往下挪 → **弹栈/出栈**

跟着算一遍 111+222+333 里临时结果的存取：
第1步 算 111+222=333，把 333 压栈暂存：栈顶 → [333]
第2步 需要它时弹栈取出，与 333 相加：栈顶 → [   ]（位置还在，333 已被当成垃圾）
第3步 得到最终结果 666——"先算的暂存、后算的先用"，正是先入后出。

> ⚠️ 注意事项：出栈了以后，**数据还在堆栈中**，只是这个数据被当成了垃圾。

> 🎯 规律：凡是"先处理最近那个"的场景（函数调用、撤销操作、括号匹配），底层都是栈。

> 💡 一句话总结：栈是内存区域，CPU先入后出。

### 2. 数据结构中的栈：LIFO 的抽象数据类型

**是什么**：先说白话——数据结构中的栈是把物理堆栈的"脾气"（只许动顶端）单独抽出来做成的操作集，不再关心内存里哪块区域。严格说，数据结构中的栈跟物理中的栈**不一样**——它是模仿栈结构的特点而做出的**一系列动作**，即栈结构的一个**抽象数据类型**。只允许在一端（栈顶）插入和删除，**先进后出/后进先出**（LIFO，Last In First Out——最后放进的最先取出）。和线性表一样，可以用**顺序存储结构**或**链式存储结构**两种方式实现栈的操作。

**为什么**：现实与系统中"最后放的先取"的场景（函数调用链、临时结果的保存）天然是这种规律；限制只动一端，换来操作简单且开销恒定。

**怎么用**（两种存储形态，课件图示）：
```
顺序存储（数组+top下标）           链式存储（单链表，栈顶在表头）
 6 |  |  ← top=6  栈满             top → [an|●]  ← 栈顶
 1 | 2 | ← top=1  栈有两个元素           [an-1|●]
 0 | 1 |                                [an-2|●]
   top=-1  空栈                          ⋮  → [a1|^] ← 栈底
```

跟着算一遍"只动栈顶"的过程：依次入栈 A、B、C，再出栈两次：
```
入A       入B       入C       出栈      出栈
top→ A    top→ B    top→ C    top→ B    top→ A
           A         B         A
                     A
出栈顺序：C、B——最后进栈的最先出栈（LIFO）
```

> ⚠️ 注意事项：链式实现时**首元结点是栈顶、尾结点是栈底**；顺序实现时 top 是下标、会移动，栈底固定不动。

> 🎯 规律：把线性表的插删限制到一端，行为就完全确定——只看这一端就知道进出顺序。

> 💡 一句话总结：受限线性表，只动栈顶一端。

### 3. 顺序栈与链栈的实现

**是什么**：先说白话——顺序栈是"数组 + 一个会移动的记号 top"，top 像便利贴标着"下一只盘子放哪"；链栈干脆就是上一章的头插法单链表，表头即栈顶。严格定义：
- **顺序栈**：数组 + 栈顶下标 top。配套代码约定 top 初始化为 0，**top-1 才是真正的栈顶数据**；入栈先存后 `top++`，出栈先 `top--`
- **链栈**：基于**带头结点的单链表**实现，栈顶指针就是头指针，**首元结点是栈顶、尾结点是栈底**；入栈=头插法，出栈=删除首元结点

**为什么**：顺序栈结构简单、省空间但容量固定（要判满）；链栈容量随内存动态伸缩、天然无"满"的问题，但每个结点多付一个指针域且仍要判空。

**怎么用**：

跟着算顺序栈（maxx=4，top 表示下一个可放的下标）：
```
操作       数组内容           top   说明
初始       [ ][ ][ ][ ]       0     top==0 即空栈
Push 5     [5][ ][ ][ ]       1     先存 data[0]=5，再 top++
Push 8     [5][8][ ][ ]       2
Pop        [5][8][ ][ ]       1     只做 top--，8 还在数组里（垃圾）
Push 2     [5][2][ ][ ]       2     data[1] 被 2 覆盖
取栈顶     Get 返回 data[top-1]=data[1]=2
```
注意第 4 行：Pop 之后 8 仍躺在数组里——"出栈只是栈顶下移"的直接证据。

```c
/* 顺序栈 */
typedef struct { int *data; int top; } Stack;   // top本质是下标
void Push(Stack *s, int k) {                    // 入栈
    if (s->top == maxx) { printf("栈满，无法入栈\n"); return; }  // 判满
    s->data[s->top] = k;  s->top++;             // 先存后挪
}
int IsEmpety(Stack *s) { return s->top == 0; }  // 判空
void Pop(Stack *s) {                            // 出栈
    if (IsEmpety(s)) { printf("栈空，无法出栈\n"); return; }
    s->top--;                                   // 下移即出栈
}
int Get(Stack s) { return s.data[s.top - 1]; }  // 取栈顶：top-1

/* 链栈 */
LinkStack Push(LinkStack s, int k) {            // 入栈=头插
    SNode *p = (SNode*)malloc(sizeof(SNode));
    p->data = k;  p->next = s->next;  s->next = p;
    return s;
}
LinkStack Pop(LinkStack s) {                    // 出栈=删首元结点
    if (IsEmpety(s)) { printf("栈空，无法出栈\n"); return s; }
    SNode *p = s->next;  s->next = p->next;
    free(p);  p = NULL;
    return s;
}
```
链栈入栈的指针变化（before/after）：
```
before：  s(头) → [6|●] → [3|^]        ← 6 是栈顶（首元结点）
操作：    p->next = s->next;  s->next = p
after：   s(头) → [9|●] → [6|●] → [3|^]   ← 9 成为新栈顶
```

> ⚠️ 注意事项：顺序栈 Push 前判满、Pop 前判空；链栈没有满的问题但仍要判空；free 后置 NULL 防野指针。

> 🎯 规律：顺序栈盯着 top 下标走（存取都在 top-1），链栈直接套用"头插 + 头删"旧模板。

> 💡 一句话总结：入栈出栈均O(1)，判满判空别忘掉。

### 4. 队列：定义与应用场景

**是什么**：先说白话——排队买票：新来的排到队尾，队头的人先走，插队无效；队列就是把这条社会规则写死的数据结构。严格定义：队列是一种**特殊的线性表**，特殊之处在于只允许在**表的前端进行删除操作**、在**表的后端进行插入操作**。和栈一样，队列也是**操作受到限制的线性表**。进行插入操作的端称为**队尾**，进行删除操作的端称为**队头**；队列中没有元素时称为**空队列**；队列的数据元素又叫**队列元素**。在队列中插入一个队列元素称为**入队**，删除一个队列元素称为**出队**。因为只允许在一端插入、另一端删除，只有**最早进入**的队列元素才可以被删除，故队列又称**先进先出线性表（FIFO，First In First Out——先来的先走）**。

**为什么**：排队模型——先来的先服务。课件给出的两大应用：① **解决主机与外部设备速度不匹配**问题；② **多用户引起的资源竞争**问题。

**怎么用**：
```
出队 ←  [队头 front] a0 a1 a2 ... an [队尾 rear]  ← 入队
        删除端（前端）              插入端（后端）
```
跟着算一遍：a0、a1、a2 依次入队，再出队一次：
```
初始    front → [  ][  ][  ]  ← rear
入 a0   front → [a0][  ][  ]  ← rear
入 a1   front → [a0][a1][  ]  ← rear
入 a2   front → [a0][a1][a2] ← rear
出队    front → [  ][a1][a2] ← rear    （a0 离开——最先进来的先走）
```

> ⚠️ 注意事项：队头管出、队尾管进，两端各司其职——这是它与栈（单端操作）最本质的区别。

> 🎯 规律：一端进一端出天然保序——凡是"先来的先服务"的场景都套队列。

> 💡 一句话总结：队尾进队头出，先进先出。

### 5. 顺序队列、假溢出与循环队列（重中之重）

**是什么**：先说白话——数组是"直"的，队列元素不断向前走，前门边的空位永远用不上；循环队列把数组首尾掰弯接成一个环，让 rear 绕圈跑，空位就能循环复用。严格定义：
- **顺序队列**：用一片**连续的存储空间**（一维数组）存放队列数据元素，类似顺序栈。**队头设置在最近一个离开队列元素所占的位置，队尾设置在最近一个进入队列的元素位置**；队头队尾随插入删除而变化；**队列为空时 front == rear**
- **假溢出**：当队尾指针指向 size-1 时代表长度已满，但按队列的规则实际情况是**还有空闲的空间**（出队腾出来的前部用不上）——这就是假溢出
- **循环顺序队列**：解决假溢出——把顺序队列看成**首尾相接的循环结构**（首尾指示器不变）。队尾到达数组上限且第 0 个空间空闲时，队尾指示器指向数组 0 端

**为什么**：数组是"直"的，元素不断后移会先耗尽末端；取模（% 求余数运算）让下标回到 0 端，等于把数组掰弯成环：
```c
rear  = (rear  + 1) % maxSize;   // 队尾指示器 +1 的操作
front = (front + 1) % maxSize;   // 队头指示器 +1 的操作
```

**怎么用（三大公式，必背）**：
| 状态 | 条件 | 说明 |
|------|------|------|
| 队空 | `rear == front` | 判空条件 |
| 队满 | `(rear + 1) % maxSize == front` | **少使用一个空间**来区分空和满 |
| 元素个数 | `(rear - front + maxSize) % maxSize` | +maxSize 防止出现负数 |

跟着算一遍"走到回绕"（maxSize=5，f 队头 r 队尾，从空队出发）：
第1步 初始：f=0, r=0，判空 f==r → 空队
第2步 入 a0：data[0]=a0，r=(0+1)%5=1
第3步 入 a1：data[1]=a1，r=2
第4步 入 a2：data[2]=a2，r=3，个数 (3-0+5)%5=3
第5步 出队 a0：f=(0+1)%5=1，0 号位腾出来了
第6步 入 a3：data[3]=a3，r=4
第7步 入 a4：data[4]=a4，r=(4+1)%5=0 ← **回绕！rear 从 4 号"跳"回 0 号**

```
此时 f=1，r=0，个数 (0-1+5)%5=4 —— maxSize=5 最多只装 4 个（牺牲了一格）：
下标    0     1     2     3     4
      [   ] [a1]  [a2]  [a3]  [a4]
       ↑r=0  ↑f=1
再入队？判满 (r+1)%maxx==f → (0+1)%5=1==f → 队满，a5 进不来
（若先出队一次让 f 走到 2，0 号位空出，a5 才能从 r=0 入队）
```

取模 = 把直数组掰成环：
```
        ┌────────────────────────┐
        ↓                        │
        0 → 1 → 2 → 3 → 4 ──────┘
（rear/front 沿箭头前进，走过 4 由 %maxSize 绕回 0）
```

```c
/* 循环队列代码模板 */
typedef struct { int *data; int f, r; } Queue;   // f队头 r队尾
Queue InitQueue() { q.f = q.r = 0; }             // 初始化
void EnQueue(Queue *q, int k) {                  // 入队
    if (q->f == (q->r + 1) % maxx) { printf("队满,无法入队\n"); return; }
    q->data[q->r] = k;
    q->r = (q->r + 1) % maxx;                    // 取模后移
}
int IsEmpty(Queue *q) { return q->r == q->f; }   // 判空
void DeQueue(Queue *q) {                         // 出队
    if (IsEmpty(q)) { printf("队空,无法出队\n"); return; }
    printf("%d\n", q->data[q->f]);
    q->f = (q->f + 1) % maxx;
}
```

| 对比 | 普通顺序队列 | 循环队列 |
|------|--------------|----------|
| 各自定义 | 一维数组直排实现的队列 | 首尾相接循环结构的顺序队列 |
| 核心区别 | rear 到末端即报"满"（假溢出） | 指针取模回绕，出队空间可复用 |
| 各自特点 | front 前面腾出的空间浪费掉 | 牺牲一个单元区分空满 |
| 使用场景 | 缺陷明显，基本不用 | 顺序队列的标准形态 |
| 典型示例 | rear==size-1 误判满，front 前却有空位 | `(rear+1)%maxSize==front` 才是真满 |
| 记忆口诀 | 假溢出骗人，取模掰成环 | |

> ⚠️ 注意事项：判满的"牺牲一个空间"是为了解决队空队满都 `rear==front` 的问题；个数公式里的 `+maxSize` 不能省，否则 rear < front 时算出负数。

> 🎯 规律：取模=把直线掰成环；判满用"下一个位置是不是队头"提前一步预判，留出一格做空满的"界碑"。

> 💡 一句话总结：取模成环，牺牲一格辨空满。

### 6. 链式队列：尾进头出与防野指针

**是什么**：先说白话——链式队列没有"回绕"的烦恼，它就是上一章两个旧动作的组合：入队用带尾指针的尾插法，出队用删首元结点，唯一的新考点是删到空时把尾指针拉回。严格说：用带头结点的单链表实现的队列：`f` 是队首指针（指向头结点，出队删的是 `f->next` 即首元结点），`r` 是队尾指针（指向尾结点）。入队用**带尾指针的尾插法**，出队删首元结点。初始化时 `f = r = 头结点`；判空：`f->next == NULL`。

**为什么**：队列一端删一端插，单链表**头删 O(1)、带尾指针的尾插 O(1)**——两个方向都不用遍历，正好匹配。

**怎么用**：

跟着算一遍"删空触发 r 拉回"：入队 a、b，再连续出队两次：
第1步 入 a：[头]→[a]，r 指向 [a]
第2步 入 b：[头]→[a]→[b]，r 指向 [b]
第3步 出队 a：p=[a]，p≠r，直接 f->next 指向 [b]，无需动 r
第4步 出队 b：p=[b]，**p==r 成立 ★ 先 r=f 拉回头结点**，再删——队空，r 仍安全
第5步 反证：第4步若不拉回，r 悬在已 free 的 [b] 上，下次入队 r->next=s 就是写野指针

```
删最后一个结点 b（before/after）：
before：  f → [头|●] → [a|●] → [b|^]
                              ↑ r 也指着 [b]
操作：    第1步 r == p 成立 → r = f（先拉回尾指针）
          第2步 f->next = p->next;  free(p)
after：   f → [头|^]，r = f        （队空，但还能安全入队）
```

```c
typedef struct { QNode *f, *r; } Queue;      // f队首指针 r队尾指针
void EnQueue(Queue *q, int k) {              // 入队：r后面插新结点
    QNode *s = (QNode*)malloc(sizeof(QNode));
    s->data = k;  s->next = NULL;
    q->r->next = s;
    q->r = s;                                // 移动尾指针
}
void DeQueue(Queue *q) {                     // 出队：删首元结点
    if (q->f->next == NULL) { printf("队空,无法出队\n"); return; }
    QNode *p = q->f->next;                   // p指向首元结点
    if (q->r == p) q->r = q->f;              // ★删的是尾结点：r拉回头结点，防r野指针
    q->f->next = p->next;
    free(p);  p = NULL;
}
```

> ⚠️ 注意事项：最容易漏的就是 `if (q->r == p) q->r = q->f;`——把最后一个结点删掉后 r 还指着已 free 的空间，再入队 `r->next = s` 就是操作野指针。

> 🎯 规律：凡指向"将被删除结点"的指针，删除前都必须被改写——尾指针也不例外。

> 💡 一句话总结：尾进头出，删空记得拉回r。

### 7. 双端队列：两端自由的队列

**是什么**：先说白话——普通队列只开两个口（尾进、头出），双端队列干脆四扇门全开，哪端都能进哪端都能出。严格说：双端队列就是**两端都是结尾的队列**——队列的**每一端都可以插入数据项和移除数据项**（前端进/前端出/后端进/后端出）。相对于普通队列，双端队列的**入队和出队操作在两端都可以进行**。

**为什么**：这种数据结构的特性使得它更加实用和方便，并且可以**退化**（限制某些口不用，就变回更简单的结构）成更简单的结构（课件重点）：
- 只允许使用**一端**进行出队、入队操作 → **等价于一个栈**
- 限制**一端只能出队**、另一端**只能入队** → **等价于一个普通队列**

**怎么用**（配套代码：循环数组 + 计数器 sum；l 指向真正的左端数据，r 指向右端数据后一个位置）：
```c
typedef struct { int *data; int l, r; int sum; } Deque;  // sum=队列中数据个数
左入：l = (l - 1 + maxx) % maxx;  data[l] = k;  sum++;   // 先退位再存（+maxx防负）
右入：data[r] = k;  r = (r + 1) % maxx;  sum++;
左出：取 data[l];  l = (l + 1) % maxx;  sum--;
右出：r = (r - 1 + maxx) % maxx;  取 data[r];  sum--;
判满 sum == maxx，判空 sum == 0     // 用计数器后不用牺牲空间
```

跟着算一遍（maxx=5，初始 l=r=0，sum=0）：
第1步 右入 1：data[0]=1，r=(0+1)%5=1，sum=1
第2步 右入 2：data[1]=2，r=2，sum=2
第3步 左入 0：l=(0-1+5)%5=4 ← **回绕**（不加 maxx 会得 -1），data[4]=0，sum=3
第4步 左出：取 data[4]=0，l=(4+1)%5=0，sum=2
第5步 右出：r=(2-1+5)%5=1，取 data[1]=2，sum=1
剩下的数据：data[0]=1——四个口都动过了，且两次后退都靠 +maxx 兜底。

> ⚠️ 注意事项：向左移动是 `-1`，必须写成 `(x - 1 + maxx) % maxx`，否则 x=0 时下标变 -1；用 sum 计数判空满，容量可以全部用满。

> 🎯 规律：加一个计数器 sum 记个数，"牺牲一格辨空满"就可以省掉——空满之争本质是信息不足，补信息即解。

> 💡 一句话总结：两端能进能出，可退化栈和队列。

### 8. 三种应用级队列：LRU/LFU、延迟队列、阻塞队列

**是什么**：先说白话——前面都是"裸队列"，工程里给队列各加一条新规则，就长出这三个实用件。严格定义：
- **LRU（Least Recently Used，最近最久未使用）缓存淘汰**，三条规则：① 新数据插入到**链表头部**；② 每当**缓存命中**（即缓存数据被访问），则将数据**移到链表头部**；③ 当**链表满**的时候，将**链表尾部**的数据丢弃。这是根据**时间**判断；如果根据**使用次数**判断，就叫 **LFU（Least Frequently used）**，Redis 用的应该就是 LFU
- **延迟队列**：普通队列按入队顺序处理；延迟队列中的元素在**入队时会指定一个延迟时间**，表示希望经过该指定时间后再处理。从某种意义上说它不像队列，**更像是一个以时间为权重的堆**。典型场景：新建订单 15 分钟未支付自动取消、会议预定开始前半小时通知、安全工单超 24 小时未处理自动提醒、外卖距超时还有 10 分钟提醒；数据量小、时效要求不高可以轮询数据库，数据量大且实时性要求高（如每天百万甚至千万级订单超时）就必须用延迟队列
- **阻塞队列**：一个可以存放 0 到 N 个元素的队列。**队列为空时，弹出操作（获取第一个元素并移除）会被阻塞，直到有元素插入才被唤醒；队列已满时，插入操作会被阻塞，直到有元素弹出后才被唤醒**。线程池中往往用阻塞队列保存暂时没有空闲线程可以直接执行的任务，线程空闲后再弹出执行

**为什么**：三者都是普通队列的"规则变体"——缓存按热度淘汰、延迟任务按时间权重组队、并发场景用阻塞做背压；它们的载体（链表、双端队列、堆）都建立在前几章结构之上。

**怎么用**：

跟着算一遍 LRU（容量 3 的缓存，[ ] 左端是链表头）：
第1步 访问 A → 缓存 [A]
第2步 访问 B → 新数据插头部 → [B, A]
第3步 访问 C → [C, B, A]
第4步 访问 D → 链表已满，淘汰尾部 A → [D, C, B]
第5步 再次访问 B → 命中，B **移到**头部（不是重新插入）→ [B, D, C]
第6步 访问 E → 淘汰尾部 C → [E, B, D]
全程离队头越近 = 最近越常用；队尾 = 最久未用，第一个被丢弃。

```
LRU 演化：空 → A → A,B → A,B,C → 满时 A 被淘汰 → 访问B则移头（不是重新插入B）
双端队列退化：限一端进出 = 栈；一端只进另一端只出 = 队列
```

> ⚠️ 注意事项：LRU 按"时间"、LFU 按"次数"，别混；"B 最近又被使用"是把 B 移到链表头部，**不是**加入 B 而是再次使用 B。

> 🎯 规律：普通队列 + 一条新规则（按时间/按次数/按阻塞）= 一个工程组件；万变不离"受限线性表"。

> 💡 一句话总结：LRU按时间，LFU按次数。

### 🧩 本章归纳：一条主线串全章

全章主线：**栈与队列都是"线性表 + 操作限制"**——把插删限制到一端，得到栈（LIFO）；限制成"一端进一端出"，得到队列（FIFO）；把限制放松到两端，得到双端队列。限制越严，行为越确定、实现越简单；每放松一步，实现就要多补一块（回绕、计数器、拉回尾指针）。

| 结构 | 操作口 | 顺序实现的关键 | 链式实现的关键 |
|------|--------|----------------|----------------|
| 栈 | 1 个（栈顶） | top 下标移动，判满判空 | 头插/头删（复用单链表模板） |
| 队列 | 2 个（尾进头出） | 取模成环 + 牺牲一格辨空满 | 带尾指针尾插 + 删首元 + r 拉回 |
| 双端队列 | 4 个 | 循环数组 + sum 计数器 | 双向链表 |

回头看才看得见的三条联系：
1. **"限制"换"高效"**：正因为只动一端（或固定两端），每个操作才能恒定 O(1)；上一章线性表插删 O(N) 的烦恼，被规则直接关在门外。
2. **顺序存储的两大补丁在本章集中亮相**：取模回绕修"假溢出"，牺牲一格或加计数器修"空满难辨"——这两个手法在今后一切环形结构里反复出现。
3. **链式实现全是上一章的旧模板**：入栈=头插、出栈=删首元、入队=带尾指针的尾插、出队=删首元——"先接后断、free 置 NULL"逐字重演，第三章学扎实等于白送这一章。

## 🔍 相似概念辨析

### 组1：栈 vs 队列

| 对比维度 | 栈 | 队列 |
|----------|-----|------|
| 各自定义 | 只允许在栈顶一端插入删除的操作受限线性表 | 只允许后端插入、前端删除的操作受限线性表 |
| 核心区别 | 先进后出/后进先出（LIFO） | 先进先出（FIFO） |
| 各自特点 | 栈顶可变、栈底固定，单端操作 | 队尾进、队头出，两端各司其职 |
| 使用场景 | 函数调用地址取用、临时结果保存 | 主机与外设速度不匹配、多用户资源竞争 |
| 典型示例 | 弹夹装子弹：先压后弹 | 排队服务：先来先服务 |
| 记忆口诀 | 栈是弹夹，队列是排队 | |

### 组2：顺序栈 vs 链栈

| 对比维度 | 顺序栈 | 链栈 |
|----------|--------|------|
| 各自定义 | 数组 + 栈顶下标 top 实现的栈 | 带头结点单链表实现的栈（首元为栈顶） |
| 核心区别 | 容量固定，必须判满 | 动态伸缩，无满之忧 |
| 各自特点 | top 是下标，top-1 为栈顶数据；top==0 空 | 入栈=头插，出栈=删首元；`s->next==NULL` 空 |
| 使用场景 | 容量可预估 | 容量不可预估 |
| 典型示例 | `data[top-1]` 取栈顶 | `s->next->data` 取栈顶 |
| 记忆口诀 | 顺序怕满，链栈怕空 | |

### 组3：循环队列 vs 普通顺序队列

| 对比维度 | 普通顺序队列 | 循环队列 |
|----------|--------------|----------|
| 各自定义 | 一维数组直排存放的队列 | 首尾相接循环结构的顺序队列 |
| 核心区别 | rear 到数组上限即报满（假溢出） | 指针取模回绕，出队空间可复用 |
| 各自特点 | front 前腾出的空间用不上 | 牺牲一个空间区分空满 |
| 使用场景 | 缺陷明显，基本不用 | 顺序队列的标准实现 |
| 典型示例 | rear==size-1 误判满 | `(rear+1)%maxSize==front` 判满 |
| 记忆口诀 | 直排假溢出，成环才解渴 | |

### 组4：队列 vs 双端队列

| 对比维度 | 队列 | 双端队列 |
|----------|------|----------|
| 各自定义 | 队尾插入、队头删除的受限线性表 | 两端都可插入和移除数据项的队列 |
| 核心区别 | 只有一进一出两个口 | 四个口：前/后端各可进可出 |
| 各自特点 | 先进先出，规则刚性 | 限制操作即可退化为栈或队列 |
| 使用场景 | 公平排队、速率缓冲 | 两端都要操作的场景（如 LRU） |
| 典型示例 | 出队 a0、入队 an | 前端进/出、后端进/出随意组合 |
| 记忆口诀 | 队列两口，双端四口 | |

### 组5：LRU vs LFU

| 对比维度 | LRU | LFU |
|----------|-----|-----|
| 各自定义 | 最近最久未使用缓存淘汰策略 | 最不经常使用（按使用次数）缓存淘汰策略 |
| 核心区别 | 按**时间**判断淘汰谁 | 按**次数**判断淘汰谁 |
| 各自特点 | 新数据插头部，命中移头部，满丢尾部 | 统计使用频率再淘汰 |
| 使用场景 | 时间局部性强的访问模式 | 访问频率稳定的场景 |
| 典型示例 | C 变成最久未使用的被淘汰；B 最近又被使用移到头 | Redis 目前使用的应该就是 LFU |
| 记忆口诀 | LRU看钟表，LFU数次数 | |

## 📋 速查表

### 循环队列公式卡（必背）
```
判空：rear == front
判满：(rear + 1) % maxSize == front      （牺牲一个空间）
个数：(rear - front + maxSize) % maxSize
入队：data[rear]=k;  rear=(rear+1)%maxSize
出队：取 data[front];  front=(front+1)%maxSize
```

### 顺序栈模板
```c
typedef struct { int *data; int top; } Stack;   // top是下标，top-1=栈顶数据
判空 top==0    判满 top==maxx
入栈：data[top]=k; top++      出栈：top--      取栈顶：data[top-1]
```

### 链栈模板（首元结点=栈顶）
```c
入栈=头插：p->next = s->next;  s->next = p
出栈=删首元：p = s->next;  s->next = p->next;  free(p);  p=NULL
判空：s->next==NULL    取栈顶：s->next->data
```

### 链式队列模板（f 指头结点，r 指队尾）
```c
入队尾插：r->next = s;  r = s
出队头删：p = f->next;  if(r==p) r=f;  f->next = p->next;  free(p)
判空：f->next==NULL（初始 f=r=头结点）
```

### 双端队列四操作（循环数组 + sum）
```c
左入：l=(l-1+maxx)%maxx; data[l]=k      右入：data[r]=k; r=(r+1)%maxx
左出：取data[l]; l=(l+1)%maxx           右出：r=(r-1+maxx)%maxx; 取data[r]
判空 sum==0    判满 sum==maxx           // 向后退必须 +maxx 防负
```

### 双端队列退化规则
```
只允许一端进行出队、入队        → 等价于栈
一端只能入队、另一端只能出队    → 等价于普通队列
```

### 复杂度速览（教科书共识）
```
入栈/出栈：O(1)        入队/出队：O(1)（循环队列、带尾指针的链队列均如此）
双端队列四操作：O(1)    LRU 命中移头/淘汰尾：O(1)（双向链表实现）
```
