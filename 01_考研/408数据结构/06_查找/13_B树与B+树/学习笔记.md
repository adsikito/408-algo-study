## 第十三章：B树与B+树

> 课件来源：`B树的概念和常用操作.pdf`、`B+树.pdf`
>
> 配套代码：`B树的代码/BTree.cpp`、`B+树参考代码/BPlusTree.cpp`
>
> 本章主线：**为磁盘而生**——硬盘以块为单位管理，把树做"胖"（一个结点存多个关键字），矮胖的高度 = 更少的磁盘 I/O。B树吃透"分裂上移、借与合并"，B+树只记差异化。

## 🗺️ 本章地图

> **本章解决一个问题：10 亿条数据放在硬盘上，怎么组织才能两三次 I/O 就查到？**
> 路线是"先立靶、再改进"：先弄清磁盘按块存取、树要矮胖的动机（知识点 1）；再立 B 树的 5 条定义与查找方式（2~3）；然后是两大操作——插入"分裂上移"（4）与删除"借/合并"（5），本章手算主战场；最后是改进版 B+树：数据全在叶子、叶子串成链（6~9），高度公式 O(log_m N) 收尾（10）。
> B+树的一切差异化设计都源于一句话："非叶不带数据——索引更密更矮、叶子串链、区间好查"。

## 📌 本章重点（3-5个）

⭐ **m 阶 B 树的定义（5 条约束）**：结点最多 m-1 个关键字；根最少 1 个；非根至少 ⌈m/2⌉-1 个；结点内关键字有序（左子树 < 它 < 右子树）；所有叶子同层
⭐ **B 树插入 = 分裂上移**：溢出结点从中间位置 ⌈m/2⌉ 处分裂，中间关键字上移父结点，连锁分裂传到根 → 树高 +1
⭐ **B 树删除 = 借与合并**：内部结点先取前驱/后继替换转成叶子删除；下溢则向兄弟借（父下移、兄弟上移），兄弟不够就合并，可能级联到根 → 树高 -1
⭐ **B+树结构差异**：数据指针全在叶子，非叶只当索引媒介；叶子按 Pnext 链成有序单链表；查找任何元素都要走到叶子，磁盘 I/O 次数恒定
⭐ **阶与高度**：含 N 个关键字（记录）的 m 阶树高 log_{2k+1}(N+1) ≤ h ≤ 1+log_{k+1}((N+1)/2)，复杂度 O(log_m N)

## 🔥 本章难点（2-3个）

🔥 **B 树删除的五种情况手算**：课件 5 阶案例连环删 21→27→32→40，覆盖"直接删、后继替换、借、合并、级联合并到根"全流程
🔥 **B+树插入/删除的索引修正**：插入比最大值还大的关键字时，从根到该结点路径上所有索引值都要改；删除最大/最小关键字也要回溯改父到根的索引
🔥 **B 树阶与高度的推导**：最小度 k 下 Nmin/Nmax 结点数、Imin/Imax 关键字数、高度上下限公式的来历与使用

## ⚠️ 本章易错点（3-5个）

⚠️ **阶 m 的含义记反**：阶 = 结点**孩子个数**的最大值 → 关键字最多 **m-1** 个（不是 m 个）；m=2 就是普通二叉搜索树
⚠️ **关键字下限算错**：非根结点至少 **⌈m/2⌉-1** 个关键字；根结点最少 1 个（下限公式 (m+1)/2-1 即 ⌈m/2⌉-1，配套代码 BTree.cpp 用的正是它）
⚠️ **以为 B+树在中途命中就结束**：内部结点中出现目标值只是"控制查找的媒介"，不是数据本身，必须继续走到叶子才算找到——所以 B+树查任何元素 I/O 次数都相同
⚠️ **B 树删内部结点关键字直接删**：必须先用**左子树最大（前驱）或右子树最小（后继）**替换它，转化为删叶子中的关键字，否则子树指针接不上
⚠️ **B+树删最大/最小值忘改索引**：会破坏"从根到该结点的索引值"性质，必须向上回溯把所有旧值替换为次最大/次最小值

## 📖 知识点讲解

### 1. 为什么要有 B 树

**是什么**：之前学的树（二叉查找树、AVL、红黑树）数据保存在内存；数据量大时往往存在**硬盘**上，而**硬盘以块为单位**管理。B树（又称 B-树）就是**多路平衡查找树**：一个结点存多个关键字、多个孩子，B树中所有结点的孩子个数的最大值称为**阶**，用 m 表示（m=2 即二叉搜索树）。

**为什么**：访问物理介质的时间要越少越好，B树就是为了**最小化磁盘访问次数**。二叉类树每个结点只存 1 个键值，海量数据时树高非常大、访问时间增加；B树单结点存许多键、有多个孩子，**大大降低高度 → 更快磁盘访问**。平衡就是让树尽量"胖"，高度不线性增长。

**怎么用**：实际应用中阶数 m 都非常大（通常大于 100），所以存大量数据树高也很小。结点内存关键字 key + 数据 data + 孩子指针，一个 key 和它的 data 合称一个**记录**。

> ⚠️ 注意事项：B树/B+树优化的指标是磁盘 I/O 次数，不是内存比较次数（结点内 O(m) 的扫描在内存中进行，可忽略）。

> 🎯 规律：存储介质的"块"决定结点的"胖"——一次 I/O 读一整个结点，树高即 I/O 次数。

> 💡 一句话总结：磁盘按块读，树胖高度矮。

### 2. m 阶 B 树的定义（必背 5 条）

**是什么**：一棵 m 阶 B 树：
1. 每个结点最多有 **m-1** 个关键字；
2. 根结点最少可以只有 **1** 个关键字；
3. 非根结点至少有 **⌈m/2⌉-1** 个关键字；
4. 每个结点中的关键字**从小到大**排列，每个关键字的左子树所有关键字都小于它，右子树所有关键字都大于它；
5. **所有叶子结点位于同一层**（根到每个叶子的长度相同）。

**为什么**：第 5 条"叶子同层"是 B树平衡的来源；第 3 条保证结点"半满"，让删除时有得借、合并后仍不塌。

**怎么用**：以 m=5 为例——结点最多 4 个 key、非根最少 ⌈5/2⌉-1=2 个 key，课件 5 阶删除案例全部围绕 [2,4] 区间展开。配套代码：`#define minn (m+1)/2-1`，即 ⌈m/2⌉-1。

| 结点 | 关键字数 | 孩子数 |
|------|---------|--------|
| 根（非叶时） | 1 ~ m-1 | 2 ~ m |
| 非根非叶 | ⌈m/2⌉-1 ~ m-1 | ⌈m/2⌉ ~ m |

**跟着算**——验收 3 阶 B 树的一个结点 [5 | 9]：3 阶要求 key 数 ∈ [⌈3/2⌉-1, m-1] = [1, 2]，此结点 2 个 key ✓；孩子 3 个 ≤ m=3 ✓；再全局查一条"所有叶子是否同层"。三条逐一过、全过才合法——判断题最爱把下限挖成 ⌊m/2⌋-1 让你上当。

> ⚠️ 注意事项："阶"是孩子数上限，不是关键字数；别把"非根至少 ⌈m/2⌉-1 个关键字"与"至少 ⌈m/2⌉ 个孩子"混写。

> 🎯 规律：验收 B 树只查三样——key 上限 m-1、非根下限 ⌈m/2⌉-1、叶子同层。

> 💡 一句话总结：最多 m 减一，非根半数起。

### 3. B 树的查找与中序遍历

**是什么**：查找与 BST 极为类似，只是结点里有多个关键字（结点内可用二分/顺序匹配）：① 先与结点第一个关键字比较，匹配则成功；② 不成功继续与后面的关键字比；③ 遇到**大于查找值**的关键字，就往它与前一个关键字**之间的分支**往下搜；④ 若最后一个关键字都比查找值小，往**最右分支**往下搜；⑤ 查到**空结点**则失败。

**为什么**：多路结构一次 I/O 读一整块结点，结点内匹配是廉价操作，跨越一层 = 一次磁盘 I/O。

**怎么用**：**中序遍历**与二叉树相似：从最左边的孩子开始，递归打印最左孩子，再对剩余的孩子和关键字重复同样的过程，最后递归打印最右孩子（得到有序序列）。

**跟着算**——在下面的 3 阶 B 树里查 8（走一层 = 一次磁盘 I/O）：

```text
          [5 | 10]
         /    |    \
     [2,3]  [7,8]  [12,15]
```
第1步 根结点内比：8>5、8<10 → 落到 5 与 10 之间的中间分支（第 1 次 I/O）；
第2步 进 [7,8]：8=8 → 命中（第 2 次 I/O）。
若查 9：同路进 [7,8]，9>8 → 走 8 的右分支到空结点 → 失败，同样只花 2 次 I/O——"叶子同层"保证失败的代价也恒定。

> ⚠️ 注意事项：查找失败一定终止在最底层（因为所有叶子同层）；配套代码 SearchBTree 在结点内找"第一个 ≥ k 的位置 i"，命中则返回 (结点,i)，否则走 ptr[i-1] 左分支。

> 🎯 规律：一层一次 I/O；结点内怎么比都行，关键是"键之间选分支"。

> 💡 一句话总结：结点内比键，分支间下楼。

### 4. B 树的插入：回溯法与主动插入法

**是什么**：插入总是先**定位到查找失败的叶子**，若该叶子关键字个数 < m-1 直接插入；否则**分裂**：
1) 取一个新结点，把插入 key 后的原结点从**中间位置 ⌈m/2⌉** 分成两部分；
2) 左部分留在原结点，右部分放进新结点，**中间位置 ⌈m/2⌉ 的关键字插入父结点**；
3) 若父结点也超上限则继续分裂，传到根则新建根，**B树高度 +1**。
本质：把 ⌈m/2⌉ 位置的关键字变成左右两半的父结点，向上"贡献"一个关键字。

**为什么**：回溯法插入后若层层上溢，需要从叶往根回溯多遍；**主动插入法**在下降途中就提前拆分沿途已满结点（x 从根出发，孩子 y 已满就先拆 y，k 与 y 中间关键字比大小决定去左半还是右半），到叶子时必定有空位直接插入——**不必回溯、不会发生级联效应**；缺点是**可能做很多不必要的拆分**。

**怎么用**——手算口诀（m=3 例子）：结点 [20,30,40] 插入后 3 个 key 超上限（最多 2 个）→ 第 ⌈3/2⌉=2 个关键字 30 上移父结点，[20] 留原结点，[40] 放新结点。配套代码 Split：`s=(m+1)/2`，key[1..s-1] 留原结点、key[s] 上传、key[s+1..m] 给新结点。

**跟着算**——3 阶 B 树（每结点最多 2 个 key）依次插 1、2、3、4，亲眼看"分裂上移怎么长高"：
第1步 插 1、2：根 [1,2]，未超上限；
第2步 插 3：[1,2,3] 溢出 → 从 ⌈3/2⌉=2 处分裂：中间 key **2 上移当新根**，[1] 留原结点、[3] 进新结点——树高 +1；
第3步 插 4：4>2 走右叶 → [3,4] 恰满但不溢，结束。

```text
插 3 后（分裂长高）：          插 4 后：
        [2]                          [2]
       /   \                        /    \
    [1]     [3]                  [1]      [3,4]
```

> ⚠️ 注意事项：分裂点永远是 **⌈m/2⌉**（BTree.cpp 中 key 数组从下标 1 开始存、预留下标 m 就是为了"先插入后分裂"）；分裂上移的是**一份关键字**，不是整个结点。

> 🎯 规律：满了才裂、裂必取中、中键上贡——只有根分裂时树才长高。

> 💡 一句话总结：满了从中间裂，中间上贡献。

| 对比 | 回溯法 | 主动插入法 |
|------|--------|-----------|
| 拆分时机 | 插入后溢出才分裂 | 下降途中见满就拆 |
| 回溯 | 可能层层回溯 | 无回溯、无级联 |
| 代价 | 遍历结点两次 | 可能有 unnecessary 拆分 |

### 5. B 树的删除（五种情况，必考手算）

**是什么**：删除流程：① 搜索要删除的元素；② 在**叶子**上直接删除；③ 删除后产生**下溢出**（键数小于最小值 ⌈m/2⌉-1）→ 向兄弟**借**：父结点元素下移至当前结点，兄弟元素上移至父结点（左兄弟移最大元素，右兄弟移最小元素）；④ 兄弟也到下限 → **合并**兄弟与分割键。若删的是**内部结点**的元素：它是左右子树的分割值，需从**左子树最大（前驱）或右子树最小（后继）**中选新分割符替换，被选中者从原子结点移除；若左右子结点均达下限则合并，删除后仍不足则继续合并。

**为什么**：叶子直接删不影响结构；内部结点的关键字承担"分割"职责，必须找前驱/后继顶替。

**怎么用**——课件 5 阶案例（每结点 key ∈ [2,4]）：

```
a) 原始树（略，按操作逐步理解）
b) 删 21：叶子删除后 key 数 ≥ 2，不下溢，删除结束
c) 删 27：27 在非叶结点 → 用后继 28 替换 27，到右孩子叶子中删 28
   → 该叶剩 1 个 key < 2，兄弟有 3 个 → 借：父结点 28 下移、兄弟 26 上移
   （左/右兄弟任选其一都行，只是最终形态不同）
d) 删 32：该叶剩 1 个 key，兄弟也仅 2 个（无处可借）
   → 父结点 30 下移，两个孩子合并成一个新结点
e) 删 40：该叶 < 2，兄弟无多余 → 父结点 key 下移与（左）兄弟合并
   → 合并传导使当前结点只能继续合并 → 根中再无关键字 → 树高 -1
```

配套代码 DeleteBtree：非终端结点取 **key[i] 的中序后继**（右子树一路 ptr[0] 到底）替换，问题转化为删终端结点；删后 keynum < minn 调 Restore——兄弟够借（keynum ≥ minn+1）就 Borrow，否则 Meger，合并后父结点可能继续下溢递归调整；根合并后 keynum < 1 则孩子顶替当新根（树高 -1）。

**跟着算**——3 阶 B 树（每结点 key ∈ [1,2]）连删两刀，看"借不到就合并、合并到根树变矮"：

```text
          [5]
        /     \
   [1,2]       [7]
```
第1步 删 2：[1,2] → [1]，仍 ≥ 下限 1，不下溢，结束；
第2步 再删 1：左叶变空 → 下溢；右兄弟 [7] 只有 1 个 key（恰在下限），**无可借** → 父分割键 5 下移，两个孩子合并成 [5,7]；
第3步 根变空 → 唯一孩子顶替当新根，**树高 -1**。

> ⚠️ 注意事项：借 = "父下移一个 + 兄弟上移一个"（两次替换，不是直接搬兄弟的 key）；合并 = "父分割键下移 + 两兄弟合成一个结点"；级联合并到根时树才会变矮。

> 🎯 规律：下溢先看兄弟口袋——有富余就"换"（借），没富余就"合"（父键下来垫底）。

> 💡 一句话总结：叶子直接删，下溢先借后合。

### 6. B+树的概念与结构

**是什么**：B+树消除 B-树做索引的缺陷——B-树所有中间结点都存数据指针（指向含键值的磁盘文件块），挤占结点空间 → 可存结点数变少 → 层数增加 → 搜索变慢。**B+树仅在叶子结点存数据指针**：叶子必须把所有键值和对应数据指针存进磁盘文件块；叶子被链接起来（Pnext 指针）提供**对记录的有序访问**——叶子层构成第一级索引，内部结点构成多层索引的其他层；叶子的某些 key 也出现在内部结点中，**充当控制搜索的媒介**。结点有**两个阶** a（内部）与 b（叶子）：
- 内部结点 <P1,K1,P2,…,Kc-1,Pc>（c≤a）：关键字升序；子树 X 满足 1<i<c 时 K(i-1)<X≤Ki、i=1 时 X≤K1、i=c 时 X>K(c-1)；内部结点最多 a 个孩子指针；**根至少 2 个指针**，非根至少 ⌈a/2⌉ 个；含 c 个孩子则含 **c-1 个关键字**。
- 叶子结点 <<K1,D1>,<K2,D2>,…,<Kc-1,Dc-1>,Pnext>（c≤b）：Di 指向磁盘上关键字等于 Ki 的真实记录；关键字升序；**所有叶子在同一层**；沿 Pnext 可像单链表一样遍历所有叶子。

**为什么**：非叶不带货 → 同样大小的磁盘页能装更多索引键 → 树更矮；叶子链表让区间访问、全量扫描按序直达。

**怎么用**：结构示意（课件图）——根[P1,6,P2] → 内部结点 3、8 → 叶子 [2|D1][3|D1] → [4][6] → [7][8] → [12]，橙色 Pnext 把叶子串成链，叶子下方指向实际磁盘记录。

> ⚠️ 注意事项：B+树与 B-树差异三条（课件查找部分）：① B+树所有数据均保存在叶子，根和内部结点只是媒介，内部结点元素同时存在于子结点中且是其**最大（或最小）**元素；② 每个叶子有指向下一个叶子的 Pnext；③ 根结点的最大元素是整棵树最大元素，插入删除都要维持该性质。

> 🎯 规律：B+树把"货"全塞进叶子，索引层因此更密；叶子链是附赠的"顺序通道"。

> 💡 一句话总结：索引不上楼，叶子串成链。

### 7. B+树的查找：单元素与区间

**是什么**：**单元素查找**：从根出发逐层向下到叶子。课件例查 59（M 阶树）：第一次磁盘 I/O 访问根[59,97]，59 ≤ 59 → 走第一个孩子；第二次访问[15,44,59]，44 < 59 ≤ 59 → 走第三个孩子；第三次访问叶子[51,59]，顺序遍历内部找到 59。**区间查找**：先在叶子中定位到区间下界，再**沿 Pnext 顺序扫描**叶子链，直到超过区间上界为止（B-树做区间查找要反复中序回溯，非常麻烦，这正是 B+树的强项）。

**为什么**：即使目标值出现在根/内部结点，那也只是媒介不是数据，**必须走到叶子**——所以**每个元素的磁盘 I/O 次数相同，查询效率稳定**。

**怎么用**——综合来看 B+树的三条优势（课件原文）：
1. 查找时磁盘 I/O 次数更少：非叶结点可存更多关键字，同样数据量更"矮胖"，效率更高；
2. 查询所有关键字的磁盘 I/O 次数都一样，查询效率稳定；
3. 进行区间查找时更加简便实用。
同为 h 层时 B+树能存更多元素；相比 B-树的中序遍历，B+树只需像遍历单链表一样扫描一遍叶子。

> ⚠️ 注意事项：配套代码 bplus_tree_insert/delete 的查找循环 `while (node->child != NULL)` 就是在强制走到底层叶子；binary_search 命中后 index+1 再下行（右子树），保证重复键继续向下。

> 🎯 规律：中途见到目标值只当"路标见过"，必须走到叶子才算数——I/O 次数因此恒定。

> 💡 一句话总结：一路走到叶，区间扫链表。

### 8. B+树的插入（四种情况）

**是什么**：插入**全部在叶子结点上进行**，且不能破坏关键字自小而大的顺序；关键字个数超过限制时**分裂**。设阶数 M（课件例 M=3，⌈M/2⌉=2 取上限、⌊M/2⌋=1 取下限）：
1. 目标叶子关键字数 **< M** → 直接插入（如插入 12 进 [10,15]）；
2. 目标叶子关键字数 **= M** → 分裂成两结点：一个含 **⌈M/2⌉** 个、另一个含 **⌊M/2⌋** 个关键字，并将 **⌈M/2⌉ 处关键字上移**至双亲（双亲个数 < M 则结束）。课件例：插 95，[85,91,97] 分裂为 [85,91] 与 [97]，95 插入得 [95,97]，91 上移；
3. 上移导致**双亲关键字数 > M** → **继续分裂双亲**。课件例：插 40 后 37 上移，父[15,37,44,59] 超 M → 分裂为 [15,37] 与 [44,59]，37 再上移到 [37,59,97]，结束；
4. 插入的关键字**比当前最大值还大** → 破坏了从根到该结点的所有索引值，**先修正再分裂**。课件例：插 100（旧最大 97），先把根到该叶路径上所有 97 改成 100，再照情况 2 分裂。

**为什么**：内部结点是"每棵子树最大（最小）值"的路标，最大值变化必须同步路标，否则查找会走错分支。

**怎么用**——配套代码 BPlusTree.cpp：叶子溢出时 `mid=keynum/2`，`temp=keys[mid]` 上父，右半 keys/data 拷给新叶并接好 next 链；内部结点分裂从 `mid+1` 开始拷贝（**中间关键字移动上移、叶子分裂保留副本**）；父为空则新建根结点。

> ⚠️ 注意事项：B+树分裂上移后，**叶子里仍保留该关键字**（数据不下放也不删除）；这点与 B 树"中间键彻底上移"不同。

> 🎯 规律：B+树分裂"留底上移"——叶子保留副本当最大值路标；插新最大值先改一路索引再分裂。

> 💡 一句话总结：只胖叶子，裂了留底上移。

### 9. B+树的删除（五种情况 + 三步总结）

**是什么**：与 B-树删除类似，五种情况（课件例 M=3，⌈M/2⌉=2）：
1. 删除后关键字个数**大于 ⌈M/2⌉** → 直接删（如删 91，[85,91,97] 有 3 个 > 2）；
2. 删的是该结点**最大/最小关键字** → 回溯修改双亲直到根中所有该索引值（如删全树最大 97，向上回溯把所有 97 替换为次最大 91）；
3. 删后个数 **< ⌈M/2⌉** 且兄弟**有富余** → 向兄弟**借**（如删 51：兄弟[21,37,44] 有 3 个 → 借 44，双亲索引 44 改成 37）；
4. 兄弟**没有富余**（个数 = ⌈M/2⌉）→ 与兄弟**合并**（如删 59：兄弟[21,37] 只有 2 个 → 删 59 后 [44] 与 [21,37] 合并成 [21,37,44]，向上回溯把所有 59 替换为次最大 44）；
5. **合并可能使双亲也被破坏** → 依以上规律继续处理双亲（如删 63：[72] 与 [85,91] 合并 → 回溯删 [72,91] 中的 72 → 只剩 91 不满足 → 从兄弟[15,44,59] 借 59，并把兄弟的父结点索引 59 替换为 44）。

**为什么**：借和合并都可能改变子树的最大/最小值，父结点中的索引是路标，必须跟着改。

**怎么用**——课件删除总结三步骤：
1. 删除该关键字，若不破坏 B+树性质，直接完成（情况 1）；
2. 若删除导致该结点最大（或最小）值改变，相应改动其父结点中的索引值（情况 2）；
3. 若导致结点关键字个数不足：向兄弟借，或与兄弟合并（情况 3、4、5）——注意这两种方式有时需要更改父结点中的索引值。

> ⚠️ 注意事项：配套代码删除先下到叶子删除，`keynum < min` 时按"借（叶子/内部左旋右旋）→ 合并"处理并向上回溯；根 keynum==0 时让孩子顶替为根（树高 -1）。

> 🎯 规律：B+树删除 = 删数据 + 修路标——凡最大/最小值变化，父到根的索引全跟着改。

> 💡 一句话总结：借合并之外，记得修路标。

### 10. B 树/B+树的复杂度与高度分析（阶与高度）

**是什么**：设最小度 k（即课件 B-树中的最小度数：内部结点**至少 k+1 个孩子、至多 2k+1 个孩子**），树高 h（根到叶长度相同）：
- 结点数下限 Nmin = 1 + 2·((k+1)⁰ + (k+1)¹ + … + (k+1)^(h-2)) = 1 + (2/k)((k+1)^(h-1) − 1)
- 结点数上限 Nmax = Σ(i=0..h-1)(2k+1)^i = (1/2k)((2k+1)^h − 1)
- 关键字数下限 **Imin = 2(k+1)^(h-1) − 1**，上限 **Imax = (2k+1)^h − 1**
- 高度上下限：**log_{2k+1}(I+1) ≤ h ≤ 1 + log_{k+1}((I+1)/2)**（I≥1；I=0 时 h=0）

**为什么**：每层"最少孩子数"连乘得到最少结点/关键字（最矮），"最多孩子数"连乘得到上限（最高），对不等式取对数即得高度范围——这就是对数级复杂度的来历。

**怎么用**：结束度（阶）为 m 的 B树，每结点最多存 m 个关键字，共 N 个关键字且树完全填满时 N = m^h → **h = log_m N**。结点内遍历 m 个键的 O(m) 在内存中进行、可忽略；关心的是**磁盘 I/O 次数 = 树高**，故 B-树/B+树查找、插入、删除的时间复杂度均为 **O(log_m N)**，量级一致（B+树非叶不带数据一次读更多结点，实际更矮胖、性能更好）。

> ⚠️ 注意事项：推导里 h 是"根到叶的长度"，空树 h=0；m 很大（>100）时 log_m N 极小——10 亿数据 200 阶也就三四层。

> 🎯 规律：最少孩子连乘出高度下限、最多孩子连乘出上限，取对数即得——I/O 次数 = 树高 = O(log_m N)。

> 💡 一句话总结：高度就是对数，I/O 数层数。

### 🧩 本章归纳：一条主线串全章

> **主线：一切设计都围绕"少一次磁盘 I/O"——把树做胖做矮，再把数据挪到叶子。**
> 磁盘按块读 → 一个结点装一整块（多 key 多孩子）→ 高度压到 log_m N → B 树靠"分裂上移"长高、"借/合并"变矮，⌈m/2⌉-1 的半满约束保证删完不塌 → B+树再进一步：非叶甩掉数据只当路标（更密更矮），叶子存全部数据并串成链（区间直达），代价是查找必须走到底、最大/最小值变化要回溯修索引。

| 操作 | B 树 | B+树 |
|------|------|------|
| 插入 | 满 → ⌈m/2⌉ 处裂、中键上移 | 叶满 M → 裂成 ⌈M/2⌉/⌊M/2⌋，上移且叶子留副本；插新最大先修索引 |
| 删除 | 下溢 → 借（父下移+兄弟上移）/合并（父键下移），级联到根树高 -1 | 同借/合并，且最大/最小变化要回溯改索引 |
| 查找 | 中途命中即停 | 必到叶子；区间查找扫 Pnext 链 |

回头看才看得见的三条规律：
1. **半满约束是给删除留后路**：⌈m/2⌉-1 不是限制插入，而是保证借有得借、合并不塌方——定义第 3 条与删除算法是一体的。
2. **"路标一致性"贯穿 B+树**：内部结点的 key 是子树最大（最小）值的副本，凡最大/最小变动（插新最大、删最大/最小、借、合并），父到根的索引必须同步——考题的坑几乎全在这里。
3. **复杂度只是换了底数**：二叉树 O(log₂N) → B树 O(log_m N)，m>100 时 10 亿数据三四层——"矮胖"两个字值千金。

## 📋 速查表

### m 阶 B 树关键数字（配套代码 minn=(m+1)/2-1）
```
关键字数：根 1 ~ m-1        非根 ⌈m/2⌉-1 ~ m-1
孩子数  ：根 2 ~ m          非根 ⌈m/2⌉ ~ m
所有叶子同层；m=2 退化为二叉搜索树
```

### 插入三步（分裂）
```
①查找到失败的叶子，插入关键字
②超过 m-1 个 → 从 ⌈m/2⌉ 处分裂：key[s] 上移父结点（s=(m+1)/2）
③父也溢出继续分裂；传到根 → 新建根，树高 +1
```

### 删除决策链
```
内部结点 → 前驱(左子树最大)/后继(右子树最小) 替换 → 转化为删叶子
删叶子后 ≥ ⌈m/2⌉-1           → 结束
下溢：兄弟够借(≥⌈m/2⌉)        → 父键下移 + 兄弟键上移
      兄弟不够借               → 父分割键下移 + 兄弟合并
      合并导致父下溢            → 递归处理父；根空 → 孩子顶替，树高 -1
```

### B+树速记
```
结构：非叶只有索引(key+孩子)，叶子 = (key,数据指针) + Pnext 单链
插入：全在叶子；叶子满 M 个 → 分裂 ⌈M/2⌉/⌊M/2⌋，⌈M/2⌉ 处关键字上移(叶子留副本)
     插入新最大值 → 先把根到叶路径上的旧最大索引全改成新值，再分裂
删除：> ⌈M/2⌉ 直接删；动最大/最小 → 回溯改索引；不足 → 借/合并(可能改父索引)
优势：①非叶不带货更矮胖、I/O 更少 ②每个元素 I/O 次数相同 ③区间查找扫叶子链
```

### 复杂度与高度（最小度 k，关键字数 I）
```
Imin = 2(k+1)^(h-1) - 1          Imax = (2k+1)^h - 1
Nmin = 1 + (2/k)((k+1)^(h-1)-1)  Nmax = ((2k+1)^h - 1)/(2k)
高度：log_{2k+1}(I+1) ≤ h ≤ 1 + log_{k+1}((I+1)/2)
满树 N = m^h → h = log_m N → 查找/插/删均为 O(log_m N)（磁盘 I/O 次数 = 树高）
```

### 代码骨架（BTree.cpp）
```c
#define m 5
#define minn (m+1)/2-1              // ⌈m/2⌉-1：非根关键字下限
typedef struct BTNode{
    int key[m+1];                    // key[1..m]，先插入后分裂预留1位
    struct BTNode *ptr[m+1];         // ptr[0..m]：key[i]左孩子ptr[i-1]、右孩子ptr[i]
    int keynum; struct BTNode *fa;
}BTNode;
// 查找：结点内找第一个>=k的i；失败返回应插入的(结点,位置)
// 插入：Insert后 keynum>m-1 → s=(m+1)/2 分裂，key[s]与右半上父；根分裂则 NewRoot
// 删除：非终端 → 后继替换；Remove后 keynum<minn → Borrow / Meger → 递归Restore
```

### 代码骨架（BPlusTree.cpp）
```c
typedef struct bplus_node_s{
    KEY *keys; VALUE *data;          // data 仅叶子有，内部结点为 NULL

```
