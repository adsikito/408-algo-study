## 🗺️ 本章地图

本章解决一个痛点：**二叉排序树（BST）会退化成链表**，怎么让它自己保持平衡？路线：§1-§2 先看病根与药方原型——多路平衡树（2-3 / 2-3-4 / B树）绝对平衡、结点对齐磁盘页，但天生是多叉的 → §3-§4 引出红黑树：把 2-3-4 树的每个结点拆成"一黑挂几红"的二叉形态，并用黑高推出高度上界 → §5 练好旋转这门基本功 → §6-§7 攻克插入（看叔叔）与删除（双黑、看兄弟）两大调整。顺序之所以这样排：插入删除的每一步"变色+旋转"，都是 2-3-4 树分裂/合并在二叉世界的翻译动作——不懂 §2 的分裂，就背不动 §6 的口诀。

## 📌 本章重点（3-5个）

⭐ **红黑树的5条性质与2-3-4树的等价关系**：红黑树就是 2-3-4 树（3、4结点"上黑下红"拆开），性质不必死记，用 2-3-4 树绝对平衡反推
⭐ **黑高 bh 与高度上界**：bh(x) 不含起点；黑高 bh≥h/2；n 个结点红黑树 h≤2lg(n+1)，最长路径不超过最短路径的 2 倍
⭐ **插入调整（看叔叔）**：新结点必先染红；叔红→变色上溯，叔黑→按 LL/LR/RR/RL 旋转（对照 AVL 四型）
⭐ **删除调整（看兄弟）与双黑**：删除黑色结点产生双黑，任务是把双黑变单黑；兄弟黑有红孩子四型旋转 / 兄弟黑两孩全黑向上递归 / 兄弟红旋转转换
⭐ **左旋与右旋的指针操作**：y 接管 x 的位置、子树交接、双亲指针维护，插入删除调整全靠它

## 🔥 本章难点（2-3个）

🔥 **从 2-3-4 树理解红黑树**：插入对应"临时4节点/5节点分裂、中间元素上移"，红黑树的左旋、右旋、变色只是分裂在二叉形式下的表达；只有分裂根节点才会增高
🔥 **删除的双黑及其 6 种情形**：双黑概念（y 黑 x 黑，y 的黑色"留在"了 x 上）、a) 兄弟黑有红孩子（LL/LR/RR/RL，两步旋转）、b) 兄弟黑两孩全黑（红+双黑=单黑，向上递归）、c) 兄弟红（旋转转换成 a/b），还有双黑是根直接减黑高
🔥 **插入调整的向上迭代**：叔红变色后爷爷 g 变红可能又与曾祖冲突，要把 g 当新插入结点继续循环，直到根（根再染黑，整树黑高+1）

## ⚠️ 本章易错点（3-5个）

⚠️ **红黑树的叶子结点是 NULL(NIL) 结点**：不是最下层的实结点！NULL 默认按黑色处理，"黑路同"必须数到 NULL；删黑色叶子就会产生双黑
⚠️ **黑高"起点不算"**：bh(x) 是从 x 出发（不含 x 自身）到叶结点路径上的黑色结点数；树的黑高=根的黑高
⚠️ **叔叔是黑色≠叔叔存在**：NULL 结点也算黑，代码里必须先判 `u != NULL && u->color == RED` 才是叔红，否则按叔黑处理
⚠️ **新插入结点默认染红色，不是染黑**：只有根例外（插根染黑，整树黑高+1）；LR/RL 双旋变色与 LL/RR 不同——LL/RR 旋完 p 黑 g 红，LR/RL 旋完新根 z 黑 g 红
⚠️ **插入看叔叔、删除看兄弟，别搞混**；删除度为 2 的结点时，真正被删的是中序后继 y（数据先复制过来），颜色属性跟着被 free 的结点走

## 📖 知识点讲解

### 1. 红黑树前导：BST 退化、AVL 局限与磁盘 I/O

**是什么**：一句话点破：BST 长歪了就是链表，本章的全部工作就是给 BST 立规矩，逼它自己不长歪。展开说：二叉排序树（BST）= 二叉树 + 有序性（左<根<右）。按 A、B、C 顺序插入会退化成**单链表**，极端情况下操作复杂度从 O(logn) 掉到 O(n)。平衡的手段就是**旋转**（把某个孩子提升上来顶替父亲、整棵树依然有序的换形操作）——能自平衡的 BST 叫平衡树。第一种平衡树是 1962 年的 AVL 树（任意结点左右子树高度差≤1）。当数据大到内存装不下、要存磁盘（如数据库索引）时，一次磁盘 I/O 的代价约为内存访问的**十万倍**，而一次 I/O 读一页（4KB/8KB），所以评价索引结构的最重要指标是**尽量减少磁盘 I/O 次数**——二叉树一结点一元素，树要么度大要么太高，于是发展出**多路查找树**（每结点可存多个元素、多于 2 个孩子，高度可控，查找 O(logN)，底数为叉数）。

**为什么**：AVL 有两大缺点：① 结点多时**不直观**（难以一眼验证平衡）；② 插入删除的**自平衡过程非常复杂**。多路树一个结点存多个元素恰好对齐磁盘一页，配合局部预读性原理减少 I/O。

**怎么用**：先跟着算一遍 BST 是怎么一步步歪掉的——按 A、B、C 顺序插入（A<B<C）：
```text
第1步 插 A：  A                 （成为根）
第2步 插 B：B>A → 接到 A 的右边
              A
               \
                B
第3步 插 C：C>B → 接到 B 的右边
              A
               \
                B
                 \
                  C     ← 每个结点只剩一个孩子：退化成链表，
                            查 C 要比较 3 次，n 个有序数就要比较 n 次
```
再认识 2-3 树的两个基本结点，后面 2-3-4 树、B 树、红黑树全由它推：

| 对比 | 2-节点 | 3-节点 |
|------|--------|--------|
| 元素数 | 1 个 | 2 个 |
| 子树数 | 2 个（左<父<右） | 3 个（左、中、右，中间元素介于两元素之间） |
| 记忆 | 一元素两娃 | 两元素三娃 |

> ⚠️ 注意事项：AVL 更平衡但旋转多；红黑树是弱平衡但旋转少——选型在"查找优先"与"插删频繁"之间取舍。

> 🎯 规律：树的效率由形状决定，一切平衡手段都在干同一件事——压低树高，把最坏的 O(n) 拉回 O(logn)。

> 💡 一句话总结：BST 会退化，平衡靠旋转，磁盘看 I/O。

### 2. 2-3树 / 2-3-4树与B树

**是什么**：多路树的念头很朴素：一个结点多装几个元素，树就矮一截，树矮查找就少走几层。2-3 树是**绝对平衡树**——任意结点到其所有叶子结点深度相等，只需维护 2-节点和 3-节点。2-3-4 树再允许 4-节点（3 个元素、4 个孩子）。把"允许一个结点多于两个子结点、自平衡、叶结点等高"的一类树归纳为 **B 树**，用**度（Degree）**区分：度 3 的 B 树 = 2-3树，度 4 = 2-3-4树。若过程中允许临时 5 节点存在就是 2-3-4-5 树……子子孙孙无穷尽，统称 B 树。

**为什么**：B 树多元素结点利于缓存磁盘数据，常用于数据库索引；但 B 树有个大缺陷——**范围查找很难实现**（如查所有大于 B 且小于 K 的元素），于是又发展出 B+ 树。本章重点是红黑树，2-3-4 树是理解红黑树的钥匙。

**怎么用**——先跟着走一遍"分裂上浮"，再对照插入的 4 种情况。依次插入 1、2、3、4：
```text
第1步 插 1：  [1]           落进空树当根（2-节点）
第2步 插 2：  [1 2]         向 2-节点插入 → 合并成 3-节点
第3步 插 3：临时 4-节点 [1 2 3] 装满了，中间元素 2 上浮当父：
                  [2]
                 /   \
               [1]   [3]      拆成 3 个 2-节点，叶结点依然等高
第4步 插 4：4>2 走右子树，落进叶 [3] 合并：
                  [2]
                 /   \
               [1]   [3 4]    又是"向 2-节点插入"，直接合并
```
2-3 树插入 4 种情况（先查找，命中不插；未命中插到叶子结点）：

| 情形 | 处理 |
|------|------|
| ① 向 2-节点插入 | 直接合并成 3-节点 |
| ② 向只有一个 3-节点的树插入 | 临时成 4-节点→拆成 3 个 2-节点，中间元素上浮当父 |
| ③ 向父为 2-节点的 3-节点插入 | 同②，中间元素上移与父合并成 3-节点 |
| ④ 向父为 3-节点的 3-节点插入 | 持续向上分解，直到遇 2-节点父变 3-节点；若到根还是 4-节点→分解根，**树高 +1**（只有分解根才会增高） |

2-3 树删除 3 种情况（与插入相反）：删 3-节点叶子上的元素→直接删；删非叶子结点→用中序后继换位转成删叶子；删 2-节点叶子→最复杂，按"父 2 兄 3 下移上移、父 3 拆分合并、满二叉树整层降高"调整。

> ⚠️ 注意事项：2-3 树需维护两种结点，代码量大、额外开销可能比普通 BST 还慢，但查询效率更稳定。

> 🎯 规律：插入先落到叶子，再自下而上"满了就拆、中间上浮"；中途分裂只转手，唯有分裂根结点整棵树才长高。

> 💡 一句话总结：多路上浮拆分满，绝对平衡叶等高。

### 3. 红黑树的定义与5条性质（等价2-3-4树）

**是什么**：一句话：把 2-3-4 树的每个多元素结点拆成"一个黑结点挂若干红孩子"，拆出来的二叉形态就叫红黑树——5 条性质全是这种拆法的自然结果。红黑树 = 每个结点带颜色（红/黑）的**自平衡二叉排序树**，满足 5 条性质：
1、每个结点是红色或黑色；
2、**根结点是黑色**；
3、**所有叶子结点（NULL/NIL 结点，即在树中补画出来代表"空"的占位结点）是黑色**；
4、**红色结点的两个孩子必是黑色**——任何路径上不存在两个连续的红结点；
5、**从任一结点到其每个叶子结点（NULL）的所有路径含相同数目的黑色结点**（黑路同）。
把 3-节点、4-节点拆开："高位元素黑、低位元素红、红线相连"——**红黑树就是 2-3-4 树**，性质 5 对应 B 树叶结点等高（绝对平衡）。按红孩子的位置可细分：左倾红黑树（红只能当左孩子，黑结点带单左红子或双红子两种状态）、右倾红黑树（镜像）、AA 树（红只能当右孩子，仅一种状态，可视作 2-3 树的演化）。

**为什么**：性质 3+4 限制了红结点数量，性质 5 保证黑高一致 → 任何路径不会比别的路径长出一倍以上，整体高度被压在 O(logn)，BST 的退化被杜绝（三结点单链在红黑树中不可能出现）。

**怎么用**——先把 2-3-4 结点拆成红黑形态，再练"数黑路同"：
```text
3-节点 [10 20] ⇔ 黑 20 带红 10：    4-节点 [10 20 30] ⇔ 黑 20 带双红：
    (B 20)                              (B 20)
    /     \                             /     \
(R 10)   NIL                        (R 10)   (R 30)
                                    /   \    /   \
                                  NIL   NIL NIL  NIL

在右图上验证性质 5（NULL 也算黑）：
  20→10→左NULL：黑结点 {20, NULL} → 2 个
  20→10→右NULL：黑结点 {20, NULL} → 2 个
  20→30→NULL ：黑结点 {20, NULL} → 2 个（10、30 是红，不计）
  条条路都是 2 个黑 → 性质 5 成立 ✓
```
验证一棵树是否红黑树：先查性质 1~4（快速），再对每个结点到每个 NULL 叶子数黑结点（性质 5，别忘数 NULL 自己）。

| 对比 | 二叉排序树BST | 红黑树RBT |
|------|--------------|-----------|
| 有序性 | 有（左<根<右） | 有（左<根<右） |
| 平衡性 | 无保证，可退化成链表 | 弱平衡，h≤2lg(n+1) |
| 复杂度 | 平均 O(logn)，最坏 O(n) | 稳定 O(logn) |
| 维护成本 | 无 | 插删需变色/旋转 |

> ⚠️ 注意事项：NULL 结点默认按黑色处理；"不相邻红"指的是红结点的父亲和孩子都不能是红结点。

> 🎯 规律：别死背性质，记模型——一个黑结点连同它的红孩子就是 2-3-4 树的一个结点，性质全是这条的推论。

> 💡 一句话总结：左根右、不红红、黑路同。

### 4. 黑高 bh 与高度上界 h≤2lg(n+1)

**是什么**：黑高就是"只数黑结点的高度"——黑结点在每条路上一样多，是树的钢筋骨架，红结点只是挂在骨架上的装饰（性质 4 限死它连不成串）。**黑高 bh(x)** = 从结点 x 出发（**不含 x 自己**）到其任一叶子结点（NULL）的简单路径上的黑色结点数目；**树的黑高 = 根结点的黑高**，也等于对应 2-3-4/B 树的高度。

**为什么**：由性质 4（无连续红）红结点至多占路径一半 → 黑高 **bh ≥ h/2**；由性质 5 所有路径黑结点数相同 → 黑高一致。由性质 3、4 可得重要结论：**一个结点到其最远后代叶结点的顶点数目，不超过到最近叶结点数目的 2 倍**。

**怎么用**——先拿小树数一遍黑高，再推上界。数黑高（口诀：起点不算、NULL 要算）：
```text
        (B 20)        bh(20)：走 20→10→NULL，黑结点 = {NULL} 共 1 个
       /      \       bh(30)：走 30→NULL，黑结点 = {NULL} 共 1 个
   (R 10)   (R 30)    bh(10)：10 是红，黑高与父结点相同 = 1
   /   \     /   \    树的黑高 = 根的黑高 = 1
 NIL   NIL NIL  NIL   对照：h = 2，bh = 1，恰好取等 bh ≥ h/2
```
推导 n 个结点红黑树的高度上界：
```text
黑高为 bh 的红黑树没有红结点时结点最少（恰为满二叉树）：
    n ≥ 2^bh − 1   →   bh ≤ log₂(n+1)
又 bh ≥ h/2：
    h/2 ≤ log₂(n+1)   →   h ≤ 2log₂(n+1)
```
即所有操作（查找、插入、删除、最大、最小）稳定 O(logn)。

> ⚠️ 注意事项：数黑高时"起点不算、NULL 要算"；bh(6)=2 与 bh(15)=2 可以相等——红结点的黑高与父结点相同。

> 🎯 规律：算结点下界先抓"最瘦"的树——没有红结点时恰为满二叉树；别的树只会更胖，所以 n ≥ 2^bh − 1 稳稳成立。

> 💡 一句话总结：黑高起点不算，高度不超两倍最短。

### 5. 旋转：左旋与右旋（一切调整的基石）

**是什么**：旋转就是"孩子上位换父亲"：让一边的孩子顶上来当新家长，旧父亲带着另一侧搬到旁边去——树依然有序，只是左右两边的"重量"换了边。左旋：结点 x 的右孩子 y 顶上来，x 变成 y 的左孩子，y 原来的左子树交给 x 当右子树。右旋：镜像——左孩子 y 顶上来，x 变 y 的右孩子，y 原来的右子树交给 x 当左子树。

**为什么**：AVL 靠左旋右旋修高度差；红黑树里旋转负责"调整结构"，变色负责"调整颜色"，两者配合完成 2-3-4 树的分裂（插入一个右孩子再左旋变色 = 2-3-4 树的 3 节点；三个元素成一线再旋 = 形成 4 节点……）。

**怎么用**——先用具体数字走一遍右旋，再对照代码（颜色跟着结点走，旋转本身不动颜色）：
```text
对 30 右旋（y=20 是 30 的左孩子）：
        (B 30)                  (B 20)
        /    \                  /    \
    (R 20)  (B 40)    →     (B 10)   (R 30)
    /   \                           /    \
 (B 10) (B 25)                  (B 25)  (B 40)

对号入座：① y=20 上位，接替 30 的位置（连父亲关系一起接管）；
② 30 下沉，成为 20 的右孩子；③ 20 原来的右孩子 25 过继给 30 当左孩子。
中序序列 10-20-25-30-40 旋转前后不变——旋转只改结构，不破坏有序性。
```
以右旋为例（配套代码，含双亲指针维护）：
```c
// 在以 root 为根的树中对 x 右旋：y 是 x 的左孩子
RBTNode* y  = x->l;
RBTNode* fx = x->pa;          // x 的父亲
x->l = y->r;                  // y 的右子树过继给 x
if (y->r) y->r->pa = x;
y->r = x;  x->pa = y;         // x 下沉为 y 的右孩子
y->pa = fx;                   // y 接管 x 的父亲位置
if (!fx) root = y;            // x 原是根 → y 成为新根
else (fx->l==x) ? (fx->l=y) : (fx->r=y);
```
左旋对称：`y=x->r; x->r=y->l; ... y->l=x;`。

> ⚠️ 注意事项：旋转后别忘三处双亲指针（x->pa、y->r->pa、y->pa）和根结点替换；空树/无父亲分支要特判。

> 🎯 规律：旋转不改变中序序列，只动三处指针——"孩子上位、孙儿过继、父亲认新"。

> 💡 一句话总结：孩子上位，孙儿过继，父亲认新。

### 6. 红黑树的插入操作与调整

**是什么**：一句话：新结点先染红（红不破坏黑路同），之后只解决"红红相邻"这一个问题——看叔叔的脸色行事。插入 = BST 插入 + 着色（比 AVL 多一个"重新着色"手段）。约定：**新插入结点必须是红色**（不破坏黑路同），若是根则染黑。出现不平衡（父子连续红，破坏"不红红"）时**先考虑重新着色，不行再旋转**，按**叔叔结点 u 的颜色**分情况（叔叔 = 父亲的兄弟，即祖父 g 的另一个孩子）。设 x 新结点、p 父、g 祖父、u 叔叔：

| 前提 | 情形 | 处理 |
|------|------|------|
| p 是黑色 / x 是根 | — | 不调整 / 根染黑 |
| p 红、**u 红** | 叔红 | p、u 变黑，g 变红，**把 g 当新 x 向上重复**（g 为根时染黑结束） |
| p 红、**u 黑** | LL（p 是 g 左孩子且 x 是 p 左孩子） | 右旋 g，交换 g、p 颜色（p 黑 g 红） |
| | LR（p 是 g 左孩子且 x 是 p 右孩子） | 先左旋 p 转成 LL，再右旋 g，x 黑 g 红 |
| | RR（p 是 g 右孩子且 x 是 p 右孩子） | 左旋 g，交换 g、p 颜色（p 黑 g 红） |
| | RL（p 是 g 右孩子且 x 是 p 左孩子） | 先右旋 p 转成 RR，再左旋 g，x 黑 g 红 |

**为什么**：叔红时三红线挤在一层，等价于 2-3-4 树临时 4 节点变 5 节点，中间元素上浮=变色最省事；叔黑时无法只靠变色，等价于需要"拆结点"，用旋转换形。LL/RR 一旋到位，LR/RL 得先"掰直"再旋。

**怎么用**——两种情形各走一个小例子，再记全流程。

【叔红变色】在 (B 20) 带两个红孩子的树（即 4-节点 [10 20 30] 的红黑形态）中插入 5：
```text
第1步 5<20 走左、5<10 走左，挂到 10 左下，染红
第2步 父 10 红、叔 30 红 → 叔红：p=10、u=30 变黑，g=20 变红
第3步 20 是根 → 按性质 2 染黑，结束；黑高由 1 变 2（对应 5-节点分裂、根上浮）

    (B 20)                    (B 20)
   /      \                  /      \
(R 10)   (R 30)    ───→   (B 10)    (B 30)
 /                           /
(R 5)                      (R 5)
```

【叔黑旋转 LL】在 (B 20) 带左红孩 10（右孩子是 NULL，算黑）的树中插入 5：
```text
第1步 5 挂到 10 左下，染红；父 10 红、叔 = NULL（黑）→ 叔黑 LL
第2步 x、p 都是左孩子 → 对 g=20 右旋，再换色：10 变黑、20 变红
第3步 一次调整结束（2-3-4 视角：3-节点 [10 20] 插 5 → 4-节点 [5 10 20]）

    (B 20)                    (B 10)
    /                        /      \
(R 10)          ───→     (R 5)     (R 20)
 /
(R 5)
```

插入全流程（对应代码 Insert + Fixup）：
```text
1. 标准 BST 插入，新结点 z 染红          → 满足顺序性
2. z 是根 → 染黑（整树黑高 +1）
3. 父 p 红且 z 非根 → Fixup：
   while (p 存在且 p 红)：
     叔红：p/u 变黑，g 变红，z = g 上溯
     叔黑：LL/RR 单旋（p 黑 g 红）后 break
           LR/RL 双旋（z 黑 g 红）后 break
   若上溯到根（p 为 NULL）→ 根染黑
```

| 对比 | 叔叔红 | 叔叔黑 |
|------|--------|--------|
| 本质（2-3-4树） | 临时结点上浮分裂 | 需拆分结点 |
| 手段 | 只变色（p、u 黑，g 红） | 旋转 + 变色 |
| 是否上溯 | 是，g 作新 x 继续 | 否，一次调整完 break |
| 记忆 | 叔红变色往上爬 | 叔黑旋转变色一刀切 |

> ⚠️ 注意事项：叔叔黑不代表叔叔存在——NULL 也算黑；连续插三个元素在 2-3-4 树里都汇成 4 节点，红黑树最终形态必是"黑根带两个红孩子"；插第四个元素对应 5 节点分裂，需一连串旋转变色。

> 🎯 规律：先看叔叔定手段（红→只变色上溯，黑→旋转收尾），再看父子方位定型号（LL/LR/RR/RL）。

> 💡 一句话总结：插入染红看叔叔，叔红变色叔黑旋。

### 7. 红黑树的删除操作与调整（双黑）

**是什么**：一句话：插入怕"多了红"，删除怕"少了黑"——少掉的那个黑记作"双黑"，全部调整都是为了把它销掉。删除与插入同用"变色 + 旋转"，区别：**插入看叔叔，删除看兄弟**。插入最易破坏性质 4（连续红）；删除最易破坏性质 5（删黑结点使黑高降低）。核心概念**双黑（Double Black）**：删除黑色结点 v 且被其黑色孩子 u 顶替时，u 被标记为双黑（v 的黑色"留"在了 u 身上）；删除的主要任务就是**把双黑变回普通单黑**。设 v 被删结点、u 顶替结点、s 兄弟（代码记 w；兄弟 = 双亲的另一个孩子）、p 父、r 是 s 的红孩子：

| 步骤 | 情形 | 处理 |
|------|------|------|
| ① 标准BST删除 | 度为 2 | 用中序后继的数据替换，转成删后继（最终删的一定是度 1/0 的结点） |
| ② 简单情况 | u 或 v 是红色 | 把顶替结点 u 染黑即可（黑高不变；v 是 u 的父，二者不会同时红） |
| ③ 复杂情况 | 双黑且 u 是根 | 双黑直接变单黑，**整树黑高 −1** |
| | a) s 黑且至少一个红孩子 | **LL**（s 是 p 左孩，r 是 s 左孩）：s 取 p 色→右旋 p→r、p 变黑；**LR**（r 是 s 右孩）：先左旋 s（转成 LL）再按 LL；**RR / RL** 镜像 |
| | b) s 黑且两个孩子都黑 | s 变红，双黑上移给 p：p 红→p 变黑结束（**红 + 双黑 = 单黑**）；p 黑→p 成新双黑**继续向上循环**；到根走③ |
| | c) s 是红色 | 此时 p 必黑、s 的孩子必黑。s 是 p 左孩→右旋 p；s 是 p 右孩→左旋 p；旋转后 p、s 换色（s 黑 p 红）→ 新兄弟必为黑 → 转 a) 或 b) |

**为什么**：双黑的本质是这条路径比兄弟路径"少了 1 个黑"。a) 借兄弟子树的红结点转上来补黑（一次旋转永久解决）；b) 兄弟也帮不上，只能把"缺黑"上抛给父亲，等价于 2-3 树删除 2-节点叶子时的向上合并；c) 兄弟是红没法直接借，先旋一步把兄弟换成黑的。

**怎么用**——先跟着走一遍最经典的 b) 型（兄弟帮不上、双黑上抛），再记全流程。删黑色叶子 10：
```text
第1步 v=10 是黑叶，u=NULL 顶替它 → 10 的黑"留"在 u 上，u 成双黑
第2步 s=30 黑、两个孩子全黑（都是 NULL）→ b) 型：s 变红，双黑上移给 p=20
第3步 p=20 是黑 → 20 成新双黑；20 已是根 → 双黑直接变单黑，整树黑高 −1

      before                          after
       (B 20)                          (B 20)
      /      \            ───→             \
   (B 10)   (B 30)                        (R 30)
   ↑ v=10，删它
```
双黑是怎么记到账上的（把第1步放大看）：
```text
   (B 20)                       (B 20)
  /      \         删 10       /       \
(B 10)  (B 30)    ────→   NIL(双黑)  (B 30)
经过 NIL(双黑) 的路径比经过 30 的路径少 1 个黑——
这个亏空就是"双黑"，后面所有调整都在设法把它销掉
```
删除全流程（对应代码 Delete + DE_Fixup）：
```text
1. FindNode 找到 y；度 2 → 后继 data 复制，转删后继
2. x = y 唯一的孩子（可为 NULL），x 顶替 y，free(y)
3. 记录 y 的颜色：yc == RED → 结束；yc == BLACK → DE_Fixup
   while (x != root 且 x 是黑/NULL)：
     w 红 → 对 p 旋转 + 换色（转成兄弟为黑）
     w 两孩全黑 → w 变红，x = p 上溯
     w 有红孩子 → LR/RL 先转 LL/RR，再 w 取 p 色、
                  旋转 p、r 与 p 变黑，break
   最后 x 是红 → x 染黑
```

| 对比 | 删除看兄弟s黑（a型） | 删除看兄弟s黑（b型） | 删除看兄弟s红（c型） |
|------|---------------------|---------------------|---------------------|
| 条件 | s 黑、有红孩子 r | s 黑、两孩全黑 | s 红 |
| 手段 | 旋转 + 变色，一次搞定 | s 变红，双黑上移递归 | 旋转换色转 a/b |
| 结束 | 双黑当场消除 | 父红即停，到根减黑高 | 不直接结束 |

> ⚠️ 注意事项：删红结点（无论叶还是带一个黑孩子）都不需要调整；双黑上溯途中 p 变双黑后 p 的红孩子会"吸收"双黑（红+双黑=单黑）；双黑到根意味着整棵树黑高减 1，这是红黑树唯一降黑高的途径。

> 🎯 规律：双黑 = 这条路径欠一个黑；兄弟有红就借来转（a 型一次解决），借不到就向上抛（b 型递归），兄弟是红先旋成黑再借（c 型转 a/b）。

> 💡 一句话总结：删除看兄弟，双黑借黑往上抛。

### 🧩 本章归纳：一条主线串全章

一条主线：**BST 退化 → 找到绝对平衡的模型（2-3-4树）→ 把模型翻译成二叉树（红黑树）→ 用"变色 + 旋转"维护翻译的等价性**。回头看，全章的每个口诀都能在 2-3-4 树里找到原型：

| 动作 | 2-3-4 树里的原型 | 红黑树里的表达 |
|------|------------------|----------------|
| 插入 | 临时结点装满 → 中间元素上浮分裂 | 叔红 = 变色上溯（上浮）；叔黑 = 旋转换形（拆结点） |
| 删除 | 结点被掏空 → 向兄弟借、借不到与父亲合并 | 双黑：a 型借黑（旋转）、b 型向上合并（递归）、c 型先换黑再借 |
| 变高/变矮 | 分裂根结点 / 合并到根 | 变色传到根再染黑（黑高+1）/ 双黑到根（黑高−1） |

跨知识点的三条共性规律：
1. **所有平衡树 = 加约束 + 破坏时修复**：AVL 约束高度差，红黑树约束颜色；插删破坏约束后，修复时共用同一套旋转。
2. **变色管"账面"，旋转管"结构"**：能只动颜色解决的绝不动结构（叔红变色、b 型只染红兄弟），结构非动不可才旋转（叔黑、a 型；c 型只是先把兄弟换成黑的）。
3. **黑高是全章的度量衡**：性质 5 定死黑高，由 bh ≥ h/2 推出 h ≤ 2lg(n+1)；黑高全章只有两个变化时机——变色传到根（+1）与双黑到根（−1）。

### 组1：红黑树 vs AVL树

| 对比维度 | 红黑树 RBT | AVL 树 |
|----------|-----------|--------|
| 各自定义 | 满足 5 条颜色性质的自平衡二叉排序树 | 任意结点左右子树高度差≤1 的二叉排序树 |
| 核心区别 | **弱平衡**：最长路径≤最短路径 2 倍 | **强平衡**：高度差≤1，相同结点数时 AVL 高度≤红黑树 |
| 各自特点 | 每结点只多 1 个存储位存颜色；插入最多 2 次旋转、删除 O(1) 次调整居多 | 每结点存平衡因子/高度；插删可能触发 O(logn) 次旋转 |
| 使用场景 | 插入删除频繁（map/set、TreeMap/TreeSet、Linux CPU 完全公平调度、epoll） | 插删少、查找相对频繁的场景 |
| 典型示例 | 按序插入 1,2,3 不会退化，靠变色+一次旋转复原 | 插入 1,2,3 立即触发旋转保持严格平衡 |
| 记忆口诀 | 查多选 AVL，改多选红黑 | |

### 组2：插入调整 vs 删除调整

| 对比维度 | 插入调整 | 删除调整 |
|----------|----------|----------|
| 各自定义 | 新结点染红后修复"不红红"的过程 | 删除结点后修复黑高/双黑的过程 |

| 使用场景 | Insert 后 `Fixup(z)` | Delete 后 `DE_Fixup(x, p)` |

### 组3：左旋 vs 右旋

| 对比维度 | 左旋 | 右旋 |
|----------|------|------|

| 典型示例 | `LeftRotate(g)` 后 g 变 y 的左孩子 | `RightRotate(g)` 后 g 变 y 的右孩子 |
| 记忆口诀 | 左旋右娃上位，右旋左娃上位 | |

### 组4：黑高 bh vs 树高 h

| 对比维度 | 黑高 bh | 树高 h |
|----------|---------|--------|
| 各自定义 | 从 x（不含 x）到 NULL 叶结点路径上的黑色结点数 | 从根到最远叶结点路径上的结点数 |
| 核心区别 | 只数黑结点，全树处处相等（性质5） | 数所有结点，随红结点分布波动 |

| 使用场景 | 推导高度上界、验证性质 5 | 分析操作复杂度 O(h) |
| 典型示例 | bh(6)=2，bh(红15)=2 | n 结点最坏 h≈2lg(n+1) |
| 记忆口诀 | 黑高看黑不算己，树高看全最多黑两倍 | |

## 📋 速查表

### 5条性质（左根右、不红红、黑路同）
```text
1. 每个结点要么红色要么黑色
2. 根结点是黑色
3. 所有叶子结点（NULL/NIL）是黑色
4. 红色结点的两个孩子必是黑色（路径上无连续红结点）
5. 任一结点到其每个 NULL 叶结点的所有路径，黑色结点数目相同
推论：bh ≥ h/2；最长路 ≤ 2×最短路；n 个结点 h ≤ 2lg(n+1)
```

### 插入情形处理表（新结点染红，p 红才调整）
| 情形 | 判定 | 处理 |
|------|------|------|
| x 是根 | 父为空 | 染黑（黑高+1） |
| p 黑 | — | 不调整 |
| 叔红 | u 存在且红 | p、u 变黑，g 变红，z=g 向上迭代 |
| LL | p 是 g 左孩，x 是 p 左孩 | 右旋 g；p 黑 g 红 |
| LR | p 是 g 左孩，x 是 p 右孩 | 左旋 p → 按 LL；x 黑 g 红 |
| RR | p 是 g 右孩，x 是 p 右孩 | 左旋 g；p 黑 g 红 |
| RL | p 是 g 右孩，x 是 p 左孩 | 右旋 p → 按 RR；x 黑 g 红 |

### 删除情形处理表（删黑产生双黑，看兄弟 s）
| 情形 | 判定 | 处理 |
|------|------|------|
| y 红 | 被删结点红 | 直接删，不调整 |
| y 黑 x 红 | 顶替结点红 | x 染黑 |
| 双黑是根 | x == root | 变单黑，整树黑高−1 |
| c) s 红 | s 是 p 左孩→右旋 p；s 是 p 右孩→左旋 p | 旋转后 p、s 换色 → 转 a) 或 b) |
| a-LL | s 黑、s 是 p 左孩、红孩 r 是 s 左孩 | s 取 p 色 → 右旋 p → r、p 变黑 |
| a-LR | s 黑、s 是 p 左孩、红孩 r 是 s 右孩 | 左旋 s（转 LL）→ 按 a-LL |
| a-RR | s 黑、s 是 p 右孩、红孩 r 是 s 右孩 | s 取 p 色 → 左旋 p → r、p 变黑 |
| a-RL | s 黑、s 是 p 右孩、红孩 r 是 s 左孩 | 右旋 s（转 RR）→ 按 a-RR |
| b) 全黑 | s 黑、两个孩子都黑 | s 变红，双黑给 p：p 红则 p 变黑结束；p 黑则 p 成新双黑继续上溯 |

### 旋转代码模板（含双亲指针）
```c
RBTNode* RightRotate(RBTree root, RBTNode* x){   // 右旋
    RBTNode* y  = x->l;                          // y = 左孩子
    RBTNode* fx = x->pa;
    x->l = y->r;  if(y->r) y->r->pa = x;         // 孙过继
    y->r = x;     x->pa = y;                     // x 下沉
    y->pa = fx;
    if(!fx) root = y;                            // x 原是根
    else (fx->l==x) ? (fx->l=y) : (fx->r=y);     // 接管父亲
    return root;
}                                                // 左旋镜像: y=x->r; x->r=y->l; y->l=x
```

### 插入调整 Fixup 核心骨架
```c
while (p && p->color == RED){
    u = (p == g->r) ? g->l : g->r;
    if (u && u->color == RED){          // 叔红：变色上溯
        p->color = BLACK; u->color = BLACK; g->color = RED;
        z = g; p = z->pa;               // g 作新 z
    } else {                            // 叔黑：旋转后 break
        if (LL){ RightRotate(g);  p->color=BLACK; g->color=RED; }
        if (RR){ LeftRotate(g);   p->color=BLACK; g->color=RED; }
        if (LR){ LeftRotate(p); RightRotate(g); z->color=BLACK; g->color=RED; }
        if (RL){ RightRotate(p); LeftRotate(g); z->color=BLACK; g->color=RED; }
        break;
    }
}
if (!p) root->color = BLACK;            // 上溯到根 → 根染黑
```

### 常用结论
```text
新结点默认红色，根例外染黑            NULL 结点算黑色叶子
插入看叔叔：叔红变色上溯，叔黑旋转     删除看兄弟：双黑借黑、红+双黑=单黑
只有双黑到根 / 分裂根节点 才会改变黑高  应用：map/set、TreeMap/TreeSet、Linux CFS、epoll
```
