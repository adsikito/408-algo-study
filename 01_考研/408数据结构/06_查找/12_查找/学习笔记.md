>
> 配套代码：`折半查找代码/折半查找.c`、`哈希查找代码/开放定址法.c`
>
> 本章主线：**用 ASL 统一衡量查找性能**。线性表上做顺序/折半/分块，哈希表一步到位；必练手算三件套：折半过程、判定树 ASL、哈希冲突处理。

## 🗺️ 本章地图

> **本章解决一个问题：在一张表里找东西，怎样比得最少？**
> 路线是"先立标尺，再逐级升级"：先用最朴素的顺序查找立起标尺 ASL（知识点 1~2）；表有序就能对半砍——折半查找与判定树（3~4），本章手算主战场；整表有序太苛刻，退一步"块间有序"——分块查找（5）；最后换思路：不比较、直接算位置——哈希表与冲突处理（6~9）。
> 前半章靠"比较"，后半章靠"计算"，ASL 把两者放在同一把尺子上；每升一级都要付代价（有序前提 / 索引空间 / 冲突处理），代价与收益的交换就是各节之间的内在关系。

## 📌 本章重点（3-5个）

⭐ **平均查找长度 ASL = Σpi·ci**：衡量查找算法性能的唯一标尺，分"查找成功 ASL"和"查找失败 ASL"两种
⭐ **折半查找**：前提"顺序存储 + 有序"，手算 low/high/mid 缩小区间，O(log n)
⭐ **折半判定树**：n 个圆形结点 + n+1 个方形失败结点，判定树是平衡二叉树，成功/失败 ASL 靠它手算
⭐ **分块查找**：块间有序、块内无序，索引表(块内最大关键字, 块首地址) + 块内顺序查找，两步走
⭐ **哈希冲突处理**：冲突只能缓解不可避免（抽屉原理）；链地址法 vs 开放地址法（线性探测/平方探测/双重哈希），再哈希扩容（α>0.75 二倍扩容）

## 🔥 本章难点（2-3个）

🔥 **判定树的画法与 ASL 计算**：中间位置作根递归构造；成功 ASL = 各层结点数×层数之和 / n；失败 ASL = 挂到 n+1 个方形结点上的比较次数 / (n+1)
🔥 **线性探测的聚集问题与 lazy delete**：冲突元素连成一片使探测越来越长；删除只能"懒删除"标记，直接置空会截断探测链导致后续元素找不到
🔥 **再哈希（rehash）全过程**：每次插入检查装填因子 α=n/m，α>0.75 触发；新建 2 倍大数组，用新哈希函数把所有元素重新散列一遍

## ⚠️ 本章易错点（3-5个）

⚠️ **折半查找前提记漏**：必须"顺序存储 + 按关键字有序"；课件强调：不能说折半查找"不能"用于链式存储，只是顺序表设计更方便、效率更高
⚠️ **区间收缩写错**：循环条件是 `l <= r`（区间至少一个元素）；命中不了必须 `r=mid-1` / `l=mid+1`，写成 `l<r` 或漏 ±1 会死循环、漏解
⚠️ **顺序查找优化记反**：被查概率大的放靠前只缩短**查找成功**的 ASL，**查找失败**的 ASL 不变
⚠️ **哈希删除直接置空**：开放地址法中把槽清空，探测链从此断掉，排在其后的同义词再也查不到；正确做法是 lazy delete（清数据不释放，查找时跳过）
⚠️ **链地址法最坏复杂度**：所有元素堆进同一条链时退化为 O(n)（概率微乎其微）；且冲突"只能缓解、不可避免"——哈希函数是把大空间映射到小空间，抽屉原理保证必撞

## 📖 知识点讲解

### 1. 查找的基本概念与 ASL

**是什么**：查字典不会从第一页翻到最后一页，而是先估"该翻哪一段"——**各种查找算法的全部差别，就在于"怎么缩小比较范围"**。严格地说：查找就是在数据集合中找满足条件的数据元素。**静态查找**：数据集合稳定，不需添加、删除元素；**动态查找**：查找过程中需要同时添加或删除元素。**关键字(key)**：数据元素（记录）中某个数据项的值，可唯一标识一个元素。整个查找都在内存中进行称**内查找**，需要访问外存称**外查找**。**平均查找长度 ASL**（Average Search Length，平均要比多少次关键字才能命中）= Σ(i=1..n) pi·ci，n 为表长，pi 为查找第 i 个元素的概率（通常相等 p=1/n），ci 为找到第 i 个元素所需的比较次数。ASL 分查找成功（Σpi=1）与查找失败（m 种失败情况，Σqi=1）两种。

**为什么**：查找的时间主要花在关键字比较上，ASL 越大时间性能越差、越小越好，所以它是衡量查找算法好坏的统一指标。

**怎么用**：静态查找 → 线性表组织数据，用顺序查找；排好序可升级为折半查找、斐波那契查找。动态查找 → 二叉排序树、散列表。

**跟着算**——4 元素顺序表 `[7, 3, 9, 5]`，等概率（p=1/4）顺序查找：
第1步 数出每个元素的比较次数 ci：找 7 比 1 次、找 3 比 2 次、找 9 比 3 次、找 5 比 4 次；
第2步 成功 ASL = (1+2+3+4)/4 = 10/4 = **2.5**——n=4 时正好等于 (n+1)/2；
第3步 找 99（失败）：4 个全比过才敢说"没有"——失败要看全表，与元素怎么排无关。

> ⚠️ 注意事项：算 ASL 先分清"成功/失败"两种口径，别混算；pi 不相等时 ASL 要按实际概率加权。

> 🎯 规律：算 ASL 万能三步——给每个元素数比较次数、按概率加权、成功与失败分开口径。

> 💡 一句话总结：ASL 是查找性能的统一标尺。

| 对比 | 静态查找 | 动态查找 |
|------|---------|---------|
| 集合是否变化 | 稳定，不含插删 | 查找中伴随插删 |
| 常用结构 | 顺序表（有序/无序） | 二叉排序树、散列表 |
| 关注点 | 查得快 | 插删查都快 |

### 2. 顺序查找

**是什么**：闭卷考场找人、手里又没有座位表，只能一排排问过去——顺序查找就是这种"笨办法里的保底办法"。正式说：顺序查找（Sequential Search）又叫线性查找（Linear Search），最基本：从表中第一个（或最后一个）记录开始，逐个把记录的关键字与给定值比较，相等则成功；全部比完仍不相等则失败。

**为什么**：它对存储无要求（顺序、链式都行，表无需有序），是"保底"算法；代价是 O(n)，n 大时太慢。

**怎么用**：逐个扫描即可。**优化**：各元素被查概率不等时，把概率大的放在靠前位置——查找成功时 ASL 进一步缩短；查找失败的 ASL 没有改变。

**跟着算**——表 `[12, 45, 8, 30]`：查 30 要比 12、45、8、30 共 4 次；查 99 也要 4 次才知道失败。若 45 是"热门元素"，把它挪到第 1 位后查它只需 1 次，但查 99 失败仍是 4 次——**重排只赚"成功"的便宜，失败照旧扫全表**。

> ⚠️ 注意事项：优化只影响成功 ASL；失败仍然要扫全表。

> 🎯 规律：无序表没有"结构红利"，性能只能靠按概率重排元素来挖掘。

> 💡 一句话总结：逐个比，概率大的放前头。

### 3. 折半查找（二分查找）——必考手算

**是什么**：猜 1~100 之间的数字，每次猜中间那个数、根据"大了/小了"扔掉一半——折半查找就是把这个游戏搬到有序表上。正式说：折半查找先确定待查记录所在的范围（区间），取区间中间位置 mid 的记录与给定值比较：相等则成功；不等则缩小一半区间继续，直到找到或**区间大小小于零**（查找失败）为止。前提：**有序表 + 顺序存储（随机存取）**。它也是分治思想的很好例证。

**为什么**：要求随机存取是因为必须方便地定位查找区域；链式存储无法 O(1) 取中点，效率低。

**怎么用**——先用 7 元素小表走一遍建立手感，再看课件大例。

**跟着算**：有序数组 `[10, 20, 30, 40, 50, 60, 70]`（下标 0~6），查 60：
第1步 low=0，high=6，mid=⌊(0+6)/2⌋=3，a[3]=40 < 60 → 目标在右半，low=mid+1=4；
第2步 low=4，high=6，mid=⌊(4+6)/2⌋=5，a[5]=60，相等 → **2 次比较成功**。
若查 35（失败）：
第1步 mid=3，a[3]=40 > 35 → high=mid-1=2；
第2步 low=0，high=2，mid=1，a[1]=20 < 35 → low=mid+1=2；
第3步 low=2，high=2，mid=2，a[2]=30 < 35 → low=3 > high=2，区间空 → **失败**（3 次）。
每比较一次淘汰一半，7 个元素最多比 3 次——这就是对数复杂度的直观来源。

课件手算范例：有序数组 `[5 13 19 21 37 56 64 75 80 88 92]`（下标 0~10）查找 21：

| 趟 | low | high | mid=⌊(low+high)/2⌋ | a[mid] | 比较结果 |
|----|-----|------|-----|--------|----------|
| 1 | 0 | 10 | 5 | 56 | 21<56 → high=mid-1=4 |
| 2 | 0 | 4  | 2 | 19 | 21>19 → low=mid+1=3 |
| 3 | 3 | 4  | 3 | 21 | 相等，**查找成功**（3 次比较） |

代码模板（配套 `折半查找.c`，下标 1~n，查不到 ans=-1）：

```c
int l = 1, r = n, ans = -1, mid;
while (l <= r) {              // 待查找区间至少有一个数据就继续
    mid = (l + r) / 2;        // 中间位置
    if (k == a[mid]) { ans = mid; break; }
    else if (k < a[mid]) r = mid - 1;   // 往左半区
    else                 l = mid + 1;   // 往右半区
}
```

> ⚠️ 注意事项：`while(l<=r)` 不是 `l<r`；收缩必须是 `mid±1`（mid 已比较过，不再进区间）；折半仅适合顺序存储且要求元素有序，链式存储不是"不能用"而是设计不便、效率不高。

> 🎯 规律：每比一次排除一半，比较次数 = 目标在判定树中的层数。

> 💡 一句话总结：有序顺序表，对半砍区间。

### 4. 折半查找判定树与 ASL 计算——必考手算

**是什么**：把折半的每一次"取中点、往左还是往右"画成一张地图，就是判定树——层数即比较次数。正式说：折半过程可用二叉树描述：把当前查找区间的**中间位置元素作为根**，左、右子表递归构造为左、右子树——这棵树叫**判定树(decision tree)** 或比较树(comparison tree)。圆形结点 = 记录（关键字值），最下面的**方形叶结点 = 查找失败的情况**。有 n 个元素的判定树有 **n 个圆形结点 + n+1 个方形结点**，且判定树是**平衡二叉树**。判定树形态只与 n 有关，与元素值无关。

**为什么**：成功查找长度 = 根到目的结点路径上的结点数；失败查找长度 = 根到对应失败结点**父结点**路径上的结点数。有了层数就能手算 ASL。

**怎么用**——先拿知识点 3 的 7 元素表练手，再上课件 11 元素大例。

**跟着算**：`[10, 20, 30, 40, 50, 60, 70]` 的判定树（□ 为方形失败结点）：

```
              40                  ← 第 1 次比较
           /      \
         20        60              ← 第 2 次
        /  \      /  \
      10   30   50    70           ← 第 3 次
     /\   /\   /\    /\
    □ □  □ □  □ □   □  □          ← 失败结点共 n+1 = 8 个
```

第1步 成功 ASL：1 层 1 个结点、2 层 2 个、3 层 4 个 → (1×1 + 2×2 + 3×4)/7 = 17/7 ≈ **2.43**；
第2步 失败 ASL：8 个方形结点全挂在 3 层圆形结点下，比较次数 = 其父结点层数 3 → (3×8)/8 = **3**；
第3步 对照体会：失败略贵，因为失败总要比到"确认无路可走"为止。

课件 11 元素表 `[5 13 19 21 37 56 64 75 80 88 92]` 的判定树：

```
深度1:                    56
深度2:            19              80
深度3:        5       21      64      88
深度4:         \13     \37     \75     \92
（每个深度4结点下还挂2个方形失败结点□；5/21/64/88 的空左孩子处各挂1个□）
```

成功 ASL = (1×1 + 2×2 + 3×4 + 4×4) / 11 = 33/11 = **3**
失败 ASL：12 个失败结点中，4 个挂深度 3（3 次），8 个挂深度 4（4 次）= (3×4 + 4×8)/12 = **11/3**

> ⚠️ 注意事项：失败结点计数 = n+1 个，别漏挂空指针的位置；每个结点值大于左子树、小于右子树（判定树本身是 BST + 平衡）。

> 🎯 规律：成功数"圆结点层数"、失败数"方结点父结点层数"，分母分别是 n 和 n+1。

> 💡 一句话总结：中点做根分层算，失败挂方形结点。

### 5. 索引存储结构与分块查找

**是什么**：字典就是"拼音目录 + 分章节的正文"：先翻目录定章节，再进章节逐页翻——分块查找把这套搬到查找表上。正式说：**索引存储结构** = 存储数据的同时建立附加的**索引表**，索引项一般形式为 **(关键字, 地址)**：关键字唯一标识一个结点，地址指向该关键字对应结点（可以是相对地址如数组下标）。查关键字先在索引表快速查找（索引表按关键字有序，可折半），再由地址取主表元素。**分块查找**又称索引顺序查找，是它的典型应用：把查找表分成若干子块，**块内可以无序，块之间有序**（第 1 块最大关键字 < 第 2 块所有关键字 < …）；索引表记录**各块最大关键字 + 各块第一个元素的地址**，按关键字有序。

**为什么**：索引换来效率，代价是建立索引表增加时间和空间开销。分块吸取顺序查找和折半查找各自的优点：**既有动态结构，又适于快速查找**。

**怎么用**——先看小例，再走课件例。两步走：① 在索引表中确定待查记录所在的块（索引表可顺序查或折半查）；② 在块内顺序查找。

**跟着算**：主表 `[6, 3 | 12, 9, 15 | 21, 18]`，索引表 `[6, 15, 21]`（各块最大关键字，有序）。查 18：
第1步 查索引表（顺序）：18>6、18>15、18≤21 → 落在第 3 块（3 次比较）；
第2步 第 3 块 `[21, 18]` 内顺序找：21≠18、18=18 → 成功（2 次）。
全程 3+2 = 5 次；块越大索引表越短、块内越慢，块数与块长是一对此消彼长的旋钮。

```
索引表(有序，可折半)：  [ 6 ]     [ 15 ]     [ 21 ]
                        |          |          |
主表(块内无序，顺序找)： 6  3  |  12  9  15  |  21  18
                       └─块1─┘   └──块2──┘   └─块3─┘
```

课件例子：索引表 `10[0,1] 20[2,5] 30[6,8] 40[9,10] 50[11,13]`，主表 `7 10 | 13 19 16 20 | 27 22 30 | 40 36 | 43 50 48`。查 22：22<30 且 ≥20 → 落在第 2 块 [2,5]，块内顺序找到 22。

> ⚠️ 注意事项：块内无序所以块内只能顺序查找；折半只能用在"有序"的那张表（索引表）上。

> 🎯 规律：哪里有序就把"快查"用在哪里——索引表有序可折半，块内无序只配顺序扫。

> 💡 一句话总结：块间有序定块，块内顺序翻找。

### 6. 哈希表与哈希函数

**是什么**：把"查找"从"逐个比较"换成"算一下位置"——像通讯录按姓名直接算出该翻哪一页，翻到即中。动机——用"直接访问表"（以关键字本身做数组下标）插/查/删都是 O(1)，如 `arr[15000000000] = 0xFF0A`；但空间浪费巨大、且整型根本存不下 11 位电话号。**哈希是对直接访问表的改进**：用**哈希函数**（把关键字翻译成数组下标的公式）把大数或字符串映射为一个较小的整数（**哈希值**，即算出来的下标）作为下标；存记录指针的数组就是**哈希表**。一个好的哈希函数应满足四个条件：
1. **效率高**：很长的字符串/二进制文本也能快速算出哈希值；
2. **同一性**：散列结果尽量均匀，越均匀冲突越少（如电话号取后四位比前四位更有区分性）；
3. **雪崩效应**：输入微小变化引起输出巨大变化（`"I love J"` 与 `"I love Y"` 只差一个字母，MD5 输出千差万别）；
4. **不可反向推导**：从哈希值推不出原始数据（MD5/SHA 即此类算法）。

**为什么**：哈希换来"一步定位"，但把大空间压进小空间必然撞车——见知识点 7。

**怎么用**：除数取余法最常用：`H(key) = key MOD p`，配套代码 `开放定址法.c` 用 `Hash(key)=key%13`、表长 15。小例感受"一步定位"：H(key)=key%7 时，50→1、76→6——一个元素都还没比，位置已经算出来了。

> ⚠️ 注意事项：MD5、SHA 都是历史悠久且不可逆的 Hash 算法；哈希值相同不代表原文相同。

> 🎯 规律：哈希把"找"变成"算"，比较次数换成一次函数求值；代价是大空间压小空间、必撞车。

> 💡 一句话总结：大键压小下标，一步定位。

### 7. Hash 碰撞与链地址法

**是什么**：两个人被分进同一个抽屉，就叫冲突——两个不同输入被映射到同一输出，且新插入值落到了**已被占用的槽**，就产生了 **Hash 碰撞（冲突）**。冲突**只能缓解，不可避免**——输入空间远大于哈希空间，由**抽屉原理**（n+1 个元素放进 n 个集合，必有集合 ≥2 个元素；十个苹果放九个抽屉，必有抽屉 ≥2 个）保证必撞。**链地址法**：把所有发生碰撞的元素用**单链表**串起来（样式与图的邻接表存储相似）。

**为什么**：链表天生可增长，插入删除只动指针，不用挪动其他元素。

**怎么用**——先用 3 个互相冲突的元素建立手感，再看课件大例。

**跟着算**：表长 7，H(key)=key%7，插入 1、8、15（三者 %7 都等于 1）：
第1步 插 1：1%7=1，1 号槽空 → 直接放；
第2步 插 8：8%7=1，撞上 1 → 新结点链到 1 后面；
第3步 插 15：15%7=1，再撞 → 链到 8 后面。

```
1 号槽: [1] → [8] → [15]
```

第4步 查 15：到 1 号槽沿链比 1、8、15 → 3 次命中——**比较次数 = 它在链中的位置**。

课件范例：`H(key) = key MOD 7`，依次插入 `[50, 700, 76, 85, 92, 73, 101]`：
50%7=1、700%7=0、76%7=6 不冲突直接放；85%7=1 撞 50 → 链到 50 后；92%7=1 → 接 85；73%7=3 放；101%7=3 → 链到 73 后。最终：

```
0: 700
1: 50 → 85 → 92
2:
3: 73 → 101
4:
5:
6: 76
```

**优缺点**（课件 4+4 条）：
- 优点：① 实现起来简单；② 哈希表永远不会溢出，可向单链表加更多元素；③ 对哈希函数和装填因子的选择没啥要求；④ 在不知道要插入和删除关键字多少和频率的情况下，链地址法有绝对优势。
- 缺点：① 用链表存储关键字，**缓存性能不佳**（开放寻址法用连续地址空间，缓存性能更好）；② 浪费空间（有些槽位从未被使用）；③ 链表太长时最坏查找退化为 O(n)；④ 需要额外空间存链表指针。

**性能**：设槽位数 m、关键字数 n，**装填因子(load factor) α = n/m**（表里已经放了几成满）。期望查找、插入、删除时间均为 **O(1 + n/m)**；当 n/m 为 O(1) 量级时即 O(1)。极端情况 n 个数全进同一槽成单链表则 O(n)，但概率微乎其微。

> ⚠️ 注意事项：链地址法是"冲突的同义词串一条链"，不是每槽一条链。

> 🎯 规律：同义词挂一条链，查找代价 = 链上位置；链只增不挤，表永不溢出。

> 💡 一句话总结：冲突同义词，一链串起来。

### 8. 开放地址法：线性探测 / 平方探测 / 双重哈希

**是什么**：不挂链、撞了就在表内"挪窝"——开放地址法中**所有元素都存放在哈希表内**，必须随时保证槽位数 m ≥ 关键字数 n（必要时复制旧数据**动态扩容**）。冲突了就按规则探下一个位置，共三种：
- **线性探测法**：`Hash(x)%M` 有数据 → 试 `(Hash(x)+1)%M` → 再有 → 试 `(Hash(x)+2)%M` ……
- **平方探测法**(Quadratic Probing)：探测宽度变为 i 的平方：`(Hash(x)+1×1)%M` → `(Hash(x)+2×2)%M` → `(Hash(x)+3×3)%M` ……
- **双重哈希**：需要第二个哈希函数 Hash2(key)，第 i 次探测位置为 `i×Hash2(key)`：`(Hash(x)+1×Hash2(x))%M` → `(Hash(x)+2×Hash2(x))%M` ……

**为什么**：线性探测缓存性能最佳、易于计算，但受**原始聚集(primary cluster)** 之害——发生碰撞的元素紧挨成组（如课件表中 50,85,92,73,101 因碰撞紧挨着），Hash(key) 落进该段的任意位置都会让聚集更大，探测次数大大增加；平方探测跳着走可缓解聚集。

**怎么用**——用同样 3 个冲突元素，对比链地址法改走"线性探测"的路。

**跟着算**：表长 7，H(key)=key%7，插入 1、8、15：
第1步 插 1：1%7=1 → 放 1 号槽；
第2步 插 8：1 号被占 → (1+1)%7=2 → 放 2 号槽；
第3步 插 15：1、2 号都被占 → (1+2)%7=3 → 放 3 号槽。

```
槽:    0      1      2      3      4     5     6
     [  ]  [ 1 ]  [ 8 ]  [15 ]  [  ]  [  ]  [  ]
             └── 15 的探测轨迹：1 → 2 → 3 ──┘
```

第4步 查 15：从 1 号槽沿**同一条路径** 1→2→3 找到——查找必须能复现插入时的探测路；
第5步 危险动作：若把 8 物理置空，再查 15 → 探到 2 号槽为空就误判"15 不存在"——探测链断了。这正是"懒删除"的由来。

线性探测手算（课件范例 `H(key)=key MOD 7`，同上数组）：
50%7=1、700%7=0、76%7=6 直接放；85%7=1 撞 50 → (85%7+1)%7=2 放；92%7=1 → 2 被占 → 3 放；73%7=3 → 4 放；101%7=3 → 4 被占 → 5 放。最终：

```
0:700  1:50  2:85  3:92  4:73  5:101  6:76
```

配套代码 `开放定址法.c`（Hash=key%13，表长15，nul=-1）：

```c
int Findadd(HashTable *h, int k) {
    int i = Hash(k), d = 0;
    while (h->data[i] != nul) {        // 该位置冲突
        d++;
        i = (Hash(k) + d) % (h->m);    // 线性探测计算新地址
    }
    return i;
}
```

**lazy delete（懒删除）**：删除并不释放存储空间，只清空里面的数据。如删 92：92%7=1 是 50 → 探 2 是 85 → 探 3 恰是 92，清空数据即可。

> ⚠️ 注意事项：开放地址法删元素**不能物理置空**——空槽是探测终止标志，置空后排在它后面的同义词永远查不到；必须 lazy delete。三种探测比较：线性探测缓存性能最佳但受原始聚集影响；平方探测/双重哈希缓解聚集（课件：平方探测对应"二次聚集"概念）。

> 🎯 规律：查找靠复现插入时的探测路径——所以路径上一个"假空位"都不能有（懒删除的本质）。

> 💡 一句话总结：撞了就按规则挪窝。

| 对比 | 线性探测 | 平方探测 |
|------|---------|---------|
| 探测增量 | +1, +2, +3 … | +1², +2², +3² … |
| 缓存性能 | 最佳（顺序访问） | 较差（跳跃访问） |
| 聚集 | 原始聚集严重 | 聚集缓解 |
| 计算 | 最简单 | 简单 |

### 9. 再哈希与哈希的应用

**是什么**：表和人一样，太挤了就搬家——**装填因子 α = 表中填入的记录数 / 哈希表的长度**（表的"拥挤度仪表"）。每次添加新键值对时检查 α，**α > 0.75 就执行再哈希(rehash)**。步骤：① 每次添加新键值对检查装填因子；② α>0.75 触发再哈希；③ 创建一个长度为原来 **2 倍**的新数组；④ 遍历原哈希表所有元素，用**新的哈希函数**重新计算位置插入新数组。

**为什么**：α 越大表越满、冲突概率越高、性能越差；扩容 + 换哈希函数（如 key%7 → key%14）把元素重新摊开。

**怎么用**——先看 4 元素小表感受"重新摊匀"，再看课件大例。

**跟着算**：表长 4，已放 1、5、9（key%4 全落在槽 1，挤成一串）。插入 13 后 α = 4/4 = 1 > 0.75 → 触发再哈希：
第1步 新建长度 8 的数组；
第2步 换哈希函数 key%4 → key%8，逐个重算：1→1、5→5、9→1、13→5；
第3步 结果：原来 4 个全挤一个下标，现在两两分摊——这就是"翻倍 + 换尺子"的意义。

课件范例：7 个元素 [50,700,76,85,92,73,101] 插入大小 7 的表，装填因子从 1/7 涨到 6/7 > 3/4 → 新建长度 14 的数组，改用 `Hash(key)=key%14` 重新散列：700→0、85→1、73→3、76→6、50→8、92%14=8 撞 50 → 9、101%14=3 撞 73 → 链/探测安放。

**哈希的应用**（课件列举）：信息摘要（MD5/SHA）、密码校验、数据结构（C++ `unordered_set/unordered_map`、Java `HashSet/HashMap`、Python `dict`）、编译操作、Rabin-Karp 算法（模式匹配、抄袭检查）、负载均衡（一致性哈希）、数据库（MySQL、Redis）、版本校验/防篡改等。

> ⚠️ 注意事项：再哈希必须"换表 + 换哈希函数"整套重来，不能只扩数组不重散列。

> 🎯 规律：装填因子是拥挤度仪表，超阈值就"翻倍搬家 + 换哈希函数"重新摊匀。

> 💡 一句话总结：太满就翻倍重散。

### 🧩 本章归纳：一条主线串全章

> **主线：查找只有两条路——"逐个比较"或"直接算位置"，全章每一节都是在减少比较次数。**
> 顺序查找无前提、O(n) → 买到"有序 + 顺序存储"就能对半砍：折半 O(log n)，判定树把过程画成地图 → 整表有序太苛刻，退而求"块间有序"：分块两步走 → 干脆放弃比较：哈希函数一步算位置，代价是冲突 → 冲突两大家族：链地址（表外挂链）与开放地址（表内挪窝，删除必须懒删除）→ 表太满（α>0.75）再哈希摊匀。

| 结构 | 前提/代价 | 查找靠什么 | 成功 ASL 量级 |
|------|----------|-----------|--------------|
| 顺序查找 | 无 | 逐个比较 | (n+1)/2 |
| 折半查找 | 顺序存储 + 有序 | 判定树逐层砍半 | ≈log₂(n+1)−1 |
| 分块查找 | 索引表 + 块间有序 | 索引定块 + 块内顺序 | 索引 ASL + 块内 ASL |
| 哈希查找 | 空间换时间 + 冲突处理 | 计算位置 | O(1+n/m) |

回头看才看得见的三条规律：
1. **每升一级都是拿"额外信息"换比较次数**：有序性换折半、索引表换分块、空间换哈希——天下没有免费的快。
2. **ASL 是全章唯一的标尺**：结构怎么变，考法永远是"每个元素比几次、按概率加权，成功/失败分开口径"。
3. **位置会"连锁"的结构，最怕路径断掉**：线性探测不能物理置空、扩容必须整表重散——因为查找靠复现当年的路径。

| 对比维度 | 顺序查找 | 折半查找 |

| 核心区别 | 无前提要求 | 必须顺序存储 + 有序 |
| 各自特点 | O(n)；优化只缩短成功 ASL | O(log n)；需随机存取 |

| 各自特点 | O(log n)，表须静态有序 | 两步走：先定块后块内顺序找 |
| 使用场景 | 建好不动的有序表 | 插删较多（动态结构）又要求较快 |
| 典型示例 | 判定树求 ASL=3 | 索引表 10/20/30 定块查 22 |
| 记忆口诀 | 折半砍一半，分块先锁块 | |

### 组4：链地址法 vs 开放地址法

| 对比维度 | 链地址法 | 开放地址法 |
|----------|---------|-----------|
| 各自定义 | 冲突元素用单链表串在槽后 | 所有元素都存在表内，冲突按规则探测 |
| 核心区别 | 表外挂链 | 表内挪窝，要求 m ≥ n |

| 使用场景 | 插入删除数量与频率未知 | 空间紧凑、查询为主 |
| 典型示例 | [50,700,76,85,92,73,101] mod 7 → 1 号槽 50→85→92 | 同数组线性探测 → 2 号槽放 85 |

### 组5：线性探测法 vs 双重哈希

| 对比维度 | 线性探测法 | 双重哈希 |
|----------|-----------|---------|
| 各自定义 | 冲突后依次探 +1,+2,+3… | 冲突后探 i×Hash2(key) |
| 核心区别 | 步长固定为 1 | 步长由第二个哈希函数决定 |
| 各自特点 | 缓存性能最佳、易计算；原始聚集 | 步长分散、聚集最小；多算一次哈希 |
| 使用场景 | 小表、追求缓存命中 | 大表、聚集敏感场景 |
| 典型示例 | 92 撞 1 → 探 2 → 探 3 落位 | 探测序列随 key 各不相同 |
| 记忆口诀 | 线性顺爬，双哈希蹦跳 | |

## 📋 速查表

### 四种查找性能对照
```
顺序查找  O(n)            ASL成功=(n+1)/2；无前提
折半查找  O(logn)         ASL≈log2(n+1)-1；前提：顺序存储+有序
分块查找  介于两者之间     ASL = 索引表ASL + 块内ASL；块间有序块内无序
哈希查找  期望O(1)        链地址 O(1+n/m)；冲突难免，删除用懒删除
```

### 折半查找模板（配套代码：下标1~n）
```c
int l=1, r=n, ans=-1, mid;
while (l <= r) {                 // 区间还有元素
    mid = (l+r)/2;
    if (k == a[mid]) { ans=mid; break; }
    else if (k < a[mid]) r = mid-1;
    else                 l = mid+1;
}
```

### 折半手算口诀
```
mid = ⌊(low+high)/2⌋；小了往右 low=mid+1，大了往左 high=mid-1
判定树：n 个圆形结点 + (n+1) 个方形失败结点，本身是平衡二叉树
ASL成功 = Σ(层数×该层结点数)/n；失败 = Σ(比较次数×失败结点数)/(n+1)
```

### 分块查找两步
```
①索引表(块最大关键字, 块首地址, 有序) → 顺序或折半定位块
②块内无序 → 只能顺序查找
```

### 哈希三模板
```c
/* 1.哈希函数 */  int Hash(int k){ return k % 13; }   // 除数取余法
/* 2.链地址法 */  冲突：tail->next = 新节点            // 单链表串同义词
/* 3.线性探测 */  while(data[i]!=nul){ d++; i=(Hash(k)+d)%m; }
```

### 开放地址法三种探测公式
```
线性探测：  (Hash(x) + i)        % M,  i = 1,2,3…
平方探测：  (Hash(x) + i*i)      % M,  i = 1,2,3…
双重哈希：  (Hash(x) + i*Hash2(x)) % M
```

### 再哈希四步骤
```
①插入时检查装填因子 α = 记录数/表长
②α > 0.75 触发再哈希
③新建 2 倍长度数组
④全部元素用新哈希函数重新散列（key%7 → key%14）
```

### 易混数字
```
抽屉原理：冲突只能缓解、不可避免
成功/失败 ASL 必分开算；顺序优化不改失败 ASL
开放地址法：m ≥ n；物理置空 = 截断探测链，必须 lazy delete
```
