# 学习笔记模块改进设计方案

> **适用对象**：`C:\Users\freecss\Desktop\资料` 下的 50 篇学习笔记（数据结构 16 篇 + 算法集训 34 篇）
> **设计目标**：提升学习效率、支撑长期复习、便于建立知识体系
> **主用环境**：Obsidian 桌面版（资料库内已存在 `.obsidian` 配置目录）；同时保证在通用 Markdown 编辑器、手机、打印稿中均可读
> **设计日期**：2026-09-12

---

## 零、设计前提：一个必须解决的矛盾

上一轮已确认的排版约定是「**不使用 emoji，仅使用 Markdown 原生语法**」。而本轮需求要求「**支持不同颜色标记**」。Markdown 原生语法不支持颜色，这构成直接冲突。

**本方案的处理办法是分层，而不是二选一：**

| 层 | 内容 | 作用 | 失效后果 |
|----|------|------|---------|
| **第 1 层：语义层** | Markdown 原生语法（标题、加粗、引用块、表格、任务列表、`[P0]` 文字标签） | 承载全部信息，任何环境可读 | 无（这是兜底层） |
| **第 2 层：视觉层** | HTML `<span class>` 与 Obsidian Callout | 提升扫描速度，降低认知负荷 | 颜色丢失，但信息不丢 |

**由此推出一条贯穿全案的硬规则：**

> **【硬规则】颜色永不单独承载信息。**
> 每一处使用颜色的地方，必须同时具备等价的非颜色编码——字重（粗细）或文字标签。
> 这样在**黑白打印**、**色觉障碍**、**导出 PDF**、**GitHub 预览**等场景下，信息一律不丢失。

这条规则也正好解释了「颜色」与「粗细」为何要配合使用：**颜色是类别通道，粗细是强度通道，两者正交，共同编码。**

## 一、颜色标记体系

### 1.1 三个维度必须走三条独立通道

需求提到三个分类维度：**知识点类型**、**重要程度**、**掌握状态**。若三者都用颜色，很快会变成视觉噪声（试想一篇笔记里同时出现九种颜色）。因此拆成三条通道：

| 通道 | 语义维度 | 载体 | 变化频率 | 颜色数量 |
|------|---------|------|---------|---------|
| **通道 A** | 知识点类型（是「什么」） | 块级背景色 + 左侧色条 | 低（内容定稿后不变） | 6 |
| **通道 B** | 重要程度（有多重要） | 行内文字色 + 字重 | 低（考试/赛事要求决定） | 3 |
| **通道 C** | 掌握状态（会不会） | **纯文字标签，不上色** | **高（每次复习都变）** | 0 |

**通道 C 为什么不上色？** 因为它变化最频繁。如果掌握状态带颜色，每次复习后整篇笔记的颜色分布都会改变，会破坏「颜色等于稳定语义」的认知习惯，读者必须重新学习配色含义。因此掌握状态一律用文字标签，保证颜色系统长期稳定。

### 1.2 通道 A：知识点类型（块级，6 类）

用于包裹整段内容，表达「这段是干什么用的」。

| 类型 | 浅色主题（底色 / 色条） | 深色主题（底色 / 色条） | Obsidian Callout |
|------|----------------------|----------------------|-----------------|
| 核心定义与概念 | `#EAF2FB` / `#2E75B6` | `#1B2A3A` / `#5B9BD5` | `> [!note]` |
| 模板与公式 | `#F3EAFB` / `#7030A0` | `#2A1B3A` / `#A874D6` | `> [!abstract]` |
| 例题与自测 | `#EAF7EC` / `#2E7D32` | `#16281A` / `#5CB85C` | `> [!example]` |
| 易错与陷阱 | `#FDECEA` / `#C0392B` | `#2E1A1A` / `#E06B5F` | `> [!warning]` |
| 通俗解释与类比 | `#E6F4F5` / `#00838F` | `#14282A` / `#4DD0E1` | `> [!tip]` |
| 补充与延伸 | `#F4F5F7` / `#7A828A` | `#20242A` / `#8B949E` | `> [!info]` |

### 1.3 通道 B：重要程度（行内，3 级）

| 等级 | 含义 | 浅色主题 | 深色主题 | 字重 | 黑白打印降级 | 文字标签 |
|------|------|---------|---------|------|------------|---------|
| **P0** | 必掌握。不会则直接失分 | `#C0392B` | `#FF7B72` | 700 加粗 | 加粗 | `[P0]` |
| **P1** | 需熟练。中频或作为 P0 的前置 | `#B9770E` | `#E3B341` | 600 半粗 | 下划线 | `[P1]` |
| **P2** | 了解即可。低频或背景知识 | `#70757A` | `#8B949E` | 400 常规 | 常规 | `[P2]` |

### 1.4 通道 C：掌握状态（文字标签，5 态）

| 状态 | 标签 | 含义 | 判定方式 |
|------|------|------|---------|
| 未学 | `[未学]` | 尚未接触 | 默认状态 |
| 学过 | `[学过]` | 读过讲解，未独立练习 | 看完笔记 |
| 会做 | `[会做]` | 能独立完成不查资料 | 独立做对 1 道题 |
| 易错 | `[易错]` | 反复出错，需重点回顾 | 同类题错 2 次以上 |
| 已掌握 | `[掌握]` | 隔周复测仍能完成 | 间隔 7 天以上复测通过 |

**状态流转**：`[未学]` → `[学过]` → `[会做]` → `[掌握]`；任一步做错则退回 `[易错]`，重做通过后回到上一状态。

### 1.5 图例（每篇笔记开头必须插入，只此一处，不重复）

```markdown
> **图例**
>
> **重要程度**：`P0` 必掌握（红／加粗）｜`P1` 需熟练（橙／半粗）｜`P2` 了解即可（灰／常规）
> **内容类型**：定义概念（蓝）｜模板公式（紫）｜例题自测（绿）｜易错陷阱（红）｜通俗类比（青）｜补充延伸（灰）
> **掌握状态**：`[未学]` `[学过]` `[会做]` `[易错]` `[掌握]`
```

> **注意**：图例中同时写出了颜色名与文字标签。即使颜色失效（打印、色觉障碍），读者仍能通过「加粗／半粗／常规」和标签读懂全篇。

### 1.6 颜色数量控制

全文同时出现的彩色元素上限：**6 种块色（但一篇笔记通常只用到 3 至 4 种）+ 3 种文字色**。

若某篇笔记的块色种类超过 4 种，说明内容分类过细，应合并。**颜色越少，识别越快**——这是本方案最重要的取舍。

## 三、知识点关联的设计方式

### 3.1 六种关联关系

知识不是孤立的点，而是有类型的边。只有把边的类型说清楚，关联才有复习价值。

| 代号 | 关系 | 含义 | 典型问法 | 复习价值 |
|------|------|------|---------|---------|
| `[前置]` | 依赖 | 学 B 之前必须先会 A | 「不会 A 会怎样？」 | 断链定位 |
| `[后续]` | 深化 | B 是 A 的自然延伸 | 「A 还能往哪走？」 | 建立期待 |
| `[并列]` | 同位 | A 与 B 同类，属同一层 | 「它们何时用哪个？」 | 选型判断 |
| `[易混]` | 冲突 | A 与 B 极易混淆 | 「区别是什么？」 | 防错 |
| `[组合]` | 协同 | A 加 B 解决某类题 | 「什么题需要两个一起用？」 | 解题套路 |
| `[同构]` | 类比 | A 与 B 结构相同，跨领域 | 「它们为什么像？」 | 迁移理解 |

### 3.2 三条落地机制

**机制一：行内关联标记（就地，最有效）**

每个知识点末尾固定写一段「关联」，用代号加指向：

```markdown
**关联**
- `[前置]` → 见 2-4 循环队列的判空判满公式
- `[易混]` → 见 2-6 链式队列。区别在于链式队列不存在假溢出一说
- `[组合]` → 与 3-1 栈组合可解决表达式求值
```

> **要点**：关联必须写在**知识点内部**，不能只放章末。学习者读到该点时正是需要关联的瞬间，章末再提已经错过时机。

**机制二：双向回填（对抗单向链接）**

原资料的关联是单向的（A 提到 B，但 B 不知道 A）。必须**双向**：

- 学到新知识点时，**顺手回到旧笔记**，在旧知识点的「关联」里补一条 `[后续]`。
- 维护一个待办清单，记录「哪些旧笔记需要回填」。

> 这条机制是双链（`[[...]]`）能自动维护的部分。若使用 Obsidian，`[[知识点名]]` 会自动生成反向链接面板，无需手工回填。**建议在 Obsidian 内使用双链，在导出稿中保留纯文字关联表**，两套并存。

**机制三：全局图谱（鸟瞰）**

单独维护一份 `_知识图谱.md`，用纯文本树或 Mermaid 画全局依赖：

```text
数据结构
├─ 线性表 ──┬─ 顺序表 ── 折半查找的前置
│           └─ 链表 ──── 栈/队列的链式实现
├─ 栈与队列 ─┬─ 栈 ──── DFS 的非递归实现
│            └─ 队列 ── BFS 的核心容器
├─ 树 ───────┬─ 二叉搜索树 ── AVL / 红黑树
│            └─ 哈夫曼树 ───── 贪心思想的实例
...
```

### 3.3 关联与优先级的交叉应用：先修排序

把「关联」与「优先级」两个维度交叉，可以生成**自动的学习顺序**：

| 情况 | 处理方式 |
|------|---------|
| 前置是 `P0`，本点也是 `P0` | 先学前置，不可跳过 |
| 前置是 `P1`，本点是 `P0` | 前置按 `P0` 对待（因为它是 `P0` 的前提） |
| 前置是 `P2`，本点是 `P0` | 检查依赖是否过强，若只是「最好先看」，允许跳过 |
| 本点无前置 | 可作为章节起点 |

> **【要点】** 优先级不能只看知识点自身，必须叠加「被多少 `P0` 依赖」。一个 `P1` 知识点若被三个 `P0` 依赖，它的实际优先级高于其标称等级。

### 3.4 关联密度控制

每篇笔记的关联条数建议控制在 **知识点数乘以 1.5 以内**。超出说明关联标注过细，反而增加阅读负担。

## 四、回顾机制设计

### 4.1 四层回顾，覆盖不同时间尺度

| 层次 | 触发时机 | 动作 | 载体 |
|------|---------|------|------|
| **即时回顾** | 读完一个知识点 | 复述「一句话定义」；先自测再对答案 | 知识点内「一句话定义」 |
| **章内回顾** | 读完一章 | 做章末自测清单；只看「核心内容」能否全部复述 | 六、本章总结 6.1 与 6.3 |
| **跨章回顾** | 每学完 3 至 5 章 | 走一遍「跨章关联地图」；做关联知识点的对比题 | 五、跨章关联地图 |
| **长期回顾** | 按间隔重复表 | `+1 天 / +3 天 / +7 天 / +21 天` 复测 | 6.4 间隔重复表 + `_复习计划.md` |

### 4.2 主动回忆优先于重读

回顾必须**先回想再看**，否则只是重读，效果低下。落地方式：

- 每个知识点的「一句话定义」**默认折叠**（Obsidian 用 `> [!question]-` 折叠 Callout，或 `<details>` 标签）。
- 自测题的答案统一放章末「七、自测答案」，且默认折叠。
- 复习时先自问自答，再展开核对。

### 4.3 掌握状态驱动的复习调度

| 当前状态 | 下次复习间隔 | 复习动作 |
|---------|------------|---------|
| `[未学]` | — | 首次学习 |
| `[学过]` | 1 天 | 复述定义 + 重看误区 |
| `[会做]` | 3 天 | 重做例题（不看答案） |
| `[易错]` | 1 天，连续 3 次 | 只做错题对应的知识点，直到连续通过 |
| `[掌握]` | 21 天 | 抽查一道综合题 |

> **【要点】** `[易错]` 状态的复习频率必须**高于** `[未学]`。这是间隔重复系统里最容易被忽略的一点：人们倾向于复习自己会的，回避自己错的。

### 4.4 错题回炉机制

现有 `总笔记.md` 已有「错题本」表格，升级为三表联动：

```text
错题记录表  →  关联知识点  →  知识点掌握状态
（错在哪）      （为什么错）      （状态退回 [易错]）
```

**闭环规则**：任何一次做错，必须完成三个动作：
1. 在错题表登记（日期、题号、错误原因分类、正确思路一句话）
2. 定位到对应的知识点，把它的掌握状态改回 `[易错]`
3. 在该知识点的「常见误区」里补充这条新发现的误区

> 第 3 步是关键——**错题只有沉淀进知识点才真正被消化**，否则只是一个孤立的记录。

**三栏的分工**：

- 右栏负责**体系感知**（大纲看结构，反向链接看关联，复习计划看进度）

### 5.2 关键排版参数

| 项 | 值 | 理由 |
|----|----|------|
| 正文最大宽度 | 750px | 每行 35 至 45 汉字，减少回扫，最利阅读 |
| 正文字号 | 16px | 长时间阅读不疲劳 |
| 行高 | 1.75 | 中文需要比英文更大的行距 |
| 段落间距 | 0.9em | 便于区分段落 |
| 色块内边距 | 12px 16px | 底色块不压迫文字 |
| 色块左边框 | 4px 实线 | 色条是主要识别信号，需足够粗 |
| 代码块字号 | 14px | 与正文区分 |

### 5.3 手机复习场景

手机不适合读长笔记，只适合**抽认与自测**。建议：

- 新建 `_每日复习.md`，每行一条待复习项，格式为 `- [ ] 知识点名 → 一句话提示`。
- 手机上只打开这一个文件，配合 Obsidian 移动端的任务列表，逐条打钩。
- 长笔记留到桌面端精读。

### 5.4 打印场景（考前）

打印是整个色系最容易被破坏的场景。必须满足：

| 项 | 处理 |
|----|------|
| 底色块 | 全部转为**淡灰底或纯白加左侧黑边**，节省墨且不糊 |
| `P0` | 保持**加粗**（黑白下仍可辨识） |
| `P1` | 转**下划线**（补回颜色丢失后的区分度） |
| `P2` | 常规（无标记） |
| 折叠内容 | **全部展开**（打印件的折叠无意义） |
| 关联标记 | 保留纯文字（`[前置]` 等标签本身就是文字） |
| 图例 | 保留，且注明「黑白打印时按字重区分」 |

> **【要点】** 打印样式必须在 CSS 里单独写一个 `@media print` 块。这是「颜色永不单独承载信息」原则最终落地的地方——如果这一步没做，黑白打印稿会丢失全部重要程度信息。

### 5.5 视觉降噪原则

「简洁易用」的核心不是少写字，而是**少用视觉通道**：

1. **一屏之内彩色块不超过 3 个**。若超出，说明该段该拆分或降级为普通引用块。
2. **同级内容用同色**。同一章的所有例题都用绿块，不要一节换一个颜色。
3. **颜色只用于分类，不用于装饰**。禁止「为了好看」加颜色。
4. **默认不使用高饱和色**。底色一律用浅色调（饱和度低于 15%），只有色条用高饱和。
5. **加粗有节制**。一段之内加粗不超过 2 处，否则加粗失去区分力。

## 八、本方案的核心取舍（结论）

1. **颜色分三条通道**，而不是三个维度各配一套颜色。避免九色混战。
2. **掌握状态不上色**。因为它变化最频繁，上色会破坏颜色语义的稳定性。
3. **颜色永不单独承载信息**。每处颜色都配字重或文字标签，保证打印与色觉障碍场景可用。
4. **关联写在知识点内部**，不只放章末。在学习者最需要的那一刻提供。
5. **关联必须双向**。新学知识点时回填旧笔记，避免单向死链。
6. **优先级要叠加被依赖次数**。一个被三个 `P0` 依赖的 `P1`，实际优先级高于标称。
7. **`[易错]` 的复习频率要高于 `[未学]`**。这是间隔重复最易被忽略的一点。
8. **错题必须沉淀进知识点的「常见误区」**，否则只是一条孤立记录。
9. **先跑样板再批量改造**。未被使用的结构就是负担。
