# 笔记、题库与知识点的组织方案

> **作用**：定义竞赛编程学习中**知识点、笔记、题库**三个实体的关系与组织方式，以及三者在学习顺序中的位置。
> **适用范围**：`02_竞赛` 分类下的全部内容。
> **配套文件**：`03_题库\README_题库使用说明.md`、`03_题库\_题库总表.md`、`03_题库\_知识点索引.md`、`03_题库\check_bank.py`
> **定版时间**：2026-09-12

---

## 一、三个实体分别是什么

| 实体 | 定义 | 颗粒度 | 数量级 |
|------|------|-------|-------|
| **知识点** | 不可再分的最小学习单元，如「单调栈的维护操作」「`ios::sync_with_stdio`」 | 一个概念或一个写法 | 约 160 个 |
| **笔记** | 按学习顺序组织的知识点讲解，如「阶段 3 单调栈」 | 一个主题 | 约 42 篇 |
| **题目** | 一道可提交的竞赛题，如「洛谷 P5788 单调栈模板」 | 一道题 | 数十至数百道 |

三者的分工，用一句话概括：

> **知识点是「学什么」，笔记是「怎么讲」，题库是「怎么练」。**

## 二、三者的关系（核心）

### 2.1 关系图

```text
                    ┌──────────────────────────────────┐
                    │        知识点（Knowledge Point）    │
                    │  学习的最小单元，是全文的枢纽        │
                    └───┬──────────────────────────┬────┘
                        │                          │
             1 : N      │                          │      N : M
        （一个笔记讲多个知识点）          （一题考多个知识点，一个知识点被多题考）
                        │                          │
                        ▼                          ▼
        ┌───────────────────────────┐   ┌───────────────────────────┐
        │        笔记（Note）         │   │      题目（Problem）        │
        │  按学习顺序的讲解载体        │   │  练习与检验的载体            │
        │  阶段 0 至 8 / 模块 A 至 F  │   │  按「阶段 → 知识点」分组     │
        └───────────┬───────────────┘   └───────────┬───────────────┘
                    │                              │
                    │        1 : N                 │
                    └──────►（笔记引用题目作为例题）◄┘
```

### 2.2 三条关系的性质

| 关系 | 类型 | 含义 | 载体 |
|------|------|------|------|
| 知识点 ← 笔记 | **1 : N** | 一个笔记承载多个知识点；一个知识点只归属一个笔记 | 笔记的「知识点讲解」节 |
| 知识点 ↔ 题目 | **N : M** | 一道题考核多个知识点；一个知识点被多道题考核 | 题库总表的「涉及知识点」列 |
| 笔记 → 题目 | **1 : N** | 笔记的「典型例题」节引用题目 | 笔记里写题目编号 |

> **【要点】** **知识点是枢纽**。
> 学习顺序沿着「知识点 → 笔记」这条线走（先学哪个知识点）；
> 练习顺序沿着「知识点 → 题目」这条线走（学了就该做哪些题）。
> 两条线共用知识点作为锚点，所以顺序不会错位。

### 2.3 为什么题目与知识点是 N:M 而不是 1:N

一道题往往同时考多个知识点。例如洛谷 P1462（通往奥格瑞玛的道路）同时考「二分答案」与「最短路」——它属于阶段 1 的二分，也属于阶段 5 的图论。

若强行归到唯一的章节，会导致另一章的「学了就该做」清单里漏掉它。因此题目允许多归属，并在总表中标注**主知识点**（唯一）与**副知识点**（可多个）。

> **【规律】** 主知识点决定这道题出现在题库的哪个阶段分组下；副知识点用于反向检索。

## 三、单一真源划分（避免双写）

三个实体各有自己的真源文件。**任何一个信息只在一处定义**。

| 信息 | 单一真源 | 其他位置的写法 |
|------|---------|--------------|
| **知识点的元数据**（编号、名称、优先级、掌握状态、所属笔记） | `_知识点索引.md` | 笔记中只写编号与名称 |
| **知识点的讲解**（是什么 / 为什么 / 怎么用 / 易错） | 各篇笔记 | 索引中不重复 |
| **题目的元数据**（题号、链接、来源、难度、涉及知识点、状态） | `_题库总表.md` | 笔记中只写题号 |
| **题目的代码** | `代码/<平台>-<题号>.cpp` | 总表中只写文件名 |
| **题目的思路**（可选，仅对值得写的题） | `题解/<平台>-<题号>.md` | 总表中只写文件名 |

### 3.1 唯一的例外

有一条信息需要**两处维护**，因为它是跨实体的状态：

**知识点的掌握状态**同时影响「学」与「练」两个环节。

- 真源放在 `_知识点索引.md`（因为状态属于知识点本身）
- 题库总表的「状态」列记录的是**题目**的完成情况（未做 / 已做 / 已通过 / 待复习），与知识点状态不同
- 两者的联动规则：**同一知识点下的题目全部通过后，才把该知识点的状态提升为 `[掌握]`**

### 3.2 禁止的双写

> **【硬规则一】** 笔记中引用题目时，**只写题号，不写完整链接**。
> 链接以总表为准，避免题目换链接后两处不一致。
>
> **【硬规则二】** 总表中**不抄题面**。题面在题目链接里，抄一遍既占篇幅又易过时。
>
> **【硬规则三】** 代码**只存 `代码/` 目录下**，不在笔记或总表里粘贴大段代码。
> 笔记里可以放小的模板，但题解代码一律在 `代码/`。

## 四、学习顺序如何贯穿三者

用户的核心要求是「按照学习顺序组织内容，以竞赛为主线，其次涵盖 C++ 的竞赛相关知识点」。这个顺序通过三个载体落实：

### 4.1 笔记侧：编号即顺序

```text
主线　01_算法专题\        阶段 0 → 阶段 8
次线　02_竞赛C++\         模块 B → A → C → D → E → F（注意 B 在最前）
```

> **【注意】** 竞赛 C++ 的学习顺序是 **B 最先**（输入输出与性能），不是字母序。
> 详见 `02_竞赛C++\README_模块总览与学习顺序.md`。

### 4.2 题库侧：按阶段分组，不按平台排

题库总表**不按平台（洛谷 / 力扣 / CF）排列**，而是**按「阶段 → 知识点」分组**。

理由：平台的划分对学习毫无帮助——学到阶段 3 时，不会因为题目在洛谷还是力扣而改变该不该做。而按阶段分组后，**学到哪就做到哪**，清单可以直接当待办用。

### 4.3 知识点侧：学习顺序号

`_知识点索引.md` 中的「序」列是全局学习顺序号，由「阶段号 + 章节内序号」组成，例如 `3-2` 表示阶段 3 的第 2 个知识点。

**三个载体的顺序必须一致**：

```text
知识点 3-2 单调栈的维护操作
   ↓ 归属
笔记  阶段3_基础数据结构\单调栈.md
   ↓ 引用
题目  luogu-P5788（主知识点 3-2）
```

## 六、命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 题目编号 | `<平台小写>-<原题号>` | `luogu-P5788`、`leetcode-42`、`cf-1927A` |
| 代码文件 | `<题目编号>.cpp` | `luogu-P5788.cpp` |
| 题解文件 | `<题目编号>.md` | `luogu-P1462.md` |
| 平台前缀 | `luogu` / `leetcode` / `cf` / `lanqiao` / `baidu` / `ccf` | — |
| 知识点编号 | `<阶段号>-<序号>` | `3-2`、`6-1`；C++ 模块用 `<字母>-<序号>` 如 `B-2` |

> **【注意】** 平台前缀用小写，题号保持原平台的大小写形式（洛谷用 `P`，力扣用数字，Codeforces 用 `1927A`）。

## 七、四步工作流

学一个知识点到把它练扎实，固定走四步：

```text
第 1 步　学　　在笔记里读完知识点
              ↓
第 2 步　登记　在「_题库总表.md」对应阶段下加一行
              （填题号、链接、来源、难度、涉及知识点）
              ↓
第 3 步　做　　在「代码/」下建 <题目编号>.cpp
              （总表的状态列改为「已做」）
              ↓
第 4 步　复盘　通过后状态改「已通过」
              同一知识点下全部通过 → 更新 _知识点索引.md 的状态为 [掌握]
              没通过 → 记录错误原因，状态改「待复习」
```

### 步骤 2 的「登记」是关键动作

> **【重点】** **先登记后做题**，不要做完了才回头补登记。
> 理由：登记时就要确定这道题考哪个知识点，这一步会暴露「这题我是否该现在做」的问题。
> 做完再补登记，往往会发现题目超纲或重复。

### 状态字段的取值

| 字段 | 位置 | 取值 |
|------|------|------|
| 题目状态 | 总表 | `未做` / `已做` / `已通过` / `待复习` |
| 知识点状态 | 知识点索引 | `[未学]` / `[学过]` / `[会做]` / `[易错]` / `[掌握]` |

> **【易错】** 两个「状态」含义不同，不要混用。
> 题目「已通过」只说明这道题过了，不代表知识点掌握——换一道同知识点的题可能又错。
> 所以知识点状态要**全部相关题目通过后才提升**。

## 八、校验机制

`check_bank.py` 负责检查三者的一致性，防止长期维护后失真。

| 检查项 | 说明 |
|--------|------|
| 链接格式 | 题目链接是否符合平台规范 |
| 知识点存在性 | 总表里写的知识点编号，能否在 `_知识点索引.md` 中找到 |
| 代码文件存在性 | 状态为「已通过」的题，`代码/` 下是否真有对应文件 |
| 命名一致性 | 总表的题号与代码文件名是否一致 |
| 未覆盖知识点 | 有哪些 P0 知识点在题库里一题都没有 |
| 超纲检查 | 题目涉及的知识点，其所属阶段是否已在该题的学习顺序之前 |

**运行方式**：

```bash
python check_bank.py 03_题库                # 全量校验
python check_bank.py 03_题库 --report       # 输出统计报告
```

运行前需确认题库目录可访问。

## 十、本方案的核心取舍

1. **知识点是枢纽**，不是笔记也不是题目。因为学习顺序与练习顺序都要挂在它上面。
2. **题目允许多归属知识点**（N:M），并用「主 / 副」区分。强行单归属会导致漏题。
3. **题库按阶段分组，不按平台排**。平台划分对学习没有指导意义。
4. **三处禁止双写**：笔记只写题号、总表不抄题面、代码只在 `代码/`。
5. **两个状态字段含义不同**，题目通过不等于知识点掌握。
6. **先登记后做题**，登记这一步能暴露「该不该现在做」的问题。
7. **题库独立于笔记目录**，与两套笔记并列，便于跨阶段引用。
8. **校验脚本必需**。三者分离的好处是清晰，代价是可能失真，脚本补上这个代价。
