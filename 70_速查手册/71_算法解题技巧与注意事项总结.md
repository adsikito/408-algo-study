## 一、常见题型分类与识别信号

### 1.1 识别信号总表

**做题的第一步不是想算法，是从题面找信号。**

| 题面出现的特征 | 判定题型 | 首选算法 | 复杂度 |
|--------------|---------|---------|-------|
| 「一次过程」「按规则走」 | 模拟 | 直接照做 | 视题 |
| 「不超过 n」「数据范围很小」 | 枚举 | 穷举全部可能 | O(方案数) |
| 「多次询问区间和」「前缀」 | 前缀和 | 预处理前缀 | 建 O(n) 查 O(1) |
| 「多次区间加减」「区间修改」 | 差分 | 差分数组 | 改 O(1) 还原 O(n) |
| 「连续子数组」「满足某条件的区间」 | 尺取法 | 双指针，r 扩 l 缩 | O(n) |
| 「单调」「有序」「最小/最大的最大值」 | 二分答案 | 猜 mid + check | O(log 值域 × check) |
| 「第 k 小」「插入删除并查前驱后继」 | 平衡结构 | `set` / 树状数组 | O(log n) |
| 「合并集合」「是否同集合」 | 并查集 | 路径压缩 | 近 O(1) |
| 「敌对关系」「食物链」 | 种类并查集 | 扩展域 | 近 O(1) |
| 「向左右找第一个更大/更小」 | 单调栈 | 单调栈 | O(n) |
| 「滑动窗口最值」「定长区间最值」 | 单调队列 | 单调双端队列 | O(n) |
| 「所有方案」「可行解」「走迷宫」 | 搜索 | DFS / BFS | 视剪枝 |
| 「最少步数」「无权最短路」 | BFS | 队列层扩展 | O(n+m) |
| 「非负权最短路」 | Dijkstra | 堆优化 | O(m log m) |
| 「含负权」「判负环」 | Bellman-Ford / SPFA | n-1 轮松弛 | O(nm) |
| 「多源最短路」「n 较小」 | Floyd | 三重循环 | O(n³) |
| 「依赖顺序」「能否完成」 | 拓扑排序 | 入度法 | O(n+m) |
| 「连通所有点的最小代价」 | 最小生成树 | Kruskal / Prim | O(m log m) |
| 「一笔画」「每条边恰好一次」 | 欧拉路径 | Hierholzer | O(n+m) |
| 「子串匹配」「模式串出现位置」 | 字符串匹配 | KMP | O(n+m) |
| 「两个串是否相同」「子串比较」 | 字符串哈希 | 多项式哈希 | 建 O(n) 查 O(1) |
| 「最长上升子序列」「最长公共子序列」 | 线性 DP | 状态转移 | O(n²) |
| 「按区间合并」「括号匹配类 DP」 | 区间 DP | 先短后长枚举 | O(n³) |
| 「容量限制下取最大价值」 | 背包 | 01 / 完全 / 多重 | O(nW) |
| 「树上的最优选择」 | 树形 DP | DFS 回溯合并 | O(n) 至 O(nk) |
| 「n ≤ 20 且状态是集合」 | 状压 DP | 位运算表示集合 | O(n·2ⁿ) |
| 「区间修改 + 区间查询」 | 线段树 | 懒标记 | O(log n) |
| 「单点修改 + 前缀查询」 | 树状数组 | lowbit | O(log n) |

### 1.2 三条快速排除法

| 信号 | 排除什么 |
|------|---------|
| 数据规模到 10⁵ 以上 | **排除 O(n²) 及以上**。多数朴素解法直接不可用 |
| 需要「输出方案」而非仅「最优值」 | **排除降维后的 DP**。降维会丢失决策路径，必须保留完整表 |
| 要求「字典序最小」 | **排除单纯的贪心**。需先在最优解集合内再取字典序最优 |

> **【规律】** 看数据范围定算法，比看题面描述更可靠。
> n ≤ 20 想状压或暴搜；n ≤ 500 想 O(n³)；n ≤ 5000 想 O(n²)；n ≤ 10⁶ 想 O(n log n)；n ≤ 10¹⁸ 想 O(log n)。

## 二、各题型的典型解题思路

每个题型给「思路骨架 + 简短示例」。篇幅所限只写骨架，展开讲解见对应笔记。

### 2.1 模拟与枚举

**思路骨架**：先明确要维护哪些状态变量，再逐条照题意更新；枚举则要确定枚举的维度与顺序。

**示例**：题目要求模拟小球在网格中移动并转向。
关键是先列出状态 `(x, y, dir)`，再写「一次移动」的函数，循环调用。「转向规则」写成一个表，不要用一堆 `if`。

> **【易错】** 模拟题的错几乎都在「漏改状态」——改了坐标忘了改方向，或处理完边界没更新计数。

### 2.2 前缀和与差分

**思路骨架**：前缀和把「区间求和」变成「两个前缀相减」；差分把「区间修改」变成「两个点修改」。

**示例**：给 n 个数，m 次询问区间 `[l, r]` 的和。
建 `pre[i] = pre[i-1] + a[i]`，则答案是 `pre[r] - pre[l-1]`。**注意是 `l-1`，不是 `l`。**

差分：把 `[l, r]` 全部加 x，写 `d[l] += x; d[r+1] -= x;`。
**`r+1` 那一项最容易漏。**

### 2.3 尺取法（双指针）

**思路骨架**：`r` 向右扩张进入窗口，`l` 向右收缩离开窗口。**`l` 永不回退**，所以总复杂度 O(n)。

**示例**：求和 ≥ target 的最短子数组。
`r` 每步加一个元素，当窗口和达标就尝试缩 `l`，缩到不达标为止，过程中记录最短长度。

> **【易错】** 收缩时**先处理离开窗口的元素，再 `l++`**。顺序写反会算错窗口和。另外数组含负数时单调性被破坏，尺取法失效。

### 2.4 二分

**思路骨架**：两种用法——**查值**（在有序数组找元素）与**二分答案**（对答案空间二分，用 `check` 判断可行性）。

**示例**：求最小速度使总时间 ≤ H（吃香蕉问题）。
下界是 1，**上界取可能的最大速度而不是 0**。`check(v)` 返回是否可行，若可行则记录答案并缩小上界。

> **【易错】** 二分答案的三处坑：**下界从 1 而不是 0 开始**（0 会导致除零）、`check` 内累加要用 `long long`、循环写成 `while (lo < hi)` 时注意死循环。

### 2.5 贪心

**思路骨架**：每步取局部最优 + **必须能证明全局最优**。竞赛中常用「交换论证」：假设最优解在某步与贪心选择不同，交换后不变差。

**示例**：合并果子（每次合并当前最小的两堆）。
用优先队列堆维护最小值。**贪心本身不难，难的是想到用堆维护**——若每轮重新排序会退化为 O(n² log n)。

> **【易错】** 贪心最大的风险是**想当然**。没证明就写，很容易被一个反例击穿。判断依据：能否举出反例；举不出也别急着写，试着交换论证。

### 2.6 递归与分治

**思路骨架**：确定三要素——**递归出口、递归式、递归树**。

**示例**：汉诺塔。把「移动 n 个盘」分解为「移动 n-1 个到中转柱 → 移动最大盘 → 移动 n-1 个到目标柱」。
参数顺序轮换是最易错处，建议先手推 n=2 和 n=3 再写代码。

### 2.7 搜索（DFS / BFS）

**思路骨架**：
- DFS：**填值 → 标记 → 递归 → 撤销标记**（回溯必须恢复现场）
- BFS：**队列 + 方向数组 + dist + 标记**，**入队时即标记**（不是出队时）

**示例**：走迷宫求最短步数。BFS 首次到达某格时的步数就是最短步数。
标记必须在入队时打，否则同一格会被多次入队。

> **【易错】** DFS 漏回溯、BFS 出队才标记——这两个错误占据搜索题失分的大半。

### 2.8 图论

**思路骨架**：先选存储（稠密用邻接矩阵，稀疏用链式前向星），再选算法（题面信号见第一节）。

**示例**：Dijkstra 堆优化。核心是「每次取出当前距离最小的点，用它松弛邻居」。
用 `priority_queue<pair<int,int>, vector<...>, greater<...>>` 实现小顶堆，配合**懒删除**（弹出时判 `vis`）。

> **【易错】** 负权图用 Dijkstra **必错**；`Prim` 与 `Dijkstra` 的 `dist` 含义不同（前者是到生成树的距离，后者是到源点的距离），不可混用模板。

### 2.9 动态规划

**思路骨架**：五步——辨问题（有无最优子结构、重叠子问题）→ 定状态 → 列转移方程 → 定枚举顺序 → 定初值与答案位置。

**示例**：01 背包。`dp[j] = max(dp[j], dp[j-w[i]] + v[i])`，内层**必须倒序**。
倒序保证每件物品只用一次；正序就变成完全背包了。

> **【易错】** 三个高频坑：LIS 的答案**不在 `dp[n]`**，要在全表取 max；区间 DP **必须按长度从小到大枚举**；「恰好装满」的初始化是 `-∞` 而非 0。

### 2.10 数据结构（线段树 / 树状数组）

**思路骨架**：区间问题优先树状数组（代码短），涉及区间覆盖型修改则用线段树。

**示例**：树状数组三个函数——`lowbit`、`add`、`ask`。
`ask(r) - ask(l-1)` 得区间和。要支持区间加，就把树状数组建在差分数组上。

> **【易错】** 树状数组**下标必须从 1 开始**（`lowbit(0)` 会死循环）；线段树数组要开 **4n**；下传懒标记后**必须清零**。

## 三、时间与空间复杂度考量

### 3.1 数据规模推定可用复杂度（最实用的一张表）

以 1 秒时限、现代评测机为基准的经验值：

| 数据规模 n | 可接受的最高复杂度 | 典型算法 |
|-----------|-----------------|---------|
| n ≤ 10 | O(n!) 勉强 | 全排列暴搜 |
| n ≤ 20 | O(2ⁿ) | 状压 DP、子集枚举 |
| n ≤ 100 | O(n⁴) | 高维 DP |
| n ≤ 500 | O(n³) | Floyd、区间 DP |
| n ≤ 5000 | O(n²) | 普通 DP、邻接矩阵 |
| n ≤ 10⁶ | O(n log n) | 排序、堆、线段树 |
| n ≤ 10⁷ | O(n) | 线性筛、单调栈 |
| n ≤ 10⁸ | O(n) 需卡常 | 简单循环 + 快读 |
| n ≤ 10¹² | O(√n) | 试除法、分块 |
| n ≤ 10¹⁸ | O(log n) | 快速幂、矩阵快速幂、数论 |

> **【要点】** **先看范围，再想算法。** 这一步能砍掉大量错误方向。
> 经验值会因常数因子浮动，卡在边界时应保守一档。

### 3.2 常数因子的影响

同一复杂度下，常数差异可达数倍。以下写法会显著放大常数：

| 写法 | 影响 | 替代 |
|------|------|------|
| 循环内 `endl` | **慢约 32 倍** | 用 `"\n"` |
| `cin` 未关同步 | 慢约 4 倍 | 加两行关闭同步 |
| `vector` 未 `reserve` | 多次扩容拷贝 | 提前 `reserve` |
| 函数未 `inline` 且高频调用 | 调用开销累积 | 加 `inline` 或改宏 |
| 反复 `push_back` 到二维 `vector` | 分配开销大 | 用一维数组拍平 |
| 取模用 `%` 且高频 | 慢于位运算 | 模数为 2 的幂时改 `&` |

> **【规律】** 复杂度决定能不能过，常数决定卡不卡线。
> **先降复杂度，再压常数**——顺序反了会白费功夫。

### 3.3 空间复杂度与内存限制

多数 OJ 内存限制 256 MB。按 `int` 4 字节估算：

| 规模 | `int` 数组 | 判断 |
|------|-----------|------|
| 10⁶ | 4 MB | 安全 |
| 10⁷ | 40 MB | 安全 |
| 3×10⁷ | 120 MB | 接近上限 |
| 10⁸ | 400 MB | **超限** |

**示例**：n ≤ 3×10⁶ 时开两个 `int` 数组是 24 MB，安全；但开 `long long` 就变 48 MB，仍安全；若再开一个二维数组就会超。

> **【易错】** 递归深度也占空间。DFS 递归到 10⁶ 层会爆栈（默认栈约 8 MB，每层几十字节）。
> 处理办法：改非递归，或确认 OJ 允许调大栈。

## 四、边界条件处理方法

### 4.1 边界清单（写代码前逐项对照）

| 类别 | 边界情形 | 处理要点 |
|------|---------|---------|
| **空** | n = 0、空串、空数组 | 循环是否自然跳过？加不加法？ |
| **单元素** | n = 1 | 二分、尺取、DP 是否会越界 |
| **极小值** | 所有元素相同、全为 0 | 弹出条件用 `<=` 还是 `<` |
| **极大值** | n 取下界、值取上界 | 数组是否留冗余；累加是否溢出 |
| **负数** | 数组含负数 | 尺取法单调性是否成立；`max` 的初值 |
| **重复** | 元素相同、边权相同 | 去重、判重、排序稳定性 |
| **自环/重边** | 图论 | 是否影响最短路与生成树 |
| **不连通** | 图论 | 是否需判「不可达」并输出特值 |
| **越界** | 下标 0 与 n+1 | `a[l-1]`、`a[r+1]` 是否合法 |

### 4.2 四类最常见的边界错误

**错误一：前缀和忘了 `l-1`**

```cpp
// 错误：区间 [l, r] 的和
int s = pre[r] - pre[l];
// 正确：
int s = pre[r] - pre[l - 1];
```

**错误二：差分忘了 `r+1`**

```cpp
// 错误：只在 l 处加
d[l] += x;
// 正确：r+1 处要减回来
d[l] += x; d[r + 1] -= x;
```

**错误三：二分下界取 0**

```cpp
// 错误：速度可以为 0 → check 内除零
int lo = 0, hi = maxv;
// 正确：按题意取真实下界
int lo = 1, hi = maxv;
```

**错误四：累加不用 `long long`**

```cpp
// 错误：n 个 10^9 累加必溢出 int
int sum = 0;
for (int i = 0; i < n; ++i) sum += a[i];
// 正确：
long long sum = 0;
```

> **【记忆】** 边界四问：**会不会空？会不会只有一个？会不会全一样？会不会溢出？**

### 4.3 边界测试用例模板

每个程序至少自测这四组：

```text
1) 最小值组    n = 1 或 n = 0
2) 全相同组    所有元素取同一值（如全 1、全 0、全 -1）
3) 极值组      元素取题面上界与下界
4) 有序 / 逆序 严格递增与严格递减
```

## 五、易错点提示

### 5.1 按类别汇总

| 类别 | 易错点 | 后果 |
|------|-------|------|
| **整数** | `int` 溢出（最大值约 2.1×10⁹） | WA，且错得很隐蔽 |
| **数组** | 开小、下标越界、`n+1` 写成 `n` | RE |
| **初始化** | 多组数据未清空；`ans` 初值不当 | WA，且通常「第一组对后面全错」 |
| **循环** | `<` 与 `<=` 混用；`i` 与 `j` 写反 | WA 或死循环 |
| **比较** | 排序比较器未定义严格弱序 | RE 或排序结果不确定 |
| **取模** | 减法后未加模数；负数取模为负 | WA |
| **浮点** | 相等判断用 `==`；精度不足 | WA |
| **字符串** | `next` 是关键字；下标从 0 还是 1 | 编译错或 WA |
| **指针/引用** | 传参未加引用导致拷贝；悬垂指针 | TLE 或 RE |
| **多组数据** | 未判 EOF；未重置状态 | 多输出一组或死循环 |

### 5.2 五条最值得记住的

**一、`int` 溢出是头号隐蔽错误**

```cpp
// 错误：a、b 都是 int，乘积先按 int 算再赋给 long long
long long c = a * b;
// 正确：先转 long long
long long c = 1LL * a * b;
```

**示例场景**：求 n 个数的乘积取模，n 最大 10⁵，每个数 10⁹。写成 `ans = ans * a[i] % MOD` 就全错。

**二、多组数据忘记清空状态**

```cpp
// 错误：栈里留着上一组的数据
int main() {
    while (scanf("%d", &n) != EOF) {
        for (...) { s.push(x); }
        // 处理
    }
}
// 正确：每组开头清空
```

**示例场景**：多组数据的括号匹配。第一组正确，从第二组开始全错，就是这个原因。

**三、排序比较器必须满足严格弱序**

```cpp
// 错误：写成 <=，可能触发未定义行为
sort(a, a + n, [](int x, int y) { return x <= y; });
// 正确：严格小于
sort(a, a + n, [](int x, int y) { return x < y; });
```

**示例场景**：自定义结构体按第二关键字排序时最容易写错。

**四、减法取模要加回模数**

```cpp
// 错误：可能得到负数
ans = (a - b) % MOD;
// 正确：
ans = ((a - b) % MOD + MOD) % MOD;
```

**五、浮点不要用 `==` 比较**

```cpp
// 错误
if (x == y) ...
// 正确：比较差值
if (fabs(x - y) < 1e-9) ...
```

> **【记忆】** 溢出、初始化、比较器、取模负数、浮点相等——这五条覆盖了大部分「代码看起来对但过不了」的情况。

## 六、系统的调试与优化方法

### 6.1 调试：按成本从低到高

| 顺序 | 方法 | 适用 | 成本 |
|------|------|------|------|
| 1 | **读代码**，重点看边界与初始化 | 一切情况 | 最低 |
| 2 | **小数据手推**，与程序输出逐行比对 | 逻辑错误 | 低 |
| 3 | **打印中间态**（用调试宏，不污染提交） | 状态类错误 | 低 |
| 4 | **`assert` 断言**关键不变量 | 越界与非法状态 | 中 |
| 5 | **对拍**：写暴力 + 生成器，批量比对 | 逻辑严谨性 | 中 |
| 6 | **二分定位**：注释掉后半段看前半段对不对 | 复杂逻辑 | 中 |
| 7 | **二分修改版本**：确定是哪次改动引入的错 | 改错回归 | 高 |

### 6.2 对拍（最有价值的一项能力）

**为什么必须掌握**：它是**唯一能自动发现逻辑错误**的手段。前面六项都靠人判断，对拍靠计算机。

**三步构成**：

```text
1) 暴力程序 bf.cpp      —— 写法简单但保证正确（可以慢）
2) 数据生成器 gen.cpp   —— 生成随机小数据
3) 比对脚本             —— 循环跑两者，比对输出
```

**小数据是关键**：随机数据要**规模小、范围小**，这样才容易撞出边界情况。

**示例脚本**：

```bash
#!/bin/bash
# 对拍脚本：反复生成小数据，比对暴力与优化程序的输出
for ((i = 1; i <= 1000; ++i)); do
    ./gen > in.txt          # 生成一组随机数据
    ./bf  < in.txt > out1.txt   # 暴力程序
    ./sol < in.txt > out2.txt   # 待测程序
    if ! diff -q out1.txt out2.txt > /dev/null; then
        echo "第 $i 组数据不一致，已保存到 in.txt"
        exit 1
    fi
done
echo "1000 组数据全部一致"
```

> **【要点】** 对拍发现不一致时，**不要急着改代码**，先把那组数据留下来手工推演——
> 想清楚哪边错、为什么错，再动手。否则容易越改越乱。

### 6.3 优化：四层，按顺序做

| 层 | 手段 | 效果 | 何时做 |
|----|------|------|-------|
| **第 1 层** | **降复杂度**（换算法） | 量级提升 | **永远最先做** |
| 第 2 层 | 输入输出优化（关同步、用 `"\n"`） | 约 4 倍 / 约 32 倍 | 数据量大时必做 |
| 第 3 层 | 常数优化（`reserve`、`inline`、位运算） | 数成 | 卡常时做 |
| 第 4 层 | 内存布局优化（一维拍平、减少随机访问） | 数成 | 内存敏感时做 |

**示例场景**：n = 10⁵ 的区间查询，朴素做法 O(n²) 需 10¹⁰ 次操作必超时。
正确做法是换树状数组降到 O(n log n)。**此时做任何常数优化都救不回来。**

> **【易错】** 最常见的优化失误是**顺序颠倒**——先花两小时压常数，最后才发现算法该换。
> 判断依据：算一下复杂度与数据规模是否匹配（查第 3.1 节表），不匹配就先换算法。

### 6.4 超时与超内存的排查顺序

| 症状 | 排查顺序 |
|------|---------|
| **TLE** | ① 复杂度是否匹配数据规模 → ② 是否用了 `endl` → ③ 是否关了流同步 → ④ 是否有重复计算可预处理 → ⑤ 是否死循环 |
| **RE** | ① 数组是否开小 → ② 是否下标越界 → ③ 是否除零 → ④ 是否递归爆栈 → ⑤ 是否读入了不存在的文件 |
| **MLE** | ① 数组是否开太大 → ② 是否开了多余的大数组 → ③ 类型是否用大（`long long` 换 `int`） |
| **WA** | ① 是否溢出 → ② 是否漏初始化 → ③ 是否漏边界 → ④ 输出格式是否对 → ⑤ 对拍 |

## 七、速查索引（一页纸）

### 7.1 提交前最后一遍

- [ ] 数据范围看过了吗？复杂度匹配吗？
- [ ] `int` 会不会溢出？累加用 `long long` 了吗？
- [ ] 数组开够了吗？留冗余了吗？
- [ ] 多组数据判 EOF、清状态了吗？
- [ ] 循环用 `"\n"` 而不是 `endl` 了吗？
- [ ] 关了流同步吗？
- [ ] 边界四问过一遍了吗？（空、单元素、全相同、极值）
- [ ] 输出格式与题目要求一致吗？（空格、换行、小数位数）
- [ ] 调试代码（`freopen`、`cerr`）不会进提交吗？

### 7.2 三句口诀

| 口诀 | 含义 |
|------|------|
| **先看范围，再想算法** | 数据规模决定可用复杂度，这一步能砍掉大量错误方向 |
| **先降复杂度，再压常数** | 顺序反了会白费功夫 |
| **想不清就对拍** | 对拍是唯一能自动发现逻辑错误的手段 |
