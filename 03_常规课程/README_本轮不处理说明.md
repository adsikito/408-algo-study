## 二、为何本轮不处理

依据 `21_笔记分类体系.md` 的「单一问题法」判定：

```text
问题 1　是 408 大纲要求的内容吗？　　　　　否
问题 2　在算法竞赛的赛场上能直接用上吗？　否
问题 3　以上都不是 → 归本分类，本轮不处理
```

上述三个模块的内容，**既不服务 408 统考，也不服务算法竞赛**。
例如：

- 智能指针与移动语义解决的是资源管理与拷贝开销，赛场代码生命周期只有几十行，不需要；
- 协程与 Modules 在多数 OJ 的编译器版本上**根本不支持**，写了也无法提交；
- 多线程、网络编程、HTTP 服务器是**求职方向**资产，与考研和竞赛均无关。

强行纳入只会稀释竞赛与考研笔记的密度。

## 三、与竞赛 C++ 的边界

本分类与 `02_竞赛\02_竞赛C++\` 的划分规则，以 `21_笔记分类体系.md` 的第四章为单一真源。要点如下：

### 3.1 仅归竞赛 C++ 的内容

`ios::sync_with_stdio(false)`、`cin.tie(nullptr)`、手写快读快写、编译期调试宏、STL 卡常写法、
`lower_bound` / `unique` + `erase`、`__builtin_` 系列、对拍、RE / TLE / MLE 排查、比赛模板。

### 3.2 仅归本分类的内容

类与继承、多态与虚函数、模板元编程、可变参数模板、异常处理、智能指针、移动语义的完整语义、
协程、Modules、`std::filesystem`、`optional` / `variant` / `any`、多线程、网络编程、
构建系统（CMake / Makefile）、设计模式。

### 3.3 两边都需要、但主写方在本分类的内容

| 知识点 | 本分类写 | 竞赛 C++ 侧只写 |
|--------|---------|---------------|
| `vector` | 完整语义、构造析构、异常安全 | 内存预分配、迭代器失效、卡常用法 |
| `string` | 完整类语义、SSO、编码处理 | `cin` 读串、`getline`、`stringstream` 分割 |
| `sort` | 完整算法实现与迭代器要求 | 自定义比较器、lambda、稳定性要求 |
| 指针 | 完整内存模型、RAII | 数组传参、函数传参避免拷贝 |
| 位运算 | 完整位运算语义与未定义行为 | lowbit、状压、集合运算 |
| 递归 | 调用栈机制与尾递归优化 | 递归深度与爆栈规避 |

> **【硬规则】** 上表中六个知识点的**主写方为本分类**。
> 竞赛侧只写赛场特定用法，并用一行文本链接指向本分类，**不得复制正文**。

## 五、后续处理建议

本分类的笔记适合**另立一期任务**单独处理，理由是：

1. 225 个课时量（25 讲加 36 项加 7 章）远超竞赛 C++ 的 6 个模块，混在一起做会互相拖慢。
2. 服务目标不同：本分类服务求职与工程能力，需要对标岗位要求，而不是对标赛事考点。
