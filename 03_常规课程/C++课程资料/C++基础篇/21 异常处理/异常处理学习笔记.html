异常处理运行机制总览

异常处理本质是一条控制权转移链路：错误检测点（throw）和处理点（catch）分离，中间由 try 划定保护范围。

1try 包住保护代码
可能出错的调用放进 try 块，后跟一个或多个 catch
2throw 抛出异常
异常类型 = 表达式类型，函数立即"返回"
3跳过 try 剩余语句
一旦抛出，try 块后面的语句全部不执行
4catch 按序类型匹配
逐个检查类型声明；都不匹配则程序终止
5程序继续正常流转
catch 处理完从 try-catch 之后继续（mycode.cpp 的 cout<<1111 是证明行）

模块一：异常处理概述 + 标准异常

1. 异常处理概述（P4-6）【了解】

异常处理是 C++ 处理运行时错误的过程，让程序出错后仍能正常流转（P5-6）；三个关键字 try / catch / throw（P6）；不处理异常则打印异常消息并终止程序（P5）。P4 除0案例是全章入口，必须分清三种"除以0"：

情况结果会抛 C++ 异常吗
整数除以0（int/int）程序崩溃终止否，硬件级错误，catch 不到
浮点除以0（double/double）得 inf/nan 照常往下传（P10 案例）否，静默产出错误值
代码主动 throw抛出异常对象是，这才是异常机制管的事
结论：异常不会自动出现——错误要自己检测、自己 throw（P11 结论）。inf=infinity（Linux）等同 #INF（Windows）；nan=not a number 等同 #IND（Windows），一般由溢出或未定义浮点操作（如对 -1 开方）产生（P10 注释）。
人话总结：异常就是"出错时的紧急出口"。

2. 标准异常（P7-8）【熟悉】

全部派生自 std::exception，按父子层次组织，定义在 <exception> 头文件中：

std::exception（父类，提供 what() 方法）
├── bad_alloc / bad_cast / bad_typeid / bad_exception
├── logic_error 家族：domain_error / invalid_argument / length_error / out_of_range
└── runtime_error 家族：range_error / overflow_error / underflow_error
异常描述（P8）
std::exception所有标准 C++ 异常的父类
std::bad_alloc通过 new 抛出（内存分配失败）
std::bad_cast通过 dynamic_cast 抛出
std::bad_typeid通过 typeid 抛出
std::bad_exception处理无法预期的异常时非常有用
std::logic_error理论上读代码就能检测到的异常
std::domain_error使用了无效的数学域
std::invalid_argument使用了无效的参数
std::length_error创建了太长的 std::string
std::out_of_range越界访问，如 vector::at()、bitset
std::runtime_error理论上读代码检测不到的异常
std::range_error存储超出范围的值
std::overflow_error / underflow_error数学上溢 / 下溢
#include <exception>   // 标准异常都在这个头文件里
std::vector<int> v = {1, 2, 3};
try { v.at(10); }                            // at() 会做越界检查
catch (std::exception& e) { /* e.what() */ } // 用父类引用接
人话总结：现成的异常家族，记得 include exception。

模块二：try/catch · throw · catch（三个重点）

3. try/catch 语句（P9-10）【重点】

① 是什么
try 块放可能出错的代码（称为保护代码），后跟一个或多个 catch 捕获处理（P9）。
② 为什么
P10 证明 div(50,0) 浮点除0不崩溃、输出 inf 照常往下传——错误值悄悄污染程序，必须用 try/catch 把错误引到处理点。
try {
    double result1 = div(v1, v2);   // 保护代码
    cout << result1 << endl;        // 上行若抛异常，本行跳过
}
catch (ExceptionName1 e1) { /* 处理类型1 */ }
catch (ExceptionName2 e2) { /* 处理类型2 */ }
catch (...)               { /* 万能兜底，只能放最后 */ }
④ 注意：一个 try 可配多个 catch 按序匹配；try 块中一旦某语句抛异常，后续语句全部跳过。
人话总结：try 试一试，catch 接住处理。

4. 抛出异常 throw（P11-13）【重点】

① 是什么
throw 表达式; 在任何位置主动抛异常，表达式结果的类型决定异常类型（P12）。
② 为什么
div 函数内部最清楚"除数为0"，由它检测抛出，调用者决定怎么处理——错误发生点与处理点分离（P11）。
double div(double a, double b) {
    if (b == 0) {
        throw "Division by zero condition!";  // 抛出 const char* 类型
    }
    return (a / b);   // 抛出后这行不执行
}

配套代码同款：mycode.cpp 的 mydiv 在 v2==0 时 throw "divsion by zero condition"（比教材少感叹号、拼写少个 i）。

④ 注意（P13 核心教训）：只抛出、不捕获，程序无法正常运行结束——没人接异常就触发 terminate。
人话总结：想抛就抛，类型由表达式决定。

5. 捕获异常 catch（P14-16）【重点】

catch 跟在 try 后面，按括号里的异常声明指定捕获类型，按书写顺序逐一匹配（P14）。两种形式与教材控制台实录：

形式写法输出（P15/P16）
万能捕获catch(...)出错了! 然后 50（程序没死，add 照常执行）
类型捕获catch(const char* msg)Division by zero condition! 然后 50（msg 接住抛出的字符串）
try { double result1 = div(v1, v2); cout << result1 << endl; }
catch (const char* msg) { cerr << msg << endl; }   // 与 throw 类型严格一致

test01 中被注释的块就是这种写法，与 mydiv 抛出的 const char* 严格匹配。

④ 注意：catch 按顺序匹配，子类 catch 必须写在父类前面，否则被子类之前出现的父类截胡；catch(...) 只能垫底。
人话总结：按顺序匹配，子类放前面。

模块三：自定义异常 + 课堂练习 + 嵌套类/局部类

6. 自定义异常（P17-18）【重点】

① 是什么
继承 std::exception 并重写 what() 的类，用类对象表达业务自定义错误。
② 为什么
throw 字符串只给一句话；自定义异常是类型，携带语义、可被精确 catch、可扩展错误码。what() 是 exception 提供的公共方法，返回异常原因。
class MyException : public exception {
public:
    const char* what() const throw() {  // 重写 what()；const throw() 承诺不抛异常
        return "my test exception";
    }
};
int add(int v1, int v2) {
    if (v1 > 0) { MyException myex; throw myex; }  // 抛自定义对象
    return v1 + v2;
}
// main 中：
try { cout << add(100, 200) << endl; }
catch (exception& e) { cout << e.what() << endl; }  // 父类引用接子类对象

输出 my test exception。配套 MyExcption + add + test01 完全同构，test01 实际输出两行：my test exception 和 1111（后者证明异常处理完程序继续跑）。

④ 注意：捕获类异常必须用引用 catch(exception& e)——防对象切片、保多态；const throw() 是老式异常规格（现代 C++ 用 noexcept），新手照抄即可。
人话总结：继承 exception，重写 what，说清错因。

7. 课堂练习1：数组下标越界异常（P19-22）

思路三步：① 枚举当异常类型（异常不一定是类）→ ② 函数内两道边界检查越界就 throw → ③ catch 后按枚举值分支输出。

enum index { underflow, overflow };   // 0=下标太小, 1=下标太大
int array_index(int* arr, int n, int index) {
    if (index < 0)   throw underflow;   // 下标太小
    if (index > n-1) throw overflow;    // 下标太大
    return arr[index];                  // 合法下标正常取值
}

教材 P21 main 输出只有 5 和 index underflow!——第三个调用（idx=15）永远执行不到：idx=-1 抛异常后 try 块剩余语句全部跳过，且 exit(-1) 直接终止进程。想看 overflow 输出，得像配套 test02 那样把调用拆开分别测。

test02 当前输出 13（下标2合法取13）；放开 -2 行输出"下标太小了"；放开 100 行输出"下标太大了"；三行全放开只输出"下标太小了"。

人话总结：枚举当异常用，越界就抛。

8. 嵌套类和局部类（P23-30）【熟悉】

维度嵌套类局部类
定义位置类的内部函数体内
可见范围外围类作用域（外部用需 OuterClass::Inner 限定）仅所在函数内
成员函数类外定义可以（作用域链写全）不可以，必须类内定义
静态成员可以有不能有
访问外围成员不能访问外围类任何成员（反之亦然）实践中很少使用
class OuterClass {            // 外围类
public:
    class InnerClass {        // 嵌套类：语法上藏在外围类里
    public:
        void func();          // 可在类体外定义
    };
    InnerClass obj;           // 外围类持嵌套类对象作成员
};
void OuterClass::InnerClass::func() { /* 类外定义：作用域链写全 */ }

void func() {                 // 局部类：定义在函数体内
    class LocalClass {
    public:
        int num;
        void setNum(int n) { num = n; }              // 必须类内定义
        void showNum() { cout << "num=" << num << endl; }
    };
    LocalClass lc; lc.setNum(111); lc.showNum();     // num=111
}

P28-30 案例输出（与 test03 一致）：

Outerclass func()      ← 外围类对象调用，内部又调了嵌套类对象
InnerClass func()
**********************
InnerClass func()      ← OuterClass::InnerClass ic1; 作用域限定直接用
**********************
num = 111              ← 局部类演示

嵌套类只是"语法上的嵌入"，没有访问特权；老版本编译器可能不支持该特性（P23）。用途：外围类用它做底层实现并对用户隐藏（如迭代器）。

人话总结：藏在类里/函数里的类，只是作用域把戏。

陷阱一：catch 匹配顺序——子类必须在父类前

try { throw MyEx(); }        // 抛子类对象
catch (exception&)  { cout << "exception&"; }  // 父类在前：截胡！实际输出这行
catch (MyEx&)       { cout << "MyEx&"; }        // 子类在后：永远不可达

陷阱二：throw 与 catch 类型必须严格一致（不隐式转换）

try { throw "div by zero"; }           // const char*
catch (exception& e) { cout << "A"; }  // 捕不到！char* 不是 exception
catch (string s)     { cout << "B"; }  // 也捕不到！不会自动转换
catch (const char* m) { cout << m; }   // 类型一致才接得住 → 输出 div by zero

这正是 mycode.cpp 的现实：mydiv 抛 const char* 只能用 catch(const char*) 接；add 抛 MyExcption 对象只能用 exception& 接。两个都写错 → 程序 terminate。

另附两个高频错误：① 整数除0不会抛 C++ 异常，直接崩溃，想用异常机制必须自己 if 检测后 throw；② catch(...) 写在最前面会吞掉所有异常——永远放最后。

3throw 与 catch 类型不一致严格一致：const char* 配 const char*，类配引用
4以为异常抛出后 try 后面的语句还会执行不会，直接跳到 catch
5以为整数除0会抛异常int/int 除0直接崩溃，需自己 if 检测后 throw
6以为浮点除0会抛异常得 inf/nan 不抛；想抛自己写
7值传递捕获类异常 catch(exception e)用引用 catch(exception& e)，防切片保多态
8忘记 #include <exception>用 std::exception 前先包含
9what() 签名抄错const char* what() const throw() 照抄
10嵌套类想访问外围类私有成员不允许，嵌套类只是语法嵌入无特权
11局部类成员函数写到类外必须类内定义，且不能有静态成员
12只 throw 不 catch程序 terminate；每个 throw 都要有对应 catch

try 围住危险代码，throw 一抛控制权转移，catch 按类型接力处理。机制主线
子类在前，父类在后，三点(...)只能垫底。匹配顺序
抛啥接啥要门当户对；自定义异常继承 exception、重写 what。类型匹配
