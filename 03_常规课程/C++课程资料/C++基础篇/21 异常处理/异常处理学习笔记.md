## 模块一（基础篇）

### 1. 异常处理概述（P4-6）【了解】

**一句话概括**：异常处理是 C++ 处理"运行时错误"的机制，让程序出错后不至于直接崩溃，而是把控制权转移到专门处理错误的代码上去（P5-6）。

**P4 案例：这段代码有什么问题？**

```cpp
#include <iostream>
using namespace std;
int main()
{
    int num1=100, num2=0, num3=0;
    num3 = num1 / num2;   // 整数除以 0！
    cout << num3 << endl;
    return 0;
}
```

输出与后果：`num1 / num2` 是**整数除以0**，属于未定义行为。在 Visual Studio 下直接运行会弹"运行时错误"对话框，程序异常终止，`cout` 那行永远执行不到。

关键区分（贯穿全章的核心认知）：

| 情况 | 结果 | 会抛 C++ 异常吗 |
|------|------|----------------|
| 整数除以0（int / int） | 程序崩溃终止 | 否，硬件级错误，catch 不到 |
| 浮点除以0（double / double） | 得到 inf / nan，程序继续跑 | 否，静默产出错误值 |
| 代码里主动 `throw` | 抛出异常对象 | 是，这才是异常机制管的事 |

所以 C++ 的异常不会"自动出现"——**错误要靠程序员自己检测、自己 throw**（P11 的结论）。P10 的注释补充：inf = infinity（Linux）等同 #INF（Windows），nan = not a number 等同 #IND（Windows）；inf 一般是数值超出浮点表示范围（阶码溢出），nan 一般是对浮点做了未定义操作（如对 -1 开方）。

**人话总结**：异常就是"出错时的紧急出口"。

### 2. 标准异常（P7-8）【熟悉】

**① 是什么**：C++ 预先定义好的一整套异常类，全部派生自 `std::exception`，按父子层次组织（P7）。

**② 为什么**：常见错误（内存分配失败、越界、类型转换失败）大家都会遇到，标准库统一提供，不用每次自己造。

**层次结构**（P7 图整理为标准继承树）：

```
std::exception（所有标准异常的父类）
├── std::bad_alloc          new 分配内存失败
├── std::bad_cast           dynamic_cast 转换失败
├── std::bad_typeid         typeid 对空指针解引用
├── std::bad_exception      处理无法预期的异常
├── std::logic_error        理论上读代码就能发现的逻辑错误
│   ├── std::domain_error      使用了无效的数学域
│   ├── std::invalid_argument  使用了无效的参数
│   ├── std::length_error      创建了太长的 std::string
│   └── std::out_of_range      越界访问（如 vector::at()）
└── std::runtime_error      理论上读代码发现不了的运行时错误
    ├── std::range_error       存储超出范围的值
    ├── std::overflow_error    数学上溢
    └── std::underflow_error   数学下溢
```

**全表（P8）**：

| 异常 | 描述 |
|------|------|
| std::exception | 所有标准 C++ 异常的父类 |
| std::bad_alloc | 可以通过 new 抛出 |
| std::bad_cast | 可以通过 dynamic_cast 抛出 |
| std::bad_typeid | 可以通过 typeid 抛出 |
| std::bad_exception | 处理无法预期的异常时非常有用 |
| std::logic_error | 理论上可以通过读取代码来检测到的异常 |
| std::domain_error | 使用了一个无效的数学域时抛出 |
| std::invalid_argument | 使用了无效的参数时抛出 |
| std::length_error | 创建了太长的 std::string 时抛出 |
| std::out_of_range | 方法越界访问时抛出，如 std::vector 和 std::bitset 的 at() |
| std::runtime_error | 理论上不可以通过读取代码来检测到的异常 |
| std::overflow_error | 发生数学上溢时抛出 |
| std::range_error | 尝试存储超出范围的值时抛出 |
| std::underflow_error | 发生数学下溢时抛出 |

**③ 怎么用**（5行示例）：

```cpp
#include <exception>   // 标准异常都在这个头文件里
#include <vector>
#include <iostream>
int main() {
    std::vector<int> v = {1, 2, 3};
    try { v.at(10); }                        // at() 会做越界检查
    catch (std::exception& e) { std::cout << e.what(); }  // 输出：vector::_M_range_check
}
```

**④ 注意事项**：使用标准异常要 `#include <exception>`；memory 头文件里的 `bad_alloc` 在 new 失败时自动抛出（默认不返回 nullptr）。

**人话总结**：现成的异常家族，记得 include exception。

## 模块二（核心篇）

### 3. try/catch 语句（P9-10）【重点】

**① 是什么**：try 块放置可能出错的代码（称为**保护代码**），后面跟一个或多个 catch 块负责捕获并处理对应类型的异常（P9）。

**② 为什么**：P10 的 `div(50, 0)` 案例证明——浮点除0不崩溃但输出 `inf`（错误结果照常往下传），程序"正常运行结束"却算出了错值。要把错误引到能处理它的地方，就必须用 try/catch 把调用包起来。

**③ 怎么用**：

```cpp
try {
    double result1 = div(v1, v2);   // 保护代码：可能抛异常的调用
    cout << result1 << endl;        // 若上行抛异常，本行不执行
}
catch (ExceptionName1 e1) { /* 处理类型1 */ }
catch (ExceptionName2 e2) { /* 处理类型2 */ }
catch (...)               { /* 万能兜底，必须放最后 */ }
```

P10 原案例（没有异常处理时）：

```cpp
double div(double x, double y) { return (x / y); }
double add(double x, double y) { return x + y; }
int main() {
    double v1 = 50, v2 = 0;
    double result1 = div(v1, v2);
    cout << result1 << endl;      // Windows 输出：inf（不是崩溃！）
    double result2 = add(v1, v2);
    cout << result2 << endl;      // 50
}
```

**④ 注意事项**：try 块中有多条语句时，一旦某条抛出异常，**后续语句全部跳过**，直接跳到匹配的 catch；一个 try 可以配多个 catch，按顺序匹配。

**人话总结**：try 试一试，catch 接住处理。

### 4. 抛出异常 throw（P11-13）【重点】

**① 是什么**：`throw 表达式;` 在代码任何位置主动抛出异常，**表达式结果的类型决定了异常的类型**（P12）。

**② 为什么**：P11 结论——div 函数内部最清楚"除数为0"这个错误，由它检测并抛出，调用者决定怎么处理；错误的发生点和处理点分离。

**③ 怎么用**（P12 案例）：

```cpp
double div(double a, double b) {
    if (b == 0) {
        throw "Division by zero condition!";  // 抛出 const char* 类型的异常
    }
    return (a / b);   // 抛异常后这行不会执行，函数立即"返回"
}
```

配套代码 mycode.cpp 中的同款（第36-40行区域）：

```cpp
double mydiv(double v1, double v2) {
    if (v2 == 0) {
        throw "divsion by zero condition";  // 抛 const char*（源码拼写比教材少个 i）
    }
    return v1 / v2;
}
```

**④ 注意事项**（P13 的核心教训）：**只抛出、不捕获，程序无法正常运行结束**——异常没人接，std::terminate 被触发，程序直接终止。throw 的操作数可以是任意类型：字符串、int、枚举、类对象都行，类型即身份。

**人话总结**：想抛就抛，类型由表达式决定。

### 5. 捕获异常 catch（P14-16）【重点】

**① 是什么**：catch 跟在 try 后面，按括号里的**异常声明**指定要捕获的类型，按书写顺序逐一匹配（P14）。

**② 为什么**：P13 证明只抛不捕程序会死；catch 就是异常的"接球手"，接住后程序才能继续正常流转。

**③ 怎么用**——两种形式（P14）：

```cpp
try { double result1 = div(v1, v2); cout << result1 << endl; }
catch (...) { cout << "出错了!" << endl; }        // 形式1：省略号，捕获任何异常
```

P15 输出（控制台）：

```
出错了!
50
```

解读：div 抛异常 → 跳进 catch(...) 打印"出错了!" → **程序没死**，继续执行 main 里后面的 add(v1,v2)，正常打印 50。

```cpp
try { double result1 = div(v1, v2); cout << result1 << endl; }
catch (const char* msg) { cerr << msg << endl; }  // 形式2：捕获指定类型，拿到异常消息
```

P16 输出（控制台）：

```
Division by zero condition!
50
```

解读：catch 的参数类型 `const char*` 与 throw 抛出的类型一致，所以能把抛出的字符串接进 msg 里打印；之后 add 照常执行输出 50。

配套代码 mycode.cpp 中 test01 被注释的捕获块就是这种写法：

```cpp
try {
    cout << mydiv(num1, num2) << endl;
}
catch (const char* msg) {   // 与 mydiv 抛出的 const char* 严格匹配
    cerr << msg << endl;    // 输出：divsion by zero condition
}
```

**④ 注意事项**：**catch 按顺序匹配，子类 catch 必须写在父类 catch 前面**——否则父类先匹配成功，子类分支永远轮不到；`catch(...)` 能接任何异常，所以只能垫底放最后。

**人话总结**：按顺序匹配，子类放前面。

### 6. 自定义异常（P17-18）【重点】

**① 是什么**：继承 `std::exception` 并重写 `what()` 的类，用类对象表达"业务里自定义的错误"（P17）。

**② 为什么**：throw "字符串" 只能给一句话；自定义异常是类型，携带语义，可以被精确 catch，也能扩展成员（错误码等）。`what()` 是 exception 类提供的公共方法，用于返回异常的原因描述。

**③ 怎么用**（P17-18 教材案例）：

```cpp
#include <exception>
class MyException : public exception {
public:
    // 重写 what()；const throw() 表示承诺此函数不抛异常（C++98 异常规格写法）
    const char* what() const throw() {
        return "my test exception";
    }
};

int add(int v1, int v2) {
    if (v1 > 0) {          // 如果 v1>0，抛出自定义异常对象
        MyException myex;
        throw myex;
    }
    return v1 + v2;
}

int main() {
    int num1 = 100, num2 = 200;
    try { cout << add(num1, num2) << endl; }   // add 抛异常，这行不执行
    catch (exception& e) {                      // 用父类引用接住子类对象
        cout << e.what() << endl;               // 输出：my test exception
    }
}
```

输出：`my test exception`。`add(100,200)` 中 v1=100>0 触发 throw，try 块的 cout 被跳过，异常被 `catch(exception& e)` 接住，`e.what()` 返回重写的字符串。

配套代码 mycode.cpp 完全同构（注意源码类名拼写少个 i）：

```cpp
class MyExcption : public exception {
public:
    const char* what() const throw() { return "my test exception"; }
};
double add(double v1, double v2) {
    if (v1 > 0) { MyExcption myex; throw myex; }   // v1>0 就抛
    return v1 + v2;
}
void test01() {
    int num1 = 200, num2 = 0, num3;
    try { cout << add(num1, num2) << endl; }   // 200>0 → 抛
    catch (exception& e) { cout << e.what() << endl; }
    cout << 1111 << endl;                       // 证明程序还活着，继续往下跑
}
```

test01 实际输出：

```
my test exception
1111
```

**④ 注意事项**：捕获类异常用**引用** `catch(exception& e)`，避免对象切片、也能正确触发多态；`const throw()` 是老式异常规格，意思是"保证不抛"，新手照抄即可，现代 C++ 已改用 `noexcept`。

**人话总结**：继承 exception，重写 what，说清错因。

### 7. 课堂练习1：数组下标越界异常（P19-22）

**题目（P19）**：创建一个数组和取元素的函数；下标小于0抛 `underflow`，下标大于最大下标 n-1 抛 `overflow`，其他情况正常取值。

**思路分析（三步）**：
1. 异常不一定非得是类——**枚举值就能当异常抛**：`enum index { underflow, overflow };`
2. 函数内做两道边界检查，越界就 `throw` 对应枚举常量，类型即 `index` 枚举类型；
3. main 里 try 包住调用，catch(index e) 拿到枚举值后用 if 判断是哪一种越界，输出不同提示。

**教材解法（P20 声明 / P22 函数）**：

```cpp
#include <iostream>
using namespace std;
enum index { underflow, overflow };   // 0=underflow 下标太小, 1=overflow 下标太大
int array_index(int* arr, int n, int index);

int array_index(int* arr, int n, int index) {
    if (index < 0)    throw underflow;   // 下标太小，抛枚举常量
    if (index > n-1)  throw overflow;    // 下标太大
    return arr[index];                   // 合法下标，正常取值
}
```

**教材 main（P21）**：

```cpp
int main() {
    int* arr = new int[10];
    for (int i = 0; i < 10; i++) arr[i] = i;
    try {
        cout << array_index(arr, 10, 5)  << endl;   // 正常：输出 5
        cout << array_index(arr, 10, -1) << endl;   // 抛 underflow
        cout << array_index(arr, 10, 15) << endl;   // 永远执行不到！
    }
    catch (index e) {
        if (e == underflow)      { cout << "index underflow!" << endl; exit(-1); }
        else if (e == overflow)  { cout << "index overflow!"  << endl; exit(-1); }
    }
    return 0;
}
```

**输出分析**：先打印 `5`；第二次调用 idx=-1 抛 underflow，try 块中**第三条语句被跳过**（活生生演示"异常后后续语句不执行"）；catch 匹配后打印 `index underflow!`，`exit(-1)` 直接终止整个进程——所以 overflow 分支在这个 main 里永远不会被验证到。想看到 overflow 输出，得像配套代码那样把三个调用拆开分别测。

**配套代码 mycode.cpp 的改造版（test02，第15-23行 + 24-32行）**：

```cpp
void test02() {
    int* arr = new int[5];
    for (int i = 0; i < 5; i++) arr[i] = i + 11;   // arr = {11,12,13,14,15}
    try {
        //cout << array_index(arr, 5, -2)  << endl;  // 放开→抛underflow→"下标太小了"
        //cout << array_index(arr, 5, 100) << endl;  // 放开→100>4抛overflow→"下标太大了"
        cout << array_index(arr, 5, 2) << endl;     // 正常：输出 13
    }
    catch (index e) {
        if (e == underflow)     cout << "下标太小了" << endl;
        else if (e == overflow) cout << "下标太大了" << endl;
    }
}
```

三种情况的输出：`13`（当前，下标2合法取13）；放开 -2 行 → `下标太小了`；只放开 100 行 → `下标太大了`；**三行全放开 → 只输出"下标太小了"**（第一个异常抛出后，try 里后面两行全部跳过）。

**人话总结**：枚举当异常用，越界就抛。

### 8. 嵌套类和局部类（P23-30）【熟悉】

**嵌套类**

**① 是什么**：定义在另一个类（外围类）内部的类（P24 语法：class 外围类名 { class 嵌套类名 { ... }; };）。

**② 为什么**：外围类需要用嵌套类对象作为底层实现，且只想给自己用、对用户隐藏该实现（P23）。

**③ 怎么用 + 特点**（P25）：

```cpp
class OuterClass {
public:
    class InnerClass {          // 嵌套类：语法上藏在外围类里
    public:
        void func();            // 成员函数可在类体外定义
    };
    InnerClass obj;             // 外围类持有嵌套类对象作为成员
};
// 类体外定义要写全作用域链：外围类::嵌套类::函数
void OuterClass::InnerClass::func() { /* ... */ }
```

**④ 注意事项**：嵌套类**不能访问外围类的任何成员**（反之亦然），它只是"语法上的嵌入"，没有特殊访问权；外围类可以通过**对象**访问嵌套类的公有成员（不能访问其保护/私有成员）；类名在外要用作用域限定 `OuterClass::InnerClass`；老版本编译器可能不支持。

**局部类**

**① 是什么**：定义在函数体内的类（P26-27）。

**② 为什么 / 特点**：只在定义它的局部域内可见，出了函数就不能用；适合函数内部私有的小工具结构。

**③ 怎么用**：

```cpp
void func() {
    class LocalClass {          // 局部类
    public:
        int num;
        void setNum(int n) { num = n; }          // 成员函数必须定义在类体中
        void showNum() { cout << "num=" << num << endl; }
    };
    LocalClass lc; lc.setNum(111); lc.showNum(); // num=111
}
```

**④ 注意事项**：成员函数**必须**定义在类体内（不能类外定义）；**不能有静态数据/函数成员**；实践中很少使用。

**嵌套类 vs 局部类 对比表**：

| 维度 | 嵌套类 | 局部类 |
|------|--------|--------|
| 定义位置 | 类的内部 | 函数体内 |
| 可见范围 | 外围类作用域（外部用需 OuterClass::X 限定） | 仅定义它的函数体内 |
| 成员函数类外定义 | 可以（作用域链写全） | 不可以，必须类内定义 |
| 静态成员 | 可以有 | 不能有 |
| 访问外围成员 | 不能访问外围类任何成员 | 不能访问函数局部变量（除全局） |
| 实用频率 | 常见（隐藏实现、迭代器） | 很少使用 |

**P28-30 教材案例输出**：

```
OuterClass func()
InnerClass func()
**********************
InnerClass func()
**********************
num = 111
```

解读：`oc1.func()` 打印第一行后，外围类 func 内部又调 `obj.func()` 打印第二行；`OuterClass::InnerClass ic1; ic1.func();` 直接打印 InnerClass func()（演示作用域限定用法）；最后全局 func() 里的局部类打印 num=111。

**人话总结**：藏在类里/函数里的类，只是作用域把戏。

## 5. 两大易错陷阱（代码演示）

### 陷阱一：catch 匹配顺序——子类必须写在父类前面

```cpp
class MyEx : public exception { public: const char* what() const throw() { return "boom"; } };
try {
    throw MyEx();            // 抛子类对象
}
catch (exception&) {         // 父类写在前：先匹配成功，把异常"截胡"
    cout << "exception&" ;  // 实际走到这里！
}
catch (MyEx&) {              // 子类写在后：永远不可达（编译器警告）
    cout << "MyEx&";
}
```

输出：`exception&`。正确写法是把 catch(MyEx&) 放在 catch(exception&) 前面。

### 陷阱二：throw 与 catch 的类型必须严格匹配（不隐式转换）

```cpp
try { throw "div by zero"; }        // 抛的是 const char*
catch (exception& e) { cout << "A"; }   // 捕不到！const char* 不是 exception
catch (string s)     { cout << "B"; }   // 也捕不到！不会自动把 char* 转成 string
catch (const char* msg) { cout << msg; } // 只有类型一致才接得住
```

输出：`div by zero`。对应 mycode.cpp 的现实意义：mydiv 抛 const char*，test01 若只写 catch(exception&) 去接，程序会 terminate——所以被注释的那块用的是 catch(const char* msg)。反过来，add 抛的是 MyExcption 对象，必须用 exception&（或 MyExcption&）接，用 catch(const char*) 也接不住。

**另附两个本章相关的高频错误**：
- 整数除0不会抛 C++ 异常，直接崩溃；想用异常机制就必须自己 `if (b==0) throw ...`。
- catch(...) 写在最前面会吞掉所有异常，让后面的 catch 全部失效——永远放最后。

**(1) 什么叫异常处理？**
答：异常处理是一种程序定义的错误，它对程序的逻辑错误进行设防，并对运行异常加以控制。在 C++ 中，异常处理是对所能预料的运行错误进行处理的一套实现机制。

**(2) C++ 的异常处理机制有何优点？**
答：C++ 的异常处理机制使得异常的引发和处理不必在同一函数中。C++ 异常处理的目的是在异常发生时，尽可能地减小破坏，周密地善后，而不影响其他部分程序的运行。这样底层的函数可以着重解决具体问题，而不必过多地考虑对异常的处理；上层调用者可以在适当的位置设计对不同类型异常的处理，这在大型程序中是非常必要的。
