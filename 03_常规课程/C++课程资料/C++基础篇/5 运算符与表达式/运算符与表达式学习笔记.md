## 1.1 正号 `+` 与负号 `-`（一元运算符）｜课件 P4 表前 2 行【重点】

**① 是什么**
一句话定义：`+`、`-` 放在**单个操作数前面**时是一元运算符，表示数值的符号，不改变数值大小（`-` 会取相反数）。
生活比喻：温度计上"零下 4 度"的负号，只是告诉你方向在零以下，不代表"4 被谁减掉了"。

**② 为什么**
计算机里的整数用**补码**存储（正好呼应课件 P2 复习页的原码/反码/补码）。有了符号位，语言就必须提供一元 `-` 来生成相反数——它的底层动作是"按位取反再加一"。这也是为什么 `sizeof(-4)` 与 `sizeof(4)` 相同。

**③ 怎么用**

```cpp
#include <iostream>          // 头文件：cout 在这里
using namespace std;

int main() {
    int a = +3;              // 一元正号：写了等于没写，纯粹提高可读性
    int b = -4;              // 一元负号：b 存的是 -4 的补码
    int c = -a;              // 取相反数：c = -3
    cout << a << " " << b << " " << c << endl;
    cout << sizeof(a) << " " << sizeof(b) << endl;   // 符号不改变类型和字节数
    return 0;
}
// 输出：
// 3 -4 -3
// 4 4
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范：以为负号能突破类型范围
    // int bad = -2147483648;   // MSVC/GCC 都可能报警告：字面量 2147483648 已超出 int
    //                          // 编译器把 2147483648 当 unsigned/long，再取负，语义微妙
    // ✅ 正确写法：用减法表达 INT_MIN，或用 long long 加后缀
    int good = (-2147483647 - 1);        // INT_MIN 的经典可移植写法
    long long v = -2147483648LL;         // 加 LL 后缀，类型明确
    cout << good << " " << v << endl;
    return 0;
}
// 输出：
// -2147483648 -2147483648
```

> **有个坑**：`a = -b` 与 `a - b` 长得太像。前者是**一元负号**（第3优先级、右结合）外加一条赋值，后者是**减法**（第6优先级、左结合）。差别不只一个空格：`a=-b` 是一条语句，`a - b` 甚至不是语句（没有 `=`，它只是个表达式）。

## 1.2 加法运算符 `+`（二元）｜清单第 1 条【重点】

**① 是什么**
一句话定义：`+` 把两个操作数相加，结果的类型由"共同类型"决定（两边先提升到同一类型再加）。
生活比喻：两笔钱放进同一个钱包，钱包能装的钱有上限——装不下的部分不会报错，而是**从另一头冒出来**。

**② 为什么**
硬件只有固定位数的加法器（32 位 / 64 位）。两个大数相加超过该类型的表示范围，就会发生**溢出（overflow）**，产生"回绕"的错误值。C++ 规定**有符号整数溢出为未定义行为（UB）**，**无符号整数溢出则明确规定回绕**——两者后果不同，都必须防。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 10, b = 3;
    int sum = a + b;                       // 课件表：5 + 5 = 10
    cout << "a + b = " << sum << endl;
    cout << "5 + 5 = " << 5 + 5 << endl;

    short s1 = 30000, s2 = 30000;
    auto r = s1 + s2;                      // short + short 会先提升为 int 再相加
    cout << "s1 + s2 = " << r
         << "，r 的类型是 " << (sizeof(r) == sizeof(int) ? "int" : "其他") << endl;
    return 0;
}
// 输出：
// a + b = 13
// 5 + 5 = 10
// s1 + s2 = 60000，r 的类型是 int
```

**关键行状态走读**：`int a=10, b=3;` → 栈上 `a=10`（4 字节）、`b=3`（4 字节）。执行 `a + b`：两个 `int` 类型相同，无需提升，直接整数加法得 13，赋给 `sum`。`short s1=30000; short s2=30000;` → 若按 `short` 相加，60000 超出 `short` 上限 32767 会溢出；但因为**整型提升**先把两者升为 `int`，结果 60000 安全落在 `int` 范围内。这个例子恰好说明：提升既是陷阱（下面 1.8 会讲 char），也是保护。

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
#include <climits>           // INT_MAX, INT_MIN 在这里
using namespace std;
int main() {
    // ❌ 错误示范：有符号溢出，结果是未定义行为
    int big = INT_MAX;            // 2147483647
    int boom = big + 1;           // UB！GCC -O0 通常打印 -2147483648，但编译器有权做任何事
    cout << boom << endl;         // 别指望它稳定

    // ✅ 正确写法一：升级到更宽的类型
    long long safe = static_cast<long long>(big) + 1;   // 2147483648，稳稳的
    cout << safe << endl;

    // ✅ 正确写法二：加之前做范围检查
    if (big <= INT_MAX - 1) { cout << "这次加法是安全的\n"; }
    return 0;
}
// 输出：
// -2147483648
// 2147483648
// 这次加法是安全的
```

> **小心**：`cout << a + b << endl;` 中的 `+` 会被优先计算（第6级高于 `<<` 的第7级），所以不需要括号。但一旦换成字符串拼接思维（`"x=" + a`）就会编译失败——C++ 内置的 `+` **不能**用来拼 C 风格字符串，那是 `std::string` 重载运算符后才有的能力。

## 1.3 减法运算符 `-`（二元）｜清单第 2 条【重点】

**① 是什么**
一句话定义：`-` 求两数之差，**左操作数减右操作数**，顺序不能换（`a-b ≠ b-a`）。
生活比喻：余额扣款。账户里只有 3 块钱，硬刷 10 块的卡——银行卡会拒绝，但 C++ 不会拒绝，它会给你一个"欠出来的怪数"。

**② 为什么**
减法不对称，所以是**左结合**：`a - b - c` 必须解释成 `(a - b) - c`。而在**无符号类型**上做减法，结果小于 0 时会按模回绕，得到一个大正数——这是 C/C++ 最著名的隐藏 bug 源之一。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 10, b = 3;
    cout << "a - b = " << a - b << endl;               // 课件表：10 - 5 = 5 同理
    cout << "b - a = " << b - a << endl;               // 负数完全合法
    cout << "10 - 5 = " << 10 - 5 << endl;

    // 结合性演示
    cout << "10 - 3 - 2 = " << 10 - 3 - 2 << endl;     // (10-3)-2 = 5
    cout << "10 - (3 - 2) = " << 10 - (3 - 2) << endl; // 括号改变结果 = 9
    return 0;
}
// 输出：
// a - b = 7
// b - a = -7
// 10 - 5 = 5
// 10 - 3 - 2 = 5
// 10 - (3 - 2) = 9
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范：无符号下溢，看着像"成功"实则灾难
    unsigned int remain = 3;
    unsigned int cost = 10;
    if (remain - cost > 0) {                 // remain-cost = 4294967289，永远 > 0！
        cout << "库存充足，可以扣款（其实不够！）\n";   // 结果：真的走进了这里
    }
    // ✅ 正确写法：比较之前不要先相减
    if (remain > cost) { cout << "不会打印\n"; }
    else { cout << "正确判断：库存不足\n"; }
    // ✅ 或者明确使用有符号类型
    int signedRemain = 3;
    if (signedRemain - static_cast<int>(cost) > 0) { cout << "不会打印\n"; }
    else { cout << "有符号版本给出 -7，判断正确\n"; }
    return 0;
}
// 输出：
// 库存充足，可以扣款（其实不够！）
// 正确判断：库存不足
// 有符号版本给出 -7，判断正确
```

> **跨平台提醒（提示词硬性要求）**：`char` 到底是有符号还是无符号，**C++ 标准没有规定**，由各实现自行决定——GCC（x86/x64）默认 `signed char`，MSVC 默认 `signed char`，但 ARM 上的 GCC 常默认 `unsigned char`。所以 `char c = 200; if (c - 100 > 0)` 这类判断在不同编译器上可能给出相反结论。**安全写法**：需要数值语义时写死 `signed char` 或 `unsigned char`，或者 `int v = static_cast<unsigned char>(c);`。

## 1.4 乘法运算符 `*`｜清单第 3 条【重点】

**① 是什么**
一句话定义：`*` 求两数之积。注意 `*` 还是个"多义演员"——在声明里它表示指针，在表达式里它表示乘法，在 `*ptr` 里它表示解引用。
生活比喻：单价 × 数量。数量翻十倍，总价也翻十倍——如果总价那个变量装不下，钱就直接"爆"没了。

**② 为什么**
乘法增长最快，因此**最容易溢出**。两个 `int`（各 4 字节）相乘，结果最大可达约 4.6×10¹⁸，远超 `int` 上限 2.1×10⁹。此外，`int * int` 在两个操作数都是 `int` 时**不会自动升到 `long long`**，溢出发生在赋值之前。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 10, b = 3;
    cout << "a * b = " << a * b << endl;             // 课件表：5 * 2 = 10
    cout << "5 * 2 = " << 5 * 2 << endl;

    // 想放大 10000 倍又担心 int 不够？先升类型再乘
    int n = 1000000;                                  // 一百万
    long long ok = static_cast<long long>(n) * 10000; // 先转，再乘 → 安全
    cout << "ok = " << ok << endl;
    return 0;
}
// 输出：
// a * b = 30
// 5 * 2 = 10
// ok = 10000000000
```

**关键行状态走读**：`static_cast<long long>(n) * 10000` —— `n`（`int`, 1000000）先被显式转为 `long long`；此时另一个操作数 `10000` 仍是 `int`，触发**算术转换规则**：`int` 与 `long long` 混合，`int` 自动升为 `long long`，最终在 64 位空间里算出 10000000000，安然无恙。若写成 `n * 10000`（都在 `int` 里算），就已经溢出，之后再转 `long long` 也救不回来。

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
#include <climits>
using namespace std;
int main() {
    // ❌ 错误示范：先溢出再转换，为时已晚
    int n = 1000000;
    long long wrong = n * 10000;      // n*10000 在 int 里算 → UB，实际常得到 1410065408
    cout << "wrong = " << wrong << endl;

    // ❌ 错误示范：把乘号当声明符
    int* p, q;                        // p 是 int*，q 仍然是 int！星号只管紧邻的那个名字
    // ✅ 正确写法：每个指针单独写星号，或者用别名
    int b = 5;
    int *p1, *q1;                     // 两个都是 int*
    using IntPtr = int*;
    IntPtr p2, q2;                    // 两个都是 int*，最清晰
    p1 = &b; q1 = &b; p2 = &b; q2 = &b;
    cout << "p1=" << *p1 << " q1=" << *q1 << " p2=" << *p2 << " q2=" << *q2 << endl;

    // ✅ 溢出前的防护写法
    int aa = 1000000, bb = 10000;
    if (aa != 0 && bb > INT_MAX / aa) { cout << "会溢出，改走 long long 分支\n"; }
    return 0;
}
// 输出：
// wrong = 1410065408
// p1=5 q1=5 p2=5 q2=5
// 会溢出，改走 long long 分支
```

## 1.5 除法运算符 `/` 与整数除法截断｜清单第 4、5 条【重点 · 全章第一杀手】

**① 是什么**
一句话定义：`/` 求商；**当两个操作数都是整数时，结果只保留整数部分，小数部分被直接砍掉（向零取整）**；只要有一个操作数是浮点，就做真正的浮点除法。
生活比喻：把 7 块糖平分给 2 个人——每人 3 块，剩下那块**不会切成半块**，它就那样消失了，没人通知你。

**② 为什么**
整数类型在硬件层没有"小数位"的概念，`idiv` 指令同时产出商和余数，语言层面只能取其中一个：`/` 取商（丢弃余数），`%` 取余数（丢弃商）。所以截断不是 bug，是**设计**。课件把这行字单独强调在 P4 页面上，正是因为它违反所有人从小学到高中的直觉。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 课件 P4 语法表：10 / 3 = 3 =====
    cout << "10 / 3   = " << 10 / 3 << endl;         // 整数除法，截断

    // ===== 清单第5条：7/2 与 -7/2 =====
    cout << "7 / 2    = " << 7 / 2 << endl;          // 3，不是 3.5
    cout << "-7 / 2   = " << -7 / 2 << endl;         // -3（向零取整，不是 -4）
    cout << "7 / -2   = " << 7 / -2 << endl;         // -3
    cout << "-7 / -2  = " << -7 / -2 << endl;        // 3

    // ===== 想要小数的四种正确写法 =====
    cout << "7.0 / 2        = " << 7.0 / 2 << endl;             // 写法1：字面量带小数点
    cout << "7 / 2.0        = " << 7 / 2.0 << endl;             // 写法2：右边是浮点
    cout << "(double)7 / 2  = " << (double)7 / 2 << endl;       // 写法3：C 风格强转
    int a = 7, b = 2;
    cout << "static_cast<double>(a)/b = "
         << static_cast<double>(a) / b << endl;                  // 写法4：C++ 推荐

    // ===== 课堂代码第27行的写法 =====
    int aa = 10, bb = 3; float d = 0;
    d = aa * 1.0 / bb;
    cout << "d = aa * 1.0 / bb = " << d << endl;
    return 0;
}
// 输出：
// 10 / 3   = 3
// 7 / 2    = 3
// -7 / 2   = -3
// 7 / -2   = -3
// -7 / -2  = 3
// 7.0 / 2        = 3.5
// 7 / 2.0        = 3.5
// (double)7 / 2  = 3.5
// static_cast<double>(a)/b = 3.5
// d = aa * 1.0 / bb = 3.33333
```

**逐行走读（清单第 5 条要求的经典案例）**

```
int a = 7;          // 栈：a = 7（int, 4 字节）
int b = 2;          // 栈：b = 2（int, 4 字节）
int c = a / b;      // ① 两个操作数都是 int → 走"整数除法"这条路
                    // ② 数学值 3.5，向零取整 → 商 3
                    // ③ c = 3。被砍掉的 0.5 永久丢失，没有任何警告、没有任何地方保存它
double e = a / b;   // 陷阱升级版：a/b 仍然先算成 int 的 3，然后才转 double
                    // e = 3（即 3.000000），不是你想要的 3.5！
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    int total = 7, count = 2;

    // ❌ 错误示范一：整数除法算平均分，小数部分静默消失
    double avg1 = total / count;        // 先 7/2=3（int），再转 3.0 → 错！
    cout << "avg1 = " << avg1 << endl;

    // ✅ 正确写法：让除法发生时至少有一个是浮点
    double avg2 = static_cast<double>(total) / count;   // 3.5 ✔
    double avg3 = 1.0 * total / count;                  // 3.5 ✔（1.0*7=7.0 已是 double）
    double avg4 = total / (double)count;                // 3.5 ✔
    cout << "avg2=" << avg2 << " avg3=" << avg3 << " avg4=" << avg4 << endl;

    // ❌ 错误示范二：除以零
    int z = 0;
    // cout << 10 / z << endl;         // 整数除零 = 未定义行为，运行时通常崩（SIGFPE / 0xC0000094）
    cout << "10.0 / 0.0 = " << 10.0 / 0.0 << endl;   // 浮点除零 = inf（IEEE 754 特殊值，不崩）

    // ✅ 正确写法：除法之前永远先判除数
    if (z != 0) { cout << 10 / z << endl; } else { cout << "除数不能为 0\n"; }
    return 0;
}
// 输出：
// avg1 = 3
// avg2=3.5 avg3=3.5 avg4=3.5
// 10.0 / 0.0 = inf
// 除数不能为 0
```

> **口诀**：*整除截断要小心，想要小数先变身。*
> **面试必问**："7/2 的结果是什么？如何得到 3.5？" 标准答法见[面试高频考点](#面试)。

## 1.6 取模运算符 `%`｜清单第 6 条【重点】

**① 是什么**
一句话定义：`%` 求**整数除法**的余数，写作 `m % n`；两个操作数**必须都是整数**；结果的绝对值永远小于右操作数的绝对值。
生活比喻：一圈 60 分钟的表盘。现在是第 137 分钟，`137 % 60 = 17`——你只需要知道"转过几圈后停在哪"。

**② 为什么**
`/` 扔掉的正是 `%` 要留下的，两者是同一条 `idiv` 指令的两个出口。取模是**判断整除、循环取值、拆位取数字**的基础工具：`i % n` 做环形数组、`n % 2` 判奇偶、`n % 10` 取个位。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 课件 P4 语法表：10 % 3 = 1 =====
    cout << "10 % 3 = " << 10 % 3 << endl;

    // ===== 三大典型用途 =====
    for (int n = 0; n <= 6; ++n) {
        cout << n << (n % 2 == 0 ? " 是偶数\n" : " 是奇数\n");   // 用途1：判奇偶
    }
    int idx = 137, size = 5;
    cout << "环形下标：" << idx << " % " << size << " = " << idx % size << endl; // 用途2：循环取值
    int num = 358;
    cout << "个位=" << num % 10
         << " 十位=" << num / 10 % 10
         << " 百位=" << num / 100 % 10 << endl;                              // 用途3：拆位

    // ===== 清单第 6 条：负数取模 =====
    cout << "-7 % 2  = " << -7 % 2 << endl;    // -1
    cout << "7 % -2  = " << 7 % -2 << endl;    //  1
    cout << "-7 % -2 = " << -7 % -2 << endl;   // -1
    cout << "-9 % 4  = " << -9 % 4 << endl;    // -1
    cout << "9 % -4  = " << 9 % -4 << endl;    //  1
    cout << "恒等式检验 (a/b)*b + a%b == a ："
         << ((-7 / 2) * 2 + (-7 % 2) == -7) << endl;
    return 0;
}
// 输出：
// 10 % 3 = 1
// 0 是偶数
// 1 是奇数
// 2 是偶数
// 3 是奇数
// 4 是偶数
// 5 是奇数
// 6 是偶数
// 环形下标：137 % 5 = 2
// 个位=8 十位=5 百位=3
// -7 % 2  = -1
// 7 % -2  =  1
// -7 % -2 = -1
// -9 % 4  = -1
// 9 % -4  =  1
// 恒等式检验 (a/b)*b + a%b == a ：1
```

**负数取模规则（背下来）**

| 表达式 | 结果 | 记忆要点 |
|--------|------|----------|
| `7 % 2` | `1` | 正常 |
| `-7 % 2` | `-1` | **符号跟随左操作数** |
| `7 % -2` | `1` | 右操作数符号不影响结果符号 |
| `-7 % -2` | `-1` | 仍跟随左边 |
| 恒等式 | — | `(a/b)*b + a%b` 恒等于 `a`（C++11 起强制） |

因为 `/` 自 C++11 起规定**向零取整**（truncation toward zero），所以 `%` 的符号必然跟着左操作数走。这也意味着：**负数取模的结果可能是负数**，直接拿去当数组下标会越界。

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
#include <cmath>            // fmod 在这里
using namespace std;
int main() {
    // ❌ 错误示范一：对浮点数用 %（这正是课堂代码第33-35行被注释掉的原因）
    float v1 = 11.234f, v2 = 2.45f;
    // cout << (v1 % v2) << endl;   // 编译错误！
    // error: invalid operands of types 'float' and 'float' to binary 'operator%'
    //                          ↑ 来自 GCC 的真实报错信息
    // ✅ 正确写法：浮点取余要用库函数
    cout << "fmod(11.234, 2.45) = " << fmod(11.234, 2.45) << endl;

    // ❌ 错误示范二：负数结果当下标
    int arr[5] = {1, 2, 3, 4, 5};
    int i = -1, n = 5;
    int pos = i % n;                 // -1 ！arr[-1] 直接越界
    // ✅ 正确写法：加上模数再取模，把结果"掰正"
    int safePos = ((i % n) + n) % n; // 4 ✔ 数学上叫"欧几里得取模"
    cout << "safePos = " << safePos << " arr[safePos]=" << arr[safePos] << endl;

    // ❌ 错误示范三：右操作数为 0
    // cout << 7 % 0 << endl;        // 未定义行为，运行崩溃
    return 0;
}
// 输出：
// fmod(11.234, 2.45) = 1.534
// safePos = 4 arr[safePos]=5
```

> **跨平台提醒（提示词硬性要求）**：C++98/03 时代，负数除法的取整方向（向零 or 向下）由实现定义，`%` 的符号因此**编译器而异**（老版 Visual C++ 与 GCC 曾不一致）。**C++11 起标准化为向零取整**，MSVC 2012+、GCC 4.7+、Clang 全部一致。**安全写法**：仍想万无一失就用 `((a % b) + b) % b`，或干脆避免对负数取模。

## 1.7 自增 `++` 与自减 `--`｜课件 P4 表末两行 + 课堂代码第39-41行 + 课件 P16 作业【重点】

**① 是什么**
一句话定义：`++`/`--` 让变量自身加 1 / 减 1；放在变量**后面**（后缀，如 `a++`）"先用旧值参与表达式，再自增"，放在**前面**（前缀，如 `++a`）"先自增，再用新值参与表达式"。
生活比喻：`a++` 像"拍完照再长高一厘米"——照片里还是原来的你；`++a` 像"先长高再拍照"——照片里是新高度。

**② 为什么**
C 语言为了写出紧凑的指针遍历而设计了这个运算符，代价是引入"副作用发生的时机"这一复杂概念。课件 P16【作业】直接把"`++i` 和 `i++` 的区别？"列为**面试真题**，说明这是必考点。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 课件 P4 表：a = 2; a++ → 3 =====
    int a = 2;
    a++;                                // 单独成句时，a++ 与 ++a 完全等价
    cout << "a = 2; a++ 之后 a = " << a << endl;         // 3

    // ===== 课件 P4 表：a = 10; a-- → 9 =====
    int a2 = 10;
    a2--;
    cout << "a = 10; a-- 之后 a = " << a2 << endl;       // 9

    // ===== 课堂代码第39-41行：后缀用在表达式里 =====
    int num = 100;
    cout << "num-- 表达式的值 = " << num-- << endl;      // 打印 100（旧值）
    cout << "此刻 num = " << num << endl;                // 99（已经减过了）

    // ===== 前缀 vs 后缀的经典四行 =====
    int m = 5;
    int x = m++;          // x 拿旧值 5，然后 m 变 6
    int y = 5;
    int z = ++y;          // y 先变 6，z 拿新值 6
    cout << "m=" << m << " x=" << x << " | y=" << y << " z=" << z << endl;

    // ===== for 循环里推荐 ++i =====
    for (int i = 0; i < 3; ++i) cout << i << " ";
    cout << endl;
    return 0;
}
// 输出：
// a = 2; a++ 之后 a = 3
// a = 10; a-- 之后 a = 9
// num-- 表达式的值 = 100
// 此刻 num = 99
// m=6 x=5 | y=6 z=6
// 0 1 2
```

**前缀 / 后缀对照表（面试标准答案格式）**

| 写法 | 名称 | 表达式取值 | 变量最终值 | 单独成句时 |
|------|------|-----------|-----------|-----------|
| `a++` | 后缀自增 | **旧值** | 旧值+1 | 与 `++a` 完全等价 |
| `++a` | 前缀自增 | **新值** | 旧值+1 | 同上 |
| `a--` | 后缀自减 | 旧值 | 旧值−1 | 与 `--a` 等价 |
| `--a` | 前缀自减 | 新值 | 旧值−1 | 同上 |

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范一：一行里多次修改同一变量 → 未定义行为
    int i = 1;
    // int r = i++ + i++ + i;      // UB！GCC 可能给 4，别的编译器给别的值，谁也没错

    // ✅ 正确写法：一行只做一件事
    int i2 = 1;
    int a1 = i2++;              // 1
    int a2 = i2++;              // 2
    int sum = a1 + a2 + i2;     // 1+2+3 = 6，清清楚楚
    cout << "sum = " << sum << endl;

    // ❌ 错误示范二：把 ++ 当成"加很多"，连着写
    // int t = 3; int bad = ++++ t;   // 编译器读成 t++ ++t → 语法/语义双重错误

    // ✅ 想在输出里既显示又递增，分成两句
    int shown = 100;
    cout << shown << endl;      // 先显示
    shown++;                    // 再改
    cout << shown << endl;
    return 0;
}
// 输出：
// sum = 6
// 100
// 101
```

> **提示词硬性要求的写法约定**：**初学者永远不要把 `++`/`--` 与其他运算符混在同一行。** 只在"单独成句"或"for 循环第三段"里使用它。`for` 里推荐 `++i`：对 `int` 而言它与 `i++` 性能相同（编译器优化掉了临时值），但对 STL 迭代器等类类型，前缀省下一次拷贝，确实更快。养成统一写 `++i` 的习惯最省心。

## 1.8 算术运算中操作数类型不一致时的自动提升｜清单第 7 条【重点】

**① 是什么**
一句话定义：做算术运算时，编译器会**自动把"低精度"操作数升级为"高精度"类型**，然后在同一类型下计算，结果就是这个高精度类型。
生活比喻：两个人要合账，必须先统一货币单位——人民币和美元相加，系统会自动把人民币折成美元再算，你拿到手的永远是美元。

**② 为什么**
CPU 的加法器一次只能处理一种数据格式，混合类型无法直接进 ALU，必须先"对齐"。而对齐方向只能是**小容纳大**（否则信息丢失），所以升级链永远是单向向上的：`char/short → int → unsigned → long → long long → float → double → long double`。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 场景1：char 与 int 相加（课件 P11 第一条原文举例）=====
    char c = 'a';               // 'a' 的 ASCII 码是 97
    int b = 1;
    auto r1 = c + b;            // char 先升成 int(97)，再 97 + 1 = 98
    cout << "c + b = " << r1 << endl;                       // 98（数字，不是字符）
    cout << "r1 占 " << sizeof(r1) << " 字节，即 int" << endl;

    // ===== 场景2：int 与 double 运算（课件 P11 第二条原文举例）=====
    int i = 5;
    double d = 2.5;
    auto r2 = i * d;            // int 5 升成 double 5.0，再 5.0 * 2.5 = 12.5
    cout << "i * d = " << r2 << "，占 " << sizeof(r2) << " 字节" << endl;

    // ===== 场景3：short 相加也会升成 int（整型提升）=====
    short s1 = 30000, s2 = 30000;
    auto r3 = s1 + s2;          // 先各自升为 int，再相加 → 60000（安全）
    cout << "s1 + s2 = " << r3 << "，占 " << sizeof(r3) << " 字节" << endl;

    // ===== 场景4：float 与 double 混合，float 被拉高 =====
    float f = 1.5f;
    double dd = 2.0;
    cout << "f + dd 占 " << sizeof(f + dd) << " 字节（8 = double）" << endl;

    // ===== 场景5：除法里提升带来的"意外好处" =====
    int total = 7, cnt = 2;
    cout << "total / cnt = " << total / cnt << endl;                       // 3（都 int）
    cout << "total / 2.0 = " << total / 2.0 << endl;                       // 3.5（自动升）
    return 0;
}
// 输出：
// c + b = 98
// r1 占 4 字节，即 int
// i * d = 12.5，占 8 字节
// s1 + s2 = 60000，占 4 字节
// f + dd 占 8 字节（8 = double）
// total / cnt = 3
// total / 2.0 = 3.5
```

**提升优先级速查（谁听谁的）**

```
long double   ← 最高，遇到它所有人都得升
double
float
unsigned long long / long long
unsigned long / long          （位数相同的无符号优先，故 unsigned int > int）
unsigned int
int / short / char / bool     ← 这几类一律先升为 int（叫"整型提升 integral promotion"）
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范一：以为 char + char 还是 char
    char x = 100, y = 100;
    auto s = x + y;                 // 实际是 int 的 200，不是 char
    cout << "x + y = " << s << endl;      // 200
    char narrowSum = static_cast<char>(x + y);  // 压回 char → 静默窄化
    cout << "压回 char 后 = " << (int)narrowSum << endl;   // 44（200 的低 8 位按补码解释）

    // ❌ 错误示范二：有符号与无符号混合，负数被"洗白"
    unsigned int u = 10;
    int si = -1;
    cout << "si + u = " << (si + u) << endl;    // 4294967295！si 先升 unsigned 变成巨大正数
    cout << "(u > si) = " << (u > si) << endl;  // 1（true）— 反直觉到让人崩溃
    // ✅ 正确写法：混合运算前显式统一到同一种符号性
    cout << "static_cast<int>(u) + si = " << static_cast<int>(u) + si << endl;   // 9 ✔

    // ✅ 结论：bool 参与算术也会升为 int（false→0，true→1）
    cout << "true + true = " << (true + true) << endl;   // 2
    return 0;
}
// 输出：
// x + y = 200
// 压回 char 后 = 44
// si + u = 4294967295
// (u > si) = 1
// static_cast<int>(u) + si = 9
// true + true = 2
```

## 1.9 赋值运算符 `=` 与连续赋值｜清单第 8 条【重点】

**① 是什么**
一句话定义：`=` 把右边的值**复制**给左边的变量；它本身也是一个**表达式**，其值和类型就是"被赋进去的那个值"。左边必须是能被写入的**左值**（lvalue）。
生活比喻：复印机。`C = A + B` 是"把 A+B 复印一份塞进 C 的抽屉"，原件（A、B）毫发无损。

**② 为什么**
`=` 有值这件事，是"连续赋值 `a = b = c = 0`"和"循环里 `while ((ch = get()) != EOF)`"能成立的根基。也正因为它有值、又像 `==`，才制造了本章第二大经典 bug。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 基本用法：先算右边，再复制给左边 =====
    int A = 5, B = 7;
    int C = A + B;                       // 课件 P5 表第一行：C = A + B
    cout << "C = A + B -> C = " << C << endl;

    // ===== 连续赋值（右结合 R-L 的典型）=====
    int x, y, z;
    x = y = z = 10 + 5;                  // 解析为 x = (y = (z = 15))
    cout << "x=" << x << " y=" << y << " z=" << z << endl;

    // ===== 赋值是一个表达式，有自己的值 =====
    int v = (y = 42);                    // y 先变 42，整个表达式值也是 42
    cout << "v=" << v << " y=" << y << endl;

    // ===== 左右类型不同时，右边先转换再存入（引出 4.1）=====
    int n = 3;
    double df = n;                       // int → double，widening，安全
    char ch = 'A';
    int code = ch;                       // char → int，97，安全
    double pi = 3.999;
    int trunc = static_cast<int>(pi);    // double → int，必须显式，得 3（截断不是四舍五入）
    cout << "df=" << df << " code=" << code << " trunc=" << trunc << endl;
    return 0;
}
// 输出：
// C = A + B -> C = 12
// x=15 y=15 z=15
// v=42 y=42
// df=3 code=97 trunc=3
```

**栈内存布局：`int A = 5, B = 7; int C = A + B;` 执行前后**

```
高地址
┌──────────────────────────────────┐
│  C  (int, 4 字节)  初值：垃圾值     │ ← 执行 C = A + B 后：0x0000000C (=12)
├──────────────────────────────────┤
│  B  (int, 4 字节)  0x00000007      │  不变，仍是 7
├──────────────────────────────────┤
│  A  (int, 4 字节)  0x00000005      │  不变，仍是 5
└──────────────────────────────────┘
低地址  （栈向低地址生长；成员实际顺序由编译器决定，此处示意"各自独立 4 字节槽位"）

中间过程：A+B 的 12 先落在寄存器 EAX 里，再由 store 指令写入 C 的 4 字节槽位。
关键点：赋值是"复制"，A 和 B 的值不受影响；C 的槽位被整体覆盖。
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
#include <climits>
using namespace std;
int main() {
    // ❌ 错误示范一：左边不是左值
    int a = 1;
    // a + 1 = 5;              // 编译错误：expression is not assignable / l-value required
    // 5 = a;                  // 编译错误：常量不能当左值
    // ✅ 正确写法：左边必须是变量（或可写引用/解引用）
    a = 5;
    cout << "a = " << a << endl;

    // ❌ 错误示范二：赋值给不同类型导致静默丢数据
    int big = 300;
    char small = static_cast<char>(big);   // 窄化：300 塞不进 1 字节，无运行时警告
    cout << "small = " << (int)small << endl;
    // ✅ 更稳妥：直接用能容纳的类型，或先做范围检查
    if (big >= CHAR_MIN && big <= CHAR_MAX) {
        cout << "这个值才允许放进 char\n";
    } else {
        cout << "300 超出 char 范围，应该用 int/short\n";
    }
    return 0;
}
// 输出：
// a = 5
// small = 44
// 300 超出 char 范围，应该用 int/short
```

## 1.10 `=` 与 `==` 的本质区别及混淆 bug｜清单第 9 条【重点】

**① 是什么**
一句话定义：`=` 是**赋值**（写入动作，返回写入的值），`==` 是**相等比较**（读取判断，返回 `bool`）。课件 P5 页面上孤零零写着标题「**=与==？**」——老师用问号提醒你：这里是全人类新手必踩的坑。

**② 为什么**
两者外观只差一个等号，但语义一个是"改"、一个是"问"。C++ 之所以不禁止 `if (flag = 0)`，是为了保留 `while (ptr = next())` 这种合法惯用法；代价就是把纠错责任交给程序员和编译器警告。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    int target = 5;

    // ===== 正确：用 == 提问 =====
    if (target == 5) {
        cout << "== 判断：target 确实是 5\n";
    }

    // ===== 正确：用 = 回答（写入）=====
    target = 10;                       // 把 10 写进 target
    cout << "赋值后 target = " << target << endl;

    // ===== 两者同时出现的正确惯用法 =====
    int score = 0;
    bool passed = (score == 60);       // 先 == 得到 bool，再 = 存入 passed
    cout << "passed = " << (passed ? "true" : "false") << endl;
    return 0;
}
// 输出：
// == 判断：target 确实是 5
// 赋值后 target = 10
// passed = false
```

**`=` 与 `==` 全面对比表**

| 维度 | `=` 赋值 | `==` 相等比较 |
|------|---------|--------------|
| 优先级（课件 P10 表） | **第 15 级**（很低，接近底部） | **第 9 级** |
| 结合性 | **从右至左 R-L** | 从左至右 L-R |
| 操作数个数 | 二元 | 二元 |
| 结果类型 | 左操作数的类型（所赋的值） | `bool` |
| 是否修改变量 | **会**（左边被写入） | 不会（只读） |
| 运算发生时机 | 运行期 | 运行期（常量比较可编译期折叠） |
| 在 `if` 里的后果 | 恒为该值，非 0 即为真，且改了变量 | 正常的真假判断 |
| 典型误用信号 | 编译器警告 C4706 / `-Wparentheses` | — |

**④ 注意事项 & 错误示范（bug 案例对比）**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ==================== 案例 1：if 里写成赋值 ====================
    int status = 1;
    if (status = 0) {                         // ❌ 本想判断"是否等于 0"
        cout << "状态异常\n";
    } else {
        cout << "一切正常（走进 else）\n";       // 永远走这里
    }
    cout << "status 现在是 " << status << endl;   // 输出 0 —— 变量已被偷偷改成 0
    // 分析：status = 0 这个赋值表达式的值是 0 → 0 转 bool 为 false → else 分支
    //      更可怕的是原本 status=1 的记录被抹平了，数据损坏。
    // ✅ 正确写法
    if (status == 0) { cout << "正确写法：确实为 0\n"; }

    // ==================== 案例 2：赋值当判断，条件恒真 ====================
    int retry = 3;
    if (retry = 1) {                          // ❌ 想问"是不是只剩 1 次"
        cout << "进入重试逻辑（每次都进！）\n";
    }
    cout << "retry = " << retry << endl;      // 3 变成了 1
    // ✅ 正确写法
    if (retry == 1) { cout << "改成 == 后依然成立，但没有改写数据\n"; }

    // ==================== 案例 3：连等 ====================
    int a = 1, b = 2;
    if (a = b = 0) { cout << "不可能进来\n"; }   // ❌ a、b 双双被清零，条件为假
    else { cout << "a 和 b 都被清零了：a=" << a << " b=" << b << endl; }
    // ✅ 正确写法
    if (a == 0 && b == 0) { cout << "这次是纯判断，不改数据\n"; }
    return 0;
}
// 输出：
// 一切正常（走进 else）
// status 现在是 0
// 正确写法：确实为 0
// 进入重试逻辑（每次都进！）
// retry = 1
// 改成 == 后依然成立，但没有改写数据
// a 和 b 都被清零了：a=0 b=0
// 这次是纯判断，不改数据
```

**防坑三板斧（务必落地）**

1. **开启编译器警告**：MSVC 用 `/W4`，GCC/Clang 用 `-Wall -Wextra`。它们会对 `if (x = 0)` 报 `C4706: assignment within conditional expression` / `suggest parentheses around assignment used as truth value`。严格团队把警告当错误看：`/WX` 或 `-Werror`。
2. **尤达条件式（Yoda condition）**：把常量写在左边 —— `if (5 == x)`。若手滑写成 `if (5 = x)`，编译期立刻报错（常量不是左值），把运行时 bug 提前到编译期。现代团队不太推崇（可读性差），但作为应急技巧值得知道。
3. **`==` 优先惯例**：写 `if` 时先在心里念一遍"我是在**问**还是在**改**"。凡是条件里出现"改"，几乎必然是 bug。

> **口诀**：*一个等号是赋值，两个等号问相等；条件里面见单号，九成九是写错了。*

## 1.11 复合赋值运算符 `+= -= *= /= %=`｜清单第 10 条【重点】

**① 是什么**
一句话定义：把"某种运算"和"赋值"合并成一个符号，`C op= A` 表示"对 C 做 `op A` 再把结果放回 C"。
生活比喻：与其说"把你账户里的钱取出来、加 100、再存回去"，不如直接对银行说"账户加 100"——一次指令搞定，中间不落别处。

**② 为什么**
减少重复书写（`matrix[i][j] = matrix[i][j] + v;` 这种噩梦），并且**左操作数只求值一次**（对带副作用的下标表达式很重要），同时它也是 C++ 运算符重载体系的标准成员之一（`operator+=`）。

**③ 怎么用（课件 P5 语法表完整展开）**

课件 P5 下半部分是这张四列表（"结果"列给出等价展开形式）：

| 运算符 | 说明 | 范例 | 等价于 |
|--------|------|------|--------|
| `=` | 将一个表达式的值赋给另一个 | `C = A + B` | `C = A + B` |
| `+=` | 相加后再赋值 | `C += A` | `C = C + A` |
| `-=` | 相减后再赋值 | `C -= A` | `C = C - A` |
| `*=` | 相乘后再赋值 | `C *= A` | `C = C * A` |
| `/=` | 相除后再赋值 | `C /= A` | `C = C / A` |
| `%=` | 求余后再赋值 | `C %= A` | `C = C % A` |

```cpp
#include <iostream>
using namespace std;

int main() {
    int A = 5, B = 7;
    int C = A + B;                       // C = 12，从这里开始逐项演示
    cout << "起点：C = A + B = " << C << endl;

    C += A;  cout << "C += A;  -> " << C << "   （12 + 5）\n";    // 17
    C -= A;  cout << "C -= A;  -> " << C << "   （17 - 5）\n";    // 12
    C *= A;  cout << "C *= A;  -> " << C << "   （12 * 5）\n";    // 60
    C /= A;  cout << "C /= A;  -> " << C << "   （60 / 5）\n";    // 12
    C %= A;  cout << "C %= A;  -> " << C << "   （12 % 5）\n";    // 2
    return 0;
}
// 输出：
// 起点：C = A + B = 12
// C += A;  -> 17   （12 + 5）
// C -= A;  -> 12   （17 - 5）
// C *= A;  -> 60   （12 * 5）
// C /= A;  -> 12   （60 / 5）
// C %= A;  -> 2    （12 % 5）
```

**逐行状态走读（每一行结束后 C 的值）**

| 执行行 | C 变化 | 说明 |
|--------|--------|------|
| `int C = A + B;` | 垃圾值 → **12** | 先算 `A+B`=12，再复制入 C |
| `C += A;` | 12 → **17** | 等价 `C = C + A`，即 12+5 |
| `C -= A;` | 17 → **12** | 12 = 17−5 |
| `C *= A;` | 12 → **60** | 12×5 |
| `C /= A;` | 60 → **12** | 60÷5，整除刚好无余 |
| `C %= A;` | 12 → **2** | 12÷5 余 2 |

> 上面这份"起点 12"的设计有意让 `/=` 那步整除干净，方便你在脑子里逐步核对；抄进 IDE 跑一遍，输出应与 `// 输出：` 完全一致（本笔记已在 GCC 8.1 实测通过）。

**复合赋值在真实场景里的用法**

```cpp
#include <iostream>
using namespace std;

int main() {
    int count = 0;
    for (int i = 1; i <= 5; ++i) {
        count += i;                      // 累加器：等价 count = count + i
    }
    cout << "1+2+3+4+5 = " << count << endl;

    long long product = 1;
    for (int i = 1; i <= 5; ++i) product *= i;      // 累乘器
    cout << "5! = " << product << endl;

    int total = 100;
    total /= 3;                          // 注意：整数除法，同样截断！
    cout << "total /= 3 -> " << total << endl;      // 33，不是 33.33

    int remain = 100;
    remain %= 7;
    cout << "remain %= 7 -> " << remain << endl;    // 2
    return 0;
}
// 输出：
// 1+2+3+4+5 = 15
// 5! = 120
// total /= 3 -> 33
// remain %= 7 -> 2
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
#include <cmath>
using namespace std;
int main() {
    // ❌ 错误示范一：忘记 /= 仍是整数除法
    int score = 7, times = 2;
    score /= times;                 // 3，不是 3.5
    cout << "score = " << score << endl;
    // ✅ 正确写法：想要小数就别让 /= 作用在 int 上
    double ratio = 7;  ratio /= 2;  // 3.5 ✔
    cout << "ratio = " << ratio << endl;

    // ❌ 错误示范二：浮点数用 %=
    double f = 5.5;
    // f %= 2;                      // 编译错误：invalid operands of types 'double' and 'int' to binary 'operator%'
    // ✅ 正确写法
    f = fmod(f, 2.0);               // 1.5
    cout << "fmod(5.5, 2.0) = " << f << endl;

    // ✅ 复合赋值与 = 的一个真实差别：左操作数只求值一次
    int arr[3] = {10, 20, 30};
    int idx = 1;
    arr[idx++] += 5;                // arr[1] 变 25，idx 变 2 —— 只索引一次
    cout << "arr[1]=" << arr[1] << " idx=" << idx << endl;
    return 0;
}
// 输出：
// score = 3
// ratio = 3.5
// fmod(5.5, 2.0) = 1.5
// arr[1]=25 idx=2
```

> **优先级提醒（课件 P10 表第 15 级）**：`+=` 和 `=` 同在**第 15 级**，比所有算术、比较、逻辑运算符都低。所以 `C = A + B;` 一定先算 `A+B`。反过来 `x = a == b;` 是先 `a == b` 得 bool，再赋给 `x`。

## 模块一微型总结（3 句话）

1. 算术五兄弟 `+ - * / %` 里，`/` 的**整数截断**和 `%` 的**只吃整数 + 符号跟左边**是两个必考陷阱。
2. `=` 是"改"、`==` 是"问"，两者优先级差 6 级（15 级 vs 9 级），条件里写错 `=` 会同时造成"逻辑恒真"和"数据被污染"双重事故。
3. 五个复合赋值 `+= -= *= /= %=` 就是"运算 + 回填"的缩写，展开形式必须秒答；但别忘了 `*=` 会带来溢出、`/=` 同样截断、`%=` 不许碰浮点。

## 2.1 六种比较运算符及其返回值类型 `bool`｜清单第 11、12、14 条【重点】

**① 是什么**
一句话定义：比较运算符把两个值放在一起"比大小/论相等"，产出一个 **`bool` 类型**的结果——`true` 或 `false`。
生活比喻：裁判举牌。你踢一脚（表达式），裁判只回答两种话："有效"（true）或"无效"（false），不会给你打 8.5 分。

**② 为什么**
早期 C 语言没有 `bool`，比较结果用 `int` 的 1/0 表示（这就是课件表里"真，也就是 1 / 假，也就是 0"这句话的历史原因）。C++ 引入了真正的 `bool` 类型（实测 `sizeof(bool)` = 1 字节），使"真假"成为一等公民，也让 `if`、`while` 的条件表达式有了规范类型。**这是 C++ 与 C 在逻辑运算上最重要的差异之一**（提示词专项要求第 4 条）。

**③ 怎么用（课件 P6 语法表完整展开）**

| 运算符 | 说明 | 范例 | 结果（课件原文） |
|--------|------|------|------------------|
| `==` | 相等 | `4 == 3` | 假，也就是 `0` |
| `!=` | 不等于 | `4 != 3` | 真，也就是 `1` |
| `<` | 小于 | `4 < 3` | 假，也就是 `0` |
| `>` | 大于 | `4 > 3` | 真，也就是 `1` |
| `<=` | 小于等于 | `4 <= 3` | 假，也就是 `0` |
| `>=` | 大于等于 | `4 >= 3` | 真，也就是 `1` |

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 课件 P6 表的六行，逐个复现 =====
    cout << "4 == 3 -> " << (4 == 3) << "  （假，也就是 0）\n";
    cout << "4 != 3 -> " << (4 != 3) << "  （真，也就是 1）\n";
    cout << "4 <  3 -> " << (4 <  3) << "  （假，也就是 0）\n";
    cout << "4 >  3 -> " << (4 >  3) << "  （真，也就是 1）\n";
    cout << "4 <= 3 -> " << (4 <= 3) << "  （假，也就是 0）\n";
    cout << "4 >= 3 -> " << (4 >= 3) << "  （真，也就是 1）\n";

    // ===== 课堂代码第50行：cout << (4 >= 3) << endl; =====
    cout << (4 >= 3) << endl;

    // ===== 结果其实是 bool，不是 int =====
    bool r1 = (4 >= 3);
    bool r2 = (4 == 3);
    cout << "r1 = " << boolalpha << r1 << ", r2 = " << r2 << endl;   // boolalpha 显示 true/false
    cout << "sizeof(bool) = " << sizeof(r1) << " 字节\n";
    cout << "true 当数字用：" << (r1 + r2) << "   （true=1, false=0）\n";
    return 0;
}
// 输出：
// 4 == 3 -> 0  （假，也就是 0）
// 4 != 3 -> 1  （真，也就是 1）
// 4 <  3 -> 0  （假，也就是 0）
// 4 >  3 -> 1  （真，也就是 1）
// 4 <= 3 -> 0  （假，也就是 0）
// 4 >= 3 -> 1  （真，也就是 1）
// 1
// r1 = true, r2 = false
// sizeof(bool) = 1 字节
// true 当数字用：1
```

## 2.2 双字符比较运算符必须紧挨书写｜清单第 13 条【重点】

**① 是什么**
一句话定义：`>=`、`<=`、`==`、`!=` 这四个符号各由**两个字符**组成，两个字符之间**不能有空格**，也不能拆开。课件 P6 页面上的强调原文就是一句：**「符号必须挨在一起」**。

**② 为什么**
词法分析（lexing）阶段，编译器从左往右扫描字符流，靠**连续字符**识别运算符 token。`>=` 被识别成一个 token；一旦中间加了空格，就被切成 `>` 和 `=` 两个 token，语义瞬间崩塌。
生活比喻：汉字"明"由"日"和"月"拼成，中间插进别的笔画就不是"明"了。`>=` 拆成 `> =` 就不再是"大于等于"。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    int age = 20;
    if (age >= 18) cout << "成年\n";        // ✔ 紧挨
    if (age <= 60) cout << "未到退休年龄\n"; // ✔ 紧挨
    if (age == 20) cout << "正好 20 岁\n";   // ✔ 紧挨
    if (age != 0)  cout << "非零\n";         // ✔ 紧挨

    // 正确的空格位置：符号两侧可以有空格（推荐），符号内部绝不可以
    if (age>=18) cout << "紧凑写法也能编译，但可读性差\n";
    return 0;
}
// 输出：
// 成年
// 未到退休年龄
// 正好 20 岁
// 非零
// 紧凑写法也能编译，但可读性差
```

**④ 注意事项 & 错误示范（四种典型拆坏方式）**

```cpp
#include <iostream>
using namespace std;
int main() {
    int n = 5;
    // ❌ 拆法一：>= 中间加空格 → 变成"先 > ，再赋值"
    // if (n > = 3) { }
    // 编译错误：expected primary-expression before '=' token
    //          （编译器看到的是 n > (=3)，= 后面缺左值）

    // ❌ 拆法二：== 写成 = → 语法通过，语义全错（参见 1.10）
    // if (n = 3) { }        // 把 3 写进 n，条件恒真

    // ❌ 拆法三：!= 写成 !== 或 =!
    // if (n !== 3) { }      // 编译错误：'!' 不能接 '=='
    int m = 9;
    if (m =! 3) { cout << "不会进\n"; }
    cout << "危险演示：int m=9; 写了 if (m =! 3) 之后 m 变成 " << m << "\n";
    // 这句竟然能编译！它被读成 m = (!3)，即 m = 0 —— 隐蔽性极强

    // ❌ 拆法四：<= 写成 =<（数学课本里没有，C++ 里也没有）
    // if (n =< 10) { }      // 编译错误

    // ✅ 唯一正确写法
    if (n >= 3 && n <= 10 && n != 7 && n == 5) { cout << "标准写法\n"; }
    return 0;
}
// 输出：
// 危险演示：int m=9; 写了 if (m =! 3) 之后 m 变成 0
// 标准写法
```

> **同类规则扩展**：这条"必须紧挨"的规则适用于**所有**多字符运算符：`++ -- += -= *= /= %= == != && || :: -> << >> >>= <<= ...` 全都不能拆开。特别小心的三个：`&&`（别写成 `& &`）、`||`（别写成 `| |`）、`->`（别写成 `- >`）。

## 2.3 逻辑与 `&&`：运算规则与短路特性｜清单第 15 条【重点】

**① 是什么**
一句话定义：`A && B` 表示"A 和 B 同时成立"，**两边都为真结果才为真**；左边为假时**右边根本不会被计算**。
生活比喻：面试两轮都要通过才录用；第一轮就被刷，简历直接退回——第二轮面试官连你名字都不知道（右边压根没参加）。

**② 为什么**
短路不是性能优化，而是**语义规定**：`&&` 的左操作数是一个序列点，左边确定为 false 后，右操作数的值已无法影响结果，标准因此规定它不求值。这个特性给了我们一件利器：**用左边条件守卫右边的危险操作**（防止除零、防止空指针解引用、防止数组越界）。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 真值表（课堂代码第52-56行，注释写着"同真为真"）=====
    cout << "1 && 1 -> " << (1 && 1) << "   真\n";
    cout << "0 && 1 -> " << (0 && 1) << "   假\n";
    cout << "1 && 0 -> " << (1 && 0) << "   假\n";
    cout << "0 && 0 -> " << (0 && 0) << "   假\n";

    // ===== 实用场景：多个条件同时成立 =====
    int age = 25, hasTicket = 1;
    if (age >= 18 && hasTicket == 1) {
        cout << "欢迎入场\n";
    }

    // ===== 短路的价值：守卫除零 =====
    int divisor = 0, dividend = 10;
    if (divisor != 0 && dividend / divisor > 1) {
        cout << "商大于 1\n";
    } else {
        cout << "条件为假，而且没有崩溃——左边已判负，右边没执行\n";
    }
    return 0;
}
// 输出：
// 1 && 1 -> 1   真
// 0 && 1 -> 0   假
// 1 && 0 -> 0   假
// 0 && 0 -> 0   假
// 欢迎入场
// 条件为假，而且没有崩溃——左边已判负，右边没执行
```

**`&&` 真值表（标准格式，操作数以 bool 表述）**

| A | B | A && B | 右边是否求值 |
|---|---|--------|-------------|
| true | true | **true** | 是 |
| true | false | **false** | 是 |
| false | true | **false** | **否（短路）** |
| false | false | **false** | **否（短路）** |

> 课堂代码第 52 行的中文注释是「**逻辑与 && 同真为真**」——四个字记住了整张表。

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范一：把守卫条件写在了后面（详见陷阱专题2）
    int d = 0, n = 10;
    // if (n / d > 1 && d != 0) { }   // 先算 n/d → 整数除零 → 未定义行为，直接崩
    //                                    右边的 d != 0 本来能救命，可惜轮不到它执行
    // ✅ 正确写法：把"排除危险"的条件放最左边
    if (d != 0 && n / d > 1) { cout << "不会进\n"; }
    else { cout << "安全地跳过了除法\n"; }

    // ❌ 错误示范二：把位与 & 当逻辑与 &&
    int flagA = 2, flagB = 4;
    cout << "flagA & flagB  = " << (flagA & flagB) << endl;    // 0（按位与，二进制 10 & 100）
    cout << "flagA && flagB = " << (flagA && flagB) << endl;   // 1（逻辑与，只看是否为 0）
    // 而且 & 完全没有短路能力：两边都会求值！

    // ❌ 错误示范三：依赖 && 右边的副作用
    int counter = 0;
    bool ready = false;
    ready && counter++;        // counter 保持 0 —— 右边没执行！
    cout << "counter = " << counter << endl;
    // ✅ 正确写法：需要副作用就老老实实分开写
    if (ready) { counter++; }

    // ✅ 正确示范：短路的正面威力
    int len = 0;
    int data[5] = {1, 2, 3, 4, 5};
    bool found = false;
    for (int i = 0; i < len && i < 5; ++i) {   // len=0 → i<len 立即 false，循环体一次都不进
        if (data[i] == 3) found = true;
    }
    cout << "found = " << (found ? "true" : "false") << endl;
    return 0;
}
// 输出：
// 安全地跳过了除法
// flagA & flagB  = 0
// flagA && flagB = 1
// counter = 0
// found = false
```

## 2.4 逻辑或 `||`：运算规则与短路特性｜清单第 16 条【重点】

**① 是什么**
一句话定义：`A || B` 表示"A 或 B 至少有一个成立"，**两边都为假结果才为假**；左边为真时**右边不会被计算**。
生活比喻：一道门有两把钥匙，任意一把能开就行。你掏出第一把就开了，第二把钥匙留在兜里——它今天不会被用到。

**② 为什么**
与 `&&` 对称：左操作数已确定为 true，右边再怎么变结果都是 true，标准规定不再求值。于是 `||` 也成了一台保险机：**左边先证明"不用干危险的事了"，右边就永远不会执行**。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 真值表（课堂代码第58-62行，注释写着"同假为假"）=====
    cout << "1 || 1 -> " << (1 || 1) << "   真\n";
    cout << "0 || 1 -> " << (0 || 1) << "   真\n";
    cout << "1 || 0 -> " << (1 || 0) << "   真\n";
    cout << "0 || 0 -> " << (0 || 0) << "   假\n";

    // ===== 实用场景：任一条件满足即可 =====
    char grade = 'F';
    if (grade == 'F' || grade == 'D') {
        cout << "需要补考\n";
    }

    // ===== 短路的价值：先判空再用指针 =====
    int* p = nullptr;
    if (p == nullptr || *p > 0) {          // 左边 true → *p 永不执行，避免崩溃
        cout << "指针为空，安全跳过解引用\n";
    }
    return 0;
}
// 输出：
// 1 || 1 -> 1   真
// 0 || 1 -> 1   真
// 1 || 0 -> 1   真
// 0 || 0 -> 0   假
// 需要补考
// 指针为空，安全跳过解引用
```

**`||` 真值表**

| A | B | A \|\| B | 右边是否求值 |
|---|---|----------|-------------|
| true | true | **true** | **否（短路）** |
| true | false | **true** | **否（短路）** |
| false | true | **true** | 是 |
| false | false | **false** | 是 |

> 课堂代码第 58 行注释「**逻辑或 || 同假为假**」。

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范一：短路让必要的副作用消失
    int tries = 3;
    bool alreadyWarned = true;
    alreadyWarned || (tries-- > 0);      // 左边 true → tries-- 不执行
    cout << "tries 仍是 " << tries << "（本以为会变 2）\n";
    // ✅ 正确写法：把有副作用的判断放前面，或拆成两句
    if (!alreadyWarned) { tries--; }
    cout << "拆开后 tries = " << tries << "（alreadyWarned 为 true，仍未减）\n";

    // ❌ 错误示范二：写成单竖线，丢掉短路
    int d = 0, v = 5;
    // if (d == 0 | v / d > 1) { }       // 位或 | 两边都算 → v/d 除零崩溃
    // ✅ 正确写法：永远用 ||
    if (d == 0 || v / d > 1) { cout << "第一个条件命中，后面的不看了\n"; }

    // ❌ 错误示范三：想表达"x 不在 1..10 内"却写错
    int x = 5;
    if (x < 1 || x > 10) cout << "越界\n"; else cout << "在范围内\n";
    if (1 > x > 10) cout << "不会打印\n"; else cout << "确认：1 > x > 10 恒为假\n";
    return 0;
}
// 输出：
// tries 仍是 3（本以为会变 2）
// 拆开后 tries = 3（alreadyWarned 为 true，仍未减）
// 第一个条件命中，后面的不看了
// 在范围内
// 确认：1 > x > 10 恒为假
```

## 2.5 逻辑非 `!`｜清单第 17 条【重点】

**① 是什么**
一句话定义：`!` 是一元运算符，把真假翻转：真变假、假变真；它对**任何标量值**都能用——0 变 true，非 0 变 false。
生活比喻：开关的反向拨杆。灯亮你说"不亮"，灯灭你说"亮"。

**② 为什么**
大量判断天然以"否定"形态出现（"如果不合法就报错"、"若非空则处理"）。`!` 让你直接表达否定，而不必写成 `== false` 这种啰嗦且易错的形式。它的优先级极高——课件 P9 表里 `!` 位列**第 3 级**（与一元 `-`、`++a`、`(type)`、`sizeof` 同级），而且是**从右至左**结合。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 课堂代码第64-66行：逻辑非 取反 =====
    cout << "!1 -> " << !1 << endl;        // 0
    cout << "!0 -> " << !0 << endl;        // 1

    // ===== 对 bool 使用 =====
    bool isOpen = false;
    if (!isOpen) cout << "门是关着的\n";
    isOpen = !isOpen;
    cout << "取反后 isOpen = " << boolalpha << isOpen << endl;

    // ===== 对整数使用：0 与非 0 之分 =====
    cout << "!0    -> " << !0 << "   （零 → 真）\n";
    cout << "!100  -> " << !100 << "  （非零 → 假）\n";
    cout << "!!100 -> " << !!100 << " （双重取反：把任意值规范成 0/1）\n";

    // ===== 与比较组合：最常见的否定式判断 =====
    int input = -5;
    if (!(input > 0)) cout << "输入不是正数（包含 0 和负数）\n";

    // ===== 优先级演示：! 比 > 先算，所以要小心 =====
    int n = 5;
    cout << "(!n > 1)  -> " << ((!n) > 1) << "  因为先算 !n=0，再 0>1 → 0\n";
    cout << "!(n > 1)  -> " << (!(n > 1)) << "  这才是『n 不大于 1』\n";
    return 0;
}
// 输出：
// !1 -> 0
// !0 -> 1
// 门是关着的
// 取反后 isOpen = true
// !0    -> 1   （零 → 真）
// !100  -> 0  （非零 → 假）
// !!100 -> 1 （双重取反：把任意值规范成 0/1）
// 输入不是正数（包含 0 和负数）
// (!n > 1)  -> 0  因为先算 !n=0，再 0>1 → 0
// !(n > 1)  -> 0  这才是『n 不大于 1』
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范一：忘了括号，把否定式判断写反
    int score = 55;
    if (!score >= 60) { cout << "不及格\n"; }
    // 解析为 (!score) >= 60 → score 非零 → !score = 0 → 0 >= 60 = false
    // 结果：55 分被判成了"及格"！（这句不会打印）
    // ✅ 正确写法：! 的作用范围一定要用括号说清
    if (!(score >= 60)) { cout << "这次真的不及格\n"; }
    // 或者更直白，干脆不用 !
    if (score < 60) { cout << "最清晰的写法\n"; }

    // ❌ 错误示范二：把 ! 与 != 混为一谈
    int a = 0, b = 0;
    if (!a == b) { cout << "不会进\n"; }   // 读作 (!a) == b → 1 == 0 → false

    // ❌ 错误示范三：! 写成 ~（按位取反）
    cout << "!5 -> " << !5 << endl;      // 0（逻辑取反）
    cout << "~5 -> " << ~5 << endl;      // -6（按位取反）
    // 二者毫无关系，一字之差结果天差地别。
    return 0;
}
// 输出：
// 这次真的不及格
// 最清晰的写法
// !5 -> 0
// ~5 -> -6
```

```
逻辑运算符            [一张大问号配图]
int a = 100;
a > 200 && a++ > 1        短路      a=?

int a = 100;
a < 200 || --a != 1               a=?
```

页面上还单独用彩色字标了一个词：**短路**。这两道题就是本章分量最重的内容——它们考察的不是"会不会写"，而是"**会不会预测副作用**"。

**① 是什么**
一句话定义：短路求值（short-circuit evaluation）指 `&&` 在左假时、`||` 在左真时，**跳过右操作数的求值**，直接给出结果；因此右边携带的任何副作用（`++`、赋值、函数调用、I/O）也随之消失。

**② 为什么**
逻辑上右边已不影响结果 → 标准授权省略。对编译器来说省掉一次运算；对程序员来说，这是一把双刃剑：既能拿来当"安全护栏"，也能不知不觉吃掉你以为一定会执行的 `a++`。

**③ 怎么用（课件两题的完整解答 + 对照组）**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ========== 课件题 1：int a = 100; a > 200 && a++ > 1; a = ? ==========
    int a = 100;
    a > 200 && a++ > 1;                        // 表达式结果被丢弃，只为观察 a
    cout << "题1：a > 200 && a++ > 1 之后，a = " << a << endl;   // ★ 答案：100

    // ========== 课件题 2：int a = 100; a < 200 || --a != 1; a = ? ==========
    int a2 = 100;
    a2 < 200 || --a2 != 1;
    cout << "题2：a < 200 || --a != 1 之后，a = " << a2 << endl; // ★ 答案：100

    // ========== 对照组 3：左边为真时，&& 右边会执行 ==========
    int a3 = 100;
    a3 > 50 && a3++ > 1;
    cout << "对照3：a > 50 && a++ > 1 之后，a = " << a3 << endl;  // 答案：101

    // ========== 对照组 4：左边为假时，|| 右边会执行 ==========
    int a4 = 100;
    a4 > 200 || --a4 != 1;
    cout << "对照4：a > 200 || --a != 1 之后，a = " << a4 << endl; // 答案：99

    return 0;
}
// 输出：
// 题1：a > 200 && a++ > 1 之后，a = 100
// 题2：a < 200 || --a != 1 之后，a = 100
// 对照3：a > 50 && a++ > 1 之后，a = 101
// 对照4：a > 200 || --a != 1 之后，a = 99
```

**逐行状态变化走读（清单第 18 条要求的核心表述）**

| 案例 | 左操作数 | 左边结论 | 右边是否执行 | `a` 起始 → 结束 |
|------|---------|---------|-------------|----------------|
| 课件题1 `a > 200 && a++ > 1` | `100 > 200` → **false** | 整个 `&&` 已注定为 false | **不执行** → `a++` 落空 | 100 → **100** |
| 课件题2 `a < 200 \|\| --a != 1` | `100 < 200` → **true** | 整个 `\|\|` 已注定为 true | **不执行** → `--a` 落空 | 100 → **100** |
| 对照3 `a > 50 && a++ > 1` | `100 > 50` → **true** | 还需看右边 | 执行 `a++` → a 变 101 | 100 → **101** |
| 对照4 `a > 200 \|\| --a != 1` | `100 > 200` → **false** | 还需看右边 | 执行 `--a` → a 变 99 | 100 → **99** |

> 一句话记忆：**`&&` 怕左假，`||` 怕左真；一旦触发短路，右边的副作用全部作废。**
> 课件 P7 旁边那张大大的"**?**"配图，正是在问你：你以为 `a++` 一定会执行吗？

**④ 注意事项 & 错误示范**

```cpp
#include <cstdio>
#include <iostream>
using namespace std;

bool needSave = false;
int g_calls = 0;
bool expensiveCheck() { ++g_calls; return true; }   // 假装很贵

int main() {
    // ❌ 错误示范一：把带副作用的判断藏在右边
    int dirtyCount = 5;
    needSave && (dirtyCount--, printf("保存了\n"));   // 全都没执行，日志一行没打
    cout << "dirtyCount = " << dirtyCount << endl;    // 还是 5
    // ✅ 正确写法：副作用放明确的 if 体里
    if (needSave) {
        --dirtyCount;
        cout << "保存了\n";
    }

    // ❌ 错误示范二：搞反条件顺序，短路救不了命
    int* ptr = nullptr;
    // if (*ptr != 0 && ptr != nullptr) { }  // 💥 先解引用空指针 → 段错误，程序当场死
    // ✅ 正确写法：把"安全检查"永远放在最左边
    if (ptr != nullptr && *ptr != 0) { cout << "不会进\n"; }
    else { cout << "左边 false，右边 *ptr 从未执行，平安无事\n"; }

    // ✅ 正面利用：短路是免费的性能护栏
    bool cacheHit = false;
    if (cacheHit && expensiveCheck()) { cout << "不会进\n"; }
    cout << "expensiveCheck 被调用次数 = " << g_calls << endl;
    bool cacheHit2 = true;
    if (cacheHit2 && expensiveCheck()) { cout << "第二次命中\n"; }
    cout << "最终调用次数 = " << g_calls << endl;
    return 0;
}
// 输出：
// dirtyCount = 5
// 左边 false，右边 *ptr 从未执行，平安无事
// expensiveCheck 被调用次数 = 0
// 第二次命中
// 最终调用次数 = 1
```

> **面试关键词**（提示词点名的必考题）："解释逻辑运算符的短路特性并举例"。答题模板：*定义（左边已能定结果时不求值右边）→ 方向（`&&` 左假短路、`||` 左真短路）→ 副作用后果（`a++` 不执行）→ 工程用途（守卫除零/判空）→ 反面风险（不该被跳过的副作用）*。五句话说完，稳过。

## 2.7 逻辑运算中的隐式 bool 转换｜清单第 24 条相关【重点】

**① 是什么**
一句话定义：`&& || !` 以及 `if while for` 的条件位置，期望拿到 `bool`；如果你给它一个整数、字符或指针，编译器会**隐式转换**——**0（含空指针）变 `false`，任何非 0 变 `true`**。课件 P11 原文第三条正是这句：「**条件判断中，非布尔型自动转换为布尔类型**」。

**② 为什么**
C++ 继承了 C 的"一切皆可判真假"传统，让 `if (ptr)`、`if (len)` 这类写法自然成立。C++11 起进一步引入**上下文转换（contextual conversion）**：条件表达式隐式套用 `explicit operator bool()`，所以像 `std::stringstream ss; if (ss)` 这种也能工作，同时又不至于让 `cout << ss` 意外编译。

**③ 怎么用**

```cpp
#include <iostream>
#include <sstream>
using namespace std;

int main() {
    // ===== 各种非 bool 值进入逻辑判断 =====
    cout << "if(0)     -> " << (0 ? "true" : "false") << endl;
    cout << "if(5)     -> " << (5 ? "true" : "false") << endl;
    cout << "if(-1)    -> " << (-1 ? "true" : "false") << endl;      // 非零即真，负数也真
    cout << "if('A')   -> " << ('A' ? "true" : "false") << endl;     // ASCII 65 → 真
    cout << "if('\\0') -> " << ('\0' ? "true" : "false") << endl;    // 值 0 → 假

    // ===== 指针 =====
    int* nullPtr = nullptr;
    int real = 1;
    int* validPtr = &real;
    if (nullPtr)  cout << "不会打印\n";
    if (validPtr) cout << "validPtr 非空，可以解引用：" << *validPtr << endl;

    // ===== 非 bool 值参与 && || 时结果仍是 bool =====
    auto r = 3 && 4;
    cout << "3 && 4 的类型是 bool，值 = " << boolalpha << r << endl;
    cout << "sizeof(3 && 4) = " << sizeof(3 && 4) << " 字节\n";

    // ===== 逻辑运算结果再参加算术：true=1, false=0 =====
    cout << "(2 > 1) + (3 > 5) = " << ((2 > 1) + (3 > 5)) << endl;   // 1 + 0 = 1

    // ===== 流对象的 explicit operator bool =====
    stringstream ss;
    int outVal = 0;
    ss << "abc";
    if (ss >> outVal) cout << "解析成功\n";
    else cout << "解析失败（abc 不是整数），ss 转 bool 为 false\n";
    return 0;
}
// 输出：
// if(0)     -> false
// if(5)     -> true
// if(-1)    -> true
// if('A')   -> true
// if('\0') -> false
// validPtr 非空，可以解引用：1
// 3 && 4 的类型是 bool，值 = true
// sizeof(3 && 4) = 1 字节
// (2 > 1) + (3 > 5) = 1
// 解析失败（abc 不是整数），ss 转 bool 为 false
```

**④ 注意事项 & 错误示范**

```cpp
#include <cstring>
#include <iostream>
using namespace std;

int findIndex() { return 0; }        // 约定 0 表示"找到在下标 0"

int main() {
    // ❌ 错误示范一：想用数组名判空
    char buf[] = "";
    if (buf) cout << "这句永远打印！数组名永不为空指针\n";
    // ✅ 正确写法：判断长度
    if (buf[0] != '\0') { cout << "不会打印\n"; }
    if (strlen(buf) > 0) { cout << "也不会打印\n"; }

    // ❌ 错误示范二：把返回值当真假时忽略"0 是假"的特殊含义
    if (findIndex()) cout << "找到了\n"; else cout << "没找到（逻辑错！）\n";
    // ✅ 正确写法：明确用 != 比较，别让隐式转换替你决定
    if (findIndex() != -1) cout << "这次说清楚了：找到了\n";

    // ❌ 错误示范三：连续赋值 + 隐式转换叠加，最难 debug
    int flag = 2;
    if (flag = 0) { /* 既有 = 误用，又有 0→false 转换，两个坑叠在一起 */ }

    // ✅ 建议写法：需要 bool 的地方就写 bool，别让编译器猜
    bool isValid = (flag != 0);
    if (isValid) { cout << "干净利落\n"; }
    return 0;
}
// 输出：
// 这句永远打印！数组名永不为空指针
// 没找到（逻辑错！）
// 这次说清楚了：找到了
// 干净利落
```

## 模块二微型总结（3 句话）

1. 六个比较运算符统统返回 **`bool`（1 字节）**，其中四个双字符符号 `>= <= == !=` 必须紧挨书写，拆开就是编译错误或 `=!` 这种阴间陷阱。
2. `&&` **同真为真、左假短路**；`||` **同假为假、左真短路**；`!` 优先级高达第 3 级且右结合，作用于比较表达式时必须加括号。
3. 短路的真正威力在于"**副作用会不会发生**"——课件 P7 那两道 `a=100` 的题，正确答案都是 **100**（不是 101 也不是 99），理由就是右边整段被跳过。

> C++一共有 **18** 个优先级，运算中按优先级进行计算，当优先级相同时，根据**结合性**规则来决定。

>

> 因为在程序中，**正确性 > 可读性 > 简洁性**

## 3.1 18 级优先级总表（课件 P9/P10 图片全文转录）｜清单第 19 条

**① 是什么**
一句话定义：优先级（precedence）决定"哪个运算符先抢走它的操作数"；结合性（associativity）决定"优先级相同的邻居们从左还是从右开始排队"。课件 P9、P10 是两张四列表格截图（列名：**优先级 / 运算符 / 结合律 / 助记**），列出优先级 1–16 级（第 17、18 级属少见运算符，基础课表格里未列，故页面写"18 个优先级"而表列到 16）。

**② 为什么**
`3 + 4 * 5` 之所以等于 23，全靠这张表。它存在不是为了折磨你，而是为了让表达式**不必到处写括号**就能唯一解析。

**③ 课件 P9 表格逐行转录（优先级 1–8）**

| 优先级 | 运算符 | 结合律 | 助记 |
|--------|--------|--------|------|
| 1 | `::` | 从左至右 | 作用域 |
| 2 | `a++`, `a--`, `type()`, `type{}`, `a()`, `a[]`, `.`, `->` | 从左至右 | 后缀自增减、函数风格转型、函数调用、下标、成员访问 |
| 3 | `!`, `~`, `++a`, `--a`, `+a`, `-a`, `(type)`, `sizeof`, `&a`, `*a`, `new`, `new[]`, `delete`, `delete[]` | **从右至左** | 逻辑非、按位非、前缀自增减、正负、C 风格转型、取大小、取址、指针访问、动态内存分配 |
| 4 | `.*`, `->*` | 从左至右 | 指向成员指针 |
| 5 | `a*b`, `a/b`, `a%b` | 从左至右 | 乘除、取模 |
| 6 | `a+b`, `a-b` | 从左至右 | 加减 |
| 7 | `<<`, `>>` | 从左至右 | 按位左右移 |
| 8 | `<`, `<=`, `>`, `>=` | 从左至右 | 大小比较 |

|--------|--------|--------|------|

| 10 | `a&b` | 从左至右 | 按位与 |

> ① **数字越小优先级越高**，第 1 级最高、最先绑定；
> ② 第 2 列看"谁和谁同级"——**同一行内的运算符彼此同级**；
> ③ 第 3 列"结合律"只在**同级相邻**时起作用：从左至右就是"先算左边的"，从右至左就是"先算右边的"；全表只有第 3 级和第 15 级是"从右至左"，其余全是"从左至右"；
> ④ 第 4 列"助记"是给口语化记忆的锚点，例如第 5 级叫"乘除、取模"、第 15 级整行叫"赋值族"；
> ⑤ 最需要记住的三个"反直觉"点：**`<<`/`>>`（第7）比 `<`/`>`（第8）更高**——所以 `cout << a < b` 会被解析成 `(cout << a) < b`；**`&`（第10）比 `==`（第9）更低**——所以 `flags & MASK == 0` 实际是 `flags & (MASK == 0)`，是经典 bug；**`&&`（13）比 `||`（14）高**——所以课件 P13 那道练习题可以先算 `&&` 再算 `||`。

**⑤ 抓关键分组，不要全背（提示词"记忆策略"）**

只需记住**七层金字塔**，其余查表：

```
第 1 层  最高：  ()  []  .  ->  函数调用  后缀++/--        ← "贴着东西就走"的成员访问类
第 2 层  一元：  !  ~  ++a  --a  +a  -a  (type)  sizeof  &  *  new  delete   【右结合】
第 3 层  算 术： *  /  %        然后       +  -
第 4 层  比 较： <  <=  >  >=   然后       ==  !=
第 5 层  位/逻辑： &  ^  |      然后       &&  然后  ||     ← 逻辑与比逻辑或高！
第 6 层  赋 值： ?:  =  +=  -=  *=  /=  %=                  【右结合】
第 7 层  最低：  逗号 ,
```

```cpp

using namespace std;

int main() {
    // ===== 用代码验证金字塔的几处高低关系 =====
    cout << "3 + 4 * 5      = " << 3 + 4 * 5 << "   （* 高于 +）\n";         // 23
    cout << "(3 + 4) * 5    = " << (3 + 4) * 5 << "  （括号改写了优先级）\n"; // 35

    cout << "2 + 3 < 4 * 5  = " << (2 + 3 < 4 * 5) << " （算术高于比较）\n";  // 1
    cout << "1 || 0 && 0    = " << (1 || 0 && 0) << "   （&& 高于 ||）\n";    // 1
    cout << "5 % 3 + 1      = " << 5 % 3 + 1 << "      （% 高于 +）\n";       // 3
    int x = 0, y = 0;
    x = y = 7;
    cout << "x = y = 7      -> x=" << x << " y=" << y << " （= 右结合）\n";   // 7 7
    return 0;
}

// (3 + 4) * 5    = 35  （括号改写了优先级）

// 2 * 6 / 3      = 4    （同级左结合）
// 2 + 3 < 4 * 5  = 1 （算术高于比较）
```

**⑥ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 经典 bug 一：位与 & 的优先级低于 ==
    unsigned int flags = 0x04;
    const unsigned int MASK = 0x04;
    if (flags & MASK == 0) {        // 解析为 flags & (MASK == 0) = flags & 0 = 0 → 判"真"
        cout << "误判：以为标志位没设置\n";
    }
    // ✅ 正确写法：位运算永远加括号
    if ((flags & MASK) == 0) { cout << "确实没设置\n"; } else { cout << "已设置，这才是真相\n"; }

    // ❌ 经典 bug 二：<< 优先级高于 <
    int val = 3;
    // cout << val < 5 << endl;     // 解析为 (cout << val) < 5 << endl，能编译但语义诡异
    // ✅ 正确写法
    cout << (val < 5) << endl;       // 打印 1

    // ❌ 经典 bug 三：* 的多义性
    int b = 5;
    int *p1 = &b, *p2 = &b;          // 声明里的 * 是指针符，不是乘法
    cout << "* 在声明里是指针：" << *p1 << " " << *p2 << endl;   // 5 5
    cout << "* 在表达式里是乘法：" << 3 * 4 << endl;             // 12
    return 0;
}
// 输出：
// 误判：以为标志位没设置
// 已设置，这才是真相
// 1
// * 在声明里是指针：5 5
// * 在表达式里是乘法：12
```

## 3.2 左结合（L-R）与右结合（R-L）｜清单第 20 条【熟悉】

**① 是什么**
一句话定义：当**同一优先级**的运算符连成一排时，**左结合**表示"从左往右依次算"（`a-b-c` → `(a-b)-c`），**右结合**表示"从右往左依次算"（`a=b=c` → `a=(b=c)`）。
生活比喻：排队结账。左结合像普通队伍——先来先服务；右结合像倒着点名——最后一个先被处理。

**② 为什么**
数学里减法天生不可交换也不满足结合律：`(10-3)-2 = 5`，而 `10-(3-2) = 9`。语言必须选一个方向才能唯一解析，人类习惯从左读，所以绝大多数运算符选了左结合。**赋值偏偏选右结合**，是为了让 `a = b = c = 0` 这种链式初始化能自然工作（`=` 有返回值这件事正是它的前提）。**逻辑非 `!` 是右结合**，因为它是**前缀一元**运算符，必须向右抓住它的操作数，`!!x` 才有意义（先算右边那个 `!x`）。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ========== 左结合家族 ==========
    cout << "--- 左结合（从左往右算）---\n";
    cout << "100 - 10 - 5 - 1 = " << 100 - 10 - 5 - 1
         << "   即 ((((100-10)-5)-1))\n";                      // 84
    cout << "2 * 3 * 4 * 5 = " << 2 * 3 * 4 * 5 << "\n";       // 120
    cout << "100 / 5 / 2 = " << 100 / 5 / 2
         << "   而非 " << 100 / (5 / 2) << "（加括号结果就变了）\n"; // 10 vs 40
    cout << "1+2+3+4 = " << 1+2+3+4 << "（左结合逐次相加）\n";        // 10

    // ========== 右结合家族 ==========
    cout << "\n--- 右结合（从右往左算）---\n";
    int a, b, c;
    a = b = c = 5;                                    // a = (b = (c = 5))
    cout << "a = b = c = 5  ->  a=" << a << " b=" << b << " c=" << c << "\n";  // 5 5 5

    cout << "!!5 双重取反（右结合）= " << !!5 << "\n";  // 1：先算 !5=0，再算 !0=1
    cout << "!(!5) 显式加括号        = " << !(!5) << "\n"; // 1，与上面等价

    // ========== 赋值与算术结合后整体仍是 R-L（课件 P8 原话）==========
    int p = 2, q = 3;
    p = q = p + q;                    // p = (q = (p + q))，先算 p+q=5，再 q=5，再 p=5
    cout << "p = q = p + q  ->  p=" << p << " q=" << q << "\n";   // 5 5
    return 0;
}
// 输出：
// --- 左结合（从左往右算）---
// 100 - 10 - 5 - 1 = 84   即 ((((100-10)-5)-1))
// 2 * 3 * 4 * 5 = 120
// 100 / 5 / 2 = 10   而非 40（加括号结果就变了）
// 1+2+3+4 = 10（左结合逐次相加）
//
// --- 右结合（从右往左算）---
// a = b = c = 5  ->  a=5 b=5 c=5
// !!5 双重取反（右结合）= 1
// !(!5) 显式加括号        = 1
// p = q = p + q  ->  p=5 q=5
```

**左结合 / 右结合分类清单（背这张小表就够了）**

| 结合方向 | 包含哪些运算符 | 记忆要点 |
|---------|---------------|---------|
| **从左至右 L-R** | 所有算术 `+ - * / %`、移位 `<< >>`、全部比较 `< <= > >= == !=`、位运算 `& ^ |`、逻辑 `&& ||`、逗号 `,`、后缀 `a++ a-- a[] a() a.b a->b`、作用域 `::` | **"绝大多数都是左结合"** |
| **从右至左 R-L** | 全部赋值 `= += -= *= /= %= &= ^= |= <<= >>=`、三元 `?:`、一元前缀 `! ~ ++a --a +a -a`、解引用 `*p`、取址 `&a`、`(type)` 强制转换、`sizeof`、`new`/`delete`、`throw` | **"赋值、三元、一元运算符这三类是右结合"** |

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范：同级但语义互相冲突的"连改"
    int k = 5;
    // int bad = k++ + k;          // UB：同一表达式内多次读取/修改 k，时机不明

    // ❌ 错误示范：把右结合的复合赋值串起来玩
    int m = 1, n2 = 2, o = 3;
    // m *= n2 += o;               // 数学上是 m *= (n2 += 3) → n2=5, m=5，但可读性极差
    // ✅ 正确写法：一行一句
    n2 = n2 + o;                 // 5
    m = m * n2;                  // 5
    cout << "拆开写：m=" << m << " n2=" << n2 << endl;   // 5 5

    // ✅ 真正推荐的右结合用法：链式赋值
    int x1, y1, z1;
    x1 = y1 = z1 = 0;            // 干净的初始化
    cout << "链式初始化：" << x1 << y1 << z1 << endl;
    return 0;
}
// 输出：
// 拆开写：m=5 n2=5
// 链式初始化：000
```

## 3.3 不确定就加括号：明确意图｜清单第 21 条【熟悉】

**① 是什么**
一句话定义：当你无法 100% 确定编译器会怎么解析一个表达式，就**用括号把自己的思路写出来**——课件 P8 原话：「在使用的时候，如果不确定，或者运算符太多，就按照自己的思路用括号隔开」。

**② 为什么**
括号是唯一能**凌驾**优先级表的东西，成本为零（现代编译器会把冗余括号优化掉，不产生额外指令）。不加括号的收益是"少敲两个键"，风险是"线上事故"。**代码是写给人看的，顺便让机器执行。**

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    unsigned int status = 0x08;
    const unsigned int READ  = 0x01;
    const unsigned int WRITE = 0x08;

    // ===== 不加括号：错得离谱 =====
    bool wrong = status & READ == 0;      // status & (READ == 0) → status & 0 → 0 → false
    // ===== 加了括号：意图清楚 =====
    bool right = (status & READ) == 0;    // 0x08 & 0x01 = 0 → true（确实没有读权限）
    cout << "wrong = " << boolalpha << wrong << ", right = " << right << endl;

    // ===== 判断可写：三重条件全部加括号 =====
    bool canWrite = ((status & WRITE) != 0) && ((status & READ) == 0);
    cout << "canWrite = " << canWrite << endl;                  // true

    // ===== 平均分的正确算法，括号写清楚 =====
    int sum = 7, cnt = 2;
    double avg = static_cast<double>(sum) / static_cast<double>(cnt);
    cout << "avg = " << avg << endl;                             // 3.5

    // ===== 成绩分档：每个边界都用括号自成一组 =====
    int score = 87;
    char level = (score >= 90) ? 'A' : ((score >= 80) ? 'B' : ((score >= 60) ? 'C' : 'D'));
    cout << "score=" << score << " 等级=" << level << endl;      // B

    // ===== 取整后再乘：括号消除歧义（同时暴露浮点截断）=====
    double price = 19.99; int qty = 3;
    long long cents = static_cast<long long>(price * 100) * qty;
    cout << "总分（以分为单位）= " << cents << endl;               // 5994，不是 5997！
    return 0;
}
// 输出：
// wrong = false, right = true
// canWrite = true
// avg = 3.5
// score=87 等级=B
// 总分（以分为单位）= 5994
```

> **这行例子值 5994 而非 5997，是一个真实陷阱**：`19.99 * 100` 在 `double` 里算出的并不是精确的 `1999.0`，而是 `1998.99999…`；`static_cast<long long>` 一律**向零截断**，于是变成 `1998`，再乘 3 得 `5994`。**涉及金额时不要靠浮点乘 100 再截断**，应改用 `llround(price * 100)`（需 `<cmath>`）或从一开始就用整数分单位存储。

**加括号的四条实操准则**

1. **位运算 (`& ^ | ~ << >>`) 一律包起来**——它们的优先级低到超乎想象（第 7、10、11、12 级），且极易与 `==`、`&&` 混写。
2. **逻辑表达式内部，每"一项判断"自成括号**：`(a > 0) && (b < 10)`。虽然 `&&` 已低于比较，但读者不需要知道这件事。
3. **三元 `?:` 嵌套必加括号**，或改用 `if/else`（可读性问题不属于优先级问题）。
4. **算术里凡是要打破 `* / %` 先于 `+ -` 的自然顺序，必写括号**：`(a + b) / c`。

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 过度加括号反而降低可读性
    int a = 5, b = 3;
    int overkill = (((a))) + (((b)));              // 满屏噪音
    int fine = a + b;                              // 同级一目了然，不必加
    cout << "overkill=" << overkill << " fine=" << fine << endl;

    // ❌ 括号位置写错，语义完全反转（这个坑非常常见）
    int n = 5;
    if (!n > 1) { cout << "不会进来\n"; }          // (!n) > 1 → 0 > 1 → false
    if (!(n > 1)) { cout << "也不会进来\n"; }       // n=5 → !(true) → false
    if (n > 1)  { cout << "想表达的其实是这个：n 大于 1 ✔\n"; }
    return 0;
}
// 输出：
// overkill=8 fine=8
// 想表达的其实是这个：n 大于 1 ✔
```

## 3.4 表达式书写原则：正确性 > 可读性 > 简洁性｜清单第 22 条【熟悉】

**① 是什么**
一句话定义：课件 P8 结尾的一句金句——「因为在程序中，**正确性 > 可读性 > 简洁性**」。它是一个**排序原则**：三者冲突时，先保正确，再谈好读，最后才追求简短。

**② 为什么**
"简洁"往往靠炫技达成（`*p++ = *q++;`、`a=b=c=0`、`i+++j`），它省下几个字符，却把理解成本转嫁给半年后的你和 review 你代码的同事。而"正确性"是产品底线，"可读性"是团队协作底线，两者的损失都比"多打两个括号"贵得多。

**③ 怎么用（三级取舍的实际对照）**

```cpp
#include <iostream>
using namespace std;

int main() {
    int base = 100, rate = 15, cap = 120;

    // ---------- 反例：牺牲可读性换取"简洁" ----------
    // int result = base + rate > cap ? base : base + rate;   // 依赖 ?: 与 > 的优先级，读三遍
    // ---------- 正例：正确性 + 可读性 ----------
    int grown = base + rate;                                  // 第一步：先算增长后的值
    int result = (grown > cap) ? cap : grown;                  // 第二步：再封顶
    cout << "result = " << result << endl;                     // 115

    // ---------- 反例：一行做完所有事 ----------
    // ---------- 正例：拆成清楚的三步（交换）----------
    int left = 1, right = 2;
    int temp = left;
    left = right;
    right = temp;
    cout << "交换后 left=" << left << " right=" << right << endl;   // 2 1
    // C++ 更好的写法：#include <algorithm> 后用 std::swap(left, right)

    // ---------- 反例：把判断藏进算术 ----------
    int isAdult = (base >= 18);          // 能用，但晦涩
    // ---------- 正例：直接写 bool ----------
    bool adultEnough = (base >= 18);
    cout << "adultEnough = " << boolalpha << adultEnough << endl;   // true

    // ---------- 反例：连环三元 ----------
    char g1 = (base > 200) ? 'A' : (base > 100) ? 'B' : (base > 50) ? 'C' : 'D';
    // ---------- 正例：if/else if 链条 ----------
    char g2;
    if      (base > 200) g2 = 'A';
    else if (base > 100) g2 = 'B';
    else if (base > 50)  g2 = 'C';
    else                 g2 = 'D';
    cout << "g1=" << g1 << " g2=" << g2 << "（结果相同，g2 更好维护）\n";
    return 0;
}
// 输出：
// result = 115
// 交换后 left=2 right=1
// adultEnough = true
// g1=C g2=C（结果相同，g2 更好维护）
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范："简洁"逼出了未定义行为
    int i = 0;
    // int v = i++ + i++ * 2;        // 省了三行代码，换来一个不可移植的炸弹

    // ✅ 正确写法：宁可多写两行
    int i2 = 0;
    int first = i2++;             // 0
    int second = i2++;            // 1
    int v2 = first + second * 2;  // 0 + 1*2 = 2，每一步都可预测
    cout << "v2 = " << v2 << endl;   // 2
    return 0;
}
// 输出：
// v2 = 2
```

> **三级取舍速记**：*先保证算得对，再保证看得懂，最后才保证写得短。*

## 3.5 课件 P13/P14 课堂练习：完整推导｜综合运用

课件 **P13** 出题（原文）：

```
练习
int aa = 1；
int bb = 2；
aa > 0 && bb > aa || !1 && bb <= aa, 该表达式的值为？
```

课件 **P14** 揭晓答案（原文）：**`true （或 1）`**

**逐步推导（严格按优先级 + 结合性 + 短路）**

表达式：`aa > 0 && bb > aa || !1 && bb <= aa`，其中 `aa = 1`，`bb = 2`。

涉及的优先级：`!`＝第 3 级（最高）＞ 关系 `>` `<=`＝第 8 级 ＞ `&&`＝第 13 级 ＞ `||`＝第 14 级（最低）。
所以**先分组**：`(aa > 0 && bb > aa) || (!1 && bb <= aa)`。

| 步骤 | 计算 | 值 | 说明 |
|------|------|----|------|
| ① | `aa > 0` → `1 > 0` | **true** | 第 8 级比较 |
| ② | `bb > aa` → `2 > 1` | **true** | 第 8 级比较 |
| ③ | `true && true` | **true** | 第 13 级 `&&`，左边为真所以右边照算 |
| ④ | 左半整体已为 **true** | **true** | `||` 左真 → **短路**，右半边 `!1 && bb <= aa` 完全不执行 |
| ⑤ | 最终结果 | **true（即 1）** | 与课件 P14 公布的答案一致 ✔ |

**注意**：即使不利用短路，右半边的值也算不出来不同结果——`!1` = false，false `&&` 任何东西都是 false，于是 `true || false` = **true**。两种推理路径都通向 `true`，这正是课件设计这道题的精妙之处：**它同时考了优先级、结合性和短路**。

```cpp
#include <iostream>
using namespace std;

int main() {
    int aa = 1;
    int bb = 2;

    // ===== 原式，交给编译器按优先级解析 =====
    bool ans = (aa > 0 && bb > aa || !1 && bb <= aa);
    cout << "原式的值 = " << boolalpha << ans << "（数字形式：" << noboolalpha << ans << "）\n";

    // ===== 手动加分组括号，验证优先级判断 =====
    bool grouped = ((aa > 0) && (bb > aa)) || ((!1) && (bb <= aa));
    cout << "加括号后 = " << grouped << "（应与上面一致）\n";

    // ===== 观察短路：给右半边加上副作用计数 =====
    int rightEvalCount = 0;
    bool trackLeft  = (aa > 0) && (bb > aa);           // true
    bool trackRight = (rightEvalCount++, false);        // 模拟右半边是否被执行
    bool shorted = trackLeft || trackRight;
    cout << "左半为 true 时 || 触发短路，最终 = " << shorted << endl;

    // ===== 逐项打印，方便对照上表 =====
    cout << "aa>0=" << (aa > 0) << " bb>aa=" << (bb > aa)
         << " !1=" << !1 << " bb<=aa=" << (bb <= aa) << endl;
    return 0;
}
// 输出：
// 原式的值 = true（数字形式：1）
// 加括号后 = 1（应与上面一致）
// 左半为 true 时 || 触发短路，最终 = 1
// aa>0=1 bb>aa=1 !1=0 bb<=aa=0
```

> **同类必练变式**（把本题改成会考查短路副作用的形式）：
> ```cpp
> #include <iostream>
> using namespace std;
> int main() {
>     int aa = 1, bb = 2;
>     bool r = (aa > 5) && (bb++ > aa);     // 左边 false → 短路，bb++ 不执行
>     cout << "r=" << r << " bb=" << bb << "（bb 若被 ++ 过应为 3）\n";
>     return 0;
> }
> // 输出：
> // r=0 bb=2（bb 若被 ++ 过应为 3）
> ```

## 模块三微型总结（3 句话）

1. 优先级共 18 级（课件表列到 16 级），**数字越小越先绑定**；只有第 3 级（一元运算符）和第 15 级（赋值、三元）是**右结合**，其余一律左结合。

## 4.1 隐式转换的方向：char → int → float → double 提升链｜清单第 23 条【重点】

**① 是什么**
一句话定义：隐式转换（implicit conversion，课件称"自动类型转换"）由**编译器自动完成**，方向永远是**从小类型升到大类型**，程序员不写任何转换符号。
生活比喻：自动扶梯——只能往上走（小→大），不会把你往下送；想下楼必须自己走楼梯（显式转换）。

**② 为什么**
小→大的转换**不会丢失信息**（`int` 的值域完全包含 `char`/`short`，`double` 能表示 `int` 的所有整数），所以编译器可以负责任地自动做。反过来大→小可能丢数据，责任必须落到写代码的人头上，因此语言强制你签字画押（写转换符号）。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ===== 提升链：char → short → int → long → float → double → long double =====
    char  c = 'A';              // 65
    int   i = 10;
    float f = 2.5f;
    double d = 1.25;

    cout << "char + int  -> 结果占 " << sizeof(c + i) << " 字节（都按 int 算）\n";
    cout << "int + double-> 结果占 " << sizeof(i + d) << " 字节（int 升成 double）\n";
    cout << "float+double-> 结果占 " << sizeof(f + d) << " 字节（float 升成 double）\n";
    cout << "char + double-> 结果占 " << sizeof(c + d) << " 字节\n";

    // ===== 课件 P11 第一条原文举例：char 和 int 相加 =====
    char c1 = 'a';               // 97
    int b1 = 1;
    cout << "'a' + 1 = " << (c1 + b1) << endl;      // 98（是数字，不是字符 'b'）

    // ===== 课件 P11 第二条原文举例：int 和 double 运算 =====
    int n = 3;
    double half = 0.5;
    cout << "3 * 0.5 = " << (n * half) << endl;     // 1.5（n 被升为 3.0）
    return 0;
}
// 输出：
// char + int  -> 结果占 4 字节（都按 int 算）
// int + double-> 结果占 8 字节（int 升成 double）
// float+double-> 结果占 8 字节（float 升成 double）
// char + double-> 结果占 8 字节
// 'a' + 1 = 98
// 3 * 0.5 = 1.5
```

```cpp
    int big = 2000000000;                     // 2×10⁹，接近 int 上限
    double safe = big + big;                  // ❌ big+big 先在 int 里算 → UB
```

## 4.2 隐式转换发生在两种场景｜清单第 24 条【重点】

**① 是什么**
一句话定义：课件 P11 列出的三条原文，其实归为**两类半场景**——**混合类型运算**（前两条 bullet）、**条件判断**（第三条 bullet），此外还有第三类常被忽略的：**赋值时左右类型不同**。
生活比喻：只有两个地方海关会替你自动办手续——跨境购物（运算）和过闸机（判断）。其余情况（比如自己搬大件行李）都得亲自申报（显式转换）。

**② 为什么**
分清楚场景才不会漏。**运算**里的转换决定结果的类型；**判断**里的转换决定真假；**赋值**里的转换则可能是**窄化**（危险）。三者规则不同，混为一谈是最常见的理解漏洞。

**③ 怎么用**

```cpp
#include <iostream>
using namespace std;

int main() {
    // ========== 场景 A：混合类型运算（课件 P11 前两条 bullet）==========
    char  ch = '5';           // ASCII 53
    int   num = 1;
    cout << "[A1] char + int   : " << (ch + num) << "  （'5'=53 → 54）\n";
    int   i = 4;
    double d = 2.0;
    cout << "[A2] int / double : " << (i / d) << "  （int 升成 double 再除，不发生截断）\n";

    // ========== 场景 B：条件判断（课件 P11 第三条 bullet）==========
    int count = 0;
    if (count) cout << "B-不会打印\n"; else cout << "[B] 非 bool 值 0 → false\n";
    char letter = 'x';
    if (letter) cout << "[B] 字符 'x'(120) 非零 → true\n";
    int* ptr = nullptr;
    if (!ptr) cout << "[B] 空指针 → false，取反后为 true\n";

    // ========== 场景 C：赋值时左右类型不同（最容易被漏掉的一类）==========
    double pi = 3.99;
    int shrink = static_cast<int>(pi);        // 需要显式：大转小
    cout << "[C] (int)3.99 = " << shrink << "  （截断，不是四舍五入成 4）\n";
    int grow = 42;
    double expand = grow;                     // 无需显式：小转大
    cout << "[C] int→double 自动 : " << expand << endl;
    return 0;
}
// 输出：
// [A1] char + int   : 54  （'5'=53 → 54）
// [A2] int / double : 2  （int 升成 double 再除，不发生截断）
// [B] 非 bool 值 0 → false
// [B] 字符 'x'(120) 非零 → true
// [B] 空指针 → false，取反后为 true
// [C] (int)3.99 = 3  （截断，不是四舍五入成 4）
// [C] int→double 自动 : 42
```

**三场景对照表**

| 场景 | 触发点 | 转换方向 | 是否需要你写代码 | 典型风险 |
|------|--------|---------|-----------------|---------|
| A 混合运算 | `+ - * / %`、比较、位运算 | 小 → 大（提升到共同类型） | 不需要 | 忘了浮点参与会使整数也变浮点；无符号拉高有符号 |
| B 条件判断 | `if while for && \|\| ! ?:` | 任意标量 → `bool` | 不需要 | 0 与"有效值 0"混淆；`=`` 误用叠加 |
| C 赋值 | `=` 与 `+= -= …` | 右 → 左的类型 | **大转小时需要** | 窄化静默丢数据（`double`→`int`、`int`→`char`） |

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 错误示范：只在赋值处加转换，运算已经出错
    int total = 9, groups = 2;
    double avgLate = total / groups;         // 除法仍是整数除法 → 4.000000
    cout << "avgLate = " << avgLate << endl;
    // ✅ 正确写法：在运算发生之前转换
    double avgEarly = static_cast<double>(total) / groups;   // 4.5
    cout << "avgEarly = " << avgEarly << endl;

    // ❌ 错误示范：函数实参传递也是隐式转换场景（第10章会大量遇到）
    // void show(int x);  show(3.9);         // 静默把 3.9 截断成 3
    // ✅ 正确写法：调用点显式写出意图
    double raw = 3.9;
    int truncated = static_cast<int>(raw);
    cout << "显式传参：" << truncated << endl;
    return 0;
}
// 输出：
// avgLate = 4
// avgEarly = 4.5
// 显式传参：3
```

## 4.3 栈内存布局：为什么 char 能隐式转 int，反之要显式｜清单第 23、25 条支撑（提示词专项要求第 2 条）

**① 是什么**
一句话定义：类型转换的本质是**在内存里重新解释/搬运那几串比特**。小类型放进大盒子，只需在高位补符号位或零；大类型塞进小盒子，必须**砍掉高位**——砍掉的那部分再也找不回来。

**② 为什么**
理解了字节布局，"小转大安全、大转小危险"就不再是需要死背的规则，而是显然的事实。这也解释了为什么 `int`→`double` 虽然字节数相同（都是 8/4）却仍要小心：它们**编码方式完全不同**（整数用补码，浮点数用 IEEE 754 的符号位+指数+尾数）。

**③ 内存布局图（GCC/MSVC 64 位，小端序）**

```
【 widening：char → int，安全 】
char  c = 'A';            内存：[ 41 ]                       （1 字节，0x41 = 65）
       ↓ 隐式转换（符号扩展：正数补 0，负数补 1）
int   v = c;              内存：[ 41 00 00 00 ]              （4 字节，值仍为 65）
                              ↑ 高位全部补齐，原值完整保留，零信息损失

【 narrowing：int → char，危险 】
int   big = 300;          内存：[ 2C 01 00 00 ]              （4 字节，0x0000012C = 300）
       ↓ 强制塞进 1 字节盒子（只保留最低 1 字节）
char  s = (char)big;      内存：[ 2C ]                       （1 字节，0x2C = 44）
                              ✗ 高位 01 00 00 被永久丢弃 → 300 变成 44

【 同样 4 字节但编码不同：int → float 】
int   n = 1;              位模式：0000 0000 0000 0000 0000 0000 0000 0001
float f = 1.0f;           位模式：0 01111111 00000000000000000000000（符号|指数|尾数）
       ↑ 转换必须重写这 32 位，不能"直接挪用"，所以运行时要有 cvtsi2ss 之类的指令开销
```

**④ 怎么用（配合代码验证上面的布局）**

```cpp
#include <iostream>
#include <cstring>       // memcpy
using namespace std;

int main() {
    // 观察 char → int 的符号扩展
    char pos = 'A';                    // 65
    char neg = static_cast<char>(-30); // -30
    cout << "char 'A' → int = " << static_cast<int>(pos) << endl;
    cout << "char -30  → int = " << static_cast<int>(neg) << " （符号位扩展，仍为 -30）\n";
    unsigned char uneg = static_cast<unsigned char>(-30);
    cout << "unsigned char 同值 = " << static_cast<int>(uneg) << " （0xE2 被当作 226）\n";

    // 观察 int → char 的高位丢弃
    int big = 300;
    char cut = static_cast<char>(big);
    cout << "(int)300 → char = " << (int)cut << " ，因为 300 = 0x012C，只剩低字节 0x2C\n";

    // 打印 int 的原始字节（小端序可见低位在前）
    int probe = 300;
    unsigned char bytes[sizeof(probe)];
    memcpy(bytes, &probe, sizeof(probe));
    cout << "300 的内存字节（低→高）：";
    for (size_t k = 0; k < sizeof(probe); ++k) cout << hex << (int)bytes[k] << " ";
    cout << dec << endl;

    // 观察 int → double 的编码差异
    int one = 1;
    double done = one;
    cout << "int 1 与 double 1.0 都各占 " << sizeof(one) << "/" << sizeof(done)
         << " 字节，但位模式完全不同\n";
    return 0;
}
// 输出：
// char 'A' → int = 65
// char -30  → int = -30 （符号位扩展，仍为 -30）
// unsigned char 同值 = 226 （0xE2 被当作 226）
// (int)300 → char = 44 ，因为 300 = 0x012C，只剩低字节 0x2C
// 300 的内存字节（低→高）：2c 1 0 0
// int 1 与 double 1.0 都各占 4/8 字节，但位模式完全不同
```

**⑤ 注意事项 & 常见错误**

- **别把"字节数够"当成"转换安全"**：`float`(4B) → `int`(4B) 字节数一样，却会丢掉小数部分；`int` → `float` 也只保 24 位有效尾数，超过约 1677 万的 `int` 转 `float` 会失真。
- **符号扩展取决于源类型的符号性**：`signed char(-30)` → `int` 得 `-30`；`unsigned char(226)` → `int` 得 `226`。这正是前面反复强调"要写死 signed/unsigned"的原因。

## 4.4 显式转换写法一：`(typeName) value`（C 风格）｜清单第 25 条【重点】

**① 是什么**
一句话定义：把目标类型写在圆括号里放在值前面，`int c = (int)a;`。这是**从 C 语言继承来的写法**，课件 P11 明确标注为"C语言的写法"。
生活比喻：一句万能的"我不管，就按这个来"——它既可能是善意的数值转换，也可能是危险的指针乱 reinterpret，编译器无从分辨。

**② 为什么（以及为什么要警惕）**
C 风格的 `(T)v` 是一个**语法多面手**，它会依次尝试：const 去除（等价 `const_cast`）、数值转换（等价 `static_cast`）、指针重解释（等价 `reinterpret_cast`）。因为它**偷偷包含最危险的那一档**，一旦你写的类型和实际需要的语义差一点，就可能编译通过而运行崩溃。

**③ 怎么用（课堂代码第89行就是这个写法）**

```cpp
#include <cstdint>         // intptr_t 在这里
#include <iostream>
using namespace std;

int main() {
    float a = 112.34f;
    int c1 = (int)a;                // 课堂代码.cpp 第89行的写法：C 风格强转
    cout << "(int)a = " << c1 << endl;

    // 也可以给表达式整体转换
    int x = 7, y = 2;
    cout << "(double)x / y = " << (double)x / y << endl;

    // 指针也能转（这正是危险之处）
    intptr_t addrLike = 100;         // 用 intptr_t 才跨平台；直接写 int 在 64 位 GCC 会警告
    int* p = (int*)addrLike;         // ⚠️ 竟然编译通过！它在做 reinterpret_cast 的事
    cout << "指针被硬造出来了，值为 " << p << " —— 千万别去解引用它\n";
    (void)p;                         // 仅演示，不 deref
    return 0;
}
// 输出（地址值随平台而异，此处为 64 位 MinGW 实测）：
// (int)a = 112
// (double)x / y = 3.5
// 指针被硬造出来了，值为 0x64 —— 千万别去解引用它
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    const int k = 10;
    // int* bad = (int*)&k;         // C 风格能编译：悄悄 cast away const
    // *bad = 20;                   // ❌ 未定义行为！k 可能在只读段，也可能被常量折叠
    // ✅ 正确写法：如果真要改，就不要声明成 const；确需去 const 用 const_cast 并保证对象本身可变
    int mutableK = 10;
    int* good = const_cast<int*>(&mutableK);
    *good = 20;
    cout << "合法修改后 = " << mutableK << endl;

    // ✅ 更推荐：干脆不去 const，写清楚逻辑
    cout << "避免 cast 才是上策，k = " << k << endl;
    return 0;
}
// 输出：
// 合法修改后 = 20
// 避免 cast 才是上策，k = 10
```

> **C 风格转换的三宗罪**：① 难以在代码里搜索（满屏都是圆括号）；② 语义不明确（不知道你想要哪种转换）；③ 允许不该允许的转换（如去掉 `const`、无关指针互转）而不给警告。

## 4.5 显式转换写法二：`typeName(value)`（函数式记法）｜清单第 26 条【重点】

**① 是什么**
一句话定义：把类型名当成一个"函数"来调用，`int c = int(a);`。课件 P11 标注为"c++的写法"，正式名称是**函数式类型转换（functional cast）**。
生活比喻：给它套上函数调用的外衣，看起来就像一次正规加工工序，比裸括号更像"有意为之"。

**② 为什么**
它与 `(T)v` **能力完全相同**（内部做的还是那一组转换），只是**书写形态**更接近 C++ 的现代风格，且便于放进模板参数场景。它的价值主要在可读性，不在安全性。

**③ 怎么用（课堂代码第90行）**

```cpp
#include <iostream>
using namespace std;

int main() {
    float a = 112.34f;
    int c = int(a);                 // 课堂代码.cpp 第90行的写法：函数式转换
    cout << "int(a) = " << c << endl;

    // 多个参数？不行——函数式转换只接受一个操作数
    int x = 7, y = 2;
    cout << "double(x) / y = " << double(x) / y << endl;

    // 与自定义类型结合时最自然（构造即转换）
    // std::string s = std::string("abc");   // 同一形态
    return 0;
}
// 输出：
// int(a) = 112
// double(x) / y = 3.5
```

**④ 注意事项 & 错误示范**

```cpp
#include <iostream>
using namespace std;
int main() {
    int a = 100;
    // ❌ 陷阱：函数式记法可能被解析成"变量声明"
    int b = int(a);        // 这里是转换，b = 100
    int c = int(a + 1);    // 转换，c = 101
    // int d(int);         // 这一行是"函数声明"！不是转换（著名的 most vexing parse）
    cout << "b=" << b << " c=" << c << endl;

    // ⚠️ 提醒：函数式转换同样能做危险事（它 == C 风格的能力）
    const int k = 5;
    // auto danger = (int&)k;   // 引用形式更隐蔽，C++ 规范写法请用 const_cast
    cout << "k=" << k << endl;
    return 0;
}
// 输出：
// b=100 c=101
// k=5
```

> **要点**：`type(v)` 和 `(type)v` **本质相同**，都不是安全选择。C++ 给出的答案是第三种——`static_cast`。

## 4.6 显式转换写法三：`static_cast<typeName>(value)`（C++ 推荐）｜清单第 27 条【重点】

**① 是什么**
一句话定义：`static_cast<T>(v)` 是 C++ 提供的**受约束的、语义明确的**编译期检查转换，只做"合理的"数值转换、向上/向下的类层次指针转换等，**拒绝**明显荒谬的转换。课件 P11 原文：「`static_cast<>` 可以将值从一种数值类型转换为另外一种数据类型，格式为：`static_cast<typeName> (value)`」。

**② 为什么**
它是**自文档化**的：读代码的人一眼看到"这里有一次刻意的类型跨越"；它也是**可搜索**的（`grep static_cast` 一把抓）；最重要的是它**拒绝了不该发生的转换**（例如两个无关的具体类型之间），把 bug 拦在编译期。

**③ 怎么用（课堂代码第91行）**

```cpp
#include <iostream>
using namespace std;

int main() {
    float a = 112.34f;
    int c = static_cast<int>(a);            // 课堂代码.cpp 第91行的写法：C++ 推荐
    cout << "static_cast<int>(a) = " << c << endl;

    // 最有价值的用途：拯救整数除法
    int x = 7, y = 2;
    cout << "x / y                = " << x / y << endl;
    cout << "static_cast<double>(x) / y = "
         << static_cast<double>(x) / y << endl;      // 3.5 ✔

    // 用于 char ↔ int
    char ch = 'a';
    int code = static_cast<int>(ch);
    cout << "static_cast<int>('a') = " << code << endl;
    char back = static_cast<char>(code + 1);
    cout << "static_cast<char>(98) = " << back << endl;

    // 用于 bool 显式化
    int raw = 42;
    cout << "static_cast<bool>(42) = " << boolalpha << static_cast<bool>(raw) << endl;
    return 0;
}
// 输出：
// static_cast<int>(a) = 112
// x / y                = 3
// static_cast<double>(x) / y = 3.5
// static_cast<int>('a') = 97
// static_cast<char>(98) = b
// static_cast<bool>(42) = true
```

**三种显式写法横向对比表（提示词硬性要求的"对比 C 语言写法差异"）**

| 维度 | `(type)v` C 风格 | `type(v)` 函数式 | `static_cast<type>(v)` C++ 推荐 |
|------|------------------|------------------|-------------------------------|
| 课件出处 | P11"C语言的写法" | P11"c++的写法" | P11 单独列为一条 |
| 可读性/自文档化 | 差，易与普通括号混淆 | 中 | **好**，一眼看出是转换 |
| 能否 grep 搜索 | 难 | 难 | **容易** |
| 是否包含 `reinterpret_cast` 能力（指针乱转） | **是**（危险） | **是**（危险） | **否**（编译期拒绝无关类型互转） |
| 是否能去掉 `const` | **是**（危险） | 一般不用于此 | **否**（要用 `const_cast`） |
| 编译期检查强度 | 弱 | 弱 | **强** |
| 与模板配合 | 别扭 | 可用 | **最佳**（`static_cast<T>(v)` 中 T 可为模板参数） |
| 推荐度 | 遗留代码 | 少用 | ✅ **首选** |

**④ 注意事项 & 错误示范**

```cpp
#include <climits>         // INT_MIN, INT_MAX 在这里
#include <iostream>
using namespace std;
int main() {
    // ❌ 误解一：以为 static_cast 会帮你做运行时安全检查
    double huge = 1e20;
    int clipped = static_cast<int>(huge);       // UB！超出 int 范围，static_cast 不会报错也不会拦
    cout << "clipped 是个不可靠的值：" << clipped << endl;
    // ✅ 正确写法：转换前先做范围校验
    if (huge >= static_cast<double>(INT_MIN) && huge <= static_cast<double>(INT_MAX)) {
        cout << "范围合法才转\n";
    } else {
        cout << "1e20 根本放不进 int，必须先处理\n";
    }

    // ❌ 误解二：忘记 < > 里的类型不能省
    int v = 3;
    // auto miss = static_cast(v);              // 编译错误：missing template argument
    auto ok = static_cast<double>(v);
    cout << "ok = " << ok << endl;

    // ✅ static_cast 也会向下转换指针（有代价，见第14章）
    cout << "static_cast 的定位是『编译期已知关系的转换』，多态向下转应使用 dynamic_cast\n";
    return 0;
}
// 输出（本机 GCC 8.1 实测；注意第一行的值属于 UB 产物，换编译器可能不同）：
// clipped 是个不可靠的值：-2147483648
// 1e20 根本放不进 int，必须先处理
// ok = 3
// static_cast 的定位是『编译期已知关系的转换』，多态向下转应使用 dynamic_cast
```

> **`static_cast` 不做的事**（记住这四条就懂了整个 cast 家族分工）：
> 不做运行时类型检查（那是 `dynamic_cast`）；不去 `const`（那是 `const_cast`）；不重解释无关指针/整数（那是 `reinterpret_cast`）；不做超出目标类型范围的值合法性检查（那是你自己的责任）。

## 4.7 ASCII 码与字符型数据的互转｜清单第 28 条【重点】

**① 是什么**
一句话定义：字符在内存里存的就是一个整数（ASCII 码），课件 P12 是一整张《ASCII 字符代码表》截图。记住四个锚点：`'0'`=48、`'A'`=65、`'a'`=97、空格=32、`'\0'`=0。
生活比喻：ASCII 表是一本"电话号码簿"——每个字符有个固定的门牌号，`char` 与 `int` 互转就是查号/被查号。

**② 为什么**
计算机只认数字。为了让字母也能存取比较，人们约定了这张表。因为表中数字字符 `'0'`~`'9'` **连续排列**（48~57）、大写字母 **连续**（65~90）、小写字母 **连续**（97~122），我们才能用 `'5' - '0'` 这种减法把字符变成数值——这是本章最实用的一招。

**③ 课件 P12 表格内容与查阅方法（提示词"图表必讲"要求）**

课件那张表是一张二维网格：**列标题是"高四位"**（0000 ~ 0111，对应十进制 0~7），**行标题是"低四位"**（0000 ~ 1111，对应 0~F）。查某个字符就找"高四位行 × 低四位列"的交叉格。表还分左右两大区：

- **左半区（高四位 0000、0001）＝ ASCII 非打印控制字符**：如 0=NUL 空、7=BEL 震铃、8=BS 退格、9=HT/TAB 水平制表、10=LF 换行、13=CR 回车、27=ESC 转意。这些字符**看不见**，用于控制设备。
- **右半区（高四位 0010 ~ 0111）＝ ASCII 打印字符**：从 32=空格开始，依次为标点、数字、大写字母、小写字母。
- 表格底部有一行注释：**"表中的 ASCII 字符可以用 ALT + 小键盘上的数字键 输入"**（Alt+65 就能打出 A）。

**常用字符数值对照表（从课件 P12 表中摘录的高频项）**

| 字符 | 十进制 | 十六进制 | 说明 |
|------|--------|----------|------|
| `'\0'` | 0 | 0x00 | 空字符，C 风格字符串结束标志 |
| `'\n'` | 10 | 0x0A | 换行 LF |
| `'\t'` | 9 | 0x09 | 制表符 TAB |
| `' '`（空格） | 32 | 0x20 | 最小的可打印字符 |
| `'!'` | 33 | 0x21 | 最大的常用标点起点 |
| `'0'` | **48** | 0x30 | 数字起点 |
| `'9'` | 57 | 0x39 | 数字终点 |
| `'A'` | **65** | 0x41 | 大写起点 |
| `'Z'` | 90 | 0x5A | 大写终点 |
| `'a'` | **97** | 0x61 | 小写起点 |
| `'z'` | 122 | 0x7A | 小写终点 |
| `'~'` | 126 | 0x7E | 常用可打印终点 |
| `127` | 127 | 0x7F | DEL 删除 |

**关键规律（务必内推出来，不要死背）**

```
'0' = 48        数字字符减去 '0' 即得其数值：  '7' - '0' = 55 - 48 = 7
'A' = 65        大写字母减 'A' 得序号：        'D' - 'A' = 68 - 65 = 3
'a' = 97        小写字母减 'a' 得序号：        'd' - 'a' = 100 - 97 = 3
'a' - 'A' = 32  大小写相差 32（0x20）：        小写 ↔ 大写就是 ±32
```

**④ 怎么用**

```cpp

using namespace std;

int main() {
    // ===== 四个锚点值 =====
    cout << "'0' = " << (int)'0' << ", 'A' = " << (int)'A'
         << ", 'a' = " << (int)'a' << ", 'z' = " << (int)'z' << endl;

    // ===== 课堂代码第72-74行：char + int 得到的是数字 =====
    char c = 'a'; int b = 1;
    cout << "c + b = " << (c + b) << endl;         // 98

    // ===== 课堂代码第77-83行：char ↔ int 双向赋值 =====
    char c2 = 'a'; int bb = 1;
    int d = c2;                    // char → int：97
    char e = static_cast<char>(bb);// int → char：值 1 是不可打印控制字符
    cout << "int d = c -> " << d << endl;
    cout << "char e = 1 -> [" << e << "]（值 1 是控制字符，屏幕上看不见）\n";
    char printable = static_cast<char>(98);
    cout << "char(98) -> [" << printable << "]\n";

    // ===== 字符 ↔ 数字互转的经典三招 =====
    char digitChar = '7';
    int digitValue = digitChar - '0';
    cout << "'7' - '0' = " << digitValue << endl;
    int anotherDigit = 3;
    char back = static_cast<char>(anotherDigit + '0');
    cout << "3 + '0' -> '" << back << "'" << endl;

    // ===== 大小写互转（±32）=====
    char upper = 'Q';
    char lower = static_cast<char>(upper + 32);
    cout << "'Q' + 32 = '" << lower << "'" << endl;
    char again = static_cast<char>(lower - 'a' + 'A');
    cout << "小写转回大写：'" << lower << "' -> '" << again << "'" << endl;

    // ===== 字母在表中的序号（离 'a' 多远）=====
    char letter = 'e';
    cout << letter << " 是第 " << (letter - 'a' + 1) << " 个字母\n";

    // ===== 判断是否数字字符（不用库函数的原理版）=====
    for (char t = '4'; t <= '6'; ++t) {
        if (t >= '0' && t <= '9') cout << t << " 是数字字符\n";
    }
    return 0;
}
// 输出：
// '0' = 48, 'A' = 65, 'a' = 97, 'z' = 122
// c + b = 98
// int d = c -> 97
// char e = 1 -> []（值 1 是控制字符，屏幕上看不见）
// char(98) -> [b]
// '7' - '0' = 7
// 3 + '0' -> '3'
// 'Q' + 32 = 'q'
// 小写转回大写：'q' -> 'Q'
// e 是第 5 个字母
// 4 是数字字符
// 5 是数字字符
// 6 是数字字符
```

## 模块四微型总结（3 句话）

1. **隐式转换只会往上升**（char→int→float→double，外加"任意标量→bool"），发生在**混合运算**和**条件判断**两处，赋值时的窄化则需要你显式签字。
2. **显式转换三种写法**：`(T)v` 是 C 遗产、`T(v)` 是同义换皮、**`static_cast<T>(v)` 才是 C++ 首选**——它可搜索、自文档化，并且会拒绝无关类型互转。
3. **字符即整数**：记住 `'0'`=48、`'A'`=65、`'a'`=97 三个锚点和"`X - '0'` 取数值、`±32` 转大小写"两招，ASCII 表就够用一辈子。

# 编译期 vs 运行期行为对照（提示词课件专项要求第 1 条）

**① 是什么**
一句话定义：有些"运算"在你按下运行键之前就已经由编译器算完了（**编译期**），有些必须等到程序真正跑起来才能算（**运行期**）。区分二者，才能理解为什么 `const` 常量参与运算不拖慢程序。

**② 为什么值得学**
编译器有一项基础优化叫**常量折叠（constant folding）**：只要一个表达式的操作数全是编译期已知的常量，它就在编译期直接算成一个值，把整段运算从生成的机器码里删掉。运行期开销为零。而变量参与的运算，编译器无法预知值，只能真的生成 `add`/`imul`/`idiv` 等指令。

**③ 分类对照表**

| 运算符 / 构造 | 何时发生 | 说明与依据 |
|---------------|---------|-----------|
| `sizeof(类型)` | **编译期** | 结果是 `size_t` 常量，不产生任何运行期计算；`sizeof(v)` 也不求值 `v` |
| 字面量算术 `3 + 4 * 5` | **编译期**（常量折叠） | 编译器直接生成 23；调试时看不到加法指令 |
| `const int k = 10;` 参与运算 | **编译期** | `k` 是编译期常量，`k * 2` 被折叠成 20；等价于宏替换后的效果 |
| `constexpr` 表达式（C++11） | **强制编译期** | 编译器保证在编译期算完，算不出就报错 |
| 变量算术 `a + b`、`a * b` | **运行期** | 生成 `add`/`imul` 指令 |
| 整数除法 `/`、取模 `%` | **运行期** | 生成 `idiv`，是普通加减的数十倍开销（约 20~40 周期） |
| 赋值 `=`、复合赋值 | **运行期** | 生成 store 指令；`+=` 通常是 load+add+store |
| 比较 `< > == !=` | **运行期**（常量则编译期） | 生成 `cmp` + `setcc`，结果放进寄存器或内存 |
| `&&` `\|\|` `!` | **运行期** | 短路靠跳转指令 `je`/`jne` 实现，这正是"右边不执行"的机器码证据 |
| `++` `--` | **运行期** | `inc`/`dec` 指令 |
| 隐式类型转换（选择哪条提升路径） | **编译期决定** | 编译器静态判定共同类型，不需要运行时试探 |
| 隐式/显式转换的**实际执行** | **运行期有开销** | `int`→`double` 生成 `cvtsi2sd`；`double`→`int` 生成 `cvttsd2si`（截断）；`char`→`int` 只是符号扩展 `movsx` |
| `(T)v` / `T(v)` / `static_cast<T>(v)` 三者 | **完全相同的时机** | 语法糖差异而已，生成的机器码一模一样 |

**④ 怎么用（亲眼看到常量折叠）**

```cpp
#include <iostream>
using namespace std;

int main() {
    const int kSize = 100;                 // 编译期常量
    cout << "kSize * 2 = " << kSize * 2 << endl;   // 编译期就算出 200，运行期没有乘法指令

    int n = 100;                           // 运行期才知道的变量
    cout << "n * 2     = " << n * 2 << endl;       // 这里必须真的生成一次乘法

    // sizeof 永远是编译期常量，而且不求值里面的表达式
    int danger = 0;
    cout << "sizeof(danger / 0) = " << sizeof(danger / 0) << endl;  // 输出 4，不会崩溃！
    cout << "danger 仍是 " << danger << "，因为 sizeof 里的表达式从未被求值\n";

    // constexpr 强制编译期（C++11 起三大编译器均支持）
    constexpr int squared = 7 * 7;
    cout << "constexpr squared = " << squared << endl;
    return 0;
}
// 输出：
// kSize * 2 = 200
// n * 2     = 200
// sizeof(danger / 0) = 4
// danger 仍是 0，因为 sizeof 里的表达式从未被求值
// constexpr squared = 49
```

**⑤ 注意事项 & 常见误解**

- **别以为"`const` 就是运行期不可变"**：`const int x = readInput();` 里的 `x` 只在初始化后不变，它的值是运行期得到的，因此**不能**用于数组长度，也**不会**被折叠。要编译期常量请用 `constexpr`。
- **别指望优化改变语义**：`-O2` 会把 `a + b * c` 折成一条 `lea`，但绝不会替你改掉整数截断——`7/2` 在任何优化等级下都是 3。
- **除法和取模是性能敏感点**：循环里频繁 `% 2` 可改写为 `& 1`（位运算预告，见[衔接](#衔接)一节），但**先保证可读性**，确有性能瓶颈再改。

# 与 C 语言的写法差异对照（提示词课件专项要求第 4 条）

**① 是什么**
一句话定义：本章几乎所有运算符都直接继承自 C，语义基本一致；C++ 在三个地方做了改动——**新增 `bool` 类型**、**提供命名 cast（`static_cast`）**、**把负数除法/取模的行为标准化**。

**② 为什么要讲这个**
你的教材体系里 C 与 C++ 并存，网上大量示例是 C 风格。搞清楚差异，才不会把 C 的习惯错误地带进 C++（反之亦然），也才明白老师为什么强调用 `static_cast`。

**③ 逐项对照**

| 项目 | C 语言 | C++（本章） | 影响 |
|------|--------|------------|------|
| 布尔类型 | **无内建 `bool`**（C99 才有 `_Bool` + `<stdbool.h>` 宏） | 内建 `bool`，`true`/`false` 是关键字，`sizeof(bool)==1` | C++ 里比较运算返回真正的 `bool`；C 里返回 `int` 的 1/0 |
| 逻辑运算返回值 | `int` | `bool` | C++ 中 `auto r = (1 && 2);` 推导为 `bool` |
| 真值判断 | 0 为假、非 0 为真 | 相同规则 + 指针也可判空 | 兼容，无坑 |
| 强制转换 | 只有 `(T)v` | `(T)v`、`T(v)`、`static_cast<T>(v)`（及 `const_/reinterpret_/dynamic_cast`） | C++ 能把危险转换拆出来单独管理 |
| `char` 符号性 | 实现定义 | **同样是实现定义**（不是 C++ 的改进） | 两边都得写死 `signed char`/`unsigned char` |
| 负数除法 | C99 起向零取整（此前实现定义） | **C++11 起向零取整**（此前实现定义） | 老代码迁移时最容易翻车的一项 |
| 复合赋值 | 有 | 有，且可重载（`operator+=`） | C++ 自定义类也能用 `+=` |
| `++/--` | 有 | 有，且对类类型可重载（迭代器依赖它） | C++ 里前缀通常更高效 |
| 三元 `?:` | C 里结果常为右值 | C++ 里若两分支同类型可得**左值**（可 `a>b?(c=1):(d=2)` 之类） | 细节，进阶章节展开 |
| 布尔输出 | 无 iostream | `cout << boolalpha` 打印 true/false | 本章笔记大量使用 |

**④ 三种语言风格写法对比（同一件事的四种写法）**

```cpp
#include <cstdio>      // C 风格 printf
#include <iostream>
using namespace std;

int main() {
    int total = 7, cnt = 2;

    // ---- C 风格：只有 (T)v，且没有 bool ----
    int cStyle = (int)(total * 1.0 / cnt);          // 借浮点绕开截断
    printf("C 风格 printf: %d\n", cStyle);           // 输出 3
    int isPos_C = (total > 0);                       // C 里这就是个 int，值为 1
    printf("C 里的\"真\": %d\n", isPos_C);

    // ---- C++ 风格一：函数式转换 ----
    double cppFunc = double(total) / cnt;
    cout << "C++ 函数式: " << cppFunc << endl;

    // ---- C++ 风格二（推荐）：static_cast + 真正的 bool ----
    double cppCast = static_cast<double>(total) / cnt;
    bool isPositive = (total > 0);                   // 类型就是 bool
    cout << "C++ static_cast: " << cppCast
         << "，isPositive = " << boolalpha << isPositive << endl;
    cout << "sizeof(bool)=" << sizeof(isPositive) << "（C 里没有这个类型）\n";
    return 0;
}
// 输出：
// C 风格 printf: 3
// C 里的"真": 1
// C++ 函数式: 3.5
// C++ static_cast: 3.5，isPositive = true
// sizeof(bool)=1（C 里没有这个类型）
```

**⑤ 注意事项**

- **不要在 C++ 代码里混用 `(T)v` 做指针类型互转**：那是在偷偷使用 `reinterpret_cast` 的能力，一旦出错极难定位。数值转换请统一 `static_cast`。
- **不要假设 `char` 有符号**：跨平台代码里凡是要把字节当数值处理，一律显式写 `unsigned char`。
- **不要把 C 的 `if (x = y)` 惯用法当作 C++ 特色**：C++ 有更安全的 `bool` 和更强的警告选项，应该养成 `==` 的习惯。

|--------|------|------|--------|---------|
| `&&` | 逻辑与 | `A && B` | 13 | **A 为 false** 时不求值 B |
| `\|\|` | 逻辑或 | `A \|\| B` | 14 | **A 为 true** 时不求值 B |
| `!` | 逻辑非 | `!A` | 3（R-L） | — |

真值表：`&&` 同真为真；`||` 同假为假；`!1 → 0`，`!0 → 1`。

### 表 5｜类型转换三种写法

# 易错点速查卡（笔记第 5 项 · 四列：错误现象 → 错误原因 → 正确写法 → 后果）

| # | 错误现象 | 错误原因 | 正确写法 | 后果 |
|---|----------|----------|----------|------|
| 1 | `int c = 7/2;` 得到 `3` | 两个操作数都是 `int`，走整数除法，小数被丢弃 | `double c = 7.0/2;` 或 `static_cast<double>(7)/2` | 平均分、比例、百分比全部偏小，且无任何警告 |
| 2 | `double c = 7/2;` 仍得 `3` | 除法已经以 `int` 完成，转换发生在之后 | `static_cast<double>(a) / b` | 变量声明成 `double` 也救不了，误以为"改了类型就好" |
| 3 | `if (flag = 0)` 永远不进分支 | `=` 是赋值，表达式值为 0 → false；同时把 flag 清零 | `if (flag == 0)` | 逻辑反转 **+ 数据被污染**，双重事故最难查 |
| 4 | `if (retry = 1)` 每次都进 | 赋值表达式值为 1 → 非零即真 | `if (retry == 1)` | 死循环、重复扣款、状态被覆盖 |
| 5 | `if (m =! 3)` 竟然能编译 | 被解析为 `m = (!3)`，即 `m = 0` | `if (m != 3)` | 变量被静默清零，条件恒假 |
| 6 | `if (0 < x < 10)` 恒为真 | 先算 `0<x` 得 1/0，再与 10 比较，永远小于 10 | `if (0 < x && x < 10)` | 边界校验完全失效 |
| 7 | `if (x == 0.3)` 判断浮点失败 | `0.1+0.2` 的二进制近似值是 `0.30000000000000004` | `if (fabs(x - 0.3) < 1e-9)` | 偶发的、无法复现的比较失败 |
| 8 | `cout << v1 % v2`（float）编译报错 | `%` 只接受整数操作数 | `fmod(v1, v2)`（`<cmath>`） | 编译中断（好消息：至少不会静默出错） |
| 9 | `-7 % 2` 得 `-1`，用作下标越界 | 取模结果符号跟随左操作数 | `((a % n) + n) % n` | 数组越界写入，破坏相邻内存 |
| 10 | `a > 200 && a++ > 1` 后 `a` 仍是 100 | 左边为假触发短路，右边整段（含副作用）未执行 | 需要副作用时改用 `if` 体或分开写 | 计数器丢失、日志缺失、状态机卡住 |
| 11 | `a < 200 \|\| --a != 1` 后 `a` 仍是 100 | 左边为真触发 `\|\|` 短路 | 同上 | 同上 |
| 12 | `if (b/a > 1 && a != 0)` 崩溃 | 顺序颠倒，危险运算在前，短路来不及保护 | `if (a != 0 && b/a > 1)` | 除零崩溃 / 空指针解引用 |
| 13 | `unsigned a = 0; a - 1` 得 `4294967295` | 无符号运算按模回绕，没有负数 | 改用有符号类型，或先比较大小再相减 | "库存不足"被判成"充足"，超卖 |
| 14 | `if (-1 < 0u)` 判为假 | 有符号与无符号比较，`-1` 被提升为 unsigned | 统一到同一符号性：`static_cast<long long>(-1) < 0LL` | 循环永不退出、越界 |
| 15 | `flags & MASK == 0` 误判 | `&`(第10级) 低于 `==`(第9级) | `(flags & MASK) == 0` | 权限检查形同虚设 |
| 16 | `int r = i++ + i++;` 结果不可预测 | 同一表达式内多次修改同一变量 = 未定义行为 | 拆成多行，一行一件事 | 换编译器/换优化等级就出不同答案 |
| 17 | `char e = 1; cout << e;` 什么都没输出 | 值 1 是不可打印控制字符 | 想看数字就 `cout << (int)e`；想要字符 `'1'` 要写 `1 + '0'` | 误以为程序没执行 |
| 18 | `'5' * 2` 得 `106` | 字符 `'5'` 的 ASCII 是 53 | `('5' - '0') * 2` 得 `10` | 计算结果离谱 |
| 19 | `long long bad = 1000000 * 10000;` 值不对 | 右侧先在 `int` 里溢出，之后才拓宽 | `static_cast<long long>(a) * b` | 金额、统计量悄悄错掉 |
| 20 | `char c = 300;` 变成 `44` | 大类型塞进小盒子，高位被丢弃 | 选够大的类型，或先做范围检查 | 数据损坏且无运行期提示 |
| 21 | `int* p, q;` 里 `q` 不是指针 | 声明符 `*` 只作用于紧邻的名字 | `int *p, *q;` | 编译错误或更糟的类型误解 |
| 22 | `i+++j` 读不懂 | 词法按最长匹配切成 `i++ + j` | 加空格/括号：`(i++) + j` | 可读性灾难，容易引入 UB |
| 23 | `19.99 * 100` 强转整数得 `1998` | double 表示不出精确 1999.0，向零截断 | `llround(price * 100)` 或一开始就用整数分单位 | 金额少一分，账对不平 |
| 24 | `if (find())` 把合法下标 0 当失败 | 返回值 0 隐式转成 false | `if (find() != -1)` | 找到却报"未找到" |

# 常见陷阱专题（笔记第 6 项 · 课件 5 个陷阱，前 3 个为本章最易错）

## 陷阱 1：整数除法的静默截断 ★★★ 最高频

**症状**：没有任何警告，结果就是不对。

```cpp
#include <iostream>
using namespace std;
int main() {
    int total = 95, students = 4;

    // ❌ 错误：平均分永远是整数
    double avgBad = total / students;
    cout << "avgBad = " << avgBad << endl;             // 23，不是 23.75

    // ✅ 修复写法 1：把被除数转成浮点（最推荐）
    double fix1 = static_cast<double>(total) / students;
    cout << "fix1 = " << fix1 << endl;                 // 23.75

    // ✅ 修复写法 2：字面量带小数点
    double fix2 = 1.0 * total / students;
    cout << "fix2 = " << fix2 << endl;                 // 23.75

    // ✅ 修复写法 3：C 风格强转（能跑，不如写法 1 清晰）
    double fix3 = (double)total / students;
    cout << "fix3 = " << fix3 << endl;                 // 23.75

    // ✅ 修复写法 4：让变量本身就是浮点型
    double dt = total, ds = students;
    cout << "fix4 = " << dt / ds << endl;              // 23.75

    // ✅ 修复写法 5：只想要百分比时先乘再除（保住精度）
    int percentBad = total / students * 100;           // 23*100 = 2300（错）
    int percentOk  = total * 100 / students;           // 9500/4 = 2375 ✔
    cout << "percentBad=" << percentBad << " percentOk=" << percentOk << endl;
    return 0;
}
// 输出：
// avgBad = 23
// fix1 = 23.75
// fix2 = 23.75
// fix3 = 23.75
// fix4 = 23.75
// percentBad=2300 percentOk=2375
```

**记忆要点**：**转换必须发生在除法之前**。写法 5 尤其实用——先乘后除能在纯整数域内保住精度（前提是不溢出）。

## 陷阱 2：短路的连锁反应——条件顺序决定生死 ★★★

**症状**：程序在某些输入下崩溃，而这些输入恰好是最需要保护的。

```cpp
#include <iostream>
using namespace std;
int main() {
    int a = 0, b = 10;

    // ✅ 安全：把守卫放左边，a != 0 为 false → 右边的 b/a 根本不执行
    if (a != 0 && b / a > 1) {
        cout << "商大于 1\n";
    } else {
        cout << "安全落地：条件为假，且从未做过除法\n";
    }

    // ❌ 危险：顺序颠倒，短路帮不上忙
    // if (b / a > 1 && a != 0) { }     // 先算 b/a → 整数除零 → 未定义行为，直接崩

    // ✅ 复合场景：三层守卫必须由外到内排列
    int* data = nullptr;
    int len = 0;
    if (data != nullptr && len > 0 && data[0] > 0) {
        cout << "不会进入\n";
    } else {
        cout << "三层守卫层层把关，最危险的解引用排在最后\n";
    }

    // ⚠️ 反面教材：不该被短路的副作用被短路了
    int saved = 0;
    bool dirty = false;
    dirty && (saved++, true);            // saved 保持 0
    cout << "saved = " << saved << "（本应保存一次却没执行）\n";
    if (dirty) { ++saved; }              // ✅ 改写
    cout << "改成 if 后 saved = " << saved << endl;
    return 0;
}
// 输出：
// 安全落地：条件为假，且从未做过除法
// 三层守卫层层把关，最危险的解引用排在最后
// saved = 0（本应保存一次却没执行）
// 改成 if 后 saved = 0
```

**规则**：**从左到右按"风险从低到高"排列条件**——先判空/判零/判范围，再判内容，最后才做运算和解引用。

## 陷阱 3：浮点数用 `==` 比较 ★★★（课件未涉及，但实际开发最常见）

**症状**：`0.1 + 0.2 == 0.3` 竟然是 `false`。

```cpp
#include <cmath>       // fabs
#include <iostream>
using namespace std;

int main() {
    double a = 0.1 + 0.2;
    cout.precision(20);
    cout << "0.1 + 0.2 的真实值 = " << a << endl;      // 0.30000000000000004
    cout.unsetf(ios::floatfield);
    cout.precision(6);

    // ❌ 错误示范：直接用 == 判断浮点相等
    if (a == 0.3) cout << "相等\n"; else cout << "❌ 不相等！明明应该相等\n";

    // ✅ 正确写法一：误差范围比较（绝对误差）
    const double EPS = 1e-9;
    if (fabs(a - 0.3) < EPS) cout << "✅ 在误差范围内相等\n";

    // ✅ 正确写法二：相对误差（数值可能很大或很小时更稳）
    double x = 1e10, y = 1e10 + 1.0;
    bool nearRel = fabs(x - y) <= EPS * fmax(fabs(x), fabs(y));
    cout << boolalpha << "相对误差判断 x≈y : " << nearRel << endl;

    // ✅ 正确写法三：金额一律用整数最小单位（分）存储
    long long centsX = 10, centsY = 20;               // 0.10 元 = 10 分
    cout << noboolalpha << "分为单位 10+20 == 30 : " << ((centsX + centsY) == 30) << endl;
    return 0;
}
// 输出：
// 0.1 + 0.2 的真实值 = 0.30000000000000004441
// ❌ 不相等！明明应该相等
// ✅ 在误差范围内相等
// 相对误差判断 x≈y : true
// 分为单位 10+20 == 30 : 1
```

**规则**：**浮点数永远不要用 `==` 判等**；金额不要存在 `float/double` 里。

## 陷阱 4：自增自减与其他运算混搭 ★★

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 歧义 1：i+++j —— 编译器按"最长匹配"切分成 (i++) + j
    int i = 1, j = 2;
    cout << "i+++j 其实是 (i++) + j = " << (i++ + j)
         << " ，此后 i = " << i << endl;      // 3，i 变 2

    // ❌ 歧义 2：a[i++] —— i 到底什么时候递增？
    int arr[3] = {10, 20, 30};
    int k = 0;
    int got = arr[k++];                        // 取 arr[0]=10，然后 k 变 1
    cout << "got = " << got << " k = " << k << endl;

    // ❌ 真正的炸弹：同一变量在一行里既读又写多次
    int m = 1;
    // int boom = m++ + ++m + m;               // 未定义行为，禁止

    // ✅ 铁律：一行只做一件事
    int m2 = 1;
    int p = m2++;                              // 1，m2 → 2
    int q = ++m2;                              // 3，m2 → 3
    int safe = p + q + m2;                     // 1+3+3 = 7
    cout << "safe = " << safe << endl;
    return 0;
}
// 输出：
// i+++j 其实是 (i++) + j = 3 ，此后 i = 2
// got = 10 k = 1
// safe = 7
```

**铁律**：**每一行最多让一个变量发生一次修改。** 需要多个动作就换行。

## 陷阱 5：`unsigned` 类型的回绕 ★★

```cpp
#include <iostream>
using namespace std;
int main() {
    // ❌ 回绕 1：零减负数
    unsigned int u = 0;
    cout << "u - 1 = " << (u - 1) << endl;          // 4294967295，不是 -1

    // ❌ 回绕 2：与有符号混合运算时的隐式提升
    int si = -1;
    cout << "(u > si) = " << (u > si)
         << "  因为 si 被提升成了 4294967295\n";      // 1（true）

    // ❌ 回绕 3：经典 size 反向循环死循环
    // for (unsigned int n = vec.size(); n >= 0; --n) { }   // n 永远 >= 0，死循环
    // ✅ 正确写法：用 > 0 并先处理空容器，或干脆用有符号/迭代器
    int data[4] = {1, 2, 3, 4};
    int count = 4;
    for (int n = count - 1; n >= 0; --n) { /* 倒序安全 */ }
    cout << "倒序循环安全走完，count = " << count << endl;

    // ✅ 正确写法：混合运算前统一符号性
    cout << "static_cast<long long>(si) < static_cast<long long>(u) = "
         << (static_cast<long long>(si) < static_cast<long long>(u)) << endl;   // 1
    return 0;
}
// 输出：
// u - 1 = 4294967295
// (u > si) = 1  因为 si 被提升成了 4294967295
// 倒序循环安全走完，count = 4
// static_cast<long long>(si) < static_cast<long long>(u) = 1
```

**建议**：除非确实在做位掩码或明确需要回绕语义，**初学阶段一律使用 `int`**；容器长度比较时显式转成 `size_t` 或用 `auto` 迭代器（后续章节展开）。

# 新手最常问的 5 个问题（笔记第 7 项）

### Q1：我把结果声明成 `double` 了，为什么 `7/2` 还是等于 3？

**答**：因为类型声明管不到已经算完的结果。表达式的类型由**操作数**决定，不由接收它的变量决定。求值顺序是：

```
① 先看 a / b 两个操作数的类型 → 都是 int → 执行整数除法 → 得到 int 的 3
② 再把 3 赋给 double 型变量 → 变成 3.0
```

你要做的是在**第 ① 步之前**就把某个操作数变成浮点：`static_cast<double>(a) / b`。**记住口诀："转换要趁早，赋值已经晚。"**

### Q2：`a++` 和 `++a` 到底选哪个？我看老师两种都写了。

**答**：分三种情况——

| 场景 | 建议 | 理由 |
|------|------|------|
| 单独一句（`i++;`） | 两种都行，团队里统一即可 | 效果完全相同 |
| `for` 循环第三段 | 写 `++i` | 对 `int` 无差别；对迭代器等类类型前缀省一次拷贝，习惯统一最省心 |
| 与其他运算符混在一行 | **禁止**，拆成两行 | 会踩未定义行为 |

一句话：**别纠结选哪个，纠结"别把它们混进复杂表达式"。**

### Q3：优先级表有 18 级，我要背下来吗？考试会考默写吗？

**答**：**不背全表**，课件 P15 自己也只把它标为"熟悉"。你只需要记三样东西：

1. **七层金字塔**（算术 > 比较 > 逻辑 > 赋值），见 3.1；
2. **三个反直觉点**：`<<` 高于 `<`、`==` 高于 `&`、`&&` 高于 `||`；
3. **只有两类右结合**：一元前缀（第3级）、赋值与三元（第15级）。

其余一律**加括号**。课件原话就是答案："如果不确定，或者运算符太多，就按照自己的思路用括号隔开。"

### Q4：`(int)x`、`int(x)`、`static_cast<int>(x)` 三种写法到底有什么区别？我该用哪个？

**答**：**数值转换时三者结果完全一样，生成的机器码也一样**。区别只在**安全性与可读性**：

- `(int)x` 和 `int(x)` 属于"万能转换"，它还允许你把指针乱转、把 `const` 去掉——这些是最容易写出恶性 bug 的地方；
- `static_cast<int>(x)` 会**拒绝**明显荒谬的转换，而且能在代码里一眼搜到。

结论：**自己写代码一律用 `static_cast`；读老代码时认识前两种。**

### Q5：既然 `%` 和 `/` 都会截断，为什么不干脆规定整数除法必须返回小数？

**答**：因为 `int` 类型的定义本身就**不包含小数位**——硬件的整数除法指令只能给出商和余数两个整数。语言的取舍是：

- `/` 给商，`%` 给余数，两者配对使用；
- 需要小数就换 `float/double` 类型，代价是精度限制（连 0.1 都表示不准，见陷阱 3）和更大的内存占用。

所以这不是"设计缺陷"，而是**类型系统的分工**。理解这一点，你就明白为什么"平均分"这类计算必须显式转浮点。

### 补充追问（课堂真实提问 Top 2）

**Q：`bool` 占几个字节？** A：实测 GCC/MSVC 64 位下 `sizeof(bool) == 1`。但标准只规定它能表示 true/false，并未强制 1 字节，别把这个数字当规范去考别人。

**Q：`char` 到底是数字还是字符？** A：它**就是数字**，只是打印时被翻译成对应 ASCII 字符。`cout << 'A'` 输出 `A`，`cout << (int)'A'` 输出 `65`，同一个字节两种解释。

# 面试高频考点与标准答题思路（提示词【课件类型专项补充】第 1 条）

> 提示词点名的四道题全部来自本章，其中**短路特性几乎是必考题**。每题给出"关键词 + 答题骨架"，照此组织语言即可。

## 题 1：整数除法 `7/2` 的结果是什么？如何得到 `3.5`？

**关键词**：操作数类型决定运算方式 · 向零取整 · 截断发生在赋值之前 · 至少一个操作数为浮点

**标准答法（四句话）**：
1. `7/2` 的结果是 **3**。因为两个操作数都是 `int`，走的是整数除法，小数部分被**向零截断**丢弃，且不会有任何警告。
2. 特别注意 `double r = 7/2;` 仍然是 **3.0**——除法已经以整数完成，赋值时的类型转换救不回来。
3. 想得到 3.5，必须让**除法发生时**至少有一个操作数是浮点：`7.0/2`、`7/2.0`、`(double)7/2`、`static_cast<double>(7)/2`。
4. 工程上我首选 `static_cast<double>(a) / b`，因为它语义明确、可搜索，也是 C++ 代码规范的推荐写法。

**加分回答**：若只要百分比又希望留在整数域，可以**先乘后除**：`total * 100 / students` 比 `total / students * 100` 精确得多（前提是乘法不溢出）。

## 题 2：解释逻辑运算符的短路特性并举例。

**关键词**：左已定结果 · 右操作数不求值 · 副作用消失 · 守卫条件放左边

**标准答法（五步骨架）**：
1. **定义**：`&&` 在左操作数为 false 时、`||` 在左操作数为 true 时，整个结果已经确定，标准规定**右操作数不再求值**，这就是短路求值（short-circuit evaluation）。
2. **方向记忆**：`&&` 怕左假，`||` 怕左真。
3. **举例（课件原题）**：`int a = 100; a > 200 && a++ > 1;` 之后 **`a` 仍是 100**，因为 `100 > 200` 为 false 触发短路，`a++` 这个副作用根本没执行。对称的例子 `int a = 100; a < 200 || --a != 1;` 之后 `a` 也仍是 100。
4. **正面用途**：用它做守卫——`if (ptr != nullptr && *ptr > 0)`、`if (divisor != 0 && dividend / divisor > 1)`，把危险运算放在右边就不会执行。
5. **反面风险**：绝不要把必须执行的副作用写在右边；也不要颠倒顺序写成 `if (*ptr > 0 && ptr != nullptr)`，那样短路救不了你。

## 题 3：`static_cast` 和 C 风格强制转换有什么区别？

**关键词**：语义单一 vs 语义混合 · 编译期检查强度 · 可搜索 · 拒绝危险转换

**标准答法**：

| 维度 | `(T)v` C 风格 | `static_cast<T>(v)` |
|------|---------------|---------------------|
| 实际尝试的转换种类 | 依次尝试 `const_cast` → `static_cast` → `reinterpret_cast`，**三种混在一起** | **只做一类**：静态可确定的数值转换与类层次转换 |
| 能否去掉 `const` | **能**（悄悄进行，危险） | **不能**，必须显式写 `const_cast` |
| 无关指针互转 | **允许** | **拒绝**，编译报错 |
| Code Review / grep 友好度 | 差（和普通括号无法区分） | 好（一眼可见、可全文检索） |
| 出错定位 | 难 | 易 |

一句话总结：**C 风格转换给了你不该有的能力，`static_cast` 只给你需要的能力**——能力越小越安全。补充说明：对于纯数值转换（如 `int`→`double`）两者生成的机器码完全相同，差异纯粹体现在**编译期检查与可读性**上。

## 题 4：`3 + 4 * 5` 的值是多少？`(3 + 4) * 5` 呢？

**标准答法**：
- `3 + 4 * 5` = **23**。`*` 在第 5 级、`+` 在第 6 级，数字小者优先，所以先算 `4 * 5 = 20`，再 `3 + 20 = 23`。
- `(3 + 4) * 5` = **35**。括号凌驾于优先级表之上，强制先算 `3 + 4 = 7`。
- 延伸（本题真正的杀器）：`3 + 4 * 5 % 2 - 1` = **2**。步骤：`4 * 5 = 20` → `20 % 2 = 0` → `3 + 0 - 1 = 2`。这里体现了第 5 级的 `* / %` **同为一级、从左至右**结合。

**加分回答**：正因为要心算两级同级还要考虑结合性，我在工程代码里会给 `* / %` 混排处直接加括号——课件的原则是"正确性 > 可读性 > 简洁性"。

## 附加常考：`++i` 和 `i++` 的区别？（课件 P16 作业原题）

**标准答法**：
1. **相同点**：都让变量自身加 1；**单独成句时效果完全等价**。
2. **不同点**：`++i`（前缀）**先自增，表达式的值是新值**；`i++`（后缀）**先取旧值作为表达式的值，再自增**。
3. **代码演示**：`int a = 5; int x = a++; // x=5, a=6` 对比 `int b = 5; int y = ++b; // y=6, b=6`。
4. **实现代价**：后缀必须先保存一份旧值副本才能返回，因此对类类型（如 STL 迭代器）后缀比前缀多一次拷贝构造；对 `int` 在现代编译器优化下无差别。
5. **纪律**：绝不把 `++` 与其他运算混在同一表达式（`i++ + i++` 属未定义行为）。

## 二、运算符重载预告

C++ 允许你为自定义类重新定义 `+`、`==`、`<<` 等内置运算符的行为，这是 C++ 区别于 C 的核心特性之一：

```cpp
#include <iostream>
using namespace std;

struct Money {                       // 最简单的自定义类型
    long long cents;                 // 用"分"存钱，避免浮点误差
    Money(long long c = 0) : cents(c) {}
    Money operator+(const Money& o) const { return Money(cents + o.cents); }   // 重载 +
    bool operator==(const Money& o) const { return cents == o.cents; }          // 重载 ==
};

int main() {
    Money a(1999), b(5001);
    Money sum = a + b;               // 看起来是加法，其实调用了 operator+
    cout << "sum = " << sum.cents << " 分\n";        // 7000
    cout << boolalpha << "(a == b) = " << (a == b) << endl;   // false
    return 0;
}
// 输出：
// sum = 7000 分
// (a == b) = false
```

**关键认知**：本章学的**内置运算符行为是理解重载的前提**——你必须先知道 `/` 默认会截断、`==` 默认按成员比较，才能理解"重载改变了什么"。深入内容在第19章面向对象编程。

## 三、位运算预告（课件本章未涉及，务必自行补齐）

本章课件**没有讲**位运算符，但你的教材体系第 17 章专门安排了它们。它们与逻辑运算符长得极像，最容易混淆：

| 位运算符 | 名称 | 逻辑对应 | 核心差别 |
|----------|------|----------|----------|
| `&` | 按位与 | `&&` | 逐比特操作，**无短路**；`2 & 4` = 0 |
| `|` | 按位或 | `\|\|` | 逐比特操作，**无短路**；`2 | 4` = 6 |
| `^` | 按位异或 | — | 相同为 0，不同为 1 |
| `~` | 按位取反 | `!` | `~5` = -6，而 `!5` = 0 |
| `<<` `>>` | 左移/右移 | — | 乘除 2 的幂；优先级还高于 `<`（本章已埋雷） |

**典型用途**：权限掩码（`flags & READABLE`）、快速乘除 2 的幂、加密哈希、嵌入式寄存器配置。**建议学完本章后立即安排补课。**

> 现在你就能体会优先级表里那条"`&` 低于 `==`"有多阴险：`flags & MASK == 0` 少写括号就是一个静默的逻辑错误。这也是本笔记反复强调"位运算一律加括号"的原因。

## 第 2 题（★★）逻辑运算符短路

```cpp
#include <iostream>
using namespace std;
int main() {
    int a = 100;
    a > 200 && a++ > 1;
    cout << a << endl;      // 输出：________

    int b = 100;
    b < 200 || --b != 1;
    cout << b << endl;      // 输出：________

    int c = 100;
    c > 50 && c++ > 1;
    cout << c << endl;      // 输出：________
    return 0;
}
```

**问题**：
1. 三个输出分别是什么？________、________、________
2. 解释 `if (a != 0 && b / a > 1)` 中短路如何避免除零错误。
3. 若把条件写成 `if (b / a > 1 && a != 0)` 会发生什么？为什么？

<details><summary>参考答案（做完再看）</summary>

1. `100`、`100`、`101`。前两例都因短路使右侧自增/自减未执行；第三例左侧为真故右侧执行。
2. 当 `a != 0` 为 false 时，`&&` 触发短路，`b / a` **根本不会被求值**，因此不会发生除零。
3. 会崩溃：`b / a` 排在左边，必须先算，此时 `a == 0` 导致整数除零 —— 属未定义行为，实际表现为程序异常终止（Windows 下 `0xC0000094`，Linux 下 `SIGFPE`）。右边的 `a != 0` 虽然正确却已来不及救命。

</details>

## 第 3 题（★★★）优先级与结合性

计算下列表达式的值，并在括号里注明每一步用到的优先级级别：

```
① 3 + 4 * 5 % 2 - 1 = ________
   步骤：____________________________________________

② 10 - 3 * 2 < 5 ? 1 : 2 = ________
   步骤：____________________________________________

③ int x = 0; x = 3 == 3; 则 x = ________
   步骤：____________________________________________

④ flags = 0x06; (flags & 0x02) == 0 的值 = ________；flags & 0x02 == 0 的值 = ________
   差异原因：______________________________________
```

<details><summary>参考答案（做完再看）</summary>

① **2**。`*`(5级) → `4*5=20`；`%`(5级，同级左结合) → `20%2=0`；`+`(6级) → `3+0=3`；`-`(6级) → `3-1=2`。
② **1**。`*` → 6；`-` → `10-6=4`；`<`(8级) → `4<5` 为 true；`? :`(15级) → 取第一分支 `1`。
③ **1**。`==`(9级) 高于 `=`(15级)，先算 `3==3` 得 true，再赋给 `int x` → 隐式转换为 1。
④ **两个表达式的值都是 `0`，但成因完全不同——这正是它阴险的地方。**
   - `(flags & 0x02) == 0`：先算 `0x06 & 0x02 = 0x02`（非零），再判 `== 0` → **false（0）**。这是**正确**的"没有该标志位"检查。
   - `flags & 0x02 == 0`：因 `&`(10级) **低于** `==`(9级)，被解析为 `flags & (0x02 == 0)` = `0x06 & 0` = **0**。数值上恰好也是 0，**纯属巧合**。
   - 差异原因：少了括号就换了算法。**放进 `if` 里两者行为直接相反**：`if ((flags & 0x02) == 0)` 不进入分支（正确地判定"标志位已设置"）；而 `if (flags & 0x02 == 0)` 会走进分支（错误地以为"标志位未设置"）。所以结论是：**位运算必须加括号。**

</details>

## 第 4 题（★★★★）综合编程题

**需求**：写一个完整程序，从键盘输入两个整数 `m` 和 `n`，输出：

1. 和、差、积；
2. 商与余数（**必须正确处理 `n == 0` 的情况**，此时输出提示而不是崩溃）；
3. 平均值（保留小数，不能出现整数截断）；
4. 两数的大小关系（`>`、`<`、`==` 三种情况分别输出不同文字）；
5. 在代码注释中标出每个运算符所属的优先级级别（对照课件 P9/P10 表）。

**评分要点（自查）**：

- [ ] 用了 `cin` 读取且做了输入合法性考虑
- [ ] 除法前用 `&&` 短路保护了除数为 0
- [ ] 平均值使用了 `static_cast<double>` 且在除法之前
- [ ] 所有比较都用了 `==`，条件里没有一处 `=`
- [ ] 复合表达式全部加了括号
- [ ] 能同时在 MSVC 与 GCC 下编译通过

<details><summary>参考实现（做完再看）</summary>

```cpp
#include <iostream>
using namespace std;

int main() {
    int m = 0, n = 0;
    cout << "请输入两个整数：";
    cin >> m >> n;

    cout << "和 = " << m + n << endl;                 // + : 6级 L-R
    cout << "差 = " << m - n << endl;                 // - : 6级 L-R
    cout << "积 = " << m * n << endl;                 // * : 5级 L-R

    if (n != 0 && m / n != 0) {                       // != :9级, / :5级, && :13级
        cout << "商 = " << m / n << endl;
    } else if (n != 0) {
        cout << "商 = 0（整数除法截断）" << endl;
    } else {
        cout << "除数不能为 0\n";
    }

    if (n != 0) {
        cout << "余 = " << m % n << endl;             // % : 5级
        double avg = static_cast<double>(m) / n;      // 先转再除，避免截断
        cout << "平均 = " << avg << endl;
    } else {
        cout << "余数与平均值需要非零除数\n";
    }

    if (m > n) {                                      // > : 8级
        cout << m << " 大于 " << n << endl;
    } else if (m < n) {                               // < : 8级
        cout << m << " 小于 " << n << endl;
    } else {                                          // 前面都不成立即为相等
        cout << m << " 等于 " << n << endl;
    }
    return 0;
}
// 输入示例：7 2
// 输出：
// 请输入两个整数：7 2
// 和 = 9
// 差 = 5
// 积 = 14
// 商 = 3
// 余 = 1
// 平均 = 3.5
// 7 大于 2
//
// 输入示例：5 0
// 输出：
// 请输入两个整数：和 = 5
// 差 = 5
// 积 = 0
// 除数不能为 0
// 余数与平均值需要非零除数
// 5 大于 0
```

</details>

## 第 5 题（代码审查题）参考答案 —— 做完再看

<details><summary>展开查看 5 处 bug 的定位与修复</summary>

**Bug A —— 整数除法截断 + 优先级双重问题**

```cpp
// ❌ 现状：double avg = score[0] + score[1] + score[2] / count;
// 问题：先算 score[2]/count → 78/3 = 26（恰好整除侥幸没露馅，换成 4 人就错）
//      而且整体是整数加法，最后才转 double
// ✅ 修正：
double avg = (score[0] + score[1] + score[2]) / static_cast<double>(count);
// 现在 = 253 / 3.0 = 84.3333
```

**Bug B —— `=` 与 `==` 混淆（同时破坏了数据）**

```cpp
// ❌ 现状：if (score[i] = passLine)  → 把 60 写进数组，且条件恒真
// ✅ 修正：
if (score[i] >= passLine) { cout << score[i] << " 及格\n"; }
```

**Bug C —— 短路顺序颠倒**

```cpp
// ❌ 现状：if (score[i] > avg && avg != 0)
// 这里恰好不会崩（比较不危险），但语义错了：应先确认 avg 有效再比较
// ✅ 修正（守卫前置，符合"P13 三层守卫"规范）：
if (avg != 0 && score[i] > avg) { above++; }
```

**Bug D —— unsigned 回绕**

```cpp
// ❌ 现状：unsigned int idx = 0; idx = idx - 1;  → idx = 4294967295
//      再用 idx % count → 4294967295 % 3 = 0，于是读到 score[0]=85；
//      期望的"往前退一格"应是最后一格 score[2]=78。数值看似合理，实为掩盖 bug
// ✅ 修正：改用有符号类型
int idx = 0;
idx = idx - 1;                          // -1
int safe = ((idx % count) + count) % count;   // 2 ✔
cout << score[safe] << endl;            // 输出 78
```

**Bug E —— 同一变量在一行内多次修改（未定义行为）**

```cpp
// ❌ 现状：total = total++ + total++;   → UB，换编译器结果不同
// ✅ 修正：
total = total + 1 + 1;                  // 或者明确写出两步
int first = total++;
int second = total++;
total = first + second;
```

**审查小结**：5 处 bug 分别对应本章 5 个重点——整数除法(A)、`=`/`==`(B)、短路顺序(C)、unsigned 回绕(D)、自增混搭(E)。能把这五个一次找齐，说明本章掌握达标。

</details>

提示词要求附带一段可运行的 Python 代码用于自动创建文件夹并保存笔记。由于本笔记已由工具直接写入上述路径，下面的脚本用于**在新机器上重建同样的目录结构**（若目标文件已存在则不覆盖，改名加 `_copy` 后缀）：

```python
# save_ch5_notes.py —— 创建第5章笔记目录结构（幂等，不覆盖已有笔记）
import shutil
from pathlib import Path

BASE = Path(r"C:\Users\freecss\Desktop\学习1\C++\C++基础篇\5 运算符与表达式")
NOTE_NAME = "运算符与表达式学习笔记.md"

def main():
    BASE.mkdir(parents=True, exist_ok=True)          # 需要时创建多级目录
    (BASE / "课件").mkdir(exist_ok=True)             # PDF 所在子目录
    (BASE / "资源").mkdir(exist_ok=True)             # 课堂代码所在子目录

    target = BASE / NOTE_NAME
    if target.exists():
        print(f"[跳过] 笔记已存在：{target}")
        print("       如需另存副本，请把 NOTE_NAME 改成带 _copy 的文件名。")
        return

    src = Path(__file__).resolve().parent / NOTE_NAME
    if src.exists() and src != target.resolve():
        shutil.copy2(src, target)
        print(f"[完成] 已从 {src} 复制到 {target}")
    else:
        target.write_text(
            "# 第5章 运算符与表达式 学习笔记\n\n（正文请从原仓库同步）\n",
            encoding="utf-8",
        )
        print(f"[提示] 未找到源文件，已在 {target} 创建占位笔记。")

if __name__ == "__main__":
    main()
```

> 运行方式：`python save_ch5_notes.py`（Windows 路径已使用原始字符串 `r"..."`，无需转义反斜杠）。
