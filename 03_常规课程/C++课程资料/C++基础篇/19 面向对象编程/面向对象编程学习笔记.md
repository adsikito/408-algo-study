# 第一部分　八模块完整讲解（黄金四步法）

## 模块一　面向对象概述、类与对象（19.1 第3-12页）

### 1. 面向对象和面向过程的区别（第3-6页）【了解】

**① 是什么**：面向过程 = 分析出解决问题的步骤，一步步实现（自顶向下编程）；面向对象 = 把问题拆成各个对象，用对象的行为解决问题（高度实物抽象化编程）。

**② 为什么**：两种思维解决同一问题——"番茄炒鸡蛋"：
- 面向过程：买番茄鸡蛋 → 洗番茄 → 搅鸡蛋 → 生火 → 炒菜 → 出锅（每步亲力亲为）
- 面向对象：告诉厨师"来份番茄炒蛋" → 厨师（对象）完成一切 → 出锅

**③ 怎么用/优缺点对比**：

| 对比项 | 面向过程 | 面向对象 |
|---|---|---|
| 思路 | 自顶向下按步骤 | 抽象出对象，靠对象行为 |
| 性能 | **高**（无类实例化开销） | 略低（实例化有开销） |
| 维护/复用/扩展 | 差 | **好**（封装、继承、多态解耦） |
| 典型应用 | Linux/Unix 内核等追求性能的场景 | 大型软件、游戏、框架 |
| 代表语言 | C | C++、Java、Python |

**④ 注意**：面向对象不是万能药，性能敏感的底层开发仍常用面向过程；两者经常混用。

**人话总结**：过程论亲手干，对象论找对人。

### 2. 类与对象的基本概念（第7-8页）【了解】

**① 是什么**：类 = 具有相同属性（数据）和行为（功能）的对象的抽象；对象 = 类的具体化（实例）。
**② 为什么**：类相当于**图纸/模具**，对象相当于按图纸造出来的**实物**。一张图纸能造无数实物——一个类能创建无数对象。
**③ 怎么用**：类本质上是一种**自定义数据类型**，对象就是该类型的**变量**。`Student` 是类型，`s1` 是变量。
**④ 注意**：类只是抽象描述，本身不占对象那份内存；实例化后每个对象有自己独立的成员变量。

**人话总结**：类是图纸，对象是房子。

### 3. 类的定义（第9-10页）【熟悉】

**① 是什么**：用 `class` 关键字定义的自定义类型，把数据和操作数据的函数打包在一起。
**② 为什么**：C 的 struct 只装数据，函数在外面"裸奔"；class 把"属性+行为"封装成一个整体，这是封装的基础。

**③ 怎么用**（对应 code1.cpp 中被注释的 `class Student`）：

```cpp
class Student {          // class 关键字 + 类名（首字母一般大写）
public:                  // 访问限定符后面是冒号 :
    void printName(string name) {   // 成员函数（行为）
        cout << name << endl;
    }
    string name;         // 成员变量（属性）
    int age;
};                       // 别忘了最后的分号！
```

**④ 注意**：
- 类定义末尾的 `;` 忘写是新手第一大编译错误；
- 类名首字母大写是约定俗成（`Student` 而非 `student`）；
- 不写访问限定符时，class 成员默认 private（struct 默认 public）。

**人话总结**：class 打包数据和行为，末尾分号。

### 4. 类对象（实例化）（第11-12页）【熟悉】

**① 是什么**：用类创建对象的过程叫**实例化**。
**② 为什么**：类是图纸不能直接用，必须造出对象才能存储数据、调用行为。
**③ 怎么用**（对应 code1.cpp 活动代码 `Rect r1(100,100);`）：

```cpp
Rect r1(100, 100);   // 类名 对象名(参数); 实例化一个Rect对象
r1.area();           // 通过 "对象.成员" 访问成员函数
```

**④ 注意**：访问成员用 `对象.成员`；通过指针访问用 `指针->成员`（等价于 `(*指针).成员`）。

**人话总结**：类造对象，点号取成员。

## 模块二　构造函数、析构函数、拷贝构造（19.1 第13-24页）

### 5. 构造函数（第13-17页）【重点】

**① 是什么**：与类同名、无返回值的特殊成员函数，**创建对象时自动调用**，用于初始化成员变量。
**② 为什么**：对象一出生就应该有合法的初始值，靠手动调用初始化函数容易忘记（C 语言 malloc 的痛点）；构造函数由编译器强制自动调用，杜绝"用未初始化对象"。

**③ 怎么用**（对应 code1.cpp 被注释的 Student 构造函数）：

```cpp
class Student {
public:
    Student() {                       // 无参构造（默认构造函数）
        cout << "Student mm" << endl;
    }
    Student(string name, int age) {   // 有参构造——构造函数支持重载
        this->name = name;            // this-> 区分成员与参数
        this->age = age;
        cout << "Student method" << endl;
    }
    string name;
    int age;
};
```

运行 `Student s1;` 输出 `Student mm`；`Student s2("zs", 21);` 输出 `Student method`。

**④ 注意**：
- 不写任何构造函数时，编译器自动生成一个**默认构造函数**（什么都不做）；
- 一旦自己写了有参构造，编译器**不再**提供默认构造函数，此时 `Student s1;` 会编译报错（code1.cpp 中 `Student stu(20)` 被注释就是因为当前活动代码没配默认构造，`Student s1(30)` 也是单参数不匹配问题）；
- 构造函数支持**重载**和**默认参数**（如 `printName(string name = "赵六")`）；
- 构造函数不能是虚函数（见模块八）。

**人话总结**：对象出生自动跑，初始化全靠它。

### 6. 拷贝构造函数（第18-21页）【重点】

**① 是什么**：用**一个已存在的同类型对象**初始化新对象时调用的构造函数。语法：`类名(const 类名& 对象)`。
**② 为什么**：很多场景需要"复制"对象（备份、传参、返回），默认的逐字节复制对含指针的类是危险的（浅拷贝问题，见专题一）。

**③ 怎么用**（对应 code1.cpp 被注释的 Complex 拷贝构造）：

```cpp
class Complex {
public:
    double m_real, m_imag;
    Complex(double real, double imag) { m_real = real; m_imag = imag; }
    Complex(const Complex& c) {        // 自定义拷贝构造
        m_real = c.m_real;
        m_imag = c.m_imag;
        cout << "我的调用了" << endl;
    }
};
// main 中：
Complex c1(1, 2);
Complex c2 = c1;      // 等价于 Complex c2(c1); 调用拷贝构造
cout << c2.m_real << "  " << c2.m_imag << endl;
```

实际运行输出：`我的调用了` 换行 `1  2`——证明 `Complex c2 = c1;` 走的是拷贝构造而不是赋值。

**拷贝构造的 3 种调用场景**：
1. 用对象初始化新对象：`Complex c2(c1);` 或 `Complex c2 = c1;`
2. 对象作为函数**参数**传递（按值传参时实参复制给形参）；
3. 对象作为函数**返回值**（按值返回时复制一份临时对象）。

**④ 注意**：
- 不写时编译器自动生成**默认拷贝构造函数**（逐个字节复制 = 浅拷贝）；写了自定义版本，默认版本就不存在了；
- 参数必须是**引用**：若是传值 `Complex(Complex c)`，传值又要调用拷贝构造，无限递归，编译报错；
- 建议参数加 `const`，常量对象和非常量对象都能作为源。

**人话总结**：拿旧对象造新对象，参数必须引用。

### 7. 析构函数（第22-24页）【重点】

**① 是什么**：类名前加 `~` 的特殊成员函数，**对象销毁时自动调用**，做清理工作（释放内存、关文件等）。
**② 为什么**：构造时申请的资源（堆内存、文件句柄）必须有人归还，析构函数保证"临死前"自动清理，防止资源泄漏。

**③ 怎么用**（对应 code1.cpp 被注释的 `~Student()`）：

```cpp
class Student {
public:
    ~Student() {                      // 析构函数：~类名
        cout << "call ~ Student()" << endl;
    }
};
// 对象离开作用域时自动输出 call ~ Student()
```

**④ 注意**：
- 析构**没有参数、不能重载**，一个类只能有一个析构函数；
- 没写时编译器自动生成默认析构（什么都不做）；
- 栈对象在离开作用域时析构，new 出来的堆对象在 delete 时析构；
- 析构顺序与构造顺序**相反**（先构造的后析构）。

**人话总结**：对象临终遗言，自动清场不花钱。

## 模块三　动态创建对象、对象数组、成员（19.1 第25-39页）

### 8. 动态创建对象 new/delete（第25-31页）【重点】

**① 是什么**：`new` 在**堆**上分配内存并调用构造函数；`delete` 调用析构函数并释放内存。
**② 为什么**：栈对象出了作用域就死，生命周期不受控；堆对象由程序员掌控生死。C 语言的 malloc 只分内存**不调构造**、free 只释放**不调析构**，还要手动算大小、强转、判空，极易出错；new 把"分配+初始化"合成一步，保证了"内存分配成功才构造"。

**③ 怎么用**（对应 code1.cpp 被注释的 `Person* p1 = new Person;`）：

```cpp
Person* p1 = new Person;   // 分配内存 + 自动调用Person()
delete p1;                 // 自动调用~Person() + 释放内存
p1 = NULL;                 // 建议delete后置空，防止野指针/重复delete
```

实测输出：`call Person()` 换行 `call ~Person()`。

**new vs malloc/free 对比**：

| 对比项 | new/delete | malloc/free |
|---|---|---|
| 所属 | C++ 运算符 | C 库函数 |
| 构造/析构 | **自动调用** | 不调用 |
| 内存大小 | 自动计算 | 手动 sizeof |
| 返回类型 | 具体类型指针 | void*，需强转 |
| 失败处理 | 抛异常 | 返回 NULL 需判断 |

**④ 注意**：
- delete 只能释放 new 出来的内存，与 malloc/free 混用是未定义行为；
- delete NULL 指针是安全的（什么都不发生）；
- 同一块内存 delete 两次会崩，所以 delete 后立即置 NULL。

**人话总结**：new 生娃又起名，delete 送葬又拆房。

### 9. 动态创建对象数组（第32-34页）【重点】

**① 是什么**：`new 类名[长度]` 在堆上一次创建多个对象。
**② 为什么**：对象个数在运行期才能确定时（比如班级人数），需要堆上动态建数组。

**③ 怎么用**（对应 code1.cpp 被注释的 `Student* pstu = new Student[10];`）：

```cpp
Student* pstu = new Student[10];  // 必须有默认构造函数！
delete[] pstu;                    // 数组必须用 delete[] 释放
```

实测输出：`Student mm` × 10（10 次构造），然后 `call ~ Student()` × 10（10 次析构）。

**④ 注意**：
- 堆上建对象数组**必须提供无参（默认）构造函数**——编译器没法给 10 个对象逐个传不同参数；栈上聚合初始化 `Student stu[] = {{"zs",20},{"ww",19}}` 则可以用有参构造；
- 释放必须用 `delete[]`，用 `delete` 只析构第一个，行为未定义；
- 普通数组也可 new：`int* p = new int[10]{1,2,3,4,5};`（C++11 支持初始化列表）。

**人话总结**：堆上建队要默认构造，拆队要用中括号。

### 10. 成员变量与成员函数（第35-39页）【重点】

**① 是什么**：类内定义的变量叫成员变量（描述状态），类内定义的函数叫成员函数（描述行为）。
**② 为什么**：封装的体现——数据和对数据的操作绑在同一个对象上，通过 `对象.成员` 访问。
**③ 怎么用**（对应 code1.cpp 被注释的 printName 重载）：

```cpp
s1.printName();                    // 用默认参数，输出: printNam() ->赵六
s1.printName("王五", 100, 'M');    // 调用重载版本，输出: name = 王五  age=100 sex = M
```

成员函数与普通函数一样支持**重载**和**默认参数**，通过 `对象.函数名()` 调用。

**④ 注意**：
- 成员函数的参数若与成员变量同名，函数内参数会**遮蔽**成员变量（`printName(string name)` 里打印的是参数 name，不是成员 name），要用 `this->name` 指明成员——上面输出"赵六/王五"而不是成员 s1.name 的原因就在这；
- 不创建对象，就没有成员变量的存储空间（静态成员除外）。

**人话总结**：变量记状态，函数表行为，同名this区分。

## 模块四　静态成员、const成员函数、this指针（19.1 第40-57页）

### 11. 静态成员变量（第40-44页）【重点】

**① 是什么**：用 `static` 修饰的成员变量，**所有对象共享唯一一份**，存放在全局/静态区而非对象内部。
**② 为什么**：实现多个对象间的数据共享。比如全班学生共用一个"课程名"，每个对象存一份既浪费内存又容易不一致；静态成员只存一处，一处更新全体可见。

**③ 怎么用**（对应 code1.cpp 被注释的 `static string course`，已实测）：

```cpp
class Student {
public:
    static string course;           // 类内声明
};
string Student::course = "c++";     // 类外初始化：类型 类名::变量名 = 值;

cout << "course=" << Student::course << endl;  // 类名访问 → course=c++
Student s1;
cout << "s1 course = " << s1.course << endl;   // 对象访问 → s1 course = c++
```

**④ 注意**：
- 静态成员**必须在类外初始化**（去掉 static、加 `类名::`），否则链接报错"无法解析的外部符号"；
- 两种访问方式：`类名::变量`（推荐，没对象也能访问）、`对象.变量`；
- 它不属于某个对象，sizeof(对象) 不包含它。

**人话总结**：static一份数据全类共享，类外初始化。

### 12. 静态成员函数（第45-48页）【重点】

**① 是什么**：用 `static` 修饰的成员函数，属于**类**本身而不属于任何对象。
**② 为什么**：有些操作只跟类有关、跟具体对象无关（如统计创建了多少个对象），没对象时也要能调用。
**③ 怎么用**（对应 code1.cpp 被注释的 `static void sayHello()`，已实测）：

```cpp
static void sayHello() {
    cout << "this is sayHello()" << course << endl;  // 只能访问静态成员
}
Student::sayHello();   // 类名调用 → this is sayHello()c++
s1.sayHello();         // 对象调用 → this is sayHello()c++
```

**④ 注意**：
- **只能访问静态成员**，不能访问 name/age——它没有 this 指针，不知道"当前对象"是谁；
- 非静态成员函数倒是可以随意访问静态成员；
- 没有对象也能用 `类名::函数()` 调用。

**人话总结**：静态函数无this，只碰静态成员。

### 13. const修饰成员函数（第49-51页）【熟悉】

**① 是什么**：函数头部结尾加 `const` 的成员函数，叫**常成员函数**。
**② 为什么**：只读操作的"承诺书"——编译器保证此函数不修改成员变量；且 const 对象只能调用常成员函数。
**③ 怎么用**（对应 code1.cpp 的 `void sayHi() const`，已实测）：

```cpp
void sayHi() const {                          // 承诺不修改任何成员
    cout << "sayHi()->" << course << endl;      // 能读静态成员 → sayHi()->c++
    cout << "sayHi()->" << this->name << endl;  // 能读普通成员 → sayHi()->zs
    cout << "sayHi()->" << this->age << endl;   // → sayHi()->21
}
```

**④ 注意**：
- 常成员函数内**能读不能写**：写 `this->age = 10;` 直接编译报错；
- 声明和定义处都要加 const；
- const 对象只能调用 const 成员函数。

**人话总结**：函数加const，只读不写保安心。

### 14. this指针（第52-54页）【重点】

**① 是什么**：指向**当前对象**的 const 指针，是成员函数的**隐式形参**。
**② 为什么**：s1.show() 和 s2.show() 执行的是同一份函数代码，编译器靠偷偷传入的 this（等于 &s1 或 &s2）区分"这次操作的是哪个对象"。

**③ 怎么用**（对应 code1.cpp 活动类 Student 的 show()，实测地址完全相同）：

```cpp
void show() { cout << "this ->" << this << endl; }
// main：
Student s1("za", 21);
s1.show();                      // 输出 this ->0x61fdb0
cout << "s1->" << &s1 << endl;  // 输出 s1->0x61fdb0  ← this 就是 &s1！
```

构造函数里 `this->name = name;` 是它最典型的用途：参数和成员同名时，`this->name` 指成员，裸 `name` 指参数。

**④ 注意**：
- this 是 **const 指针**，不能赋值、不能自增自减；
- 只能在**非静态成员函数**内使用（静态函数没有 this）；
- 对象创建后 this 才有意义。

**人话总结**：this就是当前对象的地址。

### 15. 课堂练习——矩形类（第55-56页）

**题目**：创建矩形类，成员变量长和宽，成员函数判断是否正方形、输出面积；创建实例验证。
**思路**：长宽设 private 体现封装；构造函数初始化长宽；`is_square()` 比较 `width == height` 返回 bool；`area()` 打印乘积。code1.cpp 活动代码即标准答案，实测输出 `r1是正方形` 和 `10000`：

```cpp
class Rect {
private:
    double width, height;                // 私有：长宽
public:
    Rect(double width, double height) {  // this区分参数与成员
        this->width = width;
        this->height = height;
    }
    bool is_square() { return this->width == this->height; }
    void area() { cout << this->width * this->height << endl; }
};
int main() {
    Rect r1(100, 100);
    bool b = r1.is_square();          // true
    cout << (b ? "r1是正方形" : "r1不是正方形") << endl;  // r1是正方形
    r1.area();                        // 10000
    return 0;
}
```

**人话总结**：私有数据公有接口，this解同名冲突。

## 模块五　访问限定符、友元、运算符重载（19.2 第4-27页）

### 16. 访问限定符（19.2 第4-6页）【重点】

**① 是什么**：控制类成员访问权限的三个关键字：public（公有）、protected（保护）、private（私有），统称成员访问限定符。
**② 为什么**：**封装**的核心手段——数据藏起来（private），只暴露必要接口（public），防止外部代码随意改坏内部状态。

**③ 三种限定符对比表**：

| 限定符 | 本类内部 | 子类内部 | 友元 | 类的对象（外部） |
|---|---|---|---|---|
| public 公有 | ✅ | ✅ | ✅ | ✅ |
| protected 保护 | ✅ | ✅ | ✅ | ❌ |
| private 私有 | ✅ | ❌ | ✅ | ❌ |

教材第6页验证：`func1()` 是本类函数，v1/v2/v3 全能访问；但对象只能 `s1.v1 = 99;`，写 `s1.v2 = 11;`（私有）或 `s1.v3 = 33;`（保护）都编译报错。

**④ 注意**：
- protected 与 private 对"对象"都不可见，区别要到**子类**里才显现（见模块六）；
- class 成员默认 private，struct 成员默认 public；
- 友元可突破一切限定（见下）。

**人话总结**：public随便用，protected留儿子，private自己藏。

### 17. 友元函数（19.2 第7-10页）【重点】

**① 是什么**：定义在类外部、在类内用 `friend` 声明的函数，能访问该类的私有和保护成员。**友元函数不是成员函数**。
**② 为什么**：外部函数有时必须直接读私有数据（打印函数、双目运算符重载），一个个写 getter 太啰嗦；友元是封装上开的一个"后门"。

**③ 怎么用**（教材第9→10页对比实验）：

```cpp
class Student {
public:
    Student(string name, int age) { this->name = name; this->age = age; }
    friend void printName(Student stu);  // 声明友元（写在哪个限定符下都行）
private:
    string name;
    int age;
};
void printName(Student stu) {
    cout << stu.name << endl;  // 第9页没friend：编译报错
}                             // 第10页加了friend：正常输出 zs
```

**④ 注意**：
- 友元函数**没有 this 指针**（不是成员），访问成员必须通过参数传入的对象；
- 友元声明不受限定符约束；
- 友元破坏封装，能不用就不用。

**人话总结**：friend发通行证，外部函数进私宅。

### 18. 友元类（19.2 第11-13页）【重点】

**① 是什么**：用 `friend class 类名;` 把一个类声明为另一个类的友元，友元类的**所有成员函数**都能访问对方的私有成员。
**② 为什么**：两个类紧密协作时（Student 的方法要读 Teacher 的私有信息），逐个函数声明友元太繁琐，干脆整个类发通行证。
**③ 怎么用**（教材第13页案例，实测输出 王五 / 张三）：

```cpp
class Teacher;                        // 前向声明
class Student {
public:
    void stu_print(Teacher& t);       // 先只声明
private:
    string name = "王五";
};
class Teacher {
private:
    string name = "张三";
public:
    friend class Student;             // Student 是 Teacher 的友元类
};
void Student::stu_print(Teacher& t) { // 类外定义：此时能访问t.name
    cout << this->name << endl;       // 王五
    cout << t.name << endl;           // 张三
}
```

**④ 注意**：
- 友元关系**单向**：A 声明 B 为友元，B 能进 A 的私宅，A 进不了 B 的；
- 友元关系**不可传递**：B 是 A 的友元、C 是 B 的友元，C 不是 A 的友元；
- 互相访问需各自声明对方为友元。

**人话总结**：友元类全家通行，单向不传递。

### 19. 运算符重载概述（19.2 第14-19页）【重点】

**① 是什么**：为已有运算符针对自定义类型赋予新含义，**本质是函数重载**——`a + b` 被编译器翻译成 `a.operator+(b)`。
**② 为什么**：`Complex c3 = c1 + c2;` 比调用 `add(c1, c2)` 直观得多，让自定义类型用起来像内置类型。教材第16页的问题"Student 直接写 `if(s1 > s2)` 行吗？"——不行，没重载 `>` 就编译报错。

**③ 规则**：
- 不能创造新运算符，只能重载 C++ 已有的；
- 不能改变运算符的**优先级、结合性、操作数个数**；
- **6 个不能重载的运算符**：`.`（成员访问）、`.*`（成员指针访问）、`::`（作用域）、`?:`（三目条件）、`#`（预处理）、`sizeof`；
- 重载后功能应与运算符本义相符。

**两种重载形式对比**：

| 形式 | 语法 | 特点 |
|---|---|---|
| 成员函数重载 | `返回类型 operator运算符(参数表)` | 左操作数是 this，右操作数是参数 |
| 友元函数重载 | `friend 返回类型 operator运算符(参数表)` | 两个操作数都是参数 |

**④ 注意**：重载决策在编译期完成，所以运算符重载属于**编译时多态**（静态绑定）。

**人话总结**：运算符即函数，operator+就是函数名。

### 20. 赋值运算符重载（19.2 第21页）【重点】

**① 是什么**：重载 `=`，规定"两个**已存在**对象之间赋值"时复制什么。
**② 为什么**：默认 `=` 做浅拷贝，类含指针时会双重释放；同时要分清：`Complex c2 = c1;`（c2 新生）走**拷贝构造**，`c2 = c1;`（两者已存在）走 **operator=**。

**③ 怎么用**（对应 code2.cpp 的 Student::operator=，实测输出）：

```cpp
void operator=(const Student& t) {   // 教材简化版；标准版返回 类名&
    this->name = t.name;
    this->age = t.age;
}
// main（教材第21页）：
Student s1, s2("王五", 30);
s2.printInfo();   // 王五  30
s2 = s1;          // operator=：把s1的("zs",20)复制给s2
s2.printInfo();   // zs  20
```

**④ 注意**：
- 必须处理**自赋值**：标准写法开头 `if (this == &t) return *this;`；
- 标准签名 `类名& operator=(const 类名& t)` 返回 *this，支持连等 `a = b = c;`；
- 不写时编译器生成默认赋值运算符（浅拷贝）。

**人话总结**：等号两边都已存在，才走operator=。

### 21. 算术运算符重载（19.2 第22页）【重点】

**① 是什么**：重载 `+ - * /` 等算术运算符。
**② 为什么**：复数、分数、向量等数学类型用运算符表达运算最自然（hw_rational.cpp 分数类就是完整实战）。
**③ 怎么用**（对应 code2.cpp 的 Complex，实测输出）：

```cpp
Complex operator+(Complex& c) {    // c1 + c2 → c1.operator+(c2)
    Complex c2;
    c2.r = this->r + c.r;          // this是左操作数，c是右操作数
    c2.i = this->i + c.i;
    return c2;                     // 返回新对象（值返回）
}
Complex operator-(Complex& c) {    // 减法同理
    Complex c2;
    c2.r = this->r - c.r;
    c2.i = this->i - c.i;
    return c2;
}
// main：实测
Complex c1(11, 12), c2(10, 11), c3, c4;
c3 = c1 + c2;  c3.print();   // 21  23
c4 = c1 - c2;  c4.print();   // 1  1
```

**④ 注意**：返回**值**而不是引用——局部对象函数结束就销毁，返回引用是悬空引用；operator+ 不修改 this，严格写法应加 const。

**人话总结**：左边调函数右边当参数，返回新对象。

### 22. 关系运算符重载（19.2 第23页）【重点】

**① 是什么**：重载 `> < == <=` 等比较运算符，返回 bool。
**② 为什么**：让对象能直接比较大小、参与排序。
**③ 怎么用**（对应 code2.cpp，实测输出）：

```cpp
bool operator>(Animal& a) { return this->age > a.age; }  // 按年龄比
bool operator==(Animal& a) { return this->age == a.age; }
bool operator<(Animal& a) { return this->age < a.age; }
// main（code2.cpp 活动代码）实测：
Animal a1(10), a2(20), a3(30);
if (a1 < a2)  cout << "a1 < a2" << endl;   // 输出 a1 < a2
if (a1 == a3) cout << "=="; else cout << "a1 != a3" << endl;  // a1 != a3
if (a3 > a2)  cout << "a3 > a2" << endl;   // a3 > a2
```

code2.cpp 里 Student 的 `operator<=` 比较的是 **name 字符串字典序**而非 age——实测 `s3("as") <= s4("zw")` 成立输出 `s1 <= s2`。教材第26页练习是**友元版**：`friend bool operator>(Animal &a1, Animal &a2);`，两个操作数都作参数。

**④ 注意**：string 已重载比较运算符（字典序），所以 `this->name < t.name` 合法；建议返回 true/false 而非 1/0。

**人话总结**：比什么你定义，返回真或假。

### 23. 下标运算符重载（19.2 第24页）【重点】

**① 是什么**：重载 `[]`，让对象像数组一样用下标访问（`arr[1]` 翻译成 `arr.operator[](1)`）。
**② 为什么**：实现**带越界检查的安全数组**——原生数组越界不报错直接崩，重载 `[]` 能拦截。
**③ 怎么用**（对应 code2.cpp 的 SafeArr，实测输出）：

```cpp
const int SIZE = 5;
class SafeArr {
public:
    int arr[SIZE];                // 构造时填 arr[i]=i
    int operator[](int i) {
        if (i >= SIZE) {          // 越界检查
            cout << "下标越界" << endl;
            return -1;            // 返回错误标志
        }
        return arr[i];
    }
};
// main 实测：
SafeArr arr;
cout << arr[1] << endl;   // 1
cout << arr[10] << endl;  // 下标越界 → 换行 → -1
```

**④ 注意**：
- 教材版只能"读"；要支持 `arr[1] = 99;` 必须返回**引用** `int& operator[](int i)`；
- 标准库 vector/string 的 `[]` 就是这么实现的。

**人话总结**：中括号变函数调用，越界能拦截。

## 模块六　继承基本概念、三种继承方式、构造析构（19.3 第4-32页）

### 24. 继承的基本概念（19.3 第4-6页）【了解】

**① 是什么**：继承是一个类从另一个类获取成员变量和成员函数的过程。被继承的叫**基类/父类**，继承的叫**派生类/子类**。
**② 为什么**：老板让你写 Dog 类，它跟已有的 Animal 类吃喝睡跑全一样——重写一遍？copy 改改？都不如让 Dog 直接继承 Animal，**代码复用、减少冗余**，基类改一处全体子类受益。派生（Derive）和继承是同一件事的两个角度：继承是"儿子接收产业"，派生是"父亲传承产业"。
**③ 使用场景**：新类与现有类相似、只多几个成员；或多个类有大量共同成员——把共同部分提取成基类。
**④ 注意**：子类继承的是基类**除构造/析构/赋值运算符/友元外**的全部成员（private 成员也被继承，只是访问不到，见专题）。

**人话总结**：儿子继承爹的家产，代码复用。

### 25. 继承的语法规则（19.3 第7-9页）【熟悉】

**① 是什么**：`class 派生类 : 继承方式 基类 { };`
**② 为什么**：指明"谁继承谁、以什么方式继承"。
**③ 怎么用**（对应 code3.cpp 被注释的 `class Dog : public Animal`，实测输出 `名字叫:wangcai  年龄是:3`）：

```cpp
class Animal {
public:
    string name;
    int age;
    void printInfo() { cout << "名字叫:" << name << "，岁数是" << age << endl; }
};
class Dog : public Animal {   // Dog继承Animal：name/age/printInfo()全是自己的了
public:
    char sex;                 // 只需写新增成员
};
Dog d1("wangcai", 3, 'F');
d1.printInfo();               // 直接用基类的方法 → 名字叫:wangcai  年龄是:3
```

**④ 注意**：继承方式不写时**默认 private**（struct 默认 public）；实际开发几乎只用 public 继承。

**人话总结**：冒号继承，只写新增成员。

### 26. 三种继承方式（19.3 第10-20页）【重点】

**① 是什么**：public、protected、private 三种继承方式，决定**基类成员到派生类后权限如何变化**。
**② 为什么**：继承方式是给基类成员在子类里的权限"封顶"——不管基类里是什么权限，进了子类最高只能是继承方式规定的级别。

**③ 权限变化大表格**（基类成员 → 派生类中的最高权限）：

| 基类成员 ↓ / 继承方式 → | public 继承 | protected 继承 | private 继承 |
|---|---|---|---|
| public 成员 | public | protected | private |
| protected 成员 | protected | protected | private |
| private 成员 | **不可访问** | **不可访问** | **不可访问** |

**核心规则：基类的 private 成员，无论怎么继承，派生类内部都访问不到**（但确实被继承了，占内存，只能通过基类的 public/protected 函数间接操作）。

教材第12-19页实验（对应 code3.cpp 被注释的 Person/Student）：
- Person 的 name=public、age=protected、height=private；
- `Student : public Person` 继承后：Student 的对象能调 setName/setAge/setHeight/printInfo（public 方法照常可用，程序正常跑）；
- 在 Student 成员函数里直接访问 `this->name`（public→public）✅、`this->age`（protected→protected）✅、`this->height`（private）❌ 编译报错；
- 改成 private 继承后，对象连 setName 都调不了——基类 public 成员全变 private，外部全瞎。

**④ 注意**：
- 想让成员"外部不能用、子类随便用"→ 声明为 **protected**；
- 三种继承里 public 继承最常用，protected/private 继承了解即可（它们其实是"按实现继承"，能用组合替代）。

**人话总结**：private永远传不进子类，public继承不改变。

### 27. 继承中的构造和析构（19.3 第21-32页）【重点】

**① 是什么**：子类**不能继承**父类的构造函数（构造函数名=类名，名字对不上），但子类构造时必须调用父类构造函数初始化继承来的成员。
**② 为什么**：子类对象里包含着一个"父类子对象"，它必须被正确初始化；语法规定：创建派生类对象**必须**调用基类构造函数。

**③ 怎么用**（对应 code3.cpp 被注释的 Animal/Monkey/GoldenMonkey，实测输出）：

```cpp
class Animal { public: Animal()  { cout << "call Animal" << endl; }
                     ~Animal() { cout << "call ~Animal" << endl; } };
class Monkey : public Animal {
              public: Monkey()  { cout << "call Monkey" << endl; }
                      ~Monkey() { cout << "call ~Monkey" << endl; } };
class GoldenMonkey : public Monkey {
              public: GoldenMonkey() { cout << "Call GoldenMonkey" << endl; } };
// main 实测输出（GoldenMonkey gm1;）：
// call Animal → call Monkey → Call GoldenMonkey → call ~Monkey → call ~Animal
```

**四条铁律**：
1. 子类构造函数通过**初始化列表**调用父类构造：`Student(参数) : Person(参数), score(s) { }`（对应 code3.cpp 的 Person/Student，实测输出 `名字:xm 年龄:20 身高:1.7`）；
2. 构造顺序：**先基类后派生类**（爷爷→爹→儿子，按继承链从最顶层往下）；
3. 析构顺序：**先派生类后基类**（与构造完全相反：儿子→爹→爷爷）；
4. 不在初始化列表里指明父类构造时，自动调用父类**默认构造函数**；父类没有默认构造则编译报错（教材第30页实验：Animal(string) 存在时 Monkey() 编译失败）。

**C++11 继承构造函数**：`using Person::Person;` 直接把父类构造函数继承过来（对应 code3.cpp 被注释的 using，实测 `Student s3("继承构造", 21, 1.8); s3.printInfo();` 输出 `名字:继承构造 年龄:21 身高:1.8`），不用再写一堆转发构造函数。不被使用的继承构造函数不会生成真实代码。

**④ 注意**：析构顺序相反很好记——先构造的是"地基"，拆房子必须最后拆地基。

**人话总结**：构造从爷爷到孙子，析构从孙子到爷爷。

## 模块七　多继承、菱形继承、虚继承（19.3 第33-55页）

### 28. 多继承（19.3 第33-37页）【重点】

**① 是什么**：一个派生类同时有多个基类：`class D : public A, public B { };`（只有一个基类叫单继承）。
**② 为什么**：一个事物可能同时具备多个类的特征——孙悟空既是动物（会吃）又是人（会说话），单继承表达不了，多继承让 Xtq 同时拥有 Animal 的 nickName 和 Person 的 name/age。
**③ 怎么用**（对应 code3.cpp 被注释的 Xtq，实测输出 `gg  xtq  M`）：

```cpp
class Xtq : public Animal, public Person {   // 逗号隔开多个基类
private:
    char sex;
public:
    Xtq(string nickName, string name, char sex)
        : Animal(nickName), Person(name), sex(sex) {}   // 初始化列表喂两个爹
    void printInfo() {
        cout << this->nickName << "  " << this->name << "  " << this->sex << endl;
    }
};
```

**④ 注意**：多继承容易让逻辑复杂、思路混乱，一直备受争议（Java 干脆取消了类多继承），中小型项目少用；实际更多用"单继承+接口/组合"。

**人话总结**：逗号连爹，全家的成员都归我。

### 29. 多继承构造函数（19.3 第38-43页）【重点】

**① 是什么**：派生类构造函数的初始化列表里依次调用多个基类的构造函数。
**② 关键规则**：**基类构造的调用顺序只由"声明派生类时基类的排列顺序"决定，与初始化列表里写的顺序无关！**

**③ 怎么用**（code3.cpp 被注释的 Ai 类与教材对照实验，均实测）：

```cpp
class Ai : public Worker, public Person {   // 声明顺序：Worker在前！
public:
    Ai() : Person(), Worker() { }           // 初始化列表故意把Person写前面
};
Ai a1;   // 实测输出：call Worker → call Person → call Ai
         // （仍然先Worker后Person——看声明顺序，不看初始化列表）

// 对照组：class Ai : public Person, public Worker
// 实测输出：call Person → call Worker → call Ai
```

**④ 注意**：写初始化列表时按声明顺序写是良好习惯，避免误导读代码的人。

**人话总结**：多个爹谁先构造，看声明顺序不看列表。

### 30. 多继承命名冲突（19.3 第44-46页）【重点】

**① 是什么**：多个基类有**同名成员**时，派生类中出现两份同名成员，直接用名字会产生二义性（命名冲突）。
**② 为什么**：编译器不知道你要的是 Person 的 printInfo 还是 Worker 的 printInfo，直接报错。
**③ 怎么用**（对应 code3.cpp 被注释的 Person/Worker/Ai，实测正常输出 `Person info` 和 `Worker info`）：

```cpp
class Person { public: void printInfo() { cout << "Person info" << endl; } };
class Worker { public: void printInfo() { cout << "Worker info" << endl; } };
class Ai : public Worker, public Person {
public:
    void info() {
        Person::printInfo();   // 基类名::成员名 —— 显式指定是哪一份
        Worker::printInfo();
    }
};
// 直接写 a1.printInfo(); 编译报错（二义性）；
// 写 a1.Person::printInfo(); 或 a1.Worker::printInfo(); 也可以
```

**④ 注意**：`类名::成员` 是万能消歧格式，菱形继承的解法也是它（见下）。

**人话总结**：同名打架，报名字（基类名::）劝架。

### 31. 菱形继承（19.3 第47-50页）【重点】

**① 是什么**：A 派生出 B 和 C，D 又同时继承 B 和 C，继承图形成一个菱形（钻石形）。
**② 问题**：D 中会得到**两份 A 的成员**——一份走 A→B→D 路径，一份走 A→C→D 路径。后果：①数据冗余（同名成员存两份）；②命名冲突（`m_a = a;` 编译器不知道改哪份，报错）。

**③ 怎么用**（教材第48-50页三步实验）：

```cpp
class A { protected: int m_a; };
class B : public A  { protected: int m_b; };
class C : public A  { protected: int m_c; };
class D : public B, public C {
public:
    void seta(int a) { m_a = a; }      // 第49页：报错！D里有两份m_a，二义性
    void seta(int a) { A::m_a = a; }   // 第50页：改用 A::m_a 指定，编译通过
    void setb(int b) { m_b = b; }      // 正确：m_b只有一份（来自B）
};
```

**④ 注意**：`A::m_a` 只解决"编译过"，没解决"存了两份"的冗余——根治要靠虚继承（见下）。

**人话总结**：菱形继承存两份，指名道姓才不吵。

### 32. 虚继承（19.3 第51-52页）【重点】

**① 是什么**：继承时加 `virtual` 关键字（`class B : virtual public A { };`），B 和 C 虚继承 A 后，D 中只保留**一份** A 的成员。
**② 为什么**：解决菱形继承的数据冗余和二义性。
**③ 怎么用**（教材第52页代码）：

```cpp
class B : virtual public A { };   // virtual加在继承方式前面
class C : virtual public A { };
class D : public B, public C {
public:
    void seta(int a) { m_a = a; }   // 不再冲突！全D只有一份m_a
};
```

**④ 注意**：虚继承有轻微空间/时间开销（虚基类指针/表），只在菱形结构里用；内存布局详见专题三。

**人话总结**：virtual继承，公共爷爷只留一份。

### 33. 虚继承构造函数（19.3 第53-55页）【重点】

**① 是什么**：虚继承下，**虚基类 A 由最终派生类 D 直接负责初始化**；B、C 中对 A 的构造调用在构造 D 时被忽略。
**② 为什么**：只有一份 A 成员，如果 B 和 C 都抢着初始化它就乱套了，所以语法规定"最终造出来的那个类"说了算。这与普通继承不同——普通继承中派生类**只能**调用直接基类的构造函数，不能越级调间接基类；虚继承反而**必须**由最终派生类直接调用虚基类构造。

**③ 怎么用**（对应 code3.cpp 被注释的 A/B/C/D，实测输出）：

```cpp
D(int a, int b, int c, int d)
    : A(a), B(90, b), C(100, c), m_d(d) {}   // A(a)必须D亲自调！B里的A(90)、C里的A(100)被忽略
// main 实测：
B b1(112, 222);  b1.printInfo();   // 112  222   （单独构造B时，B自己的A(112)生效）
C c1(113, 333);  c1.printInfo();   // 113  333
D d1(114, 2223, 3333, 444);
d1.printInfo();                    // 114  2223  3333 444
                                   // m_a=114：D直接调A(114)，压过B(90)/C(100)
D d2(1, 2, 3, 4); d2.seta(100); d2.printa();   // 100：一份m_a随处可改
```

**④ 注意**：构造顺序上，**虚基类永远最先构造**（先 A，再按声明顺序 B、C，最后 D）。

**人话总结**：虚基类谁最终谁初始化，A永远最先造。

## 模块八　多态、虚函数、虚析构、抽象类（19.4 第3-47页）

### 34. 多态的基本概念（19.4 第4-5页）【了解】

**① 是什么**："多态" = 同一个名字的事物完成不同的功能。C++ 三大特征：**封装、继承、多态**。
**② 两种多态**：
- **编译时多态（静态绑定）**：函数重载、运算符重载——编译期就能根据实参确定调用谁；
- **运行时多态（动态绑定）**：继承 + 虚函数——运行期才根据对象实际类型决定调用谁。

**③ 多态的目的**：通过**基类指针**访问所有派生类的成员函数（"全方位访问"）。没有多态，基类指针只能访问基类自己的成员。
**④ 注意**：运行时多态才是本章说的"多态"，它三要素缺一不可（见下）。

**人话总结**：同名不同命，运行时见真容。

### 35. 构成多态的条件（19.4 第6-12页）【重点】

**① 是什么**：通过基类指针调用派生类的同名覆盖函数的机制。**三个条件缺一不可**：
1. 必须存在**继承关系**；
2. 必须有**同名虚函数**且构成**覆盖**关系（函数原型完全相同：返回值、函数名、参数都一样）；
3. 通过**基类指针（或引用）**调用虚函数。

**② 为什么**：教材第7-10页实验（对应 code4.cpp 被注释的 Person/Student）：
- `person->info()` 指向 Person 对象：各调各的，没问题；
- `person = new Student(...); person->info();` **仍然调用 Person 的 info！** 基类指针类型决定了它"看得见"的成员——指针是 Person*，编译器只认 Person 的 info；
- 想让基类指针调用到 Student 的 info → 把 info 声明为 **virtual**（第11-12页）→ 多态达成。

**③ 怎么用**（code4.cpp 被注释代码还原，实测）：

```cpp
Person* p1 = new Person("zxx", 20);
p1->info();                        // person info:zxx  20
p1 = new Student("xiaoming", 11, 90);
p1->info();                        // virtual后：student info:xiaoming  11  90
                                   // （不加virtual时：person info:xiaoming  11）
```

**④ 注意**：覆盖(override)要求**函数原型相同**——只同名不同参不叫覆盖，是"重定义/遮蔽"，构不成多态（见对比表）。

**人话总结**：继承+虚函数+基类指针，三票缺一不可。

### 36. 引用实现多态（19.4 第13-14页）【熟悉】

**① 是什么**：基类**引用**指代派生类对象，调用虚函数同样触发多态。
**② 为什么**：引用和指针一样都能"以基类视角看派生类对象"。
**③ 怎么用**（对应 code4.cpp 被注释代码还原，实测）：

```cpp
Person p2("swk", 500);
Student s1("bgj", 300, 99);
Person& pper = p2;    // 基类引用绑基类对象
Person& pstu = s1;    // 基类引用绑派生类对象
pper.info();          // 实测：person info:swk  500
pstu.info();          // 实测：student info:bgj  300  99 ← 多态！
```

**④ 注意**：引用"从一而终"，定义时绑定谁就一辈子是谁，不能改指向（指针可以随时 `pa = new Cat`）——所以引用的多态表现力不如指针，代码里 `Animal& ya2 = d1; ya2.eat();` 输出 `Dog eat`。

**人话总结**：引用也能多态，但不能改嫁。

### 37. 虚函数（19.4 第15-19页）【重点】

**① 是什么**：用 `virtual` 修饰的成员函数。语法：`virtual 返回类型 函数名(参数) { }`。
**② 为什么**：虚函数是多态的开关。判断要不要声明虚函数：①这个类会当基类吗？②这个函数在子类里会不会被改功能？会改 → 声明为 virtual；不会改/子类用不到 → 别加（虚函数有虚表开销）。
**③ 怎么用**（对应 code4.cpp 被注释的 Animal/Dog/Cat，实测输出）：

```cpp
class Animal { public: virtual void eat() { cout << "Animal eat" << endl; } };
class Dog : public Animal { public: virtual void eat() { cout << "Dog eat" << endl; } };
class Cat : public Animal { public: virtual void eat() { cout << "Cat eat" << endl; } };
// main 实测：
Animal* pa = new Animal();  pa->eat();   // Animal eat
pa = new Dog();             pa->eat();   // Dog eat   ← 同一句 pa->eat() 不同结果
pa = new Cat();             pa->eat();   // Cat eat   ← 这就是多态
```

**④ 注意**：
- 只要在**基类**声明处加 virtual，派生类中的同名覆盖函数**自动成为虚函数**（写不写 virtual 都行，写了更清晰）；
- 基类虚函数没有被派生类覆盖时，派生类对象调用的是基类版本（hw_virtualFunc.txt 第4条）；
- **构造函数不能是虚函数**（构造时对象还没成型，没有虚表可查）。

**人话总结**：virtual一开，指针找真人。

### 38. 虚析构（19.4 第20-27页）【重点】

**① 是什么**：用 virtual 修饰的析构函数：`virtual ~Person() { }`。
**② 为什么——防止内存泄漏**（教材第21页）：
- 基类析构**不是**虚函数时：`delete 基类指针`（指向子类对象）**只调用基类析构**，子类析构不执行 → 子类在堆上申请的内存（指针成员 new 出来的）没人释放 → **内存泄漏**；
- 基类析构**是**虚函数时：delete 先调**子类析构**，再调**基类析构**，清理完整。

**③ 怎么用**（code4.cpp 被注释代码 + 教材对照实验，均实测）：

```cpp
// 实验A（教材第23页，~Person非虚）：
Person* p1 = new Student("zs", 20, 90);
p1->info();      // student info:zs  20  90
delete p1;       // 实测输出：call ~Person   ← 只调了父类析构！~Student没跑，泄漏！

// 实验B（教材第25页/code4.cpp，virtual ~Person）：
Person* p1 = new Student("张三", 23, 89);
p1->info();      // student info:张三  23  89
delete p1;       // 实测输出：Call ~Student() → Call ~Person()  ← 先子后父，完整释放
```

**④ 注意**：**"用来做基类的类，析构函数一般都声明为虚函数"**——这是铁律；即便子类暂时没有指针成员，加上 virtual 有备无患（开销可忽略）。析构顺序天然"先派生类后基类"，与构造相反。

**人话总结**：基类析构加virtual，delete才不漏。

### 39. 虚函数表（19.4 第28-37页）【重点】

**① 是什么**：存储虚函数地址的指针数组（vtable），编译器为**每个含虚函数的类**生成一张；每个对象里藏一个指向虚表的指针（vptr）。
**② 为什么**：运行时多态的底层实现——编译期不知道基类指针最终指向谁，只能运行时"查表"找到真正的函数地址。
**③ 工作流程**（结合教材第29页图示，详见专题四）：
1. **编译阶段**：编译器为类构造虚函数表，把每个虚函数的入口地址填入表中；同时在对象里秘密添加 vptr；
2. **构造函数执行时**：初始化 vptr 指向本类的虚表。子类构造时**先**把 vptr 指向**基类虚表**（执行基类构造函数时），**构造完成后** vptr 指向**子类虚表**；
3. **调用 `pa->eat()` 时**：经 vptr 找到虚表 → 按槽位取出函数地址 → 调用。虚表属于**类**（一个类一张，所有对象共享），对象里只有 vptr。

**④ 两个验证实验**（对应 code4.cpp 被注释的 func1~4 代码，均实测）：

```cpp
// 实验A：子类没有覆盖 func1（只新增了func3/func4）
Animal* pa = new Dog();
pa->func1();   // 实测：Animal func1 ← Dog虚表里func1槽位仍是Animal的地址

// 实验B：子类覆盖了 func1
Animal* pa = new Dog();
pa->func1();   // 实测：Dog func1 ← Dog虚表里func1槽位被替换成Dog的地址
```

**人话总结**：一类一虚表，一对象一vptr，查表调用。

### 40. 抽象基类和纯虚函数（19.4 第38-44页）【重点】

**① 是什么**：
- 纯虚函数：只声明不实现的虚函数：`virtual 返回类型 函数名(参数) = 0;`
- 抽象基类（抽象类）：包含**至少一个纯虚函数**的类。

**② 为什么**：有时基类只该当"**接口/规范**"，不该被实例化（"饮品"是个抽象概念，你造不出一杯"抽象的饮品"）。纯虚函数：①禁止创建基类对象（编译器强制）；②**强制**每个子类必须实现这些接口；③建立公共流程框架。
**③ 怎么用**（对应 code4.cpp 活动代码 AbstractDrinking 咖啡/茶案例，实测输出）：

```cpp
class AbstractDrinking {
public:
    virtual void boil() = 0;         // 烧水：纯虚函数——子类必须实现
    virtual void brow() = 0;         // 冲泡
    virtual void pourInCup() = 0;    // 倒入杯子
    virtual void putSomething() = 0; // 加辅料
    void makeDrink() {               // 普通函数规定固定流程（模板方法）
        boil(); brow(); pourInCup(); putSomething();
    }
};
class Coffee : public AbstractDrinking {
public:
    virtual void boil() { cout << "煮山泉水" << endl; }      // 各自实现四个步骤
    virtual void brow() { cout << "泡咖啡" << endl; }
    virtual void pourInCup() { cout << "咖啡倒入杯子" << endl; }
    virtual void putSomething() { cout << "加牛奶" << endl; }
};
class Tea : public AbstractDrinking { /* 煮白开水/泡茶/茶倒入杯子/加盐 */ };

void doBussiness(AbstractDrinking* ad) {   // 基类指针接收任意饮品（多态）
    ad->makeDrink();                       // 同一流程，不同实现
    delete ad;
}
int main() {
    doBussiness(new Coffee());   // 实测：煮山泉水/泡咖啡/咖啡倒入杯子/加牛奶
    cout << endl;
    doBussiness(new Tea());      // 实测：煮白开水/泡茶/茶倒入杯子/加盐
    return 0;
}
```

设计意图：**流程固定在基类（makeDrink），实现交给子类（四个纯虚函数）**——新增"可乐"只需再写一个子类，doBussiness 一行不改。

**④ 注意**：
- 抽象类**不能实例化对象**：`AbstractDrinking d;` 编译报错；但可以定义指针/引用（指向子类对象）；
- 子类必须**实现全部**纯虚函数，否则子类也是抽象类，也不能实例化；
- 纯虚函数与"虚函数"对比：`virtual void f() { }`（有实现，可选覆盖）vs `virtual void f() = 0;`（无实现，必须覆盖）。

**人话总结**：=0只定规矩不干活，逼着儿子全实现。

# 第三部分　五大难点专题

## 专题一　深拷贝 vs 浅拷贝（含指针成员）⭐

**问题根源**：编译器生成的默认拷贝构造/默认operator=是**逐字节复制**（浅拷贝）。成员里没有指针时天下太平；一旦有指针成员，复制的是**指针的值（地址）**——两个对象的指针指向**同一块堆内存**。

```cpp
class BadString {
public:
    BadString(const char* s) {
        data = new char[strlen(s) + 1];   // 堆上开内存
        strcpy(data, s);
    }
    ~BadString() { delete[] data; }       // 析构释放
    char* data;
};
int main() {
    BadString s1("hello");
    BadString s2 = s1;    // 浅拷贝：s2.data = s1.data（同一个地址！）
    return 0;
}   // s2先析构：delete[] data；s1再析构：对同一地址再delete[] → 崩溃/未定义行为
```

**深拷贝解法**——自定义拷贝构造，给新对象**另开一块内存**再复制内容：

```cpp
BadString(const BadString& other) {
    data = new char[strlen(other.data) + 1];  // 另开内存（深）
    strcpy(data, other.data);                 // 复制内容而非地址
}
```

| 对比项 | 浅拷贝 | 深拷贝 |
|---|---|---|
| 复制什么 | 成员的值（指针=地址） | 指针所指的**内容** |
| 内存份数 | 共享一份 | 各自一份 |
| 何时安全 | 无指针成员时 | 有指针成员时必须 |
| 实现方式 | 编译器默认 | 手写拷贝构造+operator= |

一句话：**浅拷贝抄地址，深拷贝抄内容；有指针必深拷**。

## 专题二　三种继承方式访问权限（记忆法）

大表格见"表4"。记忆口诀：
- **private 是铜墙铁壁**：不管怎么继承，基类 private 成员在子类内部永远不可见（但占内存、被继承）；
- **public 继承"保持原样"**：public→public，protected→protected；
- **protected 继承"封顶到 protected"**：public 降为 protected，protected 不变；
- **private 继承"一降到底"**：public、protected 都降为 private；
- 继承方式 = 子类中成员权限的**上限**（帽子）。

验证代码（教材实验）：public 继承时子类成员函数能访问基类 public/protected 成员，访问 private 报错；private 继承时外部对象连子类对象调基类 public 方法都不行。

## 专题三　菱形继承 + 虚继承内存布局（图解）

**普通菱形继承的内存布局**（D 对象里有两份 A 子对象）：

```
      A {m_a}                 D 对象的内存（数据冗余！）
     /   \                    ┌─────────────────┐
    B     C                   │ B部分: A的m_a    │ ← 第一份m_a（经B路径来）
    │     │                   │        m_b      │
     \   /                    │ C部分: A的m_a    │ ← 第二份m_a（经C路径来）
      D                       │        m_c      │
                             │ D部分: m_d       │
                             └─────────────────┘
   d.m_a 直接访问 → 二义性报错：两份m_a，编译器不知选哪份
   （写成 B::m_a / C::m_a 才能编译过，但冗余仍在）
```

**虚继承后的内存布局**（只有一份共享的 A，靠虚基类指针定位）：

```
   class B : virtual public A          D 对象的内存
   class C : virtual public A          ┌──────────────────┐
                                      │ B部分: m_b        │
      A {m_a}                         │ B的虚基类指针 ────┼──┐
     /（virtual）\                    │ C部分: m_c        │  │
    B ─────────── C                   │ C的虚基类指针 ────┼──┤
     \             /                  │ D部分: m_d        │  │
      └───── D ◄─┘                    └──────────────────┘  │
                                            ▲               ▼
                                            └──┌─────────────────┐
                                               │ 共享的A: m_a    │ ← 只此一份！
                                               └─────────────────┘
   B、C 各带一个"虚基类指针"，运行时都指向共同的那份A
   d.m_a 无二义性；seta改一处，全D对象可见
```

要点：
1. virtual 加在**中间层（B、C）**的继承方式上，D 不用写 virtual；
2. A 的成员被"抽离"到共享位置，B/C 通过虚基类指针间接访问（多一次寻址，这就是虚继承的轻微开销）；
3. **构造规则同步改变**：虚基类 A 由**最终派生类 D** 直接初始化（`D(...): A(a), B(...), C(...)`），B/C 构造函数里写的 `A(a)` 在构造 D 时被忽略；单独创建 B 或 C 对象时它们自己的 A 调用才生效（实测：B(112,222) 里 m_a=112；D(114,...) 里 m_a=114，B写的A(90)、C写的A(100)作废）；
4. 构造顺序：**虚基类最先**构造，然后按声明顺序构造 B、C，最后 D。

## 专题四　虚函数表工作原理（图解）

**单个类的虚表**（教材第29页图，等价于 code4.cpp 的 Animal/Dog）：

```
class Animal {                    class Dog : public Animal {
  virtual void eat();               virtual void eat();   // 覆盖
  virtual void func2();             virtual void func3(); // 新增
};                                };

 Animal的虚表 vtable_Animal         Dog的虚表 vtable_Dog
 ┌──────────────────┐             ┌──────────────────┐
 │ [0] &Animal::eat  │             │ [0] &Dog::eat     │ ← 覆盖：换上自己的地址
 │ [1] &Animal::func2│             │ [1] &Animal::func2│ ← 未覆盖：继承父类槽位
 └──────────────────┘             │ [2] &Dog::func3   │ ← 新增：往后追加
                                  └──────────────────┘

 Animal a;  a里的vptr ──► vtable_Animal
 Dog d;     d里的vptr ──► vtable_Dog      （一类一表，全体对象共享）
```

**多态调用的完整过程** `Animal* pa = new Dog(); pa->eat();`：

```
 ①编译期：发现eat是虚函数 → 把调用编译成"查表跳转"指令（不写死地址）
 ②运行期：new Dog() 时Dog构造函数把对象头部vptr填成vtable_Dog的地址
         （构造期间：先执行Animal构造→vptr暂指父表；再执行Dog构造→vptr改指子表）
 ③pa->eat()：pa取出对象头部的vptr → 找到vtable_Dog → 取[0]槽位 → 调用Dog::eat ✔
```

**四条要点**（对应教材第30-37页）：
1. 虚表**属于类**（一个类一张，编译期构造完成），对象只存 vptr（一个指针的开销）；
2. 普通函数（非虚）不进虚表，调用不经查表（静态绑定）；
3. 子类未覆盖 → 槽位保留父函数地址（实测输出 Animal func1）；覆盖 → 槽位替换（实测输出 Dog func1）；新增虚函数 → 表尾追加；
4. vptr 在**构造函数中初始化**，且子类构造完成后最终指向子类虚表——所以构造函数里调用虚函数不会发生"期望中的多态"（此时还是父表）。

## 专题五　虚析构函数为什么能防止内存泄漏

**事故现场还原**（无虚析构，实测）：

```cpp
class Person {  ~Person() {...} };                    // 非虚析构
class Student : public Person {
    char* hobby = new char[100];                      // 子类在堆上申请了资源
    ~Student() { delete[] hobby; }                    // 只有它知道怎么释放
};
Person* p = new Student();
delete p;   // 编译器看p的类型是Person*，且~Person非虚 → 静态绑定 → 只调~Person()
            // ~Student()被跳过 → hobby的100字节永远没人释放 → 内存泄漏！
            // 实测输出：只有 call ~Person，没有 Call ~Student
```

**加上 virtual 后**（实测）：

```cpp
virtual ~Person() {...}
delete p;   // 析构函数进入虚表 → 动态绑定 → 先调~Student()（释放hobby）
            // 再自动调基类~Person() → 完整清理
            // 实测输出：Call ~Student() → Call ~Person()
```

**底层原因**：析构函数也是函数，virtual 同样让它进虚表、走动态绑定。delete 的本质是"通过指针调析构"——非虚时按**指针类型**（Person*）绑定，虚时按**对象实际类型**（Student）绑定。

**结论口诀**：**"当爹的类，析构必虚"**——只要类可能被继承、可能通过基类指针 delete，析构函数就加 virtual。

教材第46页作业"什么是虚函数？虚函数有哪些特点？"，hw_virtualFunc.txt 给出的答案逐条解读：

5. **"只有覆盖（函数原型相同）才构成多态"**——重定义（参数不同）不构成多态，见对比表5；
6. **"构造函数不能是虚函数"**——构造时对象/虚表未就绪，无意义；
7. **"析构函数可以且有时必须是虚函数"**——防止通过基类指针 delete 泄漏（专题五）。

## 1. 类定义（第4-21行）

```cpp
class Rational {
public:
    Rational(int num, int denom);   // 构造：分子、分母
    Rational operator+(Rational rhs);  // 四则运算重载（都按值接收右操作数）

    Rational operator*(Rational rhs);
    Rational operator/(Rational rhs);

private:
    void normalize();               // 分数化简（核心难点）
    int numerator;      // 分子
    int denominator;    // 分母

```

设计要点：分子分母设为 private 强制外部只能通过构造和运算操作分数；normalize 设为 private——化简是内部事务，外部无感。

## 2. 构造函数 + normalize 化简（第23-58行）

```cpp
Rational::Rational(int num, int denom) {
    numerator = num;
    denominator = denom;
    normalize();                    // 构造即化简：2/16 → 1/8
}
```

**normalize 两步走**：

```cpp
if (denominator < 0) {              // 第①步：负号统一搬到分子
    numerator = -numerator;         // 1/-2 → -1/2（保证分母恒正，显示规范）
    denominator = -denominator;
}
int a = abs(numerator);             // 第②步：欧几里得算法求最大公约数
int b = abs(denominator);
while (b > 0) {                     // 辗转相除：gcd(a,b) = gcd(b, a%b)
    int t = a % b;
    a = b;
    b = t;                          // 循环结束时 a 就是最大公约数
}
numerator /= a;                     // 分子分母同除gcd → 最简分数
denominator /= a;                   // 2/10 → 1/5
```

**欧几里得算法推演示例**（求 gcd(2,16)）：a=2,b=16 → t=2%16=2, a=16, b=2 → t=16%2=0, a=2, b=0 → 循环结束，gcd=2 → 2/16 化简为 1/8。

## 3. 四则运算符重载（数学原理 + 代码）

```cpp
// 加法：a/b + c/d = (a*d + c*b) / (b*d)
Rational Rational::operator+(Rational rhs) {
    int e = numerator * rhs.denominator + rhs.numerator * denominator;
    int f = denominator * rhs.denominator;
    return Rational(e, f);          // 返回值顺便被normalize化简！
}
// 减法：a/b - c/d = a/b + (-c)/d —— 取负后复用加法（代码复用）
Rational Rational::operator-(Rational rhs) {
    rhs.numerator = -rhs.numerator;
    return operator+(rhs);          // 显式调用自身的operator+
}
// 乘法：a/b * c/d = (a*c) / (b*d)
Rational Rational::operator*(Rational rhs) {
    return Rational(numerator * rhs.numerator, denominator * rhs.denominator);
}
// 除法：a/b ÷ c/d = a/b * d/c —— 倒转后复用乘法
Rational Rational::operator/(Rational rhs) {
    int t = rhs.numerator;          // 交换rhs的分子分母（取倒数）
    rhs.numerator = rhs.denominator;
    rhs.denominator = t;
    return operator*(rhs);
}
```

巧思：减法复用加法、除法复用乘法；每次运算返回的临时 Rational 在构造函数里自动 normalize，所以结果永远是最简分数。

# 第八部分　速查表·核心原则·速记口诀

## 速查表

| 类别 | 内容 |
|---|---|
| **三大特征** | 封装（访问限定符藏数据）、继承（代码复用 :public）、多态（虚函数+基类指针） |
| **三类访问限定符** | public 全开放；protected 本类+子类；private 仅本类 |
| **三种继承方式** | public 原样继承；protected 封顶继承；private 到底继承（基类 private 永远不可见） |
| **四个核心机制** | 构造函数（出生初始化）、析构函数（死亡清理）、虚函数（运行时多态）、纯虚函数（接口规范） |

## 面向对象最核心的三句话

1. **封装**：数据藏私有、接口开公有，对象自己管自己的状态。
2. **继承**：共性提到基类，子类只写差异，改一处全体受益。
3. **多态**：同一接口多种实现，基类指针指谁就调谁，新增子类不改老代码。

## 三条随身速记口诀

1. **构造析构口诀**：*"构造从爷到孙，析构从孙到爷；new必配delete，数组加中括。"*
2. **继承权限口诀**：*"public原样，protected封顶，private到底；爷爷的私房钱谁也拿不着。"*
3. **多态口诀**：*"一虚二覆三指针，缺一不多态；当爹析构必加虚，delete不漏财。"*
