# 第一阶段：讲

## 模块一：C++起源与命名（对应课件 P1-P3）

### 知识点 1：C++ 名字的由来【了解｜P1-P2】

**① 是什么**
一句话定义：C++ 读作"C 加加"，是 "C Plus Plus" 的简称——在 C 语言的名字后面加了两个加号，表示"在 C 的基础上增加新特性"。

生活化比喻：如果把 C 语言比作一部功能手机，那 C++ 就是它的"Plus Pro Max"版本——不但保留了打电话发短信（面向过程编程）的全部功能，还多了智能系统（面向对象）。更妙的是名字里那个 `++`：它本身就是 C/C++ 里的自增运算符（`x++` 让 x 变多 1），所以 C++ 这个名字是一个双关语——"C 这门语言给自己 +1 了"。

**② 为什么**
课件原文（P1-P2）："20 世纪 80 年代，AT&T Bell（贝尔）实验室的 Bjarne Stroustrup 博士及其同事在 C 语言的基础上成功开发出 C++ 语言。C++ 语言是一种混合型语言，它保留了 C 语言所有的优点，同时又增添了面向对象的编程机制，我们可以将 C++ 语言视为 C 语言的改进和扩展。"取名 C++ 正是为了强调"改进和扩展"这层关系：不是推翻 C 重来，而是在 C 上做增量。

**③ 怎么用**
日常沟通中你会见到这些写法，都指同一门语言：
- 文件名后缀：`.cpp`（C Plus Plus 的缩写，也有用 `.cc`、`.cxx` 的）、头文件 `.h` / `.hpp`
- 编译器命令行：`g++ hello.cpp -o hello`
- 简称 CPP：面试与文档里常写作 "CPP" 或 "C++/CPP"

```cpp
// 示意：一个 .cpp 源文件的骨架（第3章才会正式编写运行）
#include <iostream>      // 引入标准输入输出库（C++ 风格头文件）
int main() {             // 程序入口，返回 int
    std::cout << "Hi C++";// 向屏幕输出一句话
    return 0;            // 返回 0 表示正常结束
}
// 输出：Hi C++
```

**④ 注意事项 & 常见错误示范**
- 错误认知示范："C++ 就是 C 加了几个关键字" —— 错。名字只是彩蛋式隐喻，实质是语言范式的扩展（见知识点 8~12）。
- `++` 是自增运算符没错，但 `C--` 并不存在——别在面试里开这种玩笑被当成不懂运算符优先级。
- 记忆锚点：**C++ = C Plus Plus = C + 新特性**。

> 微型总结：C++ 诞生于 20 世纪 80 年代贝尔实验室，由 Bjarne Stroustrup 及同事在 C 基础上开发；名字取"C 加加"双关自增运算符，含义是"C 的改进和扩展"；它是一种保留 C 全部优点、增添面向对象机制的混合型语言。

### 知识点 2：创始人 Bjarne Stroustrup 与贝尔实验室【了解｜P1-P3】

**① 是什么**
一句话定义：C++ 由 Bjarne Stroustrup（本贾尼·斯特劳斯特卢普）博士及其同事于 20 世纪 80 年代在 AT&T 贝尔实验室（Bell Labs）开发。

生活化比喻：贝尔实验室之于编程语言，就像少林武术团之于功夫——Fortran 之外，C 语言（Dennis Ritchie）、Unix 也出自同一家。Stroustrup 相当于在"C 这门内功心法"里融入了"Simula6 的面向对象招式"，自成一派。

**② 为什么**
为什么要研究 C++？课件虽未展开史前动机，但从 P3-P4 的"目的是提高开发效率"可以反推：当年 C 语言写大型程序时缺乏组织复杂数据的手段（没有类、没有封装），开发者需要一门"既快又能管住大工程"的语言。这正是本章反复出现的主线：**性能 + 抽象能力**。

**③ 怎么用**
在简历、答辩、面试自我介绍里能准确说出："C++ 诞生于 20 世纪 80 年代的 AT&T 贝尔实验室，创始人是 Bjarne Stroustrup。"其余人物细节（如 Simula、CwithClasses 论文年份）超出课件范围，不必强记。

**④ 注意事项**
- 常见混淆：发明 C 语言的是 Dennis Ritchie，发明 C++ 的是 Stroustrup，考试喜欢把两人互换设陷阱。
- 注意课件措辞是"Stroustrup 博士**及其同事**"，严格说是团队工作、Stroustrup 主导。

> 微型总结：记住三个关键词——80 年代、贝尔实验室、Stroustrup。他们回答了"C++ 从哪来"。

### 知识点 3：C++ 简称 CPP 的由来【了解｜P1-P3】

**① 是什么**
一句话定义：因为全称 "C Plus Plus" 太长，书写与文件系统场景下简记为 **CPP**，源代码文件也因此采用 `.cpp` 后缀。

生活化比喻：就像"中华人民共和国"日常简称"中国"——CPP 就是 C++ 在不同场合（文件名、口语速记）使用的"合法别名"。

**② 为什么**
早期文件系统与命令行对 `+` 字符支持不友好（部分 shell 里 `+` 有特殊含义），于是社区约定俗成用字母 P 代替加号：C++ → C PP → 文件名 `main.cpp`。理解这一点后，你看到 `.cc`、`.cxx` 也能明白都是同一思路的变体。

**③ 怎么用**
```bash
# g++ 编译 .cpp 文件（Windows/Linux 命令一致，示意）
g++ main.cpp -o main        # 把 main.cpp 编译链接为可执行文件 main
```
编译器根据后缀判断语言：`.c` 按 C 编译，`.cpp` 按 C++ 编译（这是后面"兼容性"话题的伏笔）。

**④ 注意事项**
- 把 C++ 代码存成 `.c` 再用 gcc 编译，模板、类等 C++ 特性会直接报错——后缀决定了编译器用什么"语言眼镜"看你的代码。

> 微型总结：模块一收束——C++ 名字=C Plus Plus=C 的自增扩展；出处=80年代贝尔实验室 Stroustrup 团队；落地别名=CPP/.cpp。下面进入本章最硬核的部分：C++ 与 C 的关系和改进（⭐⭐⭐重点）。

## 模块二：C++ 与 C 的关系及改进（对应课件 P3-P6）

### 知识点 4：C 语言是 C++ 的一部分【熟悉｜P3-P4】

**① 是什么**
一句话定义：课件原文（P3）——"C++ 和 C 语言虽然是两门独立的语言，但同时 C 语言也是 C++ 的一部分，C 语言代码几乎不用修改就能够以 C++ 的方式编译。"

生活化比喻：智能手机是功能手机的"超集"——你能在最新款 iPhone 上找到拨号键，正如你能在 C++ 里找到 printf。类比先行：C++ ⊇ C，就像"全家桶 ⊇ 汉堡"。

**② 为什么**
设计动机：让用户可以平滑地从 C 迁移到 C++（P8 原文："C++ 设计成尽可能与 C 兼容，籍此提供一个从 C 到 C++ 的平滑过渡"）。如果新语言逼所有人重写旧代码，它注定失败；保持兼容让 C++ 一夜之间继承了海量 C 代码资产。

**③ 怎么用**
把一段纯 C 代码存成 `.cpp` 用 g++ 编译，通常能直接通过：

```cpp
// C 风格代码放入 .cpp 文件——绝大多数情况无需修改即可编译
#include <stdio.h>            // C 的头文件在 C++ 中依然可用
int add(int a, int b) {       // 普通函数，无 C++ 特性
    return a + b;             // 求和并返回
}
int main() {
    printf("%d\n", add(3, 4));// 使用 C 的 printf 输出
    return 0;
}
// 输出：7
```

**④ 注意事项 & 常见错误示范**
关键词是"**几乎**"。少数 C 代码在 C++ 中编译不过，典型反例（详见第三阶段陷阱1）：

```cpp
// ❌ 这段在 C 里合法，在 C++ 里报错！
void* p = malloc(10);
int* q = p;        // C 允许 void* 隐式转任意指针；C++ 不允许，必须显式 (int*)p
```
- "C++ 完全兼容 C"是误解：正确表述是"C 基本是 C++ 的子集，但 C++ 类型检查更严格"。
- 另外 C 标准库某些标识符在 C++ 中意义不同（如 `new`、`class` 是 C++ 关键字，不能作为 C++ 变量名，即使在写 C 风格代码时也不行）。

> 微型总结：C 是 C++ 的子集（"几乎"二字值钱）；兼容是刻意设计的迁移动画；void* 隐式转换是最著名的例外。

### 知识点 5：早期名称"带类的 C"（C with Classes）【熟悉｜P3-P4】

**① 是什么**
一句话定义：课件原文（P3-P4）——"早期并没有 'C++' 这个名字，而是叫做 '带类的 C 语言'。它是作为 C 语言的一个扩展和补充出现的，它增加了很多新的语法，目的是提高开发效率。"

生活化比喻：就像孩子的小名。"带类的 C"像"小明"——直白描述特征（C 加了类）；后来家族人丁兴旺（又加了重载、模板、异常……），小名不够用了，才改名"赵思进"（C++）这个正式大名。

**② 为什么**
最初的目标极其克制：只给 C 补上"类"这一种组织能力（源自仿真语言 Simula），解决"用结构体+函数模拟现实对象太笨拙"的问题。所以早期版本确实"非常粗糙，仅支持简单的面向对象编程"（P4 原文）。

**③ 怎么用**
面试/笔试表述题："C++ 的前身是什么？"答："带类的 C（C with Classes），定位是 C 的扩展和补充，目的是提高开发效率。"

**④ 注意事项**
- 别把演变顺序说反：先有"带类的 C"，后有 C++ 之名——是语言先长大、名字后跟上，而不是反过来。
- 演变三阶段要背：**带类的 C（仅简单OOP）→ C++（语法日益强大）→ 完善支持面向过程 + OOP + 泛型编程，"几乎成了一门独立的语言，拥有了自己的编译方式"**（P4 原文）。

### 知识点 6：cfront 预处理器的历史角色【熟悉｜P3-P4】

**① 是什么**
一句话定义：课件原文（P4）——早期 C++"没有自己的编译器，而是通过一个预处理程序（名字叫 cfront），先将 C++ 代码 '翻译' 为 C 语言代码，再通过 C 语言编译器合成最终的程序。"

生活化比喻：cfront 像一位"同声传译"。C++ 说的是外语（类、继承），C 编译器只懂中文（函数、结构体），cfront 站在中间把每句 C++ 当场翻成 C，再交给 C 编译器干活。（顺带八卦：cfront 名字来自 "C front-end"，即"C 的前端"。）

**② 为什么**
为什么不直接写一个新编译器？因为造编译器成本极高，而当时 C 编译器已遍布各平台。**复用现成 C 后端**，让 C++ 一出生就能在所有有 C 编译器的机器上运行——这是 C++ 迅速流行、且至今与 C 纠缠不清的历史根源。

**③ 怎么用**
理解历史能解释今天的现象：
- 为什么 C++ 的全局变量、静态成员底层布局仍充满 C 的味道；
- 为什么名字改编（name mangling，把 `func(int)` 编成 `_Z4funci` 之类）在链接时报"LNK2019/unresolved external"往往是因为 C 和 C++ 的符号规则不一致（extern "C" 的用途，后续章节会讲）。

示意一次"cfront 式"翻译（帮助理解，不必深究）：

```cpp
// C++ 源码（你写的）
struct Point { int x, y; void move(int dx) { x += dx; } };
// 概念上 cfront 翻成的 C 代码（编译器生成的效果）
struct Point { int x, y; };                      // 结构体保留
void Point__move(struct Point* self, int dx) {   // 成员函数变普通函数
    self->x += dx;                               // this 指针变显式参数
}
```

**④ 注意事项**
- 现在的 MSVC/GCC/Clang 都是**原生 C++ 编译器**，不再经过 cfront。切勿在面试里说"g++ 先把代码翻译成 C 再编译"——那是 80 年代的事。
- cfront 是"预处理程序 + C 编译器"的两段式流程；现代编译器是一趟流水线（词法→语法→优化→代码生成）。

> 微型总结（模块二上半场）：C 是 C++ 子集靠的是设计取舍；"带类的C"是小名；cfront 是借鸡生蛋的历史外挂。接下来是本章重头戏——⭐⭐⭐ C++ 对 C 的五大改进。

### 知识点 7：C++ 继承 C 语言的全部优点【重点｜P5-P6】

**① 是什么**
一句话定义：课件（P5）"继承自 C 语言"栏原文——C++ 继承了 C 的优点：**语言简洁紧凑、使用方便灵活；拥有丰富的运算符；生成的目标代码质量高、程序执行效率高；可移植性好**。

生活化比喻：这是"富二代继承家产"——祖上（C）打下的四件不动产（简洁、运算符丰富、高效、可移植），C++ 全盘接收且不用重新挣。

**② 为什么**
如果不继承这些，C++ 就失去了对抗既有语言的资本。正因为底子好，才有 P7 那句"运行效率仅比汇编慢 10%~20%"的可能。

**③ 怎么用**
简答题模板："C++ 继承了 C 的哪些优点？"→ 逐条报菜名：简洁灵活 + 运算符丰富 + 目标代码质量高执行效率高 + 可移植性好。

**④ 注意事项**
- 别把"改进"混进"继承"答题里——引用、const、new/delete 属于"改进/扩充"，不属于"继承"。审题分栏要看清。

### 知识点 8：引用（reference）取代部分指针用法【重点｜P5-P6】

**① 是什么**
一句话定义：引用是给变量起的"别名"，声明后与原件共享同一块内存，使用时无需解引用。

生活化比喻：指针像"写着家庭住址的纸条"（用它要先按地址找上门），引用像"本人的小名"——叫阿强、叫强哥、叫老板，都是同一个人，不存在"纸条丢了找不到人"的问题。

**② 为什么**
C 语言传大结构体只能传指针，调用方必须 `&` 取址、被调方必须 `->` 解引用，两步都容易漏、容易错（空指针、野指针）。引用让"间接操作"写得像"直接操作"，更安全也更直观。

**③ 怎么用**（对比 C 写法，并排呈现）

```cpp
// C++ 写法：用引用交换两数——像操作亲儿子
void swap(int& a, int& b) {   // int& 声明引用参数，无需取址语法
    int t = a; a = b; b = t;  // 直接用名字操作实参本体
}
int main() {
    int x = 1, y = 2;         // 两个整数
    swap(x, y);               // 调用处和普通传值一模一样！
    // 此时 x==2, y==1
    return 0;
}
```

```c
/* C 写法：只能传指针——两头都要额外动作 */
void swap(int* a, int* b) {          /* 形参是指针 */
    int t = *a; *a = *b; *b = t;     /* 每次使用都要 * 解引用 */
}
int main(void) {
    int x = 1, y = 2;
    swap(&x, &y);                    /* 调用处必须 & 取址 */
    return 0;
}
```

逐行走读（C++ 版）：
1. `int x = 1, y = 2;`——栈上分配两块 4 字节内存，分别写入 1 和 2；
2. `swap(x, y);`——x 绑定到引用 a、y 绑定到引用 b，**没有拷贝**，a/b 就是 x/y 本身；
3. 函数体内三次赋值——直接改写 x、y 所在内存的值；
4. 返回后 `x==2, y==1`。C 版走读相同，只是 a/b 存的是地址，`*a` 才是间接访问。

编译期/运行期区分：引用的绑定合法性在**编译期**检查（不能不初始化、不能改绑），值的变化发生在**运行期**。

**④ 注意事项 & 常见错误示范**
```cpp
int& r;      // ❌ 编译错误：引用必须声明时初始化
int& r = 1;  // ❌ 非 const 引用不能绑定字面量（临时量），应写成 const int& r = 1;
```
- 引用一旦绑定终身不换（不支持" reseal"）；指针可以随时改指向。
- 没有"空引用"，但有空指针——传引用前不用担心 NULL，传指针前必须判空。

### 知识点 9：const 常量取代 #define 宏定义常量【重点｜P5-P6】

**① 是什么**
一句话定义：`const` 定义的是**真正参与编译期类型检查的具名常量**；`#define` 只是预处理器做的"文本替换"，没有类型。

生活化比喻：`#define PI 3.14` 像全班同学的作文里手工把"圆周率"三个字剪贴成"3.14"——剪错了没人告诉你；`const double PI = 3.14;` 则是发给每人一张盖了钢印的卡片：内容不可涂改，而且登记在册（有类型、有名字、调试器可见、编译器能查错）。

**② 为什么**
宏的三个原罪：①无类型检查；②文本替换产生副作用（见下方反例）；③出错时报错信息里没有宏名只有展开后的乱码，难排查。const 一举解决。

**③ 怎么用**（并排对比）

```cpp
const double PI = 3.14159;   // ✅ 有类型 double，编译期检查，调试器能看到 PI
const int MAXN = 100;        // ✅ 整型常量
```

```c
#define PI 3.14159           /* C 时代做法：纯文本替换，无类型 */
#define SQR(x) ((x)*(x))     /* 函数宏还得小心翼翼加括号 */
```

编译期/运行期区分：`const int MAXN = 100;` 的使用点通常在**编译期**就被常量折叠（等价于直接写 100），而 `#define` 的替换发生在更早的**预处理期**——两者都不占运行期开销，区别在于"谁在把关"：预处理器不会把关，编译器会把关。

**④ 注意事项 & 常见错误示范**
```cpp
#define SQUARE(x) x * x      // ❌ 经典坑宏：看似能用，实则炸弹
int a = SQUARE(2 + 3);       // 展开为 2 + 3 * 2 + 3 == 11，不是你想要的 25！
const int b = SQUARE(a);     // 再展开一次，后果不堪设想
```
- 正确姿势：优先 `const`；确需函数式快速计算改用 `inline` 函数（下一个知识点）。
- `const` 修饰指针有"从左往右读"口诀：`const int* p`（所指内容不可改）、`int* const p`（指针本身不可改）、`const int* const p`（都不可改）。本章只需知道方向感，第4章细讲。

### 知识点 10：内联函数（inline）取代宏定义函数【重点｜P5-P6】

**① 是什么**
一句话定义：`inline` 函数仍是真正的函数——有类型、受编译期检查，但建议编译器把函数体"就地展开"到调用点，从而兼具宏的速度和函数的安全。

生活化比喻：普通函数调用像去餐厅堂食（点单、落座、上菜都有固定流程开销）；宏像直接把菜谱塞你手里回家做（快但没质检）；内联函数则是餐厅推出的"标准化外卖料理包"——中央厨房（编译器）质检过的真菜，同时免去你跑腿（函数调用开销）。

**② 为什么**
C 时代小工具（求最大值、交换）爱用函数宏，图的是避免调用开销；但宏不安全。C++ 给出"既要又要"的方案：inline。这也呼应 P5"扩充 C 语言，如内联函数…"。

**③ 怎么用**（并排对比）

```cpp
inline int max_of(int a, int b) {  // inline 建议就地展开
    return a > b ? a : b;          // 真正的函数：a、b 只做一次求值
}
int main() {
    int i = 1, j = 2;
    int m = max_of(i++, j++);      // 安全：每个实参只求值一次
    // m==2, i==2, j==3
    return 0;
}
```

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))  /* 宏：文本替换 */
int main(void) {
    int i = 1, j = 2;
    int m = MAX(i++, j++);   /* ❌ 展开为 ((i++)>(j++)?(i++):(j++))
                                i/j 被多次求值，结果失控（未定义行为）*/
    return 0;
}
```

逐行走读（C++ 版）：调用 `max_of(i++, j++)` 时，i++、j++ 各执行一次（旧值 1、2 作为实参），比较后返回 2；随后 i、j 各自变成 2、3。宏版本则可能把 i++ 执行两次，得到 3 甚至触发未定义行为——这就是"类型安全 + 单次求值"的价值。

**④ 注意事项**
- `inline` 只是**建议**，编译器可以拒绝（递归、过大函数通常不展开）；现代编译器还会自动内联没写 inline 的小函数。
- inline 函数定义放在头文件中，否则多个 .cpp 包含时链接会报重复定义（ODR 规则的入门级体现，后续章节详述）。
- 别为了"显得快"把所有函数都标 inline——展开会让代码体积膨胀，反而可能变慢（指令缓存命中率下降）。

### 知识点 11：支持面向对象编程——封装、继承、多态（+模板）【重点｜P5-P6】

**① 是什么**
一句话定义：课件 P5"面向对象"栏原文——"同时支持面向过程和面向对象的方法：在 C++ 环境下既可以进行面向对象的程序设计，也可以进行面向过程的程序设计。因此它也具有数据封装和隐藏、继承和多态等面向对象的特征。支持面向对象编程机制，如信息隐藏、封装函数、抽象数据类型、继承、多态、函数重载、运算符重载、泛型编程（模板）。"（注：课件原文写作"乏型编程（模板）"，系"泛型编程"之排版笔误。）

四大术语的生活化比喻：
- **封装 / 信息隐藏**：自动挡汽车——你踩油门就行，不需要懂发动机内部；数据结构和使用规则捆在一起，外面捅不进去。
- **继承**：电动车继承燃油车的方向盘、刹车逻辑，再加一块电池——复用父辈的，扩展自己的。
- **多态**：同样喊一声"开始表演"，歌手唱、舞者跳、魔术师变兔——同一接口，各自反应。
- **模板（泛型编程）**：一个万能模具，浇铁是铁零件、浇塑料是塑料零件——算法写一遍，类型随便换。

**② 为什么**
面向过程写小程序没问题，写大程序时数据和操作数据的函数散落一地，改一处崩三处。OOP 把"数据+操作"捆绑成对象，用封装隔离变化、用继承复用共性、用多态隔离接口与实现——这正是 P8"可重用性、可扩充性、可维护性和可靠性等方面都较 C 语言得到了提高"的来由。

**③ 怎么用**（最小完整示意，第3章起正式编写运行）

```cpp
#include <iostream>
class Dog {                       // 封装：数据私有
private:
    int age_;                     // 内部状态，外人改不了
public:
    explicit Dog(int a) : age_(a) {}   // 构造时校验
    void set_age(int a) { if (a >= 0 && a <= 30) age_ = a; } // 对外接口
    virtual void speak() const { std::cout << "Woof!\n"; }   // 虚函数：多态入口
};
class Puppy : public Dog {        // 继承：获得 Dog 的一切
public:
    Puppy() : Dog(1) {}
    void speak() const override { std::cout << "Yip!\n"; }   // 多态：覆盖行为
};
int main() {
    Dog* d = new Puppy();         // 父类指针指向子类对象
    d->speak();                   // 运行时决定调用哪个 speak
    delete d;
    return 0;
}
// 输出：Yip!
```

编译期/运行期区分（本例是绝佳教材）：
- **编译期**：`Dog* d = new Puppy();` 能通过，因为 Puppy 是 Dog 的子类（类型检查）；`override` 拼错会被编译器当场抓住。
- **运行期**：`d->speak()` 打印 Yip 还是 Woof，要到程序跑起来查虚函数表才知道——**多态是运行期决定的**，而模板是编译期生成代码的（同一套语法，两种时机，务必分清）。

**④ 注意事项**
- 最大误区（也就是本章陷阱2）：以为 C++ = OOP。课件明说 C++"同时支持面向过程和面向对象"，还支持泛型编程；后续 lambda、移动语义等更是如虎添翼。**会用类不等于会 C++**。
- 上面的 `new`/`delete` 请留意——它们正是下一个知识点的主题；现代 C++ 实践中更推荐智能指针/容器管理内存（后续章节展开），本章先用裸 new/delete 演示语言机制。

### 知识点 12：new / delete 动态内存管理，取代 malloc / free【重点｜P5-P6】

**① 是什么**
一句话定义：课件 P5"扩充 C 语言"栏——"更灵活、方便的内存管理（new、delete）"。`new` 一步完成"分配内存 + 调用构造函数"，`delete` 一步完成"调用析构函数 + 释放内存"；malloc/free 只是 C 库函数，只会搬字节、不认识对象。

生活化比喻：malloc 像毛坯房中介——只管把地给你圈出来（给一堆无类型字节），水电家具（初始化）自己搞；new 是全精装交付——不仅给你房子，还按你的户型图（构造函数）把家具装好；delete 退租时会先把装修拆回原样（析构函数），再交还地基。

**② 为什么**
C++ 有了对象，对象就有"出生仪式"（构造）和"临终仪式"（析构）。malloc 根本不知道类型的存在，无法调用构造/析构；new/delete 与类型系统绑定，还能返回正确类型的指针（配合知识点4提到的 void* 限制，形成闭环）。

**③ 怎么用**（并排对比 + 栈/堆布局图）

```cpp
// C++ 写法
int* p = new int(42);   // 分配 4 字节并初始化为 42；若失败抛 bad_alloc
delete p;               // 销毁并释放，p 成为悬空指针
p = nullptr;            // 好习惯：置空防误用
```

```c
/* C 写法 */
int* p = (int*)malloc(sizeof(int));  /* 手动算大小、手动转型 */
*p = 42;                             /* 手动初始化 */
free(p);                             /* 只释放，不调任何"仪式" */
p = NULL;
```

对于类对象，差异更致命：

```cpp
class Widget {
public:
    Widget()  { /* 构造：申请资源 */ }
    ~Widget() { /* 析构：归还资源 */ }
};
Widget* w = new Widget();  // ✅ 自动调用 Widget::Widget()
// Widget* x = (Widget*)malloc(sizeof(Widget));  // ❌ 只拿到裸内存，构造函数从未运行
delete w;                  // ✅ 自动调用 ~Widget() 后再 free
```

逐行走读 `int* p = new int(42);`：
1. 运行期：向堆（heap）申请至少 sizeof(int)==4 字节；
2. 成功后在该地址写入 42（构造语义）；
3. 把该地址赋给栈上的指针变量 p（p 本身占 8 字节@64位平台）；
4. `delete p;`：运行期调用销毁逻辑并把内存还给堆，**p 的地址值仍在，但它已无效**（悬空指针）；
5. `p = nullptr;` 把 p 归零，之后误用会立刻崩溃暴露问题，好过悄悄写坏别人数据。

ASCII 栈/堆布局图（执行 `int n = 1; int* p = new int(42);` 之后某一刻）：

```
        低地址
  ┌──────────────────────────┐
  │  栈区 stack              │   ← 局部变量自动进出，函数返回即回收
  │  ┌────┬────┬─────────┐   │
  │  │ n=1│ p=0x…A00     │   │   n 直接住在栈里
  │  └────┴──┬───┴─────────┘   │
  │          │ p 里存的值是一个地址
  ├──────────┼────────────────┤
  │          ▼                │
  │  堆区 heap（new 的地盘）   │   ← 程序员手动管理，生命周期自由
  │  ┌───────────────┐        │
  │  │ 0x…A00: 42    │        │   *p 指向的对象住在这里
  │  └───────────────┘        │
  ├──────────────────────────┤
  │  全局/静态区 data          │
  ├──────────────────────────┤
  │  代码区 text               │
  └──────────────────────────┘
        高地址
```
标注要点：`n`、`p` 是局部变量→栈；`new int(42)` 出来的对象→堆；只有 `delete` 之后堆空间才归还，忘了 delete 就是内存泄漏。

**④ 注意事项 & 常见错误示范**
- `new` 配 `delete`、`new[]` 配 `delete[]`、malloc 配 free——交叉使用是未定义行为（数组版本还要逐个调用析构）。
- 忘记 delete → 内存泄漏；delete 后用 → 悬空指针；delete 两次 → 堆结构破坏，三者都是 C++ 新手三大杀手。
- malloc 失败返回 NULL 要判空；new 失败默认**抛异常**（不返回 NULL），除非用 `new(std::nothrow)`。

> 微型总结（模块二收官）：三大改进=「引用代指针、const代宏、inline代define」，加上「OOP四件套（封装/继承/多态/模板）」与「new/delete代malloc/free」。C++ 对 C 是继承+改进+面向对象+扩充四管齐下。

## 模块三：C++ 语言特点与应用（对应课件 P7-P13）

### 知识点 13：C++ 保留 C 精华的同时支持 OOP 范式【熟悉｜P7】

**① 是什么**
一句话定义：课件 P7 原文——"C++ 语言既保留了 C 语言的有效性、灵活性、便于移植等全部精华和特点，又添加了面向对象编程的支持，具有强大的编程功能，可方便地构造出模拟现实问题的实体和操作；编写出的程序具有结构清晰、易于扩充等优良特性，适合于各种应用软件、系统软件的程序设计。"

生活化比喻：一辆改装车——底盘、发动机（C 的效率与控制力）原厂保留，变速箱换成手自一体（OOP 范式），既能下赛道也能上下班。

**② 为什么**
"混合型语言"（P1 定性）的最大好处：不为范式牺牲性能，不为性能放弃组织大型代码的能力。项目里既可以写纯过程式热点代码榨性能，也可以用类管理架构。

**③ 怎么用**
答题句式："C++ = C 的全部精华 + 面向对象支持 → 程序结构清晰、易于扩充 → 适合应用软件与系统软件两类场景。"

**④ 注意事项**
- "混合"不等于"缝合怪"：两种范式要在合适的层级使用——用类搭架构、用过程式抠性能，而不是在每个函数里纠结用不用对象。

### 知识点 14：C++ 可读性好、代码质量高的原因【熟悉｜P7-P8】

**① 是什么**
一句话定义：课件 P7——"用 C++ 编写的程序可读性好，生成的代码质量高"；P8——"C++ 程序在可重用性、可扩充性、可维护性和可靠性等方面都较 C 语言得到了提高，使其更适合开发大中型的系统软件和应用程序。"

生活化比喻：C 代码像满墙手写便签，能干活但三个月后没人看得懂；C++ 的类、命名空间、RAII 像归档柜＋标签机——代码第一次是给人读的，顺便让机器执行。

**② 为什么**
可读/高质量的制度性来源：①更强的类型系统（const、引用、枚举类）让编译器帮你记录意图；②封装让读者不必通读全库就能理解一个模块；③名字空间解决大规模项目的命名冲突；④重载让同名操作表达同一语义。

**③ 怎么用**
写代码时自检三连："这个名字能否说明意图？这个数据能否藏起来？这个不变量能否交给类型保证？"

**④ 注意事项**
- 可读性不是语言白送的，是纪律换来的。C++ 同样能写出天书（滥用宏、魔鬼数字、超长函数）——语言给你工具，不替你负责。

### 知识点 15：运行效率仅比汇编慢 10%~20% 的原因【熟悉｜P8】

**① 是什么**
一句话定义：课件 P8（"C++语言特点"第二页）原文——"用 C++ 编写的程序可读性好，生成的代码质量高，运行效率仅比汇编语言慢 10%～20%。"

生活化比喻：顶级厨师（手写汇编老师傅）切土豆丝确实最快，但一台全自动切菜机（优化的 C++ 编译器）24 小时不休息、刀刀均匀，产量逼近甚至超过人类。C++ 就是那台"接近人工极限、但人人都能开"的机器。

**② 为什么**
三个原因层层递进：
1. C++ 语义离硬件近（指针≈地址、对象布局明确），映射到机器指令几乎没有中间损耗；
2. 现代编译器（GCC/Clang/MSVC 开 `-O2`）做了大量人工不可能完成的微优化（寄存器分配、循环展开、自动向量化、内联展开）；
3. P8 的设计原则兜底："**C++ 不使用会带来额外开销的特性**"——不用的特性就不为你付出代价（zero-overhead 哲学），所以你不会被语言本身拖慢。

```cpp
// 演示：编译器优化可以把简单循环整个折叠（编译期常量传播）
int sum_1_to_100() {
    int s = 0;
    for (int i = 1; i <= 100; ++i) s += i;  // 看似运行期累加
    return s;                                 // -O2 下常被优化为直接 return 5050
}
```

**④ 怎么用**
解释"为什么高性能领域选 C++ 而不是 Java/Python"时引用这句话（第四阶段第4题要用）。

**⑤ 注意事项**
- 10%~20% 是课件给出的经验量级，指"合理写法的 C++ vs 熟练手写汇编"，并非每个程序都如此；糟糕的 C++（无谓拷贝、频繁 new/delete）可以比好 Java 还慢。
- 别忘了另一面：Java/Python 有 JIT/GC 停顿的不确定性，金融高频、游戏帧同步等场景恰恰要避开这些"看不见的开销"。

### 知识点 16：C++ 的设计目标清单（静态类型、多用途、与C兼容等）【熟悉｜P8】

**① 是什么**
一句话定义：课件 P8 列出 C++ 的八条设计目标（原文照录，背诵版）：
1. C++ 设计成**静态类型**、和 C 同样高效且可移植的**多用途**程序设计语言；
2. C++ 设计成直接的和广泛的支援**多种程序设计风格**（程序化程序设计、资料抽象化、面向对象程序设计、泛型程序设计）；
3. C++ 设计成给程序设计者**更多的选择**，即使可能导致程序设计者选择错误；
4. C++ 设计成**尽可能与 C 兼容**，籍此提供一个从 C 到 C++ 的平滑过渡；
5. C++ **避免平台限定**或没有普遍用途的特性；
6. C++ **不使用会带来额外开销的特性**；
7. C++ 设计成**无需复杂的程序设计环境**。

生活化比喻：一把瑞士军刀的设计说明书——刀型齐全（多用途、多风格）、不和螺丝刀抢活（避免无通用性特性）、收在口袋里不额外负重（不用即零开销）、拆开包装就能用（不需复杂环境）。

**② 为什么**
"静态类型"= 编译期抓错，配合第15点"不给额外开销"，正好构成 C++ 的两阶段世界观：**能在编译期确定的绝不留到运行期**（类型检查、模板实例化、const 折叠都在编译期；虚函数分发、new 分配在运行期）。"给程序设计者更多选择，即使可能导致选择错误"——这是 C++ 与 Java/Python 气质分野：它信任你，也放任你（power comes with responsibility）。

**③ 怎么用**
默写测试：遮住上面列表，回忆七条。面试问"C++ 的设计目标"能背出 4 条以上即超越多数候选人。

**④ 注意事项**
- 别把"静态类型"理解成"不能转型"——`static_cast`/`dynamic_cast` 等仍受编译期约束，区别于脚本语言的鸭子类型。
- "无需复杂的程序设计环境"在课件语境里指语言本身不依赖庞大运行时（对比 JVM/Python 解释器），实际工程中 IDE/构建系统仍然重要。

> 微型总结：模块三上半场——C++ 的卖点是"C 的马力 + 工程的护栏"，效率比汇编只慢一档，设计目标七条定生死。下半场看点：这门语言用在哪儿、排老几。

### 知识点 17~25：九大应用领域【了解｜P10-P12】

总纲（P10 原文）："**C++ 的应用领域主要是在服务器类，需要操作硬件类或者说对性能要求高的等方向。**"

#### 17. 服务器端开发
课件：很多游戏或互联网公司的后台服务器程序基于 C++ 开发，大部分跑在 Linux 上；想入行需熟悉 Linux 操作系统及其上的开发、熟悉数据库开发、精通网络编程。
比喻：C++ 是后厨主灶——顾客看不见它，但整桌菜（每秒百万请求）全靠它颠勺。

#### 18. 游戏
课件：目前很多游戏客户端基于 C++ 开发（除了一些网页游戏可能不是）；该领域要学的东西较多，比如计算机图形、多媒体处理。
比喻：游戏引擎是 F1 赛车，C++ 是唯一能拧到毫米级扭矩的扳手——每一帧 16.6ms 的预算必须手动精算。

#### 19. 虚拟现实（VR）
课件：这个领域一直在发展，目前 VR 眼镜比较火，需要大量基于这些的 C++ 开发。
比喻：VR 是"实时渲染界的杂技"——头动画面必须在 20ms 内跟上，慢一拍你就晕，只有贴近硬件的语言敢接这活。

#### 20. 数字图像处理
课件举例：像 AutoCAD 的系统开发、像 OpenCV 的视觉识别等等。
比喻：千万像素 × 每秒 60 次 = 每秒六亿次像素运算，Python 调 C++ 库（OpenCV 底层就是 C++）正说明脏活累活谁在干。

#### 21. 科学计算
课件：在科学计算领域 FORTRAN 是使用最多的语言之一；但近年来 C++ 凭借先进的数值计算库、泛型编程等优势在这一领域应用颇多。
比喻：FORTRAN 是老字号中药铺，C++ 是新派实验室——配方（数值库）更好、抓药手法（模板元编程）更巧，客人自然分流过来。

#### 22. 网络软件
课件：C++ 拥有很多成熟的用于网络通信的库，其中最具代表性的是跨平台、重量级的 **ACE 库**——"该库可以说是 C++ 语言最重要的成果之一，在许多重要的企业、部门甚至是军方都有应用"；并举例 GOOGLE 的 chrome 浏览器就是用 C++ 开发。
比喻：ACE 像海运集装箱标准——一套箱子（跨平台网络组件）装遍企业、政府、军舰的货。

#### 23. 操作系统
课件：该领域主要使用的编程语言是 C 语言；但 C++ 凭借其对 C 的兼容性、面向对象性质，也开始在该领域崭露头角。
比喻：OS 是自家地基，房东（内核开发者）只信老木匠 C；手艺更全的 C++ 刚被允许进门打下手（如 Windows/DragonFly 内核部分模块、驱动框架）。

#### 24. 设备驱动程序
课件：也是因为效率的原因（贴近硬件、直接操作寄存器、开销可控）。
比喻：司机（驱动）离合踩得准不准直接决定车（外设）抖不抖——这里没有 GC 停车的余地。

#### 25. 其他领域
课件：分布式应用、移动（手持）设备、嵌入式系统、教育与科研与部分行业应用等。
比喻：嵌入式芯片算力捉襟见肘，恰是 C++"不用即零开销"的主场；手机 App 的音视频内核、数据库引擎、交易撮合引擎也都是这批"隐形冠军"。

**注意事项（合并）**
- 【了解】级别的答法：能说全九大方向名称 + 每个举一个例子即可，不必展开原理。
- 易错：操作系统领域**主角仍是 C**，C++ 只是"崭露头角"——答题别吹过头。

> 微型总结：C++ 的地盘 = 服务器 + 硬件 + 高性能；记九城：服务、游戏、VR、图像、科计、网络、OS、驱动、其他。

# 第三阶段：补

## 常见陷阱专题（3 个最易错点）

### 陷阱 1："C++ 完全兼容 C"的误解
反例代码——C 里合法，C++ 里直接报错：

```cpp
// ❌ C++ 编译错误：void* 不能隐式转换为其他指针类型（C 可以）
void* mem = operator new(4);   // 假设拿到了原始内存指针
int*  p   = mem;               // C 允许；C++ 报错 error C2440 / invalid conversion

// ✅ C++ 必须显式转换
int* q = static_cast<int*>(mem);   // 或者 C 风格 (int*)mem
```
另一个高频反例：C 里 `struct Foo {...}` 后可直接 `Foo f;` 吗？在 C 里必须写 `struct Foo f;`，C++ 里才可以省 `struct`——方向相反的不对称，说明两者只是"高度兼容"而非"完全等同"。此外 C99 的 VLA（变长数组）在 C++ 中从来不是标准特性。

### 陷阱 2："C++ 只是 C 加了类"的片面认知
课件 P4 早已剧透终局："已经能够很完善的支持**面向过程编程、面向对象编程（OOP）和泛型编程**"。现代 C++ 还叠加了函数式风格（lambda）、移动语义、并发库、元编程（模板特化/constexpr）。一句话：**C++ 是一门多范式语言，OOP 只是其中一柱**（呼应知识点 16 第 2 条设计目标）。

### 陷阱 3：忽视 C++ 标准版本差异
C++98/03 → 11 → 14 → 17 → 20 → 23 差异巨大（auto、lambda、智能指针、协程、模块……一代一新）。初学建议以 **C++11 为底线、C++17 为基准**练习（本书后续章节将按此口径演示）；网上抄来的代码若含 `#include <ranges>`、`std::format` 等新特性，老环境编译不过属正常，先看清版本再动手。

## 面试高频考点提醒（三题标准答案关键词）

1. **"C++ 与 C 的区别有哪些？"**
 答题框架：①关系——C 基本是 C++ 子集，C++ 在其上继承+改进+扩充；②范式——C 面向过程，C++ 多范式（OOP+泛型+过程）；③类型安全——C++ 更强类型检查（void* 不许隐式转）、const/引用替代宏与裸指针；④内存——new/delete 与构造析构绑定 vs malloc/free 只管字节；⑤标准库——iostream 体系与 STL。
2. **"为什么说 C++ 是 C 的超集？"**
 关键词："几乎不用修改就能以 C++ 方式编译"（P3 原文）+ 主动补一句"但不严格：void* 隐式转换等例外使它在集合论意义上更接近'超集但有边角差异'"——展示你知道"几乎"二字的分量。
3. **"new/delete 和 malloc/free 有什么区别？"**
 ①语言层面：new/delete 是运算符（可重载），malloc/free 是库函数；②构造析构：new 调用构造函数、delete 调用析构函数，malloc/free 完全无感知；③类型：new 返回具体类型指针，malloc 返回 void*；④大小：new 自动 sizeof，malloc 手算；⑤失败行为：new 默认抛 bad_alloc，malloc 返回 NULL；⑥释放：delete 与 new[]/delete[] 配对规则。

**第1题**：Bjarne Stroustrup（及其同事）；20 世纪 80 年代；AT&T 贝尔实验室。"++"取自 C/C++ 的自增运算符，双关"C Plus Plus = 在 C 基础上 +1（增加新特性）"。

**第3题**（任答五条）：①继承 C 全部精华（简洁灵活、运算符丰富、高效、可移植）；②同时支持面向过程与面向对象（混合型）；③可读性好、代码质量高，可重用/可扩充/可维护/可靠性提升，适合大中型软件；④运行效率仅比汇编慢 10%~20%；⑤静态类型、多用途、与 C 尽量兼容；⑥不用即零开销、避免平台限定特性、无需复杂环境。

**第4题** 参考对比表：

| 维度 | C++ | Java | Python |
|------|-----|------|--------|

## 代码审查题（为第3章预热）

下面的 Hello World 埋了若干 bug，先自行找出并改正，再对照修订版：

```cpp
#include <iostrem>                 // bug1?
using namespace std;
Main() {                           // bug2?
    cuton << "Hello, C++!" << endl
```

<details>
<summary>bug 清单与修正</summary>

1. `<iostrem>` 拼写错误 → `<iostream>`；
2. `Main()` 大小写错误，入口必须是 `main()`，且应写返回类型 `int`；
3. `cuton` 拼写错误 → `cout`；
4. `cout << ... << endl` 行末缺分号；
5. `reutrn` 拼写错误 → `return`。

修正版：

```cpp
#include <iostream>            // 标准输入输出流头文件
using namespace std;           // 使用标准名字空间（初学阶段可用，工程建议显式 std::）
int main() {                   // 入口函数：返回类型 int，函数名小写 main
    cout << "Hello, C++!" << endl;  // 输出并换行，行尾分号不可少
    return 0;                  // 0 表示程序正常退出
}
// 输出：Hello, C++!
```
</details>

## 3. 课件示例逐行走读
本章无配套代码文件。课件 P5-P6 改进点对应的示例代码已全部在上文知识点 8~12 中逐行走读（含每条语句执行后变量值与内存状态变化、栈/堆 ASCII 布局图）。另附一个综合演示：

```cpp
#include <iostream>   // 引入输出流
using namespace std;
const int LIMIT = 3;             // 编译期常量：上限3
inline bool ok(int n) { return n <= LIMIT; }  // 内联检查函数
void bump(int& r) { ++r; }       // 引用参数：直接改实参
int main() {
    int count = 0;               // 栈变量，初值0
    int* heap = new int(count);  // 堆对象，拷贝count当前值0
    while (ok(count)) {          // 运行期循环：count为0,1,2,3时均满足<=LIMIT
        bump(count);             // 栈上 count 依次变 1,2,3,4（共4轮）
    }
    cout << *heap << "," << count << endl;  // 输出 0,4
    delete heap;                 // 归还堆内存
    heap = nullptr;              // 防悬空
    return 0;
}
// 输出：0,4
```
走读（逐步跟踪）：
1. `int count = 0;`——栈上分配 4 字节，值为 0；
2. `new int(count)`——堆上分配 4 字节并**拷贝** count 当时的值 0。注意：这是副本，此后与 count 再无关联；
3. 循环判定链：ok(0)真→bump→count=1；ok(1)真→bump→count=2；ok(2)真→bump→count=3；ok(3)真（因 LIMIT==3，3<=3 成立）→bump→count=4；ok(4)假→退出。共执行 **4 次** bump；
4. `cout << *heap << "," << count`——`*heap` 是堆中从未被改动过的 0，count 是 4；
5. `delete heap; heap = nullptr;`——归还堆内存并把栈上的指针置空，防悬空。
// 输出：0,4
这个例子的教学点：堆里的副本与栈上原件从此各过各的日子（值语义拷贝），以及"边界条件 ok(3) 仍为真"这类 off-by-one 陷阱必须靠逐行走读才能暴露。

## 5. 易错点速查卡（四列）

| 错误现象 | 错误原因 | 正确写法 | 后果 |
|----------|----------|----------|------|
| `error: invalid conversion from 'void*' to 'int*'` | 误以为 C++ 完全兼容 C | `static_cast<int*>(ptr)` | 编译失败，迁移C代码受阻 |
| `SQUARE(2+3)` 结果 11 而非 25 | 宏无括号，文本替换优先级错乱 | 改用 inline 函数 | 隐蔽的逻辑错误，难以排查 |
| 传 `int*` 却忘判空导致段错误 | 指针可为 NULL，引用不可为空 | 参数用 `int&` | 程序崩溃（运行期才炸） |
| `new` 的对象忘了 `delete` | 堆内存手动管理 | RAII/及时 delete 并置 nullptr | 内存泄漏，越跑越慢直至OOM |
| `delete p; *p = 1;` | 悬空指针继续用 | delete 后置 nullptr | 未定义行为，随机作恶 |
| `new int[10]` 配 `delete p` | 数组与非数组配对错误 | `delete[] p` | 元素析构不全/堆破坏 |
| `int& r;` 编译错误 | 引用未初始化 | `int& r = x;` | 编译失败 |
| 成员函数忘写 `virtual` 期待多态 | 基类指针按静态类型分发 | 基类声明 `virtual`，子类 `override` | 调到父类版本，行为不符预期 |
| malloc 出来的"对象"直接当对象用 | 构造函数从未执行 | 改用 `new` | 读到脏内存，状态非法 |
| 用 C 编译器(gcc)编译 .cpp | 编译器与语言不匹配 | 用 g++/clang++/MSVC | 大量语法错误刷屏 |

## 7. 新手最常问的 5 个问题

**Q1：我先学 C 再学 C++，还是直接学 C++？**
直接学 C++。C++ 已包含 C 的用法（P3"子集"关系），先学 C 反而会养成 malloc、#define 宏等在本课程知识点 8~12 里要被"取代"的坏习惯。

**Q2：C++ 这么老，还值得学吗？**
TIOBE 常年前四（本章 P13 第4名），且游戏、数据库、自动驾驶、AI 推理引擎（底层框架多为 C++）仍严重依赖它——它不是夕阳语言，是"基础设施语言"。

**Q3：第一章一个程序都没写，有什么用？**
本章给你的是地图：知道引用/const/new 各自替代什么、OOP 四大件是什么，第3章起每学一个语法你就能对上坐标，学习会变成"填空"而不是"猜谜"。

**Q4：`.c` 和 `.cpp` 后缀到底差在哪？**
后缀告诉编译器按哪套语法规则解读源码：`.c` 用 C 规则（void* 可隐式转、无类），`.cpp` 用 C++ 规则（更严格的类型检查+全部新特性）。

**Q5：要不要现在就装 Visual Studio？**
可以装（下一节课预告正是"C++程序的集成开发环境介绍"），但本章重在认知框架，装环境不急于一时。
