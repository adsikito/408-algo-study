# 模块一：模板基础认知（P4-P13）

## 知识点1：模板概述（P4）【了解】

**①是什么**：模板是 C++ 的另一种代码重用机制（与继承并列）——几个类/函数功能相同、只是操作的数据类型不同时，设计一个模板即可通用。模板是 STL 各种组件的基础。

**生活化比喻**：模板就像**月饼模具**——模具本身不是月饼，但换不同馅料就能压出各种月饼；模板本身不是函数/类，但给定不同就能生成不同的函数/类。

**②为什么**：需要一个数组类，可能是 int 数组、double 数组、string 数组……逐个设计一遍是重复劳动。模板提高代码可用性、减少开发量。

**模板与继承的分工**：继承是纵向复用（父子 is-a 关系），模板是横向复用（同逻辑不同类型）。

> 人话总结：模板 = 一份逻辑，任意类型。

## 知识点2：函数模板（P5-P9）【重点】

**①是什么**：函数模板让我们生成通用函数：接受任意数据类型的参数、返回任意类型的值，而无需对每种类型都做函数重载。两种等价原型（课件原文）：

```
template <class identifier> function_declaration;
template <typename identifier> function_declaration;
```

**格式**（T 代表一种类型）：

```
template<typename T1, typename T2, ..., typename Tn>
返回类型 函数名(参数列表)
{
    // 函数体
}
```

**②为什么**（课件 P8-P9 Swap 案例）：要交换两个数，没说是整数还是小数——

**重载版本**（代码重复）：

```cpp
void Swap(int& x, int& y) {      // 交换两个整型
    int tmp = x; x = y; y = tmp;
}
void Swap(double& x, double& y) { // 交换两个双精度浮点型
    double tmp = x; x = y; y = tmp;
}
```

问题（课件原文）：重载的多个函数仅仅类型不同，代码复用率低；出现新类型就要新增重载函数，可维护性低。

**模板版本**（一份代码全搞定）：

```cpp
#include <iostream>
using namespace std;
template<typename T>          // 或 template<class T>
void Swap(T& x, T& y) {
    T tmp = x;
    x = y;
    y = tmp;
}
int main() {
    int a = 1, b = 2;
    Swap(a, b);                // T 推演为 int
    cout << a << " " << b << endl;     // 输出：2 1
    double c = 1.5, d = 2.5;
    Swap(c, d);                // T 推演为 double
    cout << c << " " << d << endl;     // 输出：2.5 1.5
    return 0;
}
```

**函数模板 vs 函数重载对比表**（结合 Swap 案例）：

| 对比维度 | 函数重载 | 函数模板 |
|----------|----------|----------|
| 代码量 | 每种类型一份，重复多 | 一份模板通用 |
| 新增类型时 | 要新增重载函数 | 零改动，自动实例化 |
| 编译器处理 | 按参数匹配现有函数 | 按实参类型生成新函数 |
| 类型安全 | 精确匹配，安全 | 生成代码依赖类型支持的运算 |
| 适用场景 | 不同类型的不同逻辑 | 同逻辑不同类型 |

**④注意事项**：

```cpp
// 错误示范：模板里用了 T 不支持的运算
template<typename T>
void print(T x) { cout << x << endl; }
// 传入没有重载 << 的自定义类 → 实例化时编译报错
```

> 人话总结：一份 Swap 模板，交换万物。

## 知识点3：函数模板的原理（P10-P13）【熟悉】

**①是什么**（课件原文）：函数模板本身并不是函数，是编译器用使用方式产生特定具体类型函数的**模具**。模板把本来应该让程序员做的重复事情交给了编译器。

**生活化比喻**：编译器像自动翻译官——你写一份"通用配方"，它根据你给的食材（实参类型）自动翻译出专属菜谱（具体函数）。

**实例化过程可视化**（编译器三阶段）：

```
源码：change(a, b)，其中 a、b 是 int
  ① 类型推演：编译器看实参类型 → 确定 T = int
  ② 代码生成：把模板体中的 T 全部替换为 int，生成
        void change(int& x, int& y) { int temp; ... }
  ③ 地址分配：新函数有独立入口地址，与 double 版本互不相同
调用 change(c, d)（double）→ 重复上述流程，生成另一份
        void change(double& x, double& y) { ... }
结论：一份模板，多份实例，地址各不相同
```

**③怎么用**（课件 change 案例）：

```cpp
#include <iostream>
using namespace std;
template<typename T>
void change(T& x, T& y) {
    T temp;
    temp = x;
    x = y;
    y = temp;
}
int main() {
    int a = 100, b = 200;
    change(a, b);
    cout << a << "  " << b << endl;      // 输出：200  100
    double c = 1.112, d = 23.12;
    change(c, d);
    cout << c << "  " << d << endl;      // 输出：23.12  1.112
    return 0;
}
```

> 人话总结：模板是模具，编译器替你压代码。

# 模块二：模板核心应用（P11-P19）

## 知识点4：函数模板的实例化（P11-P12）【重点】

**①是什么**：用不同类型的参数使用模板，称为模板的实例化。分两种：
- **隐式实例化**：让编译器根据实参推演模板参数的实际类型；
- **显式实例化**：在函数名后用 `<>` 直接指定类型，如 `add<int>(n1, n2)`。

**③怎么用**（课件 add 案例）：

```cpp
#include <iostream>
using namespace std;
template<class T>
T add(T& v1, T& v2) {
    return v1 + v2;
}
int main() {
    int n1 = 100, n2 = 200;
    int n3 = add(n1, n2);       // 隐式：推演 T = int；输出 300
    cout << n3 << endl;
    double d1 = 1.23, d2 = 2.34;
    double d3 = add(d1, d2);    // 隐式：推演 T = double；输出 3.57
    cout << d3 << endl;
    // double d4 = add(n1, d2); // 错误！编译器一般不会做类型转换，int+double 推导失败
    return 0;
}
```

**类型推导规则详解**：编译器从每个实参类型反推 T；当多个实参都要推导同一个 T 却类型不一致（int vs double）时，推导**冲突失败**——编译器不会自动把 int 转成 double 来迁就模板（那是隐式转换，模板推导不做）。

**两种解决方案**：

```cpp
// 方案1：多模板参数（课件 P12 的解法）
template<class T, class H>
T add(T& v1, H& v2) {      // T 和 H 各自推演
    return v1 + v2;
}
// 方案2：显式指定模板参数
double d4 = add<double>(n1, d2);   // 强制 T = double，n1 隐式转换为 double
```

**④注意事项**：

```cpp
// 错误示范：单模板参数传不同类型
template<class T> T add(T& v1, T& v2) { return v1 + v2; }
int n = 1; double d = 2.0;
// add(n, d);   // 编译错误：T 推导冲突
```

> 人话总结：隐式靠推导，冲突显式定，或加第二个参数。

## 知识点5：类模板（P14-P16）【重点】

**①是什么**：类模板让一个类拥有基于通用类型的成员，而不需要在定义类时确定具体数据类型。

**格式**：

```
template<class T1, class T2, ..., class Tn>
class 类模板名
{
    // 类内成员声明
};
```

**③怎么用**（课件 Pair 案例——存储两个任意类型元素）：

```cpp
template <class T>
class Pair {
    T values[2];
public:
    Pair(T first, T second) {
        values[0] = first;
        values[1] = second;
    }
};
```

**类模板成员函数类外定义**（课件 Test 案例，语法重点）：

```cpp
#include <iostream>
using namespace std;
template<class T>
class Test {
    // 普通类：类名就是类型；类模板：类名不是类型，Test<T> 才是类型
public:
    Test() {}
    void setData(const T& x);   // 类里声明
    void showDate();
private:
    T num;
};
template<class T>               // 类外定义必须带模板参数列表！
void Test<T>::setData(const T& x) {
    num = x;
}
template<class T>
void Test<T>::showDate() {
    cout << num << endl;
}
int main() {
    Test<int> t1;
    t1.setData(100);
    t1.showDate();              // 输出：100
    return 0;
}
```

**类模板特化补充**（针对特殊类型定制）：

```cpp
template<class T>
class MyCompare {
public:
    bool eq(T a, T b) { return a == b; }
};
// 针对 string 的特化：比较时忽略大小写的特殊逻辑
template<>
class MyCompare<std::string> {
public:
    bool eq(std::string a, std::string b) {
        // 特殊处理：比如转小写后比较
        return a.size() == b.size();
    }
};
```

语法：`template<> class 类名<具体类型> { ... };` ——通用模板管大多数，特化管"需要开小灶"的类型。

**④注意事项**：

```cpp
// 错误示范1：类模板当类型直接用
// Test t1;          // 错！Test 不是类型，Test<int> 才是
// 错误示范2：类外定义忘加模板前缀
// void Test<T>::setData(const T& x) {}   // 错！编译器不认识 T
```

> 人话总结：类模板带尖括号才是类型，类外定义带前缀。

## 知识点6：类模板实例化（P17-P18）【重点】

**①是什么**：类模板实例化要在模板名后加 `<>`，把实例化的类型放进去：`类模板名<具体类型> 对象名(构造参数);`

**与函数模板的关键区别**：函数模板可以靠实参自动推导；**类模板的 `<>` 不能省略**（C++17 前不支持类模板参数推导，CTAD 属于进阶内容）。

**③怎么用**（课件案例，注意课件把 Pair 拼成 Pari，正确拼写如下）：

```cpp
Pair<int> myInt(1, 2);          // 实例化为 int 版本
Pair<double> myFloat(1.1, 2.2); // 实例化为 double 版本
```

**编译器实例化过程**：看到 `Test<int>` → 把模板体中所有 T 替换为 int → 生成一个真正的类 `Test<int>`（含 `void setData(const int&)` 等）→ 再按普通类创建对象。`Test<double>` 则是另一个完全独立的类。

> 人话总结：类模板实例化，尖括号里写类型。

## 知识点7：模板别名（P19-P20）【重点】

**①是什么**：给复杂的类型名起短名字。两种机制：
- `typedef`：只能为**具体类型**（已实例化的）起别名；
- C++11 `using` 模板别名：可以为**模板本身**起别名。

**③怎么用**（课件两段对比）：

```cpp
// 方式1：typedef——只能固定一种类型
typedef Test<int> t;      // t 就是 Test<int>
int main() {
    t t1;                 // 等价于 Test<int> t1;
    t1.setData(100);
    t1.showDate();        // 输出：100
    return 0;
}
```

```cpp
// 方式2：C++11 using——为模板本身起别名，类型仍可换
template <class T>
using t = Test<T>;        // t 成为 Test 的"别名模板"
int main() {
    t<int> t1;            // 等价于 Test<int> t1
    t1.setData(100);
    t1.showDate();        // 输出：100
    return 0;
}
```

**typedef vs using 对比表**：

| 对比项 | typedef | using（C++11） |
|--------|---------|----------------|
| 为具体类型起别名 | ✅ `typedef Test<int> t;` | ✅ `using t = Test<int>;` |
| 为模板本身起别名 | ❌ 做不到 | ✅ `template<class T> using t = Test<T>;` |
| 与模板参数配合 | 需借助模板类间接实现 | 原生支持 |
| 可读性（复杂类型如函数指针） | 声明式难读 | 赋值式直观 |

**④注意事项**：课件原文提醒——如果 typedef 用得太多太长，反而忘了别名是什么意思，"不能叫简化代码，直接是给自己找麻烦"；别名要取得有意义。

> 人话总结：typedef 定死类型，using 别名模板。

## 练习：求数组最大值、最小值、平均值（P21-P22）

**思路**：模板参数 T 表示元素类型；遍历数组维护 max、min、total；size==0 时均值输出 0 防除零；均值用 `total / double(size)` 保留小数。

```cpp
#include <iostream>
using namespace std;
template<typename T>
void MathHelper(T num[], int size) {
    T max = num[0], min = num[0], total = 0;
    for (int i = 0; i < size; i++) {
        if (num[i] > max) max = num[i];
        if (num[i] < min) min = num[i];
        total += num[i];
    }
    cout << "Max  : " << max << endl;
    cout << "Min  : " << min << endl;
    if (size == 0)
        cout << "Mean : " << 0 << endl;
    else
        cout << "Mean : " << total / double(size) << endl;   // 强转 double 保小数
}
int main() {
    int a[10] = { 2,1,3,6,5,8,9,7,11,22 };
    double b[10] = { 2.1,1.5,9.2,10.5,7.5,6.5,5.5,8.2,3.1,4.6 };
    MathHelper<int>(a, sizeof(a) / sizeof(a[0]));      // 显式实例化
    cout << endl;
    MathHelper<double>(b, sizeof(b) / sizeof(b[0]));
    // 输出：Max: 22  Min: 1  Mean: 7.4  /  Max: 10.5  Min: 1.5  Mean: 5.82
    return 0;
}
```

**注意**：T 类型必须支持 `>`、`<`、`+` 运算，否则实例化失败。

# 第三阶段：补

## 难点重讲一：模板实例化的编译期机制（放慢节奏）

以 `change(a, b)`（a、b 为 int）为例，编译器分四步：

1. **看到调用**：`change` 不是普通函数而是模板 → 进入推导流程；
2. **类型推演**：检查实参 a、b 的类型都是 int → 确定 `T = int`；若 a 是 int、b 是 double → 推导冲突，直接报错（不会偷偷转换）；
3. **代码生成**：复制模板体，把所有 T 替换成 int，得到 `void change(int&, int&)` 的具体代码；
4. **地址分配**：这份实例有独立的函数地址；之后所有 int 版调用共享这一份（不会重复生成）。

**关键结论**：模板的错误往往在"实例化点"才暴露——模板定义本身可能编译通过，一旦用不支持 `+` 的类型实例化才报错，错误信息又长又吓人，定位时直接看"哪个类型实例化、缺什么运算"。

## 难点重讲二：类模板成员函数类外定义语法（逐部分拆解）

```
template<class T>   void Test<T>::setData(const T& x)   { num = x; }
└─────┬───────┘   └──────────┬────────────┘   └──┬──┘
   ①模板前缀             ②限定名：属于 Test<T>       ③函数体
```

- ① **模板前缀**：离开类体后编译器不认识 T，必须重新声明"这是一个模板、T 是类型参数"；
- ② **限定名** `Test<T>::`：指明函数属于哪个类（注意要写 `Test<T>` 而不是 `Test`）；
- ③ 函数体里的 T 由①的声明支撑。

记忆：类内声明一次，类外定义时"每个成员函数都要重新戴上模板帽子"。

## 常见陷阱专题（3 个最易错点）

### 陷阱1：单模板参数传不同类型实参

- **错误写法**：`template<class T> T add(T&, T&)` 然后 `add(int变量, double变量)`
- **后果**：编译器无法为 T 确定唯一类型，编译错误
- **正确写法**：双模板参数 `template<class T, class H>`，或显式实例化 `add<double>(...)`
- **如何记住**：一个 T 对应一种类型，多种类型就需要多个 T

### 陷阱2：类外定义忘加模板参数列表

- **错误写法**：`void Test<T>::setData(const T& x) { num = x; }`
- **后果**：编译器不认识 T，报"undeclared identifier"
- **正确写法**：`template<class T> void Test<T>::setData(const T& x) { num = x; }`
- **如何记住**：类外定义的每个成员函数都要重新声明模板身份

### 陷阱3：误以为类模板可以直接当类型

- **错误写法**：`Test t1;`
- **后果**：编译错误——Test 只是类模板名，不是类型
- **正确写法**：`Test<int> t1;`
- **如何记住**：类模板必须带 `<类型>` 后才变成真正的类型

## 新手最常问的5个问题

**Q1：class 和 typename 到底有什么区别？什么时候必须用 typename？**
在模板参数声明中两者语法完全等价（课件原文）。区别在历史与语义：typename 是后期引入、更明确表达"这是一个类型"；在嵌套依赖类型场景（如 `typename T::iterator`）只能用 typename。

**Q2：为什么类模板的声明和定义不能分到 .h 和 .cpp？**
编译器必须在实例化点看到模板完整定义才能生成实例代码。若定义在 .cpp，使用方编译时看不到，链接期又找不到具体实例 → 链接错误。工程解法：全放头文件，或用显式实例化声明（`extern template class Test<int>;`）配合集中实例化。

**Q3：函数模板和函数重载选哪个？能一起用吗？**
逻辑相同只是类型不同 → 模板；不同类型对应不同逻辑 → 重载。可以一起用：重载决议时普通函数优先于模板，模板只在没有更匹配的重载时实例化。

**Q4：模板是编译期还是运行期处理？影响性能吗？**
编译期实例化、生成真实代码；运行期与普通手写函数无异（零运行开销），代价是编译时间变长、可执行文件可能变大（每个实例一份代码）。

**Q5：using 模板别名和 typedef 的本质区别？旧项目能用 using 吗？**
typedef 只能给"已有类型"起别名，无法参数化；using 可以定义"别名模板"，像函数一样接受类型参数。using 需要 C++11，旧标准（C++98/03）项目只能用 typedef。

```cpp
    static const int value = N * Factorial<N - 1>::value;  // 模板递归

}
```

## 3条随身速记口诀

1. **模板不是函数是模具，编译器按类型压实例；隐式推导显式指定，类型冲突加参数。**
2. **类模板，尖括号里写类型才成类；类外定义戴帽子，`template<class T>` 不能丢。**
3. **typedef 定死一个型，using 别名整个模；STL 全靠模板撑，学好模板路自宽。**
