# 模块一：预处理基础

## 知识点 1｜预处理概述（P4-P5）【了解】

### ① 是什么

**一句话定义**：预处理是指在编译的第一遍扫描（词法扫描和语法分析）**之前**所做的工作，由预处理程序自动完成，主要处理所有以 `#` 开头的命令（P4-P5）。

**生活化比喻**：预处理就像**婚礼前的布场师傅**。新郎新娘（你的代码）入场（编译）之前，布场师傅已经把横幅上的"XXX"换成了真实姓名（宏替换）、把备用幕布挂上或拆掉（条件编译删代码）、把隔壁房间的屏风搬进来（`#include` 展开头文件）。新人全程不知道发生了什么——他们只看到**布置好的最终现场**（预处理后的 `.i` 文件）。

### ② 为什么（追问 3 层）

1. **为什么要预处理？** —— 因为 C++ 源码里有大量"不该由编译器操心"的文字游戏（改名、抄文件、按条件取舍），交给专职预处理程序做，编译器本体可以更简单。
2. **为什么不直接手写最终代码？** —— 宏名 `PI` 比满屏的 `3.1415926` 可读、可维护；`#include` 让模块化成为可能；条件编译让一份源码编译出 Windows/Linux 两个版本。
3. **为什么它必须在词法扫描之前？** —— 因为后面的编译器**根本不认识** `#define` 这些指令。预处理不做完，编译器看到的就是一堆非法符号。这也是一切宏相关 bug 的根源：**编译器看到的是替换后的文本，错误往往要到编译期甚至运行期才暴露，且报错位置指向替换后的代码**。

### ③ 怎么用

预处理命令行（整个源文件的骨架）必须放在**所有函数之外**，一般放在源文件**前面**（P5）：

```cpp
#include <iostream>   // 这行本身就是预处理命令（P5），先被处理
using namespace std;

#define PI 3.1415926  // 预处理命令：放在 main 函数之外、文件前部（P5 要求）

int main() {
    double r = 2.0;
    cout << "area = " << PI * r * r << endl;  // 使用宏：运行时求值的是替换后的数字
    return 0;
}
// 输出：area = 12.5664
```

想亲眼看到预处理的结果？用 g++ 只做预处理、停在编译之前（行为发生在**预处理阶段**）：

```bash
g++ -E demo.cpp -o demo.i   # -E：只跑预处理器，产物 .i 里已无任何 #define
```

### ④ 注意事项

**新手最常见错误：把预处理命令写进函数体内、又缩进错位，误以为它是"函数里的语句"**。

```cpp
int main() {
    #define LIMIT 10   // 语法上允许（GCC/MSVC 都不报错），但不推荐！
    int a[LIMIT];      // P5 明确说：预处理命令要放在所有函数之外
    return 0;
}
```

错在哪：不算编译错误，但违反课件规范（P5"放在所有函数之外，一般放在源文件前面"），多人协作时宏的作用范围会变得不可预测。**记住：`#` 开头的都不是语句，没有分号，不参与运行。**

> **人话总结**：编译之前先过一道文字工，`#` 开头全归它管。

## 知识点 2｜常用预处理指令（P6）【熟悉】

### ① 是什么

**一句话定义**：C++ 的预处理指令分三大类——**文件包含类**（`#include`）、**宏定义类**（`#define`/`#undef`）、**条件编译类**（`#if`/`#ifdef`/`#ifndef`/`#elif`/`#endif`），全部以 `#` 开头、行尾**不加分号**（P6）。

**生活化比喻**：像装修房子的三种工单——`#include` 是**搬运工单**（把别人家现成的家具搬来）；`#define`/`#undef` 是**改名工单**（给材料贴标签、撕标签）；条件编译是**取舍工单**（预算够就做 A 方案，不够就做 B 方案，没选中的方案图纸直接扔掉）。

### ② 为什么

三类指令分别解决三个层次的复用问题：**代码复用**（include）、**文字替换/命名抽象**（define）、**按环境裁剪代码**（条件编译）。分清类别，遇到任何 `#` 指令都能立刻判断"它改的是内容还是范围"。

### ③ 怎么用：总览表格（严格按 P6 整理并补强）

| 分类 | 指令 | 功能（P6 原文口径） | 起作用阶段 | 示例 |
|------|------|--------------------|-----------|------|
| 文件包含类 | `#include` | 包含一个源代码文件，头文件 | 预处理阶段（原样插入文本） | `#include <iostream>` |
| 宏定义类 | `#define` | 定义宏 | 预处理阶段（登记替换规则） | `#define PI 3.1415926` |
| 宏定义类 | `#undef` | 取消已定义的宏 | 预处理阶段（注销规则） | `#undef PI` |
| 条件编译类 | `#if` | 如果给定条件为真，则编译下面代码 | 预处理阶段（求值常量表达式） | `#if com` |
| 条件编译类 | `#ifdef` | 如果宏已经定义，则编译下面代码 | 预处理阶段（查宏名是否注册） | `#ifdef PRINT` |
| 条件编译类 | `#ifndef` | 如果宏没有定义，则编译下面代码 | 预处理阶段 | `#ifndef PR` |
| 条件编译类 | `#elif` | 如果 `#if` 条件不为真、当前条件为真，则编译下面代码 | 预处理阶段 | `#elif BA` |
| 条件编译类 | `#else` | 兜底分支，只能跟在最后面（P36） | 预处理阶段 | `#else` |
| 条件编译类 | `#endif` | 结束 `#if`…到 `#else` 条件编译块 | 预处理阶段 | `#endif` |
| 其他 | `#error` | 编译期间输出错误信息并终止编译（P38） | 预处理阶段（触发即失败） | `#error compile error here!` |
| 其他 | `#pragma` | 向编译器传递专用指示 | 编译阶段生效 | `#pragma once` |

`#include` 的两种写法差异（熟悉级必考）：

```cpp
#include <iostream>   // <>：只去系统/标准目录找（编译器 include path）
#include "myhead.h"   // ""：先在当前目录找，找不到再去系统目录 —— 自定义头文件用引号
```

### ④ 注意事项

**常见错误：给预处理命令加分号、或漏写 `#`**。

```cpp
#define PI 3.1415926;   // ❌ 行尾多了分号：分号会成为宏体的一部分
int main(){
    double s = PI * 2 * 2;;  // 展开后变成 3.1415926; * 2 * 2 —— 编译错误
    return 0;
}
```

正确写法：`#define PI 3.1415926`（行尾什么都不加）。预处理指令**不是 C++ 语句**，不需要也不能随意加分号。

> **人话总结**：三大类九种指令，全是预处理阶段的文字活。

# 模块二：宏定义体系

## 知识点 3｜宏定义（P7-P17）【重点】

### ① 是什么

**一句话定义**：宏是"用一个标识符表示一个字符串"的预处理机制；编译预处理时，程序中所有出现的宏名都被宏定义中的字符串**原样代换**，称为**宏替换**或**宏展开**（P7）。宏定义分为**无参宏**和**带参宏**两种（P7）。

**生活化比喻**：宏是 Word 里的**查找替换**，不是变量赋值。你把全文的"张总"替换成"张伟"，Word 根本不知道"张总"是人是狗——它只做**盲替换**。宏也一样，纯文本操作，零类型检查。

### ② 为什么（3 层）

1. **为什么要宏？** —— 给魔法数字起名字（`PI`、`MAX_RETRY`），一处修改、全局生效。
2. **为什么带参宏能当"穷人版函数"？** —— 因为替换发生在编译前，调用点被就地展开，**没有函数调用的压栈开销**。
3. **为什么它 bug 多？** —— 正因为替换是**纯文本**的：不求值、不检查优先级、不检查类型、参数出现几次就复制几份。这是理解本章一切坑的根本原因。

### ③ 怎么用

#### 3.1 无参宏定义（P8-P10）

语法（P8）：`#define identify expression`
- `#define`：定义宏使用的关键字
- `identify`：宏的标识符，也就是**宏名**
- `expression`：该宏所代表的表达式或者常量值

案例（P8-P10）：`#define PI 3.14` 定义了宏 PI，以后需要用 3.14 的地方可以直接写 PI。P9 提出练习："利用宏定义 PI，输入半径 r，完成求圆面积的代码"，P10 给出答案骨架 `cout << PI * r * r << endl;`。补全为完整可运行程序：

```cpp
#include <iostream>          // P5：#include 本身就是预处理命令
using namespace std;

#define PI 3.1415926         // P10 原题数值；预处理阶段登记：PI → 3.1415926

int main() {
    double r;                // P9 案例：输入半径求圆面积
    cout << "input r: ";
    cin >> r;                // 假设输入 2
    cout << PI * r * r << endl;  // 展开为 3.1415926 * r * r，运行阶段才算乘法
    return 0;
}
// 输出：input r: 2
// 输出：12.5664
```

#### 3.2 带参宏定义（P11-P14）

语法（P11）：`#define identify(paramlist) expression`，比无参宏多一段**参数列表 paramlist**。

P12 案例：`#define INC(x) x++` —— 宏 INC 接受一个参数 x，功能是把 x 自增。P13 提出练习："利用宏定义简化 num 变量自增、自减的代码"，P14 给出代码。完整可运行版：

```cpp
#include <iostream>
using namespace std;

#define INC(v) v++   // P14：宏名与(之间不能有空格，否则(被视为宏体一部分
#define DEC(v) v--   // P14 的 DEC(v) v-- ：自减简化

int main() {
    int num = 100;
    cout << "num = " << num << endl;  // 输出：num = 100
    INC(num);                         // 预处理展开为：num++;
    cout << "num = " << num << endl;  // 输出：num = 101
    DEC(num);                         // 预处理展开为：num--;
    cout << "num = " << num << endl;  // 输出：num = 100
    return 0;
}
// 输出：
// num = 100
// num = 101
// num = 100
```

#### 3.3 ⭐ SQR 括号对比：本章最重要的演示（P15-P17）

P15 抛出问题：`#define SQR(n) n*n` 下，`SQR(num)`（num=10）与 `SQR(5+5)` 输出一样吗？
P16 换成 `#define SQR(n) ((n)*(n))` 再问一遍。
P17 给出结论：**在使用宏参数时，建议将所有的参数都用 () 括起来**；宏定义中的参数称**形式参数**，宏调用中的参数称**实际参数**（与函数术语对应）。

**版本 A（P15，无括号保护）宏展开逐步演示**：

```
原始代码：
#define SQR(n) n*n
int result2 = SQR(5+5);

第一步替换（实参 5+5 代入形参 n —— 注意：代的是"原文"，不加括号、不求值）：
   宏体 n*n 里有两处 n，各自把 "5+5" 这三个字符原样贴进去
   n * n  →  [5+5] * [5+5]  →  去掉定位用的方框：5+5*5+5

第二步（还原成 C++ 语句）：
最终代码（编译器实际看到的）：
int result2 = 5+5*5+5;
```

先乘除后加减：`5 + 25 + 5 = 35`。**你以为会得到 100，实际得到 35。**

**版本 B（P16，括号保护）宏展开逐步演示**：

```
原始代码：
#define SQR(n) ((n)*(n))
int result2 = SQR(5+5);

第一步替换（实参 5+5 原样代入每个 n，宏体自带的括号保持不动）：
   ((n)*(n))  →  (([5+5])*([5+5]))  →  去掉定位用的方框：((5+5)*(5+5))

第二步（还原成 C++ 语句）：
最终代码：
int result2 = ((5+5)*(5+5));
```

`(5+5)=10`，`10*10=100`。**得到 100。**

两个版本同框对比（完整可运行，实测）：

```cpp
#include <iostream>
using namespace std;

#define SQR_BAD(n) n*n        // P15 的写法：参数裸奔
#define SQR(n) ((n)*(n))      // P16/P17 推荐写法：参数加括号 + 整体再加括号

int main() {
    int num = 10;
    cout << SQR(num) << endl;     // 展开 ((num)*(num)) → 100；两版本此处结果相同
    cout << SQR(5 + 5) << endl;   // 好版本：((5+5)*(5+5)) → 100
    cout << SQR_BAD(5 + 5) << endl;// 坏版本：5+5*5+5 → 35（P15 想让你亲眼看到的差距）
    return 0;
}
// 输出：
// 100
// 100
// 35
```

**用编译器亲眼看展开**（预处理阶段的证据）：

```bash
g++ -E t03.cpp | tail -8
# int result = num*num;
# int result2 = 5+5*5+5;   ← 预处理器真的把文本写成这样，没有任何"聪明"的加工
```

#### 3.4 code.cpp 走读印证（详见"配套文件逐行讲解"一节）

`code.cpp` 第 11 行 `#define SQR(n) ((n) *( n))` 采用括号保护版，注释（GBK 乱码还原后）意思是"防止运算符优先级的改变"；第 15 行 `#define ADD(a,b) ((a) + (b))` 演示**多参数**宏同样要给每个参数套括号。

### ④ 注意事项 + 常见错误示范（重点级）

**错误示范 1：宏名与左括号之间加了空格**

```cpp
#define SQUARE (n) ((n)*(n))   // ❌ SQUARE 后面有空格 → 这是"无参宏"，宏体是 "(n) ((n)*(n))"
int main(){
    cout << SQUARE(3) << endl; // 展开为 (n) ((n)*(n))(3) —— 编译错误
    return 0;
}
```

正确写法：`#define SQUARE(n) ((n)*(n))`。带参宏的宏名与 `(` 必须**紧挨着**，中间不能有空白。

**错误示范 2：只在宏体外层加括号，参数不保护**

```cpp
#include <iostream>
using namespace std;

#define AVG(a, b) (a + b) / 2     // ❌ 外层有括号，但参数 a、b 各自裸奔
#define SUM(a, b) a + b           // ❌ 参数和宏体都没保护

int main() {
    int x = 10, y = 4;
    cout << AVG(1, 2) * 6 << endl;       // 展开 (1 + 2) / 2 * 6 → 从左算：3/2=1，再*6 → 6（期望 9）
    cout << SUM(x - y, 2) * 3 << endl;   // 展开 x - y + 2 * 3 → 10-4+6 = 12（期望 ((x-y)+2)*3 = 24）
    return 0;
}
// 实测输出：
// 6
// 12
```

两个 bug 各有病因：`AVG(1,2)*6` 得 6 而不是 9，因为 `(1 + 2) / 2 * 6` 里 `/` 与 `*` 同优先级、从左往右，先做了整数除法；`SUM(x-y, 2)*3` 得 12 而不是 24，因为实参 `x-y` 没有自己的括号，被宏体的 `+` 直接吃掉，整体又没括号挡住外部的 `*3`。正确写法：**每个参数各自套括号，宏体整体再套一层**——`#define AVG(a, b) (((a) + (b)) / 2)`、`#define SUM(a, b) ((a) + (b))`。原则见 P17：**在使用宏参数时，建议将所有的参数都用 () 括起来**。

**错误示范 3：把带副作用的表达式传给宏**

```cpp
#define SQR(n) ((n)*(n))
int main(){
    int x = 5;
    int r = SQR(x++);      // ❌ 展开 ((x++)*(x++)) —— x 被自增两次，未定义行为
    cout << r << ", " << x << endl;
    return 0;
}
// 实测输出（MinGW 8.1）：r = 30, x = 7 —— 既不是 36 也不是 25，完全不可预期
```

原因：宏是复读机，参数在宏体出现几次，实参文本就被复制几份、求值几次。`x++` 这种自带副作用的表达式**绝不传入宏**（改用 inline 函数，见"现代 C++ 替代方案"）。

> **人话总结**：宏是查找替换，参数套好括号，别传 ++。

|---------|-------------------|---------------------------|
| **处理阶段** | 预处理阶段：纯文本替换，替换完编译器不再知道 PI 存在 | 编译阶段：真正的声明，参与语法分析与优化 |
| **类型检查** | 无。宏体可以随便写，替换后是什么类型算什么类型 | 有。类型写错编译器立刻报错 |
| **作用域** | 无作用域概念。从 `#define` 处起，直到文件尾或被 `#undef`（P21-P22） | 遵循 C++ 作用域规则（块作用域/命名空间/类内），可被限制在小范围 |
| **调试可见性** | 调试器里**看不见** PI 这个名字，只能看见散落的字面量 | 可见，gdb/VS 监视窗口能直接查看 PI |
| **内存分配** | 不分配内存（每处都是字面量内联进代码） | 一般会分配（作为对象存在；被优化或 constexpr 时可免） |
| **能否用于数组大小** | 可以（传统 C 与 C++ 都行） | C++ 中可以（编译期常量）；传统 C89 中不行 |
| **可否取地址** | 不能（它不是实体） | 能，`&PI` 合法 |
| **重定义行为** | 同名再 `#define` 会告警；可用 `#undef` 后再定义 | 同一作用域重复定义直接编译错误 |

实测双证：

```cpp
#include <iostream>
using namespace std;

#define N_MACRO 5     // 预处理阶段：文本替换
const int N_CONST = 5; // 编译阶段：编译期常量（C++ 允许做数组维度）

int main() {
    int a[N_MACRO];    // ✅ 宏做数组大小：传统 C、C++ 都可以
    int b[N_CONST];    // ✅ C++ 中 const 整型初始化器是编译期常量，可以做数组大小
                       // ❌ 但在传统 C89 中 const 只是"只读变量"，不允许做维度
    cout << sizeof(a)/sizeof(a[0]) << " " << sizeof(b)/sizeof(b[0]) << endl;
    return 0;
}
// 输出：5 5
```

**总结（现代 C++ 怎么选）**：在 C++ 中，凡是能表达成**常量**的东西，优先用 `const` / `constexpr` 替代 `#define` 数值宏——你免费获得类型检查、作用域控制、调试可见性和 IDE 跳转。`#define` 只保留给三件预处理自己才能干的事：**头文件守卫、条件编译开关、以及需要字符串化/拼接的元编程**。这正是本章后续内容的正确打开方式。

## 知识点 4｜宏函数（P18-P20、P40-P41）【重点】

### ① 是什么

**一句话定义**：宏函数就是**带参数的宏**，与普通函数类似，只是**参数没有类型**（P18）。调用时被预处理展开为表达式文本，不发生真正的函数调用。

**生活化比喻**：宏函数像**印模子盖章**——你把纸（实参文本）塞进模具（宏体）的空位里，盖几个洞就印几份一模一样的字。普通函数则是**外包公司**：你把材料原件寄过去（值传递），对方加工完把成品寄回来（返回值），全程有合同约束（类型检查）。

### ② 为什么

有些极短的通用逻辑（判数字字符、求平方、数组长度），写成函数要么被类型绑死（int 版、double 版各写一遍），要么担心调用开销。宏函数**无类型、零调用成本**，在 C 时代是标准库的常客（`max`/`min`/`isdigit` 历史上都有宏版本）。代价是：一切校验都没有，bug 全靠自觉。

### ③ 怎么用

#### 4.1 DIGIT 案例（P19-P20）

P19 出题："利用宏函数，实现判断字符是否是十进制数字！"，P20 给出参考代码。完整版：

```cpp
#include <iostream>
using namespace std;

// P20：每个参数 c 都被 () 保护，整体再用 () 包住 —— 教科书级括号保护写法
#define DIGIT(c) ((c) >= '0' && (c) <= '9')

int main() {
    char ch1 = 'a';
    char ch2 = '2';
    int d1 = DIGIT(ch1);   // 展开 ((ch1) >= '0' && (ch1) <= '9') → 'a'(97) > '9'(57) → 0
    int d2 = DIGIT(ch2);   // 展开后 '2' 在 '0'~'9' 之间 → 1
    cout << d1 << endl;    // 输出：0
    cout << d2 << endl;    // 输出：1
    return 0;
}
// 输出：
// 0
// 1
```

**宏展开逐步演示**（以 `DIGIT(ch1)` 为例）：

```
原始代码： int d1 = DIGIT(ch1);
第一步替换（实参 ch1 代入形参 c，两处 c 各代一次）：
   ((ch1) >= '0' && (ch1) <= '9')
最终代码： int d1 = ((ch1) >= '0' && (ch1) <= '9');
```

注意：`ch1` 被读了**两次**——对普通变量无害；若传 `DIGIT(buf[i++])`，`i` 就会被加两次，这就是宏函数最隐蔽的坑。

#### 4.2 ARSIZE 练习案例（P40-P41，sizeof 的巧妙运用）

P40 出题："利用宏函数，实现返回数组的元素个数"，P41 给出参考代码（其中 `cout << len endl;` 漏了 `<<`，属于课件笔误，下文修正）。

```cpp
#include <iostream>
using namespace std;

// P41：外层括号防结合问题；arr 与 arr[0] 各自加括号防实参是表达式时优先级出错
#define ARSIZE(arr) (sizeof((arr)) / sizeof((arr[0])))

int main() {
    int arr_num[5] = {1, 2, 3, 4, 5};
    int len = ARSIZE(arr_num);   // 展开 (sizeof((arr_num)) / sizeof((arr_num[0])))
    cout << len << endl;         // 20字节 / 4字节 = 5
    return 0;
}
// 输出：5
```

**宏展开逐步演示**：

```
原始代码： int len = ARSIZE(arr_num);
第一步替换（实参 arr_num 代入两处 arr）：
   (sizeof((arr_num)) / sizeof((arr_num[0])))
最终代码： int len = (sizeof((arr_num)) / sizeof((arr_num[0])));
```

巧妙之处：`sizeof` 也是**编译期**运算符（准确说在编译阶段求出结果），整个除法在编译期即可折叠成常量 5，运行时零开销。**致命前提**：`arr` 必须是真正的数组。一旦数组退化成指针（比如作为函数参数传进去），`sizeof(arr)` 就变成了指针大小（64 位下 8），结果 silently 出错——这是 ARSIZE 的经典陷阱，见下方错误示范。

#### 4.3 宏函数 vs 普通函数 对比表（课件专项要求）

| 对比维度 | 宏函数 `#define MAX(x,y) ...` | 普通函数 `int max(int a,int b)` |
|---------|------------------------------|-------------------------------|
| 处理阶段 | 预处理阶段展开，运行时不存在"调用" | 编译阶段生成调用指令，运行阶段真正 call |
| 参数类型 | **无类型**，任意可代入文本（P18） | 有严格类型，隐式转换或报错 |
| 返回值类型 | 无返回值类型，展开成什么算什么 | 有明确返回类型 |
| 调用开销 | 零调用开销（就地展开），但可能代码膨胀 | 压栈/跳转/返回开销（可被 inline/优化缓解） |
| 求值次数 | 实参文本出现几次就算几次（副作用雷区） | 实参只求值一次（传值时） |
| 类型检查 | 完全没有，错误延迟到替换后才暴露 | 编译期即时检查，报错清晰 |
| 调试 | 断点打不进"宏内部"，栈上看不到 | 可单步进入、可打断点 |
| 递归 | 不能真正递归（自我复制无限展开报错） | 可以 |

并列代码看差异：

```cpp
#include <iostream>
using namespace std;

#define MACRO_MAX(x, y) (((x) > (y)) ? (x) : (y))   // 宏版：无类型
double func_max(double a, double b) { return a > b ? a : b; } // 函数版：有类型

int main() {
    cout << MACRO_MAX(3, 2.5) / 2 << endl;  // 宏：先取到 int 3，再 3/2 → 整数除法 = 1
    cout << func_max(3, 2.5) / 2 << endl;   // 函数：返回 double 3.0，3.0/2 → 1.5
    int i = 0;
    cout << MACRO_MAX(i++, 5) << endl;      // ⚠ 展开 (((i++)>(5))?(i++):(5))，i++ 可能被复制两次
    cout << i << endl;                      // i 的最终值取决于分支走向，不可预期
    return 0;
}
// 实测输出（MinGW 8.1 -std=c++11）：
// 1
// 1.5
// 5
// 1
```

**关键点**：同样"求 3 与 2.5 的较大者再除以 2"，宏给出 `1`、函数给出 `1.5`。原因在 P18——**宏函数的参数没有类型**：宏把字面量 `3` 原样搬过来，结果类型是 `int`，于是后续 `/ 2` 掉进整数除法；函数则按形参类型把两个实参统一提升为 `double`。零类型检查省下的开销，就是用正确性换来的。

### ④ 注意事项 + 常见错误示范

**错误示范 1：ARSIZE 用在指针上**

```cpp
#include <iostream>
using namespace std;
#define ARSIZE(arr) (sizeof((arr)) / sizeof((arr[0])))
void f(int* p) {                 // 数组传参后退化为 int*
    cout << ARSIZE(p) << endl;   // ❌ sizeof(p)/sizeof(p[0]) = 8/4 = 2（64位机），静默错误
}
int main(){
    int a[10] = {0};
    cout << ARSIZE(a) << endl;   // ✅ 10（这里 a 是数组本体）
    f(a);                        // 输出那个错误的 2
    return 0;
}
// 输出：
// 10
// 2        ← 不报错、不崩溃，直接给你错答案，最难查的一类 bug
```

**错误示范 2：宏函数忘加整体括号，与外部表达式结合出错**

```cpp
#define AVG(a, b) (a + b) / 2    // ❌ 参数没保护
int main(){
    cout << AVG(1, 2) * 6 << endl; // 展开 (1 + 2) / 2 * 6 = 9（期望 ((1+2)/2)*6 也才 9？
    return 0;                        //  换成 AVG(1+1, 2) * 6 就更惨：(1+1+2)/2*6=12 而非 18）
}
```

正确写法：`#define AVG(a, b) (((a) + (b)) / 2)`。口诀见本章末尾。

> **人话总结**：宏函数=无类型函数，快但裸奔，括号是唯一的衣服。

## 知识点 5｜取消宏定义 #undef（P21-P22）【重点】

### ① 是什么

**一句话定义**：`#undef MACRO_NAME`（P21）用于取消已定义的宏或宏函数；从此处往后，该宏名不再是宏。P22 明确强调：**取消定义宏之后，不可以再次访问该宏**。

**生活化比喻**：`#define` 开灯，`#undef` 关灯。灯开着（宏生效）的区间里，屋里所有"PI"字样的东西都被照成 `3.14`；一关灯，再出现"PI"这个词，编译器就当它是墙上一个不认识的黑影（未声明标识符）。

### ② 为什么（3 层）

1. **为什么要取消宏？** —— 宏一旦定义就**默认有效到文件结尾**，作用范围太霸道。
2. **为什么范围大是坏事？** —— 第三方头文件、后续代码可能也用同名标识符，悄悄发生替换会造成灵异 bug。
3. **为什么需要显式关灯而不是不用？** —— 因为有时你需要"同名不同值"地切换（如临时覆盖 `PI` 精度、条件编译里换一套实现），只有先 `#undef` 才能安全地重新 `#define`。

### ③ 怎么用

P22 案例（先 `#define PI`，main 内用了一次，`#undef PI` 之后再用第二次）：

```cpp
#include <iostream>
using namespace std;

#define PI 3.14     // 开灯：从这一行起 PI 是宏

int main() {
    cout << "PI = " << PI << endl;  // ✅ 展开为 3.14，正常输出
#undef PI                           // 关灯：从这一行起 PI 不再是宏
    cout << "PI = " << PI << endl;  // ❌ 编译错误！PI 变成了未声明的标识符
    return 0;
}
```

g++ 实测报错（**错误在编译阶段暴露**，但根源是预处理阶段宏被注销）：

```
error: 'PI' was not declared in this scope
     cout << "PI = " << PI << endl;
```

把错误行删掉后，前半段正常输出：

```
// 输出：PI = 3.14
```

典型使用场景之一：限制宏作用范围 + 安全地重新定义：

```cpp
#include <iostream>
using namespace std;

#define PI 3.14            // 粗精度版本
int coarse_area(double r) { return (int)(PI * r * r); }  // 这个函数用粗精度就够

#undef PI                  // 用完就关灯，避免污染后面的代码
#define PI 3.1415926       // 重新开一盏更亮的灯：高精度版本
int main() {
    cout << "coarse=" << coarse_area(2.0) << endl;  // 展开时用的是 3.14 → 12（截断）
    cout << "fine  =" << PI * 2 * 2 << endl;        // 这里已是 3.1415926 → 12.5664
    return 0;
}
// 输出：
// coarse=12
// fine  =12.5664
```

### ④ 注意事项 + 常见错误示范

**错误示范：#undef 之后继续使用宏名**（正是第三阶段"陷阱 3"）

```cpp
#define DEBUG_MODE
int main() {
#ifdef DEBUG_MODE
    cout << "debug on" << endl;
#endif
#undef DEBUG_MODE
#ifdef DEBUG_MODE
    cout << "never here" << endl;   // 这段不会被编译（DEBUG_MODE 已不存在）
#endif
    cout << DEBUG_MODE << endl;     // ❌ 编译错误：DEBUG_MODE was not declared
    return 0;
}
```

要点：`#undef` 之后，`#ifdef` 判定变假、直接书写宏名变未声明标识符，**除非重新 `#define`**。另外注意：`code.cpp` 第 42 行的 `//#undef DIGIT` 正是被注释状态的演示——取消注释后，其后第 44 行 `DIGIT(ch2)` 立即编译失败，用途见逐行走读。

> **人话总结**：#define 开灯，#undef 关灯，黑灯瞎火别再喊 PI。

# 模块三：条件编译

## 知识点 6｜条件编译（P23-P39）【重点】

### ① 是什么

**一句话定义**：条件编译指按不同的条件去编译不同的程序部分，从而产生不同的目标代码文件（P23）——满足条件的代码被送去编译，不满足的直接被预处理器**扔掉**，连编译器都不会看一眼。

**生活化比喻**：条件编译像**自助餐的取菜牌**。牌子立着（宏已定义）→ 这道菜上桌（代码被编译进 exe）；牌子撤了（宏未定义）→ 那盘菜在后厨直接被倒掉，**食客（运行时）永远不知道它存在过**。这和 `if(false){...}` 完全不同——后者菜还是端上来了，只是客人不动筷子。

### ② 为什么（3 层）

1. **为什么要按条件编译？** —— 不同平台 API 不同、开发/发布需求不同、一份源码多种构建产物。
2. **为什么用预处理而不是 if 语句？** —— `if` 分支两边**都必须编译通过**且占代码体积；条件编译可以让不适用的分支**根本不参加编译**，零体积、零运行判断、还能绕过平台专有头文件。
3. **为什么它能防重复包含？** —— 头文件第一次包含时定义守卫宏，第二次包含时 `#ifndef` 判假、整文件被丢空（P24 作用 4）。

### ③ 六大指令逐个讲（P25-P39）

#### 3.1 `#ifdef identity`（P25-P28）：判断宏**已**定义

语法（P25 基本形 / P26 带 `#else` 形）：

```
#ifdef identity        #ifdef identity
code1                  code1
#endif                 #else
                       code2
                       #endif
```

identity 被 `#define` 过 → 编译 code1；否则（有 `#else` 时）编译 code2。

**P27 案例**（PRINT 从未定义）：

```cpp
#include <iostream>
using namespace std;
int main() {
    cout << "测试条件编译" << endl;
#ifdef PRINT                    // PRINT 没定义过 → 中间这块被预处理丢掉
    cout << "PRINT has defined" << endl;
#endif
    return 0;
}
// 输出：测试条件编译
```

**P28 案例**（PR 未定义，走 #else）：

```cpp
#include <iostream>
using namespace std;
int main() {
    cout << "条件编译测试2" << endl;
#ifdef PR
    cout << "PR has defined" << endl;
#else
    cout << "PR not defined" << endl;   // ← PR 未定义，编译这一块
#endif
    return 0;
}
// 输出：
// 条件编译测试2
// PR not defined
```

若在第 3 行前加一句 `#define PR`，输出立即变为 `PR has defined`（对应 `code.cpp` 第 52 行被注释的 `//#define PRINT` 开关）。

#### 3.2 `#ifndef identity`（P29-P32）：判断宏**未**定义，与 #ifdef 正好反过来（P29："if not define"）

**P30 案例**（`#ifndef` + `#else` 的完整对称形式，讲解时先看骨架再看 P31/P32 两个具体运行结果）：

```
#ifndef identity      →  identity 未被定义过：编译 code1
code1                 →  identity 已被定义过：编译 code2（有 #else 时）
#else
code2
#endif
```

**P31 案例**（PR 未定义 → 条件成立，编译输出块）：

```cpp
#include <iostream>
using namespace std;
int main() {
    cout << "条件编译测试3" << endl;
#ifndef PR
    cout << "PR not defined" << endl;   // PR 确实没定义 → 编进程序
#endif
    return 0;
}
// 输出：
// 条件编译测试3
// PR not defined
```

**P32 案例**（带 #else 的对称版本）：

```cpp
#include <iostream>
using namespace std;
int main() {
    cout << "条件编译测试4" << endl;
#ifndef PR
    cout << "PR not defined" << endl;   // ← 实际走这支
#else
    cout << "PR has defined" << endl;
#endif
    return 0;
}
// 输出：
// 条件编译测试4
// PR not defined
```

`#ifdef` vs `#ifndef` 一张表看懂（易混点，专项要求"对比表格"）：

| 宏的定义状态 | `#ifdef X` 编哪段 | `#ifndef X` 编哪段 |
|--------------|------------------|--------------------|
| X 已定义 | code1（主块） | code2（#else 块） |
| X 未定义 | code2（#else 块）；无 #else 则整块丢弃 | code1（主块） |

#### 3.3 `#if expression`（P33-P35）：接**常量表达式**，值为真（非 0）则编译

`#if` 与 `#ifdef` 的本质区别：`#ifdef` 问"**定义过没有**"，`#if` 问"**值是不是非 0**"（且 `#if` 里还支持 `defined(X)` 写法）。

**P34 案例**（com=0 → 条件为假，无 #else，整块被扔）：

```cpp
#include <iostream>
using namespace std;
int main() {
    cout << "条件编译测试5" << endl;
#define com 0
#if com                     // 0 → false，"Start compile" 那行根本不参加编译
    cout << "Start compile" << endl;
#endif
    return 0;
}
// 输出：条件编译测试5
```

**P35 案例**（加 #else 兜底）：

```cpp
#include <iostream>
using namespace std;
int main() {
    cout << "条件编译测试5" << endl;
#define com 0
#if com
    cout << "Start compile" << endl;
#else
    cout << " do not compile" << endl;   // ← com 为 0，编译这支
#endif
    return 0;
}
// 输出：
// 条件编译测试5
//  do not compile
```

把 `#define com 0` 改成 `#define com 1`，输出立刻变 `Start compile`——这就是"编译期开关"的手感。

#### 3.4 `#elif`（P36-P37）：多分支条件编译

P36 规则：`#elif` 可以跟在 `#if`、`#ifdef`、`#ifndef` 后面，但 **`#else` 只能跟在最后面**；用法和基本条件语句类似。

**P37 案例**（BY=0、BA=0，两支全假 → 什么都不编）：

```cpp
#include <iostream>
using namespace std;
int main() {
    cout << "条件编译测试" << endl;
#define BY 0
#define BA 0
#if BY
    cout << "BY has define" << endl;
#elif BA                      // BY 假才轮到 BA；BA 也为 0 → 也不编
    cout << "BA is 1" << endl;
#endif
    return 0;
}
// 输出：条件编译测试
```

改动 `#define BA 1` 再实测（验证 elif 链的短路逻辑）：

```cpp
#define BY 0
#define BA 1
#if BY
    cout << "BY has define" << endl;
#elif BA
    cout << "BA is 1" << endl;   // ← 这次命中
#endif
// 输出：
// 条件编译测试
// BA is 1
```

`#if / #elif / #else / #endif` 与运行期 `if / else if / else` 对照表：

| 维度 | 预处理 `#if/#elif/#else/#endif` | 运行期 `if/else if/else` |
|------|--------------------------------|--------------------------|
| 求值时机 | 预处理阶段 | 运行阶段 |
| 条件要求 | 只能是**常量表达式**（宏、数字、defined()） | 任意表达式，含变量 |
| 未选中分支 | **不编译**，不占 exe 体积，语法错误也不报 | 仍编译，仅不执行 |
| 个数限制 | `#else` 至多一个且必须最后（P36） | `else` 同理 |

#### 3.5 `#error`（P38-P39）：编译期输出错误信息并终止编译

P38 要点：`#error` 后面的错误信息**不需要加双引号**。语法 `#error error message`。

**P39 案例**（完整可复现，故意让它编译失败）：

```cpp
#include <iostream>

int main() {
    cout << "条件编译测试" << endl;

}
```

g++ 实测输出：

```
error: #error compile error here!
 #error compile error here!
```

实用姿势：配合条件编译做**编译环境体检**——

```cpp

#error Unsupported platform, expected Windows or Linux!
#endif
```

#### 场景 C：头文件防重复包含守卫（作用④，专项要求 5 详解）

**三段式模板（工业标准命名）**：

```cpp
// ============ matrix.h ============
#ifndef MATRIX_H_          // ① 守卫宏名 = 文件名大写，前缀路径可选，尾部下划线防撞名
#define MATRIX_H_          // ② 立刻把守卫宏定义为真

struct Matrix {            // 若不设防，下面这份定义被抄几份就"重定义"报错
    double data[9];
    int rows, cols;
};

void mat_print(const Matrix& m);

#endif                     // ③ 收尾：守卫区到此为止
```

**工作原理（首次包含 vs 重复包含）**：

```
第 1 次 #include "matrix.h"：
   MATRIX_H_ 还没定义 → #ifndef 为真 → 编译整个文件体，同时 #define MATRIX_H_
   （此时 MATRIX_H_ 已在预处理器的登记表里）

第 2 次（直接或嵌套）再包含 matrix.h：
   MATRIX_H_ 已定义 → #ifndef 为假 → 从 #ifndef 到 #endif 之间全部丢弃
   → 头文件内容等于"空文件" → 不会重复定义
```

模拟实验（单个 cpp 也能演示守卫效果，两次包含等价于多次传递依赖）：

```cpp
#include <iostream>
using namespace std;

// —— 假装这是 matrix.h 的内容被抄了两遍，但没有守卫：
//    struct Point { int x, y; };   ← 第二次就是 redefinition 编译错误
// —— 加上守卫：
#ifndef POINT_H_
#define POINT_H_
struct Point { int x, y; };
#endif

#ifndef POINT_H_          // 第二次走到这里：POINT_H_ 已定义 → 整段跳过
#define POINT_H_
struct Point { int x, y; };
#endif

int main() {
    Point p{1, 2};
    cout << "p=(" << p.x << "," << p.y << ")" << endl;
    return 0;
}
// 输出：p=(1,2)
```

**Include Guard vs `#pragma once` 对比表**：

| 维度 | `#ifndef / #define / #endif` | `#pragma once` |
|------|------------------------------|----------------|
| 标准化 | C++ 标准语法，任何编译器支持 | 非标准扩展（但 MSVC/GCC/Clang 均支持） |
| 写法 | 三处必须配对、名字不能撞 | 一行搞定 |
| 性能 | 每次都要展开+预处理判定 | 编译器按文件物理身份识别，略快 |
| 同一文件被复制成多份/符号链接/网络盘路径异常时 | 只要宏名一致仍能防重 | 可能被当成不同文件而失效 |
| 老项目/跨冷门编译器 | ✅ 首选 | ⚠ 慎用 |

选择建议：写开源库、可能遇到冷门编译器 → 用经典守卫；自家现代项目图省事 → `#pragma once` 也可，甚至可以两者叠加使用（冗余但安全）。

### ⑤ 注意事项 + 常见错误示范

**错误示范 1：#endif 数量对不上 / 配对错位**

```cpp
#ifdef A
#if 1
cout << "x" << endl;
       // ❌ 少了一个 #endif：error: unterminated #if  / #ifdef ... 
#endif
```

每个 `#if/#ifdef/#ifndef` 必须有一个 `#endif`；嵌套时像括号一样逐层配平，建议在 `#endif` 旁写注释标明关的是哪个：`#endif // DEBUG`。

**错误示范 2：在 #if 里用运行期变量**

```cpp
int level = 3;
#if level > 2                 // ❌ 预处理阶段还没有变量！level 未定义按 0 算 → 恒假
    cout << "high" << endl;
#endif
```

`#if` 的条件只能是**编译前就能确定的常量表达式**（宏、字面量、`defined()`、`__LINE__` 等）。要用变量请用普通 `if`。

**错误示范 3：条件编译里的代码语法错了也不报**

```cpp
#ifdef NEVER_DEFINED
    cout << "typo here" <<< endl;   // 这段不编译 → 里面的语法错误不被发现
#endif
```

后果：哪天有人打开了这个宏，埋藏的烂代码才会爆炸。**对策**：CI 里把所有功能宏各组合编译一遍（本项目 `code.cpp` 中被注释的各大段正是靠"手动开灯"逐个测试，见走读）。

> **人话总结**：#if 问值、#ifdef 问有无，不选中的代码连编译都没赶上。

## hw code.cpp 走读（课后作业参考答案，P43 作业）

```cpp
#include <iostream>

#define MAX(x, y)     (((x) > (y)) ? (x) : (y))   // 三层括号：整体一对 + 每个实参各自一对
#define MIN(x, y)     (((x) < (y)) ? (x) : (y))   // 三元运算符版 min/max，无任何类型检查
int main()
{
	int x = 100;
	int y = 300;
	int max = MAX(x, y);      // 展开 (((x) > (y)) ? (x) : (y)) → 300
	int min = MIN(x, y);      // 展开 → 100
	cout << "max = " << max << " min = " << min << endl;
	return 0;
}
// 输出：max = 300 min = 100
```

**宏展开逐步演示**（`MAX(x, y)`，x=100、y=300）：

```
原始代码： int max = MAX(x, y);
第一步替换（实参 x→第一、二个 x 位；y→两个 y 位，纯文本搬运）：
   (((x) > (y)) ? (x) : (y))
最终代码： int max = (((x) > (y)) ? (x) : (y));
运行阶段： 100>300 为假 → 取 (y) → max = 300
```

# 专项深化：宏函数括号陷阱专题（课件专项要求 4，四段式对比）

三种括号缺失情况，逐一"错误写法 → 错误输出 → 正确写法 → 正确输出"。以下全部经 g++ 8.1 实测。

## 陷阱 ①：宏体中参数未加括号 → 运算优先级错误

```cpp
// —— 错误写法 ——
#define SQR(n) n*n
int main(){
    int a = 2, b = 3;
    int r = 100 / SQR(a + b);   // 展开 100 / a + b * a + b
    cout << "r = " << r << endl;
    return 0;
}
// 错误输出：r = 59        ← 期望 100/(5*5)=4，实际 100/2+3*2+3 = 50+6+3 = 59
```

```cpp
// —— 正确写法 ——
#define SQR(n) ((n)*(n))
int main(){
    int a = 2, b = 3;
    int r = 100 / SQR(a + b);   // 展开 100 / ((a+b)*(a+b))
    cout << "r = " << r << endl;
    return 0;
}
// 正确输出：r = 4
```

**为什么对**：实参 `a+b` 代入前被自己的括号锁死为一个整体，不会再被外部的 `/`、`*` 拆开。

## 陷阱 ②：宏体整体未加括号 → 与外部表达式结合出错

```cpp
// —— 错误写法 ——（参数有括号，但宏体外面没包）
#define DOUBLE(x) (x) * 2
int main(){
    int s = 10;
    int r = 100 / DOUBLE(s);    // 展开 100 / (s) * 2 = 100/10*2 = 20
    cout << "r = " << r << endl;
    return 0;
}
// 错误输出：r = 20              ← 期望 100/(10*2) = 5
```

```cpp
// —— 正确写法 ——
#define DOUBLE(x) ((x) * 2)
int main(){
    int s = 10;
    int r = 100 / DOUBLE(s);    // 展开 100 / ((s) * 2) = 5
    cout << "r = " << r << endl;
    return 0;
}
// 正确输出：r = 5
```

**为什么对**：外层括号把宏体升级成一个"原子"，外部无论接 `/`、`*` 还是 `,`，都不能楔进宏体内部。

## 陷阱 ③：多语句宏未用 do-while(0) 包裹 → if-else 悬挂

```cpp
// —— 错误写法 ——
#define SWAP(a,b) int tmp=a; a=b; b=tmp
int main(){
    int x = 1, y = 2, p = 3, q = 4;
    if (x < y)
        SWAP(p, q);     // 展开：if(x<y) int tmp=p; p=q; q=tmp;
    else                // ❌ else 找不到它的 if —— 只有第一条语句属于 if
        cout << "else branch" << endl;
    return 0;
}
// 错误输出（编译期直接拒绝）：
// error: 'tmp' was not declared in this scope
// error: 'else' without a previous 'if'
```

```cpp
// —— 正确写法 ——
#define SWAP(a,b) do { int tmp=a; a=b; b=tmp; } while(0)
int main(){
    int x = 1, y = 2, p = 3, q = 4;
    if (x < y)
        SWAP(p, q);     // 展开：do{...}while(0); —— 语法上是"一条语句"
    else
        cout << "else branch" << endl;
    cout << "p=" << p << " q=" << q << endl;
    return 0;
}
// 正确输出：p=4 q=3
```

**为什么对**：`do{...}while(0)` 把 N 条语句焊成 1 条，且结尾的分号能被自然吸收；`while(0)` 保证循环体恰好执行一次、零开销。变体：多条 `cout` 组成的日志宏同样中招（实测 `error: 'else' without a previous 'if'`），一律套 do-while(0)。

**记忆口诀**：*参数个个加括号，宏体外面再套一层，多条语句 do-while(0)，副作用参数别进门。*

| 概念 | 预处理阶段 | 编译阶段 | 运行阶段 |
|------|-----------|---------|---------|
| `#include` 展开 | ✅ 原样插入文本 | — | — |

| `#ifdef/#ifndef` 判定 | ✅ 查宏名登记表 | — | — |

# 面试高频考点（第二阶段补充 1）

1. **#define 和 const 的区别？** 答三点：阶段（预处理文本替换 vs 编译期实体）、类型（无 vs 有）、调试与作用域（不可见/无作用域 vs 可见/有作用域）。加分句：C++ 里数值常量应优先 `const`/`constexpr`，`#define` 留给守卫和条件编译。
2. **#define SQR(n) n*n，SQR(1+1) 等于几？** 答 3（展开 1+1*1+1）。引申出双层括号规则和 `SQR(x++)` 的副作用翻倍问题。
3. **头文件守卫的原理？** 首次包含：`#ifndef NAME` 为真 → 编译全文并定义 NAME；再次包含：NAME 已定义 → 整段跳过。答出"防的是重复**定义**导致编译错误"是及格线，能说出与 `#pragma once` 的可移植性权衡是优秀线。
4. **#if 0 和 /* */ 注释的区别？** `#if 0` 可嵌套、可按条件复活、代码仍出现在版本 diff 中；块注释遇 `*/` 提前闭合、无法区分"暂时禁用"与"永久删除"。
5. **宏展开和函数调用的本质差异？** 宏=编译前的文本克隆（无调用帧、无类型检查、参数按出现次数重复求值）；函数=运行期的控制流转移（一次求值、有类型系统护航、可调试）。
6. **#ifdef、#ifndef、#if 有什么区别？** 前两个查"定义与否"，`#if` 算"常量表达式之值"；`#if defined(X)` ≈ `#ifdef X`，但 `#if` 可以组合逻辑：`#if defined(A) && !defined(B)`。
7. **#undef 之后会发生什么？** 宏名从预处理登记表消失：后续 `#ifdef` 判假、裸写宏名变成未声明标识符（编译错误）；想恢复必须重新 `#define`。
8. **带副作用的表达式传给宏有什么问题？** 参数被复制 N 份 → 副作用执行 N 次（`x++` 两次）→ 未定义行为；防御手段：不传副作用表达式，或用 inline 函数/模板替代。

# 现代 C++ 替代方案（第三阶段补充 2）

| 传统预处理用法 | 现代替代 | 版本 | 说明 |
|----------------|----------|------|------|
| `#define PI 3.14` | `constexpr double PI = 3.14;` | C++11 | 编译期常量 + 类型安全 + 调试可见 |
| `#define MAX(a,b) ...` | `inline` 函数 / `std::max` / 模板 | C++98/11 | 只求值一次，有类型检查 |
| 类型无关的最小宏 | 函数模板 `template<class T> auto sq(T x){return x*x;}` | C++11/14 | 泛型且不玩文本 |
| 特性探测宏 `#ifdef HAS_X` | `__has_include(...)`、`if constexpr` 检测 | C++17 | 编译期语言级探测 |
| 标记废弃接口 | `[[deprecated("use y")]]` 属性 | C++14 | 编译器原生警告，优于条件编译剔除 |
| 巨型头文件包含体系 | 模块 `import std;` | C++20 | 根治重复包含与编译防火墙问题 |
| 调试开关 `#ifdef DEBUG` | 日志库 + `std::source_location`（C++20） | — | 但仍常用宏封装 `LOG()`（要拿 `__FILE__/__LINE__` 就绕不开宏） |

仍然必须用预处理的场景：include guard、平台适配（`_WIN32` 等编译器预定义宏无法被语言特性替代）、需要 `__FILE__`/`__LINE__`/字符串化 `#`/拼接 `##` 的日志与反射类框架宏。原则：**能用语言特性就不用宏；要用宏就按工程规范武装到牙齿。**

# 工程实践中的预处理规范（第三阶段补充 3）

1. 宏命名**全大写 + 下划线**（`MAX_SIZE`、`MODULE_H_`），一眼区别于变量/函数。
2. 宏参数一律 `(p)`，宏体一律 `(...)` 外层包裹；多语句一律 `do{...}while(0)`。
3. 绝不让宏参数带副作用；对外 API 宁可写模板也别赌调用者自觉。
4. 头文件守卫命名：`<PROJECT>_<PATH>_<FILE>_H_`（Google Style），杜绝 `HEADER_H` 这种裸名撞车。
5. 条件编译嵌套 ≤ 3 层；超出就拆成独立文件或提升为构建系统选项（CMake `-D`）。
6. `#define` 尽量集中管理（config.h / build flags），禁止散落在函数间。
7. 静态分析防线：clang-tidy（`misc-*`）、cppcheck `--enable=warning`、MSVC `/W4` 对宏重定义、可疑展开均有告警；CI 开启 `-Werror` 阻断。
8. 用 `#error` 做编译环境自检（缺少必要宏时快速失败），而不是等运行时崩。

## 3. 易错点速查卡（四列）

| 错误现象 | 错误原因 | 正确写法 | 后果 |
|----------|----------|----------|------|
| `SQR(5+5)` 得 35 | 宏体参数没加括号，展开 `5+5*5+5` | `#define SQR(n) ((n)*(n))` | 计算全错且不报错 |
| `100/DOUBLE(s)` 得 20 而非 5 | 宏体整体没包括号 | `#define DOUBLE(x) ((x)*2)` | 与外部运算符错误结合 |

| `error: 'PI' was not declared` | `#undef PI` 之后还使用 PI | 需要就先重新 `#define` | 编译错误 |

| 调试器看不到宏的值 | 宏不是实体，预处理后就消失了 | 观察 const/constexpr 变量 | 排查困难 |

## 4. 常见陷阱专题（3 个最易错点，第三阶段指定）

**陷阱 1：带参宏缺括号导致优先级错误**
- 错误写法：`#define SQR(n) n*n`，调用 `SQR(5+5)` → 后果：展开为 `5+5*5+5 = 35` 而非 100（实测证实）
- 正确写法：`#define SQR(n) ((n)*(n))` → 为什么对：参数和整体都加括号保护
- 如何记住：宏参数个个加括号，宏体外面再套一层

**陷阱 2：宏带副作用表达式（如 x++）**
- 错误写法：`SQR(x++)` → 后果：展开 `((x++)*(x++))`，x 被自增两次，结果不可预期（实测 r=30, x=7）
- 正确写法：宏调用避免传副作用表达式，或改用 inline 函数 → 为什么对：文本替换会展开多次
- 如何记住：宏是复读机，传 ++ 就复读两次

**陷阱 3：#define 与 #undef 作用范围混淆**
- 错误写法：`#undef` 之后继续使用宏名 → 后果：编译错误（未定义标识符，实测 `'PI' was not declared in this scope`）
- 正确写法：明确宏的有效区间，需要时重新 `#define` → 为什么对：宏只在定义到取消之间有效
- 如何记住：#define 开灯，#undef 关灯

## 5. 新手最常问的 5 个问题

**Q1：宏和变量到底啥区别？我 `#define A 1` 然后 `A = 2;` 行不行？**
不行。`A = 2;` 会被展开成 `1 = 2;`——给字面量赋值，编译错误。宏不是变量，它连"存在"都没有，只是预处理阶段的替身演员。

**Q2：既然有 const，为什么还要学 #define？**
三个理由：① 课件本章知识体系必经之路，读老代码离不开；② 头文件守卫、平台分支、`__FILE__` 日志宏这些**只有预处理能做**；③ 面试必考（见面试考点清单）。

**Q3：`#ifdef DEBUG` 的 DEBUG 我从来没定义过，为什么程序还能跑？**
恰恰应该能跑——`#ifdef` 判"假"时那段代码**压根没被编译**，就像从没写过一样。想开启调试输出，要么源码里加 `#define DEBUG`，要么编译命令行加 `-DDEBUG`（工程常用后者）。

**Q4：为什么我的宏在 gcc 下好好的，换台机器/换个编译器就炸？**
大概率踩了：宏名与系统预定义宏撞车（如 `DEBUG`、`unix`）、`sizeof` 假设了平台字长、或依赖了某编译器的扩展语法。对策：宏名加项目前缀、跨平台矩阵 CI 编译。

**Q5：条件编译掉的代码和注释掉的代码有什么区别？**
形式上都是"不执行"，本质上：条件编译可以**由构建方一键切换**（`-DXXX`），同一份源码产出多个版本；`//` 注释只能手改源码。而且 `#if 0` 块能嵌套、块注释不能。

```
     ├─ #elif（P36-P37）：BY/BA 多分支，#else 只能垫底
     └─ #error（P38-P39）：编译期强制报错，消息不加引号
```

## 9. 随身口诀（3 条）

1. **「宏是替换不求值，参数宏体两层括」**——一切优先级 bug 治于此。
2. **「#define 开灯 #undef 关，复读机上别传 ++」**——作用区间与副作用两大纪律。
3. **「#ifdef 问有无，#if 问真假；没选中的代码，编译器瞧不着」**——条件编译心智模型。
