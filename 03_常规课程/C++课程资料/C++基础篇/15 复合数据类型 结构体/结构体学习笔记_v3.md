## §1.1 结构体概述（P4–P5｜🟢 了解）

### ① 是什么

**一句话定义**（课件 P5 原文）：结构体 (struct) 是**具有相同类型或不同类型的数据构成的数据集合**，是 C++ 中**聚合数据类型 (aggregate data type)** 的一类；其中的元素称为结构体的**成员 (member)**，成员一般用名字访问。

**生活化比喻**：数组像一排**规格完全相同的储物格**（只能放同一种东西，靠编号 0/1/2 找）；结构体像一个**行李箱**——里面一格放衣服（string）、一格放书（int）、一格放笔记本电脑（double），每格有自己的**标签名**，你按标签取东西，而不是按"第几格"。

### ② 为什么（追问三层）

**Q1：为什么要发明结构体？**
因为数组办不到。课件 P4 直接抛出了这个痛点问题：

> 「如果想保存学生的学号，姓名，年龄，各科成绩等信息，那种数据类型可以把这些数据作为一个整体保存起来？」

用数组存"一个学生"只能开三个平行数组，立刻崩盘：

```cpp
// ❌ 反例：试图用数组打包一个学生
string names[3] = {"张三", "李四", "王五"};
int    ages[3]  = {20, 21, 22};
double scores[3]= {99.5, 88, 77};
// 现在想问"张三多大？" —— 你得先 in names 里找到下标 0，再去 ages[0] 取值。
// 三个数组之间没有任何"绑定关系"，删掉 names[0] 时 ages[0] 不会跟着动 → 数据错位。
```

**Q2：为什么非要"一个整体"，分开存不行吗？**
分开存导致**无法整体传递**。函数参数只能一次传一个变量；要把"一个学生"传给函数，就得写 `printStudent(name, age, score)`，将来加一科成绩就要改所有调用点。打包成结构体后，签名永远是 `printStudent(student s)`，加成员不用动调用方。

**Q3：为什么它叫"聚合数据类型"？**
因为它不产生新的原子存储，只是把已有类型**按规则拼在一起**。所以结构体可以直接被声明为**变量、指针或数组**（课件 P5 原话："结构体可以被声明为 变量、指针 或 数组 等"），这三条路本章 §1.2 / §2.1 / §2.2 逐一打通。

### ③ 怎么用

概念层面无需代码，只需记住三个术语的对应关系：

| 课件术语 (P5) | 英文 | 相当于行李箱里的 |
|---|---|---|
| 结构体 | struct | 整个行李箱（一种**类型**） |
| 成员 | member / field | 箱内一格（有名字的变量） |
| 结构体变量 | — | 一只具体的箱子（占内存） |

### ④ 注意事项

新手最常见的误解：把 `struct student {...};` 当成"创建了一个学生"。

```cpp
struct student { string name; int age; };   // ← 这行只画了"图纸"，不占对象内存
// sizeof(student) 不为 0（它是类型的大小），但此刻内存里还没有任何"学生"存在
student s1;                                  // ← 这才真正造出一只箱子
```

**后果**：以为定义了类型就有变量可用，写出 `s1.name` 却发现 `s1` 从未声明，编译报 `'s1' was not declared in this scope`。

> 🗣️ **人话总结**：数组装同类，结构体装一家子。

## §1.2 结构体的定义和初始化（P6–P8｜🔴 重点）⭐⭐⭐

### ① 是什么

**一句话定义**（课件 P6 语法原文）：用 `struct` 关键字把若干成员声明裹进大括号，就定义出一种新类型。

```cpp
struct structName{
    type name1;
    type name2;
    type name3;
};                     // ← 注意这个大括号后的分号
```

**生活化比喻**：这是**填一张户型图**。`struct student` 是楼盘名，`name1/name2/name3` 是三间房的名字，每间房注明面积（类型）。图纸本身不能住人，要 `student s1;` 才算交付了一套具体房子。

### ② 为什么

**Q1：为什么必须写 `struct` 关键字？**
它是编译器进入"我要开始描述一个新类型"模式的开关，也是 C 语言遗留的类型标签（tag）机制入口。

**Q2：为什么需要两个分号（课件 P6 特别强调）？**
> 课件 P6 原文：「定义结构体时，每个字段名后面都需要使用 ; 结尾;最后的大括号后面，同样需要使用 ; 结尾，如果没有分号，则程序会报错。」

- **成员后的分号**：每个成员本质是一条**变量声明语句**，C++ 里声明语句必须以 `;` 结束。
- **大括号后的分号**：整个 `struct X{...}` 只是一个**声明的开头**（就像 `int`），后面的 `;` 才让它成为一条完整声明——这也正是为什么可以写 `struct X{...} s1, s2;`（末尾分号同时充当"变量声明结束符"）。

**Q3：为什么不加分号会报那么奇怪的错？**
❗ **本机实测报错**（漏写大括号后的分号）：

```cpp
struct S{ int a; int b }     // 漏了最后的分号
int main() { S s; return 0; }
```
```
g++ 8.1.0 输出：
error: expected ';' at end of member declaration
error: expected ';' after struct definition
```
编译器把下一行的 `int main()` 当成"结构体还没写完的成员"来解析，于是错误信息指向风马牛不相及的位置——**这是新手最崩溃的一类报错，根因永远在上一行的 `}`**。详见 §12 陷阱 1。

### ③ 怎么用

#### （A）三种定义变量的方式（课件 P7 左右两栏并列给出）

```cpp
#include <iostream>
using namespace std;

// 方式①：先定义类型，后单独定义变量（最常用）
struct student {
    string name;
    int age;
    double score;
};
struct student s1;         // 严格写法：带 struct 关键字（课件 P8 用的就是这个）
student s2, s3;            // C++ 简写：可省略 struct（C++ 允许，C 语言不允许）

int main() {
    // 方式②：定义类型的同时定义变量（课件 P7 右栏）
    struct person { string name; int age; } p1, p2;
    p1.age = 20;

    // 方式③：匿名结构体——只留变量，不给类型名（此后无法再定义第二个同类变量）
    struct { int x; int y; } pointA = {3, 4};
    cout << pointA.x << "," << pointA.y << endl;
    cout << s2.name.empty() << " " << p1.age << endl;
    return 0;
}
// 输出：3,4
// 输出：1 20      （string 默认构造为空串，empty() 返回 true → 打印 1）
```

三种方式对比表（相似概念必须表格对比）：

| 方式 | 写法骨架 | 能否再定义同类变量 | 典型用途 |
|---|---|---|---|
| ① 先类型后变量 | `struct X{...};` 然后 `X a;` | ✅ 可以 | **99% 的场景**，推荐 |
| ② 类型与变量同时 | `struct X{...} a,b;` | ✅ 可以（X 有名字） | 只在本文件用一次的类型 |
| ③ 匿名 | `struct {...} a;` | ❌ **不能**，只能靠 `typeof`/`decltype` | 临时凑一对值；本章作业不涉及 |

#### （B）两种初始化方式（课件 P8）

```cpp
#include <iostream>
using namespace std;
struct student { string name; int age; double score; };
int main() {
    // 路径 A：先定义，再逐个给成员赋值（课件 P8 左栏完整程序）
    struct student s1;
    s1.name = "张三";        // 逐行给成员赋值
    s1.age = 20;
    s1.score = 99.5;

    // 路径 B：定义时用大括号整体初始化（课件 P8 右下注释给出的写法）
    student s2 = {"李四", 21, 99.5};   // 顺序必须与成员声明顺序一致！
    student s3{"王五", 22, 88.0};      // 等号可省（列表初始化，C++11 起）

    cout << s1.name << s1.age << s1.score << endl;
    cout << s2.name << s2.age << s2.score << endl;
    cout << s3.name << s3.age << s3.score << endl;
    return 0;
}
// 输出：张三2099.5
// 输出：李四2199.5
// 输出：王五2288
```

⚠️ 课件 P8/P9 原文里用的是**中文引号和中文分号**（`student s1 = {“张三”，20，99.5}；`），这是幻灯片排版的产物，**直接抄进编译器必然报错**。见 §12 陷阱补充。

#### （C）部分初始化：剩余成员自动补零 —— 本机实测

```cpp
#include <iostream>
using namespace std;
struct student { string name; int age; double score; };
int main() {
    student a{"张三"};     // 只给第一个成员，其余按类型做值初始化
    student b{};           // 空大括号 → 全部归零
    cout << a.name << "|" << a.age << "|" << a.score << "\n";
    cout << b.name << "|" << b.age << "|" << b.score << "\n";
    return 0;
}
// ▶ 实测输出：
// 张三|0|0
// |0|0        （string 为空串，int/double 为 0）
```

结论：**大括号初始化没写满的部分会自动补零/补空串**，这是安全网；而完全不写 `{}` 就没有这张网（见 §1.4）。

### ④ 注意事项

1. **成员顺序即初始化顺序**。`student s2 = {21, "李四", 99.5};` 会把 `int` 塞给 `string`，编译失败或隐式转换出乱码。口诀：**图纸从上到下，括号从左到右**。
2. **不要在结构体定义内部使用中文标点**。课件里的 `“” ， ；` 是排版美化，代码必须是半角 `"`, `,`, `;`。
3. **匿名结构体不可复用**。方式③定义出的类型没有名字，写不出 `?? s4;` 这样的第二句，实务中几乎只用方式①。

> 🗣️ **人话总结**：定义是画图，变量才是发货。

## §1.3 结构体成员访问（P9｜🔴 重点延续）

### ① 是什么

**一句话定义**：用**点运算符 `.`** 通过"变量名 . 成员名"读写成员，即课件 P9 所说"访问结构体成员"。

**生活化比喻**：行李箱侧面贴着标签，你喊"箱子名 + 标签名"就能伸手进那一格——`s1.name` 就是"张三那只箱子的『姓名』格"。

### ② 为什么

**Q1：为什么不能用 `s1[0]` 这样按下标访问？**
数组下标依赖"元素同类型且等宽"，结构体成员类型各异、还被对齐填充隔开，偏移量算不出来。C++ 因此改成**按名字定位**（课件 P5："成员一般用名字访问"）。

**Q2：那编译器怎么知道 `.name` 在哪？**
编译期就把 `s1.name` 翻译成 `*( (char*)(&s1) + offsetof(student, name) )`。这正是下一章画 ASCII 内存图时要实测的**偏移量**。

**Q3：为什么 `.` 是"成员访问"而不是"取值"？**
`.` 左边必须是**对象本体**；如果左边是指针，语义就不对了——那是 §2.1 `->` 的领地。混淆二者是本章第一大错误。

### ③ 怎么用（课件 P9 完整示例，实测可编译）

```cpp
#include <iostream>
using namespace std;
struct student { string name; int age; double score; };
int main() {
    student s1 = {"张三", 20, 99.5};    // 课件 P9 的整体初始化
    cout << s1.name << endl;            // 点号访问：读
    cout << s1.age  << endl;
    cout << s1.score<< endl;
    s1.age = 21;                        // 点号访问：写（成员是普通变量，可左值）
    cout << s1.age  << endl;
    return 0;
}
// 输出：张三
// 输出：20
// 输出：99.5
// 输出：21
```

**执行时的内存状态追踪**（关键：不是语法翻译）：

| 语句执行后 | `s1.name` | `s1.age` | `s1.score` | 说明 |
|---|---|---|---|---|
| `student s1 = {"张三",20,99.5};` | "张三" | 20 | 99.5 | 三格同时填好，string 内部可能分配堆内存 |
| `cout << s1.name;` | "张三" | 20 | 99.5 | 只读出，不改状态 |
| `s1.age = 21;` | "张三" | **20 → 21** | 99.5 | 偏移 32 处的 4 字节被改写 |

### ④ 注意事项

❗ **常见错误示范：把成员当独立变量使**

```cpp
struct student { string name; int age; };
int main() {
    student s1;
    // cout << name << endl;      // ❌ 编译错误：'name' was not declared in this scope
    cout << s1.name << endl;      // ✅ 必须带"谁的名牌"
    return 0;
}
```

后果：`'name' was not declared in this scope`。成员名**只在对象语境里有意义**，脱离 `s1.` 就成了未声明标识符。（例外：§1.5 成员函数内部可直接写成员名，因为隐含了 `this->`。）

> 🗣️ **人话总结**：点名要点姓，`s1.name` 才对。

## §1.4 结构体默认值（P10｜⚪ 常规）

### ① 是什么

**一句话定义**（课件 P10 原文）：「在 C++11 标准后，可以直接在定义结构体时给成员赋初始值」。学名 **NSDMI**（Non-Static Data Member Initializer，非静态数据成员初始化器）。

```cpp
struct student {          // 课件 P10 原文，三种写法混用
    string name="C++";    // 等号形式
    int age{20};          // 大括号形式
    double score{99.5};   // 大括号形式
};
```

**生活化比喻**：给行李箱**出厂预设**——每次新造一只箱子，姓名格里已经躺着"C++"、年龄格已经写着 20，不用你每次手动塞。

### ② 为什么

**Q1：为什么要出厂预设？**
防"垃圾值"事故。不预设时，局部结构体的 `int/double` 成员是栈上的残留比特。

❗ **本机实测证据**（同一个结构体，有没有 `{}` 天差地别）：

```cpp
#include <iostream>
using namespace std;
struct Plain { string name; int age; double score; };        // 无 NSDMI
int main() {
    static Plain gp;              // 静态存储 → 零初始化
    Plain arr[3];                 // 局部数组，成员未初始化
    Plain z{};                    // 显式值初始化
    cout << "[static] age=" << gp.age << " score=" << gp.score << "\n";
    cout << "[局部数组] arr[2].age = " << arr[2].age << " (垃圾)\n";
    cout << "[z{}] age=" << z.age << " score=" << z.score << "\n";
    return 0;
}
// ▶ 实测输出：
// [static] age=0 score=0
// [局部数组] arr[2].age = 8 (垃圾)          ← 同一个 8 也出现在 classcode L108 附近实验中
// [z{}] age=0 score=0
```

看到没：`arr[2].age` 拿到了 **8**——这不是巧合，是栈上残留。**程序换个写法它就变另一个数**，这就是"偶现 bug"的经典来源。

**Q2：为什么 `string` 成员从来没垃圾值？**
因为 `string` 是类类型，**自带默认构造函数**，无论你是否写 `= ""`，它都会被构造成空串。而 `int/double` 是内置类型（POD），没人替它们初始化。

**Q3：为什么课件要在 P21 的案例里重新用上默认值？**
因为一旦有了 NSDMI，`printStudent(student s)` 收到的形参即使不被整体初始化也有兜底值——这让课件 P21 那个"只传三个值却含默认值定义"的例子显得自然。

### ③ 怎么用

```cpp
#include <iostream>
using namespace std;
struct student {
    string name = "C++";     // 别名式默认
    int age{20};             // 推荐：大括号，防止窄化转换
    double score{99.5};
    void printInfo() { cout << name << " " << age << " " << score << endl; }
};
int main() {
    student a;               // 一个都没赋 → 全用默认值
    a.printInfo();
    student b{"王五", 21, 99};   // 显式给值 → 覆盖默认值
    b.printInfo();
    student c;  c.age = 30;      // 只改一格，其余保持默认
    c.printInfo();
    return 0;
}
// ▶ 实测输出（g++ -std=c++14）：
// C++ 20 99.5
// 王五 21 99
// C++ 30 99.5
```

`classcode.cpp` 第 6–9 行用的正是这套（并把第三种写成 `=` 形式）：

```cpp
struct student {
	string name{ "赵四" };
	int age{ 20 };
	double score=100;        // ← 这里换成 = 形式，效果与 {} 等价
	void printInfo() { ... }
};
```

### ④ 注意事项 ❗（本笔记实测纠偏，重要）

**默认值 ≠ 永远生效。** 三条边界必须清楚：

| 情形 | NSDMI 是否生效 | 实测 |
|---|---|---|
| `student a;`（无任何初始化） | ✅ 生效 | `a.age == 20` |
| `student b{"王五",21,99};` | ✅ 未列出的成员才用默认值 | 见上例 |
| `student arr[3];`（局部数组，无 `{}`） | ✅ 生效（每个元素都跑一遍默认） | — |
| `Plain p;`（**无** NSDMI 的局部变量） | — | `age` 是垃圾值 8 |
| `static Plain g;` | — | 零初始化 `age==0` |

**跨标准大坑（课件没讲，此处补齐）**：带 NSDMI 的结构体在 **C++11 下不能再用大括号整体初始化**！

❗ **本机实测**（同一份代码换标准）：

```cpp
struct student { string name="C++"; int age{20}; double score{99.5}; };
int main() { student s1 = {"王五", 21, 99}; }   // 课件 P8/P9/P21 的写法
```
```
g++ -std=c++11 → error: could not convert '{"王五", 21, 99}'
                  from '<brace-enclosed initializer list>' to 'student'
g++ -std=c++14 → 编译通过，输出：王五 21 99
```

原因：C++11 规定"有用户提供的成员初始化器"的类型**不算聚合类 (aggregate)**，因而禁用聚合初始化；**C++14 撤销了这条限制**。所以课件 P10（引入默认值）与 P8/P21（大括号整体初始化）若一起编译，**必须用 `-std=c++14` 及以上**。

> 🗣️ **人话总结**：默认值是保险，别指望它替你擦屁股。

## §1.5 结构体中定义成员函数（P11–P12｜⚪ 常规 · 面向对象前哨）

### ① 是什么

**一句话定义**（课件 P11 语法）：结构体的大括号里除了数据成员，还可以写**函数**——它就是该类型的成员函数。

```cpp
struct structName{
    type name1;
    type name2;
    type name3;
    type funcName(type val1，type val2) {   // 课件 P11 原文（注意逗号是中文，实际须半角）
        return val;
    }
};
```

课件 P12 给了具体版本：

```cpp
struct student {
    string name; int age; double score;
    void printInfo(){            // 打印学生信息
        cout << name << endl;    // ← 注意：不带 s1. 前缀，直接用成员名
        cout << age << endl;
    }
};
```

**生活化比喻**：行李箱不再只是容器，它变成**智能行李箱**——你对它说"自报家门"（`s1.printInfo()`），它自己打开每一格念出来。以前你要在外面一格格翻，现在功能长在箱子上。

### ② 为什么

**Q1：为什么函数能写进结构体？**
C++ 的 struct 是"数据 + 行为"的封装载体，成员函数通过隐藏的 `this` 指针知道自己服务哪只箱子。

**Q2：为什么函数体内可以直接写 `name` 而不写 `s1.name`？**
编译器把它补全为 `this->name`。这也是 §1.3 那条"必须带对象前缀"的唯一合法例外。

**Q3：为什么这一步是"面向对象的入口"？**
一旦 struct 里有了成员函数，它与 `class` 的实际差别就只剩**默认访问权限**（见下表）。第 19 章面向对象的所有语法，起点就在这里。

### ③ 怎么用（完整可运行）

```cpp
#include <iostream>
using namespace std;
struct student {
    string name{"赵四"};           // classcode.cpp L7 的默认值
    int age{20};
    double score = 100;
    void printInfo() {             // 成员函数：定义在结构体内部即隐式 inline
        cout << name << "  " << age << "  " << score << endl;
    }
    void growUp(int years) {       // 带参数、能改成员
        age += years;
    }
};
int main() {
    student s1;
    s1.printInfo();               // 输出默认值：赵四  20  100
    s1.growUp(9);                 // age: 20 → 29
    s1.printInfo();               // 输出：赵四  29  100
    return 0;
}
// ▶ 实测输出：
// 赵四  20  100
// 赵四  29  100
```

**📌 struct vs class 前瞻对比表**（课件专项要求 2：建立认知锚点，但不深入展开）

| 对比项 | `struct` | `class` | 本章立场 |
|---|---|---|---|
| 默认成员访问权限 | **public**（人人可碰） | **private**（须经接口） | 实测见下 |
| 默认继承方式 | `public : Base` | `private : Base` | 第 19 章再学 |
| 能否写成员函数 | ✅ 能 | ✅ 能 | 完全一样 |
| 内存布局 / sizeof | 一样受对齐规则支配 | 一样（多态时多一个虚表指针） | 本章 §4.1 实测 |
| 习惯用途 | 纯数据打包（POD 味道） | 有不变量、需要封装的对象 | 本章全用 struct |

❗ **实测验证默认权限**：

```cpp
struct S { int a; };   class C { int a; };
int main(){ S s; s.a = 5;   /* OK */
            C c; c.a = 5;   /* ❌ */ }
// g++ 输出：error: 'int C::a' is private within this context
// 而 struct 版编译 0 错误 → struct 默认 public 得证
```

**从 struct 到 class 的三步演化预告**（专项补充 4）：

```
 第 1 步（P6–P9）        第 2 步（P11–P12）           第 3 步（第 19 章）
┌──────────────┐   ┌───────────────────┐   ┌────────────────────────┐
│ struct student│   │ struct student {   │   │ class Student {        │
│ {            │→  │  string name;      │→  │  private:              │
│   string name;│   │  int age;          │   │   string name; int age;│
│   int age;    │   │  void printInfo(){ │   │  public:               │
│ };           │   │    ...             │   │   void printInfo();    │
│ 只有数据      │   │  };  ← 本章到此    │   │ };  ← 数据藏起来       │
│ "能不能装"   │   │ "装了还会说话"     │   │ "别人不能乱改"         │
```

### ④ 注意事项

❗ **错误示范 1：成员函数写在结构体外面却忘了限定名**

```cpp
struct student { string name; void printInfo(); };   // 只声明
```

❗ **错误示范 2：课件 P11 语法里的中文逗号**

## §2.1 结构体指针（P13–P16｜🔴 重点）⭐⭐⭐

### ① 是什么

**一句话定义**（课件 P13 原文）：「指针可以存放任意数据类型的地址……也可以存放**结构体**的地址，存放结构体地址的指针，称为结构体指针。」

```cpp
struct structName *pName;    // 课件 P13 语法：定义一个指向 structName 的指针
```

访问其成员时，**不再用点，而用箭头 `->`**（课件 P14），或者**先解引用再加括号用点**（课件 P15）。

**生活化比喻**：`student s1` 是"箱子本体"；`student* ps` 是"写着箱子存放位置的纸条"。拿着纸条你不能直接开箱，得**按地址去取**——`ps->name` 读作"顺着 ps 记的地址，进那口箱子的 name 格"。

### ② 为什么

**Q1：为什么需要结构体指针？**
三个刚需：① 函数想把结构体"地址"传进去以修改原件（§3.2）；② 结构体很大（本章实测 48 字节），拷地址只要 8 字节；③ 动态申请与链表/树等结构全靠指针串联。

**Q2：为什么指针不能沿用 `.`？**
`.` 的左操作数要求是**对象类型**；指针是地址类型，语义不符。编译器只能另给一个既解引用又取成员的运算符，即 `->`。

**Q3：为什么 `*p.member` 一定出错？**（课件 P15 核心警告）
> 课件 P15 原文：「使用 `*` 的方式访问结构体成员，必须要使用 `()` 改变运算符的优先级，否则，会出错。」

因为 **`.` 的优先级高于 `*`**。`*p.age` 会被解析成 `*(p.age)`，即"先在指针 p 上取成员 age"——而指针没有成员。

❗ **本机实测报错**：

```cpp
student s1{...}; student* p = &s1;
cout << *p.age << endl;      // 想表达 *(p.age)，实际就是这个错误解析
```
```
g++ 8.1.0：error: request for member 'age' in 'p', which is of pointer type 'student*'
           (maybe you meant to use '->' ?)
```
注意编译器还贴心地反问"你是不是想用 `->`"——这是本章最高频的编译错误。

### ③ 怎么用

#### （A）`->` 与 `(*p).` 等价性实证（课件 P14/P15/P16 三页合并演示）

```cpp
#include <iostream>
using namespace std;
struct student { string name; int age; double score;
    void printInfo(){ cout << name << "  " << age << "  " << score << endl; } };
int main() {
    student s1;
    student* ps1 = &s1;              // 课件 P16：取址
    ps1->name = "诸葛亮";             // 写法①：箭头
    (*ps1).age = 20;                 // 写法②：解引用 + 点（括号不可省）
    ps1->score = 98.5;
    cout << ps1->name   << endl;     // 诸葛亮
    cout << (*ps1).age  << endl;     // 20
    // 铁证：两种写法算出的成员地址完全相同 → 真的是同一格
    cout << "&(ps1->name)   = " << &(ps1->name)   << endl;
    cout << "&((*ps1).name) = " << &((*ps1).name) << endl;
    s1.printInfo();
    return 0;
}
// ▶ 实测输出：
// 诸葛亮
// 20
// &(ps1->name)   = 0x61fe00
// &((*ps1).name) = 0x61fe00      ← 地址一模一样，等价性得证
// 诸葛亮  20  98.5
```

#### （B）运算符优先级辅助表（专项要求 3）

| 优先级（数字越小越先算） | 运算符 | 结合性 | 本章相关例子 |
|---|---|---|---|
| **1（最高）** | `a.b` / `a->b` / `a[i]` / `f(x)` | 左到右 | `p.name` 先成一体 |
| 2 | 一元 `*p` / `&x` / `++` / `!` | 右到左 | `*p` 在 `.` 之后才算 |
| 3 | `*` `/` `%` | 左到右 | `rand()%61` |
| 4 | `+` `-` | 左到右 | `weekday1 + weekday2` |
| 5 | `<` `>` `<=` | 左到右 | `w1 < w2` |
| 6 | `=` `+=` | 右到左 | `s.age = 21` |

由此推出四种写法判定：

| 写法 | 解析过程 | 结果 |
|---|---|---|
| `p->age` | 箭头一体 | ✅ 20 |
| `(*p).age` | 括号强制先解引用 | ✅ 20 |
| `*p.age` | 先 `p.age` → 指针无成员 | ❌ 编译错误 |
| `s->age`（s 是对象） | 对象不能用箭头 | ❌ `base operand of '->' has non-pointer type` |

#### （C）内存视角图解

```
        栈内存                              结构体 student（48 字节，实测）
  ┌─────────────────┐          ┌──────────────────────────────────────────────┐
  │ student s1      │◄─────────┤ name(offset 0, 32B)│age(32,4B)│pad│score(40,8B)│
  │  地址 0x61fe00  │   &s1    └──────────────────────────────────────────────┘
  └─────────────────┘                    ▲
  ┌─────────────────┐                    │
  │ student* ps1    │── 值 = 0x61fe00 ───┘   ps1->age  ≡  *(int*)(0x61fe00 + 32)
  │  地址 0x61fdf8  │  本身只占 8 字节          (*ps1).age ≡ 同上（完全等价）
  └─────────────────┘
```

### ④ 注意事项（野指针防御）

❗ **错误 1：指针未初始化就 `->`**

```cpp
student* pw;              // 值随机
cout << "pw(未初始化) = " << (void*)pw << endl;   // ▶ 实测：0x401519（栈残留）
// cout << pw->age;       // ❌ 未定义行为：可能崩溃，也可能读到诡异数字
```

❗ **错误 2：`delete` 后继续用（悬垂指针）**

✅ **防御三板斧（本机实测有效）**：

```cpp
#include <iostream>
using namespace std;
struct student { string name{"赵四"}; int age{20}; double score=100; };
int main() {
    student* p1 = nullptr;              // 板斧①：声明即置空
    student s1{"张三",20,99.5};
    if (p1 == nullptr) cout << "p1 是空指针，拒绝访问（防御成功）\n";
    p1 = &s1;                           // 板斧②：用前确已指向有效对象
    if (p1 != nullptr) cout << "判空通过，p1->name = " << p1->name << "\n";
    student* hp = new student{"堆上",30,60};
    cout << "hp->age = " << hp->age << "\n";
    delete hp; hp = nullptr;            // 板斧③：释放后立即置空
    cout << "delete 后置空 hp = " << (hp==nullptr?"nullptr":"dangling") << "\n";
    return 0;
}
// ▶ 实测输出：
// p1 是空指针，拒绝访问（防御成功）
// 判空通过，p1->name = 张三
// hp->age = 30
// delete 后置空 hp = nullptr
```

另外：`classcode.cpp` L58 写的是 `student s1, * ps1;` —— 一行同时定义对象和指针，`*` 只作用于 `ps1`。看懂它的等价于 `student s1; student* ps1;`，但**这种混写在 C++ 里可读性差，建议拆开写**。

> 🗣️ **人话总结**：变量用点，指针用箭。

## §2.2 结构体数组（P17–P19｜🔴 重点）⭐⭐⭐

### ① 是什么

**一句话定义**（课件 P17 原文）：「数组可以存放任意的数据类型……也可以存放**结构体**，存放结构体的数组，称为结构体数组。」

```cpp
struct structName arrName[len];   // 课件 P17 语法：每个元素都是一个 structName
```

**生活化比喻**：一个班级门口挂了 3 个一样的行李箱，编上号 0/1/2。`arrstu[1].age` 读作"**1 号箱**的年龄格"——先按编号选箱（`[]` 优先级高），再按标签选格（`.`）。

### ② 为什么

**Q1：为什么已经有了 struct，还要 struct 数组？**
一个 struct 只解决"**一个**事物的多个属性"。真实系统总有"**很多**同类事物"：全班学生、全部订单。若不用数组，就得写 `s1,s2,...,s100` 并手写一百遍，课件 P49 案例 1 的 `} s[100];` 正是这个需求。

**Q2：为什么不能拿二维数组代替？**
`int grid[100][5]` 要求 5 列同类型；而学生是 `string + int + double` 混合。类型异构 ⇒ 必须 struct；数量多 ⇒ 必须数组。两者叠加才有"结构体数组"。

**Q3：为什么遍历要用 `for` 而不是逐个写？**
因为只有 `i` 是变量。而且注意：`arr[i].name` 这个表达式里 **`[]` 和 `.` 都是左到右**，所以 `arr[i].name` 天然等价于 `(arr[i]).name`，不需要括号；但若换成指针 `p`，`p[i].name` 也行、`(p+i)->name` 也行——这是 §2.1 优先级知识的复用。

### ③ 怎么用

#### （A）循环录入 + 循环输出（课件 P18 案例）

```cpp
#include <iostream>
using namespace std;
struct student { string name; int age; double score;
    void printInfo(){ cout << name << "  " << age << "  " << score << endl; } };
int main() {
    student arrstu[3];
    for (int i = 0; i < 3; i++) {                          // 输入
        cin >> arrstu[i].name >> arrstu[i].age >> arrstu[i].score;
    }
    for (int i = 0; i < 3; i++) {                          // 输出
        cout << arrstu[i].name << "  " << arrstu[i].age << "  " << arrstu[i].score << endl;
    }
    return 0;
}
// 输入：张三 20 99.5 / 李四 21 88 / 王五 22 77.5
```

### ④ 注意事项（下标越界风险）

❗ **错误示范：循环边界写错**

```cpp
student arr[3];
for (int i = 0; i <= 3; i++) {          // ❌ i 会取到 3 → arr[3] 不存在
    arr[i].age = 20;                    //    越界写：静默破坏相邻栈变量，或直接段错误
}
for (int i = 0; i < 3; i++)             // ✅ 正确：合法下标恒为 0..len-1
```

C++ **不做数组边界检查**——越界不像 Java 抛 `ArrayIndexOutOfBoundsException`，而是**未定义行为**：可能今天正常、明天崩，也可能悄悄改了隔壁变量。课件 P49 案例里 `s[100]` 配 `2<n<100` 就是在人为保证不越界（但严格说 `n` 最大可到 99，`i<n` 仍安全；若 `n==100` 也刚好用满，`n>100` 立即越界）。

求长度的唯一正确姿势（主调方）：

```cpp
student arr[3];
int len = sizeof(arr) / sizeof(arr[0]);   // ✅ 144/48 = 3 —— 只能在"真数组"所在的作用域用
```
一旦 arr 进入函数形参就会退化，此式失效——见 §3.3 与 §12 陷阱 3。

> 🗣️ **人话总结**：先选箱再挑格，下标莫越界。

## §3.1 值传递（P20–P21）

### ① 是什么

**一句话定义**：形参写成 `structName structVal`（不带 `*` 不带 `[]`），调用时**整个结构体被复制一份**给形参。

**生活化比喻**：你把行李箱**复印了一份**交给同事，他在复印件上贴了新标签。归还后你打开自己那只箱子——一切如旧。

### ② 为什么

**Q1：为什么 C++ 默认这么"浪费"？**
因为值传递换来**隔离安全**：函数不可能意外弄脏调用方的数据，推理成本低。这是 C++ 的默认哲学（"你没说要共享，那就给你独立的"）。

**Q2：为什么"改不动原件"？**
形参与实参是两块内存。函数内的所有写操作落在副本上，`return` 时副本销毁，原件从头到尾没被碰过。

**Q3：为什么开销随体积增大？**
复制要逐字节搬。本章实测一只 `student` = **48 字节**，并且内含 `string`（复制可能触发**堆内存分配 + 字符串拷贝**，比 48 字节的 memcpy 贵得多）。循环里传一万次就是一万次深拷贝。

### ③ 怎么用（课件 P21 完整案例，实测通过）

```cpp
#include <iostream>
using namespace std;
struct student {
    string name="C++";        // 课件 P21 保留了 P10 的默认值
    int age{20};
    double score{99.5};
};
void printStudent(student s) {           // 形参：值传递 → 收下一条副本
    cout << s.name << endl;
    cout << s.age  << endl;
    cout << s.score<< endl;
}
int main() {
    student s1 = { "王五", 21, 99 };     // 课件 P21 主体
    printStudent(s1);
    return 0;
}
// ▶ 实测输出（-std=c++14）：
// 王五
// 21
// 99
```

**classcode.cpp L80–81 的同源片段**（取消注释后可编译）：

```cpp

printStudent(s1);*/
// ▶ 实测输出：王五 21 99      （L18-20 的 printStudent 用空格分隔并同行打印）
```

### ④ 注意事项

❗ **错误示范：以为值传递能改原件**

```cpp

int main(){ student u; wrongInit(u); cout << u.name; }        // 仍是默认值 "C++"

```

> 🗣️ **人话总结**：值传是复印，改不动原件。

## §3.2 指针传递（P22）

### ① 是什么

**一句话定义**：形参写成 `structName* p`，调用时只传**地址**，函数通过 `->` 直达原件。

**生活化比喻**：你不寄箱子，只把**仓库货架编号**写在纸条上发给同事。他照编号直奔原件，随便改，你回头看到的必然是改过的。

### ② 为什么

**Q1：为什么传地址就能改原件？**
因为地址是**唯一的门牌号**。`p->age = 29` 编译成"往 `p+offsetof(age)` 写"，那块内存正是实参本体。

**Q2：为什么开销固定为 8 字节？**
指针大小只取决于 CPU 地址总线宽度（x64 = 8 字节），与被指对象多大**无关**。实测：`sizeof(String)==8`（typedef 指针别名），而 `sizeof(student)==48`。

**Q3：为什么课件 P22 里函数名叫 `printStudent` 但调用写 `printStudent2(&s1)`？**
这是幻灯片的排版遗留——P21 的 `printStudent(student)` 与 P22 的 `printStudent(student*)` 同名，若同时存在会构成重载；课件为了让你一眼看出"这是第二个版本"，正文用了 `printStudent2`。**`classcode.cpp` L22 落实为 `printStudent2`**，与之呼应。读课件时要能识破这种"示意性不一致"。

### ③ 怎么用（课件 P22 案例 + classcode L84–87 实证）

```cpp
#include <iostream>
using namespace std;
struct student { string name; int age; double score;
    void printInfo(){ cout << name << "  " << age << "  " << score << endl; } };
void printStudent2(student *s) {         // 形参：指针
    cout << s->name << endl;             // ← 用 ->，不是 .
    cout << s->age  << endl;
    cout << s->score<< endl;
}
int main() {
    student s1 = { "王五", 21, 99 };
    printStudent2(&s1);                  // 课件 P22 原样：直接传 &
    student* ps2 = &s1;
    printStudent2(ps2);                  // classcode L86：先存进指针变量再传
    return 0;
}
// ▶ 实测输出（两次调用完全相同）：
// 王五
// 21
// 99
// 王五
// 21
// 99
```

**能改原件的实证（classcode L22–24 风格）**：

```cpp
void bump(student* s){ s->age += 9; }     // 通过指针写原件
int main(){ student t{"赵四",20,100};
    cout << t.age; bump(&t); cout << t.age; }
// ▶ 输出：20 然后 29   —— age 从默认值 20 变为 29，原件确实被改了
```

### ④ 注意事项

❗ **错误 1：忘记取地址符**

```cpp
printStudent2(s1);     // ❌ no known conversion for argument 1 from 'student' to 'student*'
printStudent2(&s1);    // ✅
```

❗ **错误 2：传了空指针**

```cpp
student* p = nullptr;
printStudent2(p);      // ❌ 运行时崩：段错误（解引用空指针）
// 正确：函数入口判空
void safePrint(student* s){ if (s == nullptr) { cout << "空指针，忽略\n"; return; } s->printInfo(); }
```

❗ **错误 3：把 `s->name` 写成 `s.name`** —— 报错见 §2.1 实测：`request for member 'name' in 's', which is of pointer type 'student*'`。

> 🗣️ **人话总结**：指针传地址，改动回得去。

## §3.3 数组传递（P23）

### ① 是什么

**一句话定义**：形参写成 `structName s[]`（或直接 `structName* s`），实参传数组名，**收到的是首元素地址**；必须**额外传长度**。

**生活化比喻**：一整排货架的钥匙其实只有"起始编号"这一把。你把"从 0 号架开始"告诉同事，但**必须同时告诉他一共有几架**，否则他不知道何时该停手。

### ② 为什么

**Q1：为什么数组不能整体拷贝传参？**
C++ 里数组类型**不可复制**（不能作为形参按值传递）。语言层面的出路就是"传地址"，于是数组名在表达式中**自动退化 (decay) 为指针**。

**Q2：为什么必须另传 `len`？**
退化后函数手里只有一个地址，**排面有多长这件事彻底丢失**。课件 P23 的签名 `void printStudent(student s[], int len)` 里那个 `int len` 不是风格选择，而是**语法必需**。

**Q3：为什么 `sizeof` 会骗人？**
`sizeof` 看的是**声明的类型**，不是运行时的实际对象。形参 `s` 的声明类型是 `student*`，所以 `sizeof(s)==8`。

❗ **本机实测（陷阱 3 的铁证）**：

```cpp
#include <iostream>
using namespace std;
struct student { string name; int age; double score; };
void wrong(student arr[]) {
    cout << "函数内 sizeof(arr)                = " << sizeof(arr) << "\n";
    cout << "函数内 sizeof(arr)/sizeof(arr[0]) = " << sizeof(arr)/sizeof(arr[0]) << " (错!)\n";
}
int main(){
    student arr[3];
    cout << "主调方 sizeof(arr)   = " << sizeof(arr) << "\n";
    cout << "主调方 正确长度      = " << sizeof(arr)/sizeof(arr[0]) << "\n";
    wrong(arr);
    return 0;
}
// ▶ 实测输出：
// 主调方 sizeof(arr)   = 144
// 主调方 正确长度      = 3
// 函数内 sizeof(arr)                = 8          ← 只剩指针大小
// 函数内 sizeof(arr)/sizeof(arr[0]) = 0          ← 8/48 整除 = 0，循环一次都不执行！
```

最后一行最阴险：长度为 0 **不会崩溃**，只会让函数"静悄悄地什么都不做"——bug 极难定位。

### ③ 怎么用（课件 P23 案例）

```cpp

using namespace std;

void printStudent(student s[], int len) {          // 课件 P23：数组 + 长度

    }
}

// ▶ 实测输出：
// 王五 21  99
// 张三 19  90
```

### ④ 注意事项

1. **`student s[]` 与 `student* s` 在形参位置上完全等价**，编译器视二者为同一类型。因此数组传递**能改原件**（实测见 §3.4）。
2. **不要试图在函数内恢复长度**。任何 `sizeof(形参)` 都只得 8。
3. **仍然要防越界**：`len` 传大了等于 §2.2 的越界写。

> 🗣️ **人话总结**：数组传地址，长度自己捎。

## §3.4 三种传参终极大对比（专项要求 6：性能与语义对照实验）

### 对照实验设计与实测输出

```cpp
// 实验：同一个结构体，走三条路径，打印修改前后的值证明"副本 vs 原件"
#include <iostream>
using namespace std;
struct student {
    string name{"C++"}; int age{20}; double score{99.5};
    void printInfo() { cout << name << "  " << age << "  " << score << endl; }
};
void byValue(student s)     { s.name = "inside_value";   s.age = 999; }
void byPointer(student* s)  { s->name = "inside_pointer"; s->age = 888; }
void byArray(student s[], int len) {
    for (int i = 0; i < len; i++) s[i].age = 777;
    cout << "函数内 sizeof(s)    = " << sizeof(s)   << "（指针！）\n";
    cout << "函数内 sizeof(s[0]) = " << sizeof(s[0])<< "\n";
}
int main() {
    cout << "== 主调方 sizeof(student[1]) = " << sizeof(student[1]) << "（真数组）\n\n";
    student a{"A", 20, 90};
    cout << "[改前]   a: "; a.printInfo();
    byValue(a);
    cout << "[值传后] a: "; a.printInfo();  cout << "\n";
    student b{"B", 20, 90};
    cout << "[改前]   b: "; b.printInfo();
    byPointer(&b);
    cout << "[指针后] b: "; b.printInfo();  cout << "\n";
    student arr[2] = {{"C",20,90},{"D",21,91}};
    cout << "[改前] arr[0]: "; arr[0].printInfo();
    byArray(arr, 2);
    cout << "[数组后] arr[0]: "; arr[0].printInfo();
    return 0;
}
```

▶ **本机实测输出（g++ 8.1.0 -std=c++14）**：

```
== 主调方 sizeof(student[1]) = 48（真数组）

[改前]   a: A  20  90
[值传后] a: A  20  90                      ← 纹丝不动 ⇒ 证明改的是副本

[改前]   b: B  20  90
[指针后] b: inside_pointer  888  90         ← 被改 ⇒ 证明改的是原件

[改前] arr[0]: C  20  90
函数内 sizeof(s)    = 8（指针！）
函数内 sizeof(s[0]) = 48
[数组后] arr[0]: C  777  90                 ← 被改 ⇒ 数组传参也是原件
```

### 完整对比表（背这张）

| 维度 | ① 值传递 | ② 指针传递 | ③ 数组传递 |
|---|---|---|---|
| 形参写法 | `student s` | `student* s` | `student s[]` 或 `student* s` |
| 实参写法 | `f(s1)` | `f(&s1)` | `f(arr, len)` |
| 课件出处 | P20–P21 | P22 | P23 |
| 配套代码 | classcode L18/L80 | L22/L84–87 | L26/L91–92 |
| 传的是什么 | **整份拷贝（48B + string 深拷贝）** | 地址（**恒定 8B**） | 首元素地址（8B） |
| 函数内访问符号 | `s.name` | `s->name` | `s[i].name` |
| 能否改原件 | ❌ **不能** | ✅ 能 | ✅ 能 |
| 是否需要额外长度参数 | 否 | 否 | **是（必须传 len）** |
| `sizeof(形参)` 含义 | 48（真对象） | 8（指针） | **8（退化，陷阱！）** |
| 空值风险 | 无 | **有（须判空）** | 有（须判空 + 判 len） |
| 适用场景 | 小结构体、只想读 | 单个对象、要改或怕拷 | 一批对象 |
| 一句话记忆 | 复印 | 给门牌号 | 给起始门牌 + 报个数 |

**选型口诀**：**读多用 const 引用，改必给地址，批量连长度。**

> 🗣️ **人话总结**：值传安全但白拷，指针省事要判空，数组还得带长度。

## §4.1 共用体 / 联合体 union（P24–P29｜🟡 熟悉）

### ① 是什么

**一句话定义**（课件 P24 原文）：「共用体可以存放任意数据类型的组合，也可以用来存放任意数据类型的集合；共用体也叫**联合体**。」关键性质同页给出：

> 「结构体的各个成员会占用**不同**的内存，互相之间没有影响，而共用体的所有成员占用**同一段**内存，修改一个成员会影响其余所有成员。」

```cpp
union unionName{        // 课件 P25 语法
    Type1 filed1;
    Type2 filed2;
    Type3 filed3;
};
unionName.fileld;       // 课件 P26：访问语法与 struct 完全相同，还是用点
```

**生活化比喻**：struct 是**多居室公寓**，每人一间房；union 是**一张单人床**——张三、李四、王五排班睡，同一时刻床上只有一个人，后来者把前一个人的被子直接掀了。所以"这张床多大"取决于**最胖的那个人**。

### ② 为什么（追问三层）

**Q1：为什么要发明一种"成员互相覆盖"的怪东西？**
为了**省内存**。某些场景下这些字段逻辑上互斥（同一块字节要么是整数解释、要么是浮点解释），给每个字段单独开内存纯属浪费。

**Q2：为什么大小只等于最长成员？**
因为所有成员**起始地址相同**（下文实测 `&age == &weight`）。要保证任何一个成员都能完整放下，容器至少要装得下最大的那个。

**Q3：为什么实际项目里还要学它？**
三个真实用途：① **位级解读**——不写转换就看清 float 的比特模式；② **协议/寄存器解析**——同一块字节既能整体读又能按字段读；③ **tagged union 手写变体类型**。但日常业务代码极少用 union，故教材标"熟悉"而非"重点"。

### ③ 怎么用

#### （A）课件 P27 案例（含被注释的关键行）逐行讲透

```cpp
#include <iostream>
using namespace std;
union person {         // 课件 P27 原样：int + float
    int age;           // 4 字节
    float weight;      // 4 字节
};
int main() {
    person p1;
    p1.age = 20;              // 写入这 4 字节的整数解释
    //p1.weight = 50.5;       // ← 课件注释掉的一行（见下方 (B)）
    cout << p1.age << endl;   // 输出：20          —— 刚写的就是它，正常
    cout << p1.weight << endl;// 输出：2.8026e-44 —— 同一块比特换作 float 解释
    return 0;
}
// ▶ 本机实测输出：
// 20
// 2.8026e-44
```

课件 P27 的两条旁注解释了这一切：
- `//共用体的成员不可以全部一起使用，只能单独使用其中某一个字段。`
- `//共用体成员间影响内存`

**为什么 `p1.weight` 打印出 `2.8026e-44`？** 整数 20 的比特模式是 `0x00000014`；IEEE-754 单精度把 `0x00000014` 解释为一个极小的**非规格化数** ≈ 2.8×10⁻⁴⁴。**内存没变，只是换了副眼镜去看它。**

#### （B）取消注释后：真正的"覆盖"演示（课件 P27 那行注掉的代码）

```cpp
#include <iostream>
using namespace std;
union person { int age; float weight; };
int main() {
    person p1;
    p1.age = 20;             // 此刻内存 = 整数 20 的比特
    cout << p1.age << endl;  // 20
    p1.weight = 50.5f;       // ★ 覆盖！此刻内存 = float 50.5 的比特
    cout << p1.weight << endl;
    cout << p1.age << endl;  // ← age 已经不再是 20
    cout << "&age=" << &p1.age << " &weight=" << &p1.weight << "\n";
    return 0;
}
// ▶ 本机实测输出：
// 20
// 50.5
// 1112145920                     ← 50.5 的 IEEE-754 比特 0x424A0000 按 int 读出的值
// &age=0x61fe4c &weight=0x61fe4c  ← 两成员地址完全相同 ⇒ 共享同一块内存得证
```

`0x424A0000` 转十进制正是 **1112145920** —— 这就是课件 P28「如果对新的成员赋值，就会把原来成员的值覆盖掉」的字节级铁证。

#### （C）sizeof 实测验证（课件 P29 要求的写法）

```cpp
#include <iostream>
using namespace std;
struct StructName { int a; double b; };     // 4 + (4 pad) + 8 = 16
union  UnionName  { int a; double b; };     // max(4, 8) = 8
int main() {
    int sizeStruct = sizeof(struct StructName);
    int sizeUnion  = sizeof(union  UnionName);
    cout << "sizeStruct = " << sizeStruct << " sizeUnion = " << sizeUnion << endl;
    return 0;
}
// ▶ 实测输出：sizeStruct = 16 sizeUnion = 8
```

课件 P29 用的就是这个 `cout` 模板。本章另有一组贴近 classcode 的实测：

| 对象 | 成员构成 | 实测 sizeof | 出处 |
|---|---|---|---|
| `union person{int age; float weight;}` | 4 + 4 | **4** | P27 |
| `union mixed{int a; double b; char c;}` | 4 / 8 / 1 | **8**（最长者） | 补测 |
| `struct personS{int age; float weight;}` | 4 + 4 | **8** | 补测 |
| `union person{int age; double weight;}` | 4 / 8 | **8** | classcode L32–35 + L109 |
| `struct student{string name; int age; double score;}` | 32+4+pad+8 | **48** | classcode L6–9 + L108 |

⚠️ **一处必须注意的课件与代码差异**：课件 P27 的 `union person` 第二个成员是 **float**（故 sizeof=4），而 `classcode.cpp` L32–35 改成了 **double**（故 sizeof=8）。做 sizeof 对照题时**一定看你手上那份定义**。

#### （D）ASCII 内存布局对比图（专项要求 1）

```

     └────────┘
```

### ④ 注意事项

❗ **陷阱 1：试图同时使用多个成员**

```cpp
person p; p.age = 20; p.weight = 50.5f;
cout << p.age << " " << p.weight;   // ❌ 语法没错，但 age 已是垃圾值 1112145920
// 正确认知：写完最后一个成员，之前的成员全部作废。
```

❗ **陷阱 2：读取从未写入过的成员** —— 课件 P27 未注释状态下的 `cout << p1.weight` 就是这种：合法但读的是**用另一种类型重新解释的比特**，不是"忘了赋值的随机垃圾"，而是"有确定比特、无确定语义"。

❗ **陷阱 3：给 union 放带构造/析构函数的成员（如 string）**

```cpp
union Bad { string s; int i; };   // ❌ error: ... has non-trivial constructor
```
union 不知道该调用哪个成员的构造/析构，因此**任何有非平凡特殊成员函数的类型都不能做 union 成员**。这是 C++ 相较 C 的新增限制，也是 union 应用面窄的主因。

❗ **陷阱 4：混淆"最长"与"最大对齐"**。union 的大小不仅要容纳最长成员，还必须是其**最宽成员对齐要求的整数倍**。例如 `union U{ char c; int i; };` → sizeof = 4（不是 1）。口诀：**先取最长，再向上取整到对齐倍数**。

**struct vs union 对比表**（相似概念表格并列）

| 对比项 | `struct` | `union` |
|---|---|---|
| 关键字 | `struct` | `union` |
| 成员内存 | **各自独立**（可能含填充缝隙） | **全部重叠在同一地址** |
| 大小规则 | ≥ 所有成员之和（`≥` 因缝隙，课件 P28 原话） | = 最长成员（并满足对齐） |
| 能否同时保存多成员 | ✅ 能 | ❌ 不能，一次只有一个 |
| 改一个是否影响其他 | 不影响 | **必然影响**（内存覆盖技术） |
| 访问符号 | `.` / `->` | `.` / `->`（完全一样） |
| 成员默认初始化值(NSDMI) | 允许（C++11 起） | **禁止** |
| 可放 string 等类类型成员 | ✅ 可以 | ❌ 不可以（非平凡构造） |
| 典型用途 | 建模实体 | 省内存、位级解读、协议解析 |
| 课件出处 | P6–P23 | P24–P29 |

> 🗣️ **人话总结**：结构体分房间，共用体抢张床。

## §4.2 枚举类型 enum（P30–P39｜🟡 熟悉）

### ① 是什么

**一句话定义**（课件 P30 原文）：「枚举类型 (enumeration) 是 C++ 中的一种**派生数据类型**，它是由用户定义的若干**枚举常量**的集合。」

```cpp
enum <类型名> {<枚举常量表>};    // 课件 P30 语法
```
同页强调：「"枚举常量"或称"枚举成员"，是**以标识符形式表示的整型量**……各枚举常量之间以","间隔，且**必须各不相同**。」

**生活化比喻**：`int` 是一条从 0 通到 20 亿的公路，车能停在任何位置；`enum week` 是**只有 7 个站台的地铁站**——你可以说"我在 3 号站台"，但不能停在两站之间的隧道里。枚举就是把"合法的数字"提前点名造册。

### ② 为什么（追问三层）

**Q1：为什么不直接用 `int` 表示星期？**
可读性 + 取值受限。`if (d == 3)` 里的 3 是**魔数**（到底周三还是周四？取决于你的私有约定）；`if (d == Wed)` 自解释。

**Q2：既然底层是 int，编译器还管什么？**
管赋值合法性。课件 P36：「枚举变量的值只能取枚举常量表中所列的值，就是整型数的一个子集」。❗实测 `w = 0;` 报错 `invalid conversion from 'int' to 'week'`。这就是"带类型检查的常量集"的价值。

**Q3：为什么枚举常量允许重复？**（课件 P32「各枚举常量的值可以重复」）
因为它是给整数**贴标签**，同一编号允许多个别名。例：`enum Status{ OK=0, SUCCESS=0, FAIL=1 };` 两种写法表达同一结果。

### ③ 怎么用

#### （A）基本定义（课件 P31）

```cpp
enum color {RED, BLUE, WHITE, BLACK};                 // 定义枚举类型 color
enum week  {Sun, Mon, Tue, Wed, Thu, Fri, Sat};        // 定义枚举类型 week
```

#### （B）编号规则的三种情形（课件 P32 的两个例子，实测复现）

```cpp
#include <iostream>
using namespace std;
enum fruit { apple, orange, banana = 1, peach, grape };
// 规则：指定值之前按默认序号；banana 显式 =1；之后依次 +1
enum week  { Sun = 7, Mon = 1, Tue, Wed, Thu, Fri, Sat };
int main() {
    cout << "apple=" << apple << " orange=" << orange << " banana=" << banana
         << " peach=" << peach << " grape=" << grape << "\n";
    cout << "Sun=" << Sun << " Mon=" << Mon << " Tue=" << Tue << " Wed=" << Wed
         << " Thu=" << Thu << " Fri=" << Fri << " Sat=" << Sat << "\n";
    return 0;
}
// ▶ 实测输出（与课件 P32 结论逐项一致）：
// apple=0 orange=1 banana=1 peach=2 grape=3      ← banana 与 orange 同为 1 ⇒ 值可重复
// Sun=7 Mon=1 Tue=2 Wed=3 Thu=4 Fri=5 Sat=6      ← Mon 显式 1，其后继续 +1
```

编号规则汇总：

| 情形 | 写法 | 取值规则 | 实测例 |
|---|---|---|---|
| 全默认 | `{a,b,c}` | 从 **0** 递增 | `a=0 b=1 c=2` |
| 中途指定 | `{apple,orange,banana=1,peach,grape}` | 指定前默认、指定处取值、之后 **+1** | `0,1,1,2,3` |
| 开头指定 | `{Sun=7,Mon=1,Tue,...}` | 同上，从 Mon 起重编 | `7,1,2,3,4,5,6` |
| classcode 版 | `{Sun=100,Mon,Tue=1,Wed,Thu,Fri,Sta}` | — | ▶ 实测 `Sun=100 Mon=101 Tue=1 Wed=2 Thu=3 Fri=4 Sta=5` |

> ⚠️ classcode L164 的 `Sta` 是课件/代码共同的**拼写笔误**（应为 `Sat`）。它照样能编译——枚举常量只是个标识符，编译器不看语义。这类"能跑但名字错了"的坑只能靠自查。

#### （C）枚举常量必须是标识符（课件 P33）

```cpp
// ❌ 课件 P33 明确列出的两个错误示范
enum letter {'a','b','c'};            // 枚举常量不能是字符常量
enum year  {2022,2023,2024,2025};     // 枚举常量不能是整型常量
// ✅ 正确改写（课件 P33 右半栏）
enum letter {a,b,c};
enum year   {y2022,y2023,y2024,y2025};
```
❗ **本机实测报错**：`error: expected identifier before 'a'` —— 印证 P33 的说法。

#### （D）定义枚举变量（课件 P34–P35 两种方式）

```cpp
enum week {Sun, Mon, Tue, Wed, Thu, Fri, Sat};
week w1, w2;                                  // 方式①：先类型后变量（P34/P35 左）
                                              //   C++ 中 enum 关键字可省略；C 语言必须写 enum week w1;
enum {Sun, Mon, Tue, Wed, Thu, Fri, Sat} m1, m2;   // 方式②：类型与变量同时定义，类型名可省略（P35 右）
```

#### （E）四允许（课件 P36–P38 + classcode L118–131）

```cpp
#include <iostream>
using namespace std;
enum week { Sun, Mon, Tue, Wed, Thu, Fri, Sat };   // 默认编号 Sun=0 … Sat=6
int main() {
    week weekday1, weekday2;
    weekday1 = Sun;                                     // 允许①：赋【枚举名】（P37）
    weekday2 = Mon;
    if (weekday1 < weekday2) cout << "day1 < day2\n";   // 允许②：参与【关系运算】（P38）
    cout << "允许③：可直接输出整数 weekday2 = " << weekday2 << "\n";  // 允许③：输出操作
    int num = weekday1;                                 // 允许④：隐式转 int（P38 末行）
    cout << "允许④：转 int 参与运算 num+weekday2 = " << (num + weekday2) << "\n";
    cout << "weekday1 + weekday2 = " << weekday1 + weekday2 << "\n";  // classcode L131 亦如此
    return 0;
}
// ▶ 实测输出：
// day1 < day2
// 允许③：可直接输出整数 weekday2 = 1
// 允许④：转 int 参与运算 num+weekday2 = 1
// weekday1 + weekday2 = 1
```

**同一个程序，只把枚举定义换成 classcode 的 `Sun=100` 版本**，▶ 实测第一行变成 `w1 !< w2`、末两行变成 `102`：

```cpp
enum week{Sun=100,Mon,Tue=1,Wed,Thu,Fri,Sta};   // classcode L116 原样
// 其余代码不变 → ▶ 实测：w1=100, w2(Wed)=2 → 输出 "w1 !< w2" / 100 / 2 / 102
```

这正是"改一个初始值，比较结果整个翻转"的教学点——也是本笔记反复强调**必须知道每个常量的实际整数值**的原因。

#### （G）switch 配合枚举的典型用法（课件 P39 第四条建议）

课件 P39 收口：「枚举变量的输入输出一般都采用 **switch 语句**将其转换为字符或字符串。」完整可运行版本（即课件 P51 案例 2，详见 §5.2）：

```cpp
#include <iostream>
using namespace std;
enum week { Sun, Mon, Tue, Wed, Thu, Fri, Sat };   // ★ 必须保持默认编号，Sun==0
int main() {
    int n; cin >> n;
    switch (n) {
        case Sun: cout << "星期日" << endl; break;
        case Mon: cout << "星期一" << endl; break;
        case Tue: cout << "星期二" << endl; break;
        case Wed: cout << "星期三" << endl; break;
        case Thu: cout << "星期四" << endl; break;
        case Fri: cout << "星期五" << endl; break;
        case Sat: cout << "星期六" << endl; break;
        default : cout << "输入非法" << endl; break;
    }
    return 0;
}
// ▶ 实测输出：输入 0→星期日，1→星期一，… 6→星期六，9→输入非法
```

#### （H）enum 的本质与内存

| 问题 | 答案 | 依据 |
|---|---|---|
| 底层是什么 | 整型量（课件 P30"以标识符形式表示的整型量"） | P30 |
| 变量占几字节 | 与 int 相同（实测 `sizeof(week)==4`） | P36「占用内存的大小与整型数相同」 |
| 枚举常量作用域 | **直接进入外层作用域**，`Sun` 全局可见 | 经典 enum 特性 |
| 会不会与外层同名冲突 | **会**（`enum{Open,Close}; int Close;` → 重定义错误） | 补测 |
| 现代解法 | `enum class`（强类型、须 `Weekday::Sun`、不能隐式转 int）——**本章不涉及** | 后续章节 |

### ④ 注意事项

❗ **陷阱 1：改了初值还套用上一版的 switch**。§5.2 专门分析：一旦写成 `enum week{Sun=7,...}`，P51 的 `case Sun:` 就不再对应输入 0。

❗ **陷阱 2：漏写 `break`**。`case Sun: cout<<"星期日";` 后面没有 break，会**贯穿 (fall through)** 继续执行下一个 case，输出"星期日星期一…"。这是课件 P51 每个 case 都老实写 `break` 的原因。

❗ **陷阱 3：想"输入枚举名"**。用户想输入 `Mon` 得到 1？枚举不支持 `cin >> w`。必须先 `cin >> n`（int），再用 `switch(n)` 映射；反向输出同理。

❗ **陷阱 4：指望枚举自动做范围校验**。`w = (week)999;`（强制转换）能绕过禁止①，运行时值是 999，不在 {0..6} 内。所以**别信"枚举变量一定合法"**，外部输入仍要自己校验。

❗ **陷阱 5：不同枚举类型混用当"同一整数"**。`weekday1 = RED;` 编译失败（禁止③），即使两者底层都是小整数。想让它们互通必须显式 `(week)RED`——而这已是在破坏类型安全，慎用。

> 🗣️ **人话总结**：枚举是给整数起的具名小圈子。

## §4.3 用 typedef 定义类型别名（P40–P47｜🟡 熟悉）

### ① 是什么

**一句话定义**（课件 P40 原文）：「typedef 是 C/C++ 中一个很关键的关键字，它的作用是**用来给类型起别名**。因为在遇上不同数据类型，尤其是复杂类型。」

**通用骨架**：`typedef  原有类型  新别名;`　（读懂一切用法的钥匙：把"原类型"当作一个整体替换成"别名"）

课件 P40 列出五类适用对象：**1. 基本数据类型　2. 结构体　3. 数组　4. 枚举类型　5. 指针**。

**生活化比喻**：typedef 是**改备注名**，不是新建联系人。你手机里"王总"和"老王"指向同一个人——给他发消息、让他搬家都是同一件事，不会因为有俩名字就变成俩人。与之相对，`#define PI 3.14` 是**便利贴抄了个数字**，纯文本替换，压根不是联系人（这个区别第 16 章主讲）。

### ② 为什么（追问三层）

**Q1：为什么要起别名？**
两类动机：① **可读性**——`typedef unsigned long UserId;` 让函数签名自解释；② **简化复杂声明**——函数指针、数组、嵌套指针写得让人眼花，别名能把它们拍平。

**Q2：为什么要专门讲五种用法？**
因为 typedef 的语序**不总是"类型在前、别名在后"**。数组那条（P43）最反直觉：别名被挤在中间。不掌握规律就只能死记硬背。

**Q3：为什么指针别名配 const 会翻车？**（P46/P47 重点警告）
因为 typedef 建立的是**一个不可分割的类型整体**。`const 别名` 中的 const 修饰"这个别名所代表的整个类型"，而不是"展开后的最左边"。这是本课最抽象的一点，下面用实测钉死。

### ③ 怎么用：五种用法逐个击破（课件 P41–P47）

统一实验文件（一次跑完五种用法）：

```cpp
#include <iostream>
using namespace std;
struct Person { string name; int age; };
enum Color { Red, Green, Blue };

typedef int Myint;                  // ① 基本数据类型（P41）
typedef struct Person P;            // ② 结构体（P42）
typedef int C[10];                  // ③ 数组（P43）★别名夹在中间
typedef Color primaryColor;         // ④ 枚举（P44/P45）
typedef char* String;               // ⑤ 指针（P46/P47）

int main() {
    Myint n = 100;                                    // ① 等价 int n = 100;
    cout << "① Myint n = " << n << "\n";

    P p1{"张三", 20};                                 // ② P 就是 struct Person
    cout << "② P p1 -> " << p1.name << " " << p1.age << "\n";

    C t; t[0] = 999; t[9] = 111;                     // ③ t 的类型是 int[10]
    cout << "③ C t; sizeof(t)=" << sizeof(t) << " t[0]=" << t[0] << " t[9]=" << t[9] << "\n";

    primaryColor G = Red;                             // ④ 枚举别名
    cout << "④ primaryColor G = Red -> " << G << "\n";

    String s1 = "name";                               // ⑤ 指针别名
    cout << "⑤ String s1 = " << s1 << "\n";

    cout << "\nsizeof(String)=" << sizeof(String)
         << " sizeof(Myint)=" << sizeof(Myint)
         << " sizeof(C)=" << sizeof(C) << "\n";
    return 0;
}
```

▶ **本机实测输出（g++ 8.1.0 -std=c++14）**：
```
① Myint n = 100
② P p1 -> 张三 20
③ C t; sizeof(t)=40 t[0]=999 t[9]=111
④ primaryColor G = Red -> 0
⑤ String s1 = name

sizeof(String)=8 sizeof(Myint)=4 sizeof(C)=40
```

五种用法要点表：

| # | 用法 | 课件原文骨架 | 关键提醒 |
|---|---|---|---|
| ① | 基本类型（P41） | `typedef int Myint;`<br>`typedef double Mydouble;` | 课件：「起了别名以后，别名就相当于原类型名的同义词，能使用原类型的地方就可以使用别名。`int num` 和 `Myint num` 等价。」 |
| ② | 结构体（P42） | `typedef struct Person P;` | 「将别名放在结构体之后」。C++ 里 `typedef Person P;` 也成立（struct 名可省）；带 `struct` 是兼容 C 的风格 |
| ③ | 数组（P43） | `typedef int C[10];`<br>`C t;` | ⚠️ **反直觉位置**：课件原文「别名被挤在**数组元素类型和数组元素个数之间**」。实测 `sizeof(C)==40`，证明 `C t;` 得到的是**整个数组**，不是指针 |
| ④ | 枚举（P44/P45） | `typedef Color primaryColor;`<br>`primaryColor G = Red;` | 「和结构体类型类似」。课件 P44 与 P45 **文字完全相同**（幻灯片重复排版），本笔记已逐字核对 |
| ⑤ | 指针（P46/P47） | `typedef char* String;`<br>`String s1 = "name";` | const 陷阱见下方专段。P46 与 P47 同样是重复页 |

#### ⑤ 深度拆解：const + 指针别名（课件 P46/P47 特别警告）

课件原文：
> 「对指针起别名需要注意的一点就是，如果要对别名加 const 关键字，必须要知道，我们声明的是一个**常量指针**，而不能将其按照字面上，理解为**指向常量的指针**。」

先把这对易混术语钉清楚（相似概念表格并列）：

| 名称 | 写法 | 含义 | 能否改指向 | 能否改所指内容 |
|---|---|---|---|---|
| **常量指针** (pointer to const) | `const char* p;` | 指针可变，内容只读 | ✅ 能 | ❌ 不能 |
| **指针常量** (const pointer) | `char* const p;` | 指针本身是常量，内容可变 | ❌ 不能 | ✅ 能 |
| 二者皆常 | `const char* const p;` | 都不能改 | ❌ | ❌ |

课件说的「常量指针」指的是**指针本身为常量**（上表第二行；部分中文教材把这一行译作"指针常量"，命名分歧历来存在）。**无论叫什么，行为由实测唯一确定**，见下。

```cpp
#include <iostream>
using namespace std;
typedef char* STRING;        // 别名代表 "char*" 这个整体
int main(){
    const STRING cs = "aaa";         // ★ 等价于 char* const cs（指针本身是常量）
    // cs = "bbb";                   // ❌ 编译错误：assignment of read-only variable 'cs'
    char buf[8] = "hello";
    const STRING cp = buf;           // OK
    *cp = 'H';                       // ✅ 指向的内容【可以】改 ⇒ 它绝不是"指向常量的指针"
    cout << "改内容后 cp = " << cp << "\n";
    return 0;
}
// ▶ 本机实测输出：改内容后 cp = Hello
// ▶ 若放开 cs = "bbb"; 则编译报错：error: assignment of read-only variable 'cs'
```

**证据链闭合**：
- 改指向 → 编译失败 ⇒ 指针自身是 const；
- 改内容 → 成功并把 `"hello"` 变成 `"Hello"` ⇒ 所指内容**不是** const。

⇒ `const STRING` **≠** `const char*`，而 **==** `char* const`。课件 P46 的话成立。

**为什么会这样（第三层为什么）**：把别名当作**原子单位**做替换，`const STRING` → `const (char*)` → 括号内的 `char*` 整体被 const 修饰，于是"指针是常量"。想表达"指向常量"，请**不要把 const 加在别名前面**，而应把 const 写进别名本身：

```cpp
typedef const char* ConstStr;   // const 在别名内部 → 这才是"指向常量的指针"
ConstStr a = "hello";           // a 可重新指向；*a 不可改
```
这也正是 `classcode.cpp` L173 采用的写法：
```cpp
/*typedef const char* str;
str s = "abcd";
cout << s << endl;*/
// ▶ 实测输出：abcd
```

#### typedef vs using 现代 C++ 对照表（专项要求 5）

| 维度 | `typedef`（本课主用） | `using`（C++11 别名声明） |
|---|---|---|
| 基本类型 | `typedef int Myint;` | `using Myint = int;` |
| 结构体 | `typedef struct Person P;` | `using P = struct Person;` |
| 数组 | `typedef int C[10];` | `using C = int[10];` |
| 枚举 | `typedef Color primaryColor;` | `using primaryColor = Color;` |
| 指针 | `typedef char* String;` | `using String = char*;` |
| const 语义 | 别名是原子，见上文 | **与 typedef 完全一致**：`using S=char*; const S` 仍是 `char* const` |
| **模板别名** | ❌ **做不到**（只能为每个具体实例各 typedef 一次） | ✅ `template<class T> using Vec = vector<T, MyAlloc<T>>;` |
| 可读性 | 别名藏在最右，长声明需从内往外读 | **赋值式语法**：左边新名字、右边原类型，顺读 |
| 类内成员别名 | 可以 | 可以（更常见） |
| 兼容性 | C/C++ 通吃，老代码海量 | 仅 C++11 起 |
| 本课立场 | ✅ **以 typedef 为主**（课件全部示例都用它） | 了解即可，面试常被追问 |

复杂类型可读性对比（体会 using 的优势）：

```cpp
// typedef 版：别名在最左，要从中间往外读
typedef void (*Handler)(int, char);            // Handler = "接受(int,char)、返回void的函数指针"
typedef const char* (*Comparer)(const char*, const char*);

// using 版：主语在左，宾语在右，一眼看懂
using Handler  = void (*)(int, char);
using Comparer = const char* (*)(const char*, const char*);

// 只有 using 能做到的模板别名
template <typename T> using IntVec = vector<T>;
IntVec<int> v;      // ✅ 推导自别名模板
// typedef 无法泛化，必须为 int/long/double... 各写一行 ❌
```

**选型建议**：跟着课件走用 typedef，保证你能读懂 P40–P47 每一行；自己写新代码时优先 `using`，涉及模板别名则**只能**用 `using`。

### ④ 注意事项

❗ **陷阱 1：把 typedef 当 `#define`**。

```cpp
#define STR char*
STR a, b;         // 展开为 char* a, b;  → a 是 char*，b 只是裸 char ❗（逗号后丢了 *）
typedef char* Str2;
Str2 a, b;        // 两者都是 char*  ✅ —— 这正是 typedef 优于宏的核心理由
```
第 16 章预处理会把这条差异展开细讲，此处先立锚点。

❗ **陷阱 2：数组别名位置写错**。

```cpp
typedef int arrA[10];   // ✅ 别名夹在中间
typedef int[10] arrB;   // ❌ error: expected unqualified-id before '[' token
```

❗ **陷阱 3：看到 `const 别名` 就以为是"指向常量"** —— 已在 ③ 用实测推翻。背这句：**「typedef 出来的别名是铁板一块，const 加在前面动不了内部的星号结构。」**

❗ **陷阱 4：别名遮蔽**。`typedef double score;` 之后再写 `struct student{ double score; };` 虽然合法，但同名极易误读。**别名一律用大驼峰或加后缀 T**（`Myint` / `ScoreT`），与变量名拉开风格差异。

❗ **陷阱 5：给指针类型起带 `*` 的别名后又叠加数组**。`typedef int* IntPtr; IntPtr a, b;` 两者都是 `int*` ✅；但若误写成 `typedef int* IntPtr[5]` 之类会得到"指针数组"，语义完全变了。复杂别名务必先用 `sizeof` 验一次（本文 ③ 就是用 `sizeof(C)==40` 确认它是数组而非指针）。

> 🗣️ **人话总结**：typedef 是改备注，本体还是同一个类型。

## §5.1 课堂案例 1：找总分最高的学生（P48–P49）⭐必考题型

### 题目（课件 P48 原文）

> 利用结构体，输入 n（2<n<100）个学生姓名，年龄，和三科（语文，数学，英语）成绩，找出总成绩最高的学生，输出该学生的信息。

### 解题思路（4 步拆解）

1. **建模**：一名学生 = `name + age + 三科成绩 + total` ⇒ 一个 struct，共 6 个成员（total 是派生量，也存进结构体，省得反复相加）。
2. **批量**：n 个学生 ⇒ **结构体数组** `s[100]`（上限 100 由题目 `n<100` 决定，呼应 §2.2）。
3. **边读边算**：录入每科成绩的同时立即累加 `total`，避免二次遍历。
4. **打擂台求最值**：维护"当前最高分"与其主人，遇到更大者就更新——这是求最值的通用范式。

### 课件 P49 原始代码（照录，实测可编译）

```cpp
#include <iostream>
using namespace std;
struct student {
    string name;
    int age;
    double chinese;
    double math;
    double english;
    double total;
} s[100];                          // ★ 定义类型的同时定义了全局数组 s[100]（§1.2 方式②）

int main() {
    int n; double maxv = 0; student s2;
    cin >> n;
    for (int i = 0; i < n; i++) {
        cin >> s[i].name >> s[i].age >> s[i].chinese >> s[i].math >> s[i].english;
        s[i].total = s[i].chinese + s[i].math + s[i].english;   // 边录入边求和
    }
    for (int i = 0; i < n; i++) {
        if (s[i].total > maxv) { maxv = s[i].total; s2 = s[i]; } // 结构体整体赋值！
    }
    cout << s2.name << " " << s2.age << " " << s2.chinese << " "
         << s2.math << " " << s2.english << " " << s2.total << endl;
    return 0;
}
```

### 实测运行

```
输入：
3
Tom 19 90 90 90
Amy 20 99 99 99
Bob 21 80 80 80

▶ 实测输出：Amy 20 99 99 99 297
```

**逐步状态追踪**（不是语法翻译，而是内存/状态变化）：

| 阶段 | `maxv` | `s2` | 说明 |
|---|---|---|---|
| 进入 main | 0 | 全空对象 | `student s2;` 无 NSDMI ⇒ 成员是垃圾值（隐患！见下文缺陷 B） |
| 循环 i=0 | 0 → **270** | ← s[0] Tom | 270 > 0 成立，打擂成功，`s2 = s[0]` 整体拷贝 **72 字节**（▶ 实测 `sizeof(student)==72`：name 32 + age 4 + 填充 4 + 四个 double 共 32） |
| 循环 i=1 | 270 → **297** | ← s[1] Amy | 297 > 270 成立，换人 |
| 循环 i=2 | 297 | Amy | 240 > 297 不成立，`s2` 保持不动 |
| 输出 | 297 | Amy | 297 = 99+99+99 ✓ |

两个值得表扬的写法：
- **`s2 = s[i];` 结构体可以整体赋值**（同类型自动逐成员拷贝，含 string 深拷贝）。不必一行行搬五个成员——这是 §1.1"打包成一个整体"红利的兑现。
- **`} s[100];` 把类型定义与数组定义合成一句**（§1.2 方式②），且作为全局对象获得零初始化。

### ❗ 课件代码的两个真实缺陷（实测暴露，务必掌握）

**缺陷 A：输入格式与 `cin` 顺序必须逐字对齐，否则静默错位。**
题目说"输入姓名、**年龄**、三科成绩"，课件循环也确实读了 `age`。但如果按直觉只输入"姓名 + 三科成绩"（少一个年龄），`cin` 会**依次灌入、整体前移**：

```
输入（故意少写年龄）：      实际读到：
Tom 90 90 90        →      name="Tom", age=90, chinese=90, math=90, english=未读到(0)

▶ 课件原版实测输出：Tom 90 90 90 0 180
   ↑ age 变成了 90，english 为 0，total 只有 180，全盘皆错
```
教训：`cin >> a >> b >> c` 严格按空白切分依次赋值，**缺一个值不会报错，只会全体前移**。输入格式必须与读入顺序逐字对齐。

**缺陷 B：`maxv = 0` 作初值，遇到"全部 0 分"永远选不出人。**
`s[i].total > maxv` 在 `maxv==0` 且所有人 total 都是 0 时**永不成立**，`s2` 从未被赋值 ⇒ 输出垃圾值。

```
输入：
2
X 20 0 0 0
Y 21 0 0 0

▶ 课件原版实测输出（全是随机比特）：
 7678544 2.07557e-317 0 0 3.95253e-323
```
这不是偶发崩溃，而是**逻辑必然**：条件一次都没满足过，打印的是 `student s2;` 的未初始化成员。

**修复方案（本机实测通过）**：改用**下标打擂台**，不引入"哨兵初值"这个隐患。

```cpp
#include <iostream>
using namespace std;
struct student { string name; int age;
    double chinese, math, english, total; } s[100];
int main() {
    int n; cin >> n;
    for (int i = 0; i < n; i++) {
        cin >> s[i].name >> s[i].age >> s[i].chinese >> s[i].math >> s[i].english;
        s[i].total = s[i].chinese + s[i].math + s[i].english;
    }
    int best = 0;                                   // ✅ 用下标，先假定第 0 名最强
    for (int i = 1; i < n; i++) {                   // ✅ 从 1 开始比较
        if (s[i].total > s[best].total) best = i;
    }
    cout << s[best].name << " " << s[best].age << " " << s[best].total << endl;
    return 0;
}
// ▶ 边界用例实测：2 / X 20 0 0 0 / Y 21 0 0 0   → 输出：X 20 0   （正确！不再乱码）
// ▶ 常规用例实测：3 / Tom 19 90 90 90 / Amy 20 99 99 99 / Bob 21 80 80 80 → Amy 20 297
```

**改进理由（第三层）**：`best = 0` 是"从已有候选里选最优"，天然不需要虚构一个比所有人都小的哨兵值；即使 `n == 1` 也能正确输出。而 `maxv = 0` 版本连"分数为负"的场景都会崩（成绩不为负，但换成利润、温差就必须警惕）。

**若坚持保留 maxv 版本，最小改动有三种**：`double maxv = -1e18;` ／ `bool first = true;` 标志位 ／ `double maxv = s[0].total;` 并把循环起点设为 1。

### 注意事项清单

1. `s[100]` 硬编码上限，若 `n >= 100` 立刻越界（§2.2 陷阱）。生产环境应 `new student[n]` 或用 `vector`。
2. `student s2;` 未初始化 ⇒ 一旦上面 bug 触发就输出垃圾值。**给结构体加 NSDMI 是最便宜的保险**（§1.4）。
3. `cin >> s[i].name` 遇空格截断，姓名含空格需改 `getline`。
4. 若需要"最高分的多人并列"，`>` 只留最后一人；要收集全部并列者需先求 max 再二次遍历。

> 🗣️ **人话总结**：打擂台用下标，别设假想敌。

## §5.2 课堂案例 2：枚举 + switch 输出星期（P50–P51）

### 题目（课件 P50 原文）

> 输入数字 0-6，0 表示星期日，通过 switch 和 enum 实现，输出星期对应汉字表述。
> 输入用例：0　　输出用例：星期日

### 解题思路

1. **需求翻译**："0-6 各有唯一含义" ⇒ 天生适合 enum 具名化（§4.2）。
2. **为什么必须默认编号**：题目要求 `0 ↔ 星期日`，而 enum 默认从 0 递增（P32），`Sun` 恰好是 0 ⇒ **绝对不能写 `Sun=7` 之类的自定义初值**，否则映射全乱。
3. **输入侧**：枚举不能用 `cin >> w`（禁止②），所以**用 int 接住输入**，再把枚举常量当 `case` 标签用（它们是整型常量表达式）。
4. **switch 的 case 必须是常量表达式** —— 枚举常量正是"具名整型常量"，完美契合。

### 课件 P51 代码（照录）

```cpp
enum week { Sun, Mon, Tue, Wed, Thu, Fri, Sat };   // 定义枚举类型 week（默认编号 0..6）
int n;
cin >> n;
switch (n) {
    case Sun: cout << "星期日" << endl; break;
    case Mon: cout << "星期一" << endl; break;
    case Tue: cout << "星期二" << endl; break;
    case Wed: cout << "星期三" << endl; break;
    case Thu: cout << "星期四" << endl; break;
    case Fri: cout << "星期五" << endl; break;
    case Sat: cout << "星期六" << endl; break;
}
```

> 注：P51 幻灯片展示的是**核心片段**（无 `#include`、无 `main`）。完整可编译版本已在 §4.2(G) 给出，那里额外补了 `default` 分支。

### 实测运行（完整程序见 §4.2(G)）

```
输入 0 → 星期日      输入 1 → 星期一      输入 2 → 星期二
输入 3 → 星期三      输入 4 → 星期四      输入 5 → 星期五
输入 6 → 星期六      输入 9 → 输入非法（加了 default 才有兜底）
```

### 执行时的状态变化（逐行走读）

| 语句 | `n` | 匹配到的 case | 说明 |
|---|---|---|---|
| `enum week{Sun,...}` | — | — | 编译期把 Sun=0…Sat=6 烙进符号表，不产生运行时代码 |
| `int n;` | 垃圾 | — | 内置类型未初始化 |
| `cin >> n;` | 0 | — | 输入落到 int，绕开了"枚举不能输入"的限制 |
| `switch(n)` | 0 | 命中 `case Sun:`(=0) | switch 拿 n 逐个比对 case 常量 |
| `cout<<"星期日"` | 0 | 已命中 | 输出 |
| `break;` | 0 | — | **跳出 switch**，否则会贯穿继续打印"星期一…" |

### ❗ 深度辨析：如果初值改成别的会怎样？

假设有人"顺手"写成课件 P32 的 `enum week {Sun=7, Mon=1, Tue, Wed, Thu, Fri, Sat};`，那么 `case Sun`=7、`case Mon`=1、`case Tue`=2 …

▶ **实测**（把这份定义塞进 §4.2(B) 的程序并配 switch）：输入 0 → **落入 default**（没有任何 case 等于 0！）；输入 1 → 星期一（巧合正确）；输入 2 → 星期二（但按题意应该是"星期一"）……**除 Mon 外全错。**

结论：**代码的正确性依赖枚举的编号约定**。写 switch 之前先在心里（或注释里）确认每个常量的整数值。这也是课件把 P32（编号规则）与 P51（switch 案例）分在两处的用意。

### 更好的工程写法（了解即可，不要求掌握）

```cpp
#include <iostream>
using namespace std;
enum Weekday { Sun=0, Mon, Tue, Wed, Thu, Fri, Sat };
const char* weekdayName(Weekday d) {          // 用返回值代替一堆 cout，便于复用
    switch (d) {
        case Sun: return "星期日";
        case Mon: return "星期一";
        case Tue: return "星期二";
        case Wed: return "星期三";
        case Thu: return "星期四";
        case Fri: return "星期五";
        case Sat: return "星期六";
        default : return "非法输入";
    }
}
int main() {
    int n; cin >> n;
    if (n < Sun || n > Sat) { cout << "非法输入\n"; return 0; }   // 外部输入必须校验（§4.2 陷阱4）
    cout << weekdayName((Weekday)n) << endl;
    return 0;
}
// ▶ 输入 0 → 输出：星期日
```

### 专项补充 3：`rand() % 61 + 40` 公式深度拆解

**（A）为什么是 `% 61` 而不是 `% 60`？**

`x % n` 的结果集合是 `{0, 1, ..., n-1}`，**共 n 个值**。要拿到闭区间 [40, 100]：

```
区间元素个数 = 上界 - 下界 + 1 = 100 - 40 + 1 = 61   ← 这就是 61 的来源
rand() % 61      → {0, 1, ..., 60}   共 61 个值
rand() % 61 + 40 → {40, 41, ..., 100}  正好覆盖 40~100
```

❗ **通用公式**：`rand() % (b - a + 1) + a` 产生 `[a, b]` 闭区间。忘写 `+1` 是最常见的 off-by-one。

❗ **本机实测对照**（各跑 20 万次取极值）：
```
rand()%61+40 区间实测: [40, 100] 共 61 个值      ← 满分 100 能取到
rand()%60+40 区间实测: [40, 99]  ← 永远拿不到 100，少了一个值
```
所以若写成 `%60`，**没有任何学生会得满分**——功能上不会崩，只在业务上悄悄不对，极难发现。

**（B）`srand(time(NULL))` 播种的原理**

`rand()` 是**伪随机**：一个确定算法维护的内部状态序列。`srand(seed)` 决定起点，起点相同则整条序列完全相同。

❗ **本机实测三连**：
```
无 srand 时（默认种子 1），连续两次运行程序，前 3 个数完全相同：81 85 91 / 81 85 91
srand(12345) 固定种子，重复播种两次得到完全相同序列：60 50 93 / 60 50 93
srand((unsigned)time(NULL)) 每秒变化 → 每次运行结果不同（实测第二次首行分数已变）
```

由此得出两条推论：
- **不写 srand** ⇒ 每次运行分数一模一样。对"要复现 bug"的开发场景反而是好事，但对"每次都要不同分数"的作业是致命缺陷。
- **同一次运行内 1 秒内启动两次进程** ⇒ 种子相同、序列相同。这是 `time(NULL)` 精度只到秒的固有缺陷。

**（C）C++11 `<random>` 更优替代方案（简要介绍）**

```cpp
#include <iostream>
#include <random>
using namespace std;
int main(){
    mt19937 rng(random_device{}());              // 梅森旋转引擎，周期 2^19937-1
    uniform_int_distribution<int> dist(40, 100);  // ★ 闭区间，边界 inclusive，不用自己算 +1
    cout << "mt19937+uniform_int_distribution(40,100) 前5个: ";
    for(int k=0;k<5;k++) cout << dist(rng) << " ";
    cout << "\n对比 rand()%61+40: 需自己算模数 61 = 100-40+1\n";
    return 0;
}
// ▶ 实测输出：mt19937+... 前5个: 99 75 56 58 75   （每次运行不同）
```

| 维度 | `rand()/srand()` | `mt19937` + 分布器 |
|---|---|---|
| 标准 | C 遗留，全局状态 | C++11 `<random>`，可持有多个独立生成器 |
| 区间端点 | 必须手算 `% (b-a+1) + a` | `uniform_int_distribution<int>(a,b)` 直接写区间 |
| 质量 | 低位规律明显，周期由实现决定 | 周期 2¹⁹⁹³⁷−1，统计性质好 |
| 线程安全 | ❌ 全局状态不安全 | ✅ 每线程自己的引擎 |
| 可复现 | 靠 srand 固定种子 | 靠 `seed(seq)` 固定种子，更清晰 |
| 上手成本 | 极低（本课够用） | 稍高 |

**本课立场**：作业照旧用 `rand()`，但要清楚 `%61` 的推导和 `srand` 的必要性；正式项目请转 `<random>`。

### hw_code.cpp 的四个隐藏考点与两处瑕疵

**考点 1：`=` 与 `+=` 的配合（L20–21）**

```cpp
tarray[i].t_name = "teacher_";      // 覆盖：清空旧内容并放入前缀
```

若两步都写 `=`，第二步会把前缀冲掉只剩 `"A"`；若第一步写 `+=`，则会在"上一次残留内容"后面续写（首轮是空串侥幸正确）。**"首次 `=`、此后 `+=`"是 string 拼接的标准节奏。**

**考点 2：三级成员访问链（L24–25）**

`tarray[i].sarray[j].s_name` 的解析顺序（左到右，`[]` 与 `.` 同级）：

```
tarray  →  (i)  →  .sarray  →  (j)  →  .s_name
```

**考点 3：`struct student sarray[5]` 里的 `struct` 关键字（L13）**
C++ 中 `student` 已是类型名，`struct` 可省。写上它是**兼容 C 的习惯**，也起到"强调这是个结构体类型"的可读性作用。二者编译产物完全相同。

**考点 4：为什么 `allocatespace` 这个名字很怪？**
它其实什么都没 allocate（没有 new/malloc），只是在**填充已有栈内存**。真实含义是 `assignData`。这说明：**命名要贴合行为**，否则读者会误以为内部有动态内存分配。这是给新手的一个反面教材。

# §8 「补」深度补充：本章最难的两点慢速重讲

## 8.1 难点一：内存对齐与填充缝隙（为什么 32+4+8 ≠ 44）

**先摆实测事实**：

```cpp
struct S { string name; int age; double score; };
// sizeof(string)==32, sizeof(int)==4, sizeof(double)==8
// 直觉求和 = 44；▶ 实测 sizeof(S) == 48 —— 多出来的 4 字节就是"填充缝隙 (padding)"
```

**慢速拆解：CPU 为什么要挑地址？**

想象书架取书。CPU 读内存不是"一个字节一个字节"取的，而是按 **4/8 字节的整块**去取。如果一块数据横跨了两个整块的边界，CPU 就得分两次取再拼起来——**慢**。所以编译器自动把每个成员往后推，让它从"自己能被整除的地址"开始。这条规则叫**自然对齐**：成员的起始地址必须是 `min(sizeof(成员), 对齐基准)` 的整数倍。

**逐格推演（每一步都对照实测偏移量）**：

```
成员声明顺序 →   name (string, 32B)   age (int, 4B)    ???      score (double, 8B)
需要的对齐     32(或平台基准)          4                —        8
┌─────────────────────────────────┬───────┬───────┬────────────────┐
│ offset 0 ──────────────► 31     │ 32–35 │ 36–39 │ 40 ─────► 47   │
│            name (32B)           │  age  │ 填充  │     score      │
└─────────────────────────────────┴───────┴───────┴────────────────┘
                                     ▲        ▲        ▲
                              实测 age 偏移=32  这4B白给  实测 score 偏移=40
                                                    （必须 8 的倍数，36 不行 → 跳到 40）
总大小 = 48，且 48 是最大成员对齐(8) 的倍数 ✅
```

**为什么 36 不能放 double？** 因为 36 ÷ 8 = 4.5，不整除 ⇒ 违反 double 的 8 字节对齐要求 ⇒ 填 4 字节空隙推到 40。**这就是那 4 字节的唯一来历。**

**实测验证偏移量**（本笔记全部数据的出处）：

```cpp
cout << "offset name  = " << ((char*)&((S*)0)->name  - (char*)0) << endl;   // ▶ 0
cout << "offset age   = " << ((char*)&((S*)0)->age   - (char*)0) << endl;   // ▶ 32
cout << "offset score = " << ((char*)&((S*)0)->score - (char*)0) << endl;   // ▶ 40
cout << "sizeof(S)    = " << sizeof(S) << endl;                             // ▶ 48
```

**（专项补充 2）用 `#pragma pack(n)` 控制对齐粒度**

```cpp
#include <iostream>
using namespace std;
struct A  { char c; int i; double d; };        // 自然对齐
#pragma pack(push, 1)
struct B  { char c; int i; double d; };        // 强制 1 字节粒度：不留缝隙
#pragma pack(pop)
#pragma pack(2)
struct C2 { char c; int i; double d; };        // 2 字节粒度
#pragma pack()
int main(){
    cout << "A(c+i+d)  = " << sizeof(A)  << "\n";
    cout << "B pack(1) = " << sizeof(B)  << "\n";
    cout << "C2 pack2  = " << sizeof(C2) << "\n";
    cout << "成员偏移: A.c=" << (int)((char*)&((A*)0)->c - (char*)0)
         << " A.i=" << (int)((char*)&((A*)0)->i - (char*)0)
         << " A.d=" << (int)((char*)&((A*)0)->d - (char*)0) << "\n";
    return 0;
}
// ▶ 本机实测输出：
// A(c+i+d)  = 16        ← 1 + 3pad + 4 + 8 = 16
// B pack(1) = 13        ← 1 + 4 + 8 = 13，缝隙全消
// C2 pack2  = 14
// 成员偏移: A.c=0 A.i=4 A.d=8   ← age 被从 1 推到 4（3 字节缝隙）
```

对照图：

```
struct A（自然对齐，16B）
┌──┬───┬───┬───┬───────┬────────────────┐
│c │空闲│   i   │       d            │   1 + 3(padding) + 4 + 8 = 16
└──┴───┴───┴───┴───────┴────────────────┘
  0  1   2   3   4               16

struct B（#pragma pack(1)，13B）
┌──┬───────┬────────────────┐
│c │   i   │       d        │   1 + 4 + 8 = 13，紧凑但访问可能变慢
└──┴───────┴────────────────┘
  0  1       5              13
```

**⚠️ 项目忠告（专项补充 2 要求的提醒）**：`pack(1)` 并非"更省所以更好"。

| 取消对齐的代价 | 说明 |
|---|---|
| **性能下降** | x86 上未对齐访问有额外周期惩罚；跨缓存行的字段更慢 |
| **硬件异常** | ARM/MIPS/部分 DSP **直接不支持**未对齐访问，触发 `SIGBUS` 崩溃 |
| **原子性丢失** | 未对齐的多字节读写可能被总线拆开，多线程下出现撕裂读 |
| **取地址失效** | 对压缩后的成员做 `&member` 在某些平台无法表达 |

**什么时候该用**：① 网络协议/文件格式的字节精确解析（配合 `static_assert(sizeof(B)==13)` 自检）；② 单片机 RAM 极度紧张。**GCC/Clang 的等价写法**是 `__attribute__((packed))`（MSVC 只认 `#pragma pack`）。

**另一个免费优化：调整成员声明顺序**（实测数据）：

```cpp
struct D { char a; char b; int x; };       // ▶ 实测 sizeof = 8   （2 + 2pad + 4）
struct E { char a; char b; double x; };    // ▶ 实测 sizeof = 16  （2 + 6pad + 8）
```
若把 E 改成 `{ double x; char a; char b; }` → 8 + 2 + 6pad = 16（同样大小）。**规律：把成员按大小从大到小排列，通常能减少缝隙**——但对齐到 8 时尾部仍会补齐。这是低成本的结构体瘦身法，比 `pack(1)` 安全得多。

**union 的对齐同理**：`union U{ char c; int i; };` → sizeof = 4 而不是 1，因为 int 要求 4 字节对齐，容器必须能容纳对齐后的布局。见 §4.1④ 陷阱 4。

## 8.2 难点二：三种传参的"副本 vs 原件"到底谁在改谁

这是本章第二大难点。上一轮 §3.4 已给出对照实验，这里换**更慢的节奏 + 每步配示例 + 内存图**。

### 第 1 步：先把"名字"和"内存"这两件事分开

C++ 里一条赋值 `f(x)` 的本质是 **`形参 = 实参`**。所以问题变成：**这个 `=` 复制了什么？**

- 值传递：复制**整个对象**（48 字节 + string 深拷贝）→ 两块独立内存。
- 指针传递：复制**一个地址**（8 字节）→ 两块内存里有一块存着另一块的门牌号。
- 数组传递：**语法糖**，等同指针传递。

### 第 2 步：看图理解"谁改谁"

```
【值传递】 void byValue(student s)
  main 栈帧                        byValue 栈帧
 ┌────────────────────┐          ┌────────────────────┐
 │ a: 张三/20/90 (48B) │ ══拷贝══▶ │ s: 张三/20/90 (48B) │
 └────────────────────┘          └────────────────────┘
                                        │ s.age = 999
                                        ▼
                                 s: 张三/999/90   ← 只有这里变了
 ┌────────────────────┐          ┌────────────────────┐
 │ a: 张三/20/90 (48B) │ 不变 ✅   │ 函数返回，这块内存销毁 │
 └────────────────────┘          └────────────────────┘

【指针传递】 void byPointer(student* s)
  main 栈帧                        byPointer 栈帧
 ┌────────────────────┐          ┌───────────────────┐
 │ b: B/20/90 (48B)▲───┐  ═拷址═▶│ s: 0x61feXX (8B)──┘
 └────────┬───────────┘  │       └───────────────────┘
          │              │             │ s->age = 888
          │  ◄───────────┴─────────────┘ 顺着地址写回 b 本体！
          ▼
      b.age = 888  ← 原件真的变了 ✅
```

### 第 3 步：用实测数字锁死结论（§3.4 实验的回放）

| 观察项 | 实测值 | 说明了什么 |
|---|---|---|
| 主调方 `sizeof(student[1])` | **48** | 一只学生确实 48 字节 |
| 函数内 `sizeof(s)`（值传形参） | 48 | 是真对象 |
| 函数内 `sizeof(s)`（指针/数组形参） | **8** | 只是地址 ⇒ 退化 |
| 函数内 `sizeof(s[0])` | 48 | 解引用后才是对象 |
| 值传后 `a.age` | **仍是 20** | 副本被改，原件无恙 |
| 指针后 `b.age` | **888** | 改的就是原件 |
| 数组后 `arr[0].age` | **777** | 也是原件（因为退化成指针） |

### 第 4 步：三个连环自问，检验是否真懂

**Q：`printStudent(student s)` 里执行 `s = otherStudent;` 会影响外面的实参吗？**
A：**不会**。这只是让形参副本换了内容，实参完全不知情。（易错！很多人以为整体赋值就能穿透。）

**Q：`printStudent2(student* s)` 里执行 `s = &other;` 呢？**
A：**也不会**影响实参本身指向的对象——你改的是"形参手里那张纸条上的编号"，而主调方的变量没变。要改别人的指针变量，得用**二级指针** `student** pp`（第 14 章 P2 复习里的"二级指针·熟悉"）。

**Q：那 `printStudent3(student s[], int len)` 里 `s = s+1;` 安全吗？**
A：安全且合法——只是让形参指针后移一位，主调方的数组名不受影响。但**后续再用 s 就指向了错误位置**，属于逻辑 bug。

### 第 5 步：一句话记忆锚

> **`= 号左边是形参时，它改的是形参自己；只有穿过地址写内存，才改得到原件。**

## 陷阱 1：结构体定义漏写大括号后的分号

**症状特征**：报错信息**指向下一行甚至下一个函数**，与本行毫无关系，新手因此在正确代码里反复找 bug。

**错误写法（会出什么问题）**

```cpp
struct S{ int a; int b }        // ❌ 大括号后没有分号
int main() { S s; return 0; }
```

❗ **本机 g++ 8.1.0 完整报错原文**：
```
error: expected ';' at end of member declaration
error: expected ';' after struct definition
```

**为什么会这样**：编译器读完 `}` 后认为"类型描述完了，但这条声明语句还没结束"，于是继续吞下一行的 `int main()`，试图把它解释成"又一个成员"或"紧跟类型的变量名"。第一个 error 来自 `int b }` 内部缺分号的连带误判，第二个才是真正定位到大括号后。**根因在上一行，报错却在下一行**——这是本章最坑的一类错误。

**正确写法**

```cpp
struct S{ int a; int b; };      // ✅ 成员行尾各一个分号，大括号后再补一刀
```

**如何记住**：口诀 **「成员行尾要分号，大括号后再补一刀」**。

**同类变种（都会犯同一个错）**：

```cpp
struct student {...} s1, s2;    // 末尾仍需分号 ✅（分号同时充当变量声明结束符）
typedef struct Person P;        // typedef 版也要分号 ✅
union person {...};             // union 一样要 ✅（classcode L35 就有）
enum week {...};                // enum 一样要 ✅
int arr[3] = {1,2,3};           // 数组初始化列表同理
```

**排查动作**：看到 `expected ';'` 且指向函数/其他声明，**立刻往上翻最近的那个 `}`**。

## 陷阱 2：指针访问成员时用错 `.` 和 `->`

**症状特征**：编译器不仅报错，还会主动反问"你是不是想用 `->`？"——听到提示却不知为何，是这阶段的典型状态。

**错误写法 A：指针变量用了点**

```cpp
student* p = &s1;
p.name = "张三";        // ❌
```
❗ 实测报错：
```
error: request for member 'name' in 'p', which is of pointer type 'student*'
       (maybe you meant to use '->' ?)
```

**错误写法 B：普通变量用了箭头**

```cpp
student s1;
s1->age = 20;           // ❌
```
❗ 实测报错：
```
error: base operand of '->' has non-pointer type 'student'
```

**错误写法 C：想用 `*` 但忘了括号（优先级陷阱）**

```cpp
cout << *p.age << endl; // ❌ 被解析为 *(p.age)，而 p 是指针没有 age 成员
```
❗ 实测报错：与写法 A **同一条**（`request for member 'age' in 'p', which is of pointer type`），极具迷惑性——你以为错在星号，其实错在点号抢先结合了。

**正确写法（三种全等价，任选）**

```cpp
student s1, *p = &s1;
p->name = "张三";        // ✅ 首选：最短、最常用
(*p).age  = 20;         // ✅ 合法但必须带括号
s1.score = 99.5;        // ✅ 对象用点
```

**如何记住**：口诀 **「变量用点，指针用箭」**；补一句 **「要用星号，括号保命」**。

**判定流程（三步决策）**：

```
   我要访问成员 —— 左边那个东西是什么？
        │
        ├─ 是对象本体（struct X x; / arr[i] / *ptr 的结果）  ──▶ 用 .
        │
        ├─ 是指针（X* p; / &x 的返回值 / new 的返回值）      ──▶ 用 ->
        │
        └─ 是函数返回值？先问它返回对象还是指针
                 ├─ 返回对象  ──▶ obj().member  ❌ 注意：应写 getX().member
                 └─ 返回指针  ──▶ getX()->member ✅
```

**易混场景实测**：成员函数通过指针调用也用箭头（`classcode.cpp` L23 `ps->printInfo();` ▶ 实测正常输出），别以为"函数就该用点"。

## 陷阱 3：函数内对形参数组用 `sizeof` 求长度

**症状特征**：**不报编译错误、不崩溃**，只是循环一次都不执行（长度算成 0）或次数错误。程序"看起来跑通了但什么都没干"，是最难定位的一类 bug。

**错误写法（会出什么问题）**

```cpp
void printStudent(student s[]) {
    int len = sizeof(s) / sizeof(s[0]);     // ❌ 天真地以为能自动求长度
    for (int i = 0; i < len; i++) s[i].printInfo();
}
```

❗ **本机实测**：
```
函数内 sizeof(arr)                = 8
函数内 sizeof(arr)/sizeof(arr[0]) = 0        ← 8/48 整数除法 = 0
```
⇒ `len == 0`，循环体**一次都不执行**，函数静悄悄返回空结果。

**为什么会这样**：数组作为形参会**退化 (decay)** 成首元素指针。`s[]` 与 `s*` 在形参位置上等价（编译器视角一致），`sizeof` 看的是**声明类型**，因此只得 8。

**正确写法**

```cpp
// ① 长度作为独立参数传入（课件 P23 的做法）
void printStudent(student s[], int len) { for (int i = 0; i < len; i++) s[i].printInfo(); }

// ② 在主调方算好再传（hw_code.cpp L47 的做法）
int len = sizeof(arr) / sizeof(arr[0]);   // ✅ 此处 arr 仍是真数组 → 144/48 = 3
printStudent(arr, len);
```

❗ 注意 `sizeof(arr)/sizeof(arr[0])` **必须在 arr 还是真数组的作用域里**计算，一旦已经传给函数就失效。

**如何记住**：口诀 **「数组传地址，长度自己捎」**（提示词原句为"数组传地址，长度自己捎话"，此处为凑七字节奏略作精简，含义一致）。

**同一陷阱的三个变体（都会中招）**：

| 变体 | 代码 | 后果 |
|---|---|---|
| 结构体数组 | `void f(student s[]){ n=sizeof(s)/sizeof(s[0]); }` | n=0（8/48） |
| 基本类型数组 | `void f(int a[]){ n=sizeof(a)/sizeof(a[0]); }` | n=**2**（8/4，非 0！更阴险，会少算或多算） |
| 指针别名 | `typedef int Arr[10]; void f(Arr a){ sizeof(a); }` | 8（形参仍退化） |

第二行尤其危险：它给出一个**看似合理的非零值**（8/4==2），程序会正常运行并输出错误结果，而不是一眼可见的"什么都不打印"。

**根治方案（现代 C++，了解即可）**：

```cpp
#include <array>
void f(const std::array<student,3>& arr) { arr.size(); }   // ✅ size() 永远正确
void g(std::span<student> s) { s.size(); }                 // C++20：带长度的视图
```

# §10 新手最常问的 5 个问题（基于本章内容预判）

**Q1：结构体和类到底有什么区别？我能不能全都用 class？**

A：本章阶段，**功能上零区别**，唯一差别是默认访问权限：`struct` 默认 public，`class` 默认 private（§1.5 已实测：`class C{int a;}; c.a=5;` → `error: 'int C::a' is private within this context`，而 struct 版 0 报错）。此外默认继承方式不同（struct 是 public 继承，class 是 private 继承，第 19 章才用到）。

约定俗成：**纯数据打包用 struct（本章所有例子），需要封装不变量、有私有成员的用 class。** 技术上可以全用 class，但那会让本章每一段都得手写 `public:`，得不偿失。

**Q2：为什么我的 `int age;` 一打印就是几万、几百万这种怪数？是不是编译器坏了？**

A：不是。内置类型（int/double/char）在**局部作用域且不写初始化**时，内容是栈上残留比特，即"垃圾值"。§1.4 已实测复现：无 NSDMI 的局部数组 `arr[2].age` 打出 **8**，换个函数调用层次就变另一个数。三种解法（成本由低到高）：① 定义时加 `{}`（`student z{};` ▶ 实测归零）；② 写 NSDMI（P10 教的 `int age{20};`）；③ 用全局/static（▶ 实测 static 版 age=0）。**永远不要依赖"编译器帮忙清零"。**

**Q3：`student s1;` 前面到底要不要写 `struct`？课件 P8 写了，P21 又没写。**

A：C++ 里**可省略**，写了也合法。原因：C++ 把结构体标签放进了和普通标识符同一个名字空间，`student` 本身就是类型名；C 语言则必须 `struct student s1;`（除非用 typedef）。课件 P8 的 `struct student s1;` 是**沿用 C 风格**，P21 的 `student s1 = {...}` 是**地道 C++**。建议统一用省略版，与 `class` 的书写习惯保持一致。

**Q4：为什么课件 P49 案例里 `student s2;` 不用初始化，最后打印却是垃圾？我以为结构体会自动清零。**

A：这正是 §5.1 缺陷 B 的现场。三层原因：① `s2` 是**局部变量**且该 struct **没有 NSDMI**，所以成员是垃圾值；② 由于 `maxv=0` 的哨兵设计，当所有人 total 都是 0 时 `if` 永不成立，`s2 = s[i]` 这句从未执行；③ 两者叠加 ⇒ 直接把未初始化的栈内存打印出来（▶ 实测输出 `7678544 2.07557e-317 …`）。修复办法见 §5.1：改用**下标打擂台** `int best = 0;`。

**Q5：union 这么容易出事，为什么教材还要教？实际项目中什么时候真会用到？**

A：本章教它是为了**让你理解"内存是死的、类型是活的"**——同一串比特可以被不同类型解释。这个认知是后面位运算（第 17 章）、序列化、`std::variant` 的地基。真实用途集中在三处：① 解析二进制协议/文件格式（把一段字节当 `uint32_t` 整体读，又当位域逐位读）；② 嵌入式里省 RAM 的互斥字段；③ 实现简易 tagged union（配合一个枚举标记当前活跃成员——注意这里的 enum 与 union 正好本章都学了）。**业务代码请用 `std::variant` 代替裸 union**，它有类型检查且支持 string 这类成员。

# §12 C++11 / C++14 / C++17 标准差异速查（专项补充 1）

本章有 **3 处**代码的成败取决于编译标准，务必掌握这张表：

| 特性 | C++11 | C++14 | C++17 | 本章关联 |
|---|---|---|---|---|
| 成员默认初始化值 NSDMI | ✅ 支持 | ✅ | ✅ | P10、classcode L7–9 |
| **带 NSDMI 的结构体做大括号整体初始化** | ❌ **禁止**（非聚合类） | ✅ **恢复允许** | ✅ | ⚠️ 课件 P8/P9/P21 写法在 `-std=c++11` 下直接编译失败 |
| 结构体内定义成员函数 | ✅ | ✅ | ✅ | P11–P12 |
| `enum class` 强类型枚举 | ✅（本章不教） | ✅ | ✅ | 与经典 enum 并存 |
| **结构化绑定** `auto [a,b,c] = s1;` | ❌ | ❌（仅告警） | ✅ **可用** | 补测见下 |
| `inline` 变量、`constexpr` 增强 | — | ✅ | ✅ | 后续章节 |
| `std::variant` 取代裸 union | ❌ | ❌ | ✅ | §10 Q5 |

❗ **本机实测铁证一：C++11 vs C++14（同一份代码换标准）**

```cpp
struct student { string name="C++"; int age{20}; double score{99.5}; };
int main() { student s1 = {"王五", 21, 99}; }   // 课件 P8/P9/P21 的写法
```
```
g++ -std=c++11 → error: could not convert '{"王五", 21, 99}'
                  from '<brace-enclosed initializer list>' to 'student'
g++ -std=c++14 → 编译通过 ▶ 输出：王五 21 99
```

**根本原因**：C++11 规定"存在用户提供的非静态数据成员初始化器"的类型**不算聚合类 (aggregate)**，因而禁用聚合初始化；**C++14 撤销了这条限制**。所以课件 P10（引入默认值）与 P8/P21（大括号整体初始化）**必须搭配 `-std=c++14` 及以上才能同时成立**。这是课件没有点破、但上机一定会撞到的坑。

❗ **本机实测铁证二：结构化绑定需要 C++17**

```cpp
#include <iostream>
using namespace std;
struct student { string name; int age; double score; };
int main(){
    student s1{"张三", 20, 99.5};
    auto [name, age, score] = s1;      // C++17 结构化绑定：一次拆出三个成员
    cout << name << " " << age << " " << score << "\n";
    return 0;
}
```
```
g++ -std=c++14 → warning: structured bindings only available with -std=c++17   （且失败）
g++ -std=c++17 → ▶ 实测输出：张三 20 99.5
```

**本章建议**：**统一使用 `-std=c++14` 编译本笔记所有示例**（提示词环境要求即"C++14 及以上"）。想体验结构化绑定再切 `-std=c++17`。

# §15 两套速查表

## 15.1 精简版（一页速查 · 考前 30 秒）

| 我想做什么 | 怎么写 |
|---|---|
| 定义类型 | `struct X { int a; double b; };` ← **两个分号** |
| 定义变量 | `X x;`（C++ 可省 struct） |
| 整体初始化 | `X x = {1, 2.0};` 或 `X x{1, 2.0};` |
| 成员默认值 | `struct X { int a{0}; double b=1.0; };`（需 C++14 才能配合整体初始化） |
| 访问成员 | `x.a` |
| 定义成员函数 | `void show(){ cout << a; }` 写在 `{}` 内 |
| 定义指针 | `X* p = &x;` |
| 指针访问 | `p->a` ≡ `(*p).a`（括号不可省） |
| 定义数组 | `X arr[3];` |
| 数组初始化 | `X arr[2] = {{1,2},{3,4}};` ← 用嵌套括号 |
| 数组访问 | `arr[i].a` |
| 真数组长度 | `sizeof(arr)/sizeof(arr[0])` ← **只能在主调方** |
| 值传参 | `void f(X x)` 改不动原件 |
| 指针传参 | `void f(X* x)` 能改；调用 `f(&obj)` |
| 数组传参 | `void f(X x[], int len)` 能改；**必须带 len** |
| 定义共用体 | `union U { int a; float b; };` → `sizeof(U)==4` |
| 定义枚举 | `enum Week { Sun, Mon };` → Sun=0, Mon=1 |
| 枚举变量 | `Week w = Sun;`（不能 `w = 0;`，不能 `cin >> w`） |
| typedef 基本 | `typedef int MyInt;` |
| typedef 结构体 | `typedef struct X MyX;` |
| typedef 数组 | `typedef int Arr10[10];`（别名在中间） |
| typedef 枚举 | `typedef Week Wk;` |
| typedef 指针 | `typedef char* Str;`；要"指向常量"请 `typedef const char* CStr;` |
| 判断该用点还是箭 | 左边是对象 → `.`；左边是指针 → `->` |

## 15.2 详细版（含语法 + 示例 + 实测值）

### A. 定义与初始化

```cpp
// 完整可编译骨架
#include <iostream>
using namespace std;
struct student {                 // 定义类型（不占对象内存）
    string name = "C++";         // NSDMI 三种等价写法之一
    int age{20};
    double score{99.5};
    void printInfo() {           // 成员函数（P11-12）
        cout << name << " " << age << " " << score << endl;
    }
};                               // ← 必须有这个分号

int main() {
    student s1;                              // 默认构造 → C++ 20 99.5
    student s2 = {"王五", 21, 99};           // 聚合初始化（需 -std=c++14）
    student s3{"李四", 22};                  // 部分初始化 → score 回落默认 99.5
    student arr[2] = {{"A",1,1},{"B",2,2}};  // 数组：嵌套括号
    struct student s4;                       // C 风格也合法（可省 struct）
    s1.age = 30;                             // 逐成员改写
    (void)s4;
    s2.printInfo();                          // ▶ 王五 21 99
    return 0;
}
```

### B. 指针与 `->` / `(*p).`

```cpp

ps1->name = "诸葛亮";             // ▶ 实测写入后 s1.name == "诸葛亮"
(*ps1).age = 20;                 // 等价写法；省括号 → error: request for member ...
// *ps1.name  ❌ 永远不要这样写
cout << ps1->score << endl;      // ▶ 输出 NSDMI 默认值

```

### C. 数组与遍历

# §16 随身速记口诀（贴显示器边框）

### 口诀一：定义与符号（解决 80% 编译错误）

> **成员行尾要分号，大括号后再补一刀。**
> **变量用点，指针用箭；要用星号，括号保命。**
> **图纸不占地方，发货才算变量。**

### 口诀二：内存与尺寸（解决所有 sizeof 题）

> **结构体 ≥ 成员和，缝隙只为对齐活；**
> **共用体 = 最长者，同一段床轮流卧。**
> **地址传参八个字，对象多大都不计。**

（"八个字"= x64 下指针恒占 8 字节）

### 口诀三：函数参数与枚举（解决逻辑错误）

> **值传是复印，改不动原件；指针给门牌，一改就到底；**
> **数组传地址，长度自己捎。**
> **枚举从 0 编，指定往后加；能比能输出，禁读禁整数。**

# §24 自动保存笔记的 Python 脚本

运行以下任一版本即可在本目录看到本笔记文件（笔记本身已直接写入磁盘，此脚本用于提示词要求的"自动创建文件夹并保存"流程复现）：

```python
# -*- coding: utf-8 -*-
"""自动创建《结构体》学习笔记保存目录（路径不存在时逐级创建）。"""
import os

FOLDER = r"C:\Users\freecss\Desktop\学习1\C++\C++基础篇\15 复合数据类型 结构体"
FILENAME = "结构体学习笔记.md"          # 提示词指定文件名；若已存在则另存 _v3


def ensure_folder(path: str) -> None:
    """创建目标文件夹（含缺失的各级父目录），已存在则跳过。"""
    os.makedirs(path, exist_ok=True)     # exist_ok=True 避免重复创建报错
    print(f"[OK] 目录就绪：{path}")


def target_path(folder: str, filename: str) -> str:
    """若同名文件已存在（旧版笔记），自动追加 _v3 以免覆盖历史成果。"""
    full = os.path.join(folder, filename)
    if os.path.exists(full):
        stem, ext = os.path.splitext(filename)
        full = os.path.join(folder, f"{stem}_v3{ext}")
        print(f"[!] 已存在旧版笔记，改为写入：{os.path.basename(full)}")
    return full


if __name__ == "__main__":
    ensure_folder(FOLDER)
    path = target_path(FOLDER, FILENAME)
    print("笔记目标路径：", path)
    print("下一步：把本笔记 Markdown 全文粘贴保存至上述路径即可。")
```
