## 1. 概念：作用域与变量定义（第 4-5 页）【了解】

**① 是什么**：C++ 中的变量（或常量）在程序中都有一定的作用范围，这个范围就叫**作用域**。而**变量的定义**，本质是给一段指定的内存空间起名字，方便操作这段内存——相当于给某块内存起了个别名。

**② 为什么**：内存本身只有地址没有名字，起名后人类才能读写它；而规定"名字在哪里有效"，才能让成千上万个变量互不打架。

**③ 怎么用**：
语法：`数据类型 变量名 = 值;`

基本变量类型与字节数（教材第 5 页原表，数值为通用标准定义）：

| 变量类型 | 字节（位） | 变量类型 | 字节（位） |
|----------|-----------|----------|-----------|
| int | 4 | char / unsigned char / signed char | 1 |
| unsigned int | 4 | short int | 2 |
| signed int | 4 | long int | 8 |
| float | 4 | double | 8 |
| | | long double | 16 |

> 小注：不同编译器存在差异——在 Windows/VS（MSVC）下 `long` 是 4 字节、`long double` 是 8 字节；教材表格采用 C 标准的宽泛定义。用 `sizeof(类型)` 一测便知本机真相。

```cpp
#include <iostream>
using namespace std;
int main() {
    int a = 10;                      // 按语法起名：类型 变量名 = 值
    cout << sizeof(int) << endl;     // 顺便量一下 int 占几字节
    return 0;
}
```
输出：`4`

**④ 注意事项**：
- 变量先定义后使用，编译器从上往下扫描，没见过的名字一律报"未声明的标识符"。
- 同一作用域内不能定义同名变量（重定义错误）。
- 局部变量不初始化就使用，读到的是随机垃圾值。

> **人话总结**：定义就是给内存起名，作用域就是名字的辖区。

## 2. typedef 声明——给类型起外号（第 6-7 页）【了解】

**① 是什么**：typedef 在编程语言中用来**为复杂的声明定义一个简单的别名**。教材特别提醒：它与宏定义有些差异，而且它本身就是一种存储类关键字，**不能与 auto、extern、mutable、static、register 出现在同一个表达式中**。

**② 为什么**：类型名可能又长又复杂（数组、指针、结构体尤甚），起个短外号能显著减少重复劳动；跨平台时也只需改一处别名定义。

**③ 怎么用**：
语法：`typedef 已有类型名 新类型名;`，之后就能用新名字声明变量。

```cpp
#include <iostream>
using namespace std;
typedef int abc;          // 给 int 起外号 abc
int main() {
    abc num = 1;          // 等价于 int num = 1;（教材原例）
    cout << num << endl;
    return 0;
}
```
输出：`1`

教材的 4 条重要说明，逐条用白话拆解：

1. **typedef 可以声明各种类型名，但不能用来定义变量**——`typedef int abc;` 造出的是"类型"不是"变量"，想要数据还得再写 `abc num;`。
2. **用 typedef 只是对已经存在的类型增加一个名字，不能创造新的类型**——abc 和 int 是同一类型的两个称呼，`sizeof(abc)` 依然是 4，编译器眼里毫无区别。
3. **提高编程效率**——当不同源文件都要用同一类型（尤其数组、指针、结构体、共用体这类复杂类型）时，统一用 typedef 起的短名，写得快、错得少。
4. **有利于程序的通用与移植**——程序有时会依赖硬件特性（比如某平台 int 是 2 字节），把类型收口到 typedef 处，移植时改一行就能全项目适配。

**加分对比：typedef vs #define**——教材开篇特意点了一句"它与宏定义有些差异"，差异到底在哪？看这对经典反例：

```cpp
#define PTR int*    // 预处理期纯文本替换：PTR a, b; 展开成 int* a, b; —— b 其实是个 int！
typedef int* Ptr;    // 编译器认可的类型别名：Ptr a, b; —— a、b 都是真指针
```
`#define` 是预处理阶段的"查找替换"，压根没有类型概念，替换结果全看文本运气；`typedef` 由编译器亲自处理，造出的名字是一个完整正规的**类型**，连写多个变量、`sizeof` 运算等场景下行为都符合类型规则。这就是教材强调"有差异"的原因：**宏替换是碰巧能用，类型别名是永远可靠。**

**④ 注意事项（新手陷阱）**：
- 需要"类型别名"时用 typedef，别拿 #define 硬替——上面 PTR 的反例就是翻车现场。
- 教材示例 `typedef int abc` 末尾省略了分号，自己写时千万别漏。

> **人话总结**：typedef 就是给类型办张外号卡，本质没变。

## 3. 局部变量——花括号里的过客（第 8-9 页）【重点】

**① 是什么**：在**函数内部**声明/定义的变量叫局部变量，作用域仅限于所在区域。教材特意点全家族成员：函数的**形参**、**返回值**临时量、**if 和 for 结构内部**使用的变量，统统都是局部变量。

**② 为什么**：让每个函数/块拥有私有临时空间，互不干扰——你敢在任何函数里写 `int i` 当循环计数器，就是因为局部变量天然隔离。

**③ 怎么用**：三条教材结论先用代码落实。

结论一：**使用 {} 可以限制变量的作用域**。教材第 9 页案例：

```cpp
#include <iostream>
using namespace std;
int main()
{
    cout << "测试局部变量" << endl;
    {
        int num = 100;                    // 局部：只在这一对 {} 里出生
        cout << "num = " << num << endl;  // 输出 num = 100
    }
    //cout << "num = " << num << endl;    // 放开即报错！
    return 0;
}
```
输出：`num = 100`

为什么 {} 外面的 `cout << num` 会报错：num 随那一对花括号结束而销毁，出界之后再提这个名字，编译器只会回一句**"未声明的标识符"**——它已经不认识这个人了。

结论二：**当全局变量和局部变量同名时，在函数内，局部变量会覆盖（遮蔽）全局变量**。

```cpp
#include <iostream>
using namespace std;
int num = 200;            // 全局变量
int main() {
    int num = 888;        // 局部变量，遮住全局那位
    cout << num << endl;  // 输出 888 —— 就近原则
    return 0;
}
```
输出：`888`

**结合配套代码 `code11.1.cpp` 主函数中的被注释段落逐一考古**（它们都是做这类实验留下的现场）：

第一段——验证就近原则：
```cpp
//int num = 888;
//cout << "main num:" << num << endl;
//func();
```
意图：在 main 里定义局部 num=888 后打印。若放开运行，输出 `main num:888`——main 读到的是自己的 888，而非全局的 num=1。结尾的 `func()` 是提醒：func 内部还有一位完全独立的静态 num，谁也不影响谁。

第二段——if 块内外的两个 v2：
```cpp
//int num = 100;                 //局部变量
//int v2 = 121;
//if (1 > 0) {
//	int v2 = 10;
//	cout << "v2 if:" << v2 << endl;
//}
//cout << "v2 main:" << v2 << endl;
```
意图：演示**嵌套作用域的同名遮蔽**。放开后的输出为：
```
v2 if:10     ← if 块里的新 v2
v2 main:121  ← main 的老 v2 原封未动
```
关键认识：块内 `int v2 = 10;` 不是给外面的 v2 赋值，而是**另立门户新建了一个 v2**；出 if 门它就地解散，外面那位毫发无损。（第一行的局部 num=100 与全局 num=1 同样互不干扰——只是这里没打印它。）

第三段——附录残影：
```cpp
//int num = 2;
//func1();
//cout << "main num:" << num << endl;
```
教材另一例子的残留，出处可考：它来自**教材第 13 页静态变量案例的配套说明**——那一页讲完 func() 的静态 num 之后，配套了一个"函数去修改全局 num"的对照示例（想对比"全局 num 被函数改了，而 main 里局部的 num 独善其身"），func1 就是那个对照函数的占位名，作者整理笔记时把残段留在了这里。但工程里并没有 func1 的定义，放开只会报**链接错误（无法解析的外部符号）**。知道来历即可，不必深究。

**④ 注意事项（新手陷阱）**：
- 出了 `{}` 还想用 → 直接编译报错。
- **同名是"新建一个"而不是"改了外面的"**——很多新手以为 if 里 `int v2 = 10` 改的是外面的 v2。
- 没必要故意写嵌套同名变量，纯粹给自己挖坑。

> **人话总结**：花括号是城墙，墙外的人看不见墙里的人。

## 4. 全局变量——谁都能看的公告栏（第 10-11 页）【重点】

**① 是什么**：在**函数外部**声明/定义的变量叫全局变量，作用域**在整个文件都有效**——从定义那一行往下，任何函数都能读写。

**② 为什么**：多个函数需要共享同一份数据时，靠参数传来传去太啰嗦；放在全局，人人看到的都是同一份最新状态。

**③ 怎么用**：教材第 11 页案例：

```cpp
#include <iostream>
using namespace std;
int num = 100;                                   // 全局
void test() {
    cout << "test func print num = " << num << endl;
}
int main()
{
    cout << "测试全局变量" << endl;
    cout << "num = " << num << endl;             // 输出 num = 100
    cout << "---------------------------------------------" << endl;
    test();                                      // 输出 test func print num = 100
    return 0;
}
```
输出解析：main 与 test 各读一次 num，拿到的是**同一个 100**——两处访问的是同一块内存。这正好呼应配套 `全局和局部变量作用域及生命周期.txt` 里的结论：全局变量在所有函数体外部定义，程序所有部分（甚至其他文件配合 extern）都能使用。

**结合配套代码 `code11.1.cpp` 的 total 与 func3()**——全局变量的"记忆能力"：

```cpp
int total = 0;                        // 全局
void func3() { total++; }             // 每调用一次加 1
...
func3(); func3(); func3(); func3();   // main 里连调 4 次
cout << total << endl;
```
输出：`4`

为什么能累加：total 不属于任何函数，程序一启动它就在全局区出生，直到程序退出才销毁。4 次调用改的都是**同一块内存**，结果自然是 4。若把 total 换成函数内普通局部变量，每次进函数都被重生清零，什么都攒不起来。

再看**全局 num 与静态 num 同名**的隔离效果（下节主角提前登场）：

```cpp
int num = 1;                    // 全局 num
int func() {
    static int num = 5;         // func 自己的 num（静态）
    return num--;               // 返回当前值，然后自减
}
```
两者只是**恰好重名**的两块独立内存：func 里的代码按就近原则用静态的 5，main 里的代码用全局的 1。同名不会互相覆盖，也不会互相赋值。

**④ 注意事项（新手陷阱）**：
- 全局变量不手动初始化时**默认自动为 0**（上面 `int total = 0;` 的 `= 0` 其实可以省略）。
- 全局变量人人可改，出问题排查范围大——能用参数传递解决的，尽量别上全局。
- 在局部同名环境里想强制访问全局那份，C++ 可用作用域运算符 `::num`。

> **人话总结**：全局变量是公共黑板，谁的粉笔都能写一笔。

## 5. 静态变量——函数的私人日记（第 12-13 页）【熟悉·按重点剖析】

**① 是什么**：加 `static` 的局部变量。教材两句话说透本质：
- 静态存储区的变量在**程序刚开始时就完成初始化**，也是整个程序生命周期的**唯一一次**初始化；
- **static 变量在函数内定义时，作用域只在其函数内，但生存周期为整个源程序**——退出函数后它一直存在，只是不可以再被使用（出不了函数的门）。

**② 为什么**：它介于全局和局部之间，专治两种极端——普通局部太健忘（每次失忆），全局太开放（人人可改）。需要函数"记住历史"又不许外人插手时，static 是最佳人选。核心区别一句话：**生命周期像全局（活到最后），可见性像局部（守着自家门）**。

**③ 怎么用**：存储位置上，普通局部变量住栈区（进出函数反复擦写），静态变量与全局变量一起住**静态区**（教材明确：静态存储区一般存两种变量——static 变量和全局变量）。

教材第 13 页案例（正是 `code11.1.cpp` 中 func 的原型，幻灯片把 main 误拼成了 mian——这也是个经典手误彩蛋，写成 mian 链接器会报"找不到 main"）：

```cpp
int num = 1;                  // 全局
int func(){
    static int num = 5;       // 首次进入函数时，num 初始化（仅此一次）
    return num--;             // 后面再进入函数时，num 不会被初始化
}
int main(){
    for(; num <= 5; num++)                        // 这个 num 是全局的！
        cout << num << "---" << func() << endl;
    return 0;
}
```

**两个为什么**：
- `static int num = 5;` 为什么只初始化一次？静态变量在**程序启动阶段**就随静态区一同完成初始化，运行期再次路过这行代码时编译器直接跳过，绝不"归零重来"。
- 函数退出后 num 为什么还在？它压根没被销毁——一直躺在静态区。普通局部变量死在栈上，静态变量长生在静态区。

**逐轮模拟运行**（分清三个角色：循环条件里的 num 是**全局 num=1**；func 内静态 num 从 5 开始自管自减；`num--` 先返回旧值再减 1；两者零往来）：

| 轮次 | 全局 num（循环条件） | func() 返回 | 静态 num 调用后 | 本轮打印 |
|-----|-------------------|------------|----------------|---------|
| 第1轮 | 1 ≤ 5 成立 | 5 | 4 | `1---5` |
| 第2轮 | 2 ≤ 5 成立 | 4 | 3 | `2---4` |
| 第3轮 | 3 ≤ 5 成立 | 3 | 2 | `3---3` |
| 第4轮 | 4 ≤ 5 成立 | 2 | 1 | `4---2` |
| 第5轮 | 5 ≤ 5 成立 | 1 | 0 | `5---1` |
| 收尾 | 6 > 5 不成立，循环结束 | — | — | — |

完整输出：
```
1---5
2---4
3---3
4---2
5---1
```
迷人的细节：`return num--` 是"先还后扣"，所以第 5 轮返回 1 而不是 0；若改成 `return --num` 就是"先扣后还"，输出立刻变 43210。（`code11.1.cpp` 注释里那版用空格分隔，数字规律完全相同。）

**func2() 对照实验**——静态与普通正面 PK（`code11.1.cpp` 实码，教材第 17 页幻灯片中它叫 func，并配了一句提示"多调用几次 func 函数"）：

```cpp
void func2() {
    static int v1 = 0;   // 静态：出生一次，终生记住
    int v2 = 0;          // 普通：每次进来重新投胎
    v1++;
    v2++;
    cout << "v1=" << v1 << "  v2=" << v2 << endl;
}
// main 中连调三次：
func2(); func2(); func2();
```
输出：
```
v1=1  v2=1
v1=2  v2=1
v1=3  v2=1
```
为什么 v1 能累加而 v2 永远是 1：v1 住静态区只初始化一次，三次 ++ 分别落在 1、2、3 上；v2 每次进函数都在栈上重新诞生于 0，++ 后变 1，函数一走就被回收，下次再来还是白纸一张。

**④ 注意事项（新手陷阱）**：
- 静态变量不显式初始化时**默认为 0**。
- **活得久 ≠ 谁都能看**：别的函数照样访问不到它（`code11.1.cpp` 里被注释的 `//cout << v1 << endl;` 就是当年试图跨函数偷看而失败的证据）。
- 别把"静态"理解成"值不可变"——static 说的是"位置不动、寿命长"，值照改不误。

> **人话总结**：静态变量是函数的私人日记，合上本子也不忘事。

## 6. C++ 五种存储类——官方视角再归纳（第 14-19 页）【熟悉】

**① 是什么**：存储类用于定义 C++ 程序中**变量和函数的生命周期和可见性**。寿命指变量保持活动的时间段；可见性指可访问该变量的程序模块范围。C++ 共有五种：自动(Automatic)、寄存器(Register)、静态(Static)、外部(External)、可变(Mutable)。

**教材总览表**（第 15 页原表，逐行照录）：

| 存储类 | 关键字 | 生命周期 | 可见性 | 初始值 |
|--------|----------|--------------|--------|--------|
| 自动 | auto | 函数块 | 局部 | 垃圾 |
| 寄存器 | register | 函数块 | 局部 | 垃圾 |
| 可变 | mutable | 类 | 局部 | 垃圾 |
| 静态 | static | 整个程序 | 全局 | 零 |
| 外部 | extern | 整个程序 | 局部 | 零 |

> 表格小注（帮你把表读"活"）：
> - static 行的"全局"对应**静态全局变量文件内到处可用**的场景；而第 5 节的静态局部变量可见性仍在函数内——static 用在哪，可见性就圈在哪。
> - extern 行的"局部"指你写声明的那一处才直接可见；它的本职是**跨文件共享**（声明搭桥，链接器接通）。
> - "垃圾"= 不初始化就是随机值；"零"= 编译器自动清零。

### 6.1 auto 自动存储类（第 16 页）

**是什么/怎么用**：auto 是**所有局部变量的默认存储类**，自动应用于所有局部变量——进入作用域自动创建、离开自动消亡。

**教材片段**：
```cpp
{
    auto int v1;       // 显式写出 auto
    float v2 = 99.1;   // 没写，实际上也是 auto
}
// 上例两个变量存储类相同
```
教材红字强调：**auto 只能在函数中使用**。

**为什么不推荐显式写**：既然默认就是它，写了是废话；而且 **C++11 起 auto 已被征用作"类型自动推导"关键字**，旧式用法在新编译器里反而报错——知道这层历史即可，别真写。

### 6.2 static 静态存储类（第 17 页）· 重点复习

呼应第 5 节：静态变量**只初始化一次，直到程序结束**，保留可在多次调用间传递的值；**编译器给静态变量的默认值是 0**。教材用的正是 v1/v2 对照函数（与 `code11.1.cpp` 的 func2 一致），多调几次就看到 v1 连涨、v2 恒为 1，不再赘演。

### 6.3 register 寄存器存储类（第 18 页）

**是什么**：寄存器变量请求在 CPU **寄存器**而非 RAM 中分配存储，大小与寄存器相同，访问速度比其他变量快。教材建议仅对需要快速访问的场合使用，典型如计数器：

```cpp
register int count = 0;   // 建议：这个高频小变量放寄存器
```

**为什么不能取寄存器变量的地址**（教材红字"不能得到寄存器变量的地址"）：寄存器不属于内存体系，**根本没有内存地址**，对它做 `&count` 直接报错。附赠冷知识：这只是"建议"，编译器忙不过来时会把 register 变量当普通变量处理；现代编译器优化早已比你聪明，手写 register 多数时候是仪式感。

### 6.4 extern 外部存储类（第 19 页）【重点】

**是什么**：教材表述——extern 变量**对所有程序（文件）都可见**；**如果两个或多个文件要共享相同的变量或函数，就使用它**。本质是一句承诺："这东西的定义在别处，请链接器去别处找。"

**为什么需要它**：每个 .cpp 独立编译、互相看不见对方内部。想让 B 文件用 A 文件定义的全局变量，必须在 B 文件用 extern 打招呼。

**怎么用**（双文件示意，精简到核心）：
```cpp
// one.cpp —— 真正的定义，内存在这里分配
int g_score = 95;

// another.cpp —— 只打招呼，不分配内存
extern int g_score;              // 声明而非定义
// 此后 another.cpp 里可以正常读写 g_score
```

教材第 19 页示例 `extern int v1 = 0;` 怎么理解：extern 的同时给了初值，这种写法实际退化成一次普通**定义**（都要分配内存初始化了，extern 形同虚设）。规范写法是：**定义处不带 extern，声明处才带**。

**为什么 extern 能让多文件共享同一个变量**：因为声明并没有开辟新内存，而是指向**同一份已经存在的内存**的入口，这份牵线最终由模块二讲的"链接器"完成——学完模块二即彻底打通。

### 6.5 mutable 可变存储类（第 14 页仅点名）

一句带过：mutable 用于修饰**类的成员变量**，令其在 const 对象中也允许被修改。教材表中给了它"生命周期=类、初始值=垃圾"的位置，现阶段认识这个名字即可，面向对象章节再会。

## 模块一收尾：相似概念速对比（终极对比表见第 14 节）

| 对比项 | 局部变量 | 全局变量 | 静态局部变量 |
|--------|----------|----------|--------------|
| 住哪里 | 栈区 | 静态区（全局区） | 静态区 |
| 出生时机 | 进入所在 { } | 程序启动 | 程序启动（首次路过该行生效） |
| 死亡时机 | 离开所在 { } | 程序结束 | 程序结束 |
| 谁能用 | 所在 { } 内 | 整个文件（配 extern 跨文件） | 仅本函数 |
| 忘了初始化 | 垃圾值 | 0 | 0 |

记忆钩子：**栈上是租客（随借随还），静态区是业主（长住户口）**；局部"短命健忘"、全局"公开可改"、静态局部"长命低调"。

# 模块二：多文件编程——把一间大厂房分成车间（《11.2》第 4-19 页）

## 7. 为什么要多文件编程（第 4-5 页）【了解】

**① 是什么**：教材给出的定义——为了**方便分工或后期的维护**，把代码分散存放，并遵循一个基本原则：**实现相同功能的代码应存储在一个文件中**。这就是多文件编程。

**② 为什么**：一个几千行的 main.cpp 谁看谁晕。教材列出的动机非常现实：
- **分工**：你写学生模块、我写老师模块，各改各的文件互不踩脚；
- **维护**：功能出问题直奔对应文件，改完即走；
- **保密/版权**：教材第 5 页原话场景——"有一天你写出了很牛的功能代码，出于版权和保密考虑，发布的往往是已经编译好的二进制文件，可能仅包含 .h 文件"。别人只能看到接口声明拿来就用，看不到你的实现源码。

**③ 怎么用——先认识文件家族**（教材第 4 页表格）：

| 后缀 | 身份 | 说明 |
|------|------|------|
| .h | 头文件 | 放声明（函数长什么样） |
| .hpp | 头文件 | header plus plus 的缩写，混杂着 .h 的声明与 .cpp 的定义，OpenCV 等第三方库常用 |
| .cpp | 源文件 | 放实现（函数怎么干），Windows 生态习惯 |
| .cc | 源文件 | 同 .cpp，Unix/Linux 生态习惯 |

教材第 5 页同时给出了最经典的三件套雏形（注释里 slide 把 student.h 误写成 "sudent.h"，以真实工程为准）：

```cpp
// 1.student.h   —— 只放声明
void printInfo();

// 2.student.cpp —— 放实现
#include "student.h"
// printInfo 定义

// 3.main.cpp    —— 放调用
#include "student.h"
int main() { /* ... */ }
```

**④ 注意事项**：
- "相同功能进同一文件"是原则——别把打印和计算混进一个文件，否则多文件的意义就没了。
- .h 与 .cpp 通常**成对出现**：student.h 配 student.cpp，一声明一实现。

> **人话总结**：多文件就是按功能分车间，各车间只留一张说明书（.h）。

## 8. 多文件编程具体步骤（第 6-8 页）【重点】

**① 是什么**：在 VS 里把"声明、实现、调用"三个角色分别放进头文件、源文件、main 文件的落地操作。教材用的示例项目恰好就叫 **Test001**——与你上传的真实工程同名同结构，我们直接拿实货对号入座。

**② 为什么**：步骤标准化后，任何人打开你的工程都能按图索骥找到声明与实现，这就是"工程化"的起点。

**③ 怎么用**：

VS 操作五步曲（教材第 6-7 页截图流程，创建头文件与源文件各走一遍）：
1. 在解决方案资源管理器中找到"**头文件**"（或"源文件"）文件夹；
2. 右键 → 添加 → 新建项；

4. 点击添加；

main 侧的用法一句话（教材第 8 页）：`#include "***.h"` 即可使用其中声明的函数。

- 新建了文件却没保存/没加进项目，编译时压根不带它玩。
- 头文件里写函数**实现**（而不是声明）是埋雷行为，重复包含时会炸出重定义错误（下一节正面碰撞）。

> **人话总结**：声明上户口（.h），实现去干活（.cpp），main 拿名片打电话。

## 9. #include <> 和 #include "" 的区别（第 9 页）【熟悉】

**① 是什么**：两种写法决定预处理器**去哪里找这个头文件**：
- `#include <>`：直接去**编译器的类库路径**里找，一般用于标准头文件，如 stdio.h、string.h；
- `#include ""`：先在**当前项目所在文件夹**（项目相对路径）里找自定义头文件；**如果没找到，再去编译器自带头文件目录兜底**。

**② 为什么**：搜索顺序不同，是为了让"自家的文件"和"官方的文件"各走各的门，互不耽搁。

**③ 怎么用**：

```cpp
#include <iostream>      // 标准库 → 尖括号，直奔库路径
#include "student.h"     // 自家文件 → 双引号，先找项目目录
```
教材还举了个有趣的例子：写 `#include "stdio.h"` 也能成功——项目里没有 stdio.h，于是兜底逻辑把你送到标准库目录，照样找得到。能跑，但这属于"走错门又绕回家"，规范起见各回各家。

**④ 注意事项（新手陷阱）**：
- 自定义头文件用 `<>`：编译器只逛库目录，永远找不到你的 student.h，直接报"无法打开包括文件"。
- 标准库用 `""`：能找到但慢半拍，还容易让人误以为 stdio.h 是你写的。
- 口诀：**系统的用尖括号，自家的用双引号**。

> **人话总结**：尖括号进官方大门，双引号先敲自家房门。

## 10. 防止头文件重复包含（第 10-14 页）【重点·重中之重】

**① 是什么**：一组让同一头文件的内容**只被编译一次**的保护机制。教材给出三种方法：① 宏定义（#ifndef）；② #pragma once；③ _Pragma 操作符。

**② 为什么**：先看惨案现场。头文件里若直接放了定义，重复包含就会当场面炸：

```cpp
// hero.h
int hp = 100;          // 在头文件里定义变量（危险动作）
// main.cpp
#include "hero.h"
#include "hero.h"      // 预处理器把 hero.h 粘贴两次
```
预处理后 main.cpp 里出现两个 `int hp = 100;` → 编译报**重定义**错误。函数声明重复多几次没事（声明只是打招呼），但变量定义、函数实现这类"占内存"的实体重复必炸——这就是必须防重复包含的原因。

### 方法一：#ifndef 宏定义法（第 11 页）

**语法格式**：
```cpp
#ifndef _NAME_H
#define _NAME_H
// 头文件内容
#endif
```

**原理**（教材原逻辑）：
- 第一次 `#include` 时，`_NAME_H` 尚未定义 → 于是 `#define _NAME_H` 并执行"头文件内容"；
- 之后再次 `#include` 时，`_NAME_H` 已经存在 → `#ifndef` 判断不成立，整段内容跳到 `#endif` 为止全部跳过。

一句话：**用"宏存不存在"当通行证，第一次发证，第二次查证劝返**。

**注意**（教材红字）：设置的宏名必须**独一无二**，不能和项目中其他宏重名，否则会出现"别的宏恰好把它顶掉"或"误判已包含"的灵异事件。惯用命名是 `_文件名_H` 或 `项目_文件名_H`。

** student.h 实战考古**——你上传的 student.h 把三种方法都留下了痕迹：

```cpp
//1.
//#ifndef _STUDENT_
//#define _STUDENT_
//void printInfo();
//#endif // !_STUDENT_

//2.
//#pragma once
//void printInfo();

//3.
//_Pragma("once")
//void printInfo();

#pragma once

#ifndef _STU_
#define _STU_
void printInfo();
void printName();
int getAge();
#endif // !_STU_
```
解读：
- 开头三段被注释的代码，正是当年**依次试玩三种防重复方法**的实验记录：方法1 = 纯 #ifndef 宏定义法（宏名叫 _STUDENT_）；方法2 = 纯 #pragma once；方法3 = _Pragma 操作符。
- 最后生效的部分是教材第 14 页推荐的"双保险"写法：`#pragma once` + `#ifndef _STU_ ... #endif`（宏名换成了短小的 _STU_），声明了 printInfo、printName、getAge 三个函数。
- 为什么两种一起用？往下看方法二和综合推荐就明白了。

### 方法二：#pragma once（第 12 页）

**语法格式**：文件开头一行：
```cpp
#pragma once
// 放在文件开头位置
```

**原理**：编译器遇到它，立刻知道**当前这个物理文件只引入一次**——不玩宏，编译器自己记账。

**和 ifndef 的正面 PK**（教材原对比逻辑）：
- #ifndef 靠"每次引入都要识别宏"来防重复，所以**效率不高**；但胜在 C 和 C++ 都支持宏，**可移植性**有保障；
- #pragma once **不涉及宏定义，效率很高**；
- 但它**兼容性不是很好**：老版本编译器可能不认识（发出警告但继续编译）；
- 且它**只能作用于整个文件**，无法像 #ifndef 那样只保护文件中指定的一段代码；
- 现状：几乎所有常见编译器都已支持，**VS2017 新建头文件时甚至自动带上这一行**；官方定性是"一个非标准但逐渐被广泛支持的指令"。

你工程里的 `teacher.h` 就是方法二的纯净示范——整个文件只有一行：
```cpp
#pragma once
```

### 方法三：_Pragma 操作符（第 13 页）

**是什么**：C99 标准新增的、与 #pragma 指令类似的**操作符**，可以看作 #pragma 的**增强版**——不仅能实现 #pragma 的所有功能，更重要的是**还能和宏搭配使用**（#pragma 不是标准指令、进不了宏定义，_Pragma 可以）。

**语法**：`_Pragma("once")`，同样放在文件开头位置。

```cpp
#define HEADER_GUARD _Pragma("once")   // _Pragma 能写进宏里，#pragma 做不到
HEADER_GUARD                           // 相当于 #pragma once
```

### 综合推荐写法（第 14 页）

考虑到**编译效率和可移植性**，教材推荐把两者叠加：

```cpp
#pragma once
#ifndef _NAME_H
#define _NAME_H
// 头文件内容
#endif
```
效果（教材原结论）：
- 编译器认识 #pragma once 时 → **整个文件仅被编译一次**（快）；
- 万一编译器不认识 → 后面的 #ifndef 依然站岗（稳）。

**验证**：student.h 正是这套推荐写法的实施现场（`#pragma once` 打头 + `_STU_` 宏护体）——效率与可移植双保险，教材所学与真实工程完全对上了。

**④ 注意事项（新手陷阱）**：
- 三种方法**任选其一**即可保证正确，双保险图的是安心，别叠到三层。
- 宏名必须全项目独一无二（推荐 `_文件名_H` 大写风格），重名会让防重复保护悄悄失效。
- 保护的是"内容被重复编译"，不是"文件被重复打开"——`#include` 写多次没关系，有保护就不炸。
- 函数**声明**重复无害，函数**定义**/变量定义重复必炸——保护罩不代表可以在头文件里随便写实现。

> **人话总结**：三道防盗门任选一门，教材推荐"智能锁+机械锁"双保险。

## 11. 课堂练习（第 15-16 页）思路与实战

预期输出（与真实工程运行结果一致）：

1. **student.h**：在 `#endif` 之前加一行声明 `void printAge();`；
2. **student.cpp**：追加实现，如 `void printAge() { cout << "age=20" << endl; }`（或复用 getAge 的返回值）；
3. **Test001.cpp**：直接调用 `printAge();`——因为 main 早已包含 student.h，新声明自动可见。
teacher.h 不用动（除非你想把学生功能挪去老师模块复用）。重编后三者自动协同——这就是声明/实现分离的红利。

**重编后链接器如何把 printAge 对接上**（与第 15 节的四步流水线正面呼应）：
1. **编译期**：student.h 的新声明随 `#include` 粘贴进 Test001.cpp，编译器自此认识 printAge 这个名字；Test001.obj 里的调用点只挂一张"我需要 printAge"的**符号引用欠条**。与此同时，student.cpp 独立编译，printAge 的函数真身作为**符号定义**落进 student.obj——此阶段两个文件仍互不知道对方存在；
2. **链接期**：链接器清点所有 .obj 的"欠条"和"存货"，发现 Test001.obj 欠一个 printAge、student.obj 正好供货，于是**按名字牵线**，把真实函数地址填进调用点——新方法就此接通，全程不需要你做任何额外操作；
3. **反向验证**：假如只加了声明忘了写实现，编译期照样绿灯（一句声明足以骗过编译器），链接期欠条却无主可认，当场报 **LNK2019：无法解析的外部符号**——这正是本章速记卡第 13 条的由来。

> **人话总结**：加一个方法 = 头文件报名字、源文件给真身、main 直接喊。

## 12. 作业实战：《说一说避免重复引用的方法有哪些？》（第 18 页 + 配套 txt）

教材第 18 页作业原题：**说一说避免重复引用的方法有哪些？** 配套 txt 给出的标准答案正是三条纲：

1. **使用宏定义避免重复引入**（#ifndef / #define / #endif）——C/C++ 通吃、可移植性最好；靠每次引入时识别宏，效率略低；宏名必须独一无二。
2. **使用 #pragma once 避免重复引入**——编译器直接记账，效率高；非标准指令，老编译器兼容性欠佳，且只能保护整个文件。
3. **用 _Pragma 操作符**（`_Pragma("once")`）——C99 新增，#pragma 的增强版，功能等同还能写进宏里参与宏替换。

终极总结（一张小表背下考场）：

| 方法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| #ifndef 宏 | 宏存在则跳过内容 | 标准通用、可护局部代码段 | 每次要查宏，效率低；宏名冲突风险 |
| #pragma once | 编译器记录文件只编一次 | 一行搞定、效率高 | 非标准；只保护整个文件 |
| _Pragma("once") | #pragma 的操作符版 | 可与宏搭配使用 | 同 #pragma once 的局限 |

生产环境最优解 = 方法 1 + 方法 2 叠加（student.h 实测在用），方法 3 作为了解储备。

## 14. 全局 vs 局部 vs 静态 终极对比

| 维度 | 局部变量 | 全局变量 | 静态局部变量 |
|------|----------|----------|----------------|
| 作用域（谁能看） | 所在 { } 内 | 定义处起整个文件（extern 可跨文件） | 仅所在函数内 |
| 生命周期（活多久） | 进 {} 生、出 {} 死 | 程序启动到结束 | 程序启动到结束 |
| 存储位置 | 栈区 | 静态区（全局区） | 静态区 |
| 默认初始值 | 垃圾值（随机） | 0 | 0 |
| 能否跨文件访问 | 否 | 能（另一文件 extern 声明） | 否（连跨函数都不行） |
| 初始化次数 | 每次进 {} 都初始化 | 程序启动时一次 | 程序启动时一次 |

## 15. 多文件编程完整流程总结（以真实 Test001 工程为标本）

**项目编制名单**（Test001.vcxproj 注册信息）：
- 头文件（ClInclude）：`student.h`（三函数声明 + 双保险防重复）、`teacher.h`（仅 #pragma once 的空壳）；
- 源文件（ClCompile）：`student.cpp`（三函数实现）、`Test001.cpp`（main，包含 student.h 并调用）。

**student.h 和 student.cpp 是一对**：.h 是"名片"（对外承诺有哪些功能），.cpp 是"本人"（兑现承诺的实现）。别的文件只需拿着名片（include .h）就能打电话（调用函数），不必认识本人。

**teacher.h 扩建设计**：如果想给 teacher.h 加功能，按 student 模式照方抓药——
```cpp

#ifndef _TEACHER_
#define _TEACHER_
void printTeacher();    // 新声明
#endif
```
再新建 teacher.cpp 写实现（记得 include "teacher.h"），main 里包含头文件后调用。工程里还要把新 .cpp 确认保存并注册进项目。

**终极问题：为什么 Test001.cpp 里 `#include "student.h"` 就能使用 student.cpp 中定义的函数？**
秘密在编译的四步流水线——

```
 预处理                编译                  链接
┌─────────────┐   ┌──────────────┐   ┌──────────────────┐
│ 展开#include │   │ 每个 .cpp 独立│   │ 把各 .obj 拼装    │
│student.h内容 │ → │ 编译成 .obj； │ → │ Test001.obj 中的  │
│粘贴进当前文件│   │ 有声明即可通过│   │ 调用点 ↔ student. │
└─────────────┘   └──────────────┘   │ obj 中的函数真身   │
                                     └──────────────────┘
```

1. **预处理**：`#include "student.h"` 把头文件内容原样粘贴进 Test001.cpp，于是 main 之前就有了三个函数**声明**——编译器自此认识这三个名字；
2. **编译**：每个 .cpp 各自独立编译成 .obj。Test001.obj 里 main 的调用点只记着"我需要一个 printInfo"；student.obj 里则实实在在躺着三个函数的机器码。**此阶段两个文件互不知道对方存在，声明就是全部依据**；
3. **链接**：链接器把所有 .obj 拼装，发现 Test001.obj 欠三个函数、student.obj 正好供给三个，**按名字对接**，地址填平补齐，生成 exe；
4. 这也解释了两件旧案：模块一的 extern 之所以能跨文件共享变量，靠的就是链接器这双手；而只声明不实现（如注释里的 func1）能通过编译、却倒在链接期，报"无法解析的外部符号（LNK2019）"。

> **人话总结**：声明让编译放行，实现供货，链接器物流签收。

## 16. 两份 PDF 综合练习实战

**练习一（11.1 第 20-21 页）：利用全局变量统计函数被调用次数**

思路：普通局部变量记不住历史，必须请一位"从程序启动活到结束"的角色当计数器 → 全局变量 count，func 内 `count++`，main 里循环调用后打印。

```cpp
#include <iostream>
using namespace std;
int count = 0;                 // 全局计数器：出生即 0，全程存活
void func() {
    count++;                   // 每被调一次 +1
}
int main() {
    for (int i = 0; i < 100; i++)
        func();
    cout << "func函数被调用次数：" << count << endl;
    return 0;
}
```
输出：`func函数被调用次数：100`

小陷阱提示：std 命名空间里也有个 `std::count`（输出流对象），本例因为没包含引入它的头文件侥幸不冲突；规范做法是给全局变量换个不易撞名的名字（如 `g_count`），或习惯性避免 `using namespace std;` 与全局同名变量同场。

**练习二（11.1 第 23 页作业）：简述全局变量和局部变量的作用域及生命周期**（自己的话作答）

- **局部变量**：作用域限于定义它的函数（或花括号块）内部，出了范围名字即失效；生命周期与所在作用域共存亡——进入作用域时在栈上创建，离开即销毁，不初始化时值是随机的。
- **全局变量**：作用域从定义处起覆盖整个源文件，配合 extern 声明还能被其他文件使用；生命周期与整个程序等长——程序启动时在静态区创建并自动清零，程序结束才销毁。
- 一句话收束：**局部是栈上的临时工，全局是静态区的正式工。**

# 附：考前速记卡（最容易忘的 13 条）

1. 作用域 = 谁能看见；生命周期 = 活多久。两把尺子量所有变量。
2. `{}` 定生死：局部变量出块即死，块外访问报"未声明的标识符"。
3. 同名遮蔽是"就近新建"，不是"修改外面那位"。
4. 全局变量默认 0，静态变量默认 0，普通局部不初始化是垃圾值。
5. 静态初始化一生一次：首次生效，再进函数不再赋值。
6. `num--` 先返回后自减；`--num` 先自减后返回。func 循环输出 5 4 3 2 1 的玄机在此。
7. 静态局部：寿命全场最长，可见性最小（仅本函数）——活得久 ≠ 谁都能碰。
8. auto 是局部变量默认存储类且只能函数内用；C++11 后 auto 另有含义（类型推导），旧用法别写。
9. register 不能取地址（寄存器没有内存地址）。
10. extern 是"声明不是定义"：不分配内存，牵线靠链接器。
11. `<>` 走库路径；`""` 先项目后库目录。系统尖括号、自家双引号。
12. 防重复包含三法：#ifndef / #pragma once / _Pragma("once")；最佳实践 = 前两者叠加（student.h 实测在用）。
13. 只声明不实现：编译通过，链接报 LNK2019（无法解析的外部符号）。

> 全章一句话：**变量看"住址+寿命"，函数看"名片+真身"，编译看"声明放行、链接牵手"。**
