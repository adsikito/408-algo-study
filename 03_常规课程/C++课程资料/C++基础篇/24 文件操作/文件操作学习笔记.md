## 模块一 · 基础篇（数据流 → 文件的输入与输出）

### 1.1 数据流的概念【了解】

一句话：**数据流（data stream）就是一组有序、有起点和终点的字节数据序列**（教材p4原文）。数据像水流一样"按顺序"从一端流向另一端。

以程序为参照物分两个方向：数据从外部**流向程序**叫输入流（cin、ifstream），从程序**流向外部**叫输出流（cout、ofstream）。C++ 用"流（stream）"这种灵活且面向对象的机制统一了输入输出，按操作对象分三类：

| 流类型 | 操作对象 | 代表类/对象 |
|---|---|---|
| 控制台流 | 键盘、屏幕（系统默认设备） | cin、cout、cerr |
| 文件流 | 磁盘文件（非默认设备） | ifstream、ofstream、fstream |
| 字符串流 | 内存中的字符串 | istrstream、ostrstream、strstream |

两个常考细节（p5）：

- **继承关系**：输入输出由 istream（输入流）和 ostream（输出流）两个类提供，为了双向 I/O，由二者**多继承**派生出 iostream。所以程序里包含 `<iostream>` 就能直接用 cin/cout。
- **为什么 `cout << 3.14` 能自动识别类型？** 因为 ostream 类对每种基本数据类型都重载了友元函数版的 `<<` 操作符（istream 同理重载 `>>`）。文件流继承了这套机制，所以对文件也能 `<<`/`>>` 各种类型。

### 1.2 文件处理简介【了解】

C++ 把文件也当作对象处理：通过**文件流类**操作文件，必须包含头文件 `<fstream>`（p11）。文件分**文本文件**和**二进制文件**，核心区别是**存储形式**不同（这个区别在模块三展开）。基本流程四步（p12）：**创建流对象 → 打开文件 → 读写操作 → 关闭文件**。

三个类各管一个方向：

| 类 | 方向 | 由谁引申 | 默认打开方式 | 典型用途 |
|---|---|---|---|---|
| ofstream | 写（输出） | ostream | ios::out \| ios::trunc | 把数据保存到文件 |
| ifstream | 读（输入） | istream | ios::in | 读取文件内容 |
| fstream | 读+写 | iostream | ios::in \| ios::out | 先写后读一趟搞定 |

### 1.3 文件的输入与输出【重点】

**是什么**：`open()` 在程序里的流对象和磁盘上的文件之间建立关联；之后就能像操作屏幕/键盘一样用 `<<`、`>>` 读写文件，用完 `close()` 解除关联。

**为什么**：文件不像键盘、屏幕那样是系统默认标准设备（p7 原话），程序不知道你要操作**哪个**文件、以**什么方式**操作（读？写？追加？清空？），所以必须显式给出文件名和打开模式。

**怎么用**：

open 语法（p13-14）：`void open(const char* filename, ios::openmode mode);` —— 第一个参数是文件名（可含路径），第二个参数是打开模式。

**打开模式表**（6 种，p8/p15，必背）：

| 模式 | 含义 | 一句话记忆 |
|---|---|---|
| ios::in | 读方式打开（文件不存在则打开失败） | in=进来=读 |
| ios::out | 写方式打开（**默认清空**原内容；文件不存在则自动创建） | out=出去=写 |
| ios::app | 追加写：每次写之前自动跳到文件末尾，不清空 | app=append=接着屁股后面写 |
| ios::ate | 打开时定位到文件末尾（之后可在任意位置读写） | ate=at end=开门就在末尾 |
| ios::trunc | 文件存在则清空成 0 字节 | trunc=truncate=删光 |
| ios::binary | 二进制方式打开（不加则默认文本方式） | binary=按内存字节原样 |

两种以上模式用 `|` 组合，例如 `ios::out | ios::app`（追加写）。

教材 p15 两个组合示例（原样收录）：

```cpp
ofstream outf;
outf.open("file.txt", ios::out | ios::trunc); // 写入+截断：file.txt 原内容清空后写
fstream file;
file.open("file.txt", ios::out | ios::in);    // 读写打开：保留原内容
```

运行效果：第一条语句把 file.txt 清空成白纸再写；第二条保留原内容打开，读指针停在开头，可以"先写后读"。

**三类默认打开方式表**（p16，不写 mode 时自动生效）：

| 类 | 默认模式 | 效果 |
|---|---|---|
| ofstream | ios::out \| ios::trunc | 覆盖写（清空原内容） |
| ifstream | ios::in | 只读 |
| fstream | ios::in \| ios::out | 读写，**不清空** |

**写入与读取**（p17）：写文件用流插入运算符 `<<`，读文件用流提取运算符 `>>`——和 cout/cin 用法完全一样，唯一区别是对象换成了文件流对象：

```cpp
ofstream outf;
outf.open("file.txt", ios::out);
outf << "hello file" << endl;   // << 写入，用法同 cout
outf.close();

ifstream infile;
infile.open("file.txt", ios::in);
string s;
infile >> s;                    // >> 读取，用法同 cin
cout << s << endl;              // 输出: hello（遇空格停止，详见模块二）
infile.close();
```

**关闭文件**（p18）：`void close();` 程序终止时会自动刷新所有流并关闭文件，但**要养成手动 close 的好习惯**——不关的话文件句柄一直被占着，中途想用别的程序/别的模式操作同一个文件就会出问题。

**注意事项**：

1. **open 之后必须判断 is_open()**：文件不存在、路径写错、文件被占用时 open 会**静默失败**（不报错、不弹窗），后面的读写全部白做。这是新手第一大坑。
2. ios::out 默认清空——想保留原内容请用 ios::app。
3. 教材 p9 原话：**ios::app 追加模式下同时进行文件状态判断（is_open）是一个好习惯**。
4. 别依赖"程序结束自动关闭"，写完就 close。

💬人话总结：文件也是流——开、判、读写、关。

## 模块二 · 文本篇（写入与四种读取方式）

### 2.1 文件写入案例【熟悉】

**是什么**：用 ofstream 对象 + `<<` 把文字写进文本文件，固定五步套路。
**为什么**：程序一结束内存里的数据就没了，落盘才能保存结果（古诗、成绩单、日志都靠它）。
**怎么用**：五步流程（p21 总结）：**① 包含头文件 `<fstream>` → ② 创建流对象 → ③ 打开文件 → ④ 写入内容 → ⑤ 关闭文件**。

p19 默认打开（**覆盖写**）：

```cpp
#include <iostream>
#include <fstream>               // 1.头文件
using namespace std;
int main() {
    ofstream outf;               // 2.创建流对象
    outf.open("file.txt");       // 3.打开（不写模式 = 默认 ios::out|ios::trunc）
    outf << "     山村咏怀" << endl;   // 4.写入内容（<< 用法同 cout）
    outf << "       邵雍" << endl;
    outf << "一去二三里，烟村四五家。" << endl;
    outf << "亭台六七座，八九十枝花。" << endl;
    outf.close();                // 5.关闭文件
    return 0;
}
```

教材批注：**"每次运行都会覆盖原来的内容"** ——因为 ofstream 默认 = ios::out|ios::trunc，打开瞬间原文件被清空。运行后 file.txt 恰好 4 行古诗，控制台无输出。

p20 追加写（**ios::app**）：

```cpp
outf.open("file.txt", ios::app);   // 只改这一行：追加模式
```

教材批注：**"每次运行都不会覆盖原来的内容"**。连跑 3 次 → file.txt 变 12 行（古诗重复 3 遍）。

配套代码 test01 用的正是 ios::app：

```cpp
void test01() {
    ofstream outf;
    //outf.open("file.txt");            // 注释掉的旧实验：覆盖写
    //outf.open("file.txt", ios::out);  // 同上，两种覆盖写法对比过
    outf.open("file.txt", ios::app);    // 现用：追加写
    outf << "    山村咏怀" << endl;
    outf << "          邵雍" << endl;
    outf << "一去二三里，烟村四五家。" << endl;
    outf << "亭台六七座，八九十枝花。" << endl;
    outf.close();
}
```

放开 test01 运行一次：file.txt 末尾追加 4 行古诗，控制台无任何输出。**你电脑上 file.txt 里那些重复段落，就是这类追加实验反复运行留下的痕迹。**

**注意事项**：

- 文件**不存在**时 ios::out 会自动创建（在运行目录下）；目录不存在才会打开失败。
- app 模式下顺手 is_open() 判断（教材 p9 点名的好习惯）。
- `endl` 自带换行，写一行加一个，别让所有内容挤成一行。

💬人话总结：写文件五步走，out清空app追加。

### 2.2 文件读取案例【熟悉】——四种读取方式

先记总原则（p23 原话）：**`>>` 以空格为分隔符，遇到空格就不读了**。想读整行、读全文，要换 get() 或 getline()。下面按"从低效到高效"讲四种方式（对应教材 p22-25 的五个 test）。

**方式一：eof()+get() 逐字符（test03，教材 p23）**

```cpp
char cf;
ifstream infile;
infile.open("file.txt");        // 不写模式，默认就是 ios::in
while (!infile.eof()) {         // 没到文件末尾就继续
    infile.get(cf);             // 一次读 1 个字符
    cout << cf;
}
infile.close();
```

输出：file.txt 全文逐字符打印。⚠️ **经典陷阱**：eof 标志要"读失败之后"才置位——读完最后一个字符时循环条件仍成立，再 get() 一次失败，cf 里还是旧值，**最后一个字符会被输出两遍**。教材用它演示 get() 的用法，工程上别这么写。

**方式二：get() != EOF 逐字符（test04，教材 p24 第一种）**

```cpp
char c;
while ((c = ifs.get()) != EOF) {   // 把"读到EOF"直接写进循环条件
    cout << c;
}
```

输出：全文一遍，**没有**方式一的重复问题。缺点：一个字符一次函数调用，教材原话"效率低，不建议使用"。⚠️ 冷知识：get() 返回 int（读到末尾返回 EOF=-1），把它塞进 char 再和 EOF 比较，在 char 无符号的平台/编译器上可能永远等不到 EOF——逐字符方案慎用。

**方式三：`>>` 读取（test02 = p22 单次版；test06 = p24 第二种循环版）**

```cpp
string cf;
ifstream infile;
infile.open("file.txt");
infile >> cf;                  // 只读一个"词"
cout << cf << endl;            // 输出: 测试fstream（第一个空格前的内容）
```

教材 p22 提问：**"能读取全部内容吗？"——不能！** `>>` 遇到空格/换行就停，只拿到第一个词。循环版：

```cpp
char buf[1024] = {0};
while (infile >> buf) {        // 每次读一个词
    cout << buf << endl;
}
```

输出：全文按空格/换行拆成一段一段，一行一个"词"。适合逐词处理，读句子不行。

**方式四：getline 两种版本（test07 = p24 第三种字符数组版；test05 = p24 第四种 string 版）**

```cpp
// 字符数组版（test07）：整行读入 char 数组
char buf[1024];
while (infile.getline(buf, sizeof(buf))) {
    cout << buf << endl;
}

// string 版（test05）：整行读入 string，最推荐
string str;
while (getline(infile, str)) {
    cout << str << endl;
}
```

两个版本输出相同：**按行输出全文**。区别：数组版要预估行长（开太小截断、开太大浪费）；string 版自动扩容、写法最简洁，**首选**。

**四种读取方式对比表**（p22-25 汇总）：

| 方式 | 核心代码 | 遇空格 | 读整行 | 效率 | 推荐度 |
|---|---|---|---|---|---|
| get() 逐字符（test04） | `while((c=ifs.get())!=EOF)` | 不受影响 | ✅ | 最低 | ★ 不建议 |
| eof()+get()（test03） | `while(!ifs.eof()){ifs.get(c);}` | 不受影响 | ✅ | 低 | ★ 有末字符重复陷阱 |
| `>>` 逐词（test02/06） | `while(ifs>>buf)` | **停止/分段** | ❌ | 高 | ★★ 只适合按词读 |
| getline 字符数组（test07） | `while(ifs.getline(buf,sizeof(buf)))` | 不受影响 | ✅ | 高 | ★★★ |
| getline+string（test05） | `while(getline(ifs,str))` | 不受影响 | ✅ | 高 | ★★★★ 首选 |

（p24 每个版本开头都有 `if(!ifs.is_open()){cout<<"文件打开失败！"<<endl;return 0;}` ——读取前判断打开，已成固定动作。）

### 2.3 注意事项

- `>>` 读含空格的句子会断成几段；**读整行必用 getline**。
- getline 有两个"近亲"，别混：`ifs.getline(buf, size)` 是 istream 的**成员函数**（配 char 数组）；`getline(ifs, str)` 是 `<string>` 提供的**全局函数**（配 string）。判断口诀：**参数里是"字符数组+数字"就是成员函数版，参数里是 string 对象就是全局函数版**。两种版本都会把换行符从流中取走（不写进结果）。
- 逐字符方案留给"逐字节处理"场景（比如统计字符数），平时读文本直接上 string 版 getline。

💬人话总结：读整行用getline，string版最香。

## 模块三 · 二进制篇（write / read）

### 3.1 二进制文件写【重点】

**是什么**：`write()` 把对象在内存里的**原始字节**整块拷贝到文件——落盘的就是内存快照。函数原型：`ostream& write(const char* buffer, int len);`（p26）参数：buffer 指向内存中一段存储空间（对象地址），len 是要写的字节数。

**为什么**：文本方式写对象，只能得到 `<<` 拼出来的字符串；而一个对象（比如 Student 里有 string、int）的完整状态存在内存字节里。用二进制 write 落盘，读回来 `read` 一下就**原样复活**，不用自己设计格式、逐字段解析。文本 vs 二进制对比：

| 维度 | 文本文件 | 二进制文件 |
|---|---|---|
| 写入函数 | `<<`、put()、getline 写 | write() 整块（put()/get() 也可单字符） |
| 打开模式 | 默认（不加 binary） | 必须 `ios::binary` |
| 写对象 | 只能 `<<` 各成员拼字符串 | `(const char*)&s` 内存原样落盘 |
| 记事本打开 | 正常可读 | **乱码**（正常现象） |
| 适用场景 | 配置、日志、人要看的内容 | 图片/视频、对象存档、追求速度体积 |

**怎么用**（教材 p27 案例 + 配套 test08）：

```cpp
class Student {
public:
    Student() {}                                   // 无参构造（test09 读回来要用）
    Student(string name, int age) :name(name), age(age) {}  // 带参构造：初始化列表写法
    void printInfo() { cout << name << "  " << age << endl; }
protected:
    string name;
    int age;
};

void test08() {
    ofstream of;
    Student s1("张三", 22);                        // 教材p27示例是 age=100，配套代码用的22
    of.open("student.txt", ios::out | ios::binary); // 二进制写模式
    of.write((const char*)&s1, sizeof(Student));    // 对象地址强转 const char*，按整个对象大小写
    of.close();
}
```

运行效果：控制台**无输出**；student.txt 生成，大小 = sizeof(Student)，记事本打开是一串乱码（比如 `0?！ ...` 之类）——因为 string 成员存的是"堆地址+长度"，落盘的是地址数字不是"张三"两个字。

**注意事项**：

1. 对象地址**必须强转 `const char*`**——write 只认字符指针。
2. len 用 `sizeof(Student)` 拿整个对象大小，别手数字节数。
3. 记事本打开是乱码 ≠ 写错了，二进制本来就不给人直接看。

💬人话总结：write把对象内存原样搬进文件。

### 3.2 二进制文件读【重点】

**是什么**：`read()` 从文件整块搬 len 个字节到内存 buffer，与 write 完全互逆。原型：`istream& read(char* buffer, int len);`（p28）。

**为什么**：写出去的是内存快照，读的时候把字节原样灌回一个同类型对象的内存，对象直接复活，一行代码顶手工解析 N 行。

**怎么用**（教材 p29 案例 + 配套 test09）：

```cpp
void test09() {
    ifstream bif;
    bif.open("student.txt", ios::in | ios::binary);  // 二进制读模式
    Student s;                                       // 需要无参构造来创建空对象
    bif.read((char*)&s, sizeof(Student));            // 地址强转 char*，整块灌入
    bif.close();
    s.printInfo();                                   // 输出: 张三  22
}
```

输出：`张三  22`——test08 写进去什么，读回来就是什么。教材 p29 版本还多了 `if(!bif.is_open())` 打开失败判断，并直接 `cout << s.name << " " << s.age`（配套代码封装成 printInfo，本质一样；test09 里 `cout << s.name` 那行被注释，因为 name 是 protected，外部访问不了，这正是 printInfo 存在的意义）。

**注意事项**：

1. 地址强转方向变成 **`char*`**（读要改写内存，不能 const）。
2. **对象必须有默认（无参）构造函数**——`Student s;` 要能编译。配套代码专门写了 `Student(){}`；注释掉的那版带参构造用初始化列表 `:name(name), age(age)`，是更地道的写法，两种都要认识。
3. `read((char*)&s, sizeof(Student))` 依赖类的**内存布局**：跨编译器/跨平台/带虚函数的类慎用，布局不同读回来就是废数据。
4. 读之前照样 is_open() 判断。

💬人话总结：read把文件字节灌回对象，原样复活。

## 模块四 · 综合篇（fstream 读写一体）

### 4.1 fstream 文件操作【重点】

**是什么**：ifstream 只支持 `>>`，ofstream 只支持 `<<`，**fstream 两者都支持**（p30）——一个对象既能读又能写，还能用 read/write/get/getline 全家桶。

**为什么**："先写后读"、"读到哪改到哪"这类场景，用两个对象来回切换很啰嗦；fstream 一个对象搞定。

**怎么用**：

打开两种姿势（p31）：声明时直接打开 `fstream file(filename, ios::in | ios::out);`，或者先建对象再 `file.open(filename, mode);`。只传文件名不传模式时按默认 `ios::in|ios::out`。文件用完必须 close()。

常用模式组合表（p32-33）：

| 模式组合 | 行为 |
|---|---|
| ios::out \| ios::in | 读写，**保留原内容** |
| ios::out \| ios::in \| ios::trunc | 读写，**清空原内容** |
| ios::out \| ios::app | 追加写，不动原内容 |
| ios::in（单独） | 只读 |

⚠️ p33 原话：**ios::out 默认会清空**——`ios::out` 和 `ios::out|ios::trunc` 打开都会清文件；不想清空就加 app。fstream 提供的读写操作全家福：`<<`、`>>`、read()、write()、put()、get()、getline()（p33-34）。选型原则一句话：**文本文件用逐行读写（getline），二进制文件用整块读写（read/write）**（p34-36；put()/get() 适合二进制单字符场景）。

教材 p37 案例（原样收录，逐行讲）：

```cpp
fstream iofile;                                        // 2.创建对象
iofile.open("file.txt", ios::out|ios::in|ios::trunc); // 3.读写+清空打开
iofile << "这里是写入内容测试" << endl;                 // 4.像 ofstream 一样 << 写
iofile << "this is test" << endl;
iofile.close();                                       // 5.先关闭（换模式重开前必须关）
cout << "写入完毕" << endl;
iofile.open("file.txt", ios::out | ios::in);          // 重新打开（此时用于读）
while (getline(iofile, str)) {                        // 像 ifstream 一样 getline 读
    cout << str << endl;
}
iofile.close();
cout << "读取完毕" << endl;
```

运行输出（4 行）：

```text
写入完毕
这里是写入内容测试
this is test
读取完毕
```

配套 test10 是同款结构（写入内容换成"测试fstream"和"123123123"）：

```cpp
fstream iof;
iof.open("file.txt", ios::out | ios::in | ios::trunc); // 清空后读写打开
iof << "测试fstream " << endl;
iof << "123123123" << endl;
cout << "写入完毕" << endl;
iof.close();
iof.open("file.txt", ios::in);      // 再以只读打开
string str;
while (getline(iof, str)) cout << str << endl;
cout << "读取完毕" << endl;
iof.close();
```

运行输出：`写入完毕` / `测试fstream` / `123123123` / `读取完毕`；同时 file.txt 被**重置**成这两行——你电脑上 file.txt 开头正是这两行，就是这么来的。

**注意事项**：

- 换模式重开前**必须先 close()**（一个流对象同时只关联一种打开状态）。
- `ios::out|ios::in` 不清空，但读指针在开头、写指针在开头，直接 `<<` 是**覆盖**式写，不是插入。
- 记住 4.1 的选型口诀：文本逐行、二进制整块。

💬人话总结：fstream读写全能，换模式先关再开。

## 模块五 · 进阶篇（文件定位和大小）

### 5.1 文件定位【重点】

**是什么**：文件流内部各有一个"读指针"（get pointer）和"写指针"（put pointer），`seekg()` 设置**读**位置、`seekp()` 设置**写**位置（p38）。原型：`istream& seekg(streamoff offset, seek_dir origin);`、`ostream& seekp(streamoff offset, seek_dir origin);`——offset 是偏移量（字节），origin 是基准位置。

**为什么**：默认读写都从指针当前位置顺次往后走。想"跳过文件头 10 字节再读"、"把修改写到文件中间"、"到末尾追加"，就必须能手动搬指针。

**怎么用**：基准三值表（p38）：

| 基准 | 含义 | 记忆 |
|---|---|---|
| ios::beg | 文件开头 | begin |
| ios::cur | 当前位置 | current |
| ios::end | 文件结尾 | end |

教材 p38 两个示例（原样）：

```cpp
inFile.seekg(2, ios::beg);   // 读指针：从开头向后移 2 字节（第3个字节开始读）
outFile.seekp(2, ios::cur);  // 写指针：从当前位置向后移 2 字节
```

配套获取当前位置的一对函数：`tellg()`（读指针位置）、`tellp()`（写指针位置），返回值就是"距文件开头的字节偏移"。

**注意事项**：

- seekg 管读、seekp 管写，别用混。
- **文本模式下偏移量可能不可靠**：Windows 文本方式会把 `\n` 转成 `\r\n` 存储，字节偏移和逻辑字符对不上；要做精确定位请配 `ios::binary` 打开。
- offset 可为负（配合 ios::cur/end 往回跳）。

💬人话总结：seekg管读seekp管写，beg/cur/end三基准。

### 5.2 获取文件大小【重点】

**是什么**：用 `seekg(0, ios::end)` + `tellg()` 的组合技量出文件字节数（p38-39）。

**为什么**：流类库没有现成的 "getFileSize()"——但"指针跳到末尾时的位置偏移"恰好就等于文件大小，一行定位一行取值就量出来了。

**怎么用**（教材 p40 案例 + 配套 test11）：

```cpp
long start, end;                                  // 存指针位置
ifstream ifile;
ifile.open("file.txt", ios::in | ios::binary);    // 二进制打开（配套代码用的file.txt，教材用test.txt）
start = ifile.tellg();      // 刚打开，读指针在开头 → start = 0
ifile.seekg(0, ios::end);   // 读指针直接跳到文件末尾
end = ifile.tellg();        // 末尾位置 = 文件总字节数
ifile.close();
cout << end - start << "bytes" << endl;           // 输出形如: 714bytes
```

输出：`NNbytes`（NN 是实际字节数，随文件内容变化——你电脑上当前 file.txt 约 714 字节）。核心逻辑就是 `末尾位置 - 开头位置 = 大小`，起点其实就是 0，教材把 start 也用 tellg() 记下来，纯属把逻辑写完整。

**注意事项**：

1. **必须配 ios::binary 打开**（test11 正是这么写的）：文本模式在 Windows 会做换行转换，量出来的字节数可能不准。
2. 顺序别乱：先记 start，再 seek 到 end 取 end。
3. 求完记得把指针 seekg(0, ios::beg) 拨回开头（如果后续还要读）。

💬人话总结：跳到末尾看位置，就是文件大小。

## 模块六 · 练习与全章总结

### 6.1 课堂练习（教材 p42 作业题）

**题目**：把自己喜欢的古诗或句子，写入 file1.txt 文件里面，然后再读取出来显示到控制台。

**解题思路**：写用 ofstream（+`<<`），读用 ifstream（+string 版 getline 逐行）。三步走：① ofstream 以 ios::out 打开（不存在自动创建），逐行写入古诗，close；② ifstream 以 ios::in 打开，**先 is_open() 判断**；③ getline 循环逐行输出，close。

**参考代码**：

```cpp
#include <iostream>
#include <fstream>
#include <string>
using namespace std;

int main() {
    // 第一部分：写入
    ofstream outf;
    outf.open("file1.txt", ios::out);          // 不存在会自动创建
    if (!outf.is_open()) { cout << "打开失败" << endl; return 0; }
    outf << "静夜思" << endl;
    outf << "【唐】李白" << endl;
    outf << "床前明月光，疑是地上霜。" << endl;
    outf << "举头望明月，低头思故乡。" << endl;
    outf.close();

    // 第二部分：读取
    ifstream infile;
    infile.open("file1.txt", ios::in);
    if (!infile.is_open()) { cout << "打开失败" << endl; return 0; }
    string line;
    while (getline(infile, line)) {            // string版getline逐行读，最推荐
        cout << line << endl;
    }
    infile.close();
    return 0;
}
```

运行后控制台输出：

```text
静夜思
【唐】李白
床前明月光，疑是地上霜。
举头望明月，低头思故乡。
```

- **test02**：`infile >> cf` 只执行一次，cf 是 string。输出第一个空格前的内容"测试fstream"——验证 `>>` 遇空格停止。
- **test03**：`while(!infile.eof())` + `get(cf)`。能打全文，但末尾那个字符会**打印两遍**：最后一个字符读入后 eof 标志仍未置位，再进循环 get 失败，cf 还是旧值。注释里被划掉的 `char cf[1024]`/`string cf` 是早期想用缓冲区的痕迹。
- **test04**：`(c = infile.get()) != EOF` 把读到 EOF 作为循环条件，天然避免重复，但逐字符调函数效率低——教材原话"效率低，不建议使用"。
- **test05**：string 版 getline 循环，按行输出全文，**推荐写法**。main 里没列它，纯属遗漏/备用。
- **test06**：`while(infile >> buf)` 配 char buf[1024]={0}，全文按空格/换行分段逐行打印——`>>` 家族的标准行为。
- **test07**：`infile.getline(buf, sizeof(buf))` 循环，整行读入字符数组，按行输出全文。
- **test08**：`Student s1("张三", 22)` 以 `ios::out|ios::binary` 打开 student.txt，`write((const char*)&s1, sizeof(Student))` 内存落盘。运行后控制台安静，student.txt 变成二进制乱码。
- **test09**：以 `ios::in|ios::binary` 读回，`read((char*)&s, sizeof(Student))` 后 `s.printInfo()` 输出 `张三  22`。被注释的 `cout << s.name` 是因为 name 是 protected 成员，类外访问不了——所以类里提供 printInfo()。
- **test10**：fstream 一先一后两段：`out|in|trunc` 写两行 close，再 `in` 打开 getline 循环。输出"写入完毕/测试fstream/123123123/读取完毕"，**并把 file.txt 重置成这两行**——你文件开头那两行就是它写的。
- **test11**：`start = tellg()`（此时=0）→ `seekg(0, ios::end)` → `end = tellg()`，输出 `end-start`，即文件字节数。当前 main 只跑它，所以你每次运行都在量 file.txt 的大小。

### 7.4 三大易错陷阱（附代码演示）

**陷阱一：文件打开失败未检查**

```cpp
// ❌ 错误示范
ifstream infile;
infile.open("nofile.txt");   // 文件不存在：open 静默失败，程序不报错
string s;
infile >> s;                 // 读不到任何东西，s 是空的
cout << s << endl;           // 输出：空行 —— 你还以为文件是空的
```

运行后果：不崩溃、不报错，就是"什么都没发生"——新手最容易懵的地方。

```cpp
// ✅ 正确姿势
ifstream infile;
infile.open("nofile.txt");
if (!infile.is_open()) {              // 打开失败立刻拦住
    cout << "文件打开失败" << endl;    // 明确告诉你问题在哪
    return 0;
}
```

教训：**open 之后第一件事就是 is_open()**。

**陷阱二：读取方式选择不当**

假设 file.txt 内容是两行：`hello world, hi C++` 和 `second line`。

```cpp
// ❌ 用 >> 读整篇
string word;
while (infile >> word) {
    cout << word << endl;      // 输出被拆成: hello / world, / hi / C++ / second / line
}                              // 空格、换行全被当分隔符，句子碎一地
```

```cpp
// ✅ 读整行用 string 版 getline
string line;
while (getline(infile, line)) {
    cout << line << endl;      // 输出: hello world, hi C++ / second line —— 原样两行
}
```

教训：**`>>` 是"逐词"的，句子和段落必须用 getline**。

**陷阱三：文件路径问题**

```cpp
// ❌ 以为相对路径是相对"源码文件"
ifstream ifs;
ifs.open("file.txt", ios::in);
if (!ifs.is_open()) { cout << "打开失败" << endl; }   // 真的失败了！
```

原因：相对路径是相对**程序运行时的工作目录**，不是 .cpp 源码位置。Visual Studio 里如果在项目根目录（vcxproj 所在处）直接运行，工作目录通常就是项目根目录；但生成的 exe 放在 `x64/Debug` 这类子目录里、或从别处双击运行时，工作目录就变了——file.txt 不在那里，open 静默失败。

```cpp
// ✅ 三种正确姿势
// ① 把 file.txt 放到与运行时工作目录一致的地方（VS 默认工作目录=$(ProjectDir)，即 vcxproj 所在目录）
// ② 用绝对路径（注意转义）
ifstream ifs1;
ifs1.open("C:\\Users\\freecss\\Desktop\\file.txt", ios::in);  // 双反斜杠
// ③ 或原始字符串写法，不用双写反斜杠
ifstream ifs2;
ifs2.open(R"(C:\Users\freecss\Desktop\file.txt)", ios::in);
// 无论哪种，open 后立刻：
// if (!ifs.is_open()) { cout << "文件打开失败" << endl; return 0; }
```

教训：**路径不确定时用绝对路径（或原始字符串），并且永远 is_open() 兜底**。
