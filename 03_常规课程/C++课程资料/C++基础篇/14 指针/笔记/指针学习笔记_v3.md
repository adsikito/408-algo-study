# 模块一 指针基础入门（P4–P10）

## §1.1 指针概述【了解】（P4）

### ❶ 是什么

一句话：**指针就是内存地址的别名；指针变量是专门保存内存地址的变量**。PDF 原文补充："指针也称为定位符或指示符！"

生活化比喻：**网购收货地址**。你下单时填的不是"这个人"，而是一串门牌编号，快递据此精准送达。程序访问数据也一样——内存每个字节都编了号，程序报出编号，数据就取回来了。

背景逻辑（P4 原文链条）：
1. 计算机中所有数据都必须放在内存中；
2. 为了正确访问，必须给每个字节编号；
3. 字节的编号 = 地址（Address）= 指针（Pointer）。

### ❷ 为什么（追问三层）

- 为什么要编号？因为内存里只有 0/1 比特流，不区分"这是某个 int"，只能靠位置定位。
- 为什么按"字节"编号而不是按"变量"编号？因为字节是硬件可独立寻址的最小单位，一个 int 只是"从某地址起连续的 4 个字节"。
- 为什么 C++ 要把地址暴露给程序员？因为要支持链表、树、动态内存这类"运行时才知道大小和位置"的结构——这些在第 15 章结构体之后立刻用到。

### ❸ 怎么用

概述层面只需知道怎么"看见"一个地址：

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100;                            // 在栈上分配 4 字节，写入 100
    cout << "num 的地址 = " << &num << endl;  // & 取地址，输出一个十六进制编号
    return 0;
}
// 输出（本机 g++ 8.1.0 实测）：num 的地址 = 0x61fe3c
```

关键理解：`0x61fe3c` 不是"num 的值"，是"num 住在哪"。同一个程序每次运行的地址可能不同（ASLR），但相对关系稳定。

### ❹ 注意事项

- 新手常把"地址"和"值"混为一谈：`cout << p;` 打印的是地址，`cout << *p;` 打印的是值。
- 不要把地址当普通整数随意加减到别的对象上（§1.3 会讲合法范围）。

> 🗣 人话总结：地址即门牌号，指针变量存门牌。

## §1.2 指针定义与初始化【熟悉】（P5–P8）

### ❶ 是什么

一句话：**用 `type *varName;` 定义一个存地址的变量，用 `type *p = &var;` 让它一开始就指向某变量**。

生活化比喻：`int num` 是一栋房子；`int *p = &num;` 是一张写着这栋房子门牌号的纸条。纸条（p）本身很薄（只占指针大小），但它能让你找到整栋房子。

三个符号分工（P5、P6 原文）：

| 符号 | 名称 | 出现位置 | 作用 |
|------|------|---------|------|
| `*` （声明中） | 指针声明符 | `int *p;` | 表示 p 是"存 int 地址"的变量 |
| `&` | 取地址运算符 | `&num` | 拿到变量的地址 |
| `*` （表达式中） | 解引用 / 间接引用 | `*p` | 取出 p 所指地址处的值 |

注意：声明中的 `*` 和表达式中的 `*` 是**同一符号的两种身份**，靠上下文区分。PDF P5 明确写"在变量名和类型之间加一个 `*`"；P6 明确"`*` 获取一个指针变量所指向的地址的值，也称指针的间接引用"。

### ❷ 为什么（追问三层）

- 为什么要单独一种变量存地址？因为"位置"本身就是需要传递、保存、比较的信息。
- 为什么声明要写类型（`int*` 而不是裸 `*`）？因为编译器要靠类型知道两件事：解引用时读几个字节、指针 +1 时跳几个字节。
- 为什么"只能初始化为地址，不能直接赋值为整数"（P7 原话）？因为整数值无法保证是一个合法可访问地址，允许就等于允许随便读写任意内存。

```cpp
int *p = 100;   // ❌ 错误：把整数当地址
```
现代编译器会直接拒绝（本机 g++ 8.1.0 实测）：
```
error: invalid conversion from 'int' to 'int*' [-fpermissive]
```

### ❸ 怎么用（P8 教材案例，逐行走读）

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100;                                        // ① 栈上分配 4 字节，存 100
    int *p = &num;                                        // ② 栈上分配 8 字节，存 num 的地址
    cout << "num = " << num << " &num = " << &num << endl;// ③ 值 + 地址
    cout << "*p = " << *p << " p = " << p << endl;        // ④ 解引用 + 地址本身
    return 0;
}
// 输出：num = 100 &num = 0x61fe3c
// 输出：*p = 100 p = 0x61fe3c
```

逐行状态追踪：

| 行 | 执行动作 | 内存变化 | 之后可见事实 |
|----|---------|---------|-------------|
| ① | 定义 `int num = 100` | 栈区 `[0x61fe3c, 0x61fe40)` ← 100 | `num==100` |
| ② | 定义 `int *p = &num` | 栈区另一处 8 字节 ← `0x61fe3c` | `p==&num` |
| ③ | 打印 num / &num | 无变化 | 第一行输出 |
| ④ | 打印 *p / p | 无变化；`*p` 触发"读 0x61fe3c 起的 4 字节" | 第二行输出，数值与 ③ 一致 |

**栈区内存图（本机 64 位实测地址）**

```
        栈区（高地址 → 低地址）
 ┌──────────────────────────┬──────────────────────┐
 │ 0x61fe3c ~ 0x61fe3f      │ num : int            │  值 = 100
 ├──────────────────────────┼──────────────────────┤
 │ 0x61fe40 ~ 0x61fe43      │ （对齐空隙）          │
 ├──────────────────────────┼──────────────────────┤
 │ 0x61fe44 ~ 0x61fe4b      │ p : int*             │  值 = 0x61fe3c ──┐
 └──────────────────────────┴──────────────────────┘                  │
                                                                      │
                        p 里存的地址 ──────────────────────────────────┘
                                ↓ 解引用 *p 沿箭头走一层
                          到 0x61fe3c 读出 100
```

### ❹ 注意事项 + 错误示范

| 常见错误 | 错误代码 | 后果（本机实测/说明） |
|---------|---------|---------------------|
| 星号漏写 | `int p = &num;` | `error: invalid conversion from 'int*' to 'int'`；p 变成 int，存不下地址 |
| 用整数初始化 | `int *p = 100;` | `invalid conversion from 'int' to 'int*'` |
| 类型不匹配 | `double *pd = &num;`（num 是 int） | `error: cannot convert 'int*' to 'double*'`；即使强转也会多读 4 字节越界 |
| 未初始化就用 | `int *p; *p = 100;` | ⚠️ **危险操作**：本机实测 `Segmentation fault`，exit code 139 |
| 多个指针一行少写星号 | `int *a, b;` | b 是普通 int，不是指针（老坑，建议一行一个声明） |

> 🗣 人话总结：星号定指针，& 拿地址，* 取回值。

### 补充：指针自身的大小（课件外的必知常识）

```cpp
#include <iostream>
using namespace std;
int main() {
    int    i = 1;   int*    pi = &i;
    double d = 1.0; double* pd = &d;
    char   c = 'a'; char*   pc = &c;
    cout << sizeof(i) << " " << sizeof(pi) << endl;
    cout << sizeof(d) << " " << sizeof(pd) << endl;
    cout << sizeof(c) << " " << sizeof(pc) << endl;
    return 0;
}
// 输出：4 8
// 输出：8 8
// 输出：1 8
```

结论：**指针大小与所指类型完全无关，只与平台有关**——32 位系统一律 4 字节，64 位系统一律 8 字节（本机 64 位实测均为 8）。这印证了指针本质"就是一个整数地址"。

## §1.3 指针运算 ++ / --【熟悉】（P9–P10）

### ❶ 是什么

一句话：**对指针做加减/自增自减，就是让指针"移动"到相邻的同类数据上，也叫指针的移动**。

生活化比喻：电影院连座。一排座位号是连续的，但你从"自己的座位"挪到"下一个观众的座位"，走的步长取决于每张椅子的宽度——不会只挪 1 厘米。指针 +1 挪的是"一个元素的宽度"，不是"1 个字节"。

P9 原文要点：地址本质上也是一个整数，因此可以用运算符对指针变量进行运算；常用的是加法和减法运算符，其中自增和自减用得最多；对指针变量进行自增或自减也叫做指针变量的移动。

### ❷ 为什么（追问三层）

- 为什么不设计成"移动 1 字节"？因为那样遍历数组就得手写 `p += sizeof(int)` 的倍数，极易出错。
- 为什么步长由类型决定？因为指针携带了类型信息，编译器用它算出 `sizeof(所指类型)`。
- 为什么这带来好处？它让"同一套 `p++` 代码"能同时正确遍历 int 数组、double 数组、结构体数组——迭代器与泛型的地基就在这里。

### ❸ 怎么用（P10 教材案例 + 步长实测）

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100;
    int* p = &num;
    cout << "p:" << p << endl;   // 起始地址
    p++;                         // 向后移动一个 int 的宽度
    cout << "p:" << p << endl;
    p--;                         // 再移回来
    cout << "p:" << p << endl;
    return 0;
}
// 输出：p:0x61fe3c
// 输出：p:0x61fe40    ← 差值 = 0x61fe40 - 0x61fe3c = 4 字节（sizeof(int)）
// 输出：p:0x61fe3c
```

**步长演示（同机对比 int\* 与 double\*）**

```cpp
#include <iostream>
using namespace std;
int main() {
    int    num = 100; int*    p  = &num;
    double dx  = 1.0; double* pd = &dx;
    cout << "int*:    " << p  << " -> " << p  + 1
         << " 移动 " << (char*)(p  + 1) - (char*)p  << " 字节" << endl;
    cout << "double*: " << pd << " -> " << pd + 1
         << " 移动 " << (char*)(pd + 1) - (char*)pd << " 字节" << endl;
    return 0;
}
// 输出：int*:    0x61fe3c -> 0x61fe40 移动 4 字节
// 输出：double*: 0x61fe30 -> 0x61fe38 移动 8 字节
```

核心结论一张表：

| 指针类型 | `p++` 实际加的字节数 | 原因 |
|---------|--------------------|------|
| `char*` | 1 | sizeof(char)==1 |
| `int*` | 4 | sizeof(int)==4 |
| `double*` | 8 | sizeof(double)==8 |
| `Student*`（假设 20 字节） | 20 | sizeof(Student)==20 |

所以 **"指针 +1 ≠ 地址 +1"**，正确表述是 `地址 += sizeof(所指类型)`。

内存图（一次 `p++` 前后）：

```
   改前： p ──→ [0x61fe3c: 100]   [0x61fe40: ?]   [0x61fe44: ?]
                  ↑ p 指这里

   p++ 后：                       p ──→ [0x61fe40: ?]
                                        ↑ p 现在指这里（整整跳过 4 字节）
```

四种指针算术一览：

| 运算 | 含义 | 结果类型 |
|------|------|---------|
| `p + n` / `p - n` | 前后移动 n 个元素（地址 ± n*sizeof(T)） | 同类型指针 |
| `p++` / `++p` | 移动 1 个元素（后缀返回旧值，前缀返回新值） | 同类型指针 |
| `p - q` | 两个同数组指针之间的元素个数 | `ptrdiff_t`（整数） |
| `p[n]` | 等价 `*(p+n)` | 所指类型 |

### ❹ 注意事项 + 错误示范

| 问题 | 代码 | 后果 |
|------|------|------|
| ⚠️ **危险操作：指针越界访问** | `int arr[3]={1,2,3}; int* p=arr; for(int i=0;i<10;i++) cout<<*p++;` | 前 3 次正常，之后读到别人的栈数据；若落在未映射页则段错误 |
| 以为 +1 是 +1 字节 | 手算 `&a[1] - &a[0] == 1` | 实际差 4（int）/8（double），导致长度与拷贝计算全错 |
| 对不同数组的两个指针相减 | `int a[3], b[3]; cout << (b - a);` | 结果无意义（未定义行为），标准只保证"同一数组内指针相减"合法 |
| 移动后忘了回不去 | `*p++` 循环结束后再用 p | p 已跑到数组尾之外，需重新 `p = arr;` |

⚠️ 越界实测（本机：`int arr[3]={1,2,3}` 之后连续读 10 次）：
```
1 2 3 -1 1606412304 4199136 4199056 32767 0 0
```
—— 前三个属于数组，后面全是栈上的"邻居"，这就是典型的越界读取。

> 🗣 人话总结：指针加一，跳一个元素宽。

# 模块二 指针与数组深度绑定（P11–P17）

## §2.1 数组名可看成指针【重点】（P11–P12）

### ❶ 是什么

一句话：**数组名是指向数组第 0 个元素的"常量指针"，`arr[i]` 与 `*(arr+i)` 完全等价**。

生活化比喻：一排 5 间连号客房，前台说的"这排房的房号"就是 101（首地址）。你不能改变"这排房从 101 开始"这个事实（数组名不可赋值），但可以拿着房号 +1 走到 102（用指针变量移动）。

P11 原文三条：
1. 数组保存同一种类型的一组数据，所有元素在内存中**连续存放**，地址连续；
2. 数组名可看成一个指针，指向索引为 0 的元素，第一个元素的地址称**数组首地址**；
3. ⚠️ 特别强调"并不完全等价"——**数组名其实是常量，不可被修改；指针是可以移动的，即是变量**。

### ❷ 为什么（追问三层）

- 为什么数组名要退化为首地址？因为传数组给函数时不可能整体拷贝（成本太高），只需要"从哪里开始 + 多少个"。
- 为什么 `arr[i]` 等价于 `*(arr+i)`？因为编译器直接把 `arr[i]` 翻译成 `*(arr + i*sizeof(*arr))`，下标语法只是地址算术的糖。
- 为什么数组名不能被改？因为它压根不是一个存储单元，它是"一块连续内存的起始标记"，没有可写的地址格子。

### ❸ 怎么用（P12 教材两个等价写法）

```cpp
#include <iostream>
using namespace std;
int main() {
    int arr[3] = {1, 3, 4};
    for (int i = 0; i < 3; i++) cout << "arr[" << i << "] = " << arr[i]   << endl;
    for (int i = 0; i < 3; i++) cout << "arr[" << i << "] = " << *(arr+i) << endl;
    return 0;
}
// 输出：arr[0] = 1 / arr[1] = 3 / arr[2] = 4
// 输出：arr[0] = 1 / arr[1] = 3 / arr[2] = 4     ← 两段输出完全相同
```

`*(arr+i)` 的拆解（P12 原文）：`arr` 是数组名，指向数组第 0 个元素，表示数组首地址；`arr+i` 指向数组第 i 个元素；`*(arr+i)` 表示取第 i 个元素的数据，它等价于 `arr[i]`。

**数组内存图（本机实测地址）**

```
 表达式       地址        内存格               含义
──────────────────────────────────────────────────────────
 arr+0        0x61fe20   ┌──────────┐          首地址
 *(arr+0)=1              │ arr[0]=1 │
                         └──────────┘
 arr+1        0x61fe24   ┌──────────┐
 *(arr+1)=3              │ arr[1]=3 │  ← 与上一个相差 4 字节
                         └──────────┘
 arr+2        0x61fe28   ┌──────────┐
 *(arr+2)=4              │ arr[2]=4 │
                         └──────────┘
               0x61fe2c  （数组结束，共 3 × 4 = 12 字节）
```

实测验证（对应 code.cpp 第 63–73 行被 `/* */` 注释的第二段）：

```cpp
#include <iostream>
using namespace std;
int main() {
    int arr[5] = { 1,2,3,4,5 };
    cout << arr     << endl;   // 0x61fe20
    cout << &arr[0] << endl;   // 0x61fe20   ← 与 arr 完全相同
    cout << &arr[1] << endl;   // 0x61fe24
    cout << &arr[2] << endl;   // 0x61fe28
    cout << arr + 0 << endl;   // 0x61fe20
    cout << arr + 1 << endl;   // 0x61fe24   ← 与 &arr[1] 完全相同
    cout << arr + 2 << endl;   // 0x61fe28
    return 0;
}
// 输出：以上 7 行地址依次如上（本机 g++ 8.1.0 实测）
```

三组等式，务必背下来：
```
arr        ==  &arr[0]  ==  arr + 0
arr + i    ==  &arr[i]
*(arr + i) ==  arr[i]
```

### ❹ 注意事项 + 错误示范

⚠️ **最经典的一条：数组名不能自增**（code.cpp 第 60 行的注释代码正是故意留下的错误标本）

```cpp
int arr[5] = {1,2,3,4,5};
for (int i = 0; i < 5; i++) {
    cout << "a[" << i << "]" << *(arr++) << " ";   // ❌ 错误
}
```
编译报错（本机实测）：
```
error: lvalue required as increment operand
     cout << "a[" << i << "]" << *(arr++) << " ";
```
原因：`arr` 是常量，`++` 需要一个可修改的对象（lvalue）。正确写法是把 arr 交给一个指针变量：
```cpp
int* p = arr;
for (int i = 0; i < 5; i++) cout << "a[" << i << "]" << *p++ << " ";   // ✅
```

⚠️ **sizeof 陷阱（数组名 vs 指针的分水岭）**

```cpp
int arr[5] = {1,2,3,4,5};
int* p = arr;
cout << sizeof(arr) << endl;   // 输出：20   ← 整个数组 = 5 × 4
cout << sizeof(p)   << endl;   // 输出：8    ← 指针本身大小
```

更隐蔽的一次（数组作为函数参数会退化成指针）：
```cpp
#include <iostream>
using namespace std;
void printArr(int arr[], int len) {
    cout << "函数内 sizeof(arr) = " << sizeof(arr) << endl;   // 8，不是 20！
    for (int i = 0; i < len; i++) cout << arr[i] << " ";
}
int main() {
    int a[5] = {1,2,3,4,5};
    cout << "main内 sizeof(a) = " << sizeof(a) << endl;       // 20
    printArr(a, 5);
    return 0;
}
// 输出：main内 sizeof(a) = 20
// 输出：函数内 sizeof(arr) = 8
// 输出：1 2 3 4 5
// 编译期还会给出警告：'sizeof' on array function parameter 'arr' will return size of 'int*'
```
结论：数组一旦进函数形参就只剩首地址，长度必须另外传（`len` 参数）。

### ★ 对比表之一：数组名 vs 指针变量（提示词强制要求）

| 维度 | 数组名 `int arr[5]` | 指针变量 `int* p = arr` |
|------|--------------------|------------------------|
| 本质 | 一块连续内存的起始标记（常量） | 一个存放地址的变量（有自己的存储单元） |
| 能否 `arr++` / `p++` | ❌ 编译错误（lvalue required） | ✅ 合法，移动 sizeof(int) 字节 |
| 能否赋值 `arr = &x;` | ❌ 编译错误 | ✅ 合法 |
| `sizeof` 结果 | 整个数组字节数（20） | 指针本身字节数（8） |
| 占多少内存 | 5 个 int = 20 字节 | 8 字节（64 位） |
| 能否取自身地址 | ✅ `&arr`，类型为 `int(*)[5]`，数值与 arr 相同 | ✅ `&p`，类型为 `int**` |
| 生命周期 | 随数组作用域 | 随指针变量作用域，可自由换指向 |
| 传给函数后 | 退化为 `int*`，丢失长度信息 | 仍是 `int*` |
| 内容可否修改 | ✅ `arr[0]=9` 可以 | 指针自身值可改，所指内容视类型而定 |

## §2.2 用指针遍历数组【重点】（P13–P14）

### ❶ 是什么

一句话：**把指针指向数组名，然后靠指针移动（`*(p+i)` 或 `*p++`）逐个访问元素**。

生活化比喻：导游举旗带队逛展厅。旗子（指针）每往前挪一步，游客看到的就是下一件展品；展柜本身（数组）一动不动。

P13 语法原文：`type *指针名 = 数组名；`，示例 `int arr[3] = {1, 2, 3}; int *p = arr;`，说明"定义了一个指针，其指向了数组名，直接可以通过指针的移动来访问数组中的元素"。

### ❷ 为什么

- 为什么要绕一层指针而不直接用下标？① 函数只收到指针时必须能遍历；② 链表/树等结构根本没有下标；③ 移动指针省掉每次乘法寻址。
- 为什么 `*p++` 能一行搞定？因为后缀 `++` 优先级高于 `*` 且返回旧值——先"用当前 p 解引用取值"，再"让 p 前进一步"。

### ❸ 怎么用（P14 教材两种写法）

```cpp
#include <iostream>
using namespace std;
int main() {
    int arr[3] = {1, 2, 3};
    int *p = arr;                                        // 指针指向数组首元素
    for (int i = 0; i < 3; i++)
        cout << "p[" << i << "] = " << *(p+i) << endl;   // 写法A：基址不变 + 偏移
    p = arr;                                             // ⚠️ 复位，否则下面从尾部开始
    for (int i = 0; i < 3; i++)
        cout << "p[" << i << "] = " << *p++ << endl;     // 写法B：边用边走
    return 0;
}
// 输出：p[0] = 1 / p[1] = 2 / p[2] = 3
// 输出：p[0] = 1 / p[1] = 2 / p[2] = 3
```

**`*p++` 一行的求值顺序（必须吃透）**

```
*p++     等价于  *(p++)   分两步：
  步骤1：取出 p 当前指向的值（这才是表达式的结果）
  步骤2：p 自增，指向下一个元素

对比 (*p)++  ：p 不动，把 p 指向的那个值加 1
对比 *++p    ：p 先前进一步，再解引用（第一个元素被跳过！）
```

内存图（三次 `*p++` 的过程追踪，arr 起址设为 0x61fe20）：

```
第1轮： p ──→ [0x61fe20: 1]   [0x61fe24: 2]   [0x61fe28: 3]
             输出 *p = 1，随后 p := p + 4
第2轮：                        p ──→ [0x61fe24: 2]   [0x61fe28: 3]
             输出 *p = 2，随后 p := p + 4
第3轮：                                                 p ──→ [0x61fe28: 3]
             输出 *p = 3，随后 p := p + 4
第4轮： p 已指向 0x61fe2c —— 数组之外！再用就是越界 ⚠️
```

完整可运行版（对应 code.cpp 第 77–83 行注释代码）：

```cpp
#include <iostream>
using namespace std;
int main() {
    int arr[5] = { 1,2,3,4,5 };
    int* p = arr;                                  // 定义整型指针，指向数组 arr
    for (int i = 0; i < 5; i++) cout << *p++ << " ";
    cout << endl;
    return 0;
}
// 输出：1 2 3 4 5
```

### ❹ 注意事项

| 易错点 | 说明 |
|--------|------|
| 用完不复位 | `*p++` 循环结束后 p 已越界，再次使用必须先 `p = arr;` |
| 混淆 `*p++` 与 `(*p)++` | 前者移动指针，后者修改元素值 |
| 忘记边界 | 循环次数必须等于元素个数，越界即未定义行为 |
| 依赖 `sizeof(p)/sizeof(int)` 求长度 | 只能得到 8/4==2，永远算不出真实元素个数（见 §2.1） |

> 🗣 人话总结：指针挂头一格，++ 一路走到尾。

## §2.3 二级指针与多级指针【熟悉】（P15–P17）

### ❶ 是什么

一句话：**一级指针存普通变量的地址，二级指针存一级指针的地址，写作 `int **ppn = &pnum;`**。

生活化比喻：三段查账链。你手里有一张写着"保险柜密码盒在哪"的便签（二级指针），便签指向一个小盒子，小盒子里装着"钱在哪层金库"的钥匙卡（一级指针），钥匙卡才指向真正的钱（数据）。查两次才见到本体。

P15 原文：指针指向普通数据类型（int/double 等）就是一级指针，保存变量的地址；还可以定义一个指针指向另一个指针，这个就是指针的指针，也就是二级指针。

### ❷ 为什么（追问三层）

- 为什么指针需要地址？因为在栈/堆上创建的指针变量本身也占内存，也有编号。
- 什么时候真需要"指向指针的指针"？① 函数内要修改调用者手里的指针本身（例如让 `p` 从 nullptr 变成 new 出来的地址）；② 动态二维数组；③ 链表删除头结点。
- 为什么级数理论上无限却很少超过三级？每一级都要多一次内存跳转，可读性和缓存命中都变差；三级以上几乎一定是设计问题。

### ❸ 怎么用（P15–P16 教材语法与课堂提问）

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100;
    int *pnum  = &num;     // 一级指针：存 num 的地址
    int **ppn  = &pnum;    // 二级指针：存 pnum 的地址
    cout << *pnum << endl; // 教材问：这两个输出一样吗？
    cout << **ppn << endl;
    return 0;
}
// 输出：100
// 输出：100     ← 答案：一样。解引用两层恰好回到 num
```

**层级对应规律（星号数量 == 解引用次数）**

| 表达式 | 类型 | 含义 | 实测值 |
|--------|------|------|--------|
| `num` | `int` | 数据本体 | 100 |
| `&num` | `int*` | num 的地址 | 0x61fe4c |
| `pnum` | `int*` | 存的地址（= &num） | 0x61fe4c |
| `*pnum` | `int` | 走 1 层 → num | 100 |
| `&pnum` | `int**` | pnum 自己的地址 | 0x61fe40 |
| `ppn` | `int**` | 存的地址（= &pnum） | 0x61fe40 |
| `*ppn` | `int*` | 走 1 层 → pnum 的值 | 0x61fe4c |
| `**ppn` | `int` | 走 2 层 → num | 100 |

**二级指针内存图（本机 g++ 实测地址）**

```
   栈区
 ┌────────────────────────┬────────────────────────────────┐
 │ 0x61fe4c ~ 0x61fe4f    │ num  : int   = 100             │
 ├────────────────────────┼────────────────────────────────┤
 │ 0x61fe40 ~ 0x61fe47    │ pnum : int*  = 0x61fe4c ◄───┐  │
 ├────────────────────────┼─────────────────────────────┼──┤
 │ 0x61fe38 ~ 0x61fe3f    │ ppn  : int** = 0x61fe40 ◄┐  │  │
 └────────────────────────┴──────────────────────────┼──┼──┘
                                                     │  │
   *ppn  ─────────────────────────────────────────────┘  │
        （读 ppn 指向的格子 → 得到 0x61fe4c，即 pnum 的值）│
                                                         │
   **ppn ────────────────────────────────────────────────┘
        （再读 0x61fe4c 指向的格子 → 得到 100）

   路径可视化：  ppn ──→ pnum ──→ num
                 一级     一级     终点
```

实测验证（完整四级链路）：

```cpp
#include <iostream>
using namespace std;
int main() {
    int a = 99;
    int *pa1  = &a;      int **pa2 = &pa1;     int ***pa3 = &pa2;
    cout << "&a   = " << &a   << "  a   = " << a   << endl;

    cout << "&pa2 = " << &pa2 << "  pa2 = " << pa2 << "  *pa2 = " << *pa2
         << "  **pa2 = " << **pa2 << endl;

    **pa2 = 333;
    cout << "改后 a = " << a << endl;
    return 0;
}
// 输出：&a   = 0x61fe4c  a   = 99
// 输出：&pa1 = 0x61fe40  pa1 = 0x61fe4c  *pa1 = 99
// 输出：&pa2 = 0x61fe38  pa2 = 0x61fe40  *pa2 = 0x61fe4c  **pa2 = 99
// 输出：***pa3 = 99
// 输出：改后 a = 333      ← 通过二级指针完成了对 a 的写入
```

**多级指针（P17 教材示例，级数没有限制）**

```cpp
int a = 99;
int       *pa1 = &a;    // 一级
int      **pa2 = &pa1;  // 二级
int     ***pa3 = &pa2;  // 三级
int    ****pa4 = &pa3;  // 四级
int   *****pa5 = &pa4;  // 五级
int  ******pa6 = &pa5;  // 六级
// 每一级的初值类型必须与右侧表达式严格匹配：&pa1 的类型是 int** ，
// 所以接收变量必须声明为 int**，写成 int* pa2 = &pa1; 会编译失败
```

### ❹ 注意事项 + 错误示范

| 错误 | 代码 | 后果 |
|------|------|------|
| 级数写错 | `int* p2 = &p1;`（p1 是 `int*`） | 本机实测 `error: cannot convert 'int**' to 'int*' in initialization`。这正是 code.cpp 第 90 行被注释掉的错误标本 |
| 星号数量与解引用不匹配 | `cout << *ppn;` 想输出 100 | 实际输出的是一个地址（`0x61fe4c`），不是数值 |
| 二级指针未初始化就写 | `int** pp; **pp = 1;` | ⚠️ **危险操作**：双重野指针，直接段错误 |
| 误用 `&` 拼两级 | `int** pp = &&num;` | 语法错误，`&&` 是"取地址的标签"（GCC 扩展），不是二级取地址 |

> 🗣 人话总结：几个星星几层楼，一层一层往下走。

# 模块三 指针与函数交互（P18–P26）

> 本模块是全章最难点之一。提示词要求"用更慢的节奏重讲"，因此每个小节都配栈帧图和逐步状态表。

## §3.1 指针作为函数参数【重点】（P18–P20）

### ❶ 是什么

一句话：**把外部变量的地址当参数传进函数，函数内部就能直接操作函数外部的数据，而且这些数据不会随函数结束而销毁**。

生活化比喻：值传递是"给人家一份文件复印件"，人家涂改，你的原件不受影响；指针传递是"给人家你家保险柜的钥匙"，他改动的是你的原件。

P18 原文关键点：函数参数不仅可以是基本数据类型，还可以是指针类型；用指针变量作函数参数可以将函数外部的地址传递到函数内部，使得在函数内部可以操作函数外部的数据，并且这些数据不会随着函数的结束而被销毁；如果需要在函数内部修改传入的基本类型的参数的值，那么只能通过指针的方式来传递参数，"有点像引用一样"。

### ❷ 为什么（追问三层，直击本质）

- 为什么值传递改不了原值？因为 C++ 函数调用采用"复制实参初始化形参"，形参是栈帧里另一块内存。
- 为什么复制之后就改不到？因为函数结束时该栈帧整体弹出，副本随之消失，原件从未被触碰。
- 为什么传地址就能改？因为地址是全局唯一编号，函数拿着编号可以绕过"副本层"直接定位到调用者的那块内存。

**三种传参方式栈帧对比图（对应 code.cpp 的 func1 / func2 / func3）**

```
【值传递 func1(int v1)】
 main 栈帧                func1 栈帧
 num @0x61fe2c=100 ─复制─> v1 @0x61fed4=100
                           v1++ → v1=101   （只改了副本）
                      ✂ 函数返回，func1 栈帧销毁，v1 消失
 main 再看 num → 仍然是 100

【指针传递 func2(int* v1)】
 main 栈帧                func2 栈帧
 num @0x61fe2c=100 <────── v1 @0x61fed8=0x61fe2c （存的是地址）
                           (*v1)++ → 顺着地址把 0x61fe2c 处改成 101
                      ✂ 函数返回，v1 这个"地址副本"消失，但 num 已被真改
 main 再看 num → 101 ✅

【引用传递 func3(int& v1)】
 main 栈帧                func3 栈帧
 num @0x61fe2c=100 <────── v1 是 num 的别名（无独立可写实体）
                           v1++ → 直接作用于 num
 main 再看 num → 102 ✅（外观像值传递，效果像指针传递）
```

### ❸ 怎么用（P19 语法 + P20 教材左右对照案例）

语法（P19 原文）：
```cpp
returnType funcName(paramType1 *param1) {
    return val;
}
```

P20 的两段对照（左：值传递；右：指针传递）：

```cpp
#include <iostream>
using namespace std;
void func1(int v1)  { v1++; }     // 值传递版
void func2(int* v1) { (*v1)++; }  // 指针传递版
int main() {
    int num = 100;
    cout << num << endl;          // 100
    func1(num);                   // 传的是 num 的值
    cout << num << endl;          // 仍然 100 —— 白改
    func2(&num);                  // 传的是 num 的地址
    cout << num << endl;          // 101 —— 真的改了
    return 0;
}
// 输出：100
// 输出：100     ← 值传递，原值不动
// 输出：101     ← 指针传递，原值被修改
```

加上引用版的完整对照（对应 code.cpp 第 116–127 行注释段 + func3）：

```cpp
#include <iostream>
using namespace std;
void func1(int v1)  { v1++; }
void func2(int* v1) { (*v1)++; }
void func3(int& v1) { v1++; }
int main() {
    int num = 100;
    cout << "调用前 num = " << num << endl;
    func1(num);  cout << "值传递后   num = " << num << endl;
    func2(&num); cout << "指针传递后 num = " << num << endl;
    func3(num);  cout << "引用传递后 num = " << num << endl;
    return 0;
}
// 输出：调用前 num = 100
// 输出：值传递后   num = 100
// 输出：指针传递后 num = 101
// 输出：引用传递后 num = 102
```

调用侧的关键差异（code.cpp 第 122 行中文注释原话）：**"指针作为函数参数的时候，实参的时候不能直接写变量，要通过取地址符取地址"** —— 即写 `func2(&num);` 而非 `func2(num);`。

### ❹ 注意事项 + 错误示范

| 错误 | 代码 | 后果 |
|------|------|------|
| 形参是 `int*`，实参却传变量 | `func2(num);` | `error: cannot convert 'int' to 'int*' in argument passing` |
| 形参是 `int`，却指望改原值 | `void f(int x){x=5;} f(num);` | 编译通过、静默失效，没有任何报错——最坑的一种 |
| ⚠️ 传入野指针 | `int* p; func2(p);` | 函数内 `(*v1)++` 对随机地址读写 → 段错误 |
| 想让形参改"指针本身"却只给一级 | `void f(int* p){ p = &other; }` | 只改副本，外部指针不变；要改指针本身必须用 `int**` 或 `int*&` |
| 括号漏写 | `void f(int* v){ *v++; }` | 语义变成 `*(v++)`：读了值却把指针挪走，原值没变（详见 §7.1） |

> 🗣 人话总结：想改原件，就把地址递进去。

## §3.2 案例：用指针交换两个变量【重点】（P21–P22）

### ❶ 是什么

一句话：**`void swap(int *num1, int *num2)`，用一个临时变量配合两次解引用完成互换**。

生活化比喻：两杯水要互换，必须准备第三个空杯。指针版只是多了句咒语——"往哪个杯子里倒，由地址说了算"。

P21 是题目页（原文："利用指针作为参数交换两个变量的值。"），P22 是实现页。

### ❷ 为什么

- 为什么交换一定要能"写回"？因为交换本质是对两个位置的写入操作，任何"只读"通道（值传递）都做不到。
- 为什么必须有 temp？因为 `*num1 = *num2;` 会先把 num1 的原值冲掉，不用中间变量保存就永久丢失。
- 为什么不用异或技巧 `*a^=*b; *b^=*a; *a^=*b;`？因为当 `a` 与 `b` 是同一地址时会把自己清零，属于隐藏地雷；temp 版本安全且可读。

### ❸ 怎么用（P22 教材代码，完整可运行 + 逐步走读）

```cpp
#include <iostream>
using namespace std;
void swap(int *num1, int *num2) {
    int temp;
    temp  = *num1;     // ① 备份 num1 指向的值
    *num1 = *num2;     // ② 把 num2 的值写入 num1 的地盘
    *num2 = temp;      // ③ 把备份写入 num2 的地盘
}
int main() {
    int a = 100, b = 200;
    cout << "交换前: a=" << a << " b=" << b << endl;
    swap(&a, &b);
    cout << "交换后: a=" << a << " b=" << b << endl;
    return 0;
}
// 输出：交换前: a=100 b=200
// 输出：交换后: a=200 b=100
```

**逐步状态追踪（设 a@0x1000、b@0x2000）**

| 步骤 | 语句 | a(0x1000) | b(0x2000) | temp | num1 | num2 |
|------|------|-----------|-----------|------|------|------|
| 进入 | `swap(&a,&b)` | 100 | 200 | 未定义 | 0x1000 | 0x2000 |
| ① | `temp = *num1;` | 100 | 200 | **100** | 0x1000 | 0x2000 |
| ② | `*num1 = *num2;` | **200** | 200 | 100 | 0x1000 | 0x2000 |
| ③ | `*num2 = temp;` | 200 | **100** | 100 | 0x1000 | 0x2000 |
| 返回 | 栈帧销毁 | 200 | 100 | （消失） | （消失） | （消失） |

```
交换前                        交换后
 num1 ──→ [a: 100]            num1 ──→ [a: 200]
 num2 ──→ [b: 200]            num2 ──→ [b: 100]
          （地址一根没动，动的只是格子里的值）
```

教材同名实现（code.cpp 第 17–21 行，函数名叫 `change`）实测：

```cpp
int num1 = 100, num2 = 200;
cout << "num1 = " << num1 << "    num2 = " << num2 << endl;
change(&num1, &num2);
cout << "num1 = " << num1 << "    num2 = " << num2 << endl;
// 输出：num1 = 100    num2 = 200
// 输出：num1 = 200    num2 = 100
```

### ❹ 注意事项

| 陷阱 | 说明 |
|------|------|
| 忘传 `&` | `swap(a, b)` → 编译错误 `cannot convert 'int' to 'int*'` |
| 形参写成 `int` | `void swap(int a,int b){int t=a;a=b;b=t;}` 编译通过但完全无效（值传递） |
| 自作聪明 `temp = *num1 = *num2;` | 语义变成"两边都等于 num2"，num1 原值永久丢失 |
| 传同一地址 `swap(&a,&a)` | temp 版结果 a 保持原值（安全）；异或版会得到 0 |

> 🗣 人话总结：三步倒水，地址是管道。

## §3.3 指针作为函数返回值【重点】（P23–P26）

### ❶ 是什么

一句话：**函数可以返回一个地址（`type * funcName()`），但绝对禁止返回局部变量的地址**。

生活化比喻：函数退房。房间（局部变量）在函数返回那一刻就被酒店回收（栈帧弹出），你把房号抄给别人（返回局部变量地址），别人凭号去开门——房间要么拆了，要么住了新客人。

P23 原文：函数的返回值定义为指针类型，用来返回一个变量的地址，但不可以返回局部变量的地址；函数运行结束后会销毁在它内部定义的所有局部数据，包括局部变量、局部数组和形式参数，函数返回的指针不要指向这些数据。

### ❷ 为什么（追问三层）

- 为什么函数结束要销毁局部数据？因为栈是 LIFO，栈指针弹回去后那块区域随时会被下一次调用覆写。
- 为什么返回地址反而有用？① 返回"传进来的那个地址"可实现链式调用；② 返回全局/静态/堆上的地址可实现"函数造东西给外面用"。
- 为什么有时编译器只是警告？因为返回悬空地址在语法上合法（类型没错），只有开了 `-Wall` 的部分场景能被抓到——典型"能过编译不等于能跑"。

### ❸ 怎么用（P24 语法 + P25 正例）

语法（P24 原文）：
```cpp
type * funcName() {
    return val;
}
```

P25 教材正例：

```cpp
#include <iostream>
using namespace std;
int * func1(int *num) {   // 返回类型是 int*
    *num += 100;          // 修改外部变量
    return num;           // 把收到的地址原样送回
}
int main() {
    int v1 = 1;
    cout << v1 << endl;         // 1
    int *p = func1(&v1);        // 传入地址，接住返回的地址
    cout << v1 << endl;         // 101
    cout << *p << endl;         // 101
    return 0;
}
// 输出：1
// 输出：101
// 输出：101
```

安全的三种返回来源（对应 code.cpp test1 + 全局变量，实测）：

```cpp
#include <iostream>
using namespace std;
int globalNum = 7;                       // 全局区
int* test1(int* p) { return p; }         // ✅ 返回传入的地址
int* safeGlobal()  { return &globalNum; } // ✅ 返回全局变量地址
int main() {
    int num = 100;
    int* p1 = test1(&num);
    cout << &num << endl;                // 0x61fe2c
    cout << p1   << endl;                // 0x61fe2c  ← 两者相等，地址原样传回
    cout << *safeGlobal() << endl;       // 7
    return 0;
}
// 输出：0x61fe2c / 0x61fe2c / 7
```

**允许 vs 禁止一览**

| 返回内容 | 数据存在哪 | 函数返回后是否有效 | 结论 |
|---------|-----------|------------------|------|
| 传入的参数地址 | 调用者的栈/全局/堆 | 有效 | ✅ 安全 |
| 全局变量地址 | 全局/静态区 | 有效 | ✅ 安全 |
| `static` 局部变量地址 | 静态区 | 有效 | ✅ 安全 |
| `new` 出来的堆地址 | 堆区 | 有效（但要记得 delete） | ⚠️ 安全但有释放责任 |
| 普通局部变量/局部数组/形参地址 | 本函数栈帧 | **失效** | ❌ 绝对禁止 |

### ❹ ⚠️ 危险操作（红牌）：返回局部变量的地址（P26 教材反例，页面特意打了个 `?`）

```cpp
#include <iostream>
using namespace std;
int * func2() {
    int num = 100;      // 局部变量，住在 func2 的栈帧里
    return &num;        // ⚠️ 把马上要销毁的地址交出去
}
int main() {
    int * p = func2();  // p 成了悬空指针（dangling pointer）
    cout << *p << endl; // 未定义行为
    return 0;
}
```

本机 g++ 8.1.0 实测全过程：

```
编译告警：warning: address of local variable 'v1' returned [-Wreturn-local-addr]
运行输出：&v1(函数内) = 0x61fdec
          p2(悬空)    = 0x61fdec
运行结果：Segmentation fault        ← exit code 139，程序当场崩死
```

内存图解释为什么会崩：

```
func2 执行中：                     func2 返回后：
 sp ─┐ 高地址                      sp ─┐ 高地址
     │ [num = 100] @0x61fdec           │ （这块空间已归还，标记为可复用）
     │ [返回地址]                      │ main 里的 cout 又压栈进来，直接覆写
 sp ─┘ 低地址                    sp ─┘ → sp 上移，那块内存不再属于 func2

 p 仍死死记着 0x61fdec ──→ 里面是垃圾 or 已被别人写过 ──→ 读它 = 赌博
```

正确改法（三选一，均实测通过）：

```cpp
// 方案1：由调用者提供存储，函数只负责填值（本章风格，推荐）
void fillValue(int* out) { *out = 100; }
int main(){ int x; fillValue(&x); cout << x << endl; }        // 输出：100

// 方案2：改用 static，让它住进静态区
int* func2_fixed() { static int num = 100; return &num; }
int main(){ cout << *func2_fixed() << endl; }                 // 输出：100

// 方案3：干脆返回值而不是地址
int func2_by_value() { int num = 100; return num; }
int main(){ cout << func2_by_value() << endl; }               // 输出：100
```

如何记住：**函数栈帧退出即销毁，永远不要返回栈上的地址。**

> 🗣 人话总结：返回地址可以，返回自家临建房不行。

# 模块四 指针与字符串及特殊指针（P27–P35）

## §4.1 指针与字符串【重点】（P27–P28）

### ❶ 是什么

一句话：**字符指针可以直接指向字符串常量，写作 `char *varName = "str";`，也可分两步 `char *varName; varName = "str";`**。

生活化比喻：字符串常量像贴在图书馆墙上的一幅画——指针只是"指着它的手指"，手指能换指向别的画，但不能在画上乱涂。字符数组则是"你自己复印回家的一张纸"，随便改。

P27 原文：字符串可以通过字符数组来实现，因此数组指针的相关操作其实同样适用于字符串；同时还可以直接通过指针的方式来定义一个字符串。给出语法 1（`char *varName = "str";`）和语法 2（先 `char *varName;` 后 `varName = "str";`）。

### ❷ 为什么

- 为什么字符串能用指针表示？因为 C++ 字符串本质是"以 `\0` 结尾的 char 序列"，只要拿到首地址 + 遍历到 `\0` 就够了。
- 为什么允许 `char* p = "hello"` 这种写法？因为 `"hello"` 这个字面量本身就代表一段连续内存的首地址。
- 为什么把它放只读区？因为多个指针可能共享同一份字面量，一处改写会影响全体，所以操作系统直接把该段设为只读。

### ❸ 怎么用（P28 教材案例）

```cpp
#include <iostream>
using namespace std;
int main() {
    char* pc1 = (char*)"hello world";   // 语法1：定义即初始化
    const char* pc2;                    // 语法2：先定义后赋值（现代规范用 const char*）
    pc2 = "this is C++";
    cout << pc1 << endl;                // 打印整串
    cout << *pc2 << endl;               // 打印首字符
    cout << *(pc1 + 6) << endl;         // 打印第 7 个字符
    return 0;
}
// 输出：hello world
// 输出：t
// 输出：w
```

要点：`cout << pc1;` 打印整个字符串（因为 ostream 对 `char*` 有特殊重载，会一直打到 `\0`）；`cout << *pc2;` 只打一个字符。

**字符串指针内存分区图（必读）**

```
 高地址 ┌────────────────────────────────────────────────┐
        │  栈区 (stack)                                   │
        │   pc1 : char*   = 0x41e004 ─────┐               │
        │   str[]: {'h','e','l','l','o','\0'} ← 栈上副本  │ ← 可写 ✅
        ├─────────────────────────────────┼───────────────┤
        │  堆区 (heap)                    │               │
        ├─────────────────────────────────┼───────────────┤
 低地址 │  只读常量区 (.rodata) ◄─────────┘               │
        │   'h''e''l''l''o'' ''w''o''r''l''d''\0'         │ ← 只读！写 = 段错误 ⚠️
        │   "this is C++" 也住在这里                      │
        └─────────────────────────────────────────────────┘
  图例：◄── 箭头表示指针保存的地址指向该区；只读区内容一律视为封条锁死
```

`char*` 与 `char[]` 的核心差别（实测）：

```cpp
#include <iostream>
using namespace std;
int main() {
    char arr[] = "hello";          // 内容复制到栈上
    char*  p   = (char*)"hello";   // 只读区，p 只存首地址
    cout << "sizeof(arr)=" << sizeof(arr) << " sizeof(p)=" << sizeof(p) << endl;
    arr[0] = 'H';                  // ✅ 合法
    cout << "arr可改: " << arr << endl;
    return 0;
}
// 输出：sizeof(arr)=6 sizeof(p)=8    ← 6 = "hello" 的 5 个字符 + '\0'
// 输出：arr可改: Hello
```

### ❹ ⚠️ 危险操作：修改字符串常量

```cpp
char* p = (char*)"hello";
*p = 'H';            // ⚠️ 写入只读常量区
cout << p << endl;
```
本机实测：编译无错（强制转换骗过了类型检查），运行时 `Segmentation fault`，exit code 139。

正确姿势：

```cpp
char  arr[] = "hello";  arr[0] = 'H';   // ✅ 改栈上副本 → "Hello"
const char* p = "hello";                // ✅ 用 const char* 明确"我只读"
                                        //    此时写 *p 会在编译期就被拒绝
```

另两条注意：
- `char str[] = "hello";` 与 `char str[100] = "hello";` 都可以改内容；但 `char str[100]; str = "hi";` 非法（数组名不能被赋值）。
- 现代 C++ 应写 `const char* p = "abc";`（code.cpp 第 148 行正是这样写的），因为字符串常量类型为 `const char[N]`，隐式转 `const char*` 合法，转 `char*` 在 C++11 后属于被弃用的写法。

> 🗣 人话总结：指针指常量墙，能看不敢摸。

## §4.2 指针与字符数组：遍历字符串【重点】（P29）

### ❶ 是什么

一句话：**用 `*(str+i)` 或 `*pstr++` 逐字符输出字符串，两种方式与遍历 int 数组完全同构**。

生活化比喻：数一串糖葫芦。方法 A 站在原地数"第几颗"（下标法）；方法 B 一边往前走一边摘（移动指针法）。

### ❷ 为什么

- 为什么字符串遍历不需要额外传长度？因为有 `\0` 终止符作为天然哨兵，`strlen` 也是靠扫到 `\0` 计数的。
- 为什么 char 特别适合指针法？因为 sizeof(char)==1，指针移动步长正好 1 字节，最直观。
- 为什么教材要给两种写法？为了证明"数组名寻址"和"指针移动寻址"这两套机制在字符上一致。

### ❸ 怎么用（P29 教材两段代码）

```cpp
#include <iostream>
#include <cstring>              // strlen 所在头文件
using namespace std;
int main() {
    char str[] = "hello world";
    int len = strlen(str);
    for (int i = 0; i < len; i++) cout << *(str + i);   // 写法A：数组名 + 偏移
    cout << endl;
    char* pstr = str;
    for (int i = 0; i < len; i++) cout << *pstr++;      // 写法B：移动指针
    cout << endl;
    return 0;
}
// 输出：hello world
// 输出：hello world
```

对应 code.cpp 第 157–166 行的完整版（用 `char arr_str[100]`，容量富余）：

```cpp
#include <iostream>
#include <cstring>
using namespace std;
int main() {
    char arr_str[100] = "hello world";
    int len = strlen(arr_str);
    char* pc = arr_str;
    for (int i = 0; i < len; i++) cout << *pc++;
    cout << endl;
    return 0;
}
// 输出：hello world
```

**遍历过程状态追踪（写法 B，以 "hi" 为例，地址简化）**

| 轮次 | i | pstr 进入时 | `*pstr++` 取值 | 输出 | pstr 离开时 |
|------|---|------------|---------------|------|------------|
| 1 | 0 | 0x5000 ('h') | 取 0x5000 的 'h' | h | 0x5001 |
| 2 | 1 | 0x5001 ('i') | 取 0x5001 的 'i' | i | 0x5002 |
| 结束 | — | 0x5002 ('\0') | 循环条件 i<len 不满足 | — | — |

```
 0x5000    0x5001    0x5002
┌─────┐   ┌─────┐   ┌─────┐
│ 'h' │   │ 'i' │   │ '\0'│
└─────┘   └─────┘   └─────┘
  pstr①     pstr②      （停在这，strlen 不计它）
```

### ❹ 注意事项

| 陷阱 | 说明 |
|------|------|
| 用 `sizeof(str)` 代替 `strlen` | `char str[100]="hi"` 时 sizeof==100 而 strlen==2，会打出 98 个垃圾字符 |
| 对常量字符串指针用 `arr++` 思路 | `char* s="hi";` 里 s 是指针变量可以 `s++`；`char arr[]="hi"` 里 `arr+1` 合法而 `arr++` 非法 |
| 循环写完还想继续用 pstr | 已指向末尾，需复位 `pstr = str;` |
| 忘了 `#include <cstring>` | `strlen` 未声明，编译报错 |

## §4.3 NULL 指针与 nullptr【熟悉】（P30–P32）

### ❶ 是什么

一句话：**不指向任何数据的指针叫空指针，用 NULL 表示；C++11 起更推荐用 `nullptr`**。

生活化比喻：一张空白的取件小票。NULL/nullptr 就是"这张票没对应任何包裹"——你可以拿着票（判空），但只要不去兑包裹（解引用）就绝对安全。

P30 原文要点：
- 一个指针不指向任何数据，称之为空指针，用 NULL 表示；
- **NULL 是区分大小写的，即 NULL 不能写成 null**；
- 在定义指针时或者指针使用完毕不再使用时，一定推荐将指针设置为 NULL，表明该指针不再指向任何数据；
- 定义：`#define NULL ((void *)0)`；`(void *)0` 表示把数值 0 强制转换为 `void *` 类型，最外层的 `( )` 把宏定义的内容括起来，在进行宏定义时推荐这么做，防止发生歧义。

### ❷ 为什么（三层追问）

- 为什么要有一个"空"值？为了给指针一个明确的"我没指向任何东西"状态，替代脏随机值。
- 为什么宏要写成 `((void*)0)` 双层括号？不加括号时 `NULL * 2` 会展开成 `(void*)0 * 2` 引起优先级歧义；而 `void*` 又能隐式转成任意指针类型。
- 为什么还要发明 nullptr？因为在 C++98 里字面常量 0 的类型既可以是整型，也可以是无类型指针（`void*`），在某些场景（例如函数重载）会遇到麻烦。C++11 引入 `nullptr`——它是一个"指针空值常量"，仅可以被隐式转换为指针类型，从而消除二义性。

### ❸ 怎么用

```cpp
#include <iostream>
using namespace std;
int main() {
    int* p1 = NULL;         // C 风格空指针（P31 推荐写法）
    int* p2 = nullptr;      // C++11 推荐写法
    int  num = 100;
    if (p1 == nullptr) cout << "p1 是空指针，安全（还没兑包裹）" << endl;
    p1 = &num;              // 使用前才真正挂上地址
    cout << *p1 << endl;
    p1 = nullptr;           // 用完置空，避免误用
    cout << (p2 == nullptr) << endl;
    return 0;
}
// 输出：p1 是空指针，安全（还没兑包裹）
// 输出：100
// 输出：1
```

对应 code.cpp 第 169–170 行（两个写法并存展示）：
```cpp
int* p  = NULL;
int* p2 = nullptr;
```

**★ 对比表之二：NULL vs nullptr（提示词强制要求）**

| 维度 | `NULL` | `nullptr` |
|------|--------|-----------|
| 本质 | 宏，展开为 `((void*)0)` | 关键字，类型是 `std::nullptr_t` |
| 出现版本 | C/C++ 传统 | C++11 起 |
| 书写大小写 | 必须全大写（P30 明确） | 必须全小写 |
| 能否参与算术 | 能（它本质是整数常量 0） | 不能，`nullptr + 1` 编译错误 |
| 函数重载是否有二义 | ⚠️ 有 | ✅ 无 |
| 能否隐式转成整型 | 能（`int x = NULL;` 合法） | 不能（`int x = nullptr;` 编译错误） |
| 大小 | `sizeof(NULL)` 本机为 8（按指针算） | `sizeof(nullptr_t)` 本机为 8 |
| 教材结论 | 兼容旧代码 | **"以后指针初始化赋值就使用 nullptr"**（P32 原话） |

二义性实测（最有说服力的一段）：

```cpp
#include <iostream>
using namespace std;
void f(int x)   { cout << "f(int)" << endl; }
void f(void* p) { cout << "f(void*)" << endl; }
int main() {
    f(NULL);      // ❌ 编译错误
    f(nullptr);   // ✅ 唯一匹配 f(void*)
    return 0;
}
// 编译 NULL 那一行时报错：
// error: call of overloaded 'f(NULL)' is ambiguous
// note: candidate: 'void f(int)'   /  'void f(void*)'
// 删掉 f(NULL) 只留 nullptr 后正常运行：输出 f(void*)
```

对照实验（本机）：`f(0)` 会优先匹配 `f(int)`，输出 `f(int)`；而 `f(nullptr)` 明确匹配 `f(void*)`——这就是"0 身兼两职"造成的隐性歧义。

### ❹ ⚠️ 危险操作：野指针（P31 红牌）

P31 原文：定义指针变量时 `int *p;` **不建议这样写**，一般如果指针定义出来不指向任何地址是比较危险的，叫做**野指针**；建议写成 `int *p = NULL；`

```cpp
int *p;         // 未初始化 → p 里是栈上的随机残留值
*p = 100;       // ⚠️ 往随机地址写 4 个字节
cout << *p << endl;
```
本机 g++ 8.1.0 实测：`Segmentation fault`，exit code 139。

处置守则：

| 时机 | 动作 |
|------|------|
| 定义但暂时不指向任何东西 | `int* p = nullptr;` |
| 使用前 | `if (p != nullptr) { ... }` 判空 |
| 用完/不再使用 | `p = nullptr;`（防二次误用） |
| 释放内存之后（后续章节） | 立即置空，防"悬垂指针 + 重复释放" |

> 🗣 人话总结：不用的指针写 nullptr，别让它瞎指。

## §4.4 void 指针（万能指针）【熟悉】（P33–P35）

### ❶ 是什么

一句话：**`void*` 是无类型指针，可以指向任何类型的数据，但取值前必须先强制转换成正确的指针类型**。

生活化比喻：一个没有标签的万能收纳箱。什么都能放进去（任何指针都能赋给 `void*`），但取用时你必须说清"我要按 int 的方式打开"，否则箱子不知道自己装的是什么、该读几个字节。

P33 原文：void 的意思就是"无类型"，void 指针则为"无类型指针"，void 指针可以指向任何类型的数据。所以 void 指针一般被称为通用指针或者泛指针，也可以叫做万能指针。定义：`void *p`。

### ❷ 为什么

- 为什么需要"不带类型"的指针？因为有些接口必须接收任意类型：`malloc` 返回 `void*`、线程函数参数、回调里透传用户数据。
- 为什么不能直接解引用？因为解引用要做两件事——"读几个字节"和"按什么格式解释"，`void` 两个都不知道，编译器无从生成指令。
- 为什么"任何指针可赋给 void\*，反之不行"？单向隐式转换是为了保证"丢掉类型信息"这一步由程序员主动选择，捡回来时必须显式声明。

P34 三条使用规则（原文）：
1. 在 C++ 中在任何时候都可以用 void 类型的指针来代替其他类型的指针，void 指针可以指向任何数据类型的变量；
2. 如果要通过 void 指针去获取它所指向的变量值时候，需要先将 void 指针强制类型转换成和变量名类型相匹配的数据类型指针后再进行操作；
3. 任何类型的指针都可以赋值给 void 指针，无需进行强制类型转换。

### ❸ 怎么用（P35 教材案例）

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100;
    void *p = &num;                            // 任何指针 → void*，无需转换
    cout << "p = " << p << endl;               // 打印地址本身
    //cout << "*p = " << *p << endl;           // ❌ 教材注释行：void 指针不可直接使用
    cout << " *p = " << *((int*)p) << endl;    // 先转成 int* 再解引用
    return 0;
}
// 输出：p = 0x61fe2c
// 输出： *p = 100
```

多类型演示（证明"万能"）：

```cpp
#include <iostream>
using namespace std;
int main() {
    int    num = 100;
    double d   = 3.14;
    void* vp1 = &num;
    void* vp2 = &d;
    cout << *(int*)vp1    << endl;   // 必须知道它原本是 int
    cout << *(double*)vp2 << endl;   // 必须知道它原本是 double
    return 0;
}
// 输出：100
// 输出：3.14
```

对应 code.cpp 第 173–177 行注释段（原样可运行）：

```cpp
int num = 100;
void * p = &num;
cout << p << endl;
cout << *(int *)p << endl;
// 输出：0x61fe2c
// 输出：100
```

**★ 对比表之三：void\* vs 普通指针（提示词强制要求）**

| 维度 | `void*` | 普通指针 `int*` |
|------|---------|----------------|
| 能指向的类型 | 任意 | 仅声明的那种 |
| 能否直接 `*p` 解引用 | ❌ 编译错误 | ✅ 合法 |
| 能否 `p++` | ❌ 标准不允许（GCC 扩展按 1 字节算，MSVC 直接报错） | ✅ 按 sizeof(类型) 移动 |
| 能否赋给别的类型指针 | ❌ 必须显式强转 | ✅ 同类型直接赋 |
| 接收别的类型指针 | ✅ 隐式即可（规则 3） | ❌ 类型必须匹配 |
| 典型用途 | malloc、通用接口、回调透传 | 日常访问具体数据 |
| 携带类型信息 | 无（丢失步长与解读方式） | 有（决定步长与解读方式） |
| 与 nullptr 比较 | ✅ 可以 `if (vp == nullptr)` | ✅ 可以 |

### ❹ 注意事项

| 陷阱 | 代码 | 后果 |
|------|------|------|
| 直接解引用 | `void* p=&num; cout<<*p;` | `error: invalid type argument of unary '*'` |
| 转错类型 | `int n=100; void* p=&n; cout<<*(double*)p;` | 编译通过，但读出的是把 100 的位模式当 double 解释出的荒谬值（约 `4.94e-322`）——数据彻底错 |
| 忘记转换就传给具体类型参数 | `func_intptr(vp1);` | 编译错误 `cannot convert 'void*' to 'int*'` |
| 用作"逃避类型检查"的手段 | 大量 `void*` 中转 | 一旦源类型变了，所有强转点静默出错；能用模板/明确类型就别用 `void*` |

> 🗣 人话总结：万能指针啥都装，取用之前先说型。

# 模块五 指针进阶辨析（P36–P41）

## §5.1 指针与引用的区别【重点】（P36–P37）

### ❶ 是什么

一句话：**指针是"存地址的变量"，引用是"已有变量的别名"**。

生活化比喻：指针像"通讯录里的一条记录"，可以留空、可以换号；引用像"身份证上的曾用名"，出生就绑死一个人，一辈子不能改指向，也不能凭空存在。

P36 原文：指针的本质是一个变量的地址，而引用的本质是变量的别名。同时，定义指针值可以不初始化，并且可以定义空指针，但定义引用时，必须初始化，并且不能定义空引用。补充一句很有格局的话：**每一种编程语言都使用指针，不止 C 语言和 C++ 使用指针。只是 C++ 将指针暴露给了用户（程序员），而 Java 和 C# 等语言则将指针隐藏起来了。**

### ❷ 为什么

- 为什么要有引用？让"能改实参"这件事写得像值传递一样干净，不必满屏 `*` 和 `&`。
- 为什么引用不能为空、不能改绑？正因为有这个保证，编译器才能省掉判空、直接内联优化，从而"效率比指针高、代码更安全"（P37 原话）。
- 为什么底层还是指针？因为别名最终也要落到目标地址上——所以 P41 说"引用的本质是指针常量"。

### ❸ 怎么用

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100;
    int& r = num;              // 引用必须在定义时初始化
    r = 888;                   // 通过别名改本体
    cout << "num = " << num << endl;   // 888
    cout << "r   = " << r   << endl;   // 888
    cout << (&r == &num) << endl;      // 1 —— 同一块内存的两个名字
    cout << "sizeof(r) = " << sizeof(r) << ", sizeof(num) = " << sizeof(num) << endl;
    int* p = &num;
    cout << "sizeof(p) = " << sizeof(p) << " (指针本身)" << endl;
    return 0;
}
// 输出：num = 888
// 输出：r   = 888
// 输出：1
// 输出：sizeof(r) = 4, sizeof(num) = 4
// 输出：sizeof(p) = 8 (指针本身)
```

关键观察：`sizeof(r)` 得到 4（所指对象大小），`sizeof(p)` 得到 8（指针本身大小）——这正是 hw.txt 列的第 5 条不同点。

自增语义差异（hw.txt 第 6 条，接 §1.3 实测地址）：

```cpp
int num = 100;
int& r = num;
int* p = &num;
r++;   // num: 100 → 101（值 +1）
p++;   // p  : 0x61fe3c → 0x61fe40（地址 +4 字节）
```

### ❹ 错误示范（本机 g++ 8.1.0 真实报错）

```cpp

int& r2 = 100;      // ❌ error: cannot bind non-const lvalue reference of type 'int&'
```

### ★ 对比表之四：指针 vs 引用（提示词强制要求，P36–P37 + hw.txt 全量整合）

| # | 对比维度 | 指针 | 引用 | 出处 |
|---|---------|------|------|------|
| 1 | 本质 | 一个变量，存的是地址 | 一个别名 | P36 |
| 2 | 是否实体 | 是实体（有独立内存） | 仅是个别名 | hw.txt |
| 3 | 定义时初始化 | 可以不初始化（成为野指针） | 必须初始化 | P36 |

| 5 | 可否改指向 | 可以，运行时随意换 | 绑定后终身不改（"从一而终" vs "见异思迁"） | P37、hw.txt |
| 6 | 内存分配 | 程序为指针变量分配内存区域 | 不为引用分配内存区域 | P37 第 2 条 |

| 14 | 类型安全 | 不做类型检查（`void*` 尤甚） | 类型安全，编译期检查 | hw.txt 末条 |
| 15 | 使用语法 | `*p` 取值、`&x` 传址 | 像普通变量一样直接用 | P19、P36 |

### 相似概念并列讲解：什么时候选谁

| 场景 | 推荐 | 理由 |
|------|------|------|
| 函数只需读大对象 | `const T&` | 免拷贝 + 防误改 |
| 函数需修改实参 | `T&`（首选）或 `T*` | 引用免判空、写法干净 |
| 参数允许"不传"（可选语义） | `T*` + nullptr | 引用无法表达"空" |
| 需要在函数内改变调用者的指针本身 | `T**` 或 `T*&` | 单级指针不够 |
| 保存"可能没有对象"的关系（链表 next、树 child） | `T*` | 必须能是空 |
| 运算符重载（如 `operator[]`）需要链式赋值 | 返回 `T&` | 左值语义 |

> 🗣 人话总结：指针能空能换，引用从一而终。

## §5.2 指针常量与常量指针【重点】（P38–P40）

> 本章第二大难点。提示词要求"更慢的节奏 + 每步配示例和内存图"，下面拆到最细。

### ❶ 是什么

一句话：**const 靠近谁就锁谁——写在 `*` 左边锁"值"（常量指针），写在变量名前锁"指向"（指针常量），两处都有就都锁**。

生活化比喻：
- 指针常量 `int* const p` = **车位焊死、货物随便换**：p 指向哪不能挪，但那块内存里的值可写。
- 常量指针 `const int* p` = **货箱贴封条、车随便开走**：`*p` 只读，但 p 可以改指别的变量。
- 双 const `const int* const p` = **车位焊死 + 货箱封条**：两头都不能动，纯只读窗口。

### ❷ 为什么

- 为什么要区分这两种锁？因为"不希望被改"有两种截然不同的意图：不想让别人换目标，和不想让别人污染数据。
- 为什么 `const int* p` 与 `int const* p` 等价？因为 const 修饰的是它邻近的类型 `int`，二者都表示"指向的 int 是常量"。code.cpp 第 187、191 行用的就是后置写法 `int const*`。
- 为什么读法要"从右往左"？C/C++ 声明语法按"如何使用来表达"设计，从变量名出发由近及远读最准。

### ❸ 怎么用（P38–P40 三段教材代码，逐条实测）

**① 指针常量：`int * const p`（P38，原文"const 修饰常量 即指针常量"）**

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100, num2 = 200;
    int * const p = &num;   // 指针常量：p 的指向被锁
    *p = 111;               // ✅ 正确：能改指向的值
    //p = &num2;            // ❌ 错误：不能改指向
    cout << "num = " << num << endl;
    return 0;
}
// 输出：num = 111
```
P38 原理解释：由于 const 修饰的是 p，所以 p 不能修改，即指针的值不能修改，也就是**指针的指向不能修改**。

**② 常量指针：`const int * p`（P39，原文"const 修饰指针 即常量指针"）**

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100, num2 = 200;
    const int * p = &num;   // 常量指针：*p 被锁
    p = &num2;              // ✅ 正确：能改指向
    //*p = 111;             // ❌ 错误：不能改所指的值
    cout << "*p = " << *p << endl;
    return 0;
}
// 输出：*p = 200
```
P39 原理解释：由于 const 修饰的是 `*p`，所以 `*p` 不能修改。

**③ 双重 const：`const int * const p`（P40，原文"const 修饰指针 又常量"）**

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100, num2 = 200;
    const int * const p = &num;
    //p  = &num2;   // ❌ 错误
    //*p = 222;     // ❌ 错误
    cout << "*p = " << *p << endl;   // 只能读
    return 0;
}
// 输出：*p = 100
```
P40 原理解释："都不能修改"。

**三种形式合并实测（一次跑通三条合法语句）**

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100, num2 = 200;
    int* const p = &num;          // ① 锁指向
    *p = 111;
    cout << "*p=111 -> num = " << num << endl;
    const int* p2 = &num;         // ② 锁值
    p2 = &num2;
    cout << "p2改指num2 -> *p2 = " << *p2 << endl;
    const int* const p3 = &num;   // ③ 全锁
    cout << "*p3 = " << *p3 << endl;
    return 0;
}
// 输出：*p=111 -> num = 111
// 输出：p2改指num2 -> *p2 = 200
// 输出：*p3 = 111        ← 注意 p3 读到的是已被①改过的 111
```

**★ 三种违规写法的真实编译错误（本机 g++ 8.1.0）**

| 违规写法 | 编译器报错原文 |
|---------|---------------|
| `int* const p=&num; p=&num2;` | `error: assignment of read-only variable 'p'` |
| `const int* p=&num; *p=111;` | `error: assignment of read-only location '* p'` |
| `const int* const p=&num; *p=9;` | `error: assignment of read-only location '*(const int*)p'` |

**内存图：三种 const 指针到底锁住了什么**

```
情形①：int * const p = &num;      （锁 p 自身 → 指向不可改）
   p ─╳─→ [换个目标]      p ═══→ [num: 100] ──→ *p = 111  ✅ 值可写
        ↑被封条锁住           格子里的内容可覆盖

情形②：const int * p = &num;      （锁 *p → 值不可改）
   p ───→ [num: 100] 🔒      p ═══→ [num2: 200]  ✅ 指向可改
        内容上封条，*p = 111 ❌     箭头可以换靶子

情形③：const int * const p = &num;（两头都锁）
   p ─╳─→ [num: 100] 🔒      既不能换靶子，也不能改内容 → 纯只读窗口

  图例：═══> 允许的指向    ─╳─> 禁止的改指向    🔒 禁止改值
```

### ❹ 注意事项

| 陷阱 | 说明 |
|------|------|
| 认为 `const int* p` 意味着 p 不能变 | 恰恰相反：p 可变，`*p` 不可变 |
| 认为 `int* const p` 意味着所指的值是常量 | 恰恰相反：`*p` 可写，p 不可写 |
| 指针常量不在定义时初始化 | `int* const p;` → 编译错误（const 对象必须初始化） |
| 通过别的途径绕过 | `const int* p=&num; int* q=&num; *q=5;` → 合法，num 真会变。const 只约束"通过这个指针看" |
| 忘记 `int const*` == `const int*` | code.cpp 第 187、191 行用的是后置写法，与 P39 前置写法完全等价 |

### ★ 对比表之五：指针常量 vs 常量指针（提示词强制要求）

| 对比项 | 指针常量 `int* const p` | 常量指针 `const int* p`（≡ `int const* p`） | 双锁 `const int* const p` |
|--------|------------------------|--------------------------------------------|---------------------------|
| const 位置 | `*` 右边、变量名前 | `*` 左边、类型名旁 | 两处都有 |
| 谁被锁 | 指针自身（存的地址） | 所指的值 `*p` | 两者都锁 |
| `p = &other;` | ❌ 编译错误 | ✅ 合法 | ❌ 编译错误 |
| `*p = 5;` | ✅ 合法 | ❌ 编译错误 | ❌ 编译错误 |
| 能否作函数形参 | 传不进新地址（对调用者无意义） | ✅ 常用：承诺只读源数据 | ✅ 强只读 |
| 是否必须初始化 | ✅ 必须 | 不强制（但强烈建议） | ✅ 必须 |
| 记忆口诀 | "const 挨着 p → 锁 p" | "const 挨着 int → 锁值" | "两头都有 → 全锁" |
| 典型用途 | 函数内不该换目标的指针 | 只读传入大对象、保护源数据 | 只读且固定的窗口 |
| 一句话 | 指向不能改，值能改 | 值不能改，指向能改 | 都不能改 |

**读法训练（三步走）**

```cpp
// 第1步：找到变量名 p（起点）
// 第2步：向左读——遇到 const 就贴标签
// 第3步：向右读——遇到 * 表示"指针"
int const * const p;
//        ↑ p 是 const（指针锁定）
//     *  ← p 是指针
//   ↑ const 修饰 int（值锁定）
// 合成读法：p 是一个 const 指针，指向一个 const int → 两头都锁
```

判别流程图：

```
            看到一条指针声明
                   │
        从变量名出发，先找离它最近的 const
                   │
      ┌────────────┴────────────┐
      │                         │
 const 在 * 的右边          const 在 * 的左边
 （挨着变量名）             （挨着类型名）
      │                         │

                   │

```

## §5.3 引用和常量引用【熟悉】（P41）

### ❶ 是什么

一句话：**引用的底层本质是指针常量 `int * const p`；常量引用的本质是 `const int * const p`**。

生活化比喻：普通引用像"公司工牌"——入职时绑定一个工位（指向固定），工位上的东西随便摆（值可改）。常量引用像"参观通道的玻璃窗"——不能换看哪个工位，也不能伸手碰展品。

P41 原文：引用的本质其实是：指针常量，即 `int * const p = &num;`，特点就是和指针常量的特点一样，指向的值能改变，指针的指向不能改变。常量引用的本质：`const int * const p = &num;`，特点是：指针的指向和指向的值都不能更改。

### ❷ 为什么

- 为什么引用等价于指针常量？因为引用"必须初始化 + 终身不换目标"这两条约束，恰好就是 `T* const` 的语义。
- 为什么不直接暴露成指针常量？因为语法噪音太大（每次都要 `*`），引用让调用点保持朴素。
- 为什么需要常量引用？既能避免拷贝（大对象传参），又能承诺不修改，还能接受临时值和字面量。

### ❸ 怎么用

```cpp
#include <iostream>
using namespace std;
int main() {
    int num = 100, num2 = 200;
    int&       r  = num;   // 本质：int* const p = &num
    const int& cr = num;   // 本质：const int* const p = &num
    r = 888;               // ✅ 改值（相当于 *p = 888）
    cout << "num = " << num << endl;
    cout << "cr  = " << cr  << endl;
    r = num2;              // ⚠️ 这不是改绑！它等价于 num = num2
    cout << "执行 r=num2 后 num = " << num << ", num2 = " << num2 << endl;
    //cr = 5;              // ❌ 常量引用不可写
    //int& bad;            // ❌ 引用必须初始化
    return 0;
}
// 输出：num = 888
// 输出：cr  = 888
// 输出：执行 r=num2 后 num = 200, num2 = 200   ← 本体被赋值，绑定从未改变
```

必须澄清的高频误解：`r = num2;` 看起来像"让引用改绑到 num2"，实际执行的是 `num = num2;`（把 num2 的值赋给本体 num）。引用一旦绑定，**任何语法都无法让它改指别的对象**——这正好印证"指向不可改"，也印证了它的本质是 `int* const`。

**常量引用能吃下字面量（普通引用不行）**

```cpp
#include <iostream>
using namespace std;
int main() {
    const int& cr = 100;    // ✅ 合法：延长临时值的生命周期
    cout << cr << endl;
    //int& r = 100;         // ❌ 编译错误（见 §5.1 错误示范）
    return 0;
}
// 输出：100
```

**四种"锁"的全景统一表**

| 声明 | 底层本质 | 指向可改 | 值可改 | 直观称呼 |
|------|---------|---------|-------|---------|
| `int* p = &num;` | 普通指针 | ✅ | ✅ | 双向自由 |
| `int* const p = &num;` | 指针常量 | ❌ | ✅ | 普通引用的本质 |
| `const int* p = &num;` | 常量指针 | ✅ | ❌ | 只读窗口（可换靶） |
| `const int* const p = &num;` | 双锁 | ❌ | ❌ | 常量引用的本质 |

### ❹ 注意事项

| 陷阱 | 说明 |
|------|------|
| 以为 `r = other` 换了绑定 | 它只是赋值，本体被改写 |
| 用常量引用偷偷改值 | `const int& cr=num; (int&)cr = 5;` 属未定义行为，别写 |
| 返回局部变量的引用 | 与"返回局部变量地址"完全同级的问题 ⚠️ |
| 混淆"常量引用"与"引用常量" | `const int&` 是常量引用（值只读）；不存在所谓"引用常量"，引用本身就不可改绑 |

> 🗣 人话总结：引用就是不能换靶子的指针常量。

## §6.1 课堂练习题详解：checkMax【重点】（P42–P43）

### 题目（P42 原文）

函数原型：`void checkMax(int *p1, int *p2, int *pmax);` 实现找出两个数中最大值。

考察点：**指针传参 + 解引用赋值 + 地址传递的综合运用**。三个参数全是通道，前两个是读入口，第三个是写入口。

### 解题思路（四步推导）

1. 函数返回类型是 `void`，说明结果不能靠 return 带回，只能写进第三个参数指向的内存；
2. 比较的是"值"，所以要写 `*p1 > *p2`，而不是比较地址 `p1 > p2`（后者是最常见错解）；
3. 写入结果必须解引用左侧：`*pmax = ...`；
4. 调用方要给 `n3` 的地址，且 n3 无需预先赋值（if/else 两个分支必然覆盖一次写入）。

### 参考实现（P43 教材代码，完整可运行）

```cpp
#include <iostream>
using namespace std;
void checkMax(int *p1, int *p2, int *pmax) {
    if (*p1 > *p2) {
        *pmax = *p1;
    } else {
        *pmax = *p2;
    }
}
int main() {
    int n1, n2, n3;
    cin >> n1 >> n2;           // 从键盘读入两个数
    checkMax(&n1, &n2, &n3);   // 三个地址全部传进去
    cout << n3 << endl;        // n3 里已经是最大值
    return 0;
}
// 输入：5 8      → 输出：8
// 输入：900 200  → 输出：900
```

### code.cpp 里的同名成品（第 36–43 行 + 第 196–198 行，本章唯一未注释的主流程）

```cpp

    else           { *pMax = *p2; }

    int v1 = 900, v2 = 200, v3;

```

逐行状态追踪（本机实测）：

| 步骤 | 语句 | v1 | v2 | v3 | 说明 |
|------|------|----|----|----|------|
| 1 | `int v1=900,v2=200,v3;` | 900 | 200 | 未定义 | v3 是脏值 |
| 2 | `checkMax(&v1,&v2,&v3)` | — | — | — | p1→v1, p2→v2, pMax→v3 |
| 3 | `*p1 > *p2` 即 `900>200` | — | — | — | 条件成立，走 then 分支 |
| 4 | `*pMax = *p1;` | 900 | 200 | **900** | 写进了调用者的 v3 |
| 5 | `cout << v3` | — | — | — | 输出 900 |

```

                       （箭头穿过栈帧边界，直接落到 main 的格子）
```

### 三种典型错误写法

```cpp
// 错误1：比较地址而非值
void checkMax(int* p1,int* p2,int* pmax){ *pmax = (p1 > p2) ? *p1 : *p2; }
// 结果取决于栈布局，纯属赌博

// 错误2：形参没用指针，却想用值带回
void checkMax(int p1,int p2,int pmax){ pmax = p1>p2?p1:p2; }
// 编译能过，调用方的 v3 永远是垃圾值

// 错误3：把指针本身重新赋值，没写到目标内存
void checkMax(int* p1,int* p2,int* pmax){ if(*p1>*p2) pmax = p1; else pmax = p2; }
// 只改了形参副本，v3 依然是垃圾值
```

## §6.2 作业面试题解析【重点】（P45）

### 题目（P45 原文）

**面试题：引用与指针相同点和不同点？**

### 标准答案（来自 hw.txt，该文件为 GBK 编码，已完整解码整理）

**相同点**

> 都是地址的概念：指针指向一块内存，它的内容是所指内存的地址；而引用则是某块内存的别名。

**不同点（hw.txt 原文 7 条，逐条配解释与实证）**

| # | hw.txt 原文 | 展开解释 + 实证 |
|---|------------|----------------|
| 1 | 指针是一个实体，而引用仅是个别名 | 指针有独立存储单元（64 位占 8 字节）；引用只是现有对象的新名字 |
| 2 | 引用只能在定义时被初始化一次，之后不可变；指针可变；引用"从一而终"，指针可以"见异思迁" | `int* p=&a; p=&b;` 合法；`int& r=a;` 之后再无任何语法能改绑 |
| 3 | 引用没有 const，指针有 const，const 的指针不可变 | 引用天生不可改绑，所以没有"锁指向"的必要；锁值要靠常量引用 `const int&` |
| 4 | 引用不能为空，指针可以为空 | `int& r=nullptr;` 编译失败；`int* p=nullptr;` 合法 |
| 5 | `sizeof 引用` 得到所指向变量(对象)的大小，`sizeof 指针` 得到指针本身的大小 | 实测：`sizeof(r)==4`，`sizeof(p)==8` |
| 6 | 指针和引用的自增(++)运算意义不一样 | `p++` 让地址 +4 字节移动一格；`r++` 让本体值 +1 |
| 7 | 引用是类型安全的，而指针不是（引用比指针多了类型检查） | `void*` 可强转成任意类型、运行期才出错；引用必须类型匹配才能绑定 |

**再叠加 P37 的编译视角答案（面试加分项）**

- **从现象上看**：指针在运行时可以改变其所指向的值，而引用一旦和某个对象绑定后就不再改变。
- **从内存分配上看**：程序为指针变量分配内存区域，而不为引用分配内存区域，因为引用声明时必须初始化，从而指向一个已经存在的对象；引用不能指向空值。
- **从编译上看**：程序在编译时分别将指针和引用添加到符号表上，符号表上记录的是变量名及变量所对应地址。指针变量在符号表上对应的地址值为指针变量的地址值，而引用在符号表上对应的地址值为引用对象的地址值。符号表生成后就不会再改，因此指针可以改变指向的对象（指针变量中的值可以改），而引用对象不能改。**这是使用指针不安全而使用引用安全的主要原因。从某种意义上来说引用可以被认为是不能改变的指针。**
- **效率补充**：不存在指向空值的引用这个事实，意味着使用引用的代码效率比使用指针的要高，因为在使用引用之前不需要测试它的合法性；相反，指针则应该总是被测试，防止其为空。
- **级数补充**：理论上，对于指针的级数没有限制，但是引用只能是一级。

满分答题模板（面试现场 60 秒版）：

```
"相同点：两者本质都是地址概念。
 不同点我从五个维度说：
 ① 本质：指针是存地址的实体变量，引用是别名；
 ② 内存：指针占 4/8 字节，引用不额外分配；sizeof 结果一个是自身大小、一个是被指对象大小；
 ③ 可空性与初始化：指针可不初始化（变野指针）也可为空，引用必须初始化且不能为空；
 ④ 可改性：指针能换指向，引用从一而终；++ 的含义也不同；
 ⑤ 安全与级数：引用类型安全、无需判空故效率略高，只能一级；指针有多级、需自行保证合法。"
```

> 🗣 人话总结：答引用指针，抓"实体 vs 别名"这条主线。

## §7.3 hw.txt 全文解码与点评

`hw.txt`（GBK 编码，第 45 页面试题的答案）完整内容：

```
相同点
都是地址的概念，指针指向一块内存，它的内容是所指内存的地址；而引用则是某块内存的别名。

不同点
指针是一个实体，而引用仅是个别名；
引用只能在定义时被初始化一次，之后不可变；指针可变；引用"从一而终"，指针可以"见异思迁"；
引用没有 const，指针有 const，const 的指针不可变；
引用不能为空，指针可以为空；
"sizeof 引用" 得到的是所指向的变量(对象)的大小，而 "sizeof 指针" 得到的是指针本身的大小；
指针和引用的自增(++)运算意义不一样；
引用是类型安全的，而指针不是 (引用比指针多了类型检查）
```

点评与补强（答题时补这三句更显功力）：
1. "引用没有 const" 这句容易被误解。准确说法是：**引用自身不存在"能不能改指向"的 const 概念可言**（因为它天生不可改绑），要锁住所指的值应当使用常量引用 `const int&`，其本质即 `const int* const`（P41）。
2. "sizeof 引用"那条本机实测：`sizeof(r)==4`（int 对象大小），`sizeof(p)==8`（指针本身）。
3. "++ 意义不一样"本机实测：`p++` 使地址从 `0x61fe3c` 变 `0x61fe40`（+4 字节）；`r++` 使 `num` 从 100 变 101（值 +1）。

## §7.4 两大难点慢节奏重讲

### 难点 A：指针与函数的交互机制

慢镜头（以 `func2(&num)` 为例，num 位于 `0x61fe2c`）：

```
Step 1  编译期：main 里的 &num 被翻译成"取 0x61fe2c 这个地址"
Step 2  调用前：把待传的 8 字节（地址值）压栈或放入寄存器
Step 3  进入函数：为新栈帧分配空间，把收到的 0x61fe2c 写入形参 v1 的格子
        ┌─ func2 栈帧 ──────────────┐
        │ v1 : int* = 0x61fe2c      │  ← v1 自己是"地址的副本"
        └───────────────────────────┘
Step 4  执行 (*v1)++ ：
        4a 读 v1 → 得 0x61fe2c
        4b 按 int* 类型读该地址的 4 字节 → 100
        4c 加 1 → 101
        4d 写回 0x61fe2c 这 4 字节 → main 的 num 现在是 101 ✅
Step 5  返回：func2 栈帧弹出，v1 消失；但 num 所在的 0x61fe2c 属于 main 栈帧，安然无恙
Step 6  main 继续：cout << num → 101
```

一句话本质：**函数能改的是"它有权访问的地址上的内容"，不能改的是"已经随栈帧销毁的东西"。** 这条原则同时解释了 §3.1（为什么传地址能改）与 §3.3（为什么返回局部地址不能用）——它们是同一枚硬币的两面。

### 难点 B：const 修饰规则的慢速推导

对 `int const * const p` 逐 token 拆解：

```
   int   const   *   const   p
    │     │      │     │     │
    │     │      │     │     └─ 起点：先看名字 p
    │     │      │     └─────── p 是 const → 指针自身锁定 → p 不能换指向
    │     │      └───────────── * → p 是指针
    │     └──────────────────── const 修饰 int → 所指的值锁定 → *p 不能写
    └───────────────────────── 基底类型 int
   合成读法：p 是一个 const 指针，指向一个 const int。
   验证：p=&other ❌（第二条锁）；*p=5 ❌（第三条锁）。与 P40 结论一致。
```

对 `int * const p`：

```
   int   *   const   p     → p 是 const 指针，指向 int（可变）
   验证：p=&other ❌；*p=5 ✅。与 P38 一致。
```

对 `const int * p`：

```
   const int * p            → p 是指针，指向 const int
   验证：p=&other ✅；*p=5 ❌。与 P39 一致。
```

## §7.5 常见陷阱专题（最易错点全解剖）

### 陷阱 1：返回局部变量的地址 ⚠️ 危险操作

| 项目 | 内容 |
|------|------|
| 错误写法 | `int* func(){ int x=10; return &x; }` |
| 后果 | 函数返回后 x 随栈帧销毁，指针悬空；解引用 = 未定义行为。**本机实测：编译告警 `address of local variable 'v1' returned`，运行 `Segmentation fault`，exit code 139** |
| 正确写法 | 传入外部变量地址由被调方填 / 返回全局或 static 变量地址 / 直接返回值 |
| 如何记住 | 函数栈帧退出即销毁，永远不要返回栈上的地址 |
| 识别信号 | 返回类型是 `T*` 或 `T&`，函数体里却有 `return &局部变量;` |
| 教材出处 | P23 明令禁止、P26 打 `?` 的反例、code.cpp 第 29–33 行 test2 |

### 陷阱 2：野指针未初始化直接使用 ⚠️ 危险操作

| 项目 | 内容 |
|------|------|
| 错误写法 | `int *p; *p = 100;` |
| 后果 | p 里是栈上随机残留值，写入可能覆盖关键数据或触发段错误。**本机实测：`Segmentation fault`，exit code 139** |
| 正确写法 | `int *p = nullptr;` 或 `int *p = &someVar;`，定义即初始化 |
| 如何记住 | 定义指针必初始化，不用就置 nullptr |
| 教材出处 | P31 明确点名"野指针"并给出建议写法；code.cpp 第 179 行 `//int* p;` 即此标本 |

### 陷阱 3：const 修饰位置搞混导致编译错误或逻辑错误 ⚠️ 双错

| 项目 | 内容 |
|------|------|
| 错误写法 A | 想锁"指向"却写成 `const int* p`（其实锁了值）→ `p = &other` 意外合法，本该保护的目标被换掉 |
| 错误写法 B | 想锁"值"却写成 `int* const p` → `*p = 999` 悄悄改掉了源数据 |
| 真实报错 | `assignment of read-only variable 'p'`（改了指针常量）／`assignment of read-only location '* p'`（改了常量指针的值） |
| 正确写法 | 记"const 靠近谁锁谁"：`const int *p` 锁值，`int * const p` 锁指向 |
| 如何记住 | 从右往左读声明：const 紧挨 `*` 左边锁值，紧挨变量名右边锁指针 |
| 教材出处 | P38 / P39 / P40 三页各一种；code.cpp 第 181–193 行三组试验 |

### 附加陷阱 4：void\* 未转型就解引用 ⚠️ 危险操作

```cpp
void* p = &num;
cout << *p;        // ❌ error: invalid type argument of unary '*'
cout << *(int*)p;  // ✅ 先转型再解引用 → 输出 100
```
更阴险的变体是**转错类型**：`int n=100; void* p=&n; cout<<*(double*)p;` 编译完全通过，运行输出约 `4.94e-322` 的荒谬值——静默数据损坏，比崩溃更难查。

### 附加陷阱 5：指针越界访问 ⚠️ 危险操作

```cpp
int arr[3] = {1,2,3};
int* p = arr;
for (int i = 0; i < 10; i++) cout << *p++ << " ";
// 本机实测输出：1 2 3 -1 1606412304 4199136 4199056 32767 0 0
//                ↑真数据↑      ↑全是别人的栈内存↑
```
防御手段：循环次数永远来自"元素个数"这一唯一真相源（`sizeof(arr)/sizeof(arr[0])` 只在数组本体所在作用域有效）。

### 附加陷阱 6：数组名当指针用（sizeof 与赋值双重翻车）

```cpp
int arr[5] = {1,2,3,4,5};
int x = 9;
arr = &x;              // ❌ error: assignment of read-only variable 'arr'
cout << sizeof(arr);   // 主作用域里 20，但传进函数后变 8 —— 见 §2.1
```

## §7.6 新手最常问的 5 个问题

**Q1：指针和数组到底是不是同一个东西？**
不是。它们只是"长得像、能互操作"。数组是一块连续内存的**名字**（常量，不能赋值、不能自增，`sizeof` 得到整块大小）；指针是一个**存地址的变量**（可赋值、可 `++`，`sizeof` 得到 8）。之所以容易混，是因为 `arr[i]` 被编译器翻译成 `*(arr+i)`，且数组名传参会退化成指针。判别口诀：**能 `++` 的是指针，不能的是数组名**。

**Q2：为什么函数不能返回局部变量的地址？**
因为局部变量住在函数自己的栈帧里，函数 `return` 的瞬间栈帧弹出，那块内存立刻"归零待分配"，下一次函数调用就会覆写它。你返回的地址虽然还是个数字，但它对应的内容已经不属于你了——这叫悬空指针。本机实测直接 `Segmentation fault`（exit 139）。要返回就返回全局/static/堆上的地址，或者干脆返回值。

**Q3：void\* 指针有什么用？什么时候需要它？**
它是"擦掉类型标签的通用地址"。典型场景：`malloc` 返回 `void*`、C 风格 API 传用户数据（线程参数、回调 context）、实现通用容器。规则是"任何指针 → `void*` 免费，`void*` → 具体指针必须显式强转"（P34 三条规则）。日常业务代码里能用模板或明确类型就不要用 `void*`，因为它把编译期类型检查全丢了。

**Q4：nullptr 和 NULL 有什么区别？为什么要用 nullptr？**
`NULL` 是宏，展开成 `((void*)0)`，本质上仍可当整数 0 用；`nullptr` 是 C++11 关键字，类型为 `std::nullptr_t`，只能隐式转成指针。差别在重载场合最致命：本机实测 `f(NULL)` 在存在 `f(int)` 与 `f(void*)` 两个重载时报 `call of overloaded 'f(NULL)' is ambiguous`，而 `f(nullptr)` 干净地匹配 `f(void*)`。另外 `int x = NULL;` 能通过编译（脏），`int x = nullptr;` 直接报错（干净）。教材 P32 结论："以后指针初始化赋值就使用 nullptr。"

**Q5：指针常量和常量指针怎么区分？有没有好记的方法？**
有，两步：① 看 const 挨着谁——挨着变量名（在 `*` 右边）就是**指针常量**，锁指向；挨着类型名（在 `*` 左边）就是**常量指针**，锁值。② 用比喻锚定：指针常量 = "车位焊死、货物随便换"；常量指针 = "货箱贴封条、车随便开走"。终极检验法是直接在脑子里跑一遍 `p=&other` 和 `*p=5`，哪条报 `read-only` 就说明哪条被锁。

## §7.7 课件类型专项补充（提示词"C++ 指针专题补充"三条）

### 补充 1：指针大小与平台关系

```cpp
#include <iostream>
using namespace std;
int main() {
    int    i = 1; double d = 1; char c = 1; void* vp = nullptr;
    cout << sizeof(i) << " " << sizeof(d) << " " << sizeof(c) << endl;  // 数据大小各异
    cout << sizeof(&i) << " " << sizeof(&d) << " " << sizeof(&c) << " " << sizeof(vp) << endl;
    return 0;
}
// 输出：4 8 1
// 输出：8 8 8 8    ← 所有指针一律 8 字节（64 位平台）
```

| 平台 | 指针大小 | 可寻址空间上限 |
|------|---------|--------------|
| 32 位（x86） | 4 字节 | 4 GB |
| 64 位（x64，本机） | 8 字节 | 理论 16 EB |

推论：`int*`、`double*`、`char*`、`void*`、`Student*` 占的内存**完全一样**，区别只在于编译器"读几个字节、步长跳几步"。这也解释了为什么指针可以被安全地当成整数地址看待（但不能随意赋整数值）。

### 补充 2：指针与数组的关键差异实例（边界情况）

```cpp
#include <iostream>
using namespace std;
int main() {
    int arr[5] = {1,2,3,4,5};
    int  x = 9;
    int* p = arr;
    cout << "sizeof(arr)=" << sizeof(arr) << " sizeof(p)=" << sizeof(p) << endl;
    p = &x;                       // ✅ 合法：指针可换靶子
    cout << "*p=" << *p << endl;
    //arr = &x;                   // ❌ 编译错误：assignment of read-only variable 'arr'
    //arr++;                      // ❌ 编译错误：lvalue required as increment operand
    cout << "&arr[0]=" << &arr[0] << "  &p=" << &p << endl;  // 前者是首元素地址，后者是"指针自己的地址"(int**)
    return 0;
}
// 输出：sizeof(arr)=20 sizeof(p)=8
// 输出：*p=9
// 输出：&arr[0]=0x61fe20  &p=0x61fe18   （两个完全不同的格子）
```

四条不等价边界，背下来就能秒杀判断题：
1. `sizeof(arr)` ≠ `sizeof(p)`（20 vs 8）；
2. `arr = &x;` 编译失败，`p = &x;` 合法；
3. `arr++` 编译失败，`p++` 合法；
4. `&arr` 的类型是 `int(*)[5]`，`&p` 的类型是 `int**`——即使数值巧合相同，类型也不同。

### 补充 3：字符串字面量的存储位置（配内存分区图）

```cpp
#include <iostream>
using namespace std;
int main() {
    char*  p   = (char*)"hello";   // "hello" 在只读常量区
    char   arr[] = "hello";        // 内容复制一份到栈上
    arr[0] = 'H';                  // ✅ 改栈上副本
    cout << arr << endl;           // Hello
    //p[0] = 'H';                  // ⚠️ 取消注释 → 本机实测 Segmentation fault
    cout << p << endl;
    return 0;
}
// 输出：Hello
// 输出：hello
// 若放开 p[0]='H'; → 编译无错，运行时段错误（exit 139）
```

```

   ① 写 .rodata        → 段错误（§4.1）
```

`static` 局部变量为什么能安全返回？因为它不住在栈帧里，而在 `.data`/`.bss` 区，生命周期贯穿整个程序——这是 §3.3 方案 2 成立的底层原因。

## 13.2 详细版（语法 + 示例）

### A. 声明与初始化

```cpp
int   num = 100;              // 普通变量
int*  p   = &num;             // 一级指针：存 num 的地址
int** pp  = &p;               // 二级指针：存 p 的地址
int*** ppp= &pp;              // 三级指针（理论无上限，实践少过三级）
const int* pc  = &num;        // 常量指针：*pc 只读，pc 可换靶
int* const  cp = &num;        // 指针常量：*cp 可写，cp 不可换靶
const int* const ccp = &num;  // 双锁：全只读
void*  vp = &num;             // 万能指针：任何类型都能装
int*  np  = nullptr;          // 空指针（C++11 推荐）
int*  on  = NULL;             // 空指针（旧风格）
int&   r  = num;              // 引用（必须初始化，终身不换）
const int& cr = num;          // 常量引用（值只读）
```

### B. 运算符优先级与语义（本章高频混淆点）

| 表达式 | 等价于 | 含义 |
|--------|-------|------|
| `*p++` | `*(p++)` | 先取当前值，再移动指针 |
| `(*p)++` | — | p 不动，所指的值 +1 |
| `*++p` | `*(++p)` | 先移动，再取值（跳过首元素） |
| `++*p` | `++(*p)` | 所指的值 +1 |
| `*p + 1` | — | 所指的值 +1，指针不动 |
| `&*p` | — | 还原成 p 本身（先解引用再取地址） |
| `p[n]` | `*(p+n)` | 下标只是地址算术的糖 |

### C. 函数签名模板

```cpp
void   inputByValue(int v);            // 只读副本，改了没用
void   inputByPtr  (int* v);           // 可改外部变量，调用需 f(&x)
void   inputByRef  (int& v);           // 可改外部变量，调用直接 f(x)
void   readOnlyBig (const int* v);     // 承诺不改
void   outputParam (int* out);         // 结果写回（checkMax 模式）
int*   returnInputAddr(int* p);        // ✅ 安全：原样送回
int*   returnDanger();                 // ❌ 若内部 return &局部变量 即 UB
void   twoLevel(int** pp);             // 要改"指针本身"才用
```

### D. 遍历模板（三种数据结构同一套思路）

```cpp
// int 数组
int* p = arr;      for (int i=0;i<n;i++) use(*p++);
// 字符串
char* q = str;     while (*q != '\0') { use(*q); q++; }
// 二级指针数组
int** r = ptrArr;  for (int i=0;i<n;i++) use(**r), r++;
```

### E. 判空与安全习惯

```cpp
int* p = nullptr;                     // ① 生来就空
if (p != nullptr) { use(*p); }        // ② 用前必检
p = &something;                       // ③ 需要时再挂
// ... 用完 ...
p = nullptr;                          // ④ 用完置空
```

# §十四 易错点速查卡（四列：错误现象 → 错误原因 → 正确写法 → 后果）

| 13 | `const int* p; *p=5;` 编译失败 | 常量指针锁住了值 | 需要改写就用非 const 指针 | 编译错误 `read-only location '* p'` |
| 14 | `int* const p; p=&y;` 编译失败 | 指针常量锁住了指向 | 需要换靶子就用 `const int*` 或普通指针 | 编译错误 `read-only variable 'p'` |
| 15 | `f(NULL)` 报 ambiguous | NULL 本质是 0，整型/指针皆可 | 改 `f(nullptr)` | 编译错误 `call of overloaded is ambiguous` |
| 16 | `int& r;` 编译失败 | 引用必须初始化 | `int& r = x;` | 编译错误 `declared as reference but not initialized` |
| 17 | `int& r = 100;` 编译失败 | 非常量引用不能绑定右值 | `const int& r = 100;` | 编译错误 `cannot bind non-const lvalue reference` |

# §十六 随身速记口诀（3 条 + 1 条加分）

**口诀 1｜指针寻址三层楼**
> 一个星星一层楼，几个星星几层楼；
> 取地址用 &，进门取货用 \*；
> 指针加一不是加一字节，是跳一个元素宽。

**口诀 2｜const 挨谁锁谁**
> const 挨着变量名，指向焊死不换人；（`int* const p`）
> const 挨着类型名，货箱封条不许碰；（`const int* p`）
> 两头都有 const，纯纯只读一扇窗。（`const int* const p`）

**口诀 3｜危险四条命门线**
> 定义指针必初始化，不用就置 nullptr；
> 函数栈帧退出即销毁，永远不返栈上地址；
> 字符串常量贴封条，想改请抄一份到栈；
> 数组名是常量不是指针，能 ++ 的才叫指针。

**加分口诀｜引用从一而终**
> 引用是别名不是盒子，出生即绑、终身不换；
> 不能为空、不能取空、只能一级；
> 它的真身就是 `int* const`——换了马甲的指针常量。

```python
    candidates = [

        src / "指针学习笔记_v3.md",
```

## 代码审查题（做完 T1–T4 后再做）

下面这段代码包含 **6 个本章典型错误**，请逐一找出并改正（提示：涉及值传递、const、悬空指针、野指针、只读区、缺头文件）。

```cpp
#include <iostream>
using namespace std;

int* getMax(int* a, int* b) {
    int max;
    if (*a > *b) max = *a; else max = *b;
    return &max;
}
void swap2(int a, int b) {
    int t = a; a = b; b = t;
}
int main() {
    int x = 10, y = 20;
    int* p;
    *p = 5;
    swap2(x, y);
    int* m = getMax(&x, &y);
    const int* c = &x;
    *c = 99;
    char* s = "abc";
    s[0] = 'A';
    cout << x << y << *m << s << strlen(s) << endl;
    return 0;
}
```

批改要点（本机 g++ 8.1.0 `-Wall` 实测反馈）：
- `return &max;` → `warning: address of local variable 'max' returned`（陷阱 1）
- `*c = 99;` → `error: assignment of read-only location '* c'`（陷阱 3）
- `char* s = "abc";` → `warning: ISO C++ forbids converting a string constant to 'char*' [-Wwrite-strings]`，随后 `s[0]='A'` 运行时段错误（陷阱：改只读常量区）
- `int* p; *p = 5;` → 野指针，段错误（陷阱 2）
- `swap2(x,y)` → 值交换，无效（§3.1）
- `strlen` 未包含 `<cstring>` → 编译报错
