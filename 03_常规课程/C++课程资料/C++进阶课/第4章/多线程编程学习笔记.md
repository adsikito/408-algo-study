### 1.1 线程概念（P1-P3）【重点】

#### ① 是什么
线程（Thread）是操作系统进行**任务调度的最小单位**，也叫 LWP（Light Weight Process，轻量级进程）。进程是资源分配的基本单位，线程是 CPU 调度的基本单位。同一个进程中的多个线程**共享**该进程的所有资源（堆、全局变量、文件描述符等），但每个线程拥有独立的栈空间和程序计数器。

**生活比喻**：把进程想象成一个工厂，线程就是工厂里的工人。工厂（进程）拥有厂房、设备、原材料（内存、文件描述符等资源），工人（线程）共用这些资源干活。招一个新工人比建一个新工厂便宜得多（创建线程比创建进程开销小），但工人们共用设备时如果抢着操作同一台机器就会出事（竞态条件）。

#### ② 为什么
- **为什么需要线程？** 一个进程中可能同时有多个阻塞任务（如同时等待网络IO和用户输入），单线程只能串行等待，多线程可以并行执行不同任务，提高CPU利用率。
- **为什么不用多进程代替？** 进程间通信（管道/共享内存）开销大、切换成本高；线程共享地址空间，切换只需保存少量寄存器，通信直接读写共享变量即可。
- **为什么线程不安全？** 因为多个线程操作同一份数据没有天然的隔离机制，如果不加同步互斥保护，就会出现数据竞争（Race Condition），导致结果不可预测。

#### ③ 怎么用
```cpp
// 线程 vs 进程 四维对比表
// ┌─────────────┬──────────────────┬──────────────────┐
// │   对比维度   │      进程        │      线程         │
// ├─────────────┼──────────────────┼──────────────────┤
// │ 资源开销     │ 独立地址空间,开销大│ 共享进程资源,开销小│
// │ 通信方式     │ IPC(管道/共享内存) │ 直接读写共享变量  │
// │ 安全性       │ 天然隔离,较安全   │ 共享资源,需同步   │
// │ 切换成本     │ 切换页表,成本高   │ 仅切换寄存器,成本低│
// └─────────────┴──────────────────┴──────────────────┘
```

关键特性回顾：
- 每个进程至少有一个线程（主线程）
- 任一线程调用 `exit()` 或主线程结束，整个进程终止，所有线程随之结束
- 多线程执行顺序不确定，按时间片轮转 + 抢占式调度

> **人话总结**：线程是进程里的工人，共享资源干活快但容易抢。

### 1.2 pthread_create 创建线程（P3-P8）【重点】

#### ① 是什么
`pthread_create` 是 POSIX 线程库中创建新线程的核心函数。它会在当前进程中创建一个分支线程，该线程从指定的回调函数开始执行。

**生活比喻**：就像老板（主线程）给新员工（分支线程）安排一个工位和一份工作任务（回调函数），员工拿到任务就开始干活，老板可以继续做自己的事。

#### ② 为什么
C/C++ 标准库本身不提供线程操作（C++11之前），必须依赖第三方库。Linux 上使用 POSIX 线程库（pthread），这是事实上的工业标准。

#### ③ 怎么用

**函数签名**（man手册式）：
```c
#include <pthread.h>
int pthread_create(pthread_t *thread,           // [出] 线程ID
                   const pthread_attr_t *attr,   // 线程属性,NULL=默认
                   void *(*start_routine)(void*),// 线程体函数指针
                   void *arg);                   // 传给线程体的参数
// 返回值：成功返回0，失败返回错误码（非errno，是pthread库自定义错误码）
// 编译：g++ xxx.cpp -lpthread
```

**用法一：不传参**
```cpp
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

// 线程体函数：参数void*，返回值void*
void *task(void *arg) {
    while (1) {
        printf("我是分支线程\n");
        sleep(1);
    }
    return NULL; // 正常退出应返回NULL
}

int main() {
    pthread_t tid;
    if (pthread_create(&tid, NULL, task, NULL) != 0) {
        printf("线程创建失败\n");
        return -1;
    }
    printf("线程创建成功, tid = %#lx\n", tid);
    while (1) {
        printf("我是主线程\n");
        sleep(1);
    }
    return 0;
}
// 编译：g++ 01_basic.cpp -lpthread -o 01_basic
// 输出：交替打印"我是分支线程"和"我是主线程"
```

**逐行走读**：
- `pthread_t tid;` → 在栈上分配一个变量用于存储新线程的ID
- `pthread_create(&tid, NULL, task, NULL)` → 内核创建新线程，将ID写入tid，新线程立即开始执行task函数；主线程继续往下走
- `while(1)` → 主线程死循环防止退出（若主线程return，整个进程结束，分支线程也被杀死）

**用法二：传递单个数据**
```cpp
#include <stdio.h>
#include <pthread.h>

void *task(void *arg) {
    // arg指向main中的num变量，需要强制转换
    int key = *(int *)arg;
    printf("分支线程收到: num = %d\n", key);
    return NULL;
}

int main() {
    pthread_t tid;
    int num = 520;
    pthread_create(&tid, NULL, task, &num);
    printf("主线程: num = %d\n", num);
    num = 1314; // 危险！主线程修改了共享变量
    printf("主线程修改后: num = %d\n", num);
    while (1); // 防止主线程退出
    return 0;
}
// 输出：分支线程可能打印520也可能打印1314（取决于调度时序）
```

**用法三：传递多个数据（结构体）**
```cpp
#include <stdio.h>
#include <pthread.h>

struct Info {
    int num;
    char name[20];
    double score;
};

void *task(void *arg) {
    // 将void*转为结构体指针，再拷贝到局部变量（安全做法）
    Info buf = *((Info *)arg);
    printf("分支线程: num=%d, name=%s, score=%.2lf\n",
           buf.num, buf.name, buf.score);
    return NULL;
}

int main() {
    pthread_t tid;
    Info buf = {520, "zhangsan", 99.5};
    pthread_create(&tid, NULL, task, &buf);
    printf("主线程继续执行\n");
    while (1);
    return 0;
}
// 输出：分支线程: num=520, name=zhangsan, score=99.50
```

#### ④ 注意事项

**错误示范1：向线程传递局部变量地址后主线程立即修改**
```cpp
// ❌ 错误写法
int num = 520;
pthread_create(&tid, NULL, task, &num);
num = 1314; // 主线程立刻改了，子线程读到什么不确定
```
```cpp
// ✅ 正确写法：确保子线程读完后再改，或用堆内存
int *pnum = new int(520);
pthread_create(&tid, NULL, task, pnum);
// 子线程内部用完delete，或主线程join后再delete
```

**错误示范2：忘记检查返回值**
```cpp
// ❌ 不检查返回值
pthread_create(&tid, NULL, task, NULL); // 失败了也不知道
```
```cpp
// ✅ 始终检查
if (pthread_create(&tid, NULL, task, NULL) != 0) {
    perror("pthread_create failed");
    return -1;
}
```

> **人话总结**：建线程四参数，传参用结构体最稳。

### 1.3 pthread_self / pthread_exit / pthread_join / pthread_detach（P8-P10）【重点】

#### ① 是什么
- `pthread_self()`：获取当前线程的线程号
- `pthread_exit()`：主动退出当前线程
- `pthread_join()`：阻塞等待指定线程结束并回收其资源
- `pthread_detach()`：将线程设为分离态，退出后系统自动回收资源

**生活比喻**：
- `pthread_self` = 工人看自己的工牌
- `pthread_exit` = 工人干完活主动打卡下班
- `pthread_join` = 主管站在门口等工人交完报告才离开（阻塞回收）
- `pthread_detach` = 告诉人事"这个工人离职后不用管了，系统自动处理"（非阻塞）

#### ② 为什么
- 线程结束后其占用的栈空间等资源不会自动释放（类似进程僵尸态），必须有人回收
- `join` 类似进程的 `wait`，`detach` 类似把子进程变成孤儿进程由 init 回收
- 两者选其一：**不能对同一个线程既 join 又 detach**

#### ③ 怎么用

```c
#include <pthread.h>

// 获取自身线程号（不会失败）
pthread_t pthread_self(void);

// 退出当前线程
void pthread_exit(void *retval);  // retval一般填NULL

// 阻塞回收指定线程
int pthread_join(pthread_t thread, void **retval);
// 成功返回0，失败返回错误码

// 设置分离态
int pthread_detach(pthread_t thread);
// 成功返回0，失败返回错误码
```

**综合示例**（对应课件代码）：
```cpp
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <iostream>

void *task(void *arg) {
    printf("分支线程, tid = %#lx\n", pthread_self());
    sleep(3);
    pthread_exit(NULL); // 主动退出
}

int main() {
    pthread_t tid;
    if (pthread_create(&tid, NULL, task, NULL) != 0) {
        printf("创建失败\n");
        return -1;
    }
    printf("主线程, tid = %#lx\n", tid);

    // 方式A：阻塞回收（取消注释使用）
    // pthread_join(tid, NULL);

    // 方式B：分离态（非阻塞）
    pthread_detach(tid);

    sleep(5); // 给分离态线程时间运行
    std::cout << "主线程结束" << std::endl;
    return 0;
}
// 输出：
// 主线程, tid = 0x7f...
// 分支线程, tid = 0x7f...
// （3秒后分支线程退出，5秒后主线程结束）
```

**逐行走读**：
1. `pthread_create` 创建分支线程，分支线程开始执行 `task`
2. 主线程打印自己的 tid
3. `pthread_detach(tid)` 将分支线程设为分离态，此后主线程不需要也不可以再 join 它
4. `sleep(5)` 让主线程存活足够久，使分支线程有机会完成执行
5. 分支线程 `sleep(3)` 后调用 `pthread_exit(NULL)` 退出，系统自动回收其资源

#### ④ 注意事项

**错误示范：对已 detach 的线程调用 join**
```cpp
// ❌ 未定义行为
pthread_detach(tid);
pthread_join(tid, NULL); // 对一个分离态线程join，结果不可预测
```

**错误示范：线程体函数中没有返回值**
```cpp
// ❌ 忘记return
void *task(void *arg) {
    printf("hello\n");
    // 缺少 return NULL; → 未定义行为
}
```
```cpp
// ✅ 始终返回
void *task(void *arg) {
    printf("hello\n");
    return NULL;
}
```

> **人话总结**：join阻塞等回收，detach放手系统收。

### 1.4 多线程文件拷贝练习（P10）【熟悉】

#### ① 是什么
利用两个线程分别拷贝文件的前半部分和后半部分，主线程负责创建目标文件和回收子线程资源。这是多线程协作的典型应用场景。

**生活比喻**：搬家时两个人各搬一半家具，一个人搬客厅的、一个人搬卧室的，比一个人全搬快一倍。

#### ② 为什么
大文件IO是典型的耗时操作，将文件分成两段让两个线程并行读写，理论上可以将拷贝时间缩短近一半（受磁盘IO瓶颈限制）。

#### ③ 怎么用（基于课件 09test.cpp / 07test.cpp 走读）

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <pthread.h>

// 传递拷贝信息的结构体
struct CopyInfo {
    const char *srcfile;   // 源文件路径
    const char *destfile;  // 目标文件路径
    int start;             // 起始偏移
    int len;               // 要拷贝的字节数
};

// 获取文件长度并创建目标文件
int get_file_len(const char *src, const char *dst) {
    int sfd = open(src, O_RDONLY);
    if (sfd == -1) { perror("open src"); return -1; }
    int dfd = open(dst, O_RDWR | O_CREAT | O_TRUNC, 0664);
    if (dfd == -1) { perror("open dst"); close(sfd); return -1; }
    int len = lseek(sfd, 0, SEEK_END);
    close(sfd);
    close(dfd);
    return len;
}

// 线程体：拷贝指定范围的文件内容
void *copy_task(void *arg) {
    struct CopyInfo *info = (struct CopyInfo *)arg;
    int sfd = open(info->srcfile, O_RDONLY);
    int dfd = open(info->destfile, O_RDWR);
    if (sfd == -1 || dfd == -1) { perror("open"); return NULL; }

    lseek(sfd, info->start, SEEK_SET);
    lseek(dfd, info->start, SEEK_SET);

    char buf[128];
    int total = 0, ret;
    while ((ret = read(sfd, buf, sizeof(buf))) > 0) {
        total += ret;
        if (total >= info->len) {
            // 最后一次只写需要的字节数
            write(dfd, buf, ret - (total - info->len));
            break;
        }
        write(dfd, buf, ret);
    }
    close(sfd);
    close(dfd);
    return NULL;
}

int main(int argc, char *argv[]) {
    if (argc != 3) {
        printf("用法: ./a.out 源文件 目标文件\n");
        return -1;
    }
    int len = get_file_len(argv[1], argv[2]);
    if (len <= 0) return -1;

    struct CopyInfo infos[2] = {
        {argv[1], argv[2], 0, len / 2},
        {argv[1], argv[2], len / 2, len - len / 2}
    };

    pthread_t tid1, tid2;
    pthread_create(&tid1, NULL, copy_task, &infos[0]);
    pthread_create(&tid2, NULL, copy_task, &infos[1]);

    pthread_join(tid1, NULL);
    pthread_join(tid2, NULL);
    printf("拷贝成功\n");
    return 0;
}
// 编译：g++ copy.cpp -lpthread -o copy
// 运行：./copy source.txt dest.txt
// 输出：拷贝成功
```

**逐行走读关键点**：
- `lseek(sfd, info->start, SEEK_SET)` → 每个线程将自己的文件指针偏移到负责的区段起点
- `write(dfd, buf, ret - (total - info->len))` → 最后一块可能超出负责范围，只写多余之前的部分
- 两个线程各自打开独立的文件描述符，互不影响（文件描述符是进程级资源，但每个open返回独立的fd）

#### ④ 注意事项
- 注意课件中 06test1.cpp 有个 bug：`info[2]` 初始化时用了 `argv[0]`（程序名）而非 `argv[1]`（源文件），07test.cpp 已修正
- 两个线程写同一个文件的不同区域，因为各自lseek到不同位置且写入范围不重叠，所以无需加锁
- 如果文件很小（<128字节），分两段反而增加开销

> **人话总结**：分段拷贝各干各，join等齐才算完。

### 1.5 互斥锁 mutex（P10-P13）【重点】

#### ① 是什么
互斥锁（Mutex，Mutual Exclusion）是一种同步原语，保证**同一时刻只有一个线程**持有该锁。其他试图获取该锁的线程会**阻塞等待**，直到锁被释放。

**生活比喻**：厕所门上的锁。进去的人锁上门（lock），外面的人只能排队等（阻塞）；里面的人出来开锁（unlock），下一个人才可以进去。

#### ② 为什么
- **临界资源**：多个线程共享的资源（如全局变量、文件等）
- **临界区**：访问临界资源的代码段
- **竞态条件（Race Condition）**：多个线程同时进入临界区，导致数据不一致
- 互斥锁确保临界区同一时刻只有一个线程在执行，从而消除竞态

#### ③ 怎么用

**API全家桶**（头文件 `<pthread.h>`）：
```c
// 1. 定义互斥锁
pthread_mutex_t mutex;

// 2. 初始化（二选一）
pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;          // 静态初始化
int pthread_mutex_init(pthread_mutex_t *mutex,              // 动态初始化
                       const pthread_mutexattr_t *attr);    // NULL=默认属性

// 3. 加锁（阻塞直到获得锁）
int pthread_mutex_lock(pthread_mutex_t *mutex);

// 4. 解锁
int pthread_mutex_unlock(pthread_mutex_t *mutex);

// 5. 销毁
int pthread_mutex_destroy(pthread_mutex_t *mutex);
```

**ASCII 时序图：互斥锁工作原理**
```
线程1                        互斥锁                         线程2
  |                            |                              |
  |-- lock(&mutex) ----------->|                              |
  |   (获得锁, mutex=LOCKED)    |                              |
  |   操作临界资源...           |                              |
  |                            |<----------- lock(&mutex) ----|
  |                            |   (mutex已锁定, 线程2阻塞)    |
  |-- unlock(&mutex) --------->|                              |
  |   (mutex=UNLOCKED)         |                              |
  |                            |-------------(唤醒)---------->|
  |                            |   (线程2获得锁)               |
  |                            |   操作临界资源...             |
  |                            |<----------- unlock(&mutex) --|
```

**完整示例**（对应 02mutex.cpp）：
```cpp
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

pthread_mutex_t mutex;     // 定义互斥锁
int num = 520;             // 临界资源（全局共享变量）

void *task1(void *arg) {
    while (1) {
        sleep(1);
        pthread_mutex_lock(&mutex);   // 加锁
        num -= 10;                     // 安全地修改临界资源
        printf("张三取了10，剩余%d\n", num);
        pthread_mutex_unlock(&mutex); // 解锁
    }
    return NULL;
}

void *task2(void *arg) {
    while (1) {
        sleep(1);
        pthread_mutex_lock(&mutex);   // 加锁
        num -= 20;
        printf("李四取了20，剩余%d\n", num);
        pthread_mutex_unlock(&mutex); // 解锁
    }
    return NULL;
}

int main() {
    pthread_mutex_init(&mutex, NULL); // 初始化互斥锁

    pthread_t tid1, tid2;
    pthread_create(&tid1, NULL, task1, NULL);
    pthread_create(&tid2, NULL, task2, NULL);

    pthread_join(tid1, NULL);
    pthread_join(tid2, NULL);

    pthread_mutex_destroy(&mutex);    // 销毁互斥锁
    return 0;
}
// 编译：g++ mutex_demo.cpp -lpthread
// 输出：张三和李四交替取钱，num的值始终一致不会出现脏读
```

**逐行走读**：
1. `pthread_mutex_init(&mutex, NULL)` → 在主线程中初始化锁，此时锁处于 UNLOCKED 状态
2. 两个分支线程启动后各自尝试 `lock`
3. 假设线程1先拿到锁 → 线程1执行 `num -= 10` 和 `printf`，期间线程2在 `lock` 处阻塞
4. 线程1 `unlock` → 内核唤醒线程2，线程2获得锁继续执行
5. 如此交替，保证每次只有一个线程在修改 `num`

#### ④ 注意事项

**错误示范：忘记unlock导致死锁**
```cpp
// ❌ 中间return导致unlock永远不执行
void *task(void *arg) {
    pthread_mutex_lock(&mutex);
    if (some_error) {
        return NULL; // 锁没释放！其他线程永久阻塞
    }
    pthread_mutex_unlock(&mutex);
    return NULL;
}
```
```cpp
// ✅ 每个出口都要unlock
void *task(void *arg) {
    pthread_mutex_lock(&mutex);
    if (some_error) {
        pthread_mutex_unlock(&mutex); // 先解锁再返回
        return NULL;
    }
    pthread_mutex_unlock(&mutex);
    return NULL;
}
```

**错误示范：重复加锁（同一线程）**
```cpp
// ❌ 普通互斥锁不支持递归加锁 → 死锁
pthread_mutex_lock(&mutex);
pthread_mutex_lock(&mutex); // 自己锁自己，永久阻塞
```

> **人话总结**：lock进unlock出，忘了unlock全堵死。

### 1.6 无名信号量 sem（P13-P16）【重点】

#### ① 是什么
无名信号量（Unnamed Semaphore）是一个内部维护整数 value 的同步原语。`sem_wait`（P操作）将 value 减 1，若 value < 0 则阻塞；`sem_post`（V操作）将 value 加 1，若有线程阻塞则唤醒一个。

**生活比喻**：停车场的车位计数器。入口处的显示屏显示剩余车位（value）。来一辆车就减1（wait），如果显示0就在入口排队等（阻塞）；出去一辆车就加1（post），排队的车就可以进来了。

#### ② 为什么
- 互斥锁只能实现"互斥"（同一时刻一个线程访问），无法控制执行顺序
- 信号量可以实现"同步"（线程A必须先完成某步，线程B才能继续）
- 生产者消费者模型的经典解决方案：生产者 post 通知有数据，消费者 wait 等待数据

#### ③ 怎么用

**API全家桶**（头文件 `<semaphore.h>`）：
```c
#include <semaphore.h>

// 1. 定义
sem_t sem;

// 2. 初始化
int sem_init(sem_t *sem, int pshared, unsigned int value);
// pshared=0: 线程间同步; 非0: 进程间同步(需放在共享内存)
// value: 初始值

// 3. P操作（申请资源，value-1，value<0则阻塞）
int sem_wait(sem_t *sem);

// 4. V操作（释放资源，value+1，唤醒阻塞线程）
int sem_post(sem_t *sem);

// 5. 销毁
int sem_destroy(sem_t *sem);
```

**ASCII 时序图：生产者消费者模型**
```
生产者线程                    信号量(value)                  消费者线程
    |                            |                              |
    |  生产一个产品               |                              |
    |-- sem_post(&sem) --------->| value: 0→1                   |
    |                            |                              |
    |                            |<--------- sem_wait(&sem) ----|
    |                            | value: 1→0, 消费者获得资源    |
    |                            |   消费产品                    |
    |  再生产一个                 |                              |
    |-- sem_post(&sem) --------->| value: 0→1                   |
    |                            |                              |
    |                            |<--------- sem_wait(&sem) ----|
    |                            | value: 1→0                   |
    |                            |   消费产品                    |
```

**生产者消费者示例**（对应 03sem.cpp）：
```cpp
#include <stdio.h>
#include <pthread.h>
#include <semaphore.h>
#include <unistd.h>

sem_t sem; // 定义无名信号量

// 生产者线程
void *producer(void *arg) {
    for (int i = 0; i < 5; i++) {
        sleep(1);
        printf("我生产了一辆特斯拉\n");
        sem_post(&sem);  // V操作：通知消费者有货了
    }
    return NULL;
}

// 消费者线程
void *consumer(void *arg) {
    for (int i = 0; i < 5; i++) {
        sem_wait(&sem);  // P操作：没货就阻塞等待
        printf("我消费了一辆特斯拉，很开心\n");
    }
    return NULL;
}

int main() {
    sem_init(&sem, 0, 0); // 初始值为0，消费者一开始就阻塞

    pthread_t tid1, tid2;
    pthread_create(&tid1, NULL, producer, NULL);
    pthread_create(&tid2, NULL, consumer, NULL);

    pthread_join(tid1, NULL);
    pthread_join(tid2, NULL);

    sem_destroy(&sem);
    return 0;
}
// 编译：g++ sem_demo.cpp -lpthread
// 输出：生产和消费交替出现，严格一对一
```

**ABC顺序打印练习**（对应 10test.cpp）：
```cpp
#include <stdio.h>
#include <pthread.h>
#include <semaphore.h>
#include <unistd.h>

sem_t sem1, sem2, sem3;

void *printA(void *arg) {
    while (1) {
        sem_wait(&sem1);   // 等sem1有资源才能打印A
        usleep(100000);
        printf("A");
        fflush(stdout);
        sem_post(&sem2);   // 打印完A，给B发通行证
    }
    return NULL;
}

void *printB(void *arg) {
    while (1) {
        sem_wait(&sem2);   // 等sem2
        usleep(100000);
        printf("B");
        fflush(stdout);
        sem_post(&sem3);   // 给C发通行证
    }
    return NULL;
}

void *printC(void *arg) {
    while (1) {
        sem_wait(&sem3);   // 等sem3
        usleep(100000);
        printf("C");
        fflush(stdout);
        sem_post(&sem1);   // 给A发通行证，形成循环
    }
    return NULL;
}

int main() {
    sem_init(&sem1, 0, 1); // sem1初始为1，A可以先执行
    sem_init(&sem2, 0, 0); // B、C初始阻塞
    sem_init(&sem3, 0, 0);

    pthread_t tid1, tid2, tid3;
    pthread_create(&tid1, NULL, printA, NULL);
    pthread_create(&tid2, NULL, printB, NULL);
    pthread_create(&tid3, NULL, printC, NULL);

    pthread_join(tid1, NULL);
    pthread_join(tid2, NULL);
    pthread_join(tid3, NULL);

    sem_destroy(&sem1);
    sem_destroy(&sem2);
    sem_destroy(&sem3);
    return 0;
}
// 编译：g++ abc.cpp -lpthread
// 输出：ABCABCABCABC...（严格按序循环打印）
```

**执行流程解析**：
1. sem1=1, sem2=0, sem3=0 → A的wait通过，B和C阻塞
2. A打印"A"，post sem2 → sem2=1，B被唤醒
3. B打印"B"，post sem3 → sem3=1，C被唤醒
4. C打印"C"，post sem1 → sem1=1，A被唤醒
5. 循环往复...

#### ④ 注意事项

**错误示范：信号量初始值设错导致顺序混乱**
```cpp
// ❌ 三个都初始化为0 → 所有线程都阻塞，死锁
sem_init(&sem1, 0, 0);
sem_init(&sem2, 0, 0);
sem_init(&sem3, 0, 0);
```
```cpp
// ✅ 必须有且仅有一个初始值为1作为启动令牌
sem_init(&sem1, 0, 1);
sem_init(&sem2, 0, 0);
sem_init(&sem3, 0, 0);
```

**注意**：课件 08test.cpp 中的 ABC 打印使用了不同的信号量链接顺序（sem3→sem1→sem2→sem3），原理相同只是起始点不同，sem3初始为1。

> **人话总结**：wait减一post加一，零就阻塞正就走。

### 1.7 条件变量 cond（P16-P18）【重点】

#### ① 是什么
条件变量（Condition Variable）是一种同步机制，它维护一个等待队列。消费者线程调用 `wait` 进入队列休眠，生产者线程调用 `signal/broadcast` 唤醒队列中的线程。**条件变量必须配合互斥锁使用**。

**生活比喻**：餐厅的叫号系统。顾客（消费者）取号后坐在等候区（等待队列）等着叫号；厨房做好菜后（生产者），服务员喊号（signal）叫一位顾客取餐，或者大喊"所有人的菜都好了"（broadcast）。等候区的座位是有限的，进场时要排队（互斥锁保护入队过程）。

#### ② 为什么
- 信号量虽然能实现同步，但它不区分"有没有数据"的条件判断
- 条件变量的核心优势：**wait 会自动释放锁再阻塞，被唤醒后自动重新获得锁**，避免了手动 unlock/relock 的复杂性和竞态窗口
- 适合"等待某个条件成立"的场景，如缓冲区非空、任务完成等

#### ③ 怎么用

**API全家桶**（头文件 `<pthread.h>`）：
```c
// 1. 定义
pthread_cond_t cond;

// 2. 初始化（二选一）
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;           // 静态初始化
int pthread_cond_init(pthread_cond_t *cond,               // 动态初始化
                      const pthread_condattr_t *attr);     // NULL=默认

// 3. 消费者进入等待队列（自动释放mutex，唤醒后自动重新加锁）
int pthread_cond_wait(pthread_cond_t *cond,
                      pthread_mutex_t *mutex);

// 4. 唤醒
int pthread_cond_signal(pthread_cond_t *cond);     // 唤醒一个
int pthread_cond_broadcast(pthread_cond_t *cond);  // 唤醒全部

// 5. 销毁
int pthread_cond_destroy(pthread_cond_t *cond);
```

**ASCII 时序图：条件变量工作流程**
```
消费者线程                  条件变量+互斥锁                生产者线程
    |                            |                              |
    |-- lock(&mutex) ----------->|                              |
    |-- cond_wait(&cond,&mutex)->|                              |
    |   (自动unlock mutex)       |                              |
    |   (进入等待队列,阻塞)       |                              |
    |                            |                              |
    |                            |   生产数据                    |
    |                            |<-- cond_signal(&cond) -------|
    |                            |   (唤醒队列第一个)            |
    |<-----(被唤醒)--------------|                              |
    |   (自动re-lock mutex)      |                              |
    |   消费数据                  |                              |
    |-- unlock(&mutex) --------->|                              |
```

**完整示例**（对应 04cond.cpp）：
```cpp
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

pthread_cond_t cond;    // 条件变量
pthread_mutex_t mutex;  // 配套互斥锁

// 生产者线程
void *producer(void *arg) {
    sleep(3);
    printf("我生产了3辆特斯拉\n");
    pthread_cond_broadcast(&cond); // 唤醒所有消费者
    return NULL;
}

// 消费者线程
void *consumer(void *arg) {
    pthread_mutex_lock(&mutex);            // 先加锁
    pthread_cond_wait(&cond, &mutex);      // 进入等待（自动释放锁）
    printf("%#lx: 消费了一辆特斯拉\n", pthread_self());
    pthread_mutex_unlock(&mutex);          // 解锁
    return NULL;
}

int main() {
    pthread_cond_init(&cond, NULL);
    pthread_mutex_init(&mutex, NULL);

    pthread_t tid1, tid2, tid3, tid4;
    pthread_create(&tid1, NULL, producer, NULL);
    pthread_create(&tid2, NULL, consumer, NULL);
    pthread_create(&tid3, NULL, consumer, NULL);
    pthread_create(&tid4, NULL, consumer, NULL);

    pthread_join(tid1, NULL);
    pthread_join(tid2, NULL);
    pthread_join(tid3, NULL);
    pthread_join(tid4, NULL);

    pthread_cond_destroy(&cond);
    pthread_mutex_destroy(&mutex);
    return 0;
}
// 编译：g++ cond_demo.cpp -lpthread
// 输出：3秒后生产者打印，然后3个消费者都被唤醒各自打印
```

**课件中被注释的代码段说明**（04cond.cpp 第11-21行）：
```cpp
/*
int num = 3;
while(num--)
{
    sleep(1);
    printf("%#x:生产了一辆特斯拉\n", pthread_self());
    pthread_cond_signal(&cond);  // 每生产一辆就唤醒一个消费者
}
*/
```
- **演示目的**：展示 signal 逐个唤醒消费者的模式（与 broadcast 一次唤醒全部对比）
- **预期输出**：每隔1秒唤醒一个消费者，共3次
- **被注释原因**：为了切换到 broadcast 演示模式，避免两种模式同时存在造成混淆

#### ④ 注意事项

**条件变量 vs 信号量对比表**：
```
┌──────────────┬──────────────────────┬──────────────────────┐
│   对比维度    │     条件变量          │     无名信号量        │
├──────────────┼──────────────────────┼──────────────────────┤
│ 是否需要配锁  │ 必须配合mutex        │ 不需要               │
│ 唤醒方式      │ signal/broadcast     │ post                 │
│ 条件判断      │ 支持任意条件          │ 仅基于计数           │
│ 虚假唤醒      │ 可能发生,需while检查  │ 不会                 │
│ 适用场景      │ 复杂条件等待          │ 简单计数同步         │
└──────────────┴──────────────────────┴──────────────────────┘
```

**错误示范：wait 不带 mutex**
```cpp
// ❌ 第二个参数传NULL → 未定义行为
pthread_cond_wait(&cond, NULL);
```
```cpp
// ✅ 必须传入已lock的mutex
pthread_mutex_lock(&mutex);
pthread_cond_wait(&cond, &mutex); // 内部自动unlock再阻塞
pthread_mutex_unlock(&mutex);
```

**错误示范：不使用 while 循环检查条件**
```cpp
// ❌ 虚假唤醒可能导致在没有数据时继续执行
pthread_mutex_lock(&mutex);
pthread_cond_wait(&cond, &mutex); // 可能被虚假唤醒
process_data(); // 数据可能还没准备好
pthread_mutex_unlock(&mutex);
```
```cpp
// ✅ 用while循环反复检查条件
pthread_mutex_lock(&mutex);
while (!data_ready) {
    pthread_cond_wait(&cond, &mutex);
}
process_data();
pthread_mutex_unlock(&mutex);
```

> **人话总结**：wait带锁进队列，signal叫人起来干。

### 1.8 C++11 std::thread（P18-P20）【熟悉】

#### ① 是什么
C++11 引入了 `<thread>` 头文件，提供面向对象的线程管理。`std::thread` 在构造时即创建并启动线程，支持普通函数、成员函数、Lambda、仿函数作为线程体，且可直接传参无需打包成结构体。

**生活比喻**：pthread 像是手动挡汽车，功能强大但操作繁琐；std::thread 像是自动挡，同样的事情写法更简洁、更安全。

#### ② 为什么
- pthread API 是 C 语言风格，不够 C++ 化
- 传参需要用 void* 强转，类型不安全
- C++11 线程库封装了底层实现（Linux 上仍然基于 pthread），提供了 RAII、类型安全等现代特性

#### ③ 怎么用

```cpp
#include <thread>
#include <iostream>
#include <string>
using namespace std;

// 1. 普通函数作线程体（无参）
void fun1() {
    cout << "fun1 tid=" << this_thread::get_id() << endl;
}

// 2. 带参数的函数
void fun2(int num, string str) {
    cout << "num=" << num << " str=" << str << endl;
}

// 3. 类成员函数作线程体
class MyClass {
public:
    string name;
    int age;
    void memberFun() {
        cout << "name=" << name << " age=" << age << endl;
    }
};

int main() {
    // 创建方式1：普通函数
    thread th1(fun1);

    // 创建方式2：带参函数（直接传参，无需结构体！）
    thread th2(fun2, 520, "hello");

    // 创建方式3：成员函数
    MyClass obj;
    obj.name = "zhangsan";
    obj.age = 18;
    thread th3(&MyClass::memberFun, &obj);

    // 创建方式4：Lambda表达式
    thread th4([](int key) {
        cout << "lambda key=" << key << endl;
    }, 999);

    // 回收
    th1.join();
    th2.join();
    th3.join();
    th4.join();

    return 0;
}
// 编译：g++ -std=c++11 thread_demo.cpp -lpthread
// 输出：四个线程各自打印信息
```

**常用辅助函数**：
```cpp
this_thread::get_id();              // 获取当前线程ID
this_thread::sleep_for(1s);         // C++14字面量写法
this_thread::sleep_for(chrono::seconds(1)); // C++11写法
```

**join vs detach**（对应 thread_test/01test.cpp）：
```cpp
thread th(ThreadMain);
th.join();   // 阻塞等待子线程结束
// 或
th.detach(); // 分离态，子线程独立运行
```

#### ④ 注意事项

**错误示范：创建了thread对象但不join也不detach**
```cpp
// ❌ 析构时如果线程仍joinable，程序terminate
{
    thread th(fun1);
    // 离开作用域，th析构 → std::terminate()!
}
```
```cpp
// ✅ 必须在析构前选择join或detach
{
    thread th(fun1);
    th.join(); // 或 th.detach();
}
```

> **人话总结**：构造即启动，传参不用包，join/detach必选一个。

### 1.9 C++11 std::mutex（P20-P21）【熟悉】

#### ① 是什么
`std::mutex` 是 C++11 提供的互斥锁类，对应 pthread 的 `pthread_mutex_t`。通过 `lock()/unlock()` 成员函数进行加锁和解锁。

**生活比喻**：和 pthread 互斥锁一样是厕所门锁，只是换成了智能门锁（面向对象封装），用起来更符合 C++ 习惯。

#### ② 为什么
与 pthread_mutex 功能完全等价，但提供了 C++ 风格的接口，并且可以配合 `std::lock_guard` / `std::unique_lock` 实现 RAII 自动加解锁，避免忘记 unlock。

#### ③ 怎么用

```cpp
#include <mutex>
#include <thread>
#include <iostream>
using namespace std;

mutex mux; // 实例化互斥锁对象

void task() {
    mux.lock();   // 加锁
    cout << "======================" << endl;
    cout << "tid=" << this_thread::get_id() << endl;
    this_thread::sleep_for(1s);
    cout << "**********************" << endl;
    mux.unlock(); // 解锁
}

int main() {
    for (int i = 0; i < 10; i++) {
        thread th(task);
        th.detach();
    }
    this_thread::sleep_for(20s);
    return 0;
}
// 输出：每次只有一个线程在打印分隔线之间的内容，不会交错
```

**RAII推荐写法**（补充，课件未涉及但面试高频）：
```cpp
#include <mutex>
mutex mux;

void safeTask() {
    lock_guard<mutex> guard(mux); // 构造时自动lock
    // 操作临界资源...
    // 离开作用域时guard析构，自动unlock
}
```

#### ④ 注意事项

**错误示范：lock后异常抛出导致unlock不执行**
```cpp
// ❌ 如果doSomething抛异常，unlock永远不会执行
mux.lock();
doSomething(); // 可能抛异常
mux.unlock();
```
```cpp
// ✅ 使用lock_guard保证异常安全
{
    lock_guard<mutex> guard(mux);
    doSomething(); // 即使抛异常，guard析构也会unlock
}
```

> **人话总结**：C++版互斥锁，推荐lock_guard防忘解锁。

### 1.10 C++11 condition_variable（P21-P22）【熟悉】

#### ① 是什么
`std::condition_variable` 是 C++11 的条件变量类，对应 pthread 的 `pthread_cond_t`。使用 `wait(unique_lock)` 等待，`notify_one()/notify_all()` 唤醒。

**生活比喻**：和 pthread 条件变量一样是餐厅叫号系统，只是换了套现代化的呼叫设备。

#### ② 为什么
与 pthread_cond 功能等价，但与 `std::unique_lock` 配合使用，类型更安全，语法更简洁。

#### ③ 怎么用

```cpp
#include <condition_variable>
#include <thread>
#include <mutex>
#include <iostream>
#include <list>
#include <sstream>
using namespace std;

list<string> msgs;        // 消息队列
mutex mux;                // 互斥锁
condition_variable cv;    // 条件变量

// 生产者
void writer() {
    for (int i = 0; i < 5; i++) {
        this_thread::sleep_for(2s);
        stringstream ss;
        ss << "消息" << i;

        unique_lock<mutex> lock(mux);
        msgs.push_back(ss.str());
        lock.unlock();

        cv.notify_one(); // 唤醒一个消费者
        cout << "生产了" << ss.str() << endl;
    }
}

// 消费者
void reader(int id) {
    unique_lock<mutex> lock(mux);
    cv.wait(lock); // 等待唤醒

    if (msgs.empty()) return;
    while (!msgs.empty()) {
        cout << "消费者" << id << "读取: " << msgs.front() << endl;
        msgs.pop_front();
    }
}

int main() {
    thread w(writer);
    thread r1(reader, 1);
    thread r2(reader, 2);
    thread r3(reader, 3);

    w.join();
    r1.join();
    r2.join();
    r3.join();
    return 0;
}
// 编译：g++ -std=c++11 cv_demo.cpp -lpthread
// 输出：生产者每2秒产一条消息，消费者被唤醒后消费
```

**注意**：`cv.wait(lock)` 要求 lock 的类型必须是 `unique_lock<mutex>`，不能用 `lock_guard`（因为 wait 内部需要 unlock/relock，而 lock_guard 不支持手动 unlock）。


- 纯 Linux 系统编程 / 需要精细控制 → pthread

- 两者可混用（C++11 线程库在 Linux 上底层就是 pthread）

> **人话总结**：C++11条件变量，wait配unique_lock，notify叫人起床。

## 五、易错点速查卡

| 错误现象 | 错误原因 | 正确写法 | 后果 |
|---------|---------|---------|------|
| 子线程读到错误数据 | 传局部变量地址后主线程立即修改 | 传堆内存或确保子线程读完再改 | 数据竞争，结果不确定 |
| 程序卡死不输出 | lock后中间return/异常导致unlock不执行 | 每个lock配对unlock，或用lock_guard | 死锁，所有等锁线程永久阻塞 |
| 崩溃/未定义行为 | pthread_cond_wait第二个参数传NULL | 必须传已lock的mutex | 段错误或数据损坏 |
| std::terminate | thread对象析构时仍joinable | 析构前必须join或detach | 程序异常终止 |
| ABC打印全阻塞 | 三个信号量全初始化为0 | 有且仅有一个初始化为1 | 死锁 |
| 编译undefined reference | 忘记链接pthread库 | g++加-lpthread或-pthread | 链接错误 |
| 消费者虚假唤醒后操作空数据 | if判断条件而非while | while(!ready) cond_wait(...) | 逻辑错误 |
| 对detach的线程join | 同一线程既detach又join | 二者只选其一 | 未定义行为 |

## 六、常见陷阱专题

### 陷阱1：向线程传局部变量地址导致数据竞争

**错误写法**：
```cpp
int localVar = 100;
pthread_create(&tid, NULL, task, &localVar);
localVar = 200; // 主线程立刻修改，子线程可能读到200
```
**问题**：子线程和主线程共享同一块内存，主线程修改后子线程看到的值不确定。

**正确写法**：
```cpp
int *pData = new int(100);
pthread_create(&tid, NULL, task, pData);
// 子线程内部: int val = *(int*)arg; delete (int*)arg;
```

**记忆口诀**："线程吃指针，主人别改菜"

---

### 陷阱2：互斥锁忘记unlock导致死锁

**错误写法**：
```cpp
pthread_mutex_lock(&mutex);
if (error) {
    return NULL; // 锁没释放！
}
doWork();
pthread_mutex_unlock(&mutex);
```
**问题**：error为真时直接return，unlock永远不会执行，其他线程永久阻塞。

**正确写法**：
```cpp
// 方案A：每个出口都unlock
pthread_mutex_lock(&mutex);
if (error) {
    pthread_mutex_unlock(&mutex);
    return NULL;
}
doWork();
pthread_mutex_unlock(&mutex);

// 方案B（推荐）：RAII
{
    std::lock_guard<std::mutex> guard(mux);
    if (error) return; // guard析构自动unlock
    doWork();
}
```

**记忆口诀**："上锁必解锁，否则全堵死"

---

### 陷阱3：条件变量wait不带mutex导致未定义行为

**错误写法**：
```cpp
pthread_cond_wait(&cond, NULL); // 第二个参数传NULL
```
**问题**：wait内部需要先unlock mutex再阻塞，传NULL会导致段错误或数据损坏。

**正确写法**：
```cpp
pthread_mutex_lock(&mutex);
while (!condition_met) {
    pthread_cond_wait(&cond, &mutex); // 自动unlock→阻塞→relock
}
// 使用共享数据...
pthread_mutex_unlock(&mutex);
```

**记忆口诀**："wait要带锁，进门先脱鞋"

## 七、新手最常问的5个问题

**Q1：线程和进程到底有什么区别？什么时候用线程，什么时候用进程？**
A：进程是资源分配单位，线程是调度单位。需要隔离和安全用进程（如浏览器多进程架构）；需要高效共享数据和低延迟通信用线程（如服务器并发处理请求）。记住：线程快但险，进程慢但稳。

**Q2：pthread_create的第四个参数为什么是void*？能不能直接传int？**
A：不能。pthread API是C语言接口，统一用void*作为通用指针。传int需要先取地址或转成指针（不推荐），最佳实践是传结构体指针。C++11的std::thread可以直接传任意类型参数。

**Q3：互斥锁和信号量有什么区别？能用信号量代替互斥锁吗？**
A：互斥锁只有两种状态（锁/未锁），强调"互斥"；信号量有计数值，强调"同步"。可以用初始值为1的信号量模拟互斥锁，但互斥锁有所有权概念（谁加锁谁解锁），信号量没有，因此互斥锁更安全、更高效。

**Q4：为什么条件变量必须配合互斥锁使用？**
A：因为多个消费者线程同时调用wait进入等待队列的过程本身就是临界区，如果不加锁，两个线程可能同时修改等待队列导致数据损坏。wait内部会自动unlock再阻塞、唤醒后自动relock，简化了编程。

**Q5：detach后的线程还能获取它的返回值吗？**
A：不能。detach意味着放弃对该线程的一切管理权，线程退出后资源由系统自动回收，无法再通过join获取返回值。如果需要返回值，必须用join。

## 附录：死锁的四个必要条件及预防策略（面试高频）

**四个必要条件**（缺一不可才会死锁）：
1. **互斥条件**：资源同一时刻只能被一个线程持有
2. **占有并等待**：线程持有一个资源的同时等待另一个资源
3. **不可剥夺**：已分配的资源不能被强制收回
4. **循环等待**：存在线程间的环形等待链

**预防策略**：
| 破坏的条件 | 策略 | 代价 |
|-----------|------|------|
| 互斥 | 使用无锁算法/原子操作 | 适用范围有限 |
| 占有并等待 | 一次性申请所有资源 | 资源利用率降低 |
| 不可剥夺 | 超时放弃已持有的锁 | 实现复杂 |
| 循环等待 | 按固定顺序加锁 | 需要约定全局顺序 |

**实践建议**：最常用的是"按固定顺序加锁"，例如所有线程都先锁A再锁B，就不会出现A→B和B→A的循环等待。
