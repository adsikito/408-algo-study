## 一、知识点黄金四步法讲解

### 1.1 网络体系结构（OSI七层 vs TCP/IP四层）【了解】

**是什么**：网络体系结构是计算机网络中各层协议和服务的分层组织方式。生活比喻：就像快递系统，从打包、贴单、分拣、运输到签收，每一层只做自己的事。

**为什么**：不同厂商的设备要互联互通，必须有统一的规则。分层让每层独立演进，改一层不影响其他层。追问三层：为什么要分层？因为复杂问题需要分解。为什么分七层/四层？因为功能相近的协议归为一层便于管理。为什么不合并？因为各层技术差异大，合并后维护困难。

**怎么用**：
- OSI七层（自底向上）：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层
- TCP/IP四层：链路层、网络层、传输层、应用层
- 常见协议分布：应用层有HTTP/FTP/SMTP/TFTP；传输层有TCP/UDP；网络层有IP/ICMP/IGMP；链路层有ARP/RARP

**注意事项**：OSI是理想化理论模型，实际开发中使用的是TCP/IP四层模型。不要混淆两者的层次对应关系。

> 人话总结：网络分层如快递流程，各司其职保通信。

### 1.2 TCP vs UDP【重点】

**是什么**：TCP和UDP是传输层的两种核心协议。TCP像挂号信（可靠但慢），UDP像明信片（快但可能丢）。

**为什么**：不同的应用场景对可靠性和实时性的需求不同。追问三层：为什么需要两种协议？因为"可靠"和"快速"天然矛盾。为什么TCP可靠？因为它有确认重传机制。为什么UDP快？因为它不管对方收没收到就直接发。

**怎么用**：

| 对比维度 | TCP | UDP |
|---------|-----|-----|
| 连接方式 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠（确认、重传、排序） | 不可靠（尽最大努力） |
| 数据形式 | 字节流（无边界） | 数据报（有边界） |
| 粘包问题 | 有粘包现象 | 不粘包 |
| 传输效率 | 较低（开销大） | 较高（开销小） |
| 收发同步 | 异步 | 同步 |
| 适用场景 | 文件下载、登录注册、网页浏览 | 音视频、广播组播、DNS查询 |

**注意事项**：TCP的粘包是指多个小包被合成一个大包发送，接收端需要自行拆分。UDP虽然不粘包，但超过MTU的数据会被截断丢弃。

> 人话总结：TCP稳如老牛，UDP快似闪电。

#### TCP三次握手详解

```
客户端                          服务器
  |                               |
  |-------- SYN(seq=x) --------->|   第一次：客户端发起连接请求
  |                               |
  |<-- SYN+ACK(seq=y,ack=x+1) ---|   第二次：服务器同意并回复
  |                               |
  |-------- ACK(ack=y+1) ------->|   第三次：客户端确认
  |                               |
  |===== 连接建立，可以传数据 =====|
```

- SYN（Synchronize）：同步标志位，表示请求建立连接
- ACK（Acknowledge）：确认标志位，表示确认收到
- 为什么是三次而不是两次？防止历史重复连接的初始化问题

#### TCP四次挥手详解

```
客户端                          服务器
  |                               |
  |-------- FIN(seq=u) ---------->|   第一次：客户端请求断开
  |                               |
  |<-------- ACK(ack=u+1) -------|   第二次：服务器确认收到
  |                               |   （服务器可能还有数据要发）
  |<-------- FIN(seq=w) ----------|   第三次：服务器也请求断开
  |                               |
  |-------- ACK(ack=w+1) ------->|   第四次：客户端确认
  |                               |
  |== 等待2MSL后彻底关闭 ==        |
```

- FIN（Finish）：结束标志位，表示不再发送数据
- 为什么是四次而不是三次？因为TCP是全双工的，每个方向必须单独关闭
- 2MSL等待：确保最后一个ACK能到达对方，以及让旧报文在网络中消失

#### 粘包问题的成因与解决方案

**成因**：TCP是字节流协议，发送端Nagle算法会将多个小包合并成一个大包发送；接收端缓冲区也可能一次读到多个包的数据。

**解决方案**：
1. 定长法：每个消息固定长度，不足补齐
2. 分隔符法：用特殊字符（如`\n`）标记消息结尾
3. 长度头法：消息头部包含消息体的长度字段（最常用）

### 1.3 字节序【重点】

**是什么**：字节序是多字节整数在内存中的存储顺序。大端存储像写数字从左到右（高位在前），小端存储像倒着写（低位在前）。生活比喻：大端就像我们正常读书从左到右，小端就像把书页反过来读。

**为什么**：不同CPU架构采用不同字节序（Intel x86用小端，ARM可配置）。如果两台大小端不同的主机直接传多字节整数，数值会出错。追问三层：为什么会出错？因为同一个数在不同机器上内存排列不同。怎么解决？统一规定网络传输用大端。为什么选大端？因为大端更符合人类阅读习惯，且早期网络设备就用大端。

**怎么用**：

四个转换函数（头文件 `<arpa/inet.h>`）：

```cpp
#include <arpa/inet.h>
uint32_t htonl(uint32_t hostlong);   // 主机→网络，4字节
uint16_t htons(uint16_t hostshort);  // 主机→网络，2字节
uint32_t ntohl(uint32_t netlong);    // 网络→主机，4字节
uint16_t ntohs(uint16_t netshort);   // 网络→主机，2字节
```

记忆口诀：**h**ost **to** **n**etwork = hton，**n**etwork **to** **h**ost = ntoh；**l**ong = 4字节，**s**hort = 2字节。

**何时使用**：
- 传输多字节整数（端口号、IP地址等）时**必须**转换
- 传输单字节数据或字符串时**不需要**转换

**配套代码走读**（day1/03byteorder.cpp）：

```cpp
int num = 0x12345678;          // 内存中：小端为 78 56 34 12
int res = htonl(num);          // 转为网络字节序（大端）：12 34 56 78
printf("res = %#x\n", res);    // 输出 0x12345678（在大端机器上打印的值就是原始值）
                                // 在小端机器上，htonl将 0x12345678 变为 0x78563412
```

执行结果分析：在小端主机（x86）上，`num`在内存中低地址存0x78。`htonl`将其翻转，返回值在数值上表现为0x78563412。

**判断主机大小端的两种方法**：

方法一：指针法（day1/01endian.cpp）
```cpp
int num = 0x12345678;
char *ptr = (char *)&num;     // char指针指向num的最低地址
if(*ptr == 0x12)             // 最低地址存的是高位 → 大端
    cout << "big endian";
else if(*ptr == 0x78)        // 最低地址存的是低位 → 小端
    cout << "little endian";
```

方法二：共用体法（day1/02endian.cpp）
```cpp
union Info { int num; char ch; };
union Info temp;
temp.num = 0x12345678;
// ch和num共享起始地址，ch读取的就是num最低地址的字节
if(temp.ch == 0x78) cout << "little endian";
```

**注意事项**：永远不要假设主机字节序，网络编程中涉及多字节整数一律先转网络字节序。

> 人话总结：网络传整数先转大端，收到再转回本机格式。

### 1.4 IP地址【重点】

**是什么**：IP地址是主机在网络中的唯一标识，由网络号和主机号组成。生活比喻：IP地址就像门牌号，网络号是小区名，主机号是楼栋房间号。

**为什么**：没有IP地址就无法在网络中找到目标主机。追问三层：为什么需要网络号+主机号？因为要分层寻址。为什么IPv4不够用？因为只有2^32约43亿个地址。怎么解决？NAT局域网共享公网IP + IPv6扩展到2^128。

**怎么用**：

IPv4地址分类：

| 类别 | 范围 | 网络号位数 | 主机号位数 | 用途 |
|------|------|-----------|-----------|------|
| A类 | 1.0.0.0 ~ 127.255.255.255 | 7 | 24 | 大型网络（已保留） |
| B类 | 128.0.0.0 ~ 191.255.255.255 | 14 | 16 | 中型网络 |
| C类 | 192.0.0.0 ~ 223.255.255.255 | 21 | 8 | 家庭/校园/公司 |
| D类 | 224.0.0.0 ~ 239.255.255.255 | - | - | 组播 |
| E类 | 240.0.0.0 ~ 255.255.255.255 | - | - | 保留实验 |

特殊IP地址：
- `127.0.0.1`：本地环回地址，测试本机网络栈
- `0.0.0.0`：表示任意地址（监听所有网卡）
- `255.255.255.255`：受限广播地址
- 网络号+全0主机号：表示该网络本身
- 网络号+全1主机号：该网络的广播地址

地址转换函数（头文件 `<sys/socket.h>` `<netinet/in.h>` `<arpa/inet.h>`）：

```cpp
in_addr_t inet_addr(const char *cp);      // 点分十进制字符串 → 4字节网络字节序整数
char *inet_ntoa(struct in_addr in);        // 4字节网络字节序整数 → 点分十进制字符串
```

**配套代码走读**（day1/04ip.cpp）：
```cpp
const char *ip = "192.168.10.12";
unsigned int ip_net = inet_addr(ip);
// 192=0xC0, 168=0xA8, 10=0x0A, 12=0x0C
// 网络字节序（大端）存储：C0 A8 0A 0C
printf("ip_net = %#x\n", ip_net);  // 输出 0xc0a80a0c
```

**注意事项**：`inet_ntoa`返回的是静态缓冲区指针，不可重入，多次调用会覆盖上一次的结果。`inet_addr`无法处理"255.255.255.255"（返回INADDR_NONE），建议新项目使用`inet_pton`/`inet_ntop`替代。

> 人话总结：IP是网上门牌号，传之前转格式，显示时转回来。

### 1.5 端口号【熟悉】

**是什么**：端口号是2字节无符号整数（0~65535），用于区分同一主机上的不同应用程序。生活比喻：IP地址找到了大楼，端口号就是具体的房间号。

**为什么**：一台主机运行多个网络程序，仅靠IP无法区分哪个程序接收数据。不用进程号是因为进程重启后PID变化，而端口号绑定的是应用程序。

**怎么用**：

| 端口范围 | 名称 | 说明 |
|---------|------|------|
| 0~1023 | 知名端口 | 系统保留，如HTTP=80, SSH=22, FTP=21 |
| 1024~49151 | 用户端口 | 用户程序可自行分配 |
| 49152~65535 | 动态端口 | 系统自动分配的临时端口 |

查看知名端口：`cat /etc/services`

**注意事项**：使用1024以下端口通常需要root权限。自定义端口建议选择1024以上的未占用端口。

> 人话总结：端口是程序的门牌，选1024以上免权限冲突。

### 1.6 socket函数【重点】

**是什么**：socket()函数创建一个网络通信端点，返回文件描述符。生活比喻：socket就像安装一部电话机，有了它才能打电话（通信）。

**为什么**：网络通信需要一个载体来封装发送缓冲区和接收缓冲区，socket就是这个载体的抽象。Linux中一切皆文件，socket也被抽象为文件描述符，可以用read/write/send/recv操作。

**怎么用**：

```cpp
#include <sys/types.h>
#include <sys/socket.h>
int socket(int domain, int type, int protocol);
```

| 参数 | 说明 | 常用值 |
|------|------|--------|
| domain | 协议族 | AF_INET(IPv4), AF_INET6(IPv6), AF_UNIX(本地) |
| type | 通信类型 | SOCK_STREAM(TCP), SOCK_DGRAM(UDP) |
| protocol | 具体协议 | 通常填0（由type自动推导） |

返回值：成功返回文件描述符（最小未分配原则），失败返回-1并置位errno。

**注意事项**：创建socket后应检查返回值是否为-1。socket创建的fd同时拥有发送缓冲区和接收缓冲区。

> 人话总结：socket造电话机，返回编号就能用。

### 1.7 bind/listen/accept三件套【重点】

**是什么**：bind给socket绑定IP+端口（贴门牌），listen设为被动监听状态（开门营业），accept阻塞等待并接受客户端连接（接客）。生活比喻：bind=挂招牌，listen=打开店门，accept=迎接进店的第一位客人。

**为什么**：服务器必须让客户端知道在哪里找到自己（bind），然后声明愿意接受连接（listen），最后逐个接待（accept）。追问三层：为什么bind和listen分开？因为bind只是命名，listen才是激活队列。为什么accept返回新fd？因为原sfd要继续监听新连接，不能用来通信。为什么backlog设128？这是内核已完成连接队列的上限，太小会拒绝连接。

**怎么用**：

```cpp
// bind: 绑定地址
#include <sys/socket.h>
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);

// listen: 设置监听
int listen(int sockfd, int backlog);

// accept: 接受连接
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
```

sockaddr_in结构体填充模板：
```cpp
struct sockaddr_in sin;
sin.sin_family = AF_INET;                    // 地址族
sin.sin_port = htons(8888);                  // 端口号（必须htons！）
sin.sin_addr.s_addr = inet_addr("192.168.1.1"); // IP地址（已是网络字节序）
```

返回值：bind/listen成功返回0，失败返回-1。accept成功返回新的通信fd，失败返回-1。

**注意事项**：
- `sin_port`必须用`htons()`转换，否则绑定到错误端口
- `sin_addr.s_addr`用`inet_addr()`赋值，该函数返回值已是网络字节序
- bind第二个参数需强制转换为`(struct sockaddr*)`
- accept第三个参数是传入传出参数，必须传入有效指针

> 人话总结：绑地址、开监听、接连接，三步搞定服务端。

### 1.8 connect/send/recv三件套【重点】

**是什么**：connect向服务器发起连接（拨号），send发送数据（说话），recv接收数据（听话）。生活比喻：connect=拨通电话，send=对着话筒说，recv=贴着听筒听。

**为什么**：客户端需要主动连接到服务器才能通信。TCP的send/recv基于已建立的连接，无需每次指定对方地址。

**怎么用**：

```cpp
// connect: 连接服务器
#include <sys/socket.h>
int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen);

// send: 发送数据
ssize_t send(int sockfd, const void *buf, size_t len, int flags);

// recv: 接收数据
ssize_t recv(int sockfd, void *buf, size_t len, int flags);
```

| 函数 | 返回值含义 |
|------|-----------|
| send | >0: 实际发送字节数; -1: 失败 |
| recv | >0: 实际接收字节数; 0: 对端已关闭连接; -1: 失败 |

flags参数：0=阻塞模式，MSG_DONTWAIT=非阻塞模式。

**关键提醒**：recv返回0不是错误，而是对端调用了close或shutdown，表示连接正常断开。**必须处理此情况**，否则死循环。

**注意事项**：send的实际发送字节数可能小于len（部分发送），生产环境需循环发送直到全部完成。recv同理。

> 人话总结：拨号连通后，send说recv听，零是再见负是错。

### 1.9 TCP服务器完整六步流程【重点】

**是什么**：TCP服务器的标准工作流程分为六个步骤。生活比喻：开店六步曲——装电话、挂牌子、开门、接客、聊天、关门。

**为什么**：每一步都有明确的职责，缺一不可。socket创建通信载体，bind指定服务地址，listen开启排队机制，accept接待客户，recv/send双向通信，close释放资源。

**怎么用**（配套代码 day2/01tcpSer.cpp 逐行走读）：

```cpp
// === 第1步：创建套接字 ===
int sfd = socket(AF_INET, SOCK_STREAM, 0);
// 内存状态：内核分配一个socket结构体，包含发送/接收缓冲区
// sfd=3（假设0/1/2已被stdin/stdout/stderr占用）

// === 第2步：绑定IP+端口 ===
struct sockaddr_in sin;
sin.sin_family = AF_INET;
sin.sin_port = htons(SER_PORT);              // 8888 → 网络字节序
sin.sin_addr.s_addr = inet_addr(SER_IP);     // "172.20.10.8" → 网络字节序整数
bind(sfd, (struct sockaddr*)&sin, sizeof(sin));
// 内核状态：将IP:Port与sfd关联，写入socket表

// === 第3步：启动监听 ===
listen(sfd, 128);
// 内核状态：sfd进入LISTEN状态，创建半连接队列(SYN Queue)和全连接队列(Accept Queue)
// backlog=128表示全连接队列最大长度

// === 第4步：接受连接 ===
struct sockaddr_in cin;
socklen_t socklen = sizeof(cin);
int newfd = accept(sfd, (struct sockaddr*)&cin, &socklen);
// 阻塞等待：如果没有客户端在队列中，进程睡眠
// 有客户端时：内核从全连接队列取出第一个，创建newfd
// cin被填入客户端的IP和端口（网络字节序）
// newfd是一个全新的fd，专门与该客户端通信

// === 第5步：数据收发 ===
char rbuf[128] = "";
while(1) {
    bzero(rbuf, sizeof(rbuf));
    int res = recv(newfd, rbuf, sizeof(rbuf), 0);
    // 数据流向：网卡→内核协议栈→socket接收缓冲区→用户空间rbuf
    if(res == 0) { printf("对端下线\n"); break; }
    // res>0: rbuf中有res字节的有效数据
    strcat(rbuf, "*_*");
    send(newfd, rbuf, strlen(rbuf), 0);
    // 数据流向：用户空间rbuf→socket发送缓冲区→内核协议栈→网卡
}

// === 第6步：关闭套接字 ===
close(newfd);  // 关闭通信fd，触发四次挥手
close(sfd);    // 关闭监听fd，停止接收新连接
```

**注意事项**：accept返回的newfd和sfd是两个独立的fd。sfd只负责监听，newfd负责通信。关闭时要两个都关。

> 人话总结：建绑监听接收发关，六步走完服务上线。

### 1.10 TCP客户端完整四步流程【重点】

**是什么**：TCP客户端的标准流程分四步。生活比喻：打电话四步——拿电话、拨号码、通话、挂电话。

**配套代码走读**（day2/02tcpCli.cpp）：

```cpp
// 第1步：创建套接字
int cfd = socket(AF_INET, SOCK_STREAM, 0);

// 第2步：绑定（可选，客户端一般不绑定，系统自动分配端口）
// 如果绑定，注意端口不要与服务器冲突

// 第3步：连接服务器
struct sockaddr_in sin;
sin.sin_family = AF_INET;
sin.sin_port = htons(SER_PORT);
sin.sin_addr.s_addr = inet_addr(SER_IP);
connect(cfd, (struct sockaddr*)&sin, sizeof(sin));
// 内部触发三次握手，成功后cfd进入ESTABLISHED状态

// 第4步：数据收发
char wbuf[128] = "";
while(1) {
    bzero(wbuf, sizeof(wbuf));
    fgets(wbuf, sizeof(wbuf), stdin);
    wbuf[strlen(wbuf)-1] = 0;       // 去掉fgets带入的换行符
    send(cfd, wbuf, sizeof(wbuf), 0);
    if(recv(cfd, wbuf, sizeof(wbuf), 0) == 0) {
        printf("对端下线\n"); break;
    }
    printf("收到：%s\n", wbuf);
}

// 第5步：关闭
close(cfd);
```

**注意事项**：客户端的bind是可选的，不绑定时内核自动分配一个临时端口。`fgets`读入的字符串末尾带`\n`，发送前要去掉。

> 人话总结：建连收发关，客户端四步完。

### 1.11 UDP通信【重点】

**是什么**：UDP是无连接的传输协议，使用sendto/recvfrom代替send/recv，每次发送都要指定目标地址。生活比喻：UDP像寄明信片，每张都要写收件地址，不保证送达。

**为什么**：某些场景（音视频、广播）对实时性要求高于可靠性，TCP的连接建立和确认重传开销太大。

**怎么用**：

```cpp
#include <sys/socket.h>
// 创建UDP套接字
int sfd = socket(AF_INET, SOCK_DGRAM, 0);   // 注意：SOCK_DGRAM

// 发送（无需connect）
ssize_t sendto(int sockfd, const void *buf, size_t len, int flags,
               const struct sockaddr *dest_addr, socklen_t addrlen);

// 接收（可同时获取发送方地址）
ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags,
                 struct sockaddr *src_addr, socklen_t *addrlen);
```

**UDP服务器 vs TCP服务器的区别**：
- 不需要listen和accept
- socket后用SOCK_DGRAM
- 用recvfrom/sendto代替recv/send
- 直接从recvfrom获取客户端地址，无需accept

**配套代码走读**（day2/03udpSer.cpp）：

```cpp
int sfd = socket(AF_INET, SOCK_DGRAM, 0);    // UDP套接字
// ... bind同TCP ...
struct sockaddr_in cin;
socklen_t socklen = sizeof(cin);
while(1) {
    bzero(rbuf, sizeof(rbuf));
    recvfrom(sfd, rbuf, sizeof(rbuf), 0,
             (struct sockaddr*)&cin, &socklen);
    // cin被填入发送方的IP和端口
    // socklen被更新为实际地址长度
    printf("[%s:%d]:%s\n", inet_ntoa(cin.sin_addr),
           ntohs(cin.sin_port), rbuf);
    strcat(rbuf, "*_*");
    sendto(sfd, rbuf, strlen(rbuf), 0,
           (struct sockaddr*)&cin, sizeof(cin));
    // 用刚才recvfrom获得的地址回复
}
```

**注意事项**：UDP没有连接概念，recvfrom不会返回0来表示对端下线。UDP数据报超过MTU（默认1500字节）的部分会被截断。

> 人话总结：UDP无连接，收发带地址，快速但不保达。

### 1.12 并发服务器模型【重点】

**是什么**：并发服务器能同时服务多个客户端。生活比喻：循环服务器像一个窗口只办一笔业务；fork服务器像每来一个人就开一个新窗口；线程服务器像雇多个员工在同一间办公室干活。

**为什么**：基本TCP服务器只能一对一，实际应用中服务器需要同时响应大量客户端。

**三种模型对比**：

| 对比维度 | 循环服务器 | 多进程(fork) | 多线程(pthread) |
|---------|-----------|-------------|----------------|
| 实现方式 | accept放在while中串行处理 | accept后fork子进程处理 | accept后create线程处理 |
| 并发能力 | 同一时刻只能服务一个客户端 | 多个客户端并行 | 多个客户端并行 |
| 资源开销 | 最低 | 最高（复制整个进程空间） | 中等（共享进程空间） |
| 创建速度 | 最快 | 慢（fork开销大） | 较快 |
| 通信方式 | 无需IPC | 需要管道/共享内存等IPC | 直接共享全局变量 |
| 安全性 | 无风险 | 进程隔离，安全 | 需注意线程同步 |
| 适用场景 | 简单测试 | 高安全要求 | 大多数服务器应用 |

**配套代码要点**：

fork版（day3/02tcpSerFork.cpp）关键点：
```cpp
// accept后fork
pid_t pid = fork();
if(pid > 0) {
    close(newfd);    // 父进程关闭通信fd，继续accept
} else if(pid == 0) {
    close(sfd);      // 子进程关闭监听fd，专注通信
    // ... recv/send循环 ...
    close(newfd);
    exit(EXIT_SUCCESS);
}
```
- 父进程必须关闭newfd（否则fd泄漏）
- 子进程必须关闭sfd（否则占用监听端口）
- 需要SIGCHLD信号处理回收僵尸进程：`waitpid(-1, NULL, WNOHANG)`

线程版（day3/03tcpSerThread.cpp）关键点：
```cpp
struct Info { int newfd; struct sockaddr_in cin; };
struct Info buf = {newfd, cin};
pthread_t tid;
pthread_create(&tid, NULL, deal_cli_msg, &buf);
pthread_detach(tid);   // 分离态，线程结束后自动回收
```
- 不能用pthread_join（会阻塞主线程）
- 传参要注意生命周期：buf如果是局部变量，线程可能在拷贝前就退出
- 线程间共享全局变量需要互斥锁保护

> 人话总结：循环太慢fork太重，线程适中是首选。

### 1.13 IO多路复用select/poll/epoll【重点】

**是什么**：IO多路复用允许一个线程同时监控多个文件描述符的IO事件。生活比喻：select像一个保安轮流查看每个门口是否有人；poll像保安拿着清单逐个点名；epoll像装了智能门铃，有人来自动通知保安。

**为什么**：fork/thread模型为每个客户端创建一个进程/线程，当连接数上万时资源耗尽。IO多路复用用一个线程管理成千上万的连接，大幅提升性能。

#### select详解

```cpp
#include <sys/select.h>
int select(int nfds, fd_set *readfds, fd_set *writefds,
           fd_set *exceptfds, struct timeval *timeout);
```

辅助宏：
```cpp
FD_ZERO(&set);       // 清空集合
FD_SET(fd, &set);    // 添加fd到集合
FD_CLR(fd, &set);    // 从集合移除fd
FD_ISSET(fd, &set);  // 检查fd是否在集合中
```

**配套代码走读**（day3/05tcpSerSelect.cpp 核心逻辑）：

```cpp
fd_set readfds, tempfds;
FD_ZERO(&readfds);
FD_SET(0, &readfds);      // 监控键盘输入
FD_SET(sfd, &readfds);    // 监控新连接
int maxfd = sfd;

while(1) {
    tempfds = readfds;     // select会修改集合，必须备份
    int res = select(maxfd+1, &tempfds, NULL, NULL, NULL);
    // maxfd+1: 要检测的最大fd值加1
    // 返回就绪的fd个数

    if(FD_ISSET(sfd, &tempfds)) {
        // sfd就绪 → 有新连接
        int newfd = accept(sfd, ...);
        FD_SET(newfd, &readfds);   // 加入监控集合
        if(maxfd < newfd) maxfd = newfd;
    }

    for(int i=4; i<=maxfd; i++) {
        if(FD_ISSET(i, &tempfds)) {
            // 客户端fd就绪 → 有数据可读
            int res = recv(i, rbuf, sizeof(rbuf), 0);
            if(res == 0) {
                close(i);
                FD_CLR(i, &readfds);  // 从集合移除
                // 更新maxfd...
                continue;
            }
            // 处理数据并回复...
        }
    }
}
```

select的局限：
1. fd数量限制1024（FD_SETSIZE）
2. 每次调用需重新设置fd集合（内核会修改）
3. 遍历检测O(n)复杂度
4. 需要将整个fd集合从用户态拷贝到内核态

#### poll详解

```cpp
#include <poll.h>
int poll(struct pollfd *fds, nfds_t nfds, int timeout);

struct pollfd {
    int fd;           // 文件描述符
    short events;     // 要监控的事件（POLLIN/POLLOUT等）
    short revents;    // 实际发生的事件（内核填写）
};
```

**配套代码走读**（day3/06tcpCliPoll.cpp）：

```cpp
struct pollfd pfds[2];
pfds[0].fd = 0;          // 监控键盘
pfds[0].events = POLLIN;
pfds[1].fd = cfd;        // 监控套接字
pfds[1].events = POLLIN;

while(1) {
    int res = poll(pfds, 2, -1);   // -1表示永久阻塞
    if(pfds[0].revents == POLLIN) {
        // 键盘有输入 → 读取并发送
    }
    if(pfds[1].revents == POLLIN) {
        // 套接字有数据 → 接收并显示
    }
}
```

poll比select的优势：无fd数量限制，使用数组而非位图。劣势：仍需遍历O(n)，仍需每次拷贝。

#### epoll详解（高性能方案）

```cpp
#include <sys/epoll.h>
int epoll_create(int size);         // 创建epoll实例
int epoll_ctl(int epfd, int op, int fd, struct epoll_event *event);
int epoll_wait(int epfd, struct epoll_event *events, int maxevents, int timeout);

struct epoll_event {
    uint32_t events;    // EPOLLIN, EPOLLOUT, EPOLLET等
    epoll_data_t data;  // 用户数据（常存fd）
};
```

epoll_ctl的op参数：EPOLL_CTL_ADD（添加）、EPOLL_CTL_MOD（修改）、EPOLL_CTL_DEL（删除）。

**配套代码走读**（day3/07epollTcpSer.cpp 核心逻辑）：

```cpp
// 创建epoll实例
int epfd = epoll_create(1);   // 参数1在新内核中被忽略

// 将sfd加入监控
struct epoll_event ev;
ev.events = EPOLLIN | EPOLLET;   // 读事件 + 边缘触发
ev.data.fd = sfd;
epoll_ctl(epfd, EPOLL_CTL_ADD, sfd, &ev);

struct epoll_event evs[1024];   // 接收就绪事件的数组

while(1) {
    int num = epoll_wait(epfd, evs, 1024, -1);
    // 只返回就绪的fd，无需遍历全部fd

    for(int i=0; i<num; i++) {
        int fd = evs[i].data.fd;
        if(fd == sfd) {
            // 新连接到来
            int newfd = accept(sfd, ...);
            ev.events = EPOLLIN | EPOLLET;
            ev.data.fd = newfd;
            epoll_ctl(epfd, EPOLL_CTL_ADD, newfd, &ev);
        } else {
            // 客户端数据到来
            char rbuf[5] = "";
            int res = recv(fd, rbuf, sizeof(rbuf)-1, 0);
            if(res == 0) {
                epoll_ctl(epfd, EPOLL_CTL_DEL, fd, NULL);
                close(fd);
                break;
            }
            // 处理并回复...
        }
    }
}
close(epfd);
```

**ET vs LT模式**：

| 特性 | LT（水平触发，默认） | ET（边缘触发） |
|------|---------------------|---------------|
| 触发条件 | 只要缓冲区有数据就持续通知 | 仅在状态变化时通知一次 |
| 编程难度 | 简单 | 较难（必须一次性读完数据） |
| 性能 | 略低（可能重复通知） | 更高（减少无效唤醒） |
| 面试考法 | 默认行为 | 配合非阻塞IO使用，循环recv直到EAGAIN |

epoll的核心优势：
1. 无fd数量限制（受系统内存限制）
2. 基于回调机制，只有活跃的fd才触发，O(1)复杂度
3. fd集合在内核维护，无需每次拷贝
4. 支持ET/LT两种模式

**三者对比汇总**：

| 对比维度 | select | poll | epoll |
|---------|--------|------|-------|
| 数据结构 | bitmap | 数组 | 红黑树+链表 |
| fd上限 | 1024 | 无限制 | 无限制 |
| 工作模式 | 轮询 | 轮询 | 事件驱动/回调 |
| 时间复杂度 | O(n) | O(n) | O(1) |
| fd拷贝 | 每次全量拷贝 | 每次全量拷贝 | 注册时拷贝一次 |
| 适用场景 | 跨平台兼容 | 中等规模 | Linux高性能服务器 |

> 人话总结：万级连接用epoll，百级用select够用。

### 1.14 广播与组播【了解】

**是什么**：广播是一对所有人（同网段），组播是一对一组人（加入组播组的成员）。生活比喻：广播像村里大喇叭喊话所有人都听到，组播像微信群只有群成员收到消息。

**怎么用**：

广播发送需要设置SO_BROADCAST选项：
```cpp
int broad = 1;
setsockopt(sndfd, SOL_SOCKET, SO_BROADCAST, &broad, sizeof(broad));
// 然后sendto到广播地址（如172.20.10.15或255.255.255.255）
```

组播接收需要加入组播组：
```cpp
struct ip_mreqn imr;
imr.imr_multiaddr.s_addr = inet_addr("224.1.2.3");   // 组播地址
imr.imr_address.s_addr = inet_addr("172.20.10.8");    // 本机IP
imr.imr_ifindex = 2;                                   // 网卡编号
setsockopt(recvfd, IPPROTO_IP, IP_ADD_MEMBERSHIP, &imr, sizeof(imr));
```

**注意事项**：组播地址范围是224.0.0.0~239.255.255.255（D类地址）。广播仅限同一子网内。

> 人话总结：广播全员收听，组播入群才有。

### 1.15 Unix域套接字【了解】

**是什么**：Unix域套接字（AF_UNIX）用于同一主机内的进程间通信，使用文件路径代替IP+端口。生活比喻：网络socket像打长途电话，Unix域socket像在同一栋楼里对讲机通话。

**怎么用**：

```cpp
int sfd = socket(AF_UNIX, SOCK_STREAM, 0);  // 或SOCK_DGRAM
struct sockaddr_un sun;
sun.sun_family = AF_UNIX;
strcpy(sun.sun_path, "./unix");   // 套接字文件路径
// 绑定前需检查并删除已存在的文件
if(access("./unix", F_OK) == 0) unlink("./unix");
bind(sfd, (struct sockaddr*)&sun, sizeof(sun));
```

**注意事项**：
- 字符串赋值必须用strcpy，不能直接`=`
- bind前必须unlink旧文件，否则报错Address already in use
- Unix域socket也分STREAM(DGRAM)两种类型，对应TCP/UDP语义
- 性能优于网络socket（不经过协议栈）

> 人话总结：同机通信用Unix域，文件路径替IP。

### 1.16 SO_REUSEADDR端口重用【重点补充】

**是什么**：SO_REUSEADDR允许在TIME_WAIT状态下重新绑定同一端口。生活比喻：退房后立即可以让新客人入住，不必等保洁期。

**为什么**：TCP服务器关闭后，端口进入TIME_WAIT状态（默认2MSL≈60秒），此时重新bind会报"Address already in use"。

**怎么用**（day3/05tcpSerSelect.cpp中演示）：
```cpp
int reuse = 1;
setsockopt(sfd, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof(reuse));
// 必须在bind之前调用！
bind(sfd, (struct sockaddr*)&sin, sizeof(sin));
```

**注意事项**：setsockopt必须在bind之前调用，否则无效。

> 人话总结：重用写在bind前，重启不再报占用。

## 三、配套代码逐行走读

### 3.1 day1/01endian.cpp -- 指针法判断大小端

```cpp
#include <myhead.h>
int main(int argc, const char *argv[])
{
    int num = 0x12345678;
    // num在内存中的布局取决于CPU字节序
    // 小端(x86): [78][56][34][12] ← 低地址在左
    // 大端:      [12][34][56][78]

    char *ptr = (char *)&num;
    // ptr指向num的最低地址字节
    // 小端时 *ptr == 0x78; 大端时 *ptr == 0x12

    if(*ptr == 0x12)
        cout << "big endian" << endl;
    else if(*ptr == 0x78)
        cout << "little endian" << endl;
    return 0;
}
```

**内存状态变化**：`&num`取num的地址，强转为char*后指针步长变为1字节。解引用`*ptr`读取该地址处的单个字节值。在x86机器上输出"little endian"。

### 3.2 day1/02endian.cpp -- 共用体法判断大小端

```cpp
union Info { int num; char ch; };
// num占4字节，ch占1字节
// 两者共享起始地址（偏移量都为0）

union Info temp;
temp.num = 0x12345678;
// 写入num后，ch读取的是num最低地址的那个字节
// 效果等同于指针法，但更安全（不涉及指针强转）
```

### 3.3 day1/03byteorder.cpp -- htonl转换验证

### 3.5 day3/02tcpSerFork.cpp -- fork并发服务器

关键走读：
```cpp
// SIGCHLD信号处理函数
void handler(int signo) {
    if(signo == SIGCHLD)
        while(waitpid(-1, NULL, WNOHANG) > 0);
    // -1: 等待任意子进程
    // WNOHANG: 非阻塞，立即返回
    // 循环直到没有可回收的子进程
}

// 主程序中注册信号处理
signal(SIGCHLD, handler);

// fork后的分支处理
pid_t pid = fork();
if(pid > 0) {
    close(newfd);   // 父进程不需要通信fd
    // 不调用wait（会阻塞），靠信号处理函数回收
} else if(pid == 0) {
    close(sfd);     // 子进程不需要监听fd
    // ... 通信循环 ...
    exit(EXIT_SUCCESS);  // 子进程正常退出
}
```

**为什么父进程关闭newfd**：fork后父子进程各自拥有fd表的副本，引用计数+1。父进程不关闭newfd会导致该fd永远不会释放（即使子进程关了，父进程的副本还在）。

    if(res == -1) { /* 错误 */ break; }

### 4.2 详细版速查表

#### socket函数详解

```
头文件: #include <sys/types.h> #include <sys/socket.h>
原型:   int socket(int domain, int type, int protocol);
domain: AF_INET(IPv4) | AF_INET6(IPv6) | AF_UNIX(本地)
type:   SOCK_STREAM(TCP) | SOCK_DGRAM(UDP)
protocol: 通常为0
返回:   fd(成功) | -1(失败,errno)
示例:   int sfd = socket(AF_INET, SOCK_STREAM, 0);
```

#### bind函数详解

```
头文件: #include <sys/socket.h>
原型:   int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
注意:   addr需强转为(struct sockaddr*)
        sin_port必须htons(), sin_addr.s_addr用inet_addr()
返回:   0(成功) | -1(失败)
示例:   bind(sfd, (struct sockaddr*)&sin, sizeof(sin));
```

#### listen函数详解

```
原型:   int listen(int sockfd, int backlog);
backlog: 全连接队列最大长度，推荐128
返回:   0 | -1
```

#### accept函数详解

```
原型:   int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
说明:   阻塞等待，返回新的通信fd
        addr和addrlen可传NULL（不获取客户端信息）
返回:   newfd | -1
```

#### recv函数详解

```
原型:   ssize_t recv(int sockfd, void *buf, size_t len, int flags);
flags:  0(阻塞) | MSG_DONTWAIT(非阻塞)
返回:   >0(字节数) | 0(对端关闭!) | -1(错误)
重要:   返回0必须break退出循环
```

#### send函数详解

```
原型:   ssize_t send(int sockfd, const void *buf, size_t len, int flags);
返回:   >0(实际发送字节数,可能<len) | -1(错误)
注意:   生产环境需循环发送直到全部完成
```

#### epoll三函数详解

```
epoll_create(int size) → epfd
  size在新内核中忽略，传1即可

epoll_ctl(epfd, op, fd, &ev)
  op: EPOLL_CTL_ADD | EPOLL_CTL_MOD | EPOLL_CTL_DEL
  ev.events: EPOLLIN | EPOLLOUT | EPOLLET | EPOLLONESHOT

epoll_wait(epfd, events, maxevents, timeout)
  timeout: -1(永久阻塞) | 0(立即返回) | >0(毫秒超时)
  返回: 就绪事件个数 | -1(错误)
```

## 五、易错点速查卡

| 错误现象 | 错误原因 | 正确写法 | 后果 |
|---------|---------|---------|------|
| bind失败或绑定到错误端口 | sin_port未用htons转换 | `sin.sin_port = htons(8888)` | 绑定到随机端口或报错 |
| Address already in use | 重启服务器时TIME_WAIT未过 | bind前`setsockopt(SO_REUSEADDR)` | 服务器无法启动 |
| 无限循环空消息 | recv返回0未处理 | `if(res==0){break;}` | CPU 100%，死循环 |
| send发送不完整 | 未检查send返回值 | 循环send直到累计==len | 数据丢失 |
| 多线程传参错乱 | 传局部变量地址给线程 | malloc分配堆内存传指针 | 读到脏数据或崩溃 |
| fork后fd泄漏 | 父进程未关闭newfd | `if(pid>0) close(newfd)` | fd耗尽无法accept |
| fork僵尸进程 | 未回收子进程 | signal(SIGCHLD,handler)+waitpid | 进程表耗尽 |
| select后fd丢失 | 未备份fd_set | `tempfds=readfds; select(...,&tempfds,...)` | 第二次select漏检 |
| ET模式数据丢失 | 一次recv未读完 | 循环recv直到EAGAIN | 后续数据不再触发通知 |
| Unix域bind失败 | 旧文件未删除 | `access+F_OK → unlink` | Address already in use |
| 广播Permission denied | 未设SO_BROADCAST | `setsockopt(SO_BROADCAST)` | sendto失败 |
| inet_ntoa结果被覆盖 | 连续调用覆盖静态缓冲区 | 立即拷贝结果或用inet_ntop | 打印错误的IP |
| strcpy误用= | 字符数组不能用=赋值 | `strcpy(sun.sun_path, "./unix")` | 编译错误 |

## 六、常见陷阱专题

### 陷阱1：bind时端口号忘记htons转换

**错误写法**：
```cpp
sin.sin_port = 8888;   // 直接使用主机字节序
```
**后果**：8888的主机字节序在小端机器上是0xB822，网络字节序期望是0x22B8。实际绑定到的端口号是8888在小端表示下对应的值（可能是某个随机端口），导致客户端连接不上。

**正确写法**：
```cpp
sin.sin_port = htons(8888);   // 转为网络字节序
```

**记忆口诀**："端口上网络，必先htons"

### 陷阱2：TCP服务器重启报Address already in use

**错误写法**：
```cpp
close(sfd);
// 立即重新启动服务器
sfd = socket(AF_INET, SOCK_STREAM, 0);
bind(sfd, ...);   // 报错！端口处于TIME_WAIT状态
```

**后果**：TCP四次挥手中，主动关闭方进入TIME_WAIT状态，持续2MSL（约60秒）。在此期间bind同一端口会失败。

**正确写法**：
```cpp
int reuse = 1;
setsockopt(sfd, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof(reuse));
bind(sfd, ...);   // 现在可以立即重用端口
```

**记忆口诀**："重用先setsockopt，端口不再闹脾气"

### 陷阱3：recv返回0未处理导致死循环

**错误写法**：
```cpp
while(1) {
    int res = recv(fd, buf, sizeof(buf), 0);
    printf("%s\n", buf);   // res==0时buf为空，但仍打印空行
    send(fd, buf, strlen(buf), 0);  // 无限发送空数据
}
```

**后果**：客户端断开后recv持续返回0，循环不停，CPU飙到100%，且不断向已关闭的连接发送数据。

**正确写法**：
```cpp
while(1) {
    int res = recv(fd, buf, sizeof(buf), 0);
    if(res == 0) {
        printf("对端已下线\n");
        break;            // 跳出循环
    }
    if(res == -1) {
        perror("recv error");
        break;
    }
    // 正常处理res字节的数据
}
```

**记忆口诀**："recv零是再见，不是没数据"

## 七、新手最常问的5个问题

### Q1：为什么服务器要先listen再accept，不能直接accept？

答：listen的作用是将socket从"主动"模式切换到"被动"模式，并创建连接队列。没有listen的socket不能接受连接，accept会直接报错。就像商店没有开门营业的告示，客人来了也不知道能不能进。

### Q2：accept返回的newfd和原来的sfd有什么区别？

答：sfd是监听fd，只负责接收新的连接请求，不能用来收发数据。newfd是通信fd，代表与某个特定客户端的连接，用它来recv/send。sfd好比前台接待员的电话（只接新来电），newfd好比转接给具体员工的内线电话（与客户对话）。

### Q3：为什么UDP不需要listen和accept？

答：UDP是无连接协议，没有"建立连接"的概念。每个数据包都是独立的，发送时用sendto指定目标地址，接收时用recvfrom获取来源地址。不需要预先建立通道，所以也不需要listen（声明愿意接受连接）和accept（接受特定连接）。

### Q4：select的nfds参数为什么要传maxfd+1？

答：nfds表示要检查的文件描述符范围是从0到nfds-1。如果你的最大fd是10，就需要检查0~10共11个fd，所以传10+1=11。传错了会导致高编号的fd不被检测。

### Q5：epoll的ET模式和LT模式怎么选？

答：初学者建议用LT模式（默认），编程简单，只要有数据就一直通知。ET模式适合追求极致性能的场景，但必须配合非阻塞IO和循环读取，编程难度大。面试中常被问到区别，记住：LT=有数据就通知，ET=状态变化才通知一次。
