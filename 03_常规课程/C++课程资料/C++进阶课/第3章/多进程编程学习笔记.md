#### 1.1 进程概念 【重点】

**① 是什么**
进程是程序的一次执行过程，是操作系统进行资源分配的基本单位。每个进程拥有独立的0-3G用户空间和共享的3-4G内核空间。

**生活比喻**：程序好比一张菜谱（静态文件），进程好比按照这张菜谱正在炒菜的厨师（动态执行）。同一张菜谱可以同时被多个厨师使用，每个厨师有自己的灶台、调料和锅碗瓢盆（独立的资源）。

**② 为什么**
- 为什么需要进程？因为计算机需要同时运行多个任务（浏览器、音乐、编辑器），操作系统必须为每个任务分配独立资源并隔离保护。
- 为什么用户空间独立而内核空间共享？独立性保证一个进程崩溃不影响其他进程；共享内核空间则让所有进程都能通过系统调用访问硬件资源。
- 为什么采用时间片轮询？CPU速度远快于人类感知，快速切换让每个进程"感觉"自己独占了CPU。

**③ 怎么用**

```cpp
// 演示：查看当前进程的虚拟内存映射
// 在Linux终端执行以下命令观察进程内存布局：
// cat /proc/self/maps
// 输出示例（部分）：
// 00400000-00401000 r-xp ... /usr/bin/cat    ← 代码段（用户空间）
// 7f8b8c000000-7f8b8c200000 r-xp ... libc.so ← 共享库
// ffffffffff600000-ffffffffff601000 r-xp ... [vsyscall] ← 内核空间
```

```cpp
#include <stdio.h>
#include <unistd.h>

int global_var = 100;  // 全局变量在静态区

int main() {
    int local_var = 200;  // 局部变量在栈区
    printf("全局变量地址: %p\n", (void*)&global_var);   // 静态区
    printf("局部变量地址: %p\n", (void*)&local_var);     // 栈区
    // 输出：两个地址都在0x00000000~0xBFFFFFFF范围内（用户空间0-3G）
    return 0;
}
```

**④ 注意事项**

| 错误认知 | 正确理解 |
|----------|----------|
| 进程就是程序 | 程序是静态文件，进程是动态执行实例 |
| 进程间可以随意访问对方内存 | 用户空间完全隔离，只能通过IPC通信 |
| 进程一直在运行 | 实际上是被调度器以时间片轮流执行 |

> **人话总结**：进程就是跑起来的程序，有独立内存。

#### 1.2 并发与并行 【熟悉】

**① 是什么**
- **并发（Concurrency）**：单核CPU通过时间片切换，宏观上多个任务"同时"执行，微观上任一时刻只有一个任务在处理。
- **并行（Parallelism）**：多核CPU上，多个任务真正在同一时刻同时执行。

**生活比喻**：并发就像一个人轮流炒三锅菜，每锅炒几秒就换下一锅，看起来三锅同时在炒；并行就像三个人各守一锅，真正同时炒。

**② 为什么**
理解这个区别决定了你选择多进程还是多线程：单核上多进程只是并发切换，开销大收益小；多核上才能真正发挥多进程并行的优势。

**③ 怎么用**

```bash
# 查看CPU核心数
nproc
# 输出：4（表示支持真正的4路并行）

# 查看进程在哪个CPU上运行
ps -eo pid,psr,comm | head
# 输出示例：
#   PID PSR COMMAND
#     1   0 systemd        ← 在CPU0上
#     2   0 kthreadd       ← 在CPU0上
```

**④ 注意事项**
- 并发不等于并行，单核机器上多进程本质是交替执行。
- 进程切换有上下文切换开销（保存/恢复寄存器、刷新TLB等），并非零成本。

> **人话总结**：并发是轮流干，并行是一起干。

#### 1.3 进程种类与PID 【熟悉】

**① 是什么**
- **交互进程**：由shell控制，可与用户直接交互（如vim、bash）。
- **批处理进程**：按队列统一处理，无需用户交互（如编译任务）。
- **守护进程**：脱离终端运行，随系统启停（如sshd、systemd）。
- **PID**：进程号，>=0的唯一整数标识。
- **PPID**：父进程号，每个进程都由父进程fork而来。

**特殊进程**：

| 编号 | 名称 | 作用 |
|------|------|------|
| 0号 | idle/swapper | 系统启动后第一个进程，空闲时运行，是1号和2号的父进程 |
| 1号 | init/systemd | 完成系统初始化，收养孤儿进程 |
| 2号 | kthreadd | 内核线程调度器，管理所有内核线程 |

**生活比喻**：PID就像身份证号，每个人唯一；PPID就像父亲是谁。0号进程好比开国元勋，1号进程好比管家，2号进程好比调度中心主任。

**② 为什么**
- 为什么PID从0开始？0号是系统根基，1号是用户空间的根，形成树状结构便于管理。
- 为什么需要守护进程？很多服务（网络、日志）需要在后台持续运行，不依赖任何终端。
- 为什么PPID重要？进程退出后由其父进程回收资源，PPID建立了父子关系链。

**③ 怎么用**

```bash
# 查看所有进程及其父子关系
ps -ef
# 输出：UID PID PPID C STIME TTY TIME CMD
# root  1   0    0 10:22  ?  00:00:01 /usr/lib/systemd/systemd
# root  2   0    0 10:22  ?  00:00:00 [kthreadd]

# 动态查看进程状态
top
# 输出：%CPU %MEM VIRT RES SHR S %CPU COMMAND

# 查看某进程的PID
pidof sshd
# 输出：1681

# 查看可发送的信号列表
kill -l
# 输出：1) SIGHUP  2) SIGINT  9) SIGKILL  17) SIGCHLD ...共64个
```

```cpp
#include <stdio.h>
#include <unistd.h>

int main() {
    printf("当前进程PID: %d\n", getpid());
    printf("父进程PPID: %d\n", getppid());
    // 输出：当前进程PID: 12345
    //       父进程PPID: 12340
    return 0;
}
```

**④ 注意事项**
- `/proc`目录下每个数字命名的子目录对应一个进程。
- PID不会重复（同一时刻），但进程退出后PID可能被复用。
- 守护进程没有TTY（显示为`?`），不受终端关闭影响。

> **人话总结**：三种进程各司其职，PID是唯一身份证。

#### 1.4 进程状态五态图 【重点】

**① 是什么**
Linux进程有五种主要状态：

| 状态码 | 名称 | 含义 |
|--------|------|------|
| R | Running | 正在运行或在运行队列中等待CPU |
| S | Interruptible Sleep | 可中断休眠，等待某个事件（如IO完成、信号） |
| D | Uninterruptible Sleep | 不可中断休眠，通常在等待IO操作完成，不响应信号 |
| T | Stopped | 被信号暂停（如Ctrl+Z或调试器） |
| Z | Zombie | 僵尸态，进程已退出但父进程尚未回收其资源 |

附加状态标记：`<`高优先级、`N`低优先级、`L`锁页、`s`会话组长、`l`多线程、`+`前台进程组。

**生活比喻**：R就像正在炒菜；S就像等水烧开的间隙可以看手机（能被叫醒）；D就像高压锅正在加压不能打开（叫不醒）；T就像被人喊停暂时休息；Z就像人已经走了但工位还没收拾。

**② 为什么**
- 为什么区分S和D？S状态可以被信号唤醒，D状态不行。D状态通常出现在磁盘IO等关键操作中，如果允许中断可能导致数据损坏。
- 为什么有Z状态？子进程退出后需要保留退出状态码供父进程读取，在父进程调用wait之前，子进程处于僵尸态。
- 为什么需要五态模型？精确描述进程生命周期，帮助开发者排查问题（如大量D状态说明IO瓶颈，大量Z状态说明父进程未回收）。

**③ 怎么用**

```bash
# 查看进程状态
ps aux | grep "myprogram"
# 输出：USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND
# zpp  1234 0.0  0.1  12345 1234 ?    Ss   10:22 0:01 ./myprogram
#                                              ^^
#                                              S=可中断休眠, s=会话组长

# 用top动态观察状态变化
top
# Tasks: 111 total, 1 running, 110 sleeping, 0 stopped, 0 zombie
# 注意最后zombie计数！如果>0说明有僵尸进程
```

**五态转换图（ASCII）**：

```
                    ┌──────────────────────────────────┐
                    │                                  │
         创建       ▼         调度器选中               │
      ┌──────► [就绪(R)] ◄─────────────────┐          │
      │            │                       │          │
      │     时间片到│ 获得CPU               │          │
      │            ▼                       │          │
      │       [运行(R)] ──────────────────►│          │
      │            │          时间片用完    │          │
      │            │                       │          │
      │     等待事件│                       │          │
      │            ▼                       │          │
      │      [休眠(S/D)]                   │          │
      │            │                       │          │
      │     事件到达│                       │          │
      │            └───────────────────────┘          │
      │                                               │
      │  Ctrl+Z/SIGSTOP                               │
      │            ▼                                  │
      │       [停止(T)] ──── SIGCONT ────►[就绪(R)]   │
      │                                               │
      │  exit()/异常退出                               │
      │            ▼                                  │
      └───── [僵尸(Z)] ──── wait() ────► [消亡]      │
                                          ▲           │
                                          │           │
                                    父进程回收         │
                                                      │
                              SIGKILL可从任何状态──────┘
                              （除Z外）直接终止
```

**④ 注意事项**
- D状态进程无法被kill掉（包括SIGKILL），只能等IO完成或重启。
- Z状态进程已经不消耗CPU和内存，但占用进程表项，大量僵尸会耗尽PID。
- 用`ps aux`看STAT列，组合字母含义要逐个解读（如`Ssl`表示可中断休眠+会话组长+多线程）。

> **人话总结**：五种状态画清进程一生，R在跑S在等Z该收。

#### 2.1 fork创建子进程 【重点】

**① 是什么**
`fork()`是创建新进程的系统调用，通过拷贝父进程资源生成一个几乎相同的子进程。

```c
#include <unistd.h>
pid_t fork(void);
// 参数：无
// 返回值：
//   父进程中 → 返回子进程的PID（>0）
//   子进程中 → 返回0
//   失败     → 返回-1，置位errno
```

**生活比喻**：fork就像细胞分裂——一个细胞变成两个，新细胞携带了母细胞的全部遗传信息（DNA拷贝），但从此各自独立生长。

**② 为什么**
- 为什么用拷贝而不是新建？子进程继承父进程的环境变量、打开的文件描述符、工作目录等，省去重复配置的麻烦。
- 为什么返回值不同？同一个函数在两个进程中返回不同的值，这是区分父子进程的唯一方式。
- 为什么底层不是真的全量拷贝？Linux采用写时拷贝（COW, Copy-On-Write）机制：fork时只复制页表，物理内存页仍然共享；只有当某一方写入时才真正复制该页。这大幅减少了fork的开销。（面试高频考点）

**③ 怎么用**

**案例1：不关注返回值（03fork.cpp走读）**

```cpp
#include <stdio.h>
#include <unistd.h>

int main() {
    printf("ni hao xingqiu\n");  // fork前打印一次
    fork();                       // 创建一个子进程
    printf("hello world\n");      // 父子进程都会执行此行
    while(1);                     // 防止进程结束
    return 0;
}
// 输出：
// ni hao xingqiu       ← fork前只有1个进程，打印1次
// hello world          ← 父进程打印
// hello world          ← 子进程打印
// 说明：fork之后的代码，父子进程各执行一份
```

**逐行走读**：
1. `printf("ni hao xingqiu\n")`：此时只有父进程，打印一行。
2. `fork()`：内核拷贝父进程PCB、页表（COW），创建子进程。父进程得到子进程PID，子进程得到0。
3. `printf("hello world\n")`：父进程执行一次，子进程也执行一次，共打印两行。
4. `while(1)`：两个进程都进入死循环，可用`ps aux`观察到两个进程。

**案例2：多个fork产生2^n个进程（04fork.cpp走读）**

```cpp
#include <stdio.h>
#include <unistd.h>

int main() {
    fork();   // 第1个fork：1→2个进程
    fork();   // 第2个fork：2→4个进程
    fork();   // 第3个fork：4→8个进程
    while(1); // 8个进程都在死循环
    return 0;
}
// 验证：ps aux | grep a.out | wc -l
// 输出：8
```

**案例3：正确判断返回值区分父子（05fork.cpp走读）**

```cpp
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main() {
    pid_t pid = fork();
    printf("pid = %d\n", pid);

    if (pid > 0) {
        printf("我是父进程\n");
    } else if (pid == 0) {
        printf("我是子进程\n");
    } else {
        perror("fork error");
        return -1;
    }
    while(1);
    return 0;
}
// 输出：
// pid = 12345        ← 父进程得到的返回值
// 我是父进程
// pid = 0            ← 子进程得到的返回值
// 我是子进程
```

**案例4：父子进程并发执行（06fork.cpp走读）**

```cpp
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main() {
    pid_t pid = fork();

    if (pid > 0) {
        while(1) {
            printf("我是父进程1111\n");
            sleep(1);
        }
    } else if (pid == 0) {
        while(1) {
            printf("我是子进程\n");
            sleep(1);
        }
    } else {
        perror("fork error");
        return -1;
    }
    return 0;
}
// 输出（交替出现，顺序不确定）：
// 我是父进程1111
// 我是子进程
// 我是父进程1111
// 我是子进程
// ...
// 说明：父子进程的执行顺序由调度器决定，不可预测
```

**④ 注意事项**

**错误示范：不判断返回值**
```cpp
// ❌ 错误写法
fork();
printf("这段代码父子都会执行！\n");
do_business();  // 业务逻辑被执行两次，可能导致数据重复、端口冲突等严重bug
```

**正确写法**
```cpp
// ✅ 正确写法：三岔路必须判
pid_t pid = fork();
if (pid > 0) {
    // 父进程逻辑
} else if (pid == 0) {
    // 子进程逻辑
} else {
    perror("fork error");
    return -1;
}
```

**记忆口诀**："fork三岔路，不判就迷路"

> **人话总结**：fork生娃靠返回值认爹妈。

#### 2.2 getpid/getppid 【熟悉】

**① 是什么**

```c
#include <sys/types.h>
#include <unistd.h>
pid_t getpid(void);   // 获取当前进程PID
pid_t getppid(void);  // 获取父进程PID
// 参数：无
// 返回值：对应的进程号
```

**生活比喻**：getpid就是"我叫什么名字"，getppid就是"我爸叫什么名字"。

**② 为什么**
调试多进程程序时需要确认当前代码在哪个进程中执行；发送信号时需要知道目标进程的PID。

**③ 怎么用（07fork.cpp走读节选）**

```cpp
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main() {
    pid_t pid = fork();
    if (pid > 0) {
        // 父进程中：getpid()返回自己的PID，pid变量存的是子进程PID，getppid()返回祖父PID
        printf("self pid=%d, child pid=%d, parent pid=%d\n",
               getpid(), pid, getppid());
        // 输出：self pid=1000, child pid=1001, parent pid=999
    } else if (pid == 0) {
        // 子进程中：getpid()返回自己的PID，getppid()返回父进程PID
        printf("self pid=%d, parent pid=%d\n", getpid(), getppid());
        // 输出：self pid=1001, parent pid=1000
    }
    return 0;
}
```

**④ 注意事项**
- 子进程中调用getppid()得到的是父进程PID，不是自己的PID。
- 如果父进程先退出，子进程被1号进程收养，此时getppid()返回1。

> **人话总结**：getpid查自己，getppid查老爸。

#### 2.3 exit与_exit的区别 【重点】

**① 是什么**

```c
#include <stdlib.h>
void exit(int status);   // 库函数：刷新标准IO缓冲区后退出

#include <unistd.h>
void _exit(int status);  // 系统调用：直接退出，不刷新缓冲区
// 参数status：退出状态码，会与0377做位与运算后传递给父进程
// 返回值：无（不会返回）
```

**生活比喻**：exit就像离开办公室前先整理桌面、把没写完的报告保存好再走；_exit就像接到紧急电话直接冲出办公室，桌上的草稿纸都不管了。

**② 为什么**
- 为什么有两个退出函数？标准IO（printf等）使用用户态缓冲区减少系统调用次数。如果用_exit退出，缓冲区中未刷新的数据会丢失。
- 为什么子进程中有时需要用_exit？在fork后的子进程中，如果不想重复刷新父进程遗留的缓冲区内容，应该用_exit。

**③ 怎么用（07fork.cpp走读节选）**

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();
    if (pid == 0) {
        // 子进程
        printf("11111111111111111111111111111111111");  // 没有\n，不会自动刷新
        sleep(3);
        exit(EXIT_SUCCESS);      // ✅ 刷新缓冲区后退出，上面的内容会被打印
        // _exit(EXIT_SUCCESS);  // ❌ 不刷新缓冲区，上面的内容丢失
    }
    return 0;
}
// 使用exit的输出：11111111111111111111111111111111111
// 使用_exit的输出：（什么都没有）
```

**④ 注意事项**

| 特性 | exit() | _exit() |
|------|--------|---------|
| 类型 | 库函数 | 系统调用 |
| 刷新IO缓冲区 | 是 | 否 |
| 调用atexit注册的清理函数 | 是 | 否 |
| 适用场景 | 正常退出 | fork后子进程退出、信号处理函数中 |

**错误示范**
```cpp
// ❌ 在信号处理函数中使用exit可能导致重入问题
void handler(int sig) {
    exit(0);  // exit内部可能调用malloc等非异步安全函数
}

// ✅ 信号处理函数中应使用_exit
void handler(int sig) {
    _exit(0);
}
```

> **人话总结**：exit刷缓冲再走，_exit拔腿就跑。

#### 2.4 wait/waitpid资源回收 【重点】

**① 是什么**

```c
#include <sys/types.h>
#include <sys/wait.h>

pid_t wait(int *status);
// 功能：阻塞回收任意一个子进程的资源
// 参数：接收子进程退出状态（与0377位与后的结果），可填NULL
// 返回值：成功返回被回收子进程的PID，失败返回-1

pid_t waitpid(pid_t pid, int *status, int options);
// 参数1 pid：
//   >0  : 回收指定PID的子进程（常用）
//   =0  : 回收同进程组中的任意子进程
//   =-1 : 回收任意子进程（常用，等价于wait）
//   <-1 : 回收指定进程组（组ID=|pid|）中的任意子进程
// 参数3 options：
//   0      : 阻塞等待
//   WNOHANG: 非阻塞，如果没有已退出的子进程立即返回0
// 返回值：
//   >0 : 成功回收的子进程PID
//   =0 : 非阻塞模式下暂无可回收的子进程
//   =-1: 出错
```

**生活比喻**：wait就像家长站在幼儿园门口等孩子放学，不走开直到接到孩子；waitpid(WNOHANG)就像家长每隔一会儿去看看孩子有没有出来，没出来就先忙别的。

**② 为什么**
- 为什么必须回收？子进程退出后内核仍保留其PCB中的退出状态信息，如果不回收就变成僵尸进程，浪费进程表项。
- 为什么waitpid比wait更灵活？wait只能阻塞等待任意子进程，waitpid可以指定目标、可以非阻塞轮询。
- 为什么WNOHANG重要？在服务程序中，父进程不能一直阻塞等子进程，需要边处理业务边检查是否有子进程退出。

**③ 怎么用（07fork.cpp完整走读）**

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();
    if (pid > 0) {
        // 父进程
        printf("self pid=%d, child pid=%d, parent pid=%d\n",
               getpid(), pid, getppid());
        sleep(8);  // 休眠8秒，让子进程先退出

        // 非阻塞回收：如果子进程已退出则回收，否则立即返回0
        waitpid(-1, NULL, WNOHANG);
        printf("子进程资源已经回收\n");
    } else if (pid == 0) {
        // 子进程
        printf("self pid=%d, parent pid=%d\n", getpid(), getppid());
        printf("11111111111111111111111111111111111");  // 无换行
        sleep(3);
        exit(EXIT_SUCCESS);  // 刷新缓冲区并退出
    } else {
        perror("fork error");
        return -1;
    }
    while(1);
    return 0;
}
// 输出：
// self pid=1000, child pid=1001, parent pid=999
// self pid=1001, parent pid=1000
// 11111111111111111111111111111111111
// （3秒后子进程退出，8秒后父进程尝试回收）
// 子进程资源已经回收
```

**案例：多进程文件拷贝（08test.cpp走读）**

```cpp
// 核心思路：父进程拷贝前一半，子进程拷贝后一半
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <string.h>

int copy_file(const char *src, const char *dst, int start, int len) {
    int srcfd = open(src, O_RDONLY);
    int dstfd = open(dst, O_WRONLY);
    lseek(srcfd, start, SEEK_SET);
    lseek(dstfd, start, SEEK_SET);
    char buf[128];
    int sum = 0;
    while (1) {
        int res = read(srcfd, buf, sizeof(buf));
        sum += res;
        if (res == 0 || sum >= len) {
            write(dstfd, buf, res - (sum - len));  // 最后一次可能多读了
            break;
        }
        write(dstfd, buf, res);
    }
    close(srcfd);
    close(dstfd);
    return 0;
}

int main(int argc, const char *argv[]) {
    if (argc != 3) {
        printf("usage: ./a.out srcfile destfile\n");
        return -1;
    }
    // 获取文件大小
    int srcfd = open(argv[1], O_RDONLY);
    int len = lseek(srcfd, 0, SEEK_END);
    close(srcfd);
    // 创建目标文件
    int dstfd = open(argv[2], O_WRONLY|O_CREAT|O_TRUNC, 0664);
    close(dstfd);

    pid_t pid = fork();
    if (pid > 0) {
        copy_file(argv[1], argv[2], 0, len/2);      // 父进程拷前半
        wait(NULL);                                   // 等待子进程完成
    } else if (pid == 0) {
        copy_file(argv[1], argv[2], len/2, len-len/2); // 子进程拷后半
        exit(EXIT_SUCCESS);
    }
    printf("拷贝成功\n");
    // 输出：拷贝成功
    return 0;
}
```

**④ 注意事项**

**错误示范：忘记回收**
```cpp
// ❌ 创建子进程后不管不问
fork();
do_parent_work();
// 子进程退出后变成僵尸进程，ps aux看到Z状态
```

**正确写法**
```cpp
// ✅ 及时回收
pid_t pid = fork();
if (pid > 0) {
    do_parent_work();
    wait(NULL);  // 或使用循环+waitpid(WNOHANG)非阻塞回收
}
```

**记忆口诀**："生了就要养，不收变僵尸"

> **人话总结**：wait收尸防僵尸，waitpid更灵活。

#### 2.5 父进程创建多个子进程并回收（09fork.cpp走读）

**① 是什么**
在一个父进程中连续调用多次fork创建多个子进程，然后逐一wait回收。

**② 为什么**
实际开发中经常需要一个主进程管理多个工作进程（如Web服务器的多进程模型）。

**③ 怎么用**

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();          // 创建大儿子
    if (pid > 0) {
        pid_t pid_2 = fork();    // 创建二儿子（注意：只有父进程才执行这行）
        if (pid_2 > 0) {
            printf("我是父进程\n");
            wait(NULL);          // 回收第一个退出的子进程
            wait(NULL);          // 回收第二个退出的子进程
        } else if (pid_2 == 0) {
            sleep(3);
            printf("我是进程2\n");
            exit(EXIT_SUCCESS);
        }
    } else if (pid == 0) {
        sleep(3);
        printf("我是进程1\n");
        exit(EXIT_SUCCESS);
    }
    return 0;
}
// 输出：
// 我是父进程
// 我是进程1       ← 3秒后
// 我是进程2       ← 3秒后
```

**逐行走读关键点**：
1. 第一次fork后，只有父进程（pid>0分支内）才会执行第二次fork。子进程（pid==0分支）不会再fork，避免了不必要的进程爆炸。
2. 两次wait分别回收两个子进程，wait的顺序不固定（谁先退出先回收谁）。

**④ 注意事项**
- 如果在子进程中也调用fork，会产生孙进程，进程数量指数增长。
- wait(NULL)回收的是"任意一个已退出的子进程"，不保证顺序。

> **人话总结**：多次fork要只在父进程中做。

#### 2.6 孤儿进程与僵尸进程 【重点】

**① 是什么**
- **孤儿进程**：子进程还在运行，父进程已经退出。孤儿进程被1号进程（init/systemd）收养。
- **僵尸进程**：子进程已经退出，但父进程没有调用wait回收其资源。子进程的PCB残留在进程表中。

**生活比喻**：孤儿进程就像父母去世后孩子被福利院收养，孩子本身没问题；僵尸进程就像人死了但户口没注销，占着名额不干活。

**② 为什么**
- 孤儿进程危害不大，1号进程会自动收养并回收。
- 僵尸进程的危害：每个僵尸占用一个进程表项，大量僵尸会耗尽系统可用的PID数量，导致无法创建新进程。生产环境中用`ps aux | grep Z`排查。

**③ 怎么用**

**孤儿进程演示（10zibo,.cpp走读）**
```cpp
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();
    if (pid > 0) {
        sleep(5);
        exit(EXIT_SUCCESS);  // 父进程5秒后退出
    } else if (pid == 0) {
        while(1) {
            printf("我是子进程, ppid=%d\n", getppid());
            sleep(1);
            // 父进程退出后，ppid变为1（被init收养）
        }
    }
    return 0;
}
// 输出：
// 前5秒：我是子进程, ppid=1000    ← 父进程还活着
// 5秒后：我是子进程, ppid=1       ← 被1号进程收养
```

**僵尸进程演示（11jiangshi.cpp走读）**
```cpp
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();
    if (pid > 0) {
        while(1) {
            printf("我是父进程\n");
            sleep(1);
            // 父进程一直运行但不wait，子进程退出后变僵尸
        }
    } else if (pid == 0) {
        sleep(5);
        exit(EXIT_SUCCESS);  // 子进程5秒后退出
    }
    return 0;
}
// 验证：5秒后执行 ps aux | grep a.out
// 输出中会出现 STAT=Z 的行，即僵尸进程
```

**④ 注意事项**

| 类型 | 成因 | 危害 | 解决方法 |
|------|------|------|----------|
| 孤儿进程 | 父先死子后活 | 几乎无害 | 1号进程自动收养 |
| 僵尸进程 | 子先死父不收 | 耗尽进程表项 | 父进程调用wait/waitpid |

> **人话总结**：孤儿有人养，僵尸没人收。

### 模块三：进程间通信IPC（P30-P59）

---

#### 3.1 IPC基础概念 【了解】

**① 是什么**
IPC（Interprocess Communication，进程间通信）是利用内核空间作为中介，在不同进程的用户空间之间传递数据的机制。

**② 为什么**
多个进程的用户空间相互隔离，无法直接读写对方的变量。需要借助内核空间这个"公共信箱"来交换数据。

**③ IPC方式分类总览**

| 类别 | 方式 | 特点 |
|------|------|------|
| 内核提供 | 无名管道(pipe) | 仅限亲缘进程，半双工 |
| 内核提供 | 有名管道(FIFO) | 任意进程，有文件名 |
| 内核提供 | 信号(signal) | 通知机制，非数据传输 |
| System V | 消息队列 | 有类型消息链表 |
| System V | 共享内存 | 最快IPC，需同步 |
| System V | 信号量集 | 同步互斥工具 |
| 网络 | socket | 跨主机通信 |

**④ 为什么不能用全局变量通信（01test.cpp/day2走读）**

```cpp
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int num = 520;  // 全局变量

int main() {
    pid_t pid = fork();
    if (pid > 0) {
        num = 1314;
        printf("父进程中：num = %d\n", num);  // 1314
        wait(NULL);
    } else if (pid == 0) {
        sleep(3);
        printf("子进程中：num = %d\n", num);  // 520！不是1314
    }
    return 0;
}
// 输出：
// 父进程中：num = 1314
// 子进程中：num = 520
// 结论：fork后父子进程的变量是完全独立的副本
```

> **人话总结**：进程隔离靠内核，通信也要靠内核。

#### 3.2 无名管道pipe 【重点】

**① 是什么**

```c
#include <unistd.h>
int pipe(int fildes[2]);
// 功能：在内核中创建一个无名管道
// 参数：fildes[0]=读端文件描述符，fildes[1]=写端文件描述符
// 返回值：成功返回0，失败返回-1并置位errno
```

管道是一种特殊的文件，存在于内核空间中，不存储在文件系统上。数据从写端流入，从读端流出，遵循FIFO原则。

**生活比喻**：无名管道就像一根水管连接父子两个房间，父亲往一头灌水，儿子从另一头接水。但这根水管没有门牌号，只有父子知道它在哪。

**② 为什么**
- 为什么限制在亲缘进程间？因为无名管道没有名字，只有通过fork继承文件描述符才能访问。
- 为什么是半双工？同一时刻只能单向流动，要么父写子读，要么子写父读。双向通信需要两个管道。
- 为什么管道有大小限制？内核为管道分配的缓冲区通常为64KB（Linux默认），满了写端阻塞，空了读端阻塞。

**③ 怎么用（02pipe.cpp完整走读）**

```cpp
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main() {
    int fildes[2];  // fildes[0]=读端, fildes[1]=写端

    // ⚠️ 必须在fork之前创建管道！
    if (pipe(fildes) == -1) {
        perror("pipe error");
        return -1;
    }
    printf("fildes[0]=%d, fildes[1]=%d\n", fildes[0], fildes[1]);
    // 输出：fildes[0]=3, fildes[1]=4

    pid_t pid = fork();
    if (pid > 0) {
        // 父进程：只用写端，关闭读端
        close(fildes[0]);

        char wbuf[128] = "hello world";
        write(fildes[1], wbuf, strlen(wbuf));  // 写入管道

        close(fildes[1]);  // 写完关闭写端
        wait(NULL);
    } else if (pid == 0) {
        // 子进程：只用读端，关闭写端
        close(fildes[1]);

        char rbuf[128] = "";
        read(fildes[0], rbuf, sizeof(rbuf));   // 从管道读取
        printf("收到父进程的数据为：%s\n", rbuf);
        // 输出：收到父进程的数据为：hello world

        close(fildes[0]);
        exit(EXIT_SUCCESS);
    }
    return 0;
}
```

**管道数据流转ASCII图**：

```
    父进程用户空间              内核空间                子进程用户空间
    ┌──────────────┐     ┌──────────────────┐     ┌──────────────┐
    │              │     │                  │     │              │
    │ write() ─────┼────►│  管道缓冲区(64KB) ├────►│ read()       │
    │ wbuf="hello" │     │  [h][e][l][l][o] │     │ rbuf="hello" │
    │              │     │                  │     │              │
    └──────────────┘     └──────────────────┘     └──────────────┘
         fildes[1]              ▲                      fildes[0]
         (写端)                 │                      (读端)
                                │
                        数据在内核缓冲区中
                        从写端流向读端(FIFO)
```

**管道缓冲区满的演示（03pipe.cpp走读）**

```cpp
#include <stdio.h>
#include <unistd.h>

int main() {
    int fildes[2];
    pipe(fildes);

    char buf = 'A';
    int count = 0;
    while(1) {
        write(fildes[1], &buf, 1);  // 每次写1字节
        count++;
        printf("count = %d\n", count);
        // 当count达到约65536时，write()阻塞
        // 因为管道缓冲区已满且没有读端在读
    }
    return 0;
}
// 输出：count不断递增直到约65536后程序卡住
// 结论：管道缓冲区大小约为64KB
```

**④ 注意事项**

| 规则 | 说明 |
|------|------|
| 先pipe后fork | fork后创建的管道父子各自独立，无法通信 |
| 关闭不用的一端 | 父关读端、子关写端（或反之），避免死锁 |
| 所有写端关闭后read返回0 | 表示管道中没有更多数据 |
| 所有读端关闭后write触发SIGPIPE | 默认终止进程 |

**错误示范**
```cpp
// ❌ 在fork之后才创建管道
fork();
pipe(fildes);  // 父子各自创建了独立的管道，无法互通！
```

**正确写法**
```cpp
// ✅ 先创建管道再fork
pipe(fildes);
fork();  // 子进程继承了管道的fd
```

> **人话总结**：管道是父子间的单向水管，先建再分家。

#### 3.3 有名管道FIFO 【熟悉】

**① 是什么**

```c
#include <sys/types.h>
#include <sys/stat.h>
int mkfifo(const char *pathname, mode_t mode);
// 功能：在文件系统中创建一个有名管道文件
// 参数：pathname=管道文件路径，mode=权限
// 返回值：成功返回0，失败返回-1

// 创建后用open/read/write/close像普通文件一样操作
```

**生活比喻**：有名管道就像一个带门牌号的公共信箱，任何知道地址的人都可以往里投信或取信，不限于亲属关系。

**② 为什么**
- 为什么需要FIFO？无名管道只能在亲缘进程间通信，FIFO通过文件名让无关进程也能通信。
- 为什么FIFO也是半双工？虽然文件系统中可见，但底层仍是管道机制，单向流动。双向通信需两个FIFO。

**③ 怎么用（fifo/create.cpp + send.cpp + recv.cpp走读）**

**步骤1：创建管道文件**
```cpp
// create.cpp
#include <stdio.h>
#include <sys/types.h>
#include <sys/stat.h>

int main() {
    if (mkfifo("./myfifo", 0664) == -1) {
        perror("mkfifo error");  // 如果文件已存在会报错EEXIST
        return -1;
    }
    printf("管道创建成功\n");
    // 输出：管道创建成功
    // ls -l myfifo → prw-rw-r-- （p表示管道文件）
    return 0;
}
```

**步骤2：发送端**
```cpp
// send.cpp
#include <stdio.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int sfd = open("./myfifo", O_WRONLY);  // 以只写方式打开
    char wbuf[128] = "";
    while(1) {
        printf("请输入>>>");
        fgets(wbuf, sizeof(wbuf), stdin);
        wbuf[strlen(wbuf)-1] = '\0';
        write(sfd, wbuf, strlen(wbuf));
        if (strcmp(wbuf, "quit") == 0) break;
    }
    close(sfd);
    return 0;
}
```

**步骤3：接收端**
```cpp
// recv.cpp
#include <stdio.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int rfd = open("./myfifo", O_RDONLY);  // 以只读方式打开
    char rbuf[128] = "";
    while(1) {
        bzero(rbuf, sizeof(rbuf));
        read(rfd, rbuf, sizeof(rbuf));
        printf("收到数据为：%s\n", rbuf);
        if (strcmp(rbuf, "quit") == 0) break;
    }
    close(rfd);
    return 0;
}
// 运行send和recv后，在send端输入hello，recv端输出：
// 收到数据为：hello
```

**双向FIFO通信（test目录走读要点）**
```
create.cpp 创建两个FIFO：myfifo1 和 myfifo2
send.cpp: 父进程写myfifo1 + 子进程读myfifo2
recv.cpp: 父进程读myfifo1 + 子进程写myfifo2
这样就实现了双向通信
```

**④ 注意事项**

| 对比项 | 无名管道pipe | 有名管道FIFO |
|--------|-------------|-------------|
| 创建方式 | pipe() | mkfifo() |
| 有无文件名 | 无 | 有（文件系统中可见） |
| 通信范围 | 仅亲缘进程 | 任意进程 |
| 生命周期 | 随进程结束消失 | 持久存在直到unlink |
| 打开行为 | 即时可用 | 读端open阻塞到有写端打开，反之亦然 |

> **人话总结**：FIFO是有名字的管道，陌生人也能通信。

#### 3.4 信号signal 【重点】

**① 是什么**
信号是Linux中用于通知进程某个事件发生的软件中断机制。共有64种信号（前32个为可靠信号，后32个为实时信号）。

```c
#include <signal.h>

// 注册信号处理函数
typedef void (*sighandler_t)(int);
sighandler_t signal(int signum, sighandler_t handler);
// 参数：signum=信号编号，handler=处理函数/SIG_IGN/SIG_DFL
// 返回值：成功返回之前的处理函数指针，失败返回SIG_ERR

// 发送信号
int kill(pid_t pid, int sig);
// pid>0: 发送给指定进程
// pid=0: 发送给同进程组所有进程
// pid=-1: 发送给所有有权限的进程
// pid<-1: 发送给指定进程组

int raise(int sig);  // 向自己发送信号
```

**常用信号速查表**：

| 信号 | 编号 | 触发条件 | 默认行为 | 能否捕获 |
|------|------|----------|----------|----------|
| SIGHUP | 1 | 终端关闭 | 终止进程 | 能 |
| SIGINT | 2 | Ctrl+C | 终止进程 | 能 |
| SIGQUIT | 3 | Ctrl+/ | 终止+core dump | 能 |
| SIGKILL | 9 | kill -9 | 强制终止 | **不能** |
| SIGSEGV | 11 | 段错误 | 终止+core dump | 能 |
| SIGPIPE | 13 | 管道破裂 | 终止进程 | 能 |
| SIGALRM | 14 | 定时器超时 | 终止进程 | 能 |
| SIGTERM | 15 | kill默认 | 优雅终止 | 能 |
| SIGCHLD | 17 | 子进程退出 | 忽略 | 能 |
| SIGSTOP | 19 | Ctrl+Z | 暂停进程 | **不能** |
| SIGUSR1 | 10 | 用户自定义 | 终止进程 | 能 |
| SIGUSR2 | 12 | 用户自定义 | 终止进程 | 能 |

**生活比喻**：信号就像手机通知——收到短信（SIGINT）你可以选择看或不看，但收到强制关机指令（SIGKILL）你没有任何选择权。

**② 为什么**
- 为什么需要信号？进程间需要一种轻量级的异步通知机制，不需要传输大量数据，只需告知"某事发生了"。
- 为什么SIGKILL和SIGSTOP不可捕获？这是内核的安全底线，确保管理员始终有能力终止或暂停任何进程。
- 为什么signal不够可靠？早期signal在处理完一次后会重置为默认行为（System V语义），且不支持信号排队。推荐使用sigaction替代。

**③ 怎么用**

**案例1：捕获/忽略/默认处理SIGINT（01signal.cpp走读）**

```cpp
#include <stdio.h>
#include <unistd.h>
#include <signal.h>

void handler(int signo) {
    if (signo == SIGINT) {
        printf("用户键入了ctrl + c\n");
    }
}

int main() {
    // 方式1：忽略SIGINT
    // signal(SIGINT, SIG_IGN);

    // 方式2：自定义处理
    // signal(SIGINT, handler);

    // 方式3：恢复默认行为
    signal(SIGINT, SIG_DFL);

    while(1) {
        printf("我真的还想再活五百年\n");
        sleep(1);
    }
    return 0;
}
// 方式2运行时按Ctrl+C输出：用户键入了ctrl + c（程序继续运行）
// 方式3运行时按Ctrl+C：程序被终止（默认行为）
```

**案例2：SIGKILL不可捕获（02signal.cpp走读）**

```cpp

#include <unistd.h>
#include <signal.h>

int main() {
    // 以下三种操作对SIGKILL全部报错：参数不合法(EINVAL)
    // signal(SIGKILL, SIG_IGN);   // ❌ 报错
    // signal(SIGKILL, handler);   // ❌ 报错
    // signal(SIGKILL, SIG_DFL);   // ❌ 报错

```

**案例3：利用SIGCHLD自动回收僵尸进程（03sigchld.cpp走读）**

```cpp
#include <stdio.h>
#include <unistd.h>
#include <signal.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <stdlib.h>

void handler(int signo) {
    if (signo == SIGCHLD) {
        // 循环回收所有已退出的子进程（因为信号可能合并）
        while(waitpid(-1, NULL, WNOHANG) > 0);
    }
}

int main() {
    signal(SIGCHLD, handler);  // 注册SIGCHLD处理函数

    for (int i = 0; i < 10; i++) {
        if (fork() == 0) {
            exit(EXIT_SUCCESS);  // 子进程立即退出
        }
    }

    while(1);  // 父进程持续运行
    // 验证：ps aux | grep a.out → 没有Z状态进程
    // 因为SIGCHLD处理函数自动回收了所有僵尸
    return 0;
}
```

**案例4：子进程向父进程发信号（04kill.cpp走读）**

```cpp
#include <stdio.h>
#include <unistd.h>
#include <signal.h>
#include <stdlib.h>

void handler(int signo) {
    if (signo == SIGUSR1) {
        printf("逆子，何至于此!!!\n");
        raise(SIGKILL);  // 向自己发送SIGKILL自杀
    }
}

int main() {
    signal(SIGUSR1, handler);

    pid_t pid = fork();
    if (pid > 0) {
        while(1) {
            printf("我真的还想再活五百年\n");
            sleep(1);
        }
    } else if (pid == 0) {
        sleep(5);
        printf("红尘已经看破，叫上父亲一起死吧\n");
        kill(getppid(), SIGUSR1);  // 向父进程发送自定义信号
        exit(EXIT_SUCCESS);
    }
    return 0;
}
// 输出：
// 我真的还想再活五百年  ← 每秒一次，持续5秒
// 红尘已经看破，叫上父亲一起死吧
// 逆子，何至于此!!!
// （父进程被SIGKILL杀死，程序结束）
```

**信号的发送-捕获-默认行为关系图**：

```
    发送方                     内核                     接收方
    ┌────────┐          ┌──────────────┐          ┌────────────┐
    │kill()  │─────────►│ 信号投递      │─────────►│ 检查处理方式│
    │raise() │          │ (不可靠信号   │          │            │
    │硬件异常│          │  可能丢失)    │          │ SIG_IGN?   │
    └────────┘          └──────────────┘          │ → 丢弃     │
                                                  │ SIG_DFL?   │
                                                  │ → 默认行为 │
                                                  │ 自定义函数? │
                                                  │ → 执行handler│
                                                  └────────────┘
```

**④ 注意事项**
- 信号处理函数中只能调用异步信号安全函数（如write、_exit），不能调用printf、malloc等。
- 信号不排队（可靠信号除外），快速连续发送同一信号可能只收到一次。
- SIGCHLD处理函数中要用`while(waitpid(-1,NULL,WNOHANG)>0)`循环回收，因为多个子进程可能同时退出但只产生一个SIGCHLD。

> **人话总结**：信号是轻量通知，SIGKILL谁都挡不住。

#### 3.5 消息队列 【熟悉】

**① 是什么**
消息队列是内核中维护的一个消息链表，每条消息带有类型标识，可以按类型选择性读取。

```c
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/msg.h>

key_t ftok(const char *pathname, int proj_id);
// 根据路径和项目ID生成唯一的key值

int msgget(key_t key, int msgflg);
// 创建/获取消息队列，返回消息队列ID

int msgsnd(int msqid, const void *msgp, size_t msgsz, int msgflg);
// 发送消息，msgp指向struct{long mtype; char mtext[];}

ssize_t msgrcv(int msqid, void *msgp, size_t msgsz, long msgtyp, int msgflg);
// 接收消息，msgtyp指定要接收的消息类型

int msgctl(int msqid, int cmd, struct msqid_ds *buf);
// 控制消息队列，cmd=IPC_RMID删除
```

**生活比喻**：消息队列就像快递柜——每个格子（消息）贴有标签（类型），寄件人放进去，收件人可以按标签号取指定的包裹。

**② 为什么**
- 为什么用消息类型？允许接收方按需筛选消息，实现多对多通信。
- 为什么比管道方便？消息队列有名字（key），不要求亲缘关系；消息有边界，不会粘包。
- 为什么不如共享内存快？每次收发都要在内核和用户空间之间拷贝数据。

**③ 怎么用（01msgsnd.cpp + 02msgrcv.cpp走读）**

**发送端：**
```cpp
#include <stdio.h>
#include <string.h>
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/msg.h>

struct msgBuf {
    long mtype;        // 消息类型（必须>0）
    char mtext[1024];  // 消息正文
};
#define MSGSZ (sizeof(struct msgBuf) - sizeof(long))

int main() {
    // 1. 生成key
    key_t key = ftok("/", 'k');
    printf("key = %#x\n", key);

    // 2. 创建消息队列
    int msqid = msgget(key, IPC_CREAT|0664);
    printf("msqid = %d\n", msqid);

    // 3. 发送消息
    struct msgBuf buf;
    while(1) {
        printf("请输入消息的类型：");
        scanf("%ld", &buf.mtype);
        getchar();
        printf("请输入消息正文:");
        fgets(buf.mtext, MSGSZ, stdin);
        buf.mtext[strlen(buf.mtext)-1] = '\0';

        msgsnd(msqid, &buf, MSGSZ, 0);  // 阻塞发送
        printf("消息存入成功\n");

        if (strcmp(buf.mtext, "quit") == 0) break;
    }
    return 0;
}
```

**接收端：**
```cpp
#include <stdio.h>
#include <string.h>
#include <sys/types.h>
#include <sys/ipc.h>

    long mtype;
    char mtext[1024];

int main() {
    key_t key = ftok("/", 'k');
    int msqid = msgget(key, IPC_CREAT|0664);

}
// 发送端输入类型1、正文hello后，接收端输出：
// 读取到的消息为:hello
```

**双向消息通信（05test1.cpp + 06test2.cpp要点）**：
- 05test1：父进程发类型1消息，子进程收类型2消息
- 06test2：父进程收类型1消息，子进程发类型2消息
- 两个程序配合运行实现双向通信

**④ 注意事项**
- mtype必须大于0，否则msgsnd报错。
- 消息队列是持久化的，程序退出后仍存在，必须显式msgctl(IPC_RMID)删除。
- 用`ipcs -q`查看系统中的消息队列，`ipcrm -q msqid`手动删除。

> **人话总结**：消息队列是按类型分拣的内核快递柜。

#### 3.6 共享内存 【重点】

**① 是什么**
共享内存是最快的IPC方式，多个进程将同一块物理内存映射到各自的用户空间，直接读写无需内核拷贝。

```c
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/shm.h>

int shmget(key_t key, size_t size, int shmflg);
// 创建/获取共享内存段，返回shmid

void *shmat(int shmid, const void *shmaddr, int shmflg);
// 将共享内存映射到用户空间，返回映射地址
// shmaddr=NULL让系统自动选择对齐地址
// shmflg=0表示读写模式

int shmdt(const void *shmaddr);
// 解除映射（不删除共享内存段）

int shmctl(int shmid, int cmd, struct shmid_ds *buf);
// cmd=IPC_RMID标记删除
```

**生活比喻**：共享内存就像会议室里的白板——所有人都能看到和修改同一块白板上的内容，速度快但如果不约定好谁先写谁后看，就会乱成一团。

**② 为什么**
- 为什么共享内存最快？数据不需要在内核和用户空间之间拷贝，直接在用户空间读写。
- 为什么需要同步机制？多个进程同时读写同一块内存会导致数据竞争，必须用信号量或互斥锁保护。
- 为什么用ftok生成key？保证不同程序使用相同的key就能找到同一块共享内存。

**③ 怎么用（03shmsnd.cpp + 04shmrcv.cpp走读）**

**写入端：**
```cpp
#include <stdio.h>
#include <string.h>
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/shm.h>
#include <unistd.h>

#define PAGE_SIZE 4096

int main() {
    key_t key = ftok("/", 'k');
    int shmid = shmget(key, PAGE_SIZE, IPC_CREAT|0664);
    char *addr = (char *)shmat(shmid, NULL, 0);

    while(1) {
        printf("请输入>>>");
        fgets(addr, PAGE_SIZE, stdin);       // 直接写入共享内存
        addr[strlen(addr)-1] = '\0';
        if (strcmp(addr, "quit") == 0) break;
    }

    sleep(5);
    shmdt(addr);  // 解除映射
    return 0;
}
```

**读取端：**
```cpp
#include <stdio.h>
#include <string.h>
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/shm.h>
#include <unistd.h>

    key_t key = ftok("/", 'k');
    int shmid = shmget(key, PAGE_SIZE, IPC_CREAT|0664);
    char *addr = (char *)shmat(shmid, NULL, 0);

    while(1) {
        sleep(2);
        printf("读取到消息为：%s\n", addr);  // 直接从共享内存读取
        if (strcmp(addr, "quit") == 0) break;
    }

    shmdt(addr);
    shmctl(shmid, IPC_RMID, NULL);  // 删除共享内存段
    return 0;
}
// 写入端输入hello后，读取端每2秒输出：
// 读取到消息为：hello
```

**共享内存映射ASCII图**：

```
    进程A用户空间          内核空间             进程B用户空间
    ┌──────────────┐   ┌─────────────────┐   ┌──────────────┐
    │              │   │                 │   │              │
    │  addr_a ─────┼──►│  共享内存段      │◄──┼───── addr_b  │
    │  (0x7f...)   │   │  [物理页面]     │   │  (0x7f...)   │
    │              │   │                 │   │              │
    │  直接读写    │   │  同一块物理内存  │   │  直接读写    │
    └──────────────┘   └─────────────────┘   └──────────────┘
    
    两个虚拟地址不同，但映射到同一块物理内存
    任何一方的修改，另一方立即可见
```

**④ 注意事项**
- shmat返回`(void*)-1`表示失败，不是NULL。
- shmdt只是解除映射，不删除共享内存；shmctl(IPC_RMID)才真正删除。
- 共享内存是持久的，程序退出后仍存在，必须显式删除。
- 用`ipcs -m`查看，`ipcrm -m shmid`手动删除。
- **必须配合同步机制使用**，否则数据竞争不可避免。

> **人话总结**：共享内存最快但要加锁，不加锁必翻车。

#### 3.7 信号量集 【熟悉】

**① 是什么**
信号量是一个计数器，用于控制多个进程对共享资源的访问。P操作（申请）将计数器减1，V操作（释放）将计数器加1。当计数器为0时，P操作阻塞。

```c
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/sem.h>

int semget(key_t key, int nsems, int semflg);
// 创建/获取信号量集，nsems=信号量个数

int semop(int semid, struct sembuf *sops, size_t nsops);
// struct sembuf { unsigned short sem_num; short sem_op; short sem_flg; }
// sem_op=-1 → P操作（申请资源）
// sem_op=+1 → V操作（释放资源）

int semctl(int semid, int semnum, int cmd, ...);
// SETVAL: 设置信号量初始值
// IPC_RMID: 删除信号量集
```

**生活比喻**：信号量就像停车场的车位计数器——入口P操作（进一辆车减1），出口V操作（出一辆车加1）。计数器为0时，入口处的车只能等着。

**② 为什么**
- 为什么需要信号量？共享内存虽快但没有内置同步，信号量提供了内核级的原子操作来保护临界区。
- 为什么用信号量集而不是单个信号量？一个信号量集包含多个信号量，可以用一套API管理多个同步资源。
- 为什么P/V操作是原子的？由内核保证，不会被其他进程打断，避免了用户态锁的竞争问题。

**③ 怎么用（sem/sem.cpp + sem/03shmsnd.cpp + sem/04shmrcv.cpp走读）**

**信号量封装库（sem.h + sem.cpp）：**
```cpp
// sem.h
#ifndef _SEM_H_
#define _SEM_H_
int create_sem(int semcount);  // 创建并初始化信号量集
int P(int semid, int semno);   // 申请资源
int V(int semid, int semno);   // 释放资源
int delete_sem(int semid);     // 删除信号量集
#endif
```

```cpp
// sem.cpp 核心函数走读
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/sem.h>

union semun {
    int val;
    struct semid_ds *buf;
    unsigned short *array;
    struct seminfo *__buf;
};

int P(int semid, int semno) {
    struct sembuf buf;
    buf.sem_num = semno;  // 操作的信号量编号
    buf.sem_op = -1;      // -1 = P操作 = 申请资源
    buf.sem_flg = 0;      // 阻塞等待
    if (semop(semid, &buf, 1) == -1) {
        perror("P error");
        return -1;
    }
    return 0;
}

int V(int semid, int semno) {
    struct sembuf buf;
    buf.sem_num = semno;
    buf.sem_op = 1;       // +1 = V操作 = 释放资源
    buf.sem_flg = 0;
    if (semop(semid, &buf, 1) == -1) {
        perror("V error");
        return -1;
    }
    return 0;
}
```

**共享内存+信号量的生产者消费者（sem/03shmsnd.cpp走读）：**
```cpp
#include <stdio.h>
#include <string.h>
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/shm.h>
#include "sem.h"

#define PAGE_SIZE 4096

int main() {
    int semid = create_sem(2);  // 创建含2个信号量的集合
    // 初始化时输入：信号量1初始值=1（写锁），信号量2初始值=0（读锁）

    key_t key = ftok("/", 'k');
    int shmid = shmget(key, PAGE_SIZE, IPC_CREAT|0664);
    char *addr = (char *)shmat(shmid, NULL, 0);

    while(1) {
        P(semid, 0);  // 申请写锁（信号量0）
        printf("请输入>>>");
        fgets(addr, PAGE_SIZE, stdin);
        addr[strlen(addr)-1] = '\0';
        V(semid, 1);  // 释放读锁（信号量1），通知读者有新数据

        if (strcmp(addr, "quit") == 0) break;
    }

    shmdt(addr);
    delete_sem(semid);
    return 0;
}
```

**消费者端（sem/04shmrcv.cpp）对称地使用P(semid,1)/V(semid,0)**。

**ABC循环打印（test/A.cpp + B.cpp + C.cpp走读要点）**：
```
3个信号量，初始值分别为1、0、0
A进程：P(0) → 打印A → V(1)    ← 初始能执行
B进程：P(1) → 打印B → V(2)    ← 等A释放
C进程：P(2) → 打印C → V(0)    ← 等B释放
循环输出：ABCABCABC...
```

**④ 注意事项**
- semun联合体在某些系统上需要自行定义（POSIX未声明）。
- 信号量集也是持久的，程序退出后不自动删除。
- P操作可能永久阻塞（死锁），设计时要确保V操作一定会被执行。
- 用`ipcs -s`查看，`ipcrm -s semid`手动删除。

> **人话总结**：信号量是内核级红绿灯，PV配对防死锁。

### 3.1 day1/07fork.cpp 完整走读

```cpp
#include<myhead.h>
int main(int argc, const char *argv[])
{
    pid_t pid = -1;            // ① 定义变量存储fork返回值

    pid = fork();              // ② 创建子进程
                               // 父进程：pid=子进程PID(>0)
                               // 子进程：pid=0
    if(pid > 0)                // ③ 进入父进程分支
    {
        // ④ 打印三个PID：自己的、子进程的、父亲的
        printf("self pid=%d, child pid = %d, parent pid = %d\n",
               getpid(), pid, getppid());

        sleep(8);              // ⑤ 休眠8秒，确保子进程先退出

        // ⑥ 非阻塞回收：若子进程已退出则回收，否则返回0继续执行
        waitpid(-1, NULL, WNOHANG);
        printf("子进程资源已经回收\n");

    }else if(pid == 0)         // ⑦ 进入子进程分支
    {
        printf("self pid = %d, parent pid = %d\n",
               getpid(), getppid());  // ⑧ 打印自己的PID和父进程PID

        // ⑨ 注意：没有\n，数据留在缓冲区
        printf("11111111111111111111111111111111111");

        sleep(3);              // ⑩ 休眠3秒

        exit(EXIT_SUCCESS);    // ⑪ 刷新缓冲区并退出
        //_exit(EXIT_SUCCESS); // ⑫ 注释掉的版本：不刷新缓冲区
    }else
    {
        perror("fork error");  // ⑬ fork失败处理
        return -1;
    }

    while(1);                  // ⑭ 父进程回收后仍保持运行
    return 0;
}
```

**关键内存状态变化**：
- fork瞬间：子进程获得父进程页表的拷贝（COW），两者共享物理页。
- 子进程调用printf("111...")：数据写入子进程私有的stdout缓冲区（COW触发拷贝）。
- 子进程调用exit()：刷新子进程缓冲区→输出"111..."→子进程退出→变为僵尸。
- 父进程8秒后调用waitpid(WNOHANG)：回收僵尸→子进程PCB释放。

```cpp
int create_sem(int semcount) {
    key_t key = ftok("/", 'k');  // 生成key

    // 尝试独占创建
    int semid = semget(key, semcount, IPC_CREAT|IPC_EXCL|0664);
    if (semid == -1) {
        if (errno == EEXIST) {
            // 已存在则直接打开（不重新初始化！）
            semid = semget(key, semcount, IPC_CREAT|0664);
            return semid;
        }
        perror("semget error");
        return -1;
    }

    // 首次创建时初始化每个信号量
    for (int i = 0; i < semcount; i++) {
        init_sem(semid, i);  // 用户输入初始值
    }
    return semid;
}
// 关键点：IPC_EXCL确保只有第一个创建者初始化，
// 后续打开者跳过初始化，避免覆盖已有值
```

## 六、常见陷阱专题

### 陷阱1：fork后不判断返回值导致父子进程逻辑混乱

**错误写法**
```cpp
fork();
do_business();  // 父子都执行！数据被处理两次
```

**正确写法**
```cpp
pid_t pid = fork();
if (pid > 0) {
    // 父进程专属逻辑
} else if (pid == 0) {
    // 子进程专属逻辑
} else {
    perror("fork error");
    return -1;
}
```

**如何记住**："fork三岔路，不判就迷路"

### 陷阱2：忘记wait回收子进程导致僵尸进程堆积

**错误写法**
```cpp
for (int i = 0; i < 100; i++) {
    fork();  // 创建100个子进程
}
// 子进程退出后全部变僵尸
// ps aux看到100个Z状态进程
```

**正确写法**
```cpp
// 方案1：阻塞回收
for (int i = 0; i < 100; i++) {
    if (fork() == 0) exit(0);
}
for (int i = 0; i < 100; i++) wait(NULL);

// 方案2：SIGCHLD信号自动回收
void handler(int sig) {
    while(waitpid(-1, NULL, WNOHANG) > 0);
}
signal(SIGCHLD, handler);
```

**如何记住**："生了就要养，不收变僵尸"

### 陷阱3：共享内存读写不同步导致数据竞争

**错误写法**
```cpp
// 进程A
strcpy(addr, "new data");

// 进程B（无任何同步）
printf("%s\n", addr);  // 可能读到写到一半的数据
```

**正确写法**
```cpp
// 进程A（生产者）
P(semid, 0);           // 获取写锁
strcpy(addr, "new data");
V(semid, 1);           // 通知读者

// 进程B（消费者）
P(semid, 1);           // 等待新数据
printf("%s\n", addr);
V(semid, 0);           // 释放写锁
```

**如何记住**："共享不加锁，数据必翻车"

## 七、新手最常问的5个问题

**Q1：fork之后父子进程的执行顺序是怎样的？**
答：完全由操作系统调度器决定，不可预测。不要假设父先子后或子先父后。如果需要确定顺序，必须用同步机制（wait、信号量、管道等）。

**Q2：为什么fork后修改全局变量，另一个进程看不到？**
答：fork采用写时拷贝（COW），父子进程拥有独立的内存副本。修改全局变量时触发COW，各自在自己的物理页上修改。这与多线程不同——多线程共享同一地址空间。

**Q3：管道满了会怎样？空了会怎样？**
答：管道满时write()阻塞，直到有读者读走数据腾出空间；管道空时read()阻塞，直到有写入者写入数据。如果所有写端都关闭了，read()返回0（EOF）；如果所有读端都关闭了，write()触发SIGPIPE信号。

**Q4：共享内存和消息队列该选哪个？**
答：追求极致性能且数据量大选共享内存（但必须自行同步）；需要结构化消息、自动同步、按类型筛选选消息队列。简单通信优先用管道。

**Q5：SIGCHLD处理函数中为什么要用while循环waitpid？**
答：因为如果多个子进程几乎同时退出，内核可能只发送一个SIGCHLD信号（信号不排队）。如果只wait一次，剩余的子进程就变成僵尸了。`while(waitpid(-1,NULL,WNOHANG)>0)`确保一次性回收所有已退出的子进程。

## 十一、3条口诀

1. **fork三岔路，不判就迷路** —— fork后必须用if/else if/else区分父、子、错误三条路径。
2. **生了就要养，不收变僵尸** —— 创建子进程后必须wait/waitpid回收，否则子进程变僵尸占资源。
3. **共享不加锁，数据必翻车** —— 共享内存读写必须配合信号量等同步机制，否则数据竞争后果不可预测。
