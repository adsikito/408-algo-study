## 一、这个工程是什么

围绕一名在校学生的两条学习主线，把零散的学习资料重组为**可执行的学习系统**。

| 主线 | 目标 | 归入位置 | 计划篇数 |
|------|------|---------|---------|
| **考研** | 408 统考数据结构（45 分） | `01_考研\408数据结构\` | 12 |
| **算法竞赛** | CCF 系列、蓝桥杯、百度之星，可能 ACM-ICPC | `02_竞赛\`（算法专题 42 + 竞赛 C++ 7） | 49 |

| 项 | 内容 |
|----|------|
| 素材来源 | `C:\Users\freecss\Desktop\资料\02_数据结构\`（106）、`03_算法集训\`（149）、`C++\`（475），合计 **730 个文件** |
| 最终产出 | 结构化笔记库 + 题库 + 成套提示词，并发布为 GitHub public 仓库 |
| 工程根 | `资料\00_学习工程\`。**本工程的全部文件都在这个目录内**，与素材目录物理分离 |

### 1.1 三条贯穿全局的设计原则

1. **分类靠边界，不靠目录**。三类笔记（考研 / 竞赛 / 常规课程）物理隔离，边界由 `21_笔记分类体系.md` 定义。
2. **单一真源，其余引用**。同一信息只在一处定义，其他位置只做引用或摘要。矩阵见 `11_提示词执行顺序与使用说明.md` 第四节。
3. **降级不失真**。所有内容按三层语法编写——通用核心承载全部信息，平台专属语法仅作增强且必须可剥离。见 `22_排版与标注规范.md` 第七节。

### 1.2 素材目录与工程目录的分工

| 目录 | 性质 | 谁可以改 |
|------|------|---------|
| `资料\02_数据结构\`、`03_算法集训\`、`C++\` | **原始素材**，只读 | 任何人不得修改、重命名、删除 |
| `资料\00_学习工程\` | **工程目录**，可写 | 本工程的产出全部写在这里 |

> **【硬规则】** **素材目录只读。** 所有产出、副本、中间文件一律写入 `00_学习工程\`。
> 这样「原始资料零改动」这条要求天然成立，不需要额外约束。

### 2.1 编号规则

> **【重点】** 目录用**十位编号**，其内的文件用同一十位的**个位递增编号**。
> 例如 `50_工具与模板\` 内的文件编号为 `51`、`52`、`53`……。
> 编号在**整个工程内唯一**，因此正文中只写文件名即可唯一定位一个文件。

| 编号段 | 含义 | 性质 |
|-------|------|------|
| `01` 至 `09` | 内容库：考研 / 竞赛 / 常规课程 / 全局 | 学习材料 |
| `10` 至 `19` | 提示词 | 工作文档 |
| `20` 至 `29` | 规范（真源） | 工作文档 |
| `30` 至 `39` | 方案 | 工作文档 |
| `40` 至 `49` | 盘点 | 工作文档 |
| `50` 至 `59` | 工具与模板 | 工作文档 |
| `70` 至 `79` | 速查手册 | 产出物 |
| `80` 至 `89` | 合集（合并单文件） | 产出物 |

### 2.2 为什么内容库与工作文档同处工程根

早期设计曾把内容库放进 `60_内容库\` 子目录，后来改掉了。原因是：

1. **提示词与内容笔记之间大量使用相对路径**（如 `02_竞赛\03_题库\_题库总表.md`）。
   内容库若下沉一层，这些路径全部要改，改动面达数百处。
2. **发布时需要把两者分开**（内容库 → `笔记库\`，工作文档 → `工作文档\`），
   分层只会在映射时多加一层，不产生实际收益。
3. 编号本身已经完成了区分（`01` 至 `09` 是内容，`10` 以上是工具），不需要额外目录。
